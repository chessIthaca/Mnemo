Symptom: .coding/backlog.jsonl gets wiped to empty (stale in-memory state persisted over committed entries) after git operations change the disk file. BacklogStore loads items once at startup and never re-syncs from disk; persist() writes the in-memory vector unconditionally, so a stale in-memory state clobbers git's changes on the next mutation. This is the recurring "steering-time backlog clobber" (commits 3b99a87, 6e5cf25 repaired symptoms; root cause persists). · regression test: mutation_does_not_clobber_external_disk_changes
