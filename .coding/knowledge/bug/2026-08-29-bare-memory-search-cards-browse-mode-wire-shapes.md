BUG (aec6cc8a, fixed in plan d3db0070, 2026-09-17 session, branch wt/agenticcoder): SYMPTOM — memory_search activity cards sometimes render completely empty (no tier, no title, no count, no hit list; just the brain icon + ✓), leaving "found 10" indistinguishable from "found nothing" (user screenshot of three bare collapsed rows; reproduced in-session by the SHIPPED/ACTIVE:/STEP MARKER: prefix sweeps). ROOT CAUSE — memory_search BROWSE mode (no query; prefix/tier/record_type filters, src/tool/memory/retrieval.rs:176-204) emits a different wire shape than search mode: header "N memories (newest first):" (:183) vs "N memories matched:", rows "{id}  {tier}  {record_type}  {YYYY-MM-DD}  {title}[ [superseded]]" (:190-198, double-space separated, no brackets, no score) vs "[tier] title (id: …, score: …)\n  digest", and zero-hit "no memories match the filter" (:181) vs "no memories matched the query". parseMemoryEntry (frontend/src/hooks/agentEventReducer.ts, memory_search branch) matched ONLY the search shapes — the matched-header regex required the word "matched" and the tier/title/hits regexes required "[tier]" + "score:" — so every browse output parsed to all-undefined → bare card (the MemoryEntryCard matched chip renders only when matched !== undefined). Zero-hit SEARCH was never affected; memorySearchLabel also never needed changes (prefix-only args already label "browse · SHIPPED"). FIX (frontend-only) — parseMemoryEntry: matched regex gains the browse header "(\d+) memories \(newest first\):?" → N and "no \w+ match the filter" → 0 alternatives (original first, byte-preserving); a browse-row fallback pass (strict-uuid, double-space, optional [superseded]) feeds tier/title from the first row and hits[] (score undefined → the card omits the score chip). RATIONALE for frontend-side: the browse wire format is the stable agent-facing contract; reshaping the backend risks the model's parsing and the Rust browse tests for a UI-labeling ask. Regression tests: browse_results_populate_the_card + "zero-hit browse says no matches" (agentEventReducer.memory.test.ts) — both confirmed RED pre-fix (matched undefined). Review: kimi-k3 round 1 (2026-09-17-d3db0070 review) verified the fix clean, 2 low findings both fixed (this pointer corrected; parseMemoryEntry doc gained the browse branch).
