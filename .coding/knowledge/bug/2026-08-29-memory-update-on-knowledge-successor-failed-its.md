BUG (F1, fixed 2026-09-17, plan 44387fcd, branch wt/agenticcoder): memory_update on a knowledge-SUCCESSOR file errored "supersedes '<slug>' not found" and left the digest stale until the next startup content-hash reconciliation. Root cause: reindex_knowledge_files (src/memory/indexer.rs) resolved `supersedes` only within the reindexed subset (build_knowledge_metas), and KnowledgeSupport::reindex (src/tool/memory/mod.rs) passed only the touched rel — the predecessor file was never in context. Fix: predecessor-context expansion inside the targeted reindex's blocking scan (probe disk for each unresolved slug — same type dir first, then any type dir; chains followed to a fixed point; capped at MAX_PREDECESSOR_CONTEXT=64; absent slugs still surface the build_knowledge_metas error) + a conservative post-loop set_derived_metadata reconciliation mirroring index_derived's — an unchanged predecessor's superseded_by flips, and a computed sentinel/None never regresses a row's more specific existing value. Regression tests: memory::indexer::tests::reindex_knowledge_files_resolves_supersedes_against_the_corpus (failed red with the exact error before the fix) + the F1 block in tool::memory::tests::knowledge_wired_write_lands_in_a_file_and_derived_row (memory_update on the successor id).
