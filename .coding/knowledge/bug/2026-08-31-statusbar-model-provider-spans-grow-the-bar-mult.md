BUG: StatusBar bottom bar grows multiline when the window is squeezed — the model name span ("glm-5.3-flash") and provider span ("Ollama Cloud") in frontend/src/components/layout/StatusBar.tsx rendered as flex items with no max-width and no truncation, so flex squeeze wrapped their text at hyphens/spaces to multiple lines, growing the bar height (user screenshot: "glm-5.3-flash" broken onto 2 lines, placeholder cut off).
ROOT CAUSE: variable-length name spans were flex items with automatic min-size and default wrapping; unlike the short fixed badges in the same bar (max / Complete / main), nothing clamped them.
FIX (final, after three review passes — reports 2026-08-31-statusbar-truncate-review*.md): EVERY variable-length or spaced-text item in the bar is now clamped single-line, so the bar can never regrow multiline — model span "max-w-44 truncate font-medium text-cyan-400" with title template literal leading with the full effectiveModel (hover shows full name); provider span "max-w-32 truncate text-blue-400" + title={activeEndpoint}; stateLabel span "max-w-24 truncate text-green-400" + title={stateLabel}; gitBranch span "max-w-32 truncate text-purple-400" + title={gitBranch}; fixed-literal "Merge to main" button whitespace-nowrap; safety-mode button (labels "Approve Each" / "Auto Project" / "Unsafe" contain spaces) whitespace-nowrap on its base className. Pattern precedent: EndpointCard.tsx max-w-40 shrink-0 truncate.
REGRESSION TEST: frontend/src/components/layout/StatusBar.truncate.test.ts — 7 source-contract assertions (?raw import) pinning every clamp string, registered in frontend/vitest.config.ts include allowlist (allowlist means an unregistered test silently never runs); red before the first fix, green after each pass. Verified: frontend suite 698/698 green (51 files), tsc && vite build clean, cargo test green (no Rust changes).
