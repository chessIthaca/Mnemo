+++
title = "merged worker checkout removal is retried at every merge and app start"
created = "2026-11-06"
+++

A merged Mnemo2 worker whose checkout could not be removed (Windows os error 32 — a shell whose working folder was inside .worktrees/agent-*) used to keep the folder and its "merged, but worktree cleanup needs attention" note for ever, and its branch was never auto-deleted because sweep_merged_branches skips a worker whose checkout folder still exists. Mnemo2 now retries the removal for every Merged worker whose error starts with a checkout-cleanup note ("merged, but…" or "merge recovered, but…") at every later merge (inside merge_locked, before the branch sweep) and once at app start (TeamRuntime::open, after the trash sweep, awaited under the merge lock, then sweep_merged_branches("")). A retry that succeeds, or finds the folder gone, clears the note and persists; a retry that fails leaves the record unchanged. The branch delete is not duplicated — the existing sweep handles it. No setting, event or UI change; the cleanup_agent_worktree / remove_leftover_checkout guards (own direct child of .worktrees, links and junctions refused, registered checkout with new dirty work retained) stay unchanged. Documented in mnemo2/README.md, mnemo2/plugin/skills/mnemo-lead/SKILL.md (item 6) and mnemo2/plugin/skills/mnemo-review/SKILL.md (section 7).

Amended 2026-11-07: Regression test: a_later_merge_retries_an_earlier_merged_workers_stuck_checkout in the src-tauri/src/mnemo2/team.rs test module. It fails when the merge-time retry call is removed (the folder assertion), and passes with it. Supporting tests: a_stuck_checkout_that_still_cannot_be_removed_keeps_its_note_and_branch, the_retry_ignores_a_merged_worker_whose_error_is_not_a_checkout_note, open_retries_a_stuck_checkout_left_by_an_earlier_run. To model a held checkout, put a directory link at the checkout path before the team opens (open clears the note of a merged worker whose folder is absent), then unlink it and create the real leftover folder. The design decision is in the DECISION record about a merged worker's stuck checkout.
