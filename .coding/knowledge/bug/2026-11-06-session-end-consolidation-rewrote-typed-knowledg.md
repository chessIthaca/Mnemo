title = "session-end consolidation rewrote typed knowledge rows while their files stayed unchanged"
created = "2026-11-06"
+++

Symptom (2026-11-06): the DECISION record 'a clean team_merge deletes the merged worker's branch' had a database row with a different, untyped title and content while its file was byte-identical, so is_durable_knowledge_since did not count it and the plan board refused to close its plan until the record was written a second time. Root cause: extract_semantic_facts in src/memory/consolidation.rs listed every semantic-tier row, derived knowledge rows included (the indexer writes all derived rows as tier Semantic), and when the LLM answered with such a row's id it cloned the row and store.write-replaced it with a 60-char untyped title, the fact as content, data = SemanticData (rel_path and links lost) and the session id; the knowledge file was never touched. The indexer then never repaired it: index_derived, reindex_knowledge_files and corpus_is_stale all skipped a source whose derived_index_state content hash matched the file, and that hash never sees the row. The live DB held 105 such drifted knowledge rows (20 bug, 14 decision, 37 how, 34 spec); index_derived's post-loop metadata pass had restored their data/rel_path but not title, content or record_type. Second path: memory_update's database-only branch (and repair_by_id) could edit a Derived row when the knowledge backing was absent or data.rel_path was lost. Fix: consolidation owns only authored rows (derived rows are not listed to the LLM and not rewritten); memory_update refuses database-only edits of Derived rows; the indexer compares the stored row to the file (derived, semantic tier, same title and content, record type from the title prefix), not only the hash, in index_derived, reindex_knowledge_files and corpus_is_stale. Regression tests: semantic_extraction_leaves_derived_knowledge_rows_alone (src/memory/consolidation.rs), full_reindex_repairs_a_row_that_drifted_from_its_file (src/memory/indexer/tests/knowledge.rs), update_refuses_a_database_only_edit_of_a_derived_knowledge_row (src/tool/memory/mod.rs). Lesson: any writer that rewrites a row by id must check record_class; a derived row's file is its only legitimate writer. Diagnostic: a knowledge-keyed row with record_type none or a non-empty source_session_ids has drifted from its file.
