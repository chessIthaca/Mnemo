BUG (plan bbd712c9, reproduced 2026-12-20): A parent agent waiting on its tool-spawned descendants (reviewers) gets spammed with "[harness note] continue from where you left off." synthetic turns — up to MAX_AUTO_CONTINUE (12) of them. ROOT CAUSE: the auto-continue None-arm in src/runtime/agent.rs (run_turn_with_retry, ~:224-227) gates only on `auto_continue_streak < MAX_AUTO_CONTINUE && is_workflow_executing()`; a parent that ends its turn to wait for children (the required spawn→end-turn protocol) is indistinguishable from a stalled agent. Meanwhile the dispatch state-transition gate (src/agent/dispatch.rs:184-196, plan f7f2e2fc subagent-permission model) refuses EVERY workflow transition while descendants run ("cannot change workflow state while spawned subagents are still running" — observed live in session 2026-12-20, 5 spurious notes burned before ask_user parked the parent), so the synthetic turns can never make plan progress. NOT a cross-agent leak: notes are per-agent synthetic messages; the only parent-bound message is the child-completion Suggestion (events.rs notify_parent_on_completion → Suggestion arm, which runs regardless of streak). FIX: extend the None-arm gate with `&& !agent_loop.has_running_descendants().await` (new AgentLoop method AgentLoop::has_running_descendants, loop_impl.rs:1555, consulting the already-wired descendant_tracker field, loop_impl.rs:262 — Option<Arc<dyn DescendantTracker>>, prod impl IpcSpawner main.rs:356, trait runtime/mod.rs:270-276; None → false keeps test loops current).
