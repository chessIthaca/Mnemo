BUG: DeepSeek thinking-mode 400 — trailing assistant turn missing reasoning_content key — FIXED. Symptom: recurring non-retryable HTTP 400 "The `reasoning_content` in the thinking mode must be passed back to the API" from deepseek-v4-flash @ api.deepseek.com, in bursts of ~9-12 failures ~2s apart (.coding/logs/provider-errors.jsonl ids 39-47, 48-56, 101) — killed ≥3 agent sessions, including 2026-12-23 right after plan addf3727's finish. Root cause (LIVE-VERIFIED with 27 curl probes against the real API, plan c9b5cbe4): DeepSeek thinking mode (activated by the presence of reasoning_effort) validates the request TAIL — the assistant turn that owns it (the last message, or the issuer of trailing tool results) must carry a `reasoning_content` KEY (any value, even "" or null — the validator checks key EXISTENCE); a missing key = this 400. Historical assistant turns tolerate a missing key entirely (probes A/D/G2); the effort param absent → no validation (R5). Trigger in production: foreign 429-fallback turns (GLM/Kimi — the 429 log is full of fallback episodes) issue tool calls whose raw echo lacks the key; when their tool results return, the open-loop tail fails validation, and the provider-error note-retry loop re-sends the same broken conversation → the burst → session death. NOT the trigger: the pressure-strip (age-0 protected by keep_recent:1; historical missing-key accepted), synthetic empty-string echo (T2/R3: "" accepted), summarization/consolidation clients (single-user-message requests). Fix (src/provider/openai.rs raw-echo branch): inject `reasoning_content` (structured field or "") into the age-0 assistant raw echo when policy.reasoning_required && key absent — gated to age-0 only so the pressure-strip keeps removing historical text (ffe59699); docs reconciled in policy.rs ReasoningRetention + mod.rs Message.reasoning_content + the synthetic-path comment. Regression test: provider::openai::tests::raw_echo_injects_reasoning_content_when_required_but_absent (fails pre-fix: verbatim echo lacks the key; NOTE it must assert messages[0], the assistant echo — messages[1] is the tool result). Suites green: Rust 1869+16 passed / 0 failed, frontend 709/709. UNFIXED RELATED BUG (do not lose): DeepSeek rejects reasoning_effort:"off" — its enum is none|minimal|low|medium|high|xhigh|max; the harness effort dropdown sends "off" → instant 400 on every request when the user picks "off". Fix: map "off" → "none" for DeepSeek in config_io/resolve_reasoning_effort or the request builder.
