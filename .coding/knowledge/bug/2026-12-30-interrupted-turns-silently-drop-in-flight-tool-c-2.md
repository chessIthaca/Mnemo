BUG: user-interrupted turns silently drop in-flight tool calls (2026-12-30, user-reported "we ran into this bug again … remember pls"; evidence .coding/knowledge/bug/2026-12-30-interrupted-turns-silently-drop-in-flight-tool-c.md, commit f556a3d). Symptom: a user message arriving while a turn's tool calls are in flight silently drops some/all calls — no result block, no error; execution nondeterministic (instance 2: shell ran, sibling backlog_add didn't persist; instance 4: call text echoed into the user's follow-up message).

ROOT CAUSES (audit, plan edfff8d9): A) turn.rs post-stream block ended the turn for ANY stop_reason incl. bare Steer BEFORE the batch executed — a mid-stream user message (Prompt→Steer) silently cancelled the complete batch while the same message after stream-end drained it (sub-second timing decided whether calls ran). B) orphaned calls got UI-ONLY synthetic results, assistant message pushed with tool_calls: vec![] — the model's context never recorded the cancelled calls. C) dispatch.rs dispatch_with_interrupt DROPPED the tool future on Interrupt/Cancel mid-execution — bookkeeping mutations half-applied/unapplied. D) raw-echo hazard: a COMPLETED batch's raw (valid tool_calls) echoed with no following results → provider 400/model confusion (= the instance-4 echo, model-side, NOT frontend — flushStreamingText/pushTranscriptEntry/reduceFinished ordering verified correct).

FIX (plan edfff8d9, 2026-12-30, branch wt/agenticcoding, commit 40eadad — hybrid drain/cancel, see DECISION memory):
1. Steers DRAIN: turn.rs post-stream block gates on the new StopReason::is_hard_stop (loop_impl.rs) — a bare Steer falls through to the batch; the null-turn + bad-JSON-MAX returns carry a pending steer (were hardcoded None); the bad-JSON retry returns instead of continuing when a steer is pending; the stream-error retry skips Err when a steer is pending (the Err path would drop it).
2. Hard stops RECORD cancelled calls in history: the hard-stop block pushes the assistant message WITH the accumulated tool_calls (truncated args sanitized to "{}" + raw: None, bad-JSON precedent) + one "interrupted: not run (turn stopped)" tool_result message per call id; UI synthetic events unchanged. AMENDS the 63cbc20f spec's "UI-only, no history pushes" choice for hard stops (that choice assumed a re-issue the model could not know to make; it also left dangling raw-echoed tool_calls).
3. Mid-execution GRACE-DRAIN: dispatch_with_interrupt's Interrupt/Cancel arm awaits the pinned future bounded by DRAIN_GRACE_MS = 2000 — completion returns the REAL result (stop_signal still set), timeout drops the future + returns the synthetic "interrupted during execution" result.
4. Review fix (round-1 finding 1, verified round-2): a steer folded into Some(Interrupt)/Some(Compact) now PROMOTES to InterruptWithSteers/CompactWithSteers (loop_impl.rs fold — the old `_ => {}` arm silently discarded it), and the buffered re-injection in turn.rs's merge block runs EVEN under hard_stop (the `if !hard_stop` guard removed) — a steer typed during the grace window or buffered before the Interrupt drives the follow-up turn instead of vanishing. Cancel/Clear keep dropping (documented intent); CancelSuggestion still removes a matching steer under hard_stop.

REGRESSION TESTS (fail without the fix): src/agent/tests.rs — mid_stream_steer_drains_the_announced_tool_call (rewritten from mid_stream_steer_emits_not_run_result_for_announced_tool_call), mid_stream_steer_drains_a_multi_call_batch, mid_stream_interrupt_still_stops_before_the_batch, mid_stream_interrupt_sanitizes_truncated_args_in_history, interrupt_mid_execution_drains_a_fast_tool_with_its_real_result, interrupt_mid_execution_cancels_a_slow_tool_after_the_grace_window, commands_arriving_during_the_grace_window_are_not_lost, interrupt_with_buffered_steer_carries_the_steer; src/agent/loop_impl.rs — fold_suggestion_into_interrupt_promotes_to_interrupt_with_steers, fold_suggestion_into_compact_promotes_to_compact_with_steers, fold_suggestion_into_cancel_still_drops; frontend/src/hooks/useAgentStore.test.ts — "regression (2026-12-30 interrupted turns): interrupt mid-tool-call-stream — terminal card, user follow-up contains only the user's text" (pins the frontend contract; the echo itself was model-side, fixed by 2).
