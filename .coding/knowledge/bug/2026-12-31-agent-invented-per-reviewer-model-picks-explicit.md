BUG (user-reported, 2026-12-30 session plan 72329f2c; fixing under plan d8e7b39d / backlog c8e48f81): the main agent spawned three parallel role:reviewer subagents each on a DIFFERENT explicit model (glm-5.2 arch-perf, glm-5.3-gcp security, deepseek-v4-flash quality) — per-reviewer model assignment is configured nowhere; the agent invented it as "model diversity". The deepseek-v4-flash reviewer failed outright without writing a report (DeepSeek endpoint fragility; recovery needed ask_user + respawn on glm-5.3-gcp) — exactly the failure the configured reviewing model (GLM-5.3) exists to prevent. ROOT CAUSE (three layers): (1) the spawn_agent schema text (src/tool/agent/spawn_agent.rs:166-181) says a reviewer runs on the configured reviewing model "unless `model` is set" — the unless-clause invites the bypass; (2) the tool doc comment (:69-82) says "An explicit `model` arg always wins" — no discouragement; (3) no structural gate: an explicit model on a reviewer spawn flows straight to the forced-model pin at dispatch. FIX (plan d8e7b39d): guidance (schema + doc + prompt closing-sequence/Reviewing text: OMIT the model for reviewer spawns; the configured reviewing model [reviewing → executing → subagent → default] is authoritative) + structural enforcement (reviewer_spawn_gate in src/agent/dispatch.rs: a reviewer spawn carrying an explicit model is denied unless the failed-reviewer retry is sanctioned — ask_user opens the sanction only when a reviewer failure was pending; any reviewer spawn consumes it; the retry path keeps working). Regression tests: reviewer_spawn_gate_denies_ad_hoc_model_picks, reviewer_spawn_gate_allows_the_sanctioned_retry_and_consumes_it, reviewer_spawn_gate_no_model_spawn_consumes_sanction_and_passes, reviewer_spawn_gate_failure_pending_denies_and_preserves_sanction (src/agent/dispatch.rs tests) + the existing pin tests (spawn_agent.rs: reviewer_without_model_arg_pins_reviewing_model, reviewer_falls_back_to_executing_model, reviewer_without_any_configured_model_gets_default).
