BUG (2026-12-31, live twice in one session): a turn in the closing sequence PARKED until the user typed "c", and the outstanding tool call's result slot rendered the user's own nudge text ("c"). Three halves:

(1) PARK — reproduced + fixed (59fc685). The auto-continue None-arm (src/runtime/agent.rs run_turn_with_retry) gated only on AgentLoop::is_workflow_executing() — Reviewing was uncovered, so a turn that ended mid-closing-sequence (review → fix → commit → finish) parked forever. FIX: the gate now uses AgentLoop::workflow_expects_progress() (Executing OR Reviewing), keeping !has_running_descendants() + MAX_AUTO_CONTINUE bounds. Regression test: auto_resume_fires_when_workflow_is_reviewing (src/runtime/agent.rs tests — fails on the old gate with "agent parked; the closing sequence stalls until the user types c", passes after).

(2) ORPHAN/GARBLE — audited, NOT reproducible on current code. The result slot showed "c" (byte-identical to the following user message) and the finish call provably never executed (state unchanged; re-issue succeeded). Audit: mid-stream steers fold WITHOUT breaking the stream (turn.rs:1273-1281) and the batch drains — pinned by passing tests mid_stream_steer_drains_the_announced_tool_call + mid_stream_steer_drains_a_multi_call_batch (src/agent/tests.rs:4628/4801); the between-call safe point breaks only on hard stops (turn.rs:1747); hard stops synthesize "interrupted: not run" results for every remaining call (turn.rs:1756-1771); the UI sweeps orphaned cards with "(interrupted)" (sweepRunningCards, agentEventReducer.ts:1191, tested useAgentStore.test.ts:1467). The incidents' signature matches the PRE-edfff8d9 bug exactly — leading explanation: the running app binary predates the 2026-12-30 merge b128868; rebuild/restart picks up the fix. Residual risk: if it recurs on a current build, investigate the mid-stream provider-error retry path first.

(3) SUBAGENT SELF-CONTINUE (High 1 of the amended round-1 review, found live, fixed in ca7c152) — the ACTUAL mechanism behind the held descendant-park that blocked complete_step ("spawned subagents are still running"): tool-spawned subagents share the main plans dir and Workflow::load_latest() derives their workflow state from the main plan on disk (unchecked steps → Executing, complete + unreviewed → Reviewing), so a closing-sequence reviewer's own loop saw "progress expected" and the auto-continue gate — with no is_subagent guard and no descendants — fired up to MAX_AUTO_CONTINUE (12) synthetic self-continue turns on the finished reviewer: token burn, deliverable-mutation risk (write_review_report — the round-1 reviewer amended its own report on such a turn), and the held descendant-running flag. The Executing variant pre-existed the plan's diff (child-side counterpart of bbd712c9); the Reviewing variant was introduced by (1)'s extension. FIX: the gate gains !is_subagent() — subagents are single-task and ALWAYS park on a normal turn end; the child-completion Suggestion resumes the parent. Regression test: auto_resume_does_not_fire_for_subagents (failed pre-fix with the full 13-call plateau; passes post-fix). Deferred design option (not taken): skip load_latest for parented subagents so they start in Planning — would also remove the state-sharing surprise but changes what get_workflow_state(agent_id) shows for subagents.
