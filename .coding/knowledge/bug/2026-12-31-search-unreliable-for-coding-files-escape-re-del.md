BUG (observed 2026-12-29, plan 72329f2c; fixing under plan 2a78cc3c): locating files under .coding/ via the search tool failed three ways. (1) The auto-delegation escape re-delegated: a .coding/reviews-glob search auto-delegated to memory_search, and re-issuing the IDENTICAL search delegated again (observed twice) — root cause: SearchTool.delegation_state is a single Option<DelegatedKey> (src/tool/agent/search.rs:391) whose doc admits "any other delegating query replaces the key" (:356-359), so an interleaved delegating search breaks an earlier escape. (2) Stale-index false negative: a literal search for 'bf0f71c' with glob .coding/reviews/*.md returned "no matches found (engine: index; 1826 files indexed)" although the file was written minutes earlier — root cause: try_index treats an EMPTY raw fetch as authoritative ("the index covers every searchable file", :867-875), false during the watcher's reindex lag for newly written files (should_search DOES cover .coding/*.md; only the SQLite DBs are excluded); the F10 freshness check only examines files already IN the fetched hits (:884-900), so a file absent from the index is never checked. (3) No directory-listing affordance: read_files errors on directories ("is a directory, not a file") and search's MAX_MATCHES=100 cap + "and more matches" + console display truncation make enumerating a directory unreliable. FIX (plan 2a78cc3c): (a) delegation_state → a bounded Vec<DelegatedKey> set (cap 32, dedup) — once a query delegated, identical re-issues never re-delegate in-session; (b) the empty-raw branch returns None (→ walk) — an empty fetch can never prove absence; hits keep the fast path + F10; (c) read_files returns a sorted directory listing (name/type/size/mtime) for directory specs. Regression tests: index_empty_fetch_falls_through_to_walk_for_new_files, delegation_escape_survives_interleaved_queries, walk_cap_narrower_reissue_returns_tail_files (pin), directory_path_returns_listing.
