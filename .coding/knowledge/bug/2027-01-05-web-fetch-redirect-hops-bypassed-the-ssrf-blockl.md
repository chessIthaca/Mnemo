title = "web_fetch redirect hops bypassed the SSRF blocklist — re-gated per hop"
created = "2027-01-05"
+++

Symptom: web_fetch followed up to 5 HTTP redirects automatically (reqwest redirect::Policy::limited(5)) without re-running the SSRF internal-address blocklist on redirect targets — the gate ran exactly once, on the initial URL (src/tool/agent/web_fetch.rs). A public URL answering 302 → http://169.254.169.254/... (cloud metadata or any internal host) was fetched, bypassing SSRF protection; documented as a known residual (2026-12-23 security review LOW, backlog d187addc).

Root cause: reqwest's Policy::limited(5) follows redirects inside send(); the manual gate in execute() ran only before the initial request, so hop targets were never validated.

Fix (src/tool/agent/web_fetch.rs, final design after review round): client built with redirect::Policy::none(); fetch_following_redirects() follows up to MAX_REDIRECTS=5 hops manually, running ensure_public_http_url() (http/https scheme + hostname gate via spawn_blocking, fail-closed unwrap_or(true)) at the TOP of the loop body on EVERY requested URL — start included — so the function is self-contained (no caller-side gate precondition; execute still pre-gates the initial URL as defense-in-depth). Exceeding 5 hops → clear "too many redirects" error. reqwest parity kept: only 301/302/303/307/308 with a Location header are followed; 3xx without a Location OR with an unjoinable Location (e.g. invalid port) returned as-is ("the original response is still valid"); relative Locations resolve via Url::join. The gate is injectable (fn(&str) -> bool — production: hostname_resolves_to_internal) because the production gate blocks loopback, making a local stub server unreachable otherwise.

Regression tests (web_fetch.rs tests, RedirectStubServer on tokio TcpListener): redirect_to_internal_address_is_refused (302 → 169.254.169.254 refused with the SSRF error, exactly 1 request — target never contacted), redirect_to_non_http_scheme_is_refused (302 → file:// refused), unjoinable_redirect_location_returns_response_as_is (invalid port → 3xx as-is), too_many_redirects_errors (exactly 6 requests then error), redirect_to_public_address_succeeds (legit redirect still followed), ensure_public_http_url_gates_ips_and_schemes (IP literals — DNS-free/deterministic). Mutation-checked twice (bottom-gate and top-gate placements): disabling the gate makes redirect_to_internal_address_is_refused fail. Review: FINDINGS (2 low — unjoinable-Location erroring, ungated start) → both fixed → verification PASS (.coding/reviews/2027-01-05-web-fetch-redirect-ssrf-verification.md). Known residual: DNS rebinding (TOCTOU) stays documented in-code.
