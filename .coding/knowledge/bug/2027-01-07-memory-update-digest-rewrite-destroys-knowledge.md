Symptom: memory_update on a knowledge-backed record with digest-style content (shorter than the file body + a knowledge-path pointer tail) replaced the truth file's body — .coding/knowledge/spec/2027-01-07-backlog-item-status-plan-lifecycle-failed-means.md went −19/+1 on 2027-01-09 (restored from HEAD); three committed files carried digest tails (spec/2026-12-21-multi-provider-prompt-caching, bug/2027-01-07-serving-layer-strips, decision/2026-12-21-message-toolcall-construction). Root cause: KnowledgeStore::update (src/memory/knowledge.rs) wrote new_body verbatim after parse — no shape guard; rows are derived from files by the indexer, so digest-shaped input is incoherent for a file update (a row-only update would diverge and be clobbered by reindex). Fix (plan e8565822, backlog 63f882c9): update() refuses digest-shaped replacements via looks_like_row_digest (strictly shorter than the current body AND last non-empty line contains ".coding/knowledge/" and ends ".md") with a contract-teaching error naming the file; false positives are safe (refusal, never data loss). The three tail files repaired from git history. Regression test: update_refuses_digest_style_content_that_would_shrink_the_file (src/tool/memory/mod.rs).

Dating note (review round-1 LOW 2): the file date (2027-01-07) is the memory store's write-time stamp — every knowledge record written this session carries it (e.g. the load_tools HOW record); the incident/fix date 2027-01-09 follows the plan (e8565822), the backlog item (63f882c9), and the review report, while git and the review reports read 2026-09-10. The environment's date surfaces disagree; the file keeps its stamped date (renaming would orphan the derived row) and the body keeps the narrative dates.
