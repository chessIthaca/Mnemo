Symptom: reviewer subagents finished without writing reports and the harness finish notification was identical either way ("read its report and combine the results into a plan", path only sometimes present) — the parent needed shell forensics to learn no report existed; write_review_report's verdict-line validation rejected reports with a static error showing neither the expected format verbatim nor the received first line, so reviewers guessed and some died report-less (live-observed 2026-12-30, plan 72329f2c: 2 of 5 reviewers, two model families). Root cause: (1) static verdict rejection (write_review_report.rs); (2) the report-less notification said "read its report" and the failed-reviewer protocol gated on !success (events.rs + console.rs) so cleanly-finishing report-less reviewers got the misleading generic text; (3) tool_error_count resets on ANY tool success, so interleaved write_review_report failures never tripped MAX_RETRIES; (4) the tool returned the canonicalized \\?\ absolute path and trusted the reviewer-invented date prefix. Fix: verdict + append errors quote the received/existing first non-blank line; filenames date-prefix from the system clock (stale prefixes stripped/replaced; cross-midnight appends find the unique dated variant); returned path is project-relative ".coding/reviews/<file>"; the report-less notification says "no report was written"; the failed-reviewer protocol fires for ANY report-less reviewer (role==reviewer && no report, regardless of outcome) including the parent latch; REVIEW_REPORT_MAX_FAILURES=3 dedicated counter (reset only on write_review_report success) aborts the turn with a distinct final error; finish resolves the report path as-given → basename under the reviews dir. Regression tests: verdict_rejection_names_received_first_line, stale_date_prefix_normalized_to_today, append_with_stale_name_lands_on_normalized_file, append_after_date_rollover_finds_dated_variant, generic_text_when_no_report_path, reportless_reviewer_gets_failure_text_even_on_success, review_report_failures_abort_with_distinct_error, finish_resolves_project_relative_report_path — all confirmed failing pre-fix, passing post-fix; both suites green (root 2031/0, src-tauri 232/0).
