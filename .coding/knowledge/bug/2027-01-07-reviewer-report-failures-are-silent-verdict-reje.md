Symptom: reviewer subagents finish without writing reports and the harness finish notification is identical either way ("read its report and combine the results into a plan", path only sometimes present) — the parent needs shell forensics to learn no report exists. write_review_report's verdict-line validation rejects reports with a static error showing neither the expected format verbatim nor the received first line, so reviewers guess; some recover on retry, some exhaust their turns and die report-less (live-observed 2026-12-30, plan 72329f2c: 2 of 5 reviewers, two different model families). Root cause (four, all verified in code): (1) the verdict rejection (src/tool/agent/write_review_report.rs:228-230) is a static string — no received-first-line feedback; (2) completion_suggestion_text's None arm (src/runtime/turn_resolve.rs:256-259) says "read its report" with no report present, and the failed-reviewer protocol gates on !success (src-tauri/src/ipc/events.rs notify_parent_on_completion + src-tauri/src/console.rs notify_parent) so cleanly-finishing report-less reviewers get the misleading generic text; (3) tool_error_count resets on ANY tool success (src/agent/turn.rs:1139-1140), so write_review_report failures interleaved with reads never trip MAX_RETRIES — no dedicated accounting, the reviewer finishes silently; (4) the tool returns the canonicalized absolute path (verbatim \\?\C:\AgenticCoding alias) and trusts the reviewer-invented date prefix (stale dates live-observed: 2026-12-23/24 names written 2026-12-29/30). Fix (plan 7da7476b): verdict + append errors quote the received/existing first non-blank line; filenames date-prefix from the system clock (stale date-shaped prefixes stripped and replaced with today, via format_epoch_date); returned path is project-relative ".coding/reviews/<file>"; the None-arm notification says "no report was written"; the failed-reviewer protocol fires for ANY report-less reviewer (role==reviewer && no report, regardless of success); REVIEW_REPORT_MAX_FAILURES=3 dedicated consecutive-failure counter (reset only on write_review_report success) aborts the turn with a distinct final Error; finish resolves the report path as-given → basename under the reviews dir. Regression tests: verdict_rejection_names_received_first_line, stale_date_prefix_normalized_to_today, append_with_stale_name_lands_on_normalized_file, generic_text_when_no_report_path, reportless_reviewer_gets_failure_text_even_on_success, review_report_failures_abort_with_distinct_error, finish_resolves_project_relative_report_path — all 10 confirmed failing pre-fix.
