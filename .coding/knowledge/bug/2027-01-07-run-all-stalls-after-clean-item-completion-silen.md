Symptom: Run-all stalls after a cleanly-completed item — the next pending item never dispatches and the session sits idle until the user nudges; even the nudged turns' resolutions don't dispatch. Live incident (2026-09-08, this session): item a117e827 (plan de1f874b) completed through the full closing sequence (round-3 review PASS, commits 739c68a/dbc1367/982d0b1, finish → Complete); the turn-resolution gate stamped it done (null note — the normal path) but NO next item dispatched despite 10 eligible pending items (all live, non-deferred, null notes — no gate arm left any trace in the queue). Two user nudges produced responding turns but no dispatch. Fourth recurrence of the class (e33a07fd fixed the Complete-state gate; 8a6bcece the slid+requeued arm; a6a7727a the Planning park; 5c33e945 the manual-'c' parks) — each fix closed one arm; the class survives.

Root cause (structural, confirmed by code reading; the exact arm of the incident was unidentifiable from artifacts because every candidate arm logged only to stderr — invisible in the launched app): the dispatch chain after an item resolution has multiple arms that fail SILENTLY: (1) the busy-guard deferral (src-tauri/src/ipc/run_all.rs) returns Ok relying on "the in-flight turn's terminal event re-invokes on_main_turn_resolved" — an assumption that breaks when the busy thing is not a main-agent turn whose resolution re-drives the main lane (a spawned lane's resolution goes through on_spawned_turn_resolved; a stale/zombie descendant fires nothing); (2) the between-items auto-compact window holds the dispatch behind wait_for_compact_signal for up to AUTO_COMPACT_WAIT = 600s with only a timeout backstop; (3) run_all_dispatch_next's Err returns were eprintln'd by callers and swallowed. Once any arm stalls, the ONLY re-drive is a future main-agent turn resolution — an idle main agent produces none. Eliminated by evidence: no-eligible end_run (10 eligible items — selector verified), checkpoint failure (would annotate — all notes null), the compact chain's own failure handling (timeout → proceed), the intervention path (timing implausible).

Fix (plan 0ed9d24f, shipped on wt/agenticcoding; review 2026-09-09-run-all-stall-heartbeat-review.md FINDINGS 0H/6L — all six fixed): (1) run_all_diag — a persistent, epoch-timestamped log line for the dispatch chain, writing .coding/logs/run-all.log (dev) / temp_dir mnemo-run-all.log (packaged) — the Q2-fixed diag_line pattern; EVERY dispatch-chain arm routes through it (the busy-guard deferral, the became-busy-during-checkpoint deferral, the compact chain's seven outcomes, the dispatch-Err callers in on_main_turn_resolved/on_spawned_turn_resolved/drain_spawned_on_exit, the heartbeat); the bare eprintln!s in the touched arms were dropped (GUI-subsystem panic risk + duplication — run_all_diag keeps a swallowed stderr writeln for console parity). (2) run_all_heartbeat (RUN_ALL_HEARTBEAT = 30s) — while a run is armed, re-drives the dispatch when run_all_stalled (armed, NO current item, not compacting, stop NOT requested, main agent idle, eligible item exists) WITHOUT any turn resolution; never ends runs; spawned for the run's lifetime in backlog_run_all, bound to the run's generation (state.backlog.run_generation, bumped at each arming) so a previous run's heartbeat cannot survive into a successor. (3) DEVIATION from the plan: the separate one-shot delayed retry (~60s) after a busy-guard deferral was DROPPED — spawning it from inside run_all_dispatch_next is unbreakable async recursion (an opaque-type cycle, E0391 — even Box::pin type-erasure fails because the Box's type argument references the opaque type), and the heartbeat subsumes it at a better cadence (30s < 60s); the plan's acceptance line "a deferred busy-guard dispatch recovers without a new turn resolution" is met by the heartbeat. KNOWN LIMITATION (documented in the docs + the deferral log line): the heartbeat skips busy runs — a zombie descendant keeping has_running_descendants true forever stalls the run identically to today's behavior; the persistent deferral line makes that arm diagnosable. Regression tests (source-contract, fn_body idiom, all verified red pre-fix): heartbeat_redispatches_a_stalled_run_without_turn_resolution, heartbeat_spawned_for_the_runs_lifetime, busy_guard_deferral_is_logged_persistently, stall_arms_write_the_persistent_run_all_log.
