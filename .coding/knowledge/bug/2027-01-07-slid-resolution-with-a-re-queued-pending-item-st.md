BUG (backlog 8a6bcece, plan af1058ee, found as review LOW-3 2027-01-08 in the e33a07fd closing review .coding/reviews/2026-09-08-run-all-stall-fix-review.md): slid resolution with a re-queued (Pending) item still stalls the run.

Symptom: with the run active, the in-flight item externally re-queued to Pending mid-run (the 5bb1e4cd-style .coding/backlog.jsonl edit — the store sees Pending; the in-memory current_item pointer still references it) AND the completing turn's resolution slid (the e33a07fd slide: the finish turn's Finished deferred because a descendant still runs, then discarded when the descendant's completion notification starts a new turn), the run never dispatches the next item — a manual restart is required.

Root cause: the notification turn lands at (Complete, false) with the item Pending. closed_earlier (src-tauri/src/ipc/run_all.rs:4476-4480, the e33a07fd landed arm) requires item.status == InFlight → false. The match falls to the waiting arm (:4601) which annotates plan_open_note + RETURNS — and Complete is a RESTING state: no transition ever fires again, no auto-continue, nothing ever re-checks → the run waits forever. The spawned lane mirrors exactly (:3797-3806 closed_earlier requires InFlight; waiting arm :3948 exits early → the lane never resolves → the run waits for the lane). Pre-existing (the same scenario stalled pre-e33a07fd too; the e33a07fd fix strictly improved — the InFlight variant recovers via the landed arm).

Fix: a dedicated arm at (Complete, false) gated on item.status == Pending, in BOTH on_main_turn_resolved and on_spawned_turn_resolved, placed BEFORE the waiting arm: snapshot (note, plan_id) under the store lock, consult orphan_work_landed / orphan_work_landed_at (the drain's done-orphan evidence) WITHOUT the lock, re-verify still-Pending under the lock; landed → transition Done with the drain's note-preserving suffix "work already landed (plan complete + commits after the checkpoint) — auto-resolved done, not re-dispatched" (the spawned lane also lands the branch + removes the worktree); not landed → no transition, no annotate (the re-queue note is recovery evidence — the bba2c82d discipline), fall through to the tail's unconditional pointer clear + dispatch next (the item is already Pending — eligible for re-dispatch). The 2026-08-20 never-planned hole stays plugged: the landed predicate requires a plan_id, so a Pending item with no plan_id never resolves Done.

Regression tests (source-contract, red-first): slid_resolution_with_requeued_pending_item_dispatches_next (on_main_turn_resolved — the arm precedes the waiting arm, gated on Pending, consults orphan_work_landed, Done flip gated on landed && still_pending, no early return) + slid_resolution_spawned_lane_requeued_pending_recovers (on_spawned_turn_resolved — the same + orphan_work_landed_at + land_spawned_branch + remove_worktree).
