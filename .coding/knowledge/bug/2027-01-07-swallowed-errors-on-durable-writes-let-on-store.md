Symptom: durable-write failures were silently swallowed with no trace. (a) The plan-completion semantic-memory write (src/agent/turn.rs, store.write inside tokio::spawn in emit_workflow_state) dropped its Result — a failed memory write vanished silently. (b) Config save_all's rollback (src/config/mod.rs) dropped restore_from_backup Results — a failed rollback left a possibly half-renamed config set with no trace, and the returned error told the user nothing about the half-committed state. Two same-class residuals (store.record_tool_event, store.record_request_stats in turn.rs) were fixed in the review round (LOW 1). Root cause: `let _ =` discarding Results on durable writes — fire-and-forget was chosen so capture never blocks/breaks the turn, but the failure paths had no logging channel, and the rollback had no error-collection path. Fix (plan 8b5f37fb, quality review LOW 6): log on Err at all four turn.rs sites (eprintln with the "mnemo:" prefix, fire-and-forget semantics unchanged); extract rollback_partial_commit + rollback_with_restore (DI over the restore fn — real rename-failure injection is not cross-platform: Windows rescues/allows dir-over-file renames Unix rejects) + describe_rollback_failure (empty failures → original error unchanged; non-empty → names each failed path + the half-committed warning). Regression tests: rollback_collects_restore_failures, rollback_clean_when_restores_succeed, describe_rollback_failure_without_failures_returns_original, describe_rollback_failure_with_failures_names_paths (src/config/mod.rs tests; written first — failed to compile against the swallowing code, the reproduce step).
