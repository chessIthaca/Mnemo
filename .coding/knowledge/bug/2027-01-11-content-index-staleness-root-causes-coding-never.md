ROOT CAUSE of content-index staleness (diagnosed 2027-01-25 from the user's report "there is no one else changing files, other than mnemo, so it is a bug"). TWO mechanisms, both from Mnemo's own writes.

MECHANISM 2 — INDEXED BUT NEVER WATCHED — **FIXED** by plan 2a2ae0aa (2027-01-25) on branch wt/mnemo. The defect: `should_search` (src/tool/agent/search.rs) accepted every `.coding/` file, while `is_indexable_path` (src/codegraph/watcher.rs) rejected ANY path with a `.coding` component (blanket rule, was line 61: `is_ignored_component(name) || name == ".coding"`), so knowledge/plan/review/backlog writes fired NO watcher event and their FTS rows refreshed only when an unrelated non-.coding edit triggered a pass — permanently stale in an artifact-heavy session, contradicting the watcher's own "mirrors walk_searchable's coverage" contract.
THE FIX (make the two sets equal by construction): one shared `pub(crate) fn is_coding_data_file(rel: &Path) -> bool` in src/tool/agent/search.rs (extracted from the inline `const DATA_FILES` block that used to live inside `should_search`), now called by BOTH `should_search` (what gets indexed) and `watcher::is_indexable_path` (what triggers a pass). `.coding/` artifacts (knowledge, plans, reviews, skills, backlog.jsonl, stack.json, instance.json) ARE watched; ONLY the app's SQLite store family (codegraph.db, memory.db + -wal/-shm/-journal) stays excluded — the sole exclusion the self-trigger-loop argument needs, because the graph DB is the only thing an index pass writes itself. The old second rationale (bookkeeping churn "all session") was disproved: instance.json is written ONLY on launch (src/instance_marker.rs, no heartbeat) and stack.json only on plan-step transitions, both debounced into one pass per burst.
REGRESSION TEST: `watcher_reindexes_on_new_coding_artifact` (src/codegraph/watcher.rs) — spawns the watcher on a tempdir with a 100 ms debounce, writes `.coding/knowledge/live-artifact.md`, polls `search_content("codingartifactmarker", 10)` for 200 x 50 ms; FAILS on the pre-fix code (no event, no pass) and passes after. Re-pinned alongside it: `is_indexable_path_accepts_any_file_and_rejects_ignored` (the `.coding/plans/stack.json` case inverted to TRUE; `.coding/codegraph.db` + a memory.db-wal case stay FALSE). Suite green: 2715 passed / 0 failed / 5 ignored (+19 integration, +1 doc-test).

MECHANISM 1 — THE 800 ms DEBOUNCE — remains BY DESIGN. src-tauri/src/main.rs:2066 spawns `GraphWatcher::spawn(graph, root, Duration::from_millis(800))`; watcher.rs debounce_loop sleeps that quiet period after the last event of a burst before running a pass, so the window is 800 ms + pass time. Deliberate burst coalescing, not a defect; it is covered by the adaptive inline repair shipped under plan 90fab97e (STALE_REINDEX_CAP 32 + a 500 ms budget), which repairs a small staleness inside the query instead of walking.

STATUS: both plans' work sits on wt/mnemo (NOT merged; main is ruleset-protected 23755694 -> PR path). User-facing consequence for the dashboard/token questions of that session: none — this is index freshness only.
