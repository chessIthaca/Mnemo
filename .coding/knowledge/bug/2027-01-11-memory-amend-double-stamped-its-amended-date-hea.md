title = "memory_amend double-stamped its 'Amended <date>:' heading and records had no in-tool repair path"
created = "2027-01-11"
+++

SYMPTOM: `memory_amend` prefixed its own "Amended <stamped_date>: " heading onto a caller paragraph that already opened with one, so two live records ended up with a doubled, contradictory heading ("Amended 2027-01-11: Amended 2027-01-14: …"). Repairing them needed the constitution's last-resort shell fallback, because the file tools refuse `.coding/knowledge/**` by design and amend is append-only.

ROOT CAUSE (two, plan ecdd67ac, commit on wt/mnemo): (1) `KnowledgeStore::amend` (src/memory/knowledge.rs) formatted `"{body}\n\nAmended {stamped_date}: {paragraph}"` unconditionally — no strip of a self-supplied heading, so the caller's date could contradict the stamp; (2) no in-tool way to REMOVE text: `update` is full-body (transcription-risky, and its `looks_like_row_digest` guard refuses any candidate shorter than the body that ends in a `.coding/knowledge/…md` pointer tail — exactly the shape a shrinking repair produces).

FIX: (a) `KnowledgeStore::strip_self_headings` + `leading_self_heading` + `stamp_shaped` strip a leading stamp-shaped heading off the FIRST line before `amend` prefixes its own — `amended`/`amendment` (any case, word boundary) + a ≤120-char head that is a parenthesized group ("Amendment (…):") or a leading 4-digit year with a date-shaped tail; the head ends at the first colon that yields such a shape (a colon inside the group no longer truncates it — review round-1 LOW 1), a heading line with no colon is stripped whole (text taken from the next line), stripping repeats (doubled chains collapse) and preserves every other line; prose is returned verbatim; a bare heading strips to empty and `amend` errors "nothing to amend". (b) `replace_unique` + `KnowledgeStore::replace_in_body` + `memory_update`'s `find`/`replace_with` mode (src/tool/memory/mod.rs `repair_by_id`): exactly-one-match, body-only (front matter never matched and re-rendered identically), refuses blank/absent/ambiguous find and a body-emptying result, refuses superseded records (history is never edited), reindexes on both the knowledge-file and DB-only paths; deliberately outside the row-digest guard, documented as such ("cannot do so *silently* — the caller must spell out the exact text it removes"). The amend result appends "NOTE: stripped {n} self-supplied amendment heading(s) …" so a strip is never silent.

TESTS (fail without the fix): `amend_strips_self_supplied_heading_and_stamps_its_own_date`, `strip_self_headings_matches_stamp_shapes_only`, `replace_unique_requires_exactly_one_match`, `replace_in_body_repairs_record_text_without_digest_guard_interference`, `update_targeted_replace_repairs_a_knowledge_record`, `update_targeted_replace_argument_rules`, `update_targeted_replace_works_on_db_only_records`, `amend_result_reports_a_stripped_self_heading`.

RESIDUAL (accepted, disclosed in the doc): a time-like stamp head ("Amended 2027-01-14 12:30: x") strips at the time colon, leaving "30: x" — pre-existing, no body text lost, cleanable with the new repair mode.
