Symptom: streaming requests to the Meta muse endpoint (https://api.meta.ai/v1/chat/completions) failed terminally with HTTP 400 "'oneOf' is not permitted" (param=parameters, type=invalid_request_error) whenever the advertised tools included create_plan/update_plan; retries exhausted and the agent turn died (observed live 2027-01-18, backlog eba239b8). Root cause: muse's OpenAI-compat layer rejects `oneOf` outright inside tool `parameters`; the only emitted schemas carrying it were the steps items unions at src/app/tool/workflow/plan.rs:703 (create_plan) and :1116 (update_plan) — verified by literal search (oneOf in src/**/*.rs matched exactly those two emitted sites plus the mirrored walker fixture at src/tool/mod.rs:1492 and walker key lists). Fix (user-confirmed direction): switched both unions to `anyOf` — semantically correct, the unions are permissive (a step is a string OR {header, body}); oneOf's exactly-one-match constraint was never intended. Mirrored in the drop_stringified_nulls fixture stringified_null_dropped_through_union_branches (src/tool/mod.rs, schema key + comment). No walker changes needed — verified by reading: drop_stringified_nulls (src/tool/mod.rs:239) and the strict normalizer normalize_in_place (src/provider/strict.rs:87) recurse for key in [anyOf, oneOf, allOf] symmetrically and never rename the container; strict mode already emits anyOf for type widening (strict.rs:73). Regression test: plan_tool_schemas_emit_anyof_not_oneof in src/app/tool/workflow/plan.rs tests — builds CreatePlanTool/UpdatePlanTool via make_workflow(tempdir), serializes .schema().parameters (the exact bytes non-strict endpoints receive via pass_through), asserts contains "anyOf" and NOT "oneOf" for both tools. Proven RED pre-fix (2027-01-18, panicked showing oneOf in serialized create_plan parameters, exit 101), green post-fix. Plan 3354cbc5, branch wt/mnemo. Residual oneOf occurrences in src/ are walker key lists/docs only (src/tool/mod.rs:226/:239, src/provider/strict.rs:59/:87/:208, strict.rs:422 test comment) — no emitted tool schema carries it.
