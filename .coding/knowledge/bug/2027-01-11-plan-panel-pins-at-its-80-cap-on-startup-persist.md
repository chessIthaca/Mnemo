title = "Plan panel pins at its 80% cap on startup — persisted px width never re-normalized"
created = "2027-01-11"
+++

SYMPTOM (user, 2027-01-16): on app open the right panel (Plan tab — the startup default, useAgentStore.ts:660-666) fills as much of the app as it can, every time. ROOT CAUSE: the panel width is persisted as ABSOLUTE px (localStorage mh.rightPanelWidth; 831px measured in this box's WebView2 leveldb) and only clamped at RENDER time to [300, window.innerWidth×0.8] (frontend/src/components/layout/RightPanel.tsx:31-34); the drag path (App.tsx ResizeHandle, ~823-917) clamps at commit, so the stored value reflects a PAST larger window and is never re-normalized. The startup window-geometry clamp (commit c9da825, plan 9ff59133 — the fix for the tiny-window bug, memory da74019a) restores the window fitted/floored (min 800×560, windowRestore.ts RESTORE_MIN_*): with the window ≤ ~1040px wide, 831 ≥ 0.8×innerWidth → the panel renders PINNED at its 80% ceiling. The clamp fixed the window half of da74019a but not the panel half — the px width never re-normalizes, so it pins on every open until the window is resized or the panel re-dragged. FIX DIRECTION: persist the width as a fraction of window.innerWidth (clamped ~[0.15, 0.5]) or clamp+re-persist at restore; also cap by a main-column minimum (innerWidth − ~480) instead of 0.8 — the 800px window floor + 0.8 cap allows a 640px panel with only ~160px of chat. Files: frontend/src/components/layout/RightPanel.tsx, frontend/src/hooks/useAgentStore.ts:664,814-821, frontend/src/App.tsx, frontend/src/lib/windowRestore.ts.

Amended 2027-01-11: SECOND SYMPTOM (user, 2027-01-16): resizing the overall window keeps the tools panel at its absolute px width (only the clamp bounds — 300px floor / 0.8×innerWidth ceiling — drag it) while the flex-1 chat column (App.tsx:745) absorbs the entire delta; the panel should track the window instead. Same root cause (absolute-px persisted + rendered width, never a fraction): the fraction-based fix (persist width as a fraction of window.innerWidth, clamped ~[0.15, 0.5], guaranteed chat-column minimum) covers BOTH faces — the startup 80%-cap pinning and the resize non-tracking.
