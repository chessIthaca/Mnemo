BUG: Second production mnemo instance renders a blank white window: every instance passes an EMPTY WebView2 user data folder, so all resolve the SAME default UDF %LOCALAPPDATA%\com.mnemo.app\EBWebView (SDK default via AUMID — NOT {exe}.WebView2); one UDF holds only one live browser process, so later instances' sessions never initialize while their windows exist and render blank. Reproduced live 2027-01-13: host 440 + A 33660 + B 28976; msedgewebview2 count stuck at 25 (no new browser processes); B's window PrintWindow capture 99% near-white. Cause in-tree: wry vendor/wry/src/webview2/mod.rs:348 passes &data_directory.unwrap_or_default(); no data_directory anywhere in app code (tauri 2.11.5 webview/mod.rs:392-424 resolves config only). Fix: per-instance UDF — first keeps the default (Windows named mutex keyed on the resolved UDF path), every additional instance gets %LOCALAPPDATA%\com.mnemo.app\WebView2\mnemo-<pid> (own browser process) via webview_udf::apply wrapped on all three builder sites (main.rs:248, browser_webview.rs:330, :411), helpers in src/webview_args.rs. Regression tests: src-tauri/tests/webview_udf.rs (RED verified), webview_args unit tests, mutex round-trip. Plan 5ce69497; evidence .coding/analysis/second-instance-before.png.
