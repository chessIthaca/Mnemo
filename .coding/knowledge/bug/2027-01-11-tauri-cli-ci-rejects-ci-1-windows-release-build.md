Symptom: v0.1.1 tag build run 35514715816 (2026-09-20), windows job step "Tauri build (unsigned installers)" (`npx tauri build`) exited 1 in ~2s — before the frontend rebuild even started, so no installers, release job skipped. Root cause: the workflow's global `env: CI: "1"` — the tauri CLI's `--ci` flag is a clap bool that reads the CI env var (`[env: CI=]` in `tauri build --help`); clap rejects '1' (possible values: true, false) → instant parse error `error: invalid value '1' for '--ci'`. Fix: `CI: "true"` in .github/workflows/build.yml (with inline comment; keeps every other CI-aware tool's truthiness while satisfying clap). Regression test: `build_workflow_ci_env_is_clap_bool` in tests/integration/ci_workflow.rs — asserts every `CI:` env assignment in build.yml is "true"/"false"; proven failing pre-fix (line 36 = "1"), passing post-fix. Local repro: `$env:CI="1"; npx tauri build` → the exact CI error; with CI=true the parse is clean (`--help` shows `[env: CI=true]`). NOTE: the macOS leg of the same run (`cargo test --workspace`, exit 101 at ~3 min) is a SEPARATE cause — no Rust code reads the CI env var; still under diagnosis. Landed on wt/mnemo (plan 2327546a).
