Symptom: truncated/malformed tool-call argument payloads reject with bare messages ("ops is required", "not valid JSON (…) Please retry with a correctly-formed JSON object") that never show what the executor received → the model blind-retries the identical payload and fails identically (observed 2027-01-17 wt/mnemo jobs 3a.6/3a.8: repeated "ops is required" rejections + two identical timeout corrections on ~2.5-4 KB multi_edit/file_edit payloads; each retry a full round-trip). Root cause: every argument-rejection producer discards the received payload — dispatch.rs:219 from_str Err arm drops tc.arguments; sanitize_arguments_error (error_message.rs:52) names fields but carries no bytes/keys/tail; post-parse validators (multi_edit.rs validate_files :111/:126-131; file_edit.rs prepare_edit old_string-empty :236-245 — validate_ops's "ops is required" :563 is unreachable behind the ops.is_some() gate) run after the Value is consumed so add nothing. Emission-decay backdrop (model believes it sent the full payload): .coding/knowledge/bug/2026-12-20-code-bearing-tool-payload-emissions-degrade-unde.md. Fix (plan 81a1b70d): enriched producers — sanitize_arguments_json_error (parse path: kind Syntax/Eof, byte offset, received-N-bytes, ≤120-char received-tail, truncation remedy) + sanitize_arguments_error_with (schema path: received bytes/keys/tail + gated truncation remedy), wired at dispatch.rs + swept over all from_value sites; validators thread a captured received context; pinned edit_ops.rs:186-207 messages untouched. Regression tests: arg_shape_rejections_carry_received_bytes_context (multi_edit.rs), old_string_empty_rejection_carries_received_bytes_context (file_edit.rs), + error_message.rs mid-string/mid-brace truncation tests.
