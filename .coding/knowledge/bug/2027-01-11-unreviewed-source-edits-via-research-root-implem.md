SYMPTOM (code-reading finding, 2027-01-11, not yet reproduced by a test): source edits can land with NO review by nesting — a research ROOT pushes an implementation SUB-plan, edits source, completes everything → the workflow goes to Complete with `reviewed = true` and no reviewer ever saw the diff. No commit step runs either, so those edits sit in the tree until a later plan's commit sweeps them in.

ROOT CAUSE — the two decisions key on DIFFERENT plans:
- The write filter keys on the ACTIVE plan: `Workflow::allowed_tools` (src/workflow/mod.rs:415-423) narrows to `ToolFilter::ExecutingResearch` only when the top-of-stack plan is Research — the comment there explicitly endorses the nested case ("a research root may push an implementation sub-plan, and that sub-plan does need to write").
- The review decision keys on the ROOT plan: `Workflow::complete_step` (src/workflow/mod.rs:824-849) pops a finished sub-plan "regardless of kind (sub-plans never trigger the review sequence)" (:830-834) and only the ROOT's kind selects the transition — Implementation/BugFixing → Reviewing, Research → Complete with `reviewed = true` (:839-848).
So the direct case (a research plan editing source itself) is blocked by `ExecutingResearch` (src/tool/mod.rs:411-425 denies file_edit/file_write/file_append/convert_line_endings), but the nested case walks around it.

FIX DIRECTION (option D): when an Implementation/BugFixing sub-plan completes under a root that is not review-triggering, mark that root review-required so the nesting path lands in Reviewing at the root's completion. Verify by test (create a research root, push an implementation sub-plan, complete both → expect Reviewing, not Complete).

RELATED WART (option A, independent): the research restriction is drawn at TOOL level, not PATH level, so a research plan cannot write its own analysis artifacts with the file tools — it must fall back to shell (the code tolerates this: "NOT a security boundary: shell stays visible ... a determined shell call can still write a file") or be misfiled as an implementation plan. Precedent: plan c43ad4a3 (round-6 cache analysis) was filed as implementation precisely because "a research plan cannot write its own deliverables by construction".

NOT a defect: the `plan.kind`-independent ADVERTISED schema (file_write is still listed for research plans — `PlanFrozen` for every active plan since 2027-01-11, frozen for prefix-cache stability, measured 6,016-token collapse) — that is deliberate; enforcement is dispatch-only, which is why an attempted write looks allowed and is rejected at call time.
