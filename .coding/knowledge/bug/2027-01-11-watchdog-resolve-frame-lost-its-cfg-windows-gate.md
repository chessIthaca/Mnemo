Symptom: v0.1.1 tag build run 35514715816 (2026-09-20), macOS job step "Rust tests (workspace, macOS compile validation)" (`cargo test --workspace`) exit 101 at ~2m53s — E0425 "cannot find type HANDLE/SYMBOL_INFO/IMAGEHLP_LINE64" and "cannot find function SymFromAddr/SymGetLineFromAddr64/ensure_symbols_ready/module_name_for" at src-tauri/src/watchdog.rs:804-843. Windows leg compiled the same code green (types in scope). Root cause: `resolve_frame`'s doc comment got separated from the function; the `#[cfg(windows)]` meant for it mis-attached to `module_name_for` (which already carried its own gate) — leaving `resolve_frame` completely ungated while referencing cfg(windows)-gated types/functions that vanish on non-Windows targets. Fix: moved the doc comment + `#[cfg(windows)]` down to `fn resolve_frame` (watchdog.rs ~L796-804); its only caller `capture_thread_stack_once` was already gated, so nothing dangles. Regression test: `watchdog_windows_only_items_stay_cfg_gated` in src-tauri/tests/gating.rs — a textual guard scanning watchdog.rs top-level items (fn/struct/static/const/impl) for Windows-only identifiers (DbgHelp/threading surface + the gated helper names, comment lines stripped) and asserting a `#[cfg(windows)]` attribute within the preceding 10 lines; proven failing pre-fix (flagged line 804), passing post-fix; runs on BOTH CI legs via `cargo test --workspace`. Diagnosis path note: the CI log was UI-truncated and all raw-log endpoints need auth — the user pasted the compiler errors from the downloaded archive. Landed on wt/mnemo (plan 2327546a).
