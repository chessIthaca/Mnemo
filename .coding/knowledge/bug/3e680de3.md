Symptom: User-reported (2027-01-07): the reasoning-effort shown in the status bar does not reflect the effort level of the model chosen automatically. When the active model is auto-selected / resolved per-context (or carries a per-model reasoning_effort override), the status bar's effort indicator shows a stale or wrong value — the toolbar's last manual choice or the ENDPOINT-level default — instead of the effective effort of the model actually in use. Repro: configure models with different reasoning_effort values (per-model ModelSpec.reasoning_effort in endpoints.toml, or per-context [models.*] ModelRef.reasoning_effort), let auto-selection pick one, observe the status bar effort. Root cause: StatusBar.tsx effectiveEffort (~:157-160) reads agentEfforts[activeAgent] (toolbar choice) ?? effortForEndpoint(ep) (endpoint-level ep.reasoning_effort ?? "max") — it never consults the resolution path the request builder uses (client_factory.rs resolve_effort: ModelRef.reasoning_effort → normalize_reasoning_effort_for; else effective_reasoning_effort_for: ModelSpec.reasoning_effort → endpoint → "max", gated/clamped), and the wire (ModelChanged { model, provider } / AgentInfo) carries no effort field at all — the same gap the model display had before backlog 2980ca67 went wire-first. · regression test: mid_turn_skill_model_switch_emits_model_changed_events
