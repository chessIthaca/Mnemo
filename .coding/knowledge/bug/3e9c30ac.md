Symptom: Turn aborted with "repetition guard: 3 identical consecutive responses — breaking the tool loop" (src/agent/turn.rs:777) while the model was re-emitting identical tool calls after receiving error feedback — repair attempts were counted as repetition. Root cause: tool_error_count (src/agent/turn.rs:1464-1474) is per-CALL and reset by ANY success within a batch, so a mixed [fail, success] batch leaves the counter at 0 and the repetition ring (clear keyed on tool_error_count > 0 at :758) counts error-following responses as repetition; separately, a single batch of 3 identical failing calls increments the counter 0→3 in ONE interaction, so the post-batch MAX_RETRIES check (:876) aborts the turn without the model ever getting a repair chance ("if all three were called at the same time it shouldn't break"). · regression test: single_batch_of_identical_failing_calls_does_not_abort
