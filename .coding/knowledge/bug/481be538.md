Symptom: A tool call whose arguments need backslash escaping in JSON (e.g. search with pattern "\\(\\?<" to match the literal `(?<`) is rejected with "arguments malformed or truncated — not run; retrying" and the retry re-emits the identical broken call. Observed live 2026-09-21 (plan 263a9e31): FIVE consecutive identical failures on one search pattern before a hand-found paren-free reformulation ([(][?]) succeeded. Root cause located: handle_bad_json (src/agent/turn.rs:3229) pushes a FIXED retry message (line 3342 — "re-read the tool's schema, rewrite the COMPLETE call") on every attempt up to MAX_BAD_JSON_RETRIES=8. For a content-EMISSION failure the schema is not the missing information, so every retry is identical and the loop cannot self-break. The strategy-changing correction machinery already exists — tool_call_correction (turn.rs:3506) via pending_correction (turn.rs:1644) — but the bad-JSON path never sets it. · regression test: repeated_bad_json_for_same_tool_changes_strategy
