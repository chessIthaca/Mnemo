Symptom: Tests that pin repo source via include_str! and slice function bodies with find("\n}\n") break — or silently over-capture to EOF, weakening the pins — when git autocrlf smudges the working tree to CRLF: include_str! embeds working-tree bytes at compile time, so the "\n}\n" needle never matches "\r\n}\r\n" and src[start..].find("\n}\n") returns None → end = src.len() → the "body" is everything to EOF. Live incident 2027-01-24: a fresh checkout smudged 11 merged files to CRLF (committed blobs always identical/LF) and the source-pin tests failed although the repo content was correct; worked around once with `git -c core.autocrlf=false checkout --`. · regression test: fn_body_slices_crlf_source_exactly
