Amended 2026-11-05: The tolerance is TOP-LEVEL ONLY: anchor items inside the ops array do NOT tolerate null placeholder keys. A worker (boundaryFix01, 2026-11-05, plan 843cb384) looped 4x on "ops[0] is not a valid anchor item (invalid type: null, expected a string) — expected {old_string, new_string, count?, fuzzy_whitespace?} or {from_read, lines, new_string}" because it filled every schema-listed key with null. Anchor items must carry only the fields they use, with string values. Recovery that worked: sequential single-edit file_edit calls (top-level nulls tolerated there), from_read+lines cites for insertions, literal old_string+replace_all for repeated sites. Candidate app fix for a future session: accept null-valued keys in ops anchor items as absent, mirroring the top-level tolerance.
