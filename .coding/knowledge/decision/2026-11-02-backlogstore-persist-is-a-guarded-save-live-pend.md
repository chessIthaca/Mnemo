+++
title = "BacklogStore persist is a guarded save — live Pending/InFlight items can only leave via remove()'s explicit allow-list"
created = "2026-11-02"
+++

The engine backlog store's save is a guarded save: `BacklogStore::persist()` (src/app/backlog.rs) delegates to `persist_with_permitted_removals(permitted)`, which re-parses the disk file and REFUSES — loud `error:` eprintln, file left untouched — any write that would drop a live `Pending` or `InFlight` item not named in `permitted`. `remove()` is the ONLY caller passing an id (the user's explicit delete); every other mutation persists unpermitted. Consequences: (1) a partial or stale in-memory list (the stale-in-mem clobber class that emptied backlog.jsonl in 2026-08-31) can no longer shrink the file silently — it fails loudly; (2) `reorder` with a subset, `clear_finished`, and all engine/IPC/Mnemo2 writers keep working because they never remove live pending/in-flight items; (3) the startup `purge_expired` (open() → 30-day hard-removal of soft-deleted tombstones, then whole-file persist) keeps working because tombstones (`deleted_at` set, any status field) are not live — note that this purge REWRITES backlog.jsonl even on pure reads (every `BacklogStore::open`), which is by design, and the info log now names the file. A refused write leaves the in-memory state alone; the next mutation's `reload_from_disk` heals, so one refusal never bricks the store. Guard check = `save_guard_violations` (private, same file): parse_jsonl on disk, protect live Pending/InFlight, violation when `permitted` lacks the id AND memory neither carries it nor keeps it live; missing file → proceed, unparseable file → warning + proceed.
