title = "Mnemo2 nudged stores the suggested tier; claim_nudge requires a routing record"
created = "2026-11-03"

Mnemo2 WorkerRouting.nudged (team.rs) stores the tier the nudge SUGGESTED (to_tier), not the nudged-from tier. Evidence: the step-5 test set `Some("difficult")` on an average worker; the mission-control chip text (design §4.10) is "Laya suggests difficult — stuck" and reads it from the record. NudgeIgnored therefore fires when `final_tier(record) != nudged` (the suggestion was never taken — final_tier is the nudged-from tier), and the row's `tier` field is that final tier. Reroutes clear `nudged` (change_model, merged step 5) so an acted-on nudge is never logged as ignored. Claiming: all three nudge kinds (strikes/circles, drift, review) go through `claim_nudge(records, worker_id, enabled, mode, suggest)` in team.rs, which requires record.routing.is_some() (the one-nudge-per-worker slot lives there) and sets routing.nudged under the records lock. Consequence: a worker dispatched in routing mode off (routing: None) can never be nudged in any mode — "in mode off nothing is written" holds for off-mode-dispatched workers; a worker dispatched under shadow/suggest/auto keeps its nudge budget after the mode is switched off (strike nudges are deterministic and ungated by mode; drift and review are explicitly mode != off). Nudge/NudgeIgnored rows are gated by logs_routing(record, mode) like reroute rows. Abandoned (workspace cleanup) is deliberately NOT a NudgeIgnored site — design §4.7 enumerates merged, failed, stopped only.

Amended 2026-11-03: Amendment: review finding Q1 (commit 737480ef on wt/agent-mnemo2Nu) revised the nudge_ignored terminal set — the design §4.7 enumeration "(merged, failed or stopped)" is superseded on both ends. A failed worker is resumable (team_resume on a stronger tier takes the nudge and logs a reroute), so failure never logs nudge_ignored — the pump's Error arm and fail_worker keep the outcome row only. Abandoned IS terminal (cleanup deletes the record), so cleanup_workspace now logs nudge_ignored beside the abandoned outcome row behind the same record-only logs_routing gate. The truly terminal set is: merged, stopped, abandoned. The strike-nudge/doom-guard coincidence makes this load-bearing: three consecutive real failures fire the nudge and fail the worker in the same moment, and writing nudge_ignored there would have marked the nudge ignored before anyone could act on it.
