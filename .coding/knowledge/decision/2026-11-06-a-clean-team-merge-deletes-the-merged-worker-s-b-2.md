User decision (2026-11-06): merged branches are deleted automatically and the merge rules say so. In src-tauri/src/mnemo2/team.rs, merge_locked now deletes the worker's branch via delete_merged_branch (git branch -d, never -D) right after cleanup_agent_worktree succeeded and no other record shares the branch; sweep_merged_branches then retries the delete for other ledger::merged workers whose checkout folder is gone. Why it loses nothing: the merge is --no-ff, so the merge commit's second parent is the reviewed worker tip; worker_diff (workbench.rs) and revert_locked already read a merged worker through the merge commit, never the branch ref. Rules: the safe delete refuses a branch that is not fully merged into the lead branch; a failed delete never fails the merge and leaves the error "merged, but branch cleanup needs attention: ..." which the sweep clears; Stopped, Cancelled, Failed, conflict and audit workers and reverted merges keep their branch; no setting. The mnemo-lead and mnemo-review skills, the team_merge tool text and mnemo2/README.md state it. A stuck worktree removal is retried too, at every later merge and at every app start, and the branch sweep also runs at app start (see the DECISION about a merged worker's stuck checkout). Supersedes the old README line that said a merge "keeps the branch for audit".
