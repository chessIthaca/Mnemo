+++
title = "a merged worker's stuck checkout is retried at every merge and every app start, then its branch is swept"
created = "2026-11-07"
+++

A merged Mnemo2 worker whose checkout removal failed (Windows os error 32: a shell or program whose working folder is inside .worktrees/agent-*) is retried automatically. retry_checkout_cleanups_locked in src-tauri/src/mnemo2/team.rs runs at every merge (inside merge_locked, merge lock held, directly before sweep_merged_branches) and at every app start (TeamRuntime::open calls retry_leftover_cleanups after the trash sweep: it takes the merge lock, retries, then sweep_merged_branches("")). Candidates are workers with status Merged whose error starts with a checkout-cleanup note ("merged, but worktree cleanup needs attention" from merge_locked, "merge recovered, but worktree cleanup needs attention" from recover_worker; both are constants). A retry that works, or finds the folder already gone, clears the note and persists; a retry that fails leaves the record exactly as it was. The branch delete is NOT duplicated: once the folder is gone the existing sweep deletes the branch, which it skipped while the folder existed.
Why retry instead of anything stronger: cleanup_agent_worktree / remove_leftover_checkout stay the only deletion authority (own direct child of .worktrees, links and junctions refused, a registered checkout with new dirty work retained). A permanently held folder keeps its note and costs up to ~3 s per stuck worker at each merge and app start (12 tries, 250 ms apart); no setting, event or UI. A reverted merge's stuck folder is retried too (status Merged), its branch is still kept (the sweep requires ledger::merged).
Gotcha when testing or reasoning: cleanup_agent_worktree returns Ok for a MISSING folder, so TeamRuntime::open clears the note of a merged worker whose folder is absent. To model a held checkout, put a directory link at the checkout path before open (links are refused, the note survives), then remove only the link and create the real leftover folder after open.
Tests in the team.rs test module: a_later_merge_retries_an_earlier_merged_workers_stuck_checkout (regression), a_stuck_checkout_that_still_cannot_be_removed_keeps_its_note_and_branch, the_retry_ignores_a_merged_worker_whose_error_is_not_a_checkout_note, open_retries_a_stuck_checkout_left_by_an_earlier_run. Rules are stated in mnemo2/README.md (merge bullet), the mnemo-lead skill (item 6) and the mnemo-review skill (section 7). Never delete a stuck worker folder by hand: the next app start clears it.
