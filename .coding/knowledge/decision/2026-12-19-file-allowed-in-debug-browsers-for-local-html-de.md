DECISION (plan 541b6381, merged into main at 297ce1c3 on 2026-12-19): the debug browsers may now load file:// URLs — a deliberate relaxation of the 2026-08-12 S1 sandbox boundary. normalize_url's ALLOWED_SCHEMES is now ["http","https","data","file"]; only the standard `file://` authority form passes (guard `"file" if rest.starts_with("//")`), malformed `file:`/`file:foo`/`file:/x` get a "must use the file:///path form" error, and javascript:/about:/drive paths stay rejected. Rationale: user-requested pure-HTML debugging in both the headless offscreen browser and the visible child WebView2; navigations remain approval-gated (NeedsApproval) and file:// renders only the page the URL names. web_fetch (src/tool/agent/web_fetch.rs) deliberately NOT relaxed — stays http(s)-only against SSRF. Choke point: src/browser/mod.rs normalize_url, shared by offscreen_browser_navigate, browser_navigate/browser_webview_* IPC, and the UI URL bar (BrowserView placeholder hints file:///C:/page.html). url_host (src-tauri/src/ipc/browser_webview.rs) now falls back to the whole URL when the authority is empty so file:///C:/… watchdog notes stay informative. Regression coverage: file:// pass-through rows (Windows/POSIX/UNC/uppercase), malformed-form rejections, and #[ignore]d navigate_loads_file_url headless-Chromium test (temp HTML → file:// renders; run `cargo test --features browser -- --ignored`). Note: factory.rs tool-array ceilings for Executing/ExecutingResearch/Reviewing were raised on purpose (see its dated comments) because the `browser`-feature arrays were already ~350-410 chars over at HEAD — CI runs default features so the drift was invisible.
