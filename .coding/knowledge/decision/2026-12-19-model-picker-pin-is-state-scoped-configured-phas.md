DECISION (2026-12-20, plan 1ea8f680) — the per-agent model-picker pin is STATE-SCOPED; amends the 2026-08-22 "never yields" rule (merge 95567d2). Resolution order in `resolve_turn_provider` (src/agent/loop_impl.rs): skill override > explicit pin (state-scoped) > forced model (spawn_agent model arg) > `[models.*]` chain > default. Mechanics: the pin's scope is the workflow state of its FIRST serve, lazily stamped into `AgentLoop.pinned_state` (set_explicit_provider resets it so a fresh pick re-stamps; the deferred-swap completion path leaves it alone — same pick). Within its own state the pin beats forced/subagent/state overrides; in ANY other state it holds only while the resolver chain returns nothing configured for (workflow_state, skill_name, is_subagent) — a configured `[models.*]` slot takes over and the pin goes DORMANT (never deleted — `explicit_provider` keeps it, so it resumes if the workflow returns, e.g. abandon_plan back to Planning); with nothing configured the pin keeps serving instead of falling to the default model. 429-fallback endpoint stickiness is routing-only and never pins. Rationale: a picker choice is a statement about the phase the user acted in, not all future phases — per-state [models.*] config governs the phases it names. Docs: PLAN.md per-agent models paragraph, README.md Agents & interface; regression tests: picker_pin_yields_to_configured_model_on_state_change, picker_pin_survives_state_change_when_no_model_configured, fresh_picker_pick_restamps_in_the_current_state (src/agent/tests.rs).
