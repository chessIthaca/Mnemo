DECISION (backlog 04bd6977, plan a91e71d3, commits e3977d6/97c6ae9 on wt/agenticcoding): the Run-All pre-item checkpoint runs on the per-directory wt/* work branch — checkpoint_on_work_branch (src/project/git_ops.rs) forks/reuses the branch before committing (the same auto-fork semantics create_plan applies via ensure_work_branch), so a session sitting on main (e.g. right after merge_to_main lands a branch) never commits the dirty tree to main. A refused fork (dirty paths outside .coding/) propagates Err("work-branch fork refused: …") through the dispatch's existing checkpoint-failure path — the run stops, the item stays Pending with the reason in its note. Deliberately STRICTER than create_plan's Err semantics (which proceed on the current branch with a skip note): dispatching an item while on main with a dirty tree would commit the item's work to main too, so stopping is the only constitution-safe choice; it also keeps the resume/rollback chain intact (the checkpoint sha is the manual rollback anchor, backlog 45dcf577). Ok(None) (non-repo) falls through to the plain checkpoint, which fails cleanly as before. The old async `checkpoint` was REPLACED by checkpoint_on_work_branch (run_all.rs was its sole caller — keeping the unguarded wrapper would be dead code under deny-warnings plus a footgun). Known residual (review round 1, no action required): the resolution-time commit_success is still branch-agnostic — a natural follow-up backlog item if the class is to be fully closed.
