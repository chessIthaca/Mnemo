DECISION: The search/search_read AUTO-DELEGATED steering note is hidden by a DISPLAY-LAYER filter, not backend suppression (backlog 0458f797, shipped 2027-01-05).

- **Why display-layer:** the AUTO-DELEGATED steering line is MODEL guidance — its "re-issue this exact search" escape-hatch hint steers the model, and the escape hatch works server-side regardless of display. Suppressing at emission would blind the model; filtering at render hides it only from the user. Exactly the show_tool_activity "serves the model, not the end user" philosophy.
- **Setting:** `[ui] show_delegation_notes` (config.toml), default **false** (hidden) — consistent with show_tool_activity's model-serves rationale; the user's ask was to hide the note. Full plumbing follows the show_tool_activity precedent: general.rs UiConfig → patch.rs → settings_dto.rs → ipc/settings.rs GetSettingsUi → contract_fixtures.rs ↔ dto-get-settings.json → tauri.ts → App.tsx hydration → useAgentStore → ChatDraft → ChatSection toggle ("Show auto-delegation notes in search results").
- **Scope:** line-level ONLY — the delegation block's steering header, in BOTH emission shapes (review round 1, 2027-01-05): the FAST path (memory hunt, or symbol hunt with no glob) returns the block raw — the header line starts with `AUTO-DELEGATED` (search.rs:1328, search_read.rs:235); the PREPEND path (symbol hunt narrowed by a glob, riding above normal results) wraps it as `note: AUTO-DELEGATED` via with_note. Both twins: "to the code graph" and "to memory". The delegated answer (def:/callers:/full 360° lines) always stays; other notes (content-index staleness, reindex, literal-fallback) are untouched. Helper: frontend/src/lib/delegationNotes.ts (stripDelegationNotes + isDelegationNote).
- **Render sites (both in the ToolCard):** collapsed card's amber note chip (Message.tsx, isDelegationNote skip — prepend shape only; the fast-path block carries no engine marker so no chip fires there) + expanded output `<pre>` (stripDelegationNotes — both shapes). Console REPL and Trace tab (raw wire JSON) are debug surfaces and never filter.
- **Finding:** the "Output tab" does NOT exist — removed in commit 3ff4845 ("remove Output right-panel tab + dead toolOutputLog plumbing"). The echo map's claim #6 was stale; corrected 2027-01-05: the ToolCard is the ONLY GUI surface for tool result text. Stale "Output tab" comment references also fixed in general.rs + useAgentStore.ts (adjacent to this change); agentEventReducer.ts:611 / agentState.ts:413 / Conversation.tsx:52,138 still carry the stale phrase (pre-existing, out of scope).
- **Edge case:** merged notes ("; "-joined by merged_note) — the line filter removes only the first line; staleness text appended after the full 360° line stays visible. The staleness note's own fix (doubled "note: note:" prefix) is queued backlog item 42302c2d.
