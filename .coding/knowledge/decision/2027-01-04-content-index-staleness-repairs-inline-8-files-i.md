DECISION (2027-01-04, plan a00d05fc, branch wt/agenticcoding): content-index staleness now REPAIRS INLINE instead of warn-only. When search/search_read's FTS freshness check (F10) finds ≤ STALE_REINDEX_CAP=8 stale hit files and no index pass is running, CodeGraph::reindex_stale_files (src/codegraph/mod.rs) re-indexes them inline (vanished→prune, source→reindex_one, text→content-only upsert, became-binary→prune; paths containment-checked against the canonicalized root — a crafted out-of-root DB key is skipped, review LOW 1; atomic flag claim via compare_exchange + IndexFlagGuard so the watcher never overlaps) and try_index re-queries ONCE, serving fresh index results with a "reindexed N stale file(s) — serving fresh index results" disclosure note. Above the cap, while a pass runs, on reindex failure, or if files are re-edited during the retry → FtsOutcome::Stale → authoritative walk with the "content index stale for N file(s)" note. This supersedes the warn-only F10 contract described in .coding/knowledge/spec/2026-08-29-findings-round-f1-f13-targeted-reindex-supersede.md (historical record, left as-is). The doubled "note: note:" prefix bug is fixed: note components carry no prefix; with_note adds exactly one (new push_note helper merges components). Regression tests: stale_index_reindexes_and_serves_fresh_index_results, stale_above_the_reindex_cap_walks, stale_while_an_index_pass_runs_walks, stale_index_reindexes_and_reads_fresh_content, stale_file_beyond_the_display_cap_still_surfaces, reindex_stale_files_{refreshes_the_given_files, prunes_vanished_files, busy_returns_zero_and_leaves_the_flag, skips_out_of_root_keys}.
