R19 (backlog fd8f67c0, plan f8858f62, shipped 2027-01-10): the cache-hit extraction (.coding/analysis/cache-hit-5-extract.py) now classifies models by "ever reported cached_tokens>0 in the window" (heuristic primary) with the review's static non-reporter list as a cross-check only, and emits every A-section aggregate split by reporting vs non-reporting tier. Post-R12 reporting tier = the prompt-shape baseline (79.9% hit / 18.0% resets); non-reporting 0%/100% by construction. The optional reports_cached_tokens request_stats schema flag was SKIPPED: (1) the window heuristic self-adapts when a provider fixes reporting — glm-5.3-flash-gcp-h200-fp8-01 started reporting (57.8% hit) and moved tiers automatically, while a persisted static flag would have gone stale; (2) the write site cannot distinguish field-absent from field-zero without SSE-layer changes that queued R21 (bd9df146) reworks anyway. Detail: .coding/analysis/cache-hit-5-aggregates.txt A0; interpretation amended in .coding/analysis/2027-01-09-review-round-executive-summary.md §3.

Amended 2027-01-07: 2027-01-10 (R21, backlog bd9df146, plan a3a04af8) — the NULL-safety premise above is stale: request_stats.cached_tokens is now NULLABLE by design. Error rows (outcome='error') carry cached_tokens NULL — the provider never reported usage, which must stay distinguishable from a real reported miss (0) — and compaction rows carry purpose='summarize'. The extraction script was updated in the same change: it NULL-guards the cached/ttft/generation reads, selects outcome+purpose, and segments the aggregates — the hit/reset aggregates (A0-A5) run on main-loop rows only (outcome IS NULL AND purpose IS NULL); error rows and summarize rows get their own section (A6). Summarize rows are excluded from the hit aggregates deliberately: a compaction's request is a fresh single-message prefix, structurally unable to hit cache, so including them would drag the conversation hit% down for a structural reason rather than a cache-health signal.
