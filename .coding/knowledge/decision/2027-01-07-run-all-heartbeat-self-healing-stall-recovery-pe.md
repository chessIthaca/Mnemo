Run-all stall recovery (plan 0ed9d24f, commits 99170b8 + 3362968 on wt/agenticcoding): a run-all run is now SELF-HEALING and its dispatch-chain arms are TRACEABLE. Design decisions:
1. run_all_heartbeat (RUN_ALL_HEARTBEAT = 30s) — while a run is armed, re-drives run_all_dispatch_next when run_all_stalled (armed, NO current item, not compacting, stop NOT requested, main agent idle — not running, no running descendants — and an eligible pending item exists) WITHOUT any turn resolution. This is the class-level fix: every silent stall arm (the busy-guard deferral, the between-items compact window's 600s wait, a swallowed dispatch Err) is bounded to one heartbeat period. Never ends runs (end_run stays with the resolution paths — a heartbeat ending runs would race the normal lifecycle). Spawned for the run's lifetime in backlog_run_all, bound to state.backlog.run_generation (AtomicU64, bumped at each arming) so a previous run's heartbeat cannot survive into a successor armed within one sleep period.
2. run_all_diag — the persistent, epoch-stamped dispatch-chain log: .coding/logs/run-all.log when a .coding side-car exists under the CWD (dev), else temp_dir/mnemo-run-all.log (packaged) — the Q2-fixed diag_line pattern (a release build is a GUI-subsystem binary; bare eprintln! can vanish or panic; run_all_diag keeps a swallowed stderr writeln for console parity). EVERY dispatch-chain arm routes through it; the bare eprintln!s in the touched arms were dropped.
3. The plan's separate one-shot delayed retry (~60s) after a busy-guard deferral was DROPPED: spawning it from inside run_all_dispatch_next is unbreakable async recursion (an opaque-type cycle, E0391 — even Box::pin type-erasure fails because the Box's type argument references the opaque type), and the heartbeat subsumes it at a better cadence (30s < 60s).
4. KNOWN LIMITATION (documented in the const/fn docs, the busy-guard comment, and the deferral log lines): the heartbeat skips busy runs — a zombie descendant keeping has_running_descendants true forever stalls the run identically to today's behavior; the persistent deferral line makes that arm diagnosable.
5. run_all_stalled checks the stop flag FIRST inside the run_all guard (a stop-requested run is not stalled — the heartbeat must not dispatch one more item past a user stop) and mirrors the dispatch's exclude construction (current_item before spawned, the documented lock order).
Regression tests (source-contract, fn_body idiom, all verified red pre-fix): heartbeat_redispatches_a_stalled_run_without_turn_resolution, heartbeat_spawned_for_the_runs_lifetime, busy_guard_deferral_is_logged_persistently, stall_arms_write_the_persistent_run_all_log.
