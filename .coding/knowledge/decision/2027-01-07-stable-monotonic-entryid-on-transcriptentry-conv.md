DECISION (mem-perf review HIGH 3, plan 225e0dad, wt/agenticcoding): every TranscriptEntry carries a stable monotonic `entryId?: number`, and Conversation keys its turn/run/entry lists by it — index keys misattributed row state at the 1000-entry transcript cap (every append shifted all indices: arePropsEqual failed → deep re-render; local row state like an expanded tool card silently transferred to a different entry).

Design: (1) The field is `entryId`, NOT `id` — the `memory` variant already owns `id?: string` (the owning tool call's correlation key); an `& { id?: number }` intersection would corrupt it and TS-intersect the memory member into never. (2) Optional on the type intersection (like ts), stamped at creation: the applyAgentEvent identity pass (agentEventReducer.ts, alongside ts — covers all reducer-driven entries) + the direct-push sites that bypass it (reduceQuestionAnswered via recordQuestionAnswer, InputBar pushTranscriptMessage / handleSend user entry / /load via stampEntryIds). (3) Module-scope counter in agentState.ts (allocEntryId); stampEntryIds SYNCES the counter past foreign ids before stamping — /load is the only path that imports pre-existing ids (a saved conversation), and without the sync the next allocation could collide with a loaded id (duplicate React keys — review round 1 HIGH 1). (4) Keys: turn = turn[0][0].entryId, run = run[0].entryId, entry = e.entryId, with prefixed position fallbacks (`t${ti}`/`r${ri}`/`i${i}`) only for id-less legacy entries. (5) CRITICAL DISCIPLINE: every entry REPLACEMENT site must spread the previous entry (`{ ...prev, ...next }`) so entryId/ts carry over — a fresh literal gets a new id from the identity pass and the row's key changes mid-stream (review round 1 LOW 1: the vision-retry site; all other sites already spread). Pinned by tests: stamping monotonic, arg-delta replacement id stability, vision-retry id stability, cap stability (idBeforeCap), recordQuestionAnswer, stampEntryIds counter-sync + pass-through, and the Conversation source-contract on the key expressions.
