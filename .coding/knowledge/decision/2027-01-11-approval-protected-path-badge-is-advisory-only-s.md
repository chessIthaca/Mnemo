DECISION: the approval-dialog protected-path badge is advisory-only, shell-scoped, and normalizes like the Rust guard (plan 6d50d160, commits b0709dc + 3884212 on wt/agenticcoding; security review 2026-09-09 LOW-2). The badge fires when a shell invocation's text — the command joined with the resolved cwd (appended "/", space-separated so a command-final ".git" cannot junction) — mentions .coding/, safety.toml, or .git/: case-insensitive, backslashes normalized to forward slashes mirroring Sandbox::is_protected_write_target (src/tool/agent/sandbox.rs:204), the ".git/" token keeps its trailing slash so .gitignore does not match. Advisory only — it never gates the approval; the residual (shell bypasses the file-tool sandbox, which refuses the control-plane set: .coding/plans|reviews|knowledge/, safety.toml, backlog.jsonl, the DBs, any .git component) stays documented and accepted. Scan scoped to shell: file tools refuse those writes, and scanning their args would false-positive on diff content merely mentioning ".git/". Code: frontend/src/lib/protectedPathWarning.ts + frontend/src/components/chat/ApprovalPrompt.tsx (red ShieldAlert strip below the header row); tests: frontend/src/lib/protectedPathWarning.test.ts (10 tests incl. ?raw source contract, registered in frontend/vitest.config.ts).
