DECISION (2027-01-11, plan 9441d776, commits 363fb9d + 6309326 on wt/agenticcoding): bug_fixing detailed steps are CHECKABLE sub-items — create_plan renders `- [ ] {text}` bullets under `## Detailed steps`, and complete_step's detailed_step_index (1-indexed, exactly-one vs step_index) ticks the nth mark. DESIGN: raw-body line surgery, NOT a structured Vec<Step> field — `detailed_steps: Option<String>` stays the single on-disk truth (the marks live in the raw body and round-trip serialize→parse verbatim), PlanFile::complete_detailed_step flips the nth checkbox in place (rebuilt from the RAW text after `] ` so a leading "N. "/extra spaces survives — only the mark changes), legacy plain-dash bodies normalize to checkboxes on first tick, and the render escapes `- `-leading continuation lines so nested lists can't inflate the count. The tick NEVER transitions workflow state (sub-steps never complete the plan) and skips persist_stack (the plan file is the truth). Rationale: the Vec<Step> ripple (validate_plan_resumability/context_issue signatures, blank-line drops) bought nothing the file marks don't already provide.
