DECISION (2026-09-26): landing bookkeeping is written BEFORE the branch's final commit, never after the landing. `.coding/skills/merge_to_main.toml` and `new_release.toml` step 2 now order: (1) ruleset check, (2) write the branch's landing records (memory_supersede), (3) commit ALL uncommitted work (`.coding/` included) so the records ride the merge, (4) land — merge+push, or push+`gh pr create`, (5) no-write-after-landing rule + an empty `git status --short` check before skill_end. Rationale: a write issued after the push can never land — protected main rejects it and the carrying branch is merged+deleted — so it dangles uncommitted and rides an unrelated branch (PR #7's landing needed the whole closeout plan fc41c5aa for exactly this). Records are phrased on pre-landing facts: title tail `— MERGED into main (branch <name>, <date>)` + body naming the branch's work tip; never the merge sha (a commit cannot contain its own hash) or the PR number (exists only after `gh pr create`); on the PR path the record ships inside the PR, so it becomes true exactly when the human merges, and a rejected PR means it never lands.
