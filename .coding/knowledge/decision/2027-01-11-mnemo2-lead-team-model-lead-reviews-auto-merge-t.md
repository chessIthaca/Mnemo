User-directed (2026-10-24) Mnemo2 product/policy decision. Mnemo2 is a single-project cockpit: the start screen picks one project directory; one project per instance. The lead (main agent) owns planning, research, debugging, review, and merge with the full toolset. It reviews every worker branch and closes every finding — tiny findings it fixes itself via a `review_fix` host tool applied in the worker worktree; big findings spawn a fixer subagent. The TeamManager auto-merges a reviewed worker branch into the lead's local working branch only after: worker success + checks on the merge-time branch tip (`cargo test --workspace` re-run after any fix), every finding closed or `wontfix` with written justification, lead tree clean/idle, serialized merges. It halts on conflicts, never pushes, never merges to `main`; main stays the protected PR path (ruleset 23755694). Worker branches fork from the lead's working-branch tip at dispatch; stale bases are never auto-rebased. Workers run an executor profile (no plan/spawn/ask) in `wt/agent-*` worktrees. `agent.md` scopes the hard git gate to Mnemo1 agent workflows; the compiled agent gate still applies to the agent's own git tool. Budgeting is team-gated through concurrency, spawn, per-worker turn/time/cost, and per-project caps; model routing uses a strong lead, cheap/default workers, and a configured reviewer, with cheaper models for mechanical work, plus per-worker budget/cost telemetry. Design: `.coding/design/mnemo2.md`; policy: `agent.md` 'Mnemo2 team merge policy'; round-2 review PASS: `.coding/reviews/2026-10-24-b4b6a536-mnemo2-design-lock-review-round2.md`.
