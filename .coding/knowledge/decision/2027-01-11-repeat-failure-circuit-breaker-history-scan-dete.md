DECISION (2027-01-24, plan a9875b73, tool-call robustness): when a failed tool result's (tool name, error text) matches a PRIOR identical failure in recent history (src/agent/turn.rs `repeated_tool_failure`, 50-message window), the turn loop pushes ONE harness-attributed user-role corrective message after the batch (`tool_call_correction`) carrying the error verbatim + the tool's parameter schema (size-capped at CORRECTION_SCHEMA_CAP=1536 chars, degrading to property names + required list). RATIONALE: the empirically proven loop-breaker for the self-reinforcing malformed-call loop is a fresh corrective TURN, not error text — a live incident re-emitted the same missing-`message` git commit 15 times while the error string repeated identically; only the user's hint (a fresh user turn) broke it. History-scan (not session state): works across turn boundaries (the loop's span), deliberately NO reset-on-success (the pattern-poison stays in context — the live loop interleaved successes), decays naturally at the compaction boundary (compacted tool results lose the verbatim text). Pushed AFTER the batch so Anthropic's tool_result-after-tool_use ordering holds; one correction per batch (first repeat-failure wins); MAX_RETRIES=3 consecutive-abort semantics unchanged (the breaker is additive — fires on every repeat-failure batch, so the abort-time correction lands in history for the next turn). REJECTED ALTERNATIVES: (1) tool-result-content enrichment as primary — live evidence shows error-text repetition does not break the pattern; (2) full git tool split — high churn (never_auto_for + runtime-mutable core_operations keyed by subcommand names, deliberately-built forgiving action resolution, system-prompt references, 1571-line git.rs tests) for narrow payoff (fixes one tool while file_edit/search/spawn_agent keep the failure mode; adds tools to a 53-tool registry) — deferred as a measured follow-up if field data shows git-specific conflation persisting. Companion layers shipped: expected-shape error enrichment (git per-subcommand + file_edit line-range) and git schema tightening (required: [subcommand] + description requirements map). Tests: repeat_failure_injects_schema_correction_on_second_identical_error, distinct_tool_errors_do_not_fire_the_correction, repeat_failure_across_an_intervening_success_still_fires, schema_requires_subcommand_and_maps_required_fields, prepare_edit_lines_one_bound_only_errors.
