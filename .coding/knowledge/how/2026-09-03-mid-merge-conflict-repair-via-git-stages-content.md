Mid-merge conflict repair protocol proven effective (2026 session): when a conflicted file gets damaged or resolution needs redoing while MERGE_HEAD exists, `git checkout -m -- <path>` restores the pristine conflicted worktree from index stages (:1 base / :2 ours / :3 theirs) with all hunks back at original positions (marker labels change HEAD/origin-main -> ours/theirs — cosmetic only). Resolve via content-driven state-machine filter per file instead of hand edits: buffer ours-side vs theirs-side lines between markers, choose side per hunk via content signature (e.g. contains 'shutdown_agent(cmd_tx' -> keep ours), emit winner only, drop all marker rows; write back UTF8-noBOM preserving LF endings and trailing newline from raw Split([char]10)/Join(LF). Post-write verify inside same pass: marker count == 0 plus side-signature counts (e.g. call sites == expected). Mixed-side policies are safe this way even when hunks are byte-identical twins across positions (no manual number transcription ever). Final arbiter = full unpiped cargo test with summary-line verdict (`test result:` lines), never piped exit codes. Caution learned first-hand: file_edit line-range replacement with wrong/truncated new_string silently destroys whole hunk regions — prefer stage-restoration + scripted filters over manual splices for conflicted files
