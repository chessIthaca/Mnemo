Mnemo2's delete-old-workers flow (src-tauri/src/mnemo2/team.rs):

- `TeamRuntime::delete_workers` returns `TeamDeleteOutcome { results: Vec<WorkerDeletionResult>, snapshot: TeamSnapshot }` — one per-worker result in request order (`error: None` == deleted); a failed worker never stops the rest. Its re-check pass after stopping sessions must pass the SURVIVOR set as the batch (shared_branch flags are batch-relative: a survivor must never touch git state of a worker that failed an earlier phase).
- The deletion preview is read-only and takes NO merge lock (delete re-checks under it). Batch facts come from one `git worktree list` + one `git for-each-ref --format=%(refname) %(ahead-behind:HEAD)` (`%(ahead-behind)` needs git ≥ 2.41; parse failure falls back to per-branch rev-list — first number of the atom equals `rev-list --count HEAD..ref`, verified). Per-worker checks use `git status --porcelain --untracked-files=normal`, never `-uall` (recursing into node_modules dominates the cost).
- Checkout removal fast path: rename the validated checkout into `.worktrees/.trash/<name>-<unix_ms>` (one same-volume move), then `git worktree prune` (deregisters the moved worktree and unblocks `branch -D`), then delete the branch. The trash folder (gitignored, never tracked) is swept in the background (bounded retries) and at every `TeamRuntime::open`. On Windows the rename is refused while any file in the tree is open (the codegraph holder) — the removal then falls back to the foreground 12×50ms loop which reports the holder via the Restart-Manager probe. `validated_checkout` (team.rs) is the shared ownership guard (own folder, direct child of canonical .worktrees, never a link/junction/non-directory).
- Frontend events: `mnemo2://worker-deletion` (DELETION_EVENT_CHANNEL) streams `DeletionProgress {phase: checking|deleting, worker_id, name, preview?, error?}` per worker from the `team_delete_preview`/`team_delete` commands (they take `app: AppHandle`). `TeamTransport.onDeletionEvent` is optional so hosts/mocks predating the channel keep working.
- Frontend state: `WorkerDeletionRequest = {phase: checking|ready|deleting, rows: WorkerDeletionRow[]}`; requestDeleteWorkers opens the sheet synchronously (rows start checking), guards double-open, and bumps a flow token that invalidates stale promises/events; confirmDeleteWorkers retries only failed rows; full success closes the sheet. Vitest transport mocks for `deleteWorkers` return `{results, snapshot}`.
