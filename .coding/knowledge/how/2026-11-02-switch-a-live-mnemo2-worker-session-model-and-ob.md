Mnemo2's headless live model switch and its testing seams (durable facts, independent of any plan):

1. `AgentSession::set_model` (src/headless/session.rs) is the ONLY sanctioned way to switch a live session's model mid-run. It reuses the spawn-time parse (`forced_model_ref`, src/headless/engine.rs) and the engine's shared `ConfigModelResolver` (`EngineInner.model_resolver` — the same Arc wired into every factory-built loop) at the loop's fill_rate, then pins via `AgentLoop::set_explicit_provider`. Never build a second provider resolver; never route a model switch through the AgentCommand channel (queued commands land only after the current run — wrong semantics for mid-turn switches). `set_explicit_provider` defers when the new window is smaller (`has_pending_swap()` → compaction on the old model first).

2. `TeamRuntime::change_model` (src-tauri/src/mnemo2/team.rs) applies the live pin for busy workers (record updated + persisted, status stays Working, generation untouched); idle/stopped keep the stop→resume path where the generation ADVANCES. Live un-pinning to routing (model=None) is not kernel-supported and is refused for busy workers.

3. Testing seams that observe which model actually serves: run the engine WITHOUT an injected provider (EngineBuilder::provider/ScriptedLlm serve everything and ignore model pins — a resolver-built pin would point at the config's dead URL). Write kind="local" endpoints.toml (passes the readiness gate with no keys.toml) whose base_url targets a local TcpListener SSE stub — the repo's established idiom (no mock-HTTP crate; minimal HTTP/1.1, one response per connection, record the request JSON's "model" field). Hold a response behind a oneshot gate to act mid-turn; use an unknown-tool tool-call response to force a second request within the SAME turn. Per-model context windows: the [[endpoint.models]] TOML table form (`id`, `max_context`).

4. A worker whose turn finishes rests at WorkerStatus::Completed (not Idle); resumed/restarted workers come back Idle. The team pump's ModelChanged arm overwrites worker.model_id unconditionally; Usage/refresh arms only fill it when None.

5. Mnemo1's set_model path is separate and unchanged: config_io::resolve_model_provider + factory.context_manager_for + swap_provider_into_loop (app-side), no headless involvement.

Amended 2026-11-02: Audit-fix round (2026-11-02, same plan step) refined the seam — facts that supersede the earlier shape:
- `ModelSwitch` variants now carry the serving model id: `NextRequest { model }` / `CompactsFirst { model }` (the same string the kernel's model_changed event carries). team.rs's change_model uses the payload for a CONDITIONAL clear: never erase an already-observed `worker.model_id` that already matches the switch target — the new model's ModelChanged/Usage events may have been pumped before the record update (or the target was already serving), and an unconditional clear can leave no later event to repair it.
- set_model seeds the served-model baseline (`AgentLoop::seed_served_effective_if_empty()`, pub(crate)) BEFORE the pin: a never-served loop's baseline is otherwise seeded at run_turn entry from the ALREADY-switched provider, so a switch landing before the first request never emits model_changed when the new model first serves. The repro is a ROUTING session (model: None at spawn); a forced-model spawn does not reproduce it. Kernel fact: `note_served_effective` with an empty slot seeds silently and returns false (no announce) — an announce fires only when the (model, endpoint, effort) triple differs from the seeded one.
- The CompactsFirst/NextRequest label is computed from the window comparison itself (`provider.capabilities().max_context < loop.context_manager().max_tokens()` — the same rule set_explicit_provider applies), NEVER by sampling `has_pending_swap()` afterwards: a running turn may consume the pending swap in between.
- change_model's busy path refuses `kind == "audit"` workers ("its model is not switchable"); audit workers must be dispatched on a board plan (dispatch_on_plan) for tests to create them via `audit_dispatch(worker_id, reviewer_id, model, effort, brief)` — plain dispatch_with_id workers cannot be audited.
- Red-check discipline: disabling a call for a red-check means commenting the CALL out — appending a comment after the semicolon keeps the call live and makes the check a silent no-op.

Amended 2026-11-02: Second-audit round (2026-11-02, same plan step) added the EFFORT bookkeeping to set_model — a live switch must update the loop's effort display state, not just build the provider with the new effort:
- set_model mirrors Mnemo1's swap (config_io::swap_provider_into_loop) AFTER the pre-switch baseline seed and BEFORE the pin: `display_effort = model_resolver.display_effort_for(&model_ref)` (the ModelResolver trait method — the requested effort, else the model's configured default chain; falls back to the requested effort if the model left the config mid-switch), then the five setters: `set_resolved_model(None)`, `set_resolved_provider(None)`, `set_pinned_display_effort(display_effort.clone())`, `set_default_display_effort(display_effort)`, `set_resolved_effort(None)`.
- Why: the pin arm's serve reports effort from `pinned_display_effort` (loop_impl.rs ~1939); ModelChanged's reasoning_effort comes from `resolved_effort().or(default_display_effort())` (turn.rs ~2828). Without the bookkeeping the wire request carries the new effort (the provider is built with it) but the announce reports a stale/default effort — empirically: an effort-only high→low switch announced ("model-a", Some("max")) (the default chain) instead of Some("low") — and when the stale display effort happens to equal the baseline, no ModelChanged fires at all.
- Regression test `set_model_reports_an_effort_change_on_the_same_model` (session.rs model_tests): a session spawned with (model-a, high) holds its first request mid-flight, switches to (model-a, low), and asserts the follow-up request body carries `reasoning_effort: "low"` AND the last ModelChanged is (model-a, Some("low")). The stub's recorded request body exposes the wire effort as the top-level `reasoning_effort` field (the openai/local client sends it; a 400 triggers a strip-it retry, so stubs must return 200).
