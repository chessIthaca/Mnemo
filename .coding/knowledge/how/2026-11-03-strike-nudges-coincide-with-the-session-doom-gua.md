The session's doom guard aborts a turn after 3 consecutive tool errors ("Aborting turn: 3 consecutive tool errors (the model may be stuck)") — the SAME threshold as Laya's nudge strike limit (route_question::Strikes::new(3)). So a genuine "3 failing tool calls in a row" nudge (reason `strikes`) always coincides with the session abort: the worker lands Failed, the nudge still fires (the ToolResult event reaches the pump before the Error event), and the lead's notice suggesting team_resume with a higher tier is exactly the next move for the Failed worker. Pump event order: ToolResult(3rd) → strike nudge claimed → Error → Failed + outcome row + nudge_ignored row. Tests for stuck-worker nudges must expect WorkerStatus::Failed, not Idle. The "circles" path (verbatim repeats that succeed) does NOT trip the doom guard (successes reset the error streak), and neither does fail/fail/success/fail/fail. Also discovered while testing: a cleanly finished worker turn sets WorkerStatus::Completed (not Idle) in the pump's Finished arm — polling tests must wait for Idle|Completed|Stopped|Failed. Live-worker pump tests are possible in src-tauri: build the engine with mnemo::headless::EngineBuilder::new(opts).provider(Arc<ScriptedLlm>) and dispatch through the team; the scripted client serves every request (including model-pinned sessions), returning one LlmEvent batch per complete() and a text stop when the queue empties; unknown tool names produce deterministic failing ToolResults (parse a fragment string as serde_json::Value, unwrap_or(Value::String(raw)) at signature time).

Amended 2026-11-03: Amendment: review finding Q1 (commit 737480ef) changed the failure path's rows — the doom-guard failure now logs the outcome row ONLY; nudge_ignored is never written on failed (the worker is resumable — team_resume on a stronger tier takes the nudge and logs a reroute). The ignored nudge waits for a truly terminal point: stop, merge, or abandoned in cleanup. So the real flow after a strike-nudge-plus-doom-failure is: Nudge row, Outcome(failed); if the lead stops the worker, Outcome(stopped) + NudgeIgnored; if the lead resumes on a higher tier, a Reroute row and the nudge was taken. Tests pin this: failed_worker_does_not_log_nudge_ignored (red-checked against the pre-fix write) and stopped_after_failure_logs_nudge_ignored_once.
