title = "lead gotchas when planning, closing and merging through the Mnemo2 team tools"
created = "2026-11-06"
+++

Things the Mnemo2 lead tools do that are not obvious from their descriptions, learned on Windows with Claude Code as the external lead: (1) The board refuses a new plan until a memory_search has run since the previous new plan. (2) The spec-impact gate refuses a plan whose steps touch a file that a capability map governs (src-tauri/src/mnemo2/team.rs is governed by the dispatch-routing, external-lead, tier-ladder and worker-brief capabilities) unless a spec delta or an explicit 'no spec impact' declaration is attached. The plan-creation tool schema the lead sees may not expose the declaration field (passing it as text is rejected: 'must be struct SpecImpact'), so either attach real spec deltas, or keep the governed file out of the plan's steps and have the worker that owns the related change fix it in the same step, recording the reason with a plan decision. Re-fetch the tool schema with ToolSearch before concluding the field is missing. (3) A bug_fixing plan cannot close until its regression test is recorded: the value must be ONLY the test function name (or the exact test title literal), not a sentence; extra words fail with 'not found in the code graph'. After it is recorded, ticking the last already-done step again closes the plan. (4) The merge refuses unless the worker's working tree is clean: untracked artefacts such as browser screenshots under .coding/browser/screenshots block it; move them out instead of deleting them. (5) A worker branch based before earlier merges shows those merges as a reversed diff against the new lead tip; diff against the worker's own merge base and judge only its commits. (6) A worker's branch is named after the first 8 characters of its worker id, so ids that share their first 8 characters are refused. (7) cargo test --workspace stops at the first failing test binary unless --no-fail-fast is passed, so a red mnemo lib run hides the src-tauri suites; the mnemo2 feature tests (team, project) only run with -p mnemo-app --features mnemo2. (8) Two runtime::agent approval tests (cancel_during_approval_exits_agent, interrupt_during_approval_stops_turn_and_keeps_agent_alive) and process_tree::kill_on_close_job_ends_the_whole_tree fail intermittently under parallel load; confirm by running them alone, and on the unchanged lead branch, before blaming a change.
