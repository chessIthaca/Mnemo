Signature (7 occurrences on 2026-11-05 and 2026-11-06, including workers doing the very change that raised the cap): a Mnemo2 worker's turn aborts with "Aborting turn: N consecutive tool errors (the model may be stuck)", usually within a few requests of starting, the worktree is clean at base or holds one uncommitted edit (the failing calls were reads or edits), and Laya nudges one tier up. N was 3 until the cap was raised to 5 (agent::MAX_RETRIES in src/agent/mod.rs); builds from before that change still abort at 3. Since the raise, the harness also pushes ONE harness-attributed user message after the 2nd consecutive failing batch ("[harness tool-error nudge — not the user]", agent::TOOL_ERROR_NUDGE_AT = 2) telling the model to read the errors, change approach and stop and report if it keeps failing; a batch that triggers the identical-failure correction gets only the correction. Recovery that worked every time: (1) team_status detail plus a worktree git status/log check to confirm the failure and what, if anything, was written; (2) team_resume on the same tier (the Laya 'escalate' suggestion was never needed: every tier maps to the same model, and a worker that failed before writing anything has not visibly failed a tier); (3) a team_message that says what is on disk and gives the tool discipline: one tool call at a time; never resend an identical failing call, read the error and fix the named parameter; ops-array anchor items carry ONLY the fields they use (no null placeholder keys); never pass lines and old_string in the same file_edit call; find code with search first and read small ranges; run cargo check after each stage; after two failures of the same tool, STOP and message the lead the error text. Related: 'finished its turn' notices also fire at question-breaks and turn boundaries, so verify commits exist on the worker branch before reviewing or merging; a clean worktree means the notice is premature. A worker's transient provider error ('failed to start stream') is a different failure (usually a dropped VPN); resume it the same way once the connection is back.
