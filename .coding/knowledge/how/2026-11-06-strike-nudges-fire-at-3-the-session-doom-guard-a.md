Laya's stuck-worker strike nudge fires on the 3rd consecutive failed-or-repeated tool call (route_question::Strikes::new(3) in the Mnemo1 loop, NUDGE_STRIKE_LIMIT = 3 in src-tauri/src/mnemo2/team.rs). The session's doom guard (agent::MAX_RETRIES in src/agent/mod.rs) used to abort the turn at the SAME count of 3, so a strike nudge always coincided with a Failed worker; it was raised to 5 together with a harness nudge to the model after the 2nd failing batch, so the lead now hears 'looks stuck' at the 3rd failing call while the worker keeps running, and the worker lands Failed only at the 5th consecutive failing batch. Tests that script a worker into the doom-guard failure must script MAX_RETRIES failing calls (src-tauri mirrors the constant locally as TEST_MAX_RETRIES because it is pub(crate) in the mnemo crate; keep them in sync); three failing calls followed by a success now finish Completed with the strike nudge row still logged. Pump event order when a worker does fail: ToolResult (last) -> strike nudge claimed if not yet fired -> Error -> Failed + outcome row. The failure path logs the outcome row ONLY and never writes nudge_ignored (the worker is resumable: team_resume on a stronger tier takes the nudge and logs a reroute); the ignored nudge waits for a truly terminal point: stop, merge, or abandoned in cleanup. Tests pin this: failed_worker_does_not_log_nudge_ignored and stopped_after_failure_logs_nudge_ignored_once. The 'circles' path (verbatim repeats that succeed) never trips the doom guard (successes reset the error streak), and neither does fail/fail/success/fail/fail. A cleanly finished worker turn sets WorkerStatus::Completed (not Idle) in the pump's Finished arm, so polling tests must wait for Idle|Completed|Stopped|Failed. Live-worker pump tests are possible in src-tauri: build the engine with mnemo::headless::EngineBuilder::new(opts).provider(Arc<ScriptedLlm>) and dispatch through the team; the scripted client serves every request (including model-pinned sessions), returning one LlmEvent batch per complete() and a text stop when the queue empties; unknown tool names produce deterministic failing ToolResults (parse a fragment string as serde_json::Value, unwrap_or(Value::String(raw)) at signature time).
