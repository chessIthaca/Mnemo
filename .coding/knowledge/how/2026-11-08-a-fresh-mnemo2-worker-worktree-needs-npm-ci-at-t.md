+++
title = "a fresh Mnemo2 worker worktree needs `npm ci` at the root before `build:mnemo2`"
created = "2026-11-08"
+++

`mnemo2/node_modules` in a worktree may hold only `.vite`/`.vite-temp` caches (hoisting puts real deps at `<worktree>/node_modules`), so `npm run build:mnemo2` fails inside `npm run check` with "'svelte-check' is not recognized". Fix: `npm ci --no-audit --no-fund` at the worktree root (~30 s, 303 packages), then `npm run build:mnemo2` produces `target/mnemo2-dist` (needed by tauri `generate_context!` for `cargo test --features mnemo2 --lib`). For svelte-check alone before the install, use the main checkout's shim `& C:\Mnemo\mnemo2\node_modules\.bin\svelte-check.cmd` from `<worktree>\mnemo2` and read $LASTEXITCODE. Long cargo runs: launch with `Invoke-CimMethod Win32_Process Create` (not Start-Process), log under `.coding/tmp/`, poll the log for `DONE`.

Amended 2026-11-11: Amended — detached-cargo-run quirks verified on a cold worktree (agent-m1StepLa, plan c463f284, 2027-02). (1) Dual-encoding log: PowerShell 5.1 `>>` appends UTF-16LE to a file created with `Out-File -Encoding utf8`, so a script that mixes them is unreadable as one encoding — poll with `Get-Content` (it also opens files the running battery still holds) and strip "`0" from each line, or write every log line with the same operator. (2) The shell tool's own timeout kills a call containing `Start-Sleep 300`; poll in sleeps of ≤150 s. (3) End-to-end confirmation of the fresh-worktree recipe: `npm ci --no-audit --no-fund` (24 s, 127 packages) + `npm run build:mnemo2` → target/mnemo2-dist, then a 7-step battery (lane_/skip_turn_routing filters, `cargo build -p mnemo2-app`, both clippy runs, `cargo test --workspace --no-fail-fast`, `cargo test -p mnemo-app --features mnemo2 --lib`) all exit 0, ~20 min from cold including a red-check build; the src-tauri build-script App Control block did not fire.
