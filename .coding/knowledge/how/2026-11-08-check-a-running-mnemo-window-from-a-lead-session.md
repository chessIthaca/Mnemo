Screenshot: PrintWindow(hwnd, dc, 2) from a DPI-aware PowerShell process (SetProcessDpiAwarenessContext(-4)), or the capture is cropped. Input without moving the user's mouse: PostMessage WM_LBUTTONDOWN/UP, WM_CHAR and WM_KEYDOWN to the Chrome_RenderWidgetHostHWND child; coordinates are relative to that child. Traps: parallel Claude sessions share one Mnemo2 window, so dialogs can close and selection can change between clicks; capture first and never click Delete or Stop by coordinates. A child started with Start-Process dies when the tool's shell exits; start it with run_in_background. The desktop app ignores MNEMO_HOME and always uses ~/.mnemo (config_dir_named); only the headless engine honours it, so snapshot and restore ~/.mnemo files it may write.

Amended 2026-11-08: To press a button in the window without coordinates, use System.Windows.Automation from PowerShell: find it by exact accessible name (the aria-label, such as "Delete <worker name>") and call its Invoke, Toggle or SelectionItem pattern. The Team button needs Toggle. Set $ErrorActionPreference = 'Stop' or failures print as success, and write "${Arg1}?" because PowerShell reads "$Arg1?" as a variable named Arg1?. Before confirming a delete, require the dialog titled exactly "Delete <name>?", which the app uses only when one worker can be deleted. Reading state does not make the window yours: a person at the keyboard shares it, and dialogs can change between your calls. Starting a single-worker delete leaves a live dialog on their screen, and "Delete old (N)" removes every merged worker's record and transcript with no undo, so ask them to do deletions themselves or say so first. Before deleting anything in .coding/mnemo2: lead.json.bak and preferences.json.bak are the app's last-good recovery files, not leftovers, and a dated team.json backup can be the only copy of workers since deleted from the ledger.
