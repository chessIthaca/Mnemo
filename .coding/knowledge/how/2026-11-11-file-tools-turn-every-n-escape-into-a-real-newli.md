The file_edit / multi_edit / file_write new_string layer converts every backslash-n sequence to a REAL newline — no amount of escaping (\\n, \\\\n) lands the two-character `\n` Rust escape in the file (verified with controlled scratch experiments, 2027-02-21, job rmStaleC). When an edit needs a source-level `\n` escape (e.g. a one-line Rust fixture string like `.execute(json!({"text": "head\n\nbody..."}))`), the only expressible form is a multi-line string literal with raw newlines — which is valid Rust (a `"` literal may span lines; the newlines become part of the string) and semantically identical. In backlog_add fixtures this even satisfies the tool's headline/blank-line/body validation. Don't burn cycles trying escape variants; either use the multi-line literal and note the style deviation, or reword to avoid the escape. Related trap: a backslash at end-of-line inside a string is Rust's line-continuation — it STRIPS the newline, so `head\` + line break + `body` concatenates with NO separator.
