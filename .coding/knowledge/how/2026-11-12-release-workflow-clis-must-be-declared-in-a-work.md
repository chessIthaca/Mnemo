Rule for this repo: a GitHub Actions release workflow that runs an npm-provided CLI (e.g. `npx tauri ...` in .github/workflows/build.yml, cwd src-tauri/mnemo2-app) resolves the binary from the npm workspace root's node_modules. It therefore needs (1) `"@tauri-apps/cli"` declared in some workspace package.json (today `mnemo2` devDependencies, `"^2.12.4"`) and (2) a `node_modules/@tauri-apps/cli` entry in package-lock.json carrying `dev: true` and `bin: { "tauri": "tauri.js" }` plus its optional `@tauri-apps/cli-*` platform packages, or `npm ci` installs no `tauri` executable and npx fails instantly with "could not determine executable to run". PR CI (ci.yml) and `npm run rebuild:mnemo2` never execute the Tauri CLI (they use `cargo build -p mnemo2-app --features custom-protocol`), so the only pre-tag check is the Rust guard `build_workflow_tauri_cli_is_declared_and_locked` in tests/integration/ci_workflow.rs, which parses build.yml, root package.json, every workspace package.json and package-lock.json. Add such a guard whenever a release workflow starts calling a new external CLI. Verify locally with `npm ci` then `cd src-tauri/mnemo2-app && npx --no-install tauri --version` (prints `tauri-cli 2.12.4`).
