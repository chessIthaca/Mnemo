Verifying a grep that contains non-ASCII text (→, ⟦, …) on this Windows/PowerShell 5.1 machine: never type the Unicode directly into a `shell` tool command string — the console transport can silently mangle it and the check false-passes (mangled pattern → zero matches → looks clean). Use (1) the app's `search` tool, whose parameters travel as JSON and are Unicode-safe, or (2) a PowerShell check that builds the character inside the script from a codepoint: `$arrow = [string][char]0x2192; [regex]::Matches($text, "Settings $arrow (Classifier|...)").Count` (em dash via `[char]0x2014` when used in .Replace arguments). Always add a positive control — count a string that must exist (expect > 0) — so a mangled transport exposes itself instead of silently passing. For byte-fidelity comparisons against HEAD: set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` before `git show`, read files with `[System.IO.File]::ReadAllText` (PS 5.1's Get-Content defaults to ANSI and mangles UTF-8), and extract passages to compare using an ASCII-marker Slice function (start/end markers typed as pure ASCII) rather than retyping the special characters. The `git` tool's structured `message` parameter, unlike raw shell strings, is Unicode-safe.
