Mnemo shares one `laya-serve` per machine through a generic lease dir implemented in `src/host/shared_service.rs` (crate-root re-export `mnemo::shared_service`): `service.json` {pid, port, token, version, started_ms, created, models} written atomically and user-only (temp file + rename; Unix 0600 / Windows DACL via `mnemo::config::keys::restrict_*`), `lease-<instance pid>.json` per attached instance — each lease body carries a unique token (nanos+pid+sequence) and `LeaseGuard::drop` removes the file only on a token match, so an older guard never deletes a newer lease of the same pid. Dead pids are pruned via `mnemo::process_tree::pid_alive`; `spawn.lock` serialises spawns (60 s stale takeover, 30 s wait then the body runs with `locked == false`, and an unlocked caller must never publish a shared service — `acquire_on` then spawns a private child and leaves the descriptor untouched).

`process_tree::process_creation_id(pid)` (Windows GetProcessTimes FILETIME, Unix `ps -p <pid> -o lstart=`) is the pid-reuse guard: `ServiceInfo.created` and `ManagedChild.created` record it, and every pid-based kill (`shared_service::kill_service_tree`, laya's `kill_tree` taskkill/group-kill fallback) signals only on a match — an unproven pid is skipped and logged. The watchdog subcommand (`mnemo2-mcp laya-watchdog --run-dir <dir> --server-pid <pid>`) refuses a run-dir not shaped `<config>/run/<service>`, kills only the descriptor's pid, and lands the idle kill 45-60 s after the last lease (poll-quantized).

`LayaManager` (src/host/laya.rs): `try_attach` leases a LIVE same-model server even when the health probe fails — a cold start — returning `LayaServer::Attaching {port, pid}`; `await_shared_ready` runs the ordinary readiness budgets against it, falls back to a re-acquire only when it DIES while loading, and on a live-but-silent expiry KEEPS the lease and starts the monitor with status Failed (the classifier self-heals; the monitor promotes Failed→Ready when the probe answers). `LayaServer` = Attached | Attaching | Spawned{port, generation, shared}. `acquire`/`acquire_on(models, Option<port>)` = spawn lock → attach or spawn; `finish_start` re-points the caller's classifier slot when another instance won; `attach_shared` is the probe+lease-only fast leg. Every path that leaves the instance using a shared server starts `ensure_shared_monitor`: a task holding a Weak (a dropped manager runs its Drop — lease released — never pinned alive), ticking `shared_tick(strikes) -> TickOutcome` (Keep / Strike / Recover) — a READY server needs `SHARED_MONITOR_STRIKES` (2) consecutive silent probes before `recover_shared_server` re-acquires and re-points the slot provided via `provide_classifier_slot`. `wait_until_ready` takes its (idle, absolute) budgets as parameters; tests shrink them via `with_probe_budget`, the monitor interval via `with_monitor_interval`. `stop`/`Drop` release only this instance's lease; `stop_if_generation` spares a shared child while other live leases exist; a private spawn releases any held lease and an attach stops the previous private child.

Shared spawn = detached (Windows DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP, Unix process_group(0) — not setsid, no libc dep), no kill-on-close job, only for catalog checkpoint ids; fine-tuned artifacts, model mismatches and missing watchdog launchers fall back to the private kill-on-close child. Tests live in `cargo test -p mnemo --lib host::shared_service` and `host::laya` (scripted processes, temp dirs, no Python; real live stub pids for the pid-keyed leases; `gated_answer_server()` — a gate-flag stub HTTP server whose held socket answers only when the test opens the gate — covers the cold-start/readiness paths deterministically under parallel test load).
