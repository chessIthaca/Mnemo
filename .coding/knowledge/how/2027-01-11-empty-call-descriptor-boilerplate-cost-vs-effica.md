Data point for tool-descriptor tightening (user question, 2027-01 session). No code changed.

(1) DUPLICATION. The 4-sentence empty-call block ("Always pass X — e.g. {…} / No zero-argument form; on a 'X is required' error rewrite the full call, do not resend the empty shape / If you catch yourself emitting X with no Y, stop — write the Y first, then the call") is hand-copied into every tool with a required field: 13 occurrences across 5-6 files — src/tool/agent/codegraph.rs (4 graph tools), src/tool/agent/read_files.rs, src/tool/agent/shell.rs, src/tool/agent/git_read_tool.rs, src/tool/memory/mod.rs. Each tool carries it TWICE: the schema description AND the execute() error hint (read_files::invalid_args_error).

(2) EFFICACY. Descriptor prose is paid every turn; the error hint only on failure. This session I emitted an empty read_files call whose description leads with exactly that rule — recovery came from the ERROR text, on the next call, not the description. Also note the global TOOL-CALL DISCIPLINE section already states the rule once ("No call goes out with an empty argument object when it has required fields"), so the per-tool copies are redundant with it.

(3) TEST PIN. src/tool/agent/git_read_tool.rs::schema_advertises_the_no_zero_argument_rule asserts the block LEADS git_read's description (starts_with "Always pass `op`", contains "No zero-argument form", "do not resend the empty shape", "If you catch yourself"). Any trim must update it. History: backlog d9ad618e + 26cdbaf8 landed this deliberately — revisit with data, not as a bug.
