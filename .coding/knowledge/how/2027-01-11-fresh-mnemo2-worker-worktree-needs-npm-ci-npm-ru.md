Fresh Mnemo2 worker worktrees (C:\Mnemo\.worktrees\agent-*) have no target/ and no node_modules, so a first `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2` fails in tauri's generate_context! unless the embedded frontend dist exists. Required setup: `npm ci --no-audit --no-fund` then `npm run build` at the worktree root (frontend vite outDir = ../target/frontend-dist, which tauri.conf.json's frontendDist points at). Also: the shell tool kills commands at 300 s regardless of timeout_ms — run long builds detached via Start-Process with RedirectStandardOutput/RedirectStandardError into .coding/tmp/*.log and poll. The worktree has its own target dir (no shared CARGO_TARGET_DIR), so the first mnemo2 test build takes ~10+ min after deps are cached in registry.

Amended 2026-11-10: Start-Process caveat (2026-11-10, worktree agent-savingsI, plan 02b200ad step 3): the plain Start-Process launch — `powershell -File <script>` with `-WindowStyle Hidden` but NO `-RedirectStandardOutput/-RedirectStandardError` and all redirection done inside the script — failed silently: the child lived ~5 min, never executed even the script's first line (no log file, no cargo.exe child, no target/ artifacts), then died. Syntax was verified clean (Parser::ParseFile, 0 errors). Relaunching the identical script via `Invoke-CimMethod Win32_Process Create` with `-NoProfile -NonInteractive` worked immediately (log and cargo compile within 5 s). So: prefer CIM Create, or only the Start-Process variant that redirects BOTH streams as tool parameters; never rely on in-script redirection behind a redirect-less Start-Process.

Amended 2026-11-10: Detached battery scripts (2026-11-10, worktree agent-hangWind, plan 09d6fe1f step 2): two PowerShell 5.1 pitfalls silently wasted a full battery cycle. (1) NEVER name a helper function's parameter `$Args` — it is an automatic variable; `param([string[]]$Args)` + `& cargo @Args` splats EMPTY and cargo just prints its help, exit code 0, so every leg "passes" without compiling. Name it `$CargoArgs`. (2) PS 5.1 `>>` and `Add-Content` create the log as UTF-16LE (spaces-between-chars mojibake in UTF-8 readers); use `| Out-File -Append -Encoding utf8` and capture `$LASTEXITCODE` immediately after the pipeline (a cmdlet in the pipe does not alter it — cargo's code is what you read). Working pattern: a Run-Leg function writing `=== LEG: name ===`, cargo output, `=== exit=$code (name) ===`, poll the CIM-Create'd PID with Get-Process and Select-String the log for `^=== LEG|^=== exit|test result:|error[`.
