title = "Laya asks one question and checks itself like indexing"
created = "2026-11-06"
+++

Settings > Tiers asks only how much Laya helps pick the tier (off, watch, suggest, auto); a choice below its 30-decision unlock count shows a hint and still saves. The gates, min words, fallback tier, kNN, nudges and dispatch-effort inputs are gone from the UI but stay in mnemo2.toml and keep working; Mnemo1's own Classifier settings still edit its gates. Only the tier ladder has a Save button; Laya's other flags save per click under a collapsed section, so nothing else can raise an unsaved-changes prompt. The routing eval is now the automatic Laya check (src-tauri/src/mnemo2/laya_check.rs): it starts at project open, on a choice other than off, after an install settles, and on Check again. Unforced, it skips silently when routing is off, Laya is down, or the record's fingerprint (hand set plus checkpoint stamp) still matches. Its progress is a third `laya` pass on the indexing status, so it shows in the status line and on the page, and the first-run project hold ignores it. A successful check writes route_eval.json and applies its suggested gates through update_routing_settings, the single locked writer of [routing]; a gate with no suggestion stays as stored, and a hand-edited gate is overwritten when the fingerprint next changes. Five consecutive no-answers, under 90% usable four-label answers, or a 15-minute budget fail the check visibly and write nothing. The suggestion formula is unchanged: the lowest gate with at least 90% accuracy, which can rest on very few cases.
