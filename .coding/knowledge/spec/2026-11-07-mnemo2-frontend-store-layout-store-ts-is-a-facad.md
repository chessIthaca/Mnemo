title = "Mnemo2 frontend store layout - store.ts is a facade over per-concern modules in mnemo2/src/lib/store/"
created = "2026-11-07"
+++

mnemo2/src/lib/store.ts (about 240 lines) only holds showToast, dismissToast, resetDemo, the `actions` object (95 keys) and re-exports; components keep importing app/actions/currentProject/... from it. The concerns live in mnemo2/src/lib/store/: core.ts (app writable, createInitialState, derived stores, withToast, nextId, leadError, loadSoundToggles at import), layout.ts (pure width math), workerView.ts (pure worker/timeline mapping, buildWorker), preferences.ts, browser.ts (native pane + its app.subscribe at import), workbench.ts, navigation.ts, board.ts, indexing.ts, team.ts (team sync, worker thread/activity maps), lead.ts (lead connection + lead actions), teamActions.ts, externalLead.ts, project.ts (open/close/cleanup, initExternalLead). Rules: a module-level `let` is private to its module (accessors such as bumpLeadSession, getTeamTransport, hasPendingPreferences, discardPendingPreferences, disconnectBrowser); imports are acyclic in the order core/layout/workerView -> preferences/board/indexing/browser -> workbench -> team/navigation -> lead/teamActions -> externalLead -> project -> store.ts; modules import engines from the same files so vi.mock still applies. store.exports.test.ts pins the facade's exports and action keys.
