created = "2026-11-16"
evidence = "src/app/worktrees.rs pool functions and real-git tests; src-tauri/src/mnemo2/team/tests.rs pool tests."
+++

New Mnemo2 workers and audits get a reused checkout folder `<project>/.worktrees/pool-<n>` (worker branch names are unchanged), so its own `target/`, `node_modules/` and `.coding/codegraph.db` stay warm from the previous worker; workers build there and never set CARGO_TARGET_DIR. src/app/worktrees.rs provision_agent_checkout reuses the lowest free pool (registered, detached HEAD, clean, held by no worker record, claimed through a `pool-<n>.claim` file created exclusively with the pid; a claim is stale only when its pid is dead, and the Windows probe fails closed) with `switch --detach <base>`, `clean -ffdx -e /target/ -e node_modules/ -e /.coding/codegraph.db*` and `switch -c`; otherwise it creates the next index above every existing folder and every held path. Release detaches the checkout (idempotent for a clean detached pool); a user-confirmed delete discards and releases; every pool git command is preceded by ensure_registered_pool_checkout (direct child of canonical .worktrees, pool-<n> name, no link or junction, registered, show-toplevel is the pool itself). In src-tauri/src/mnemo2/team/: checkout_pool_lock spans held-set computation through record insertion; a released record's worktree field is cleared and persisted; startup repairs a merged record left on a clean detached pool; checkout-cleanup retries are best-effort and never fail a landed merge; merge lands the validated commit id and requires the pool to be on the worker's branch. Records with old `.worktrees/agent-<id8>` folders keep the remove-the-folder path. Pools are never deleted or pruned automatically.
