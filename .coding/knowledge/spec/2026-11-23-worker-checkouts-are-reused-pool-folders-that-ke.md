evidence = "Timed warm incremental build 32 s in .worktrees/pool-1 on 2026-11-23; after a merge pool-1 was detached and clean with its 8.7 GB target kept; tests a_released_pool_is_reused_and_keeps_build_caches (src/app/worktrees.rs) and concurrent_dispatches_never_share_a_pool (team tests)."
+++

Workers and audits are checked out into reusable folders `<root>/.worktrees/pool-<n>` (lowest free n reused, else max+1; no cap); only the folder is pooled, each worker still gets its own agent branch. A pool is held while a worker record's `worktree` equals it. Release (merge, recovery, delete, start-screen cleanup, rollback) does not remove the folder itself: it checks the worker's branch and a clean tree, detaches HEAD, and clears the record's `worktree`, so the merged branch can be deleted. A SOFT pool cap then trims the released pools above the worker slot count: after a release that frees a pool (merge, audit close, delete, cleanup), at the end of set_slots and once at start, `trim_pool_checkouts` removes every FREE pool whose index is above the slot count — highest first, `git worktree remove --force` from the root, then `remove_dir_all` for a folder that survives with its ignored caches (Windows npm junctions; that removal never follows a link), then `worktree prune`. A pool is never removed while a record holds it, while it is on a branch, dirty or has untracked work, or while another instance holds its claim; every pool at or below the slot count stays as a warm cache. Dispatch never waits on the cap (soft), so a pool above the slot count may still be created while the lower ones are held. Code: `trim_pool_checkouts` and the shared `pool_is_free` in src/app/worktrees.rs; `TeamRuntime::trim_idle_pools` in src-tauri/src/mnemo2/team.rs. Reuse = detach at the base, `git clean -ffdx` excluding /target/, node_modules/ and /.coding/codegraph.db*, then create the new branch, so build caches and the code graph stay warm. A dirty, ownerless-attached or unregistered pool is never reused. Confirmed delete discards uncommitted work (reset --hard + clean -ffd, no -x). Legacy `.worktrees/agent-<id8>` records keep the old remove-folder path. Allocation is serialized by TeamRuntime's checkout_pool_lock. Workers build in the checkout's own target/ and never set CARGO_TARGET_DIR (agent.md). Why: cargo keys workspace crates by absolute source path, so incremental reuse needs a stable path; cold `cargo test --workspace --no-run` 156 s vs about 32 s warm in a pool after touching src/lib.rs. Code: src/app/worktrees.rs (pool primitives); src-tauri/src/mnemo2/team/ spawn.rs, audit.rs, merge.rs, control.rs, deletion.rs; src-tauri/src/mnemo2/workbench.rs.
