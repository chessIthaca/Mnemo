Workers and audits are checked out into reusable folders `<root>/.worktrees/pool-<n>` (lowest free n reused, else max+1; no cap); only the folder is pooled, each worker still gets its own agent branch. A pool is held while a worker record's `worktree` equals it. Release (merge, recovery, delete, start-screen cleanup, rollback) never removes the folder: it checks the worker's branch and a clean tree, detaches HEAD, and clears the record's `worktree`, so the merged branch can be deleted. Reuse = detach at the base, `git clean -ffdx` excluding /target/, node_modules/ and /.coding/codegraph.db*, then create the new branch, so build caches and the code graph stay warm. A dirty, ownerless-attached or unregistered pool is never reused. Confirmed delete discards uncommitted work (reset --hard + clean -ffd, no -x). Legacy `.worktrees/agent-<id8>` records keep the old remove-folder path. Allocation is serialized by TeamRuntime's checkout_pool_lock. Workers build in the checkout's own target/ and never set CARGO_TARGET_DIR (agent.md). Why: cargo keys workspace crates by absolute source path, so incremental reuse needs a stable path; cold `cargo test --workspace --no-run` 156 s vs about 32 s warm in a pool after touching src/lib.rs. Code: src/app/worktrees.rs (pool primitives); src-tauri/src/mnemo2/team/ spawn.rs, audit.rs, merge.rs, control.rs, deletion.rs; src-tauri/src/mnemo2/workbench.rs.
