The Mnemo2 app is the hub: one AppHub per app instance (src-tauri/src/mnemo2/remote_hub.rs), state in <config_dir>/hub behind hub.lock, and no network listener until the first node is paired (default port 47310; the app listens on all interfaces, tests only on loopback). The lead tool team_hosts (list, pair, revoke) asks for approval; host names must match ^[A-Za-z0-9._-]{1,64}$ and may not start with '-'. Placement (team/placement.rs) runs after the tier is chosen. Claude-agent tiers and an explicit host "local" stay local. A pinned host must be paired and connected, have a free slot, run git 2.30 or newer, and be a Windows host when the check commands are Windows-only (decided from the commands only). An unpinned worker goes only to a node that passed the project's checks on that host; otherwise it runs locally. A host fails that qualification only on an environmental error such as a missing command. Code moves only as git bundles: the base commit goes to the node's pool checkout, and the worker branch comes back into a local shadow checkout before checks, review, merge and turn-end bookkeeping. Checks and proofs run on the node. WorkerRecord.remote names the host, and remote workers do not use local slots. When a host is lost, only a worker mid-turn becomes Interrupted or Failed, but its live entry is always dropped; an outage longer than 120 s fails it resumably. src-tauri/mnemo2-app/tests/remote_team_e2e.rs proves the whole flow against a real mnemo2-node process.
