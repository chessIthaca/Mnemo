SPEC: DeepSeek-family wire guarantee — reasoning_content key on the tail assistant turn. The OpenAI-compat request builder (src/provider/openai.rs, raw-echo branch of build_request_json) injects `reasoning_content` (the structured Message field, else "") into the age-0 assistant raw echo when `policy.reasoning_required && policy.reasoning_field == Some("reasoning_content") &&` the echoed key is absent — so foreign 429-fallback turns (GLM/Kimi tool-call raws without the key) can no longer poison the tail. Live-verified contract (2026-12-23, 27 curl probes vs api.deepseek.com, plan c9b5cbe4, commit b23463c on wt/agenticcoder): with reasoning_effort present, DeepSeek validates ONLY the request tail — the assistant turn that owns it (last message, or issuer of trailing tool results); key EXISTENCE matters, any value accepted incl ""/null; historical assistant turns tolerate a missing key entirely; effort param absent → no validation. Gemini (also reasoning_required, but thought_signature continuity, reasoning_field: None) never gets the injected key (Rule-1 byte-identical echo preserved); age-0-only injection keeps the pressure-strip (ffe59699) free to remove HISTORICAL reasoning text. Known adjacent gap (review note, pre-existing): the synthetic-path re-add (~openai.rs:1508) is not field-scoped — a Gemini request with a synthetic assistant message still gets the key; unverified whether Google's endpoint rejects it. Detail: BUG memory 1284933d + .coding/knowledge/bug/2026-12-23-deepseek-thinking-mode-400-tail-assistant-turn-m.md.

Amended 2027-01-11: 2026-09-12 — WIDENED by the third recurrence (backlog 969bc37d, plan c6cb69f7): the tail guarantee above is necessary but NOT sufficient. Live evidence: provider-errors.jsonl ids 104/112 (17:31:17 / 17:32:57 EDT) — both requests had the age-0 tail-owner keyed (the skill_end turn, 1295/742 chars, tool result correctly paired) and DeepSeek still returned the same 400. The discriminator: both were the FIRST deepseek-v4-flash request after a milk-turn cross-vendor re-entry — merge_to_main runs on glm-5.3-flash, Rule 5 strip_cross_vendor_reasoning had stripped reasoning_content from every cross-vendor assistant turn, and skill_end re-resolved the provider back to the deepseek pin — leaving every older tool-call turn in the open chain keyless (census: 72/78 and 79/85 assistant turns keyless). CORRECTED CONTRACT: under a requires-reasoning_content policy the key must be present on the age-0 tail-owner AND on EVERY assistant turn that carries tool_calls; text-only historical turns still tolerate a missing key (probes A/D/G2). Value: the structured text at age 0, the bare "" for older tool-call turns (any value accepted — probe T2); re-added also when the retention strip removes it, on both the raw-echo and the synthetic path. Implemented by the shared needs_reasoning_readd predicate (src/provider/openai/request.rs), with the serialized-prefix fingerprint hashing the re-add MODE (0/1/2) so a splice can never keep an age-0 serialization; regression test deepseek_keys_every_tool_call_turn_after_cross_vendor_reentry (src/provider/openai/tests.rs; companion pins: retention_deepseek_synthetic_tool_call_turn_keeps_bare_key_under_pressure). Residual: the exact API-side mechanism is inferential (reading A: every tool-call turn must be keyed; reading B: an undeclared tail-owner tool call — skill_end is absent from the post-state tools array while skill_start is present — makes the validator fall back to the previous keyless turn); the fix is a strict superset curing both.
