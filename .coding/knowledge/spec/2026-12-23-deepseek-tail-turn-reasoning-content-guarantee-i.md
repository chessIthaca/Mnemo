SPEC: DeepSeek-family wire guarantee — reasoning_content key on the tail assistant turn. The OpenAI-compat request builder (src/provider/openai.rs, raw-echo branch of build_request_json) injects `reasoning_content` (the structured Message field, else "") into the age-0 assistant raw echo when `policy.reasoning_required && policy.reasoning_field == Some("reasoning_content") &&` the echoed key is absent — so foreign 429-fallback turns (GLM/Kimi tool-call raws without the key) can no longer poison the tail. Live-verified contract (2026-12-23, 27 curl probes vs api.deepseek.com, plan c9b5cbe4, commit b23463c on wt/agenticcoder): with reasoning_effort present, DeepSeek validates ONLY the request tail — the assistant turn that owns it (last message, or issuer of trailing tool results); key EXISTENCE matters, any value accepted incl ""/null; historical assistant turns tolerate a missing key entirely; effort param absent → no validation. Gemini (also reasoning_required, but thought_signature continuity, reasoning_field: None) never gets the injected key (Rule-1 byte-identical echo preserved); age-0-only injection keeps the pressure-strip (ffe59699) free to remove HISTORICAL reasoning text. Known adjacent gap (review note, pre-existing): the synthetic-path re-add (~openai.rs:1508) is not field-scoped — a Gemini request with a synthetic assistant message still gets the key; unverified whether Google's endpoint rejects it.
