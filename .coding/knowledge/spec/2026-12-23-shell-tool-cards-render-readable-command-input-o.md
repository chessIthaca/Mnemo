SPEC: shell tool cards render readable command input/output in the expanded detail body (user directive, backlog 8c1d8a47, plan 2035cb82, commit 01f7b62 on wt/agenticcoder 2026-12-23). Message.tsx CallDetail: when name === "shell", the args section renders purpose/cwd as muted labels + the command in a pre block (no raw {"command":...} JSON); the result section renders stdout, a labeled red-tinted stderr pre, and an exit-code chip on the result label (muted slate for 0, red-400 for non-zero). The logic lives in two React-free exported helpers in frontend/src/lib/toolCardPaths.ts: shellCallFromArgs (args → {command, purpose?, cwd?} | null; null falls back to the generic pretty-JSON branch) and parseShellOutput (display output → {stdout, stderr|null, exitCode|null}). parseShellOutput is STRICT by design: exit code extracted only when the FINAL line matches /^\[exit code: (-?\d+)\]\s*$/ (the shell.rs trailer is always the last line — src/tool/agent/shell.rs:288), stderr split on the FIRST "\n[stderr]\n"; truncation-safe (a capped output's final line is the cap note → exitCode null → no chip). All parsed values render as React-escaped text nodes. Other tools keep byte-identical generic rendering. 12 unit tests pin the contract in toolCardPaths.test.ts.
