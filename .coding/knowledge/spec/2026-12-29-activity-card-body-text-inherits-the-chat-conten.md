Card body text in the agent chat renders at the SAME size as normal assistant text: it inherits 1em of the chat content — the Conversation container sets font-size: var(--app-font-size) (Conversation.tsx:94) and globals.css forces .prose to font-size: inherit, so the finalized assistant markdown renders at --app-font-size and the cards match by inheriting (backlog 900fe8d8, plan 10650092). NO text-xs / text-sm / text-[0.875em] downscale on any activity-card container (ToolCard, MemoryEntryCard, VisionEntryCard, the skill case in frontend/src/components/chat/Message.tsx). Labels/headers MAY keep a distinct smaller treatment but it must be em-based so it scales with the setting: text-[0.75em] for status/running indicators, section labels, and code pre blocks (mirroring the assistant prose's own CodeBlock treatment), text-[0.65em] for tier badges. All utilities in the card components (Message.tsx) are em-based per SPEC: tool-card spacing must be em-based (4c2f16ba) — including the CallDetail pre-block scroll caps (max-h-[24em]) and the card-path diff cap (CallDetail passes maxHeightClass="max-h-[24em]" to UnifiedDiffView; the shared max-h-64 default stays for non-card consumers). Shared child viewers keep their own treatment (CodeBlock/InlineMarkdown for assistant prose; UnifiedDiffView's rem line padding) — the same carve-out as the tier-badge chip. Rem-based utilities ignore --app-font-size and break the two-font-size guarantee (em/inherited classes scale by construction; that is why the no-rem audit IS the verification). Pinned by the "frameless + normal-size cards (backlog 900fe8d8)" source-contract describe in frontend/src/lib/toolCardPaths.test.ts (REM_UTILITIES audit + frameless assertions + affordance checks, scoped via fnSrc/caseSrc; the card-path diff cap pinned in the CallDetail test).
