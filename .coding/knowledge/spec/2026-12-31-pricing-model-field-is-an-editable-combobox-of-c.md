SPEC (backlog 82dd66fc, plan ec52b07f, commits 4e9641e/a96ab1c/9b89d71 on wt/agenticcoding): the Settings → Pricing model field is an EDITABLE COMBOBOX — a dropdown listing the models the configured endpoints serve (EndpointInfo.models via getSettings, grouped/deduped across endpoints and annotated with endpoint names — modelOptions.ts buildModelOptions) plus free typing for anything else. Selecting an entry fills the model id; typing filters (empty → all, exact match → all, else case-insensitive substring); save behavior is UNCHANGED (trim + non-empty filter + saveSettings({ pricing }) — no membership validation, so a typed model not in the list still saves; pricing is keyed by exact model name via Config::pricing_for → StatsView modelCost). ModelCombobox.tsx (frontend/src/components/settings/sections/) is the reusable component: ARIA 1.2 combobox pattern (role=listbox/option, aria-autocomplete=list, empty-filter message OUTSIDE the listbox); the entry + toggle buttons prevent the mousedown default and the root-blur close + activeElement-guarded refocus make focus behavior platform-uniform (WebKit/macOS does not focus buttons on mousedown — without the guards, mouse selection silently no-ops there). Tests: modelOptions.test.ts (8 unit), ModelCombobox.test.tsx (14 markup/source-contract), PricingSection.test.ts (4 wiring contracts) — the node-env vitest convention (no React DOM infra; pure helpers + ?raw source contracts + renderToStaticMarkup).
