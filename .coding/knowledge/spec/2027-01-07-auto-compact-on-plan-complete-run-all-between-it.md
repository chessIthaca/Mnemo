`auto_compact_on_plan_complete` (default false) — opt-in `[general]` setting (config.toml, Settings → Advanced) that compacts the main agent's context between Run-All items: after each completed plan resolves, before the next backlog item dispatches, so overnight loops start every item with a clean summarized context. Plan 7369d7f3, commits 06aca97 + dd9d7a0 on wt/agenticcoding. Semantics: (1) trigger in on_main_turn_resolved's run-all branch (src-tauri/src/ipc/run_all.rs:~1618-1640), gated on `item_resolved && setting` — exactly one compaction per resolved item; interactive completions never trigger it; (2) the compact-then-dispatch task is SPAWNED, never awaited inline (the Compacted event flows through the same event forwarder — inline await would deadlock); (3) wait = shared watch-counter (BacklogContext.compact_signal) incremented by the forwarder on the main agent's Compacted OR the Error paired with its CompactStarted (failed compaction resolves immediately); subscribe-before-send; 600s timeout then proceed — compaction is an optimization, never a blocker; (4) run-state re-check before dispatch: run gone ⇒ log + skip, stop requested ⇒ end_run, else dispatch (a user stop during the minutes-long window is honored); (5) current_item cleared once the item resolves (before the window opens) so an interactive turn during the window can't resolve against the completed item; (6) RunAllProgress.compacting surfaces "· compacting…" in the Backlog progress line.
