SPEC (2027-01-07, user ask "clarify backlog resolution: finished vs done, Clear-finished & Run-all"; plan 8c2edf0f): the consolidated backlog-resolution contract — audited, NO divergence found, documented in the run_all.rs module doc ("Finished — the one notion" section) + README backlog paragraph + pinned by tests. (1) "Finished" = TERMINAL = Done|Failed|CantResolve — one notion at every consumer: the guarded transition table (terminal→Pending only, the requeue), BacklogStore::requeue (accepts all three), clear_finished (soft-deletes exactly those), the Backlog tab's retry/clear-finished affordances (canRetry + hasFinished cover all three), the memory indexer (scans live Pending only — terminal = history), run-all/auto-feed dispatch (live Pending non-deferred only — a terminal item is never re-run). (2) Clear-finished: soft-deletes exactly the three terminal statuses (deleted_at stamp, JSONL + image sidecars kept, 30-day startup purge, union-merge-safe); NEVER clears a mid-flight item (Pending + InFlight kept). (3) Run-all: run-scoped done/total counters are in-memory state — mid-run clearing cannot touch them (backlog_clear_finished touches only the store + the change event; pinned by source contract); the start-time adoption sweep snapshots store.items() (live-only) so a soft-deleted InFlight item can never be resurrected (pinned by source contract). (4) The escape hatch (HOW d899e4f7): an agent-stamped terminal status (e.g. CantResolve via backlog_status when the automatic stamp missed) wins over the automatic Done stamp — the guarded table refuses terminal→terminal, the item keeps the agent's stamp, and the run still counts it resolved (the done counter bumps on the terminal resolution). Resolution path: Done = the turn-resolution plan-loop gate (workflow Complete + ≥1 transition this turn) + commit_success; Failed = plan abandoned; other turn ends → annotate + the run waits (status kept); a main-agent exit/crash requeues the orphan to Pending (exit drain + run-start adoption sweep) — unless the work already landed (the done-orphan guard, 6c6966b9: plan complete + commits after the checkpoint → auto-resolve Done). Scope boundary: the done-orphan guard (6c6966b9 — run-all re-dispatching already-finished items) was carved out as a separate task and has since LANDED (plan 5b988455): the drain/adoption sweep auto-resolves landed orphans to Done.
