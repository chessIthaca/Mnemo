SPEC (2027-01-07, plan 47cce50b, backlog ffd4bac3, commits d92b117→8d30bd7 on wt/agenticcoding): the run-all between-items auto-compact (`auto_compact_on_plan_complete`) now respects the fill-rate dial — it fires only when the post-item context is at/above the SAME effective threshold the engine's fill-rate summarization path uses (`summarize_at_fill_rate` × window, proxy-ceiling cap included), computed through the shared `ContextManager::effective_summarize_threshold` helper (src/agent/context.rs; `effective_summarize_at` delegates to it — no formula drift). Below the threshold the summarization LLM call is skipped and the next item dispatches directly; off (default) is byte-identical. Provenance (six review rounds converged on this): fill rate from the LIVE loop (`AgentLoop::fill_rate()`), ceiling from the factory's startup snapshot (`AgentLoopFactory::proxy_cache_ceiling()`) — the same values the engine's factory-built CMs carry. Exception: resolver-built CM turns (a `[models.*]` slot serving the turn, a 429-sticky reroute — on a picker pin or the default provider — or a forced model) read the LIVE config's ceiling; bounded, restart-healed, preflight backstop still guards the window. The app's only context-fill source: the per-agent `context_usage` map on AgentRuntimeContext (state.rs), fed by the forwarder's ContextUsage arm (events.rs), dropped on Exited. Blind cases (no main agent / loop / factory / usage entry, max==0) → compact (the pre-change behavior). Gate: `should_between_items_compact` + `between_items_compact_gate` in src-tauri/src/ipc/run_all.rs, wired into `compact_then_dispatch_next` before the compacting flag. Docs: README config paragraph + AdvancedSection help texts surface the knob→mechanism relationship. Tests: root 2133/0/4, src-tauri 278/0/0, frontend 1060/75. Reviews: .coding/reviews/2026-09-08-between-items-compact-fill-rate-gate*.md (6 rounds, PASS at round 6).
