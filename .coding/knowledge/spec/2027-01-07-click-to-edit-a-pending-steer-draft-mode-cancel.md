SPEC (2027-01-07, plan d8c74589, user request 2026-12-30): a pending (not-yet-landed) steer bubble in the InputBar backlog is click-to-edit — the text is a button (title "Edit this steer — loads it into the input; send re-queues it", a Pencil hover hint sitting OUTSIDE the truncating span so it stays visible for long texts). DRAFT MODE: clicking loads the steer text into the main input (the edit surface — overwrites any input draft, same semantics as the Up-arrow history navigation) and cancels the pending steer FULL-STACK immediately via the shared cancelPendingSteer helper (the exact X flow: removeSteer + cancelSuggestion → AgentCommand::CancelSuggestion); sending re-queues the edited text as a fresh steer via the normal steer branch (handleSend steerMode → pushPrompt + addSteer + sendSuggestion). Once the backend processes the cancel nothing can land mid-edit; the residual click-instant race (the cancel arriving after injection) is the X flow's pre-existing IPC race — the landing still shows as a transcript steer entry. No edit state exists (the draft is just the input text), so nothing goes stale after injection; an accidental click is recoverable (the text sits in the input, one Enter away from re-queuing). LANDED steers are NOT editable (plain span + "landed" label; the bubble auto-removes after fading out). Inherited limitation: the backend queue is TEXT-based — one cancel drops ALL pending steers with identical text.
