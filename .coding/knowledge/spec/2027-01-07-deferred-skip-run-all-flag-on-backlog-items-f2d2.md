SPEC (2027-01-07, backlog f2d2809b, commits c009a46 + 73ddf56 on wt/agenticcoder): `BacklogItem.deferred: bool` — the "skip Run-All" flag, ORTHOGONAL to BacklogStatus. Semantics: (1) ONLY Run-All selection skips deferred items — `BacklogStore::next_pending_eligible()` (src/backlog.rs) serves `run_all_dispatch_next`; `next_pending()` (auto-feed, dispatch-next button) and `pending_item()` (per-card ▶, manual in-app handling) are unfiltered and still dispatch deferred items. (2) Run-All total counts only pending && !deferred; the "no pending backlog items to run" start error fires only when NO pending items exist at all — an all-deferred backlog starts the run (total 0) and the first dispatch ends it cleanly via end_run (no spin, no error). (3) Orphan adoption + drain still requeue deferred orphans to Pending — the flag survives (transition mutates only status/note) and then excludes them from selection; skipping adoption would strand them InFlight with no recovery. (4) Serde: `#[serde(default, skip_serializing_if = "is_false")]` — old JSONL lines parse as false, non-deferred lines stay byte-identical (union-merge friendly). (5) Agent surface: `backlog_status` takes optional `deferred: Option<bool>`; `status` is now Option (required-unless-deferred — parking a pending item needs no status change since same-status transitions are refused); illegal transitions error before any mutation (side-effect-free). `backlog_list` marks deferred items. (6) UI: checkbox beside the status chip (title "Deferred (skip Run-All)") + violet DEFERRED badge; `backlog_set_deferred` IPC command.
