SPEC (2027-01-08, commits 3d13884 + 12ad722 on wt/agenticcoding, plan 1dbb8c66, backlog 648e0ad5): the finish gate's forced code-graph re-index — the regression-test symbol check never errors on a symbol that exists on disk.

Behavior contract: the bug_fixing finish gate resolves the recorded regression_test against the last-indexed snapshot; on a miss it runs ONE incremental pass (mtime/hash-based, backlog #91) and retries; on a STILL-miss it now ESCALATES before erroring — CodeGraph::reindex_files_containing(needle) (src/codegraph/mod.rs) walks the searchable files and force re-parses every SOURCE file whose on-disk bytes contain the needle, regardless of stored mtime/hash (the disk truth; the reindex_stale_files machinery: hash, containment guard, reindex_one, rebuild_edges; NO indexing-flag bail — a concurrent mtime/hash pass cannot fix the missing-symbol-rows case, and the upserts are idempotent). The gate then re-resolves and only errors when the symbol is absent after the forced re-index.

Error taxonomy (the message names the case, so the agent never chases a phantom rename): (1) matched == 0 — no source file on disk contains the name → the wrong-test-name error ("...not found in the code graph and no source file on disk contains the name (verified after a forced re-index)..."); (2) matched > 0 && reparsed == 0 — files contain the name but every re-parse failed (a store write failure) → inconclusive ("code graph could not be refreshed... re-run finish, do not rename the test"); (3) reparsed > 0 but no symbol resolves → the N-files error ("...even after a forced re-index of N file(s) containing the name..."); (4) the escalation itself failed (spawn/rebuild_edges error) → inconclusive. ReindexOutcome { matched, reparsed } separates the bytes-match count (incremented BEFORE any skip — a containment-guard or re-parse failure leaves matched > 0 with reparsed not incremented) from the success count (review LOW-1, 2026-09-08: a re-parse failure must read as inconclusive, never as absent).

Root cause (why the incremental pass no-ops): the mtime fast-path (mod.rs:287-294) skips the read when stored mtime == disk mtime && has_content && stored_hash.is_some(); the hash comparison (:312) skips the re-parse when the hash matches — so a DB whose meta rows are fresh but whose SYMBOL rows are stale/missing (partial write, schema drift, a prior best-effort skip) never re-parses the file. The F10 self-healing (stale_source_files) is mtime-based and shares the blind spot.

Regression tests (red-first): finish_force_reindexes_when_meta_fresh_but_symbols_missing (src/tool/workflow/plan.rs — the gate-level test: index → simulate_partial_write_for_test → finish SUCCEEDS via the escalation) + reindex_files_containing_reparses_despite_fresh_meta (src/codegraph/mod.rs — pins the no-op root cause: index(None) after the partial write still misses, then the forced re-parse finds it; asserts BOTH counters) + the extended finish_blocks_bug_plan_when_test_symbol_missing_from_graph (asserts the distinguishing message). Test scaffolding: #[cfg(test)] CodeGraph::simulate_partial_write_for_test(rel) writes fresh meta rows (hash + mtime + content) with EMPTY symbol rows — the partial-write simulation (store() is private; the helper is the sanctioned corruption route).
