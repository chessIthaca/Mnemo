SPEC: [models.summarize] routes compaction summaries (plan 0b07d0da, commit 5220a1e on wt/agenticcoding). Consumer: ModelResolver::resolve_summarize_model (src/model_resolver.rs) — a dedicated trait method like the reviewing slot's, NEVER consulted by the per-turn state chain. All three summary call sites resolve their provider through AgentLoop::summarize_provider (src/agent/loop_impl.rs, above resolve_turn_provider): maybe_compact + handle_pending_swap (src/agent/turn.rs — engine fill-rate + pre-swap paths) and compact_context (src/runtime/agent.rs — the run-all between-items compact funnels here via AgentCommand::Compact). Resolution: slot set → sticky_endpoint reroute → build_turn_provider (provider half only; the context-manager half is discarded); unset / dangling endpoint / build failure → the turn's provider, byte-identical to pre-slot behavior. The resolved model is never stamped into the turn's display state (set_resolved_model et al.) — a summary is a one-off internal call; the compact_ms metric stays on the turn's provider trace. Config surface: ModelsConfig.summarize (general.rs), ModelsConfigDto absent/null/set semantics + validation + apply (settings_dto.rs), ModelsConfigWire (settings.rs), Settings → Models "Summarization" row (7th fixed slot, ModelsSection.tsx). Caveat: the summarize model's own context window is never consulted — the whole to-summarize region is sent to it (fails safe; pick a cheap model with a large window).
