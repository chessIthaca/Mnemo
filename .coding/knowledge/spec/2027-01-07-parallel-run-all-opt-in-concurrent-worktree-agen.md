SPEC (2027-01-08, plan ffd7a86f, commit 48a35ad on wt/agenticcoding): parallel run-all — an OPT-IN concurrent dispatch mode for the backlog Run-All loop.

- **Opt-in gating**: a session-only "parallel" checkbox next to auto-feed in the Backlog tab (BacklogView.tsx; `parallel_run_all` AtomicBool on BacklogContext, never persisted). Off (default) = sequential, byte-identical to before. On = the Run-All button passes concurrency 3 (`backlog_run_all(concurrency: Option<usize>)`, clamped 1..=8 via `resolve_run_all_concurrency`). Auto-feed stays sequential — it is the single-item conveyor; parallel gates run-all only.
- **Dispatch**: item 1 → the main agent (unchanged); items 2..N → spawned PARENTLESS agents, each bound to its own git worktree (`<root>/.worktrees/runall-<item8>`, branch `wt/runall-<item8>` forked from main) via `AgentRootSpec` (sandbox/project_root/codegraph point at the worktree; plans dir = `<worktree>/.coding/plans/agents/<id>/`; fresh CodeGraph + one index pass). Selection: `next_pending_eligible_excluding` (the store PEEKS — both lanes exclude handed-out ids). `fill_spawned_window` runs on all three dispatch exits; one failed dispatch is annotated + skipped, not window-blocking. All dispatch decisions serialized under `DISPATCH_LOCK` (run_all.rs).
- **Resolution**: the forwarder routes by OWNERSHIP (`owns_spawned_run`) BEFORE the live `main_agent_id()` comparison in all four arms (Error/Finished/Executing-stamp/Exited) — spawned agents are parentless, and post-main-exit the smallest parentless id is a lane. `on_spawned_turn_resolved` = the main path's plan-tied gates read from the lane's own workflow; Done → `commit_success` on the worktree + land + remove worktree + retire agent; conflict → merge aborted, branch+worktree KEPT, paths in the item note, still Done; Failed → worktree+branch removed. Deferred lane resolutions flush via `try_flush_deferred_spawned_resolutions` (BEFORE the main flush at both sites). Every `end_run` is gated on `any_lane_in_flight`; the main-exit drain and user interventions WIND DOWN (stop flag) instead of ending while lanes work; the ours-arm determination+clear+wind-down runs under DISPATCH_LOCK (R5-L1).
- **Landing**: app-side, serialized (`LANDING_LOCK`), `--no-ff` merge into main via `.worktrees/landing` (the merge_to_main skill cannot run from a linked worktree). Conflicts surfaced, never auto-resolved. `remove_item_worktree` prunes stale metadata + runs both ops independently (a stale branch blocks re-dispatch).
- **Spawned items' reviewer reports** land in the main tree's `.coding/reviews/` (shared by design; not carried by the item's branch merge).
- Key files: src/project/worktrees.rs (new), src-tauri/src/ipc/run_all.rs (fill/dispatch_spawned_item/on_spawned_turn_resolved/drain_spawned_on_exit/stamp_spawned_in_flight + the locks), events.rs (ownership routing + the lane flush), spawn.rs (WorktreeBinding + spawn_run_all_agent), state.rs (RunAllState.concurrency/spawned + SpawnedRun), backlog.rs (next_pending_eligible_excluding), factory.rs/loop_impl.rs (AgentRootSpec plumbing). Payload: BacklogChangedPayload.parallel + RunAllProgress.{concurrency,spawned}.
