Amended 2027-01-11: Evidence rule added to the gate (plan 0011b40b, backlog 5b232b8d). `create_plan` now rejects a context line that asserts a symbol is callable/reachable without evidence, and `update_plan` applies the same rule to the APPENDED text only (so a plan accepted before the rule stays updatable). A line is a CLAIM when it holds a dotted member call (`ext._evaluator.clashOf()`, root `self`/`this`/`crate`/`super` excluded) or one of the phrases `exists at` / `is callable` / `callable from` / `is reachable` / `reachable from`; it is satisfied by a marker on the SAME line — assumption labels (assumption / assumed / unverified / unproven / not verified / to verify / hypothesis, checked first) or probe markers (verified / probe / probed / observed / measured / confirmed / reproduced / checked, matched at a word start so `unverified` never reads as `verified`). Implementation: `reachability_evidence_issue` + `holds_dotted_call` + `contains_marker` + the two `carries_*` helpers in `src/tool/workflow/plan.rs`, wired via `context_issue(.., check_evidence: bool)`; tests `validator_flags_unevidenced_reachability_claim`, `validator_accepts_evidenced_reachability_claim`, `validator_accepts_assumption_labelled_claim`, `validator_ignores_plain_symbol_mentions`, `create_plan_rejects_an_unevidenced_reachability_claim`. The path-naming gate is untouched. Doctrine: a plan carries findings, not assumptions — probe reachability during planning and attach the output; the broad "any identifier before `(`" rule was disproven mid-implementation by the `boil()` fixture (pinned by `validator_ignores_plain_symbol_mentions`) and tightened, so bare calls, `::` paths, `self.`-rooted calls and a `/`-preceded path segment before `(` (`src/kettle.rs(42)`, `static/scripts/tools.js(862)`) are ordinary mentions or locators, not claims.
