R21 (backlog bd9df146, plan a3a04af8, shipped 2027-01-10 at commits 2416dda + 9a7e423 on wt/agenticcoding): request_stats now covers the full request population, not just successful streams. (1) Error rows: every failed complete_with_retry attempt (src/agent/dispatch.rs) and once per mid-stream LlmEvent::Error (turn.rs consume_stream, guarded by had_error + usage_recorded so a Usage-then-Error stream never double-counts) writes outcome='error' with cached_tokens NULL — NOT 0, so a real reported miss stays distinguishable from "the provider never reported usage" — and prompt_tokens = our scaffolding-inclusive estimate (request_stream computes it and returns (stream, estimate) because run_turn pops the scaffolding before consume_stream runs; the eager O(history) walk is a documented accepted cost — the lazy closure is impossible across the pops). (2) Summarize rows: summarize_with_interrupt captures its own Usage event into SummarizerUsage and returns it as a 4th tuple element; all three compaction call sites (turn.rs handle_pending_swap + maybe_compact, runtime/agent.rs compact_context) record purpose='summarize' rows, including the error paths (the mid-stream summarizer Error now returns Err instead of silently replacing the conversation with a truncated summary; the interrupt path returns the captured usage — the request was billed). (3) Schema: request_stats gains nullable cached_tokens + outcome/purpose TEXT via an idempotent atomic table-rebuild migration (BEGIN IMMEDIATE...COMMIT — SQLite cannot DROP NOT NULL; gated on the outcome column missing, ordered after the endpoint migration). A MemoryStoreTrait::request_stats_rows(session_id) read API serves the row-level view. The cache-hit-5 extraction script NULL-guards and segments: hit/reset aggregates (A0-A5) run on main-loop rows only (outcome IS NULL AND purpose IS NULL); error + summarize rows get their own A6 section — summarize rows are excluded from the hit aggregates deliberately (a fresh single-message prefix is structurally unable to hit cache). TTFT: summarize rows carry ttft_ms from the forwarded Usage event; error rows record NULL (the TTFT anchor fix is a separate pending backlog item). Tests: migration_rebuilds_request_stats_for_outcome_purpose_and_nullable_cached, request_stats_rows_separates_outcome_and_purpose_tags, run_turn_records_error_request_stats, run_turn_records_summarize_request_stats, complete_with_retry_records_error_stats_per_attempt.
