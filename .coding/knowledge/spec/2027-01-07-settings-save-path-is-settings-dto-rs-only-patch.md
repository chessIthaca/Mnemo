The parallel lib-side settings-patch family in src/config/patch.rs is DELETED (plan 8684dc0e, quality review HIGH 3, commit d80bcd3 on wt/agenticcoding): validate_settings_patch, apply_settings_patch, apply_models_patch, SettingsPatch, ModelsPatch, their two tests, the TODO(F2-full), section headers, and now-unused imports. patch.rs now covers ONLY the endpoint-save path (validate_endpoint, validate_endpoint_set, apply_endpoints) + parse_safety_mode (live — settings_dto.rs:338); the non-endpoint settings save path is solely validate_and_apply_settings_patch (settings_dto.rs:258-624, called from src-tauri/src/ipc/settings.rs:822). DECISION: delete, not migrate — the live validator was strictly more complete (trace/memory/sound/browser/core_operations fields the dead struct never carried; B1-B3 already implemented there), so finishing the migration would have been a large parity refactor for zero user-visible benefit. The two dead tests were the codebase's ONLY coverage of the proxy-cache-ceiling validation and the [models] double-Option semantics — both ported to settings_dto.rs's tests (proxy_cache_ceiling_validation_rejects_tiny_and_accepts_disable_or_sane, models_patch_double_option_semantics). Subtlety: PricingEntry moved from patch.rs's module-level import into the tests-module import — after the deletion it is used only by test code, and in the non-cfg(test) compilation a module-level import would be unused (deny(warnings) error).
