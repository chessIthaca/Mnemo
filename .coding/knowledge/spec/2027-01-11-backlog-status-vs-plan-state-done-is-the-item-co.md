Two vocabularies, two layers, one bridge — never two statuses of one object. (1) Backlog ITEM status (the queue): BacklogStatus {Pending, InFlight, Done, Failed, CantResolve} — src/app/backlog.rs:291 (snake_case serde); queue data carries only these (checked: 0 rows "status":"complete", 63 "status":"done" in .coding/backlog.jsonl). (2) PLAN workflow state: planning → executing → reviewing → Complete. Bridge, documented on the transition table itself (src/app/backlog.rs:608): an item flips to done ⇔ its plan reaches Complete — automatically at TURN RESOLUTION (manual only for pre-dispatch resolutions), so a finished plan briefly shows the live phase chip "complete" while the item status is still in_flight. Where each surfaces: frontend/src/components/views/BacklogView.tsx:46 STATUS_STYLES (badge per item status) vs :55 PHASE_STYLES (live phase chip on the in-flight card, including "complete"); StatusBar.tsx:554 renders the agent's Complete state; done cards also render the tied plan_title (BacklogView.tsx:892). Historical stranding bugs, both FIXED: chat-linkage (plan 822c524a — items stayed in_flight after the plan ran to finish) and the steered-item strand (resolved 2027-01-11, plan 9c2eb7a4). A card persistently showing phase "complete" but never flipping to done would be a fresh lifecycle mismatch, not this design.

Amended 2027-01-11: The Backlog card's in-flight badge now prefixes the live plan phase — "plan: <phase>" (plan: complete, plan: executing, …) — instead of the bare phase string, with a title tooltip naming the two layers: "The tied plan's live workflow phase — the item's status flips to done when the turn resolves." Every other card's badge keeps the queue vocabulary (the item.status.replace("_", "-") fallback is untouched). Frontend-only display change (plan 559b14a3, commit 6284989 on wt/stream-plain); the layering itself — item→done ⇔ plan→Complete at turn resolution — is unchanged. Pins: three source-contract tests in frontend/src/components/views/BacklogView.test.ts + a done-card badge render pin in BacklogView.test.tsx; the live-phase branch stays un-render-testable (zustand SSR snapshot reads only initial store state), so it is pinned on source.
