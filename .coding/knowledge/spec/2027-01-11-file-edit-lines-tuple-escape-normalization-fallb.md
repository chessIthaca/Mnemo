SPEC: file_edit — lines tuple, escape-normalization fallback, no-op + miss diagnostics (plan 04a195de, backlog 838b6f4e, commit a96041b on wt/mnemo). (1) Line-range mode is `lines: [start, end]` — exactly 2 elements, 1-indexed inclusive; 1- or 3+-element arrays are rejected with the exact-expected-arguments error; start_line/end_line are gone from the schema. (2) On an exact literal miss, literal_splice tries the unescaped variant (\'→'), the escaped variant ('→\'), then whitespace normalization; every non-Exact origin rides the success output as a NOTE (batch items get per-item "edit N/M:" notes) — a fallback is never silent; the batch ambiguity guard counts the same effective needle (count_matches is variant-aware). (3) No-op edits (single-mode literal, non-empty old_string == new_string, regex exempt — a pattern can equal its replacement while changing content) are rejected pre-read with "no-op edit: old_string equals new_string"; batch items are rejected pre-write in validate_batch_args. (4) Genuine misses append a first-difference pointer ("near-miss: matched P/Q chars; first difference at char K: file has X, you sent Y") to the drift nudge (never replacing it); the scan is work-budgeted (10M compared chars). (5) The advertised schema carries NO minItems/maxItems — OpenAI's strict-mode subset rejects them (review HIGH 1; pinned by advertised_schema_carries_no_strict_unsupported_keywords).
