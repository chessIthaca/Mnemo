Tier 2 — other classes ride guidance_note on the fed-back error. (3) Provider site: classification lives at the INNER layer (dispatch::complete_with_retry) after the is_non_retryable/is_rate_limited early-returns (a 429 is never classified); confident needs_user/permanent logs ONE row (disposition escalated) and returns Error::Provider("… — classified {label}: retrying cannot help ({skip_hint})"); the marker makes Error::is_classified_skip() true → is_non_retryable() true → the OUTER layer (runtime/agent.rs run_turn_attempt) skips via its existing arm WITHOUT re-classifying (no duplicate row) and the terminal note reads "classified failure-triage skip". (4) Startup fine-tune src-tauri/src/ipc/finetune.rs: gate = enabled + Managed + auto_finetune + runtime/checkpoint installed (startup_finetune_checkpoint, default id "english"), read from the LIVE shared Config inside the spawned task; marker markers/finetune-<checkpoint> holds the last fine-tune's unix secs (corrupt reads as never); FINETUNE_MIN_NEW_ROWS 50; dataset exported as {text,label} JSONL rows (finetune/failure_triage-dataset.jsonl) on every eligible run; runner = <venv python> -m laya.finetune --dataset --out (output → finetune/finetune.log); exit 0 + non-empty out dir → Served, "No module named" → Ineligible (dataset stays, skip cleanly — laya 0.3.20 ships no training surface), else Failed. Success: marker rewritten BEFORE the restart (rows spent), restart via laya.rs start_server_models(LAYA_MODELS=<out dir>, no catalog progress) + build_managed_classifier(new port) swapped into the SHARED slot (all consumers pick it up); a failed readiness probe restores the ORIGINAL checkpoint and re-swaps.
