Landed design for Laya memory auto-typing (plan 9f9139bc, backlog a147b63c — commit 9f92130 on wt/mnemo, NOT yet merged to main). Architecture: src/memory/auto_typing.rs owns the decision layer — typing_question() = ONE choice question over six labels (SPEC/DECISION/BUG/PLAN/HOW/REVIEW), auto_type() gates: agreement-before-threshold, threshold const AUTO_TYPE_THRESHOLD=0.80 inclusive, label scrubbed (control chars stripped, 40-char cap at CONSTRUCTION — the only agent-visible surface), KeepWriter is the total fallback. The tool hook sits in src/tool/memory/mod.rs BEFORE MemoryRecordType::from_title so one retitle (strip-then-apply; strip side is case-insensitive + repeat-stripping, parse side stays case-sensitive) lands everywhere (dir/file/row/slug). INVARIANTS: (1) gate = LayaConfig.auto_type_memories (default false, omitted-while-default) AND the SHARED classifier slot non-empty — AutoTypingHandle reads the shared slot + Arc<AtomicBool> flag at CALL time, so zero classifier swap sites needed changes and Settings toggles are live (rewire flips the flag via factory.set_auto_typing_enabled; startup init is the other only writer); (2) disabled ⇒ byte-identical writes (pinned: auto_typing_disabled_leaves_the_title_byte_identical covers unwired/empty-slot/flag-off); (3) read guard dropped before the classify await; (4) seed_dataset trains only SPEC/DECISION/BUG/HOW (PLAN/REVIEW have no knowledge home — disclosed at five doc surfaces; fine-tune before enabling, per the base-checkpoint caveat). Consumers of the pattern: Laya chain items 2-4 (routing/steering/triage) should reuse the shared-slot + per-consumer AtomicBool shape rather than adding swap-site-coupled slots.
