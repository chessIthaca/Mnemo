The live shell-output preview in a running shell tool card (plan 90c15456, backlog 6f25fb7e, landed 2027-01-16 on wt/mnemo) renders at a FIXED height — h-[10em], exactly six visible lines at the element's own em (the pre's text-[0.75em] makes every em below font-size element-relative: 6 × 1.5em line-height + 2 × 0.5em padding) — reserved from the FIRST paint of a running shell card (frontend/src/components/chat/Message.tsx, gated on `showShellPreview && name === "shell" && running`), so streaming chunks can never change the card's height or jump the chat column. Only shell reserves: only shell emits ToolOutputDelta (the shell.rs sink) and shell never merges (the reducer's neverGroups). The toggle: Settings → Chat → "Stream shell output live in the tool card" — localStorage mh.showShellPreview (LS_SHOW_SHELL_PREVIEW + readShowShellPreview in frontend/src/hooks/appearance.ts, default true), store state showShellPreview + setShowShellPreview (frontend/src/hooks/useAgentStore.ts), ChatDraft field (frontend/src/components/settings/types.ts, rides serializeChat for dirty detection), localStorage-ONLY persistence (deliberately NOT in the config.toml [ui] payload, unlike the showTokenUsage sibling — per the backlog's wording). Tests: frontend/src/components/chat/Message.preview.test.tsx + Message.preview.off.test.tsx (node-env SSR; the off case seeds localStorage via a vi.hoisted window stub before store init) + the toolCardPaths.test.ts source contract.
