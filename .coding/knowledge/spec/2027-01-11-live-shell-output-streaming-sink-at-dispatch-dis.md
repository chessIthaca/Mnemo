Plan 0d2c1221 / backlog 7e6385b3 — landed on branch wt/mnemo, 2027-01-16 (worktree C:/Mnemo).

WHAT: a running `shell` call streams its stdout/stderr into its chat card AS IT IS PRODUCED; the final ToolResult stays byte-identical (that is what the model consumes) and approval/safety semantics are untouched.

BACKEND CHAIN: ShellTool::execute (src/tool/agent/shell.rs) spawns the child with piped stdout/stderr and, when the call's OutputSink is active, runs two reader tasks emitting throttled UTF-8-safe chunks (STREAM_FLUSH_INTERVAL 60 ms per stream, STREAM_FLUSH_BYTES 8 KiB batch, STREAM_CAP 256 KiB live budget + one-time truncation note); the readers are joined BEFORE the result is returned, so on a call that COMPLETES this way every delta precedes the ToolResult on the same FIFO fan-in channel. That ordering is NOT absolute: the timeout path aborts both readers and awaits the cancellation, and an interrupt (the tool future is dropped) can leave a `ReaderGuard`-aborted reader emitting after its synthetic result — every consumer therefore ALSO gates on the call having no result (`result === null`), which `ReaderGuard` narrows but cannot close (review L1). The sink is built per call at the dispatch site — AgentLoop::output_sink (src/agent/dispatch.rs) → AgentEvent::ToolOutputDelta { tool_call_id, stream, text } (wire `tool_output_delta`, golden fixture frontend/src/lib/ipc-fixtures/event-tool-output-delta.json) — cloned into dispatch_with_interrupt (so BOTH the approved and the auto-approved path stream) → ToolRegistry::dispatch_streaming (src/tool/mod.rs). The sink's try_send drops a delta on a full channel by design (the live view is pixels; the result is the truth).

FRONTEND: useAgentEvents.ts buffers chunks per (agent, tool_call_id) and flushes per frame / interval / cap, flushing BEFORE any structural event (so a buffered chunk can never land after its own result); /clear drains outputBuffers with the other delta buffers. reduceToolOutputDelta (agentEventReducer.ts) appends to the RUNNING call's liveOutput, keeping only the last LIVE_OUTPUT_CAP (16 K chars — UTF-16 code units, a DIFFERENT unit from the Rust side's byte budget) (head-drop + lone-surrogate guard), and returns the agent UNCHANGED for an unknown id or a call that already has a result (late-chunk guard); reduceToolResult sets liveOutput: undefined. Message.tsx renders liveTailPreview (last 6 lines / 400 chars, toolCardPaths.ts) under a RUNNING card's header, gated on `result === null && liveOutput`, aria-live="polite", stick-to-bottom. The memo (messageEquality.ts) re-renders via the calls-array REFERENCE — both the reducer and the batched store action (applyToolOutputDeltas) build a fresh array per mutation (pinned by a memo behavior test).

INVARIANTS: (1) the tool result is byte-identical and stays the ONLY model-visible text; (2) streaming adds NO ToolCallStart/ToolResult — the echo map's "every tool call echoes once" answer is unchanged; (3) the event is Silent in the console (src-tauri/src/console.rs); (4) only a call with result === null is ever appended to; (5) the live tail never enters the model's context.

TESTS: agent::tests::dispatch_streams_shell_output_deltas_before_the_result (in-crate funnel pin, marker-gated child, proves deltas arrive while the command runs); the shell.rs streaming tests (incremental deltas, cap + one-time note, non-UTF8, stderr tagging, byte-identity); useAgentStore.test.ts reducer tests (append, head-drop, late-chunk ignored, unknown id no-op, batched write); useAgentEvents.dispatch.test.ts (per-call coalescing + flush-before-structural-event ordering + /clear drain); toolCardPaths.test.ts (liveTailPreview units + render-site source pins); ipc-contract.test.ts (fixture drives the real reducer); messageEquality.test.ts (memo discipline).

Amended 2027-01-11: Round-2/3 refinement (2027-01-16, plan 0d2c1221, branch wt/mnemo). Three review rounds landed: round 1 FINDINGS (0 high, 6 low) → round 2 FINDINGS (0 high, 3 low, all six round-1 findings closed) → round 3 PASS (reports under .coding/reviews/2026-09-18-live-shell-output-streaming-review*.md). Two behavioural fixes matter beyond the review bookkeeping. (1) The throttle now has a real TIMER arm: `pump_stream` is a `tokio::select!` whose second arm is `sleep_until(tokio::time::Instant::from_std(last_emit + STREAM_FLUSH_INTERVAL))`, guarded on `live && !pending.is_empty()` and re-armed from the reset `last_emit`, so a line printed just before a quiet stretch is flushed within one interval instead of waiting for further bytes or EOF. Before that arm the elapsed-time check was only EVALUATED when bytes arrived — which also made the two marker-gated tests pass on Windows by accident of PowerShell's startup latency and fail on Unix (a multi-platform-neutrality defect). (2) The per-call byte budget is now reserved ATOMICALLY: `emit_pending` clamps with `truncate_to_boundary` against `room = STREAM_CAP - used`, then `compare_exchange_weak(used, used + emit_text.len())` and emits only what it reserved, so STREAM_CAP is a real bound under two racing readers (a plain load + `fetch_add` let both spend the same room). The single truncation note now gates on `clamped && !noted.swap(...)` — once per CALL, both readers sharing the flag. Also landed in this refinement: `ReaderGuard` (aborts both readers on drop; the timeout path aborts then AWAITS both handles, so no chunk can follow the error result), the honest success-path-only wording of the ordering invariant, and the frontend batched action `applyToolOutputDeltas` returning the CURRENT state object when no delta matched (zustand's Object.is short-circuit ⇒ a stray chunk costs no render).
