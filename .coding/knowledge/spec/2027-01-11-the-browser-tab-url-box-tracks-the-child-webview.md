SPEC: The Browser tab's URL box tracks the child webview's CURRENT URL (landed 2027-01-24, plan 47735e3c, commit ee1b5cf on wt/mnemo, backlog 3f838ea1). Pipeline: the shared child_webview_builder (src-tauri/src/ipc/browser_webview.rs — used by BOTH creation sites, browser_webview_ensure and ensure_for_agent_impl) attaches wry's on_page_load hook, emitting browser://url-changed on every page load (Started AND Finished — the box shows the target immediately and the committed URL after redirects; best-effort, an emit failure never fails the load). The payload is an OBJECT with a url field (browser_url_payload → json!) on BOTH browser channels — url-changed AND reveal (the reveal channel's latent bare-string/interface mismatch was aligned; its handler ignores the payload, so shape alignment only). Frontend: a module-scope idempotent listener (useAgentEvents.ensureBrowserUrlListenerStarted, mirroring the reveal listener) routes events through the pure handleBrowserUrlChanged (hooks/browserUrl.ts) into store.browserUrl — module scope means NO mount-timing gap (the store tracks the URL even while the Browser tab is hidden). BrowserView subscribes and syncs the box (setUrl + setLoadedUrl + setError(null)) on change AND on mount (the effect's initial run catches up); deps [browserUrl] only, so user typing never triggers it. Covers agent-steered CDP navigations and in-child link clicks, which never route through loadIntoChild (the frontend's own loads already sync there — the store round-trip is idempotent). Regression tests: browser_url_payload_is_url_keyed (the payload shape at the constructing helper), handleBrowserUrlChanged (routing + stale overwrite), the BrowserView source contract (s.browserUrl / setUrl / setLoadedUrl).
