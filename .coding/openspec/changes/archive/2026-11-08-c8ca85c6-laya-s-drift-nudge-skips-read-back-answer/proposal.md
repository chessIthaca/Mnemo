A read-back answer, a go-ahead reply to a read-back and a team_route_fix prompt never reach the drift check, so they draw no nudge and leave the worker's one nudge unspent; a lead message that really adds scope still nudges.

WHY. Every delivered message runs TeamRuntime::spawn_drift_check (src-tauri/src/mnemo2/team/control.rs, called at the end of message_inner_with_kind). It classifies the message text alone with the dispatch question (classify_dispatch in src-tauri/src/mnemo2/dispatch_routing.rs) and nudges when the answer clears on a tier above the worker's. The only filter is the 20-word minimum.

ROOT CAUSE. The check asks "how hard is this text as a task?" about text that is not a task description. Read-back answers and fix prompts read like implementation specs, and the kNN overlay votes on them against logged step specs (confidences of exactly 0.80 and 1.00 are 5-neighbour vote shares). The check does not know what kind of message it is reading: route_fix_with_tier (team/review.rs) sends its brief through the same path with MessageSender::Mnemo and InboxKind::Fix, and read-back replies are ordinary lead messages.

EVIDENCE, read from .coding/laya/dispatch_routing.jsonl joined to .coding/mnemo2/team.json. There are 19 drift nudge rows; 13 can be matched to the message that drew them (the other six workers have left the ledger). 10 of the 13 are read-back answers and 3 are fix prompts; none added scope. In all 10 read-back cases the nudged message was the worker's first non-Mnemo message, but in 4 of them Mnemo2 plan-changed notices came first, because the lead records its answers as plan decisions before replying. So "first inbox entry" is the wrong test; "first entry from anyone but Mnemo2" is right. Across all 40 workers in the ledger, only 2 lead messages of 20+ words would still be classified after this fix: a real scope addition ("One addition to this round: change the example's default --out ...") and a continuation message sent after a reroute.

DECISION: skip these messages outright rather than classify only their new requirements. Nothing can separate new requirements from restated ones: the message is unstructured text, Laya answers one fixed question about the whole text, and adding a model call to extract requirements would add cost and latency to a check that exists to be cheap. What a message IS, on the other hand, is known exactly from the sender and the worker record. The fix tier has its own route (team_route_fix tier auto, classify_fix_tier) and failed fix rounds escalate deterministically, so skipping fix prompts loses no signal. Accepted residual risks: a read-back answer that does add scope draws no nudge, but the lead wrote that scope and chooses the tier itself; and a second lead reply on a read-back worker is classified as an ordinary message (no worker in the ledger has had such a second reply before implementing).

CONSTRAINTS. The rule is one pure predicate on the record snapshot taken before the message joins the inbox, called in message_inner_with_kind before spawn_drift_check. No new persisted field: WorkerRecord.read_back and WorkerRecord.inbox already hold everything, and both survive a restart. MessageSender::User messages keep today's behaviour apart from the read-back rule. Classification stays detached, so a message never waits on Laya. classify_fix_tier and the strike, circles and review nudges do not change. Existing rows in the routing log stay as they are.

REGRESSION TESTS, both in src-tauri/src/mnemo2/team/tests.rs. read_back_answer_draws_no_drift_nudge dispatches a read_back worker and sends READ_BACK_ANSWER as its first lead message; on today's code the answer reaches Laya, and the test fails on the assertion "the read-back answer reached the drift check". route_fix_prompt_draws_no_drift_nudge reviews a worker with an open finding and routes the fix; on today's code the brief reaches Laya, and the test fails on "the fix prompt reached the drift check". Both then send a real scope message and require its drift nudge, which is the sync point that makes the negative check deterministic and also proves the worker's one nudge was not spent.
