# Plan: Retire Mnemo1: remove the React app and its Tauri shell

## Goal
The repository builds, tests and ships only Mnemo2: frontend/, the Mnemo1 binary (src-tauri/src/main.rs + ipc/) and every build, CI and installer step for it are gone, while Mnemo2 and the shared mnemo core keep working unchanged.

## Kind
implementation

## Context
WHY: On 2026-11-11 the user decided to retire Mnemo1 as is (record: .coding/knowledge/decision/2026-11-11-mnemo1-retires-as-is-only-the-chat-slash-command.md; settings split: .coding/knowledge/decision/2026-11-11-mnemo1-only-settings-which-retire-which-stay-con.md). Nothing else is ported; the slash commands are a separate plan that only touches Mnemo2 files.

LAYOUT (verified 2026-11-11):
- Root crate `mnemo` (src/) = the shared core library. NOT touched by this plan.
- `src-tauri` crate `mnemo-app`: a LIBRARY (src-tauri/src/lib.rs: webview_udf, instance_marker, watchdog, and `mnemo2` behind the `mnemo2` feature — the Mnemo2 host) PLUS the Mnemo1 binary `[[bin]] mnemo-app` (src-tauri/src/main.rs, console.rs, startup.rs, ipc/**). Only the binary and its files go; the library stays.
- `src-tauri/mnemo2-app` crate: the Mnemo2 binaries (mnemo2, mnemo2-mcp) with its own tauri.conf.json. Mnemo2's installer is built by `npx tauri build` run in that directory.
- src-tauri/build.rs runs `tauri_build::build()`, which reads src-tauri/tauri.conf.json and src-tauri/capabilities/*. The Mnemo2 host's `tauri::generate_context!("mnemo2-app/tauri.conf.json")` (src-tauri/src/mnemo2/mod.rs:779 and its test at :969) is compiled in THIS crate, so src-tauri/tauri.conf.json and src-tauri/capabilities/mnemo2.json MUST stay (slimmed), and src-tauri/build.rs stays.
- frontend/ is the Mnemo1 React app (npm workspace). mnemo2/ imports 5 modules from it today (step 1 copies them).
- Mnemo1 contract fixtures live in frontend/src/lib/ipc-fixtures/ and are read by tests/integration/contract_fixtures.rs (a root-crate test of the core's event serialization) — they move, the test stays.

OUT OF SCOPE (a later plan, do not start it): dead code in the core library that only Mnemo1 used (Run-All, SerializableAgentEvent consumers, Mnemo1 workflow pieces), removing retired config keys ([general.budget], auto_compact_on_plan_complete, enable_browser_inspection, [ui] chat toggles, [general.laya] auto_finetune), doc comments in src/ or src-tauri/src/mnemo2 that mention ipc/ paths, agent.md, historical docs (.coding/analysis, .coding/grok.md, .coding/llm-trace.md, .coding/scoping-*.md, PLAN.md, CHANGELOG.md history).

VERIFY (whole plan): npm ci; npm run build:mnemo2; npm test --workspace mnemo2; npm run check --workspace mnemo2; cargo build -p mnemo2-app; cargo clippy --workspace --all-targets; cargo clippy -p mnemo-app --all-targets --features mnemo2; cargo test --workspace --no-fail-fast; cargo test -p mnemo-app --features mnemo2 --lib. #![deny(warnings)] applies. Known timing flakes you may re-run once: runtime::agent cancel_during_approval and interrupt_during_approval.

## Acceptance scenarios
- `git ls-files frontend src-tauri/src/ipc src-tauri/src/main.rs src-tauri/src/console.rs src-tauri/src/startup.rs` prints nothing.
- `grep -rn "frontend/" mnemo2/src` finds no import (only the preview scene's fake graph string may remain).
- `cargo build -p mnemo2-app` and `cargo test -p mnemo-app --features mnemo2 --lib` pass, and `cargo build -p mnemo-app` builds only a library (no mnemo-app binary).
- `npm ci` at the root installs only the mnemo2 workspace and `npm test --workspace mnemo2` passes.
- No workflow under .github/workflows mentions `frontend` or runs `npx tauri build` outside src-tauri/mnemo2-app; the Windows and macOS jobs still build, stage and upload the Mnemo2 installers, and the release job is unchanged.
- `cargo test --workspace` passes, including tests/integration ci_workflow, contract_fixtures (reading tests/fixtures/ipc-contract/) and encoding_guard.
