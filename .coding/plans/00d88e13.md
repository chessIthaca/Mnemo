# Plan: App shell re-renders on every streaming frame — move the agent subscription into InflightBar + memoize the shell (mem-perf HIGH 1)

## Goal
Stop the entire app tree from reconciling on every rAF streaming flush: App.tsx no longer subscribes to the whole active-agent object; InflightBar subscribes itself by its stable agentId; Sidebar/InputBar/StatusBar are wrapped in React.memo so future App-level re-renders can't drag them along. Pinned by a source-contract regression test (App no longer selects s.agents[s.activeAgent]; InflightBar does subscribe itself).

## Kind
implementation

## Context
mem-perf review HIGH 1 (.coding/reviews/2027-01-06-full-review-memory-perf.md). App.tsx:96-98 selects s.agents[s.activeAgent] — the agent object's identity changes on every rAF streaming flush (appendStreamingText spreads the agent per flush); its only consumer is InflightBar (App.tsx:721). None of the shell children are memoized, so the entire app tree reconciles per streaming frame — the dominant streaming-jank source on long transcripts, competing with typing in InputBar during streaming. Design decisions: (1) InflightBar's body destructures `state` at the top and feeds hooks (useCountUp etc.), so it cannot handle undefined state in a single component — split into a thin self-subscribing outer gate (subscribes s.agents[agentId], returns null when the agent doesn't exist) + the unchanged inner panel (InflightBarPanel, keeps InflightBarProps). (2) App keeps its activeAgent subscription (a stable number — no per-frame identity change) to pass agentId. (3) Sidebar/InputBar/StatusBar are prop-less and self-subscribing — memo() is trivially effective; MainPanel/RightPanel are NOT memoized (MainPanel must re-render during streaming anyway; the review named exactly these three). (4) The regression test follows the established ?raw source-contract pattern (InflightBar.test.ts precedent).
