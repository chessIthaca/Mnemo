# Plan: Old workers can be deleted, and superseded work is named honestly

## Goal
"Delete old workers" offers every worker whose task is over, finished read-only audits included. The delete sheet says when a worker's step already landed through another worker instead of alarming about lost work. The summary gives each worker's last-activity time, so the Claude Desktop band can hide finished workers after 2 minutes.

## Kind
bug_fixing

## Context
WHY: the user reported, from mission control: "Two problems: which 2 workers have things not on the lead branch and is that true? And even then, it should still allow me to delete the rest which is currently not possible." Also: in Claude Desktop the workers band "should at best show me completed subtasks for 1-2 minutes, no longer."

ROOT CAUSES (verified by reading):
1. mnemo2/src/lib/store.ts `OLD_WORKER_STATUSES = ["merged", "cancelled", "stopped", "interrupted", "failed"]`, used by `requestDeleteOldWorkers`. Audit workers (WorkerRecord.kind == "audit", read-only reviewers, never merged) end in status `completed` and are never offered. Implementation workers in `completed` are work that awaits review and must NOT be offered by "Delete old workers" (they can still be deleted one by one).
2. src-tauri/src/mnemo2/team.rs `inspect_deletion` counts `rev-list --count HEAD..refs/heads/<branch>` as unmerged_commits. senderLedger34 and teamSummary35 each keep one commit that is not an ancestor of the lead branch, because their step was landed by replay workers (senderReplay36, summaryReplay38) that re-applied the commit by hand with conflict fixes. Git cannot prove equivalence (re-merging conflicts), so the count stays, but the ledger knows: another worker with the same plan_id and plan_step has status merged. The preview must name it.
3. src-tauri/src/mnemo2/mcp_server.rs `/lead/summary` sends `elapsed_ms` (last activity minus creation, team.rs ~4510) but no absolute time, so a client can't tell how long ago a worker finished.

DECISIONS:
- WorkerDeletion (team.rs ~4860, serialized to the frontend) gains `superseded_by: Option<String>`: the name of another, merged worker record on the same plan_id and plan_step (implementation kind), else None. Counting and the `discard_work` confirmation stay exactly as they are (the commits really are not on the lead branch).
- The delete sheet (mnemo2/src/components/WorkerDeleteSheet.svelte): a superseded worker's row reads e.g. "Its step landed through senderReplay36; its own 1 commit is not on the lead branch." and it is NOT counted in the red "work that is not on the lead branch" warning. The button says "Delete and discard work" only when a non-superseded worker discards work; the confirm still sends discard_work true whenever any deletable preview discards work (backend contract unchanged).
- "Delete old workers" offers OLD_WORKER_STATUSES plus workers with kind "audit" and status "completed". The toast for "no old workers" stays.
- `/lead/summary` worker entries gain `last_activity_ms` (epoch ms, created_at_ms + elapsed_ms). Existing fields unchanged; the helper passes JSON through untouched.
- ModelBadge and other displays are untouched. The Claude Desktop mod change (2-minute rule) is lead work at mnemo2/claude-desktop-mod/mnemo-workers/.

REGRESSION TESTS (bug_fixing):

Without the fix the audit id is missing.
