Export: (1) `interface LaneCommit { sha: string; lane: number; parents: string[] }` and `interface LaneLayout { commits: LaneCommit[]; laneCount: number }`; (2) `export function computeLanes(commits: GitCommitInfo[], mainSpine: ReadonlySet<string>): LaneLayout` — commits arrive in topo order (newest first); main-spine shas are PINNED to lane 0; for non-spine commits use classic lane assignment: maintain `lanes: Array<string|null>` where a lane stays occupied by the sha expected next on it; a commit takes the lane currently expecting its sha (or the first free lane), then assigns its FIRST parent to keep that lane (if the parent is spine it moves to lane 0), and each ADDITIONAL parent claims a new free lane (prefer reusing a lane already expecting that sha).
