# Plan: Fix: skill/model override ignored when skill_start happens mid-turn

## Goal
Make per-context model resolution (skill/state overrides) take effect on the next provider request within the SAME turn, so an agent-driven mid-turn skill_start (or state transition) switches to the configured model instead of staying on the turn-start snapshot.

## Kind
implementation

## Context
User reported the merge_to_main skill run did not use the configured deepseek flash model ([models.skill.merge_to_main] in config.toml). Root cause found by inspection: src/agent/turn.rs:79-86 resolves the turn provider ONCE before the tool loop; the agent called finish (→Complete) then skill_start (→Skill) mid-turn and drove the entire merge in that same turn, so resolve_turn_provider — which reads wf.state() + wf.active_skill() — was never consulted again. The resolver itself (src/model_resolver.rs resolve(), skill > subagent > state priority) is correct and covered by tests; the UI path (enter_skill sends a fresh Prompt → new turn) works. Only the mid-turn skill_start path is broken. Constitution: Windows/PowerShell, $LASTEXITCODE unpiped, doc comments on public fns, regression test per defect, cargo test green + warning-free (deny(warnings)).
