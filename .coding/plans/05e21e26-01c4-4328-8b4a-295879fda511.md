# Plan: Display executed git command in git tool output

## Goal
Make the git tool's ToolResult.output show the git command it executed (e.g. "$ git status --short") before the stdout/stderr/exit-code.

## Context
src/tool/agent/git.rs `run_git` (lines 74-108) builds a `tokio::process::Command` from `args: &[&str]` and returns a ToolResult whose `output` field is just stdout/stderr + "[exit code: N]". It never echoes the command itself. The user wants the executed command shown (e.g. "git status"). Tests use `.contains()` assertions so a prepended command line won't break them.

## Steps
- [x] 1. In `run_git`, build a display string from the args (e.g. `git status --short`) and prepend it as a header line to the `output` field of the returned ToolResult. Keep the existing data JSON unchanged.
- [x] 2. Add a test asserting the executed command appears in the output for a read op (e.g. status shows `git status`).
- [x] 3. Run `cargo test` and confirm green.
- [x] 4. Spawn a read-only reviewer subagent to review all uncommitted changes; write findings to .coding/reviews/. Fix any findings, re-run tests.
- [x] 5. Commit to the current feature branch with a clear message.
