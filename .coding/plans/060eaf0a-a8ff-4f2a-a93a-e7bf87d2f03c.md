# Plan: read_files (plural) batch read tool with per-file line ranges

## Goal
Add a read_files (plural) tool that reads multiple files in one call, each with an optional per-file line range (start_line/max_lines) to optimize context usage. Cuts multi-file exploration from N round-trips to one.

## Context
file_read (src/tool/agent/file_read.rs) reads ONE file per call. Exploring 3-4 files costs 3-4 round-trips (each is a tool call → LLM turn → response). A batch read cuts that to one call. file_read already supports start_line + max_lines per file; the batch tool should support the same per-file so the model can read just the relevant slice of each file (optimizes context usage — the user explicitly asked for this).

Design: a NEW tool `read_files` (plural) that takes an array of read specs, each {path, start_line?, max_lines?}. Reads each file through the same sandbox validation + line-numbering + line/byte-cap logic as file_read. Output: each file's content prefixed with a header (e.g. '=== path (lines a-b of N) ===') and the numbered lines, separated by blank lines. Reuse file_read's constants (DEFAULT_MAX_LINES=2000, DEFAULT_MAX_BYTES=102400) and its numbering format ('{:>4}: {}'). Per-file errors (missing/unreadable) are reported inline for that file but don't fail the whole call (one bad path shouldn't blank out the other reads). A whole-call error only if the array is empty or no specs.

Cap the number of files per call (e.g. MAX_FILES=10) to prevent unbounded output. Total output byte cap across all files (e.g. 500 KB) with a truncation note. Each file individually also capped at DEFAULT_MAX_LINES/DEFAULT_MAX_BYTES like file_read.

Registration: add ReadFilesTool to register_agent_tools in src/agent/factory.rs next to FileReadTool. SafetyLevel::AutoRun (read-only, like file_read). ToolCategory::Agent.

This is a new file src/tool/agent/read_files.rs + a mod entry in src/tool/agent/mod.rs + registration. No change to file_read itself (keep it as the single-file fast path). prompt.rs guidance: mention read_files for exploring multiple files at once.

Project: Windows 11, npm workspace at C:\myHarness. Rust tests via cargo test. This is plan 3 of the sequence (after fuzzy whitespace).
