# Plan: OS-level SSO for the Browser tab (vendored wry patch)

## Goal
Enable Windows OS-account single sign-on (AAD/MSA, Edge-equivalent silent auth via the Windows primary account) for the app's embedded WebView2 Browser tab, so authenticated sites like forms.cloud.microsoft sign in silently instead of hitting the login wall + Conditional Access rejection. Mechanism: vendor wry 0.55.1 (the vendor/tao precedent), renumber to 0.55.2, patch its WebView2 environment creation to set AllowSingleSignOnUsingOSPrimaryAccount(true), and guard the patch with a source-level regression test.

## Kind
implementation

## Context
Symptom: the app's Browser tab (native child WebView2) hit the Microsoft login wall for forms.cloud.microsoft, and the user's manual sign-in was rejected by security (Conditional Access) — the embedded webview has no OS-account SSO, unlike Edge which authenticates silently via the Windows Primary Refresh Token.

Findings:
- WebView2 exposes exactly this switch: ICoreWebView2EnvironmentOptions::AllowSingleSignOnUsingOSPrimaryAccount (MS Learn) — "enable single sign on with AAD and personal MSA resources inside WebView; all AAD accounts connected to Windows are supported". Default disabled. UWP-only capability caveat is N/A (desktop Win32 app).
- wry 0.55.1's create_environment (src/webview2/mod.rs) builds CoreWebView2EnvironmentOptions and sets additional_browser_args / extensions / language / scroll_bar_style — never the SSO flag. Tauri 2.11.5's WebviewBuilder method list (docs.rs, verified) has no environment hook, so app code cannot inject a pre-created environment.
- tauri-runtime-wry 2.11.4 pins wry = "0.55.0" (^0.55) → a vendored wry renumbered 0.55.2 satisfies the pin, exactly the vendor/tao 0.35.3→0.35.4 pattern (root Cargo.toml [patch.crates-io], workspace already excludes vendor/).
- webview2-com's CoreWebView2EnvironmentOptions wrapper has `unsafe fn set_allow_single_sign_on_using_os_primary_account(&self, bool)` (docs.rs) — same wrapper wry already calls set_additional_browser_arguments on.
- The app's CDP remote-debugging port is injected via the WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS env var (src/webview_args.rs, set in src-tauri/src/main.rs before the Tauri builder); the WebView2 loader applies it at environment creation independent of the options object → browser_* tools unaffected by the patch.
- Scope: the flag applies to every WebView2 environment wry creates in-process (main app webview, agent-chat child, Browser tab child). The first two only load local app content, so SSO there is inert; the Browser tab is the beneficiary. Unconditional patch is the Edge-equivalent behavior and avoids vendoring tauri itself.
- Regression-guard precedent: src-tauri/tests/tao_backport.rs asserts source-level invariants of the vendored tree; mirror it.
