# Plan: Plan-changed notices no longer claim to come from the built-in lead

## Goal
When a plan edit steers a working worker, the message is signed by Mnemo2, so neither the worker nor the mission control inbox says the built-in lead sent it while Claude Code is leading.

## Kind
bug_fixing

## Context
Root cause: TeamRuntime::attach_board in src-tauri/src/mnemo2/team.rs registers the board's edit observer, and it hard-codes MessageSender::Lead when it messages each working worker on the edited plan. Decision: use MessageSender::Mnemo, whose header is "[From Mnemo2]". Why that one and not a choice between lead kinds: Mnemo2 writes this notice's text itself, and the observer only receives plan_id and kinds, so it cannot know who edited the plan (Claude Code, the built-in lead, or anything else). Choosing by whether an external lead is attached would still mislabel an edit from the built-in lead while Claude Code is attached. Checked: sender only selects the delivered header and the ledger's inbox label; no code branches on it, and mnemo2/src/components/WorkerInbox.svelte already labels every sender, so no frontend change is needed. Regression test: extend plan_edit_notifies_only_working_workers in src-tauri/src/mnemo2/team.rs with an assertion on the inbox entry's sender; without the fix it fails with left Lead, right Mnemo. Verification: cargo test -p mnemo-app --features mnemo2 --lib plan_edit_notifies_only_working_workers; cargo test -p mnemo-app --features mnemo2 --lib; cargo clippy -p mnemo-app --features mnemo2 --all-targets -- -D warnings.

## Acceptance scenarios
- After a plan decision is recorded, the working worker's inbox entry has sender mnemo and its unchanged text, and the worker receives the header [From Mnemo2] instead of [From the built-in lead].
