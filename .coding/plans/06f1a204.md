# Plan: Honest worker notices: real turn ends, the actual tool errors, a cost alert, cheaper tier guidance

## Goal
The lead only hears "finished its turn" when a worker really finished, sees the actual tool errors when one fails or gets stuck, and is told when a worker gets expensive. A detailed spec goes to the cheap tier by default, and the frontend test suite stops timing out under machine load.

## Kind
implementation

## Context
WHY: in the last session the lead hand-checked team_status because "finished its turn" notices arrived for workers still working, could not see the tool errors behind a failure, could not resume a failed worker ("already running"), and only noticed afterwards that two GLM workers cost $10.27 against $0.81 for four DeepSeek workers doing the same kind of detailed spec.

ROOT CAUSE OF THE FALSE NOTICES (found by the lead, not just stale queueing):
- `team_message` to a busy worker sends `SessionCommand::Steer`. Per src/agent/loop_impl.rs `StopReason::Steer`, a steer is a soft stop: the turn drains its tool batch, breaks, emits `Finished`, and the steer drives a follow-up turn that starts with `Started`.
- `pump_worker` in src-tauri/src/mnemo2/team.rs treats every such `Finished` as a finished turn: status becomes `Completed`, `turns` increments, busy clears. Then `Started` flips it back to `Working`.
- `pump_team_notifications` in src-tauri/src/mnemo2/runtime.rs sees `Finished` plus status `Completed` and sends "finished its turn". The attach_board plan-changed observer also steers workers, so a plan edit alone can trigger it.
- Separately, a true finished notice can sit in the external queue while the worker moves on: drained text is delivered as-is.

DECISIONS ALREADY TAKEN (do not reopen):
- Fix both: a steered turn end is not a finished turn, AND each state notice is tagged with its turn and dropped at delivery if the worker has moved on.
- Tags live in the notice's first line, so all queue plumbing stays `Vec<String>`. Only the fixed first line is parsed, never the body, which can carry worker text.
- `worker reports:`, audit, plan and nudge notices are never tagged or dropped.
- A worker stays `Working` through a steered turn end; a safety deadline settles it as finished if the follow-up never starts, so a worker can never hang in `Working`.
- Tool errors: the current streak of failed calls is kept on the worker record, last 3, each output capped at 300 chars, and shown in the failure notice, the strike nudge and team_status.
- Worker text in notices stays data; the existing notice rules already say so.
- Cost notice: first at $2.00 per worker, then at each doubling, never stops or changes a worker. The amount is `cost_notice_usd` in `[routing]` of mnemo2.toml, 0 turns it off, and it gets no settings UI: the user does not want knobs on the page.
- Tier guidance: a step with a complete spec goes to routine or trivial even across files, unless Laya names a higher tier at about 0.75 or more. Laya's question text never follows ladder definitions (src/agent/route_question.rs), so changing definitions cannot shift Laya.

## Acceptance scenarios
- Steering a busy worker produces no "finished its turn" notice and no Completed status until the follow-up turn really ends, and then exactly one notice.
- If a steer's follow-up turn never starts, the worker still ends Completed with its notice within the grace period.
- A queued finished, failed or blocked notice whose worker has moved on is never delivered; worker reports are always delivered.
- A failure notice, a strike nudge and team_status show the actual last tool errors, capped and bounded.
- team_resume on a failed worker with a live session makes it idle instead of saying already running, and a delivered message clears a stale error.
- A worker passing $2.00 notifies the lead once, again at each doubling, and keeps running; 0 turns this off.
- The frontend test suite runs with 20 second timeouts and half the machine's workers, and the lead's guidance sends a complete spec to routine or trivial.
