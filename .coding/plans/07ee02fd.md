# Plan: A dev-only preview page renders Mnemo2 screens with realistic sample data

## Goal
Running the Vite dev server and opening /preview.html?scene=<name> shows mission control, a worker thread and the lead chat filled with realistic sample data, so UI changes can be reviewed in a browser without the Tauri app and without hand-written harness files. Nothing of it reaches the production bundle.

## Kind
implementation

## Context
WHY: every UI review in the 2026-11-01 session required writing a throwaway review-harness.html plus src/review-harness.ts in a worker worktree, a temporary launch config, and hand-built thread data, because the fixtures have no tool rows or Markdown with headings, code and lists. That is slow and was redone four times.

FINDINGS (probed while planning):
- verified: mnemo2/vite.config.ts has no build.rollupOptions.input, so `vite build` bundles only mnemo2/index.html; a root-level mnemo2/preview.html is served by `vite` in dev but not built.
- verified: mnemo2/scripts/assert-no-production-mock.mjs only walks src/lib, src/components, src/App.svelte and src/main.ts; files under src/preview/ may import src/test/fixtures.ts without failing `npm run check:no-mock`.
- verified: src/test/fixtures.ts exports createProjects, createWorkers, createLeadEntries, createPlanItems, createDiffFiles, fixtureState, createHighRiskWorker, createAuditWorker. WorkerThread renders `worker.messages` (entries with from/body/time, or kind "tool" entries with toolCallId/toolName/arguments/liveOutput/result).
- verified: a working harness mounts ControlRoom after `app.set(fixtureState())`, `actions.openTeam()` and setting `selectedWorkerId`; it must import @fontsource-variable/inter, @fontsource-variable/source-serif-4 and ./app.css like src/main.ts.
- verified: the dev server binds 127.0.0.1:5180 (strictPort); open http://127.0.0.1:5180/preview.html, not localhost.

DECISIONS:
- One page, mnemo2/preview.html, with a `scene` query parameter: `mission-control` (default; a worker selected whose thread has a lead message with inline code, a quoted plan with h2/h3, a list and a fenced code block, several tool rows in done/running/failed states, a worker reply and an inbox message), `worker-thread` (same thread, a needs-you worker), `lead-chat` (the lead chat with entries), `lead-idle` (top bar with an idle Claude Code lead badge), `delete-sheet` (the delete-old sheet with a superseded worker). An index of scene links shows when the parameter is unknown.
- Sample data lives in a new src/test/previewScenes.ts that builds on fixtures.ts; it is test-side code and may be reused by tests.
- No production file imports the preview; check:no-mock keeps passing and the vite build output stays unchanged.
- Document the page in mnemo2/README.md (one short section: how to start it and the scene list).

VERIFY (run in mnemo2/):
- npm run check (svelte-check: 0 errors, 0 warnings)
- npm run check:no-mock
- npx vitest run
- npx vite build, then confirm target/mnemo2-dist has no preview.html
- Start `npx vite` and load http://127.0.0.1:5180/preview.html?scene=mission-control and each other scene; report what renders.
- Fresh worker worktrees need `npm ci --no-audit --no-fund` at the worktree root first.

## Acceptance scenarios
- http://127.0.0.1:5180/preview.html?scene=mission-control shows mission control with a selected worker whose thread contains Markdown headings, inline and block code, a list and tool rows.
- Each of the scenes worker-thread, lead-chat, lead-idle and delete-sheet renders without console errors.
- npm run check:no-mock passes and vite build output contains no preview.html.
