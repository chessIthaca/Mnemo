# Plan: Sharpen inner tool descriptions (git fields + memory tools)

## Goal
Sharpen the inner tool descriptions so the LLM sees precise, per-field guidance at the call site — focusing on the git tool's subcommand-specific required fields/defaults and the three memory tools' missing field descriptions (including explaining the tier enum).

## Context
Reviewed all 19 inner tool schemas across 7 files. 14 are already well-described (file_read, file_write, file_edit, file_append, search, spawn_agent, describe_image, create_plan, update_plan, complete_step, abandon_plan, skill_start, skill_end, abandon_skill). The gaps: (1) git's per-field descriptions don't state which subcommands require which fields or the defaults; (2) the three memory tools (memory_write, memory_recall, memory_consolidate) have completely empty field descriptions — bare "type":"string" with no description, and the tier enum values aren't explained. These are description-only changes (no logic/behavior change), so existing tests should pass unchanged. The ToolSchema::new(name, description, params) signature takes the description as the 2nd arg and params as a json!({...}) block.

## Steps
- [x] 1. 1. git (src/tool/agent/git.rs): sharpen the four vague field descriptions. message → state it's required for commit, optional for merge. branch → state it's required for merge/checkout, optional for push. action → state the defaults (stash defaults to push, branch defaults to list). remote → already fine, leave it. Keep the top-level description and the enum as-is.
- [x] 2. 2. memory_write (src/tool/memory/mod.rs): add descriptions to tier (explain the four tiers: working=raw events, episodic=session summaries, semantic=facts, procedural=workflows), title (short label), and content (the memory body).
- [x] 3. 3. memory_recall (src/tool/memory/mod.rs): add descriptions to query (natural-language search), tier (optional filter, same enum as memory_write), and limit (max results, optional).
- [x] 4. 4. memory_consolidate (src/tool/memory/mod.rs): add a description to session_id (the session to compress from working→episodic).
- [x] 5. 5. Run cargo test from the project root and confirm all tests pass (description-only changes should not affect any test).
- [x] 6. 6. Review + commit: spawn a read-only reviewer over all uncommitted changes, write findings to .coding/reviews/, fix every finding, re-run cargo test, then commit to the current feature branch.
