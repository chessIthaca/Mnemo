## Goal

## Kind

## Context
EVIDENCE: the assertion that failed sits after a wall-clock poll (src-tauri/src/mnemo2/runtime/tests.rs ~:2284-2296): up to 100 iterations of team.snapshot() with a 20 ms sleep, i.e. a 2 s budget for both workers to reach Completed with a non-empty transcript. The transcript is refreshed after the turn ends, which a machine running several cargo builds can delay past 2 s. Earlier in the same test there may be other fixed deadlines (the event loop that counts `finished` and collects `texts`); check them too.

RULES (same as the earlier approval-test flake plan and the HOW record on load-proof tests): diagnose from the code which wait expires and why it is slow under load; replace wall-clock budgets with waits on the actual condition or event, with only a generous hang guard (120 s) that panics naming what it waited for; no longer sleeps-as-fix, no retries of the whole test. Keep every assertion and the test's intent. Touch product code only if the diagnosis finds a real race there (then with its own test).

REGRESSION TEST: team_runs_two_workers_concurrently_without_cross_talk itself, made deterministic. Proof before/after: run it 30 times (cargo test -p mnemo-app --features mnemo2 --lib team_runs_two_workers_concurrently_without_cross_talk, or the built test binary directly) while `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::team` runs in parallel as load; record the failure rate before and after.

VERIFY: the loop with 0 failures after the fix; cargo test --workspace; cargo clippy --workspace --all-targets.
