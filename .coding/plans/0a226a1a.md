# Plan: Fix recurring backlog.jsonl clobber: reload-from-disk before every mutation

## Goal
Restore the wiped backlog.jsonl and fix the root cause: BacklogStore must re-sync from disk before every mutation (read-modify-write) so external git changes are never clobbered by a stale in-memory state.

## Kind
bug_fixing

## Context
Investigation findings:
- BacklogStore (src/backlog.rs) holds `items: Vec<BacklogItem>` in memory, loaded once via `open()` at startup (src-tauri/src/main.rs:314). Shared via one `Arc<tokio::sync::Mutex<BacklogStore>>`.
- Every mutating method (add, remove, reorder, transition, set_status, requeue, edit, clear_finished) calls `persist()` which writes the ENTIRE in-memory vector to disk (atomic temp+rename) — never re-reads disk first.
- When git (merge/checkout/restore/merge_to_main) changes backlog.jsonl on disk, in-memory is stale. Next mutation persists stale state → clobbers git's changes.
- Current incident: HEAD (e0f35d8) has 4 items; working tree file is empty (1 blank line); in-memory store is empty (backlog_list confirms). The 4 items are safe in HEAD.
- Key constraint: do NOT add reload to persist() itself — the open() → migrate_inline_images() → persist() path must not reload (would undo the migration). Reload goes in the mutation methods only.
- The crate is #![deny(warnings)] — zero warnings required.

## Bug
.coding/backlog.jsonl gets wiped to empty (stale in-memory state persisted over committed entries) after git operations change the disk file. BacklogStore loads items once at startup and never re-syncs from disk; persist() writes the in-memory vector unconditionally, so a stale in-memory state clobbers git's changes on the next mutation. This is the recurring "steering-time backlog clobber" (commits 3b99a87, 6e5cf25 repaired symptoms; root cause persists).
