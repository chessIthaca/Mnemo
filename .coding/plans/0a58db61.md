# Plan: Backlog: steer/interrupt must not fail a pre-executing item

## Goal
A user steer or interrupt must never mark a backlog item Failed while it is still pre-execution: the item only leaves Pending when the workflow enters Executing, and an intervention returns it to the queue (non-terminal) instead of failing it.

## Kind
implementation

## Context
Root cause (traced 2026): (a) Run-All steer: send_suggestion (src-tauri/src/ipc/agent.rs:247-249) calls halt_run_all (src-tauri/src/ipc/run_all.rs:904) which stamps the in-flight item Failed (run_all.rs:948-952) even while the agent is still pre-planning. (b) Single-dispatch steer/interrupt: the soft-stop Finished resolves via the plan-loop gate (run_all.rs:822-873) and marks Failed ('plan loop did not close (workflow: Planning)'). Step-1 findings that refine the design: (1) an approval-halted run-all item NEVER resolves later (halt calls end_run clearing run_all; run-all items never enter single_in_flight) — halt's Failed stamp IS the terminal status for approvals and must be kept there; only the steer/interrupt reason must become non-terminal. (2) interrupt during run-all does NOT halt the run — the intervention handler itself must end the run. (3) a steer soft-stops the turn (StopReason::Steer -> Finished) and the steer re-runs as its own turn, so the intervention latch is always consumed by that turn's resolution; guard: only set the interrupt latch when the agent is actually running.
