# Plan: Speed up memory cleanup: parallel session consolidation + no per-session reloads

## Goal
Make Settings → Memory "Clean up memory" dramatically faster: (1) run session consolidation with bounded concurrency so the ~3 LLM calls per session overlap instead of serializing (101 sessions → ~25× faster wall time), and (2) stop re-loading the entire working tier from SQLite for every session — pass the once-loaded snapshot instead.

## Kind
implementation

## Context
cleanup (src/memory/maintenance.rs:82) loops pending sessions; each consolidate_session (src/memory/consolidation.rs:107) (a) re-lists the FULL working tier via list_by_tier (src/memory/mod.rs:1397 → load_all reads every row + embedding BLOB) — O(S×N) row loads, and (b) makes 3 sequential LLM calls (synthesize_with_llm, extract_semantic_facts, extract_procedural_workflows) when a provider is configured. 2026-08-18 diagnosis (memory a846b6b0, plan 2c926bd8) measured the stuck-at-100% case as ~101 sessions × 3 LLM calls = hours. Sessions are independent: record_tool_event tags each working row with exactly one session (documented in maintenance.rs:77-81), MemoryStore writes serialize on a single SQLite write connection (src/memory/mod.rs:330-336), and LlmClient is Send+Sync with no shared serialization (provider/mod.rs:341; openai.rs client has only trace/pending mutexes) — so bounded parallel consolidation is safe. Other callers of consolidate_session that must stay unchanged: runtime/agent.rs spawn_consolidation (session end) + tool/memory/mod.rs memory_consolidate.
