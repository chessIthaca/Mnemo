# Plan: Savings levers: fix two bugs, stop wasteful previews, and make the Cost tab's numbers honest

## Goal
The levers stop doing harm in the places a review of the real ledger found, a lever is only credited for what it really saved, and the Cost tab's Savings card shows a defensible estimate on the same traffic as its savings.

## Kind
implementation

## Context
WHY. A review of this project's real ledger (`.coding/memory.db`, 2026-11-09, at configured prices) found: the bill is about $1,087, of which cached re-sends are $600 (55%), uncached $322, output $165. The tab values the levers at $45.53 by pricing each token once at a blended input rate; a truer estimate is about $107 gross and $88 after expansions. Facts behind each fix: (1) `expand_result` output over 20,000 chars is archived again, so 250 of 580 expansions returned another preview. (2) A passing `cargo test` compresses to "exit 0: 335 error" because `is_error_line` is a substring match that runs before the passing check, and a test named with "error" or "fail" then counts as an error; the `test result: ok. 3492 passed; 0 failed` summary line also matches. (3) `plan_read` (79%) and `web_fetch` (62%) are expanded most of the time, so a preview only adds a request. (4) 29 of 30 sampled outlines were followed by ranged reads of the same file; across 29 files outline plus ranges entered 152% of the lines a whole read would have, in 183 reads instead of 29, and the ledger records outlines as gross savings. (5) `cargo fmt --check` and `rustfmt --check` sent about 1.4M tokens to the archive with no compressor, and `npx vitest` misses the existing family. (6) The read cache survives compaction and old-result trimming, so a skeleton can say "unchanged since your last full read" about content the agent no longer holds. (7) No expansion in the ledger was ever older than 6 hours, yet the archive is never pruned: 137 MB of a 268 MB database.

VALUATION MODEL (decided). Baseline: tool results were already capped at 100,000 chars, `TOOL_RESULT_MAX_CHARS`, so 25,000 tokens; `archive` and `compression` rows are credited `MAX(MIN(tokens_before, 25000) - tokens_after, 0)`, which also telescopes a compressed-then-archived result into one saving, and works on old rows with no migration. Duration: a saved token would have been re-sent at the cached rate until old-result trimming removes it, so count at most 15 later requests. Rates: the session's own model rates. Extra requests: a lever that forces a follow-up re-sends the whole prompt at the cached rate.

CONSTRAINTS. No new setting or knob of any kind: every rule is a constant, in line with the user's standing preference. Never drive the installed Mnemo2 app; never run `npm run rebuild:mnemo2`; never touch tags or release state. Commit only on your own worker branch. New savings rows must remain fire-and-forget; recording must never block or break a turn. The Mnemo1 Dashboard reads the same `savings_stats`, so its shape must not change, though its totals will honestly get smaller.

DECISIONS (do not reopen). Exempt from archiving: `expand_result`, `plan_read`, `web_fetch`. Outline threshold moves from 300 to 500 lines, because at or below 500 a whole read serves the whole file. Archive retention 14 days, no VACUUM (freed pages are reused, so the file stops growing rather than shrinking). `compaction_checkpoint` stays in the ledger but leaves the Cost tab; `truncation` leaves the tab's label table because nothing emits it. A re-adding lever shows dollars as a cost ("costs ≈ $19.50"), reversing the earlier no-dollars rule, because a real figure now exists. Not doing: extending Delta reads to ranged reads (only about 4% of reads repeat), and lowering the compaction trigger (the part of prompts above 200k costs only about $57 in cached reads).

## Acceptance scenarios
- A passing `cargo test` of hundreds of tests whose names contain 'error' or 'fail' compresses to a header reporting 0 errors, a passing count and the `test result:` line, in under 400 characters, while a real FAILED test and its panic stay visible.
- `expand_result` on a 30,000-character archived result returns the content, not another preview, and no new archive row appears; `plan_read` and `web_fetch` results are not archived; a large `shell` result still is.
- `cargo fmt --check` output lists each file with its diff count and no diff bodies; `npx vitest run` and `npx svelte-check` use the existing compressors.
- A whole read of a 450-line source file serves the file; a 600-line file serves its outline; a following ranged read in the first 500 lines records `outline_followup` charged against the outline, never beyond what the outline saved.
- After compaction or an old-result trim, a whole re-read of an unchanged file serves the full content instead of a skeleton claiming it is unchanged.
- The Cost tab shows no Compaction checkpoints or Output caps rows, shows Old results trimmed and Compaction once they have rows, shows expansions with a dollar cost, and states the model traffic its savings are measured against; a compressed-then-archived 130,000-token result is credited at most 25,000 tokens in total.
- Archive rows older than 14 days disappear shortly after the engine starts, including from archive search; newer rows survive; no setting controls it.
