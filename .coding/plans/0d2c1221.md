# Plan: Stream shell tool output live while the command runs

## Goal
A long-running `shell` call must show its output in the tool card AS IT IS PRODUCED instead of only at exit: read the child's piped stdout/stderr incrementally, throttle the chunks, and emit them as a display-only agent event keyed by tool_call_id, while the final ToolResult stays byte-identical (that is what the model consumes) and approval/safety semantics stay untouched. Source of truth: backlog 7e6385b3 (user request 2027-01-16).

## Kind
implementation

## Context
WHY: a multi-minute build/test through the shell tool is indistinguishable from a hang — the chat card and the user wait blind until the child exits (user's words: "we want to stream shell output instead of just seeing it in the end when the command is done").

DESIGN LOCKED FOR THIS PLAN. (1) Byte-identical result: `execute` becomes a thin delegate to a new `execute_streaming(args, OutputSink::none())` so there is exactly ONE capture path — no drift between streamed and non-streamed runs (a test pins the equality). (2) Sink = `OutputSink` (Clone, `Arc<dyn Fn(ToolOutputStream, &str) + Send + Sync>`) built per call at the dispatch site, capturing a CLONED fan-in sender + agent_id + tool_call_id and using `try_send` (a full channel drops a delta — a live-view pixel, never the result). (3) Throttle in the shell reader: flush at ≥60 ms since the last emit, or ≥8 KiB pending, or EOF — ~16 emits/s per stream, well under the 16 ms DeltaBatcher cadence, so ToolOutputDelta rides the forwarder as a structural pass-through (no new DeltaKind). (4) Never split a UTF-8 char: flush only up to the last valid boundary (`std::str::from_utf8` → `valid_up_to`, lossy-decode the prefix, carry the tail; lossy-decode the remainder at EOF). (5) Live-view cap 256 KiB per call with ONE truncation note; the uncapped accumulator still feeds the final result. (6) Ordering: both readers are awaited before the ToolResult is returned, so every delta precedes the result on the same FIFO fan-in channel; a delta that loses the race (timeout/cancel path) is dropped by the reducer's guard (append only while `result === null`). (7) Display-only: nothing about approval, safety modes, `never_auto_for` (core git ops), the workflow ToolFilter, the model's context echo, or the shell_filter changes.
