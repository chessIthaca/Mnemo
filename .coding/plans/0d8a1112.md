# Plan: Flaky macOS tests: the dead-connection resend test and the lead self-merge test

## Goal
Both tests are deterministic on macOS without changing the helper's deliberate no-resend rule for a connection that breaks mid-request.

## Kind
bug_fixing

## Context
1. serve_tests.rs ~line 330: the test drops the first FakeServer (`drop(first); // Mnemo2 quits; its port closes.`) and immediately sends request 2. serve.rs `forward` (~line 464) retries only `HttpError::Connect` errors (nothing delivered); an error after connecting is `Forward::Fail` on purpose ("resending could run a tool twice"). On macOS the dropped FakeServer's listener can still complete the TCP handshake from its backlog while its accept thread winds down, then the socket is reset — so the request fails as mid-request instead of as a refused connect. Fix the TEST (keep the production rule): after `drop(first)`, wait (up to 5 s, polling every 20 ms) until `std::net::TcpStream::connect(("127.0.0.1", first_port))` is refused, capturing the port before the drop; or make FakeServer's Drop join its accept thread and close the listener synchronously if that is simpler and keeps other tests unchanged. Check other serve_tests that drop a FakeServer and then expect a refused connect, and apply the same wait if they share the pattern.
2. runtime.rs `lead_merges_from_inside_its_own_turn` (~line 5166): it waits for the worker's status Completed, commits a file on the worker branch, reviews and records a check, then merges via the lead host tool; on a slow runner the review's tip and the merge's tip differ ("the current worker tip has not been reviewed"). Find what can move the worker tip or the recorded review tip after `wait_for_worker_status(..., Completed)` (e.g. a turn-end finalizer that commits or a status write racing the review) by reading team.rs (the turn-completion path and `review`/`merge_locked` tip handling). If it is a test race, make the test wait for the real quiescent point (e.g. the worker idle/no pending finalizer) before committing; if it is a production race (a tip-moving step after Completed is reported), fix it and say so. Do not weaken the assertion.

Regression tests: the two tests named above. Verification: `cargo test -p mnemo2-app`, `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::runtime`, run each named test 20 times in a loop locally (`for i in $(seq 20); do cargo test ... <name> -- --exact || break; done`), `cargo clippy --workspace --all-targets -- -D warnings`, `cargo clippy -p mnemo-app --all-targets --features mnemo2 -- -D warnings`.
