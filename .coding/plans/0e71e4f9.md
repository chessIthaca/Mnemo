# Plan: Chat tab: hide tool-call items behind show_tool_activity (default off)

## Goal
Ship the `show_tool_activity` setting (default off): a GUI-only, render-time display filter that hides tool/memory/vision/skill activity cards in the chat transcript, consolidating and removing the memory-specific `show_memory_activity` toggle — with the transcript store and the model's context echo unaffected, the Settings → Chat checkbox renamed, and full test coverage on both sides.

## Kind
implementation

## Context
Backlog db489070. Design decisions locked during exploration: (1) CONSOLIDATION per the item's preferred option — `show_memory_activity` is REMOVED everywhere; one toggle `show_tool_activity` (bool, default FALSE) governs all tool/memory/vision/skill activity cards. (2) RENDER-TIME filter, not reducer suppression: Conversation.tsx skips activity entries when the toggle is off; the transcript STORE always contains every entry (the item's test spec: "the transcript store still contains every entry either way"); the model's context echo is built server-side and is untouched. This deletes the entire per-agent flag plumbing (AgentState.showMemoryActivity, emptyAgentState seed, registerAgents stamp, setShowMemoryActivity re-stamp, applyAgentEvent agentStamped) and both reducer gates (reduceToolCallStart memory suppression, reduceMemoryRecalled gate) — memory/auto-recall entries now always enter the store. (3) Persistence follows the show_tool_images/sounds pattern: config.toml [ui] is the single source, App.tsx hydration ALWAYS applies (no localStorage mirror, no seed-if-absent guard); the old `mh.showMemoryActivity` localStorage key is orphaned harmlessly; old config.toml files with `show_memory_activity` parse fine (UiConfig has no deny_unknown_fields — unknown keys ignored, dropped on next save). (4) Simple version for hidden entries: render NOTHING (no "N tool calls" summary line) — the InflightBar shows live activity and the Output tab logs every tool result. (5) Always-visible kinds: user/assistant/error/steer/qa (conversation + user interaction); ApprovalPrompt/QuestionPrompt are not transcript entries and are unaffected. (6) Test infra is node-env vitest with an EXPLICIT include list (vitest.config.ts) and source-contract style component tests (?raw pins, no React DOM) — the filter predicate is an exported pure helper `isActivityEntry` in agentState.ts, unit-tested + pinned via a new Conversation.test.ts registered in the include. (7) The Rust contract test `assert_fixture("dto-get-settings", ...)` compares against frontend/src/lib/ipc-fixtures/dto-get-settings.json — both sides must change together (step 1). No README/doc references to show_memory_activity exist outside code (verified by repo-wide search). appearance.test.ts and agentEventReducer.memory.test.ts have NO showMemoryActivity references (verified).
