# Plan: Run-all stall after clean item completion — heartbeat re-drive + persistent arm logging

## Goal
Make a run-all run self-healing and its stall arms traceable: no armed run with eligible pending items ever sits idle waiting for a turn resolution that may never come (the "you stopped again mid run" class), and every dispatch-chain arm writes a persistent, timestamped log line so any future stall is diagnosable from .coding/logs/run-all.log in one read. Acceptance: a regression test simulating the post-resolution stall state (run armed, item done, pointer cleared, main agent idle, eligible pending items) dispatches the next item WITHOUT any turn resolution (red today — no such mechanism exists); a deferred busy-guard dispatch recovers via the delayed retry without a new turn resolution; the heartbeat no-ops when an item is in flight / compacting / no eligible items / run ended; the existing dispatch/stall/drain/orphan regression tests stay green; cargo test --workspace green.

## Context
Structural root cause (confirmed by code reading this session; the exact arm of TODAY's incident is unidentifiable from artifacts because every candidate arm logs only to stderr — invisible in the launched app):
- The dispatch chain after an item resolution has multiple arms that fail SILENTLY: (1) the busy-guard deferral (src-tauri/src/ipc/run_all.rs:3330-3346) returns Ok after eprintln "dispatch deferred — main agent still busy", relying on "the in-flight turn's terminal event re-invokes on_main_turn_resolved → this function, dispatching then" — an assumption that breaks when the busy thing is not a main-agent turn whose resolution re-drives the main lane (a spawned lane's resolution goes through on_spawned_turn_resolved, which re-drives only in its own cleanup paths; a stale/zombie descendant fires nothing); (2) the between-items auto-compact window (compact_then_dispatch_next, run_all.rs:3167-3246) holds the dispatch behind wait_for_compact_signal for up to AUTO_COMPACT_WAIT (value to be checked) with only a timeout backstop; (3) run_all_dispatch_next's Err returns are eprintln'd by callers and swallowed.
- Once any arm stalls, the ONLY re-drive is a future main-agent turn resolution — an idle main agent produces none. The gate never re-checks on its own. The user's nudges create turns, but if the busy-guard arm is the culprit (has_running_descendants still true), even those keep deferring — matching today's live behavior.
- Eliminated by evidence: no-eligible end_run (10 eligible items — selector verified: Pending && is_live && !deferred && !exclude, src/backlog.rs:820-833); checkpoint failure (would annotate the item — all notes null); the compact chain's own failure handling is sound (timeout → "dispatching anyway"); the intervention path (timing implausible — the latch is consumed at resolution start, before the user could type).
- Prior art to follow: the Q2-fixed diag_line pattern (src-tauri/src/ipc/events.rs — CWD-independent sink: project .coding/logs in dev, temp_dir packaged, OnceLock) for the persistent log; the watchdog activity ring for stall evidence.
Fix design (three parts, class-level): (1) persistent run-all log (.coding/logs/run-all.log) routing every gate/dispatch/compact arm — the diagnostic instrument that makes the next incident identifiable in one read; (2) a run-all heartbeat — while a run is armed, a periodic check (RUN_ALL_HEARTBEAT, ~30s): current_item None + not compacting + main agent idle (not running, no running descendants) + eligible pending item exists → run_all_dispatch_next; spawned at run start, self-terminates when the run ends; bounds EVERY silent stall arm to one heartbeat period; (3) a delayed retry after a busy-guard deferral (~60s) so a deferral whose assumed terminal event never comes still recovers.
