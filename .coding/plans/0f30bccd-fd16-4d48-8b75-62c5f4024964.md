# Plan: Diagnose RDP desktop-switch freeze

## Goal
Identify why myharness freezes in a Remote Desktop setup when the user switches between desktops/sessions, and produce a ranked diagnosis report with a concrete fix plan. New clue vs. the 2026-04-19 diagnosis: the freeze correlates with RDP desktop switching (WebView2 DirectComposition occlusion + synchronous controller-call territory).

## Kind
research

## Context
User reports the app froze again; the new hint is a remote-desktop situation with frequent switching between desktops. Prior freeze findings (F1 blocking git poll, F3 unbounded transcript) shipped 2026-08-17 and are verified intact (files.rs get_git_branch uses spawn_blocking). Key suspect found in recon: main.rs:95-103 on_window_event calls wv.set_size() synchronously on the main event loop on every Resized; src-tauri/src/ipc/browser_webview.rs calls set_position/set_size/show/hide on tokio workers shared by all IPC. Under RDP session/desktop switches, WebView2's DirectComposition compositor can stall, and synchronous controller calls block — a classic WebView2Feedback RDP hang pattern. Frontend lives at frontend/src (React/TSX, 49 files).
