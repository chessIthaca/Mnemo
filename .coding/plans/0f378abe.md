# Plan: Claude Code (Claude Desktop) as the external lead of Mnemo2's team

## Goal
Let Claude Code (CLI or the Claude Desktop Code tab, on the user's own subscription) lead a Mnemo2 project. It plans, dispatches, reviews and merges through Mnemo2's team tools over MCP, and Mnemo2's workers run on the user's API endpoints and tiers. The pieces: a "mnemo" Claude Code plugin (MCP server, skills, hooks) and a `mnemo2-mcp` helper that starts Mnemo2 hidden in the tray when needed.

## Kind
implementation

## Context
The full design is in `.coding/design/claude-code-lead.md` (architecture, components, hooks, risks). The user accepted it on 2026-10-31.

Agreed decisions:
- **Auto-start:** the stdio helper `mnemo2-mcp` connects to a running Mnemo2, or starts it with `--hidden` in the tray. The team manager stays in the app; no daemon split.
- **Lead guidance:** MCP `instructions` give a short lead brief, and the `mnemo-lead` skill holds the long form. The tool descriptions of `lead_host_tools()` carry over unchanged.
- **Notices:** while the lead is busy they are appended to Mnemo tool results and added by a PostToolUse hook. While it is idle, a background `mnemo2-mcp wait` wakes it, with a Stop hook as the safety net. Channels are a later upgrade.
- **Claude Code's own agents** (`Agent`/`Task`/`Workflow`) are a last resort and need the user's explicit OK, enforced by a PreToolUse hook that returns `ask`. `Explore` and `claude-code-guide` pass without a prompt (configurable). Outside an attached Mnemo project the hook allows everything.
- **Claude models as Mnemo workers** still need an API key (accepted).
- **Compliance:** only official Claude Code extension points. Never touch Claude credentials. No Anthropic marks in names.

Work rules:
- Branch `wt/claudeLead` in `.worktrees/claudeLead`. Never commit to main or `wt/mnemo`; the user decides the merge.
- Subagents never touch git state.
- Mnemo2 is running a team on the main checkout at the same time, so don't touch it.

Verification:
- `cargo test --manifest-path src-tauri/Cargo.toml -p mnemo-app --features mnemo2 --lib` (deny(warnings), so green means warning-free).
- `npx vitest run` and `npx svelte-check --threshold error` in `mnemo2/`.
- The new binary's tests.
- `npm run build:mnemo2:native` at the end.

## Acceptance scenarios
- **Auto-start:** with Mnemo2 closed, `mnemo2-mcp serve` started in a registered project directory starts Mnemo2 hidden. MCP `initialize` returns `instructions`, and `tools/list` contains `team_dispatch` and `team_status`.
- **Instance selection:** the helper connects to the instance whose run file names the cwd's project root; with none, it starts `mnemo2 --hidden --project <root>`. A stale run file (dead pid or failed ping) is ignored and removed.
- **Auth:** a request to the MCP endpoint without the run-file token is rejected (401).
- **External lead:** with an MCP session attached, a worker completing makes `deliver_lead_notice` queue the "finished its turn" notice for the external lead instead of prompting the in-app lead. The next MCP tool result carries it under "Since your last call:". `mnemo2-mcp notices --drain` returns it once.
- **Wait:** `mnemo2-mcp wait` blocks until a notice is queued, prints it and exits 0. On timeout it exits 0 with "no events".
- **Stop hook:** it blocks once when workers are active and no waiter heartbeat exists, and never blocks when `stop_hook_active` is true.
- **Agent gate:** `mnemo2-mcp gate-agent` returns `permissionDecision: "ask"` for an `Agent` call with subagent_type `general-purpose` in an attached project. It allows `Explore`, and it allows everything when no project is attached.
- **Detach:** detaching (session closed or idle timeout) returns the project to the in-app lead. Mission control shows the external-lead badge only while attached.
- **Plugin check:** the plugin passes `claude plugin validate` (if available). Every tool name mentioned in the skills and instructions exists in `lead_host_tools()`.

## Decisions
- 2026-10-31: plan created from the accepted design. Cost control: the lead (Opus) designs, reviews and integrates. Well-specified implementation goes to Sonnet subagents with disjoint file ownership, and lookups to Haiku/Sonnet. An independent reviewer subagent runs per step, and its findings are settled by the lead and recorded in `.coding/reviews/claude-lead-0f378abe-step<N>.md`.

- 2026-10-31: no global single instance. Mnemo2 deliberately supports several instances (one per project; project::attach conflict markers), so a single-instance plugin would break existing behavior. Instead, one run file per instance records its open project, and `mnemo2-mcp` picks the matching instance or starts one. This also removes the "different project open" refusal case.
- 2026-10-31: an unregistered cwd is never registered silently. The tool result tells Claude to ask the user, and a `mnemo_register_project` tool registers it after the user agrees.

## Interfaces
- 2026-10-31 **Project key.** Every request carries `root`, the canonical project root (`project::canonical_root`, a dunce path). The external lead is keyed by root, not by the Claude session id: 2.1.138 gives no session id to MCP servers (see the spike note).
- 2026-10-31 **Run file** `<config>/run/mnemo2-<pid>.json`. `<config>` = `mnemo::config::resolve_config_dir(None)`, which is `$MNEMO_HOME` or `~/.mnemo`.
  - Shape: `{"pid":u32,"port":u16,"token":"<32 hex>","version":"<CARGO_PKG_VERSION>","project":"<root>"|null,"started_ms":u64}`.
  - Written atomically (tmp + rename) at startup, rewritten when a project opens (lead_open success) or closes, and removed on `RunEvent::Exit`.
  - Owned by `src-tauri/src/mnemo2/run_file.rs`.
- 2026-10-31 **App args:** `mnemo2 [--hidden] [--project <path>]`.
  - `--hidden` builds the main window with `visible(false)`.
  - A tray icon is always present. Its menu has "Open Mnemo2" (show and focus), a disabled label "Workers: N running", and "Quit" (asks for confirmation when workers are live).
  - With `--hidden`, closing the window hides it instead of exiting.
- 2026-10-31 **Startup and open requests (backend → frontend):**
  - IPC `mnemo2_startup_project() -> Option<String>` returns the canonical `--project` once, then `None`.
  - Event `mnemo2://external-open-request` with payload `{"root": String}` asks the frontend to open that registered project through its normal `openProject` flow.
  - Event `mnemo2://external-lead` with payload `{"attached": bool, "root": String|null}` reports attach/detach.
  - IPC `external_lead_status() -> {"attached": bool, "root": Option<String>, "since_ms": Option<u64>}`.
- 2026-10-31 **Local HTTP API** (`src-tauri/src/mnemo2/mcp_server.rs`):
  - Basics: 127.0.0.1, random port, HTTP/1.1 with `Connection: close`. Every route is POST with a JSON body and requires `Authorization: Bearer <token>`; otherwise it returns 401.
  - `/health` → `{"pid","version","project"}`.
  - `/mcp`: the body is one JSON-RPC message, with header `X-Mnemo-Root: <root>` and `X-Mnemo-Helper: <absolute path of the mnemo2-mcp exe>` (`std::env::current_exe`). The server puts that path into the instructions as the waiter command: `"<helper>" wait`. That way Claude can run the waiter from Bash without depending on PATH. It returns 200 with the JSON-RPC response, or 202 with an empty body for notifications. Methods:
    - `initialize` → `{protocolVersion: (the client's), capabilities:{tools:{}}, serverInfo:{name:"mnemo",version}, instructions: LEAD_INSTRUCTIONS}`. It does not attach the lead.
    - `tools/list` → `lead_host_tools()` mapped to `{name, description, inputSchema: parameters}`, plus `open_mission_control`.
    - `tools/call` → `handle_lead_host_tool(name, arguments)` → `{content:[{type:"text",text: output + drained notices under "\n\nSince your last call:\n- ..."}], isError: !success}`.
    - `ping` → `{}`.
    - Root mismatch: if the instance has no project open, it emits external-open-request, waits up to 60 s for the runtime root to match, then proceeds. If a different project is open, it returns a JSON-RPC error whose message names both roots. If the root is not registered, it returns an error telling Claude to ask the user to add it in Mnemo2.
  - `/lead/notices`: body `{"root","mode":"drain"|"peek"}` → `{"attached":bool,"notices":[String],"active_workers":u32,"waiter_alive":bool,"summary":String}`. `summary` is a short board, workers and model line for SessionStart.
  - `/lead/wait`: body `{"root","timeout_s":u64}` → `{"notices":[String],"status":"notices"|"timeout"|"detached"|"no_project"}`. It long-polls, returns as soon as at least one notice is queued (and drains them), and returns `[]` on timeout. While open, `waiter_alive` is true.
  - `/lead/gate-agent`: body `{"root","subagent_type":String}` → `{"decision":"allow"|"ask","reason":String}`. The decision is `ask` only when an external lead is attached for root and `subagent_type` is not in `[claude_lead] agents_without_prompt` in `<config>/config.toml` (default `["Explore","claude-code-guide"]`).
  - `/lead/detach`: body `{"root"}` → `{}`.
  - The lead also detaches after 10 min with no `/mcp`, `/lead/wait` or `/lead/notices` call.
- 2026-10-31 **External lead state** (`TeamRuntime`, team.rs). Notice text is the exact string the in-app lead would get.
  - `attach_external_lead()`, `detach_external_lead()`, `external_lead_attached() -> bool`.
  - `push_external_notice(text)`, `drain_external_notices() -> Vec<String>`.
  - `wait_external_notices(timeout) -> Vec<String>` (a `tokio::sync::Notify` wakes it).
  - `deliver_lead_notice` (runtime.rs) queues to the external lead and returns true while one is attached, instead of steering or prompting the in-app lead.
- 2026-10-31 **Helper CLI** `mnemo2-mcp` (`src-tauri/src/bin/mnemo2_mcp.rs`, a console bin, required-features mnemo2). Instance lookup: walk the run files, drop dead or unreachable ones (`/health` fails), and pick the one whose `project` is an ancestor of, or equal to, the cwd's canonical root.
  - `serve`: stdio MCP bridge.
    - With no instance: if cwd is inside a registered project (`project::list`), spawn `<dir of current exe>/mnemo2[.exe] --hidden --project <root>` detached, then wait up to 30 s for its run file. If cwd is not inside a registered project, serve an inert stub: initialize without instructions, `tools/list` = `[]`.
    - Each stdin line is POSTed to `/mcp` with `X-Mnemo-Root`, and non-empty responses are written as lines.
    - On a connection failure it retries the lookup once. On stdin EOF it POSTs `/lead/detach`.
  - `notices --drain|--session-start|--stop-check`: reads hook JSON from stdin and prints hook JSON. It exits 0 with no output when no instance is found or nothing is attached. Behavior:
    - drain: PostToolUse `additionalContext` with the notices.
    - session-start: SessionStart `additionalContext` with the summary plus notices.
    - stop-check: `{"decision":"block","reason":...}` only if `active_workers > 0`, `!waiter_alive` and `stop_hook_active` is false.
  - `wait [--timeout <s>]` (default 1800): prints the notices, or `no events`, and exits 0.
  - `gate-agent`: reads PreToolUse stdin and prints `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":...}}` on ask, and nothing on allow or when no instance exists.
- 2026-10-31 **Plugin** `mnemo2/plugin/`:
  - `.claude-plugin/plugin.json` (name `mnemo`) and `.mcp.json` (server `mnemo`: command `${CLAUDE_PLUGIN_ROOT}/bin/mnemo2-mcp`, args `["serve"]`).
  - `hooks/hooks.json` in exec form (`command` + `args`) with matchers SessionStart, PostToolUse `*`, Stop, and PreToolUse `Agent|Task|Workflow`.
  - Skills `mnemo-lead`, `mnemo-plan`, `mnemo-review`, `mnemo-status`.
  - `bin/` is gitignored and filled by the build.
  - Repo-root `.claude-plugin/marketplace.json` names the marketplace `mnemo` with plugin source `./mnemo2/plugin`.

- 2026-10-31 (review round 1) **Attach and delivery.** Only `/mcp` `tools/call` and `/lead/wait` attach the external lead; `initialize`, `tools/list` and `/lead/notices` never do, so opening Claude Code in a project does not take notices from the built-in lead. Notices are pushed atomically: if no lead is attached, they go to the in-app lead. When the lead detaches, undelivered notices go to the in-app lead (Steer when busy, Prompt when idle), or are parked until they can. Drained notices are put back at the front of the queue if writing the response fails. `/mcp` initialize is answered by the helper itself (fast start); the server needs no initialize. The helper skips draining for subagent hook calls (`agent_id`) and only a `serve` session that made a `tools/call` sends `/lead/detach`.
