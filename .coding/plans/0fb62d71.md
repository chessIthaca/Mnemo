# Plan: Backlog items: send-to-top button

## Goal
Add a "send to top" button to each backlog item card: one click moves the item to the top of the queue (making it the next dispatched pending item) instead of N move-up clicks. Pure frontend — reuses the existing backlogReorder full-order push; no backend changes.

## Kind
implementation

## Context
User request (2027-01-06): "backlog items need a send to top button." Exploration findings:
- The move mechanism: BacklogView.tsx handleMove (:482-492) builds the full id array from the store's backlog, swaps neighbors, and calls backlogReorder(ids) (frontend/src/lib/tauri.ts:1547 → backlog_reorder, src-tauri/src/ipc/backlog_cmds.rs:158-166 — rewrites the store order; unlisted ids keep their relative order and go last). No backend change needed for a jump-to-top: just push a new full order with the id first.
- Ordering semantics: backlog_list returns items in display/file order; next_pending() (the auto-feed/run-all dispatch path) takes the FIRST pending item in that order — so index 0 of the rendered list = next dispatched. The up/down buttons (:565-580) are the pattern: icon buttons, disabled at the list edges (index === 0 / total - 1), no status gating, p-1 rounded hover styling.
- The card already receives index + total props; the store list is useAgentStore((s) => s.backlog).
- Test patterns in place: BacklogView.test.tsx (renderToStaticMarkup markup pinning — registered in vitest.config.ts) and the exported-pure-helper pattern (splitHeadline) for unit tests. New test files would need vitest.config.ts registration — extending the existing registered file avoids that.
- Icon: lucide-react ArrowUpToLine (arrow up to a line — the standard "send to top" glyph); fallback ChevronsUp if the import fails type-check.
