# Plan: Teach through tools and tests, not agent.md: check-run and file-write notes, policy ratchets

## Goal
Mistakes agent.md now only asks workers to avoid are reported by the shell tool when they happen or fail a test. agent.md then shrinks to pointers and judgement calls.

## Kind
implementation

## Context
WHY: rules written only in agent.md are requests; nothing tells a worker when it broke one, and every rule costs context in every prompt. Example: workers ran `cargo test --workspace; "exit=$LASTEXITCODE"`, so their check runs were not counted. The shell tool already knew (it measures only exact allow-listed commands), but said nothing, and the fix was another paragraph in agent.md. The direction: each correction moves to the strongest level it can reach. That means a tool message at the moment of the mistake, or a test that fails the build. agent.md keeps only judgement calls and short pointers.

SCOPE (decided):
1. Shell tool notes (src/tool/agent/shell.rs, the kernel `shell` tool used by every Mnemo agent):
   a. a check command run in a form that does not count;
   b. a check run that changed tracked files;
   c. shell-based file writes.
   They are added to the front of the output exactly like the existing GREP_NUDGE / REDIRECT_NOTE / CHAIN_TRANSLATION_NOTE (see around shell.rs:823-846).
2. Ratchet tests (tests/integration/policy.rs, a new module of the existing `integration` test binary, tests/integration/main.rs):
   a. `cfg(windows)` may appear only in files already on an allow-list;
   b. the count of `#[allow(` / `#![allow(` attributes per file may not grow.
   Each failure message says what to do instead.
3. agent.md: replace the long exit-code paragraph and point the remaining rules at what now enforces them. The exact text is in step 3.

A ratchet freezes today's state: existing occurrences are listed in the test, so the build stays green, and only new ones fail. Removing an occurrence never fails; the test then asks to shrink the allow-list (see step 2).

VERIFY (each alone on its line): `cargo test --workspace`; `cargo clippy --workspace --all-targets`.

## Acceptance scenarios
- A worker running `cargo test --workspace; "exit=$LASTEXITCODE"` sees a NOTE at the top of the shell result naming `cargo test --workspace` and saying to run it alone.
- A worker running `Set-Content` in the shell sees the file_edit/file_write note.
- Adding `#[cfg(windows)]` to a new src file, or a new `#[allow(dead_code)]`, makes `cargo test --test integration policy` fail with a message saying what to do instead.
- agent.md's exit-code bullet is two sentences.

## Steps
- [x] 1. **Shell notes: uncounted check runs, tree-changing check runs, shell file writes** File: `src/tool/agent/shell.rs` only. The tool already has `check_commands` (validated allow-list) and `measures_check(command, cwd)` (shell.rs:414), and computes `tree_before`/`tree_after` around a measured run. Add three notes. Like the existing ones, each is inserted at the front of `combined`, before `cap_tool_output`, and ends with `\n`. 1. **CHECK_NOT_COUNTED.** - Condition: the run was NOT measured, and some allow-listed check command `c` occurs in `args.command` as a substring. If several match, pick the longest. - Text: `NOTE: this run does not count as the \`{c}\` check. Mnemo2 counts a check only when that exact command is the whole command line, run from the checkout root, with nothing piped, chained or redirected. Run \`{c}\` alone to record it.\n` - Add it even when the command failed. 2. **CHECK_TREE_CHANGED.** - Condition: the run was measured, both trees are known, and they differ. - Text: `NOTE: this run of \`{c}\` changed tracked files, so it does not count as a check. Commit or revert those changes, then run it again.\n` 3. **SHELL_FILE_WRITE.** - Condition: `args.command` matches (ASCII case-insensitive) any of `set-content`, `add-content`, `out-file`, `sed -i`, `>>`, or a `tee` word (`| tee ` or a leading `tee `). Do not match `tee` inside other words (e.g. `guarantee`). - Text: `NOTE: change files with file_edit or file_write, not the shell: they show the diff and keep line endings. A shell write is a last resort; say why in your report.\n` Order of notes from the top: the existing BACKGROUND_HOLD, CHAIN_TRANSLATION, REDIRECT and GREP notes keep their relative order. The new notes go at the very top, in the order CHECK_NOT_COUNTED, CHECK_TREE_CHANGED, SHELL_FILE_WRITE: insert them last, in reverse order. The raw `data.stdout/stderr` stay note-free, as today. Keep the note texts as `const` (or a `fn` for the ones with `{c}`) beside the existing note constants, each with a doc comment. Tests, in shell.rs's test module, using the existing `tool_in(dir)` helper (see around shell.rs:2385): - `uncounted_check_run_gets_a_note`: with check list `["git status"]`, running `git status; echo done` returns output starting with `NOTE: this run does not count as the \`git status\` check`. - `counted_check_run_gets_no_uncounted_note`: `git status` alone; the output contains no `does not count`. - `check_run_that_edits_files_gets_tree_note`: copy the setup of `configured_editing_command_records_different_trees`; the output contains `changed tracked files`. - `shell_file_write_gets_a_note`: on Windows run `Set-Content x.txt hi`, else `echo hi >> x.txt`; the output contains `change files with file_edit`. A second run of `echo guarantee` has no such note. Done (each alone on its line): `cargo test -p mnemo shell`; `cargo test --workspace`; `cargo clippy --workspace --all-targets`; commit. Don't touch: anything outside shell.rs.
- [x] 2. **Policy ratchet tests: cfg(windows) files and #[allow] counts** Files: new `tests/integration/policy.rs`; `tests/integration/main.rs` (add `mod policy;`). Walk `src/`, `src-tauri/src/` and `src-tauri/mnemo2-app/src/` for `*.rs` files, with std::fs only, no new dependencies. Paths are repo-relative with `/` separators, found from `env!("CARGO_MANIFEST_DIR")`, as the other integration tests do. Read ci_workflow.rs for the pattern. 1. **`cfg_windows_stays_in_known_files`.** - Collect the files containing `cfg(windows)`, `cfg(target_os = "windows")`, or `cfg(not(windows))`. The last counts too: it marks a platform split. - Compare against `const WINDOWS_CFG_FILES: &[(&str, &str)]` of (path, reason). - Fill it NOW with every file that matches today. Give each a short reason from what the file is: `"WebView2 Browser pane"`, `"Windows process / console handling"`, `"path or shell differences"`, and so on. Read each file's cfg use to choose; do not guess. - A matching file missing from the list fails with: `"{path} adds Windows-only code. Library and app code must build and behave on macOS too; the only sanctioned Windows-only feature is the WebView2 Browser pane. Make the code platform-neutral, or, if it really must differ by platform, add the file to WINDOWS_CFG_FILES in tests/integration/policy.rs with the reason and give macOS its own branch."` - A listed file that no longer matches fails with: `"{path} no longer has Windows-specific code; remove it from WINDOWS_CFG_FILES."` 2. **`allow_attributes_do_not_grow`.** - Count `#[allow(` plus `#![allow(` per file. Exclude a line starting with `//` (after leading whitespace) and anything inside a string literal on the same line; a simple quote check is enough. - Compare against `const ALLOW_COUNTS: &[(&str, usize)]`, filled NOW with today's counts. - A file whose count exceeds its entry (an absent entry is 0) fails with: `"{path} has {n} #[allow(...)] attributes, more than the {max} allowed. Fix the warning's cause instead. If a lint must stay off on purpose, use #[expect(lint, reason = \"why\")], which also fails once the lint no longer fires."` - A file whose count dropped fails with: `"{path} now has {n} #[allow(...)]; lower its ALLOW_COUNTS entry to {n}."` so the ratchet tightens. Tests must pass on the current tree, and on macOS: only std, no platform paths. Done (each alone on its line): `cargo test --test integration policy`; `cargo test --workspace`; `cargo clippy --workspace --all-targets`; commit. Don't touch: any src file. If a count looks wrong, report it, don't fix code.
