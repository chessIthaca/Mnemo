# Plan: Plans tab: top-level plans with expandable details

## Goal
Mnemo2 gets a top-level Plans tab beside Lead, Team, Cost and Graph, and each plan card there keeps today's look but expands to show the whole plan (context, acceptance scenarios, decisions, interfaces, progress, full step text) as Markdown.

## Kind
implementation

## Context
Why: the user opened the Workbench's Plan tab, saw only a title, a collapsed goal and one line per step, and asked whether plans are really that short. They are not: a plan file `.coding/plans/<id>.md` is typically 4-10 KB (## Goal, ## Kind, ## Context of a page or more, ## Acceptance scenarios, ## Steps with full step text, ## Bug, ## Decisions, ## Interfaces, ## Progress, ## Regression test), and every worker receives all of it. The user's direction: "make it expandable. I like the look of the plans and it should just let me get more details. Also make the plan things something top level like lead team cost and graph."

Verified facts (probed while planning):
- verified: `mnemo2/src/components/PlanTab.svelte` renders only `plan.title`, `plan.goal` (Collapsible maxHeight 60) and `step.header ?? step.text` per step; it is mounted only in `mnemo2/src/components/Workbench.svelte` (line ~78, the default branch after browser/diff).
- verified: `BoardPlan` in `mnemo2/src/lib/boardState.ts` (and `BoardPlanView` in `src-tauri/src/mnemo2/team.rs` ~line 344) carries id, title, goal, kind, status, closed_at_ms, report_path, steps — no context, acceptance, decisions or interfaces.
- verified: `TeamRuntime::plan_document(&self, plan_id) -> Result<String, String>` exists but is private (`src-tauri/src/mnemo2/team.rs` ~line 925) and calls `PlanBoard::read_markdown` (`src/app/plan_board.rs` line 262), which first runs `self.load(id)` (line 906: the id must match a board.json row, else `unknown(id)`) and only then reads `plans_dir/<id>.md`; an unknown or malformed id therefore errors before any file access.
- verified: `board_snapshot` is the Tauri command at `src-tauri/src/mnemo2/ipc.rs` line 784, registered in `src-tauri/src/mnemo2/mod.rs` line 434; the frontend calls it through `createTauriBoardTransport` in `mnemo2/src/lib/boardEngine.ts`.
- verified: `Route` is `"start" | "lead" | "team" | "cost" | "graph"` in `mnemo2/src/lib/types.ts` line 6; the top-bar tabs are buttons in `mnemo2/src/components/TopBar.svelte` (Cost and Graph at lines 57-58, using `actions.openCost` / `actions.openGraph` from `mnemo2/src/lib/store.ts`); the route switch is in `mnemo2/src/App.svelte` (lines ~43-46).

Decisions:
- A new top-level route `"plans"` with a "Plans" button in TopBar after Graph (a lucide icon such as ListChecks), an `actions.openPlans` in store.ts, and a `PlansView` (or PlanTab reused full-width) in App.svelte. Reuse PlanTab's cards so the look stays the same; give the full-width view a sensible max content width like the Cost/Graph views. The Workbench keeps its Plan tab (it sits next to a worker's thread) unless that makes the code worse; say what you chose.
- Each plan card gets an expand control (chevron "Details", closed by default, keyboard accessible, aria-expanded). Closed, the card looks exactly as today. Opening it fetches the plan document once through a new Tauri command `board_plan_document(plan_id: String) -> Result<String, String>` (next to `board_snapshot` in ipc.rs, registered in mod.rs, backed by `plan_document` made `pub(crate)` or a thin public wrapper) and renders it with the existing `Markdown.svelte`. Skip the parts the card already shows (the `# Plan:` title line and ## Goal); keep ## Steps only if the full step text adds to the headers. Show a quiet loading line, an error line on failure, and re-fetch an open card on `mnemo2://board-changed` (the existing board sync). The snapshot payload does not grow: details stay lazy.
- `BoardTransport` gains `document(planId: string): Promise<string>`; check how other commands with arguments are invoked in this codebase for the argument casing.
- Previews: the preview page has no Tauri host. Use the dev-only seed seam pattern (a preview setter in the lib module, imported only from `mnemo2/src/test/*`; production never imports `../test/*`; `npm run check:no-mock` enforces it). Add a preview scene `plans` showing the Plans tab with several plans and one card's details open with realistic markdown.
- Use the existing type tokens (`--text-meta`, `--text-body`, `--text-title`, `--text-page` in `mnemo2/src/app.css`) and Inter.

Verification: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::` and `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`; in `mnemo2/`: `npm run check`, `npm run check:no-mock`, `npx vitest run`. Never start a dev server or any command that does not exit on its own (shell commands can hang); the lead renders the preview.

## Acceptance scenarios
- The top bar shows Lead, Team, Cost, Graph and Plans; clicking Plans opens a full-width list of open and closed plans in today's card style.
- Each plan card has a closed Details control; opening it shows the plan's context, acceptance scenarios, decisions and full step text as formatted Markdown, and closing it returns the card to its current look.
- board_plan_document with an unknown plan id returns an error without reading any file, and board_snapshot carries no new fields.
