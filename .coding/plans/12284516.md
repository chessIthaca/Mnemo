# Plan: Reasoning panel open/closed is a user choice (persisted, default closed)

## Goal
Stop the InflightBar reasoning panel from opening itself: the panel's open/closed state becomes purely the user's choice (chevron click or drag handle), remembered across app restarts via localStorage and defaulting to closed for a fresh install. No code path may expand the panel on its own.

## Kind
bug_fixing

## Context
ROOT CAUSE (verified by reading the source): frontend/src/components/chat/InflightBar.tsx lines 95-107 contain an auto-expand effect — `const reasoningNow = reasoningActive(phase, activityLog)` plus `useEffect(() => { if (reasoningBlockStarted(prevReasoningActive.current, reasoningNow)) setExpanded(true); prevReasoningActive.current = reasoningNow; }, [reasoningNow])`. `reasoningActive`/`reasoningBlockStarted` live in frontend/src/lib/reasoningPanel.ts, a module that exists ONLY to drive this auto-open (its only importer is InflightBar.tsx). The effect fires once per reasoning block, and every turn's `started` event clears the activity log, re-arming the edge — so each new turn re-opens the panel the user collapsed (Introduced deliberately 2026-08-22, plan 0d079599/backlog #84; the user is now reversing that behavior). The panel state itself is component-local `useState(false)` (line 89).

USER DECISION (asked, answered): persist the choice across restarts — not session-only.

FIX DESIGN: (1) delete the auto-expand effect + the `prevReasoningActive` ref + the reasoningPanel import from InflightBar.tsx; (2) persist `expanded` under a new localStorage key `mh.inflightPanelOpen` (default CLOSED: only the literal "1" counts as open), read once via a lazy state initializer and written on every user toggle (bar-button click AND the drag handle's collapsed branch — a drag is a user action); (3) new pure-ish helper module frontend/src/lib/inflightPanelPref.ts with the key, `parsePanelOpen`, a `typeof window === "undefined"`/try-catch guarded read, and a guarded write — mirroring the established patterns in frontend/src/hooks/appearance.ts (readLs/writeLs guards) and frontend/src/components/views/GraphView.tsx:93-113 (component-local persisted UI state: `BOTTOM_HEIGHT_KEY` + `storedBottomHeight()`); (4) delete the now-dead frontend/src/lib/reasoningPanel.ts + reasoningPanel.test.ts and their frontend/vitest.config.ts include entry.

REGRESSION-TEST DESIGN (vitest, node env — no DOM testing library in this repo; the convention is static source-contract tests via `?raw` imports, see InflightBar.test.ts's existing describes): extend frontend/src/components/chat/InflightBar.test.ts with a describe pinning that the component contains NO auto-open wiring (`not.toContain("reasoningBlockStarted")`, `not.toContain("reasoningActive")`, `not.toContain("prevReasoningActive")` — all three FAIL before the fix, so the test reproduces the defect) and that the state is user/persisted-driven (`toContain("useState(readInflightPanelOpen)")`, `toContain("writeInflightPanelOpen(")`); plus a new frontend/src/lib/inflightPanelPref.test.ts pinning default-closed for absent/""/"0"/garbage, "1" → open, and a `vi.stubGlobal("window", { localStorage: fake })` round-trip. IMPORTANT: frontend/vitest.config.ts has an EXPLICIT include allowlist — a new test file NOT registered there silently never runs (past review finding), so both the new file's entry and the removed one must be handled.

DOCS TO SYNC: docs/FEATURES.md:49 currently claims the thinking box "auto-opens the moment a reasoning block starts streaming ... (a manual collapse is respected until the next block)" — must be rewritten to the new truth. Existing test assertion to update: InflightBar.test.ts:55 pins `onClick={() => setExpanded(!expanded)}` (the click handler gains the persist call).

VERIFY: `cd frontend; npm test` (new describes must appear in the output), `cd frontend; npm run build` (tsc must compile after the module deletion), and root `cargo test` unpiped with `$LASTEXITCODE` read directly (never trust a piped exit code — agent.md).
