# Plan: A compact-then-switch no longer fails a Mnemo2 worker

## Goal
A deferred model switch (compact on the old model, then swap) is reported as information, not as an error. Mnemo2 workers keep running through it, Mnemo1 still shows its notice, and the Mnemo2 worker thread notes the summarization.

## Kind
bug_fixing

## Context
The user hit this on 2026-11-02, right after the live model switch (plan 1586c6c7) merged: worker memoryPaths122 was switched from glm-5.3 to deepseek-v4.1-flash and was marked failed.

Root cause, probed by the lead:
- verified: `sed -n 1896,1915p src/agent/turn.rs`. After completing a deferred pending swap, the turn sends `AgentEvent::Error { error: format!("Switched to '{}' (summarized for smaller context)", pending.model), retrying: false }`. The swap itself succeeded, and the turn continues (`early: None`).
- verified: `sed -n 5416,5440p src-tauri/src/mnemo2/team.rs`. The worker pump treats any `SerializableAgentEvent::Error` with `retrying == false` as a terminal failure (`worker.status = WorkerStatus::Failed`, `busy` cleared), so the informational message fails the worker.
- verified: team_status for memoryPaths122 showed status failed with exactly that error, while team_resume answered "worker 'memoryPaths122' is already running": the session is alive but the record says failed.
- verified: `grep -n 'case "error"' frontend/src/hooks/agentEventReducer.ts` shows Mnemo1 at line 1590 routing error events to reduceError; that is how Mnemo1 shows this notice today.
- verified: `src/runtime/channels.rs` has `enum AgentEvent` at line 213 with no informational or notice variant. The serializable mirror and `into_serializable` start at line 971.
- Precedent: the knowledge record "BUG: Stop emitting the visible error event for the harness tool-call correction" fixed a similar misuse of AgentEvent::Error for something that was not an error.

Decisions:
- The kernel stops sending AgentEvent::Error for a completed deferred swap. Instead it sends a new informational variant, named for what happened (for example ModelSwapSummarized { model }), added to AgentEvent and to the serializable mirror in src/runtime/channels.rs (snake_case kind, following ModelChanged's serialization). Real errors on that path stay errors.
- Mnemo1: the frontend reducer (frontend/src/hooks/agentEventReducer.ts) handles the new kind and shows the same text it shows today, as an informational notice rather than an error. Mnemo1's visible behaviour must otherwise be unchanged.
- Mnemo2: the team pump ignores the new kind for status: no failure and no busy change. mnemo2/src/lib/workerThread.ts shows it as a muted note ("Summarized the conversation to fit <short model name>"), next to the existing model-switch note. The lead runtime (src-tauri/src/mnemo2/runtime.rs) must not treat it as an error either.
- Regression test (required to close): in src-tauri/src/mnemo2/runtime.rs or team.rs tests, drive a working worker through change_model to a smaller-context model so the deferred swap completes. Assert the worker is still working (not failed), error is None, and the next request serves on the new model. It fails today because of the Error event.
- Also add a kernel test in src/agent/tests.rs that a completed deferred swap emits the new event and no Error.

## Bug
Switching a working Mnemo2 worker to a model with a smaller context window marks the worker failed with "Switched to '<model>' (summarized for smaller context)", although the switch succeeded.

## Regression test
change_model_to_a_smaller_context_summarizes_without_failing_the_worker

## Decisions
- 2026-11-02: The user (2026-11-02) clarified that the summarization itself is a bug unless the context in use exceeds the new model's limit. AgentLoop::set_explicit_provider (src/agent/loop_impl.rs, around lines 2375-2390) defers the swap and compacts whenever the new provider's max_context is smaller than the current one, even when the conversation already fits the new model. Change the rule: defer and compact only when the conversation's current token usage would not fit the new model, i.e. it exceeds the new ContextManager's sendable budget or its compaction trigger, whichever the kernel's normal turn path would use to decide that compaction is needed. Otherwise swap immediately with no summarization. This changes Mnemo1 too, intentionally: an unneeded compaction loses context there as well. AgentSession::set_model's ModelSwitch result (src/headless/session.rs) must use the same rule, so CompactsFirst is reported only when a compaction will really happen. Tests: (1) a switch to a smaller-window model while usage fits swaps immediately (no summarization, no event, the next request goes to the new model with the full history); (2) a switch where usage exceeds the new limit still compacts first and then emits the new informational event; (3) the Mnemo2 regression test from the plan.
