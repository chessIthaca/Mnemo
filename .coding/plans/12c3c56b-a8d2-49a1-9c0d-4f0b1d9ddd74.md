# Plan: Fix backlog dispatch bug + add hover preview & copy button

## Goal
Fix the backlog ▶ button so it dispatches the specific clicked item (not always the top pending), and add a hover preview (full text + small image thumbnails) plus a copy-to-clipboard button to each backlog item card.

## Context
BUG: BacklogView.tsx's ▶ button calls backlogDispatchNext() → backend dispatch_next_impl → next_pending() which returns the FIRST pending item in display order, ignoring which card was clicked. So clicking ▶ on the last item dispatches the topmost. Fix: add a backlog_dispatch_item(id) command that dispatches a specific pending item by id.

The dispatch path (backlog_cmds.rs dispatch_next_impl) is shared by auto-feed (run_all.rs:652) and the ▶ button. Auto-feed/run-all must keep using top-pending (next_pending). Only the ▶ button switches to per-item dispatch.

Store (src-tauri/src/ipc/backlog.rs) has: add, remove, reorder, set_status, edit, next_pending, clear_finished, items. No pending_item(id) yet. BacklogItem { id, text, images, status, created_at, note }. BacklogStatus { Pending, InFlight, Done, Failed, CantResolve }.

single_in_flight (AtomicU64) tracks the single-dispatch in-flight item so on_main_turn_resolved marks it Done/Failed. The new per-item dispatch must set single_in_flight too.

Frontend: BacklogView.tsx BacklogItemCard renders controls (retry/edit/dispatch/up/down/remove). canEdit = status==="pending" only. Text truncates at 200 chars, click-to-expand works for all statuses. Images shown as 10x10 thumbnails. No hover preview, no copy button. UI components: Radix Dialog + Tabs only (no Tooltip/Popover). Clipboard pattern: navigator.clipboard.writeText (Message.tsx:211, AdvancedSection.tsx:89) with 2s Check feedback. createPortal not yet used but react-dom available.

Commands registered in src-tauri/src/main.rs invoke_handler (line ~238-247). tauri.ts bindings at frontend/src/lib/tauri.ts:559-637.
