# Plan: Fix the third v2.0.0 CI round: Tauri default-run, macOS-only unused import and dead test helper

## Goal
The release build workflow passes on Windows and macOS for the 2.0.0 branch.

## Kind
bug_fixing

## Context
Root causes (lead diagnosis):
1. src-tauri/Cargo.toml now declares extra [[bin]] targets (mnemo2, mnemo2-mcp, mnemo2_route_eval, all with required-features = ["mnemo2"]) beside the app binary src/main.rs (package name "mnemo-app"). `tauri build` cannot tell which is the app. Fix: add `default-run = "mnemo-app"` to the [package] table of src-tauri/Cargo.toml (right after `name`/`version`). Nothing else in that file.
2. src-tauri/src/main.rs line 15 imports `global_config_dir` from `mnemo::config`, but its only use is inside `#[cfg(windows)] fn browser_inspection_enabled()`. On macOS/Linux the import is unused and `#![deny(warnings)]` fails the build. Fix: drop `global_config_dir` from the shared `use` and call it by full path inside the Windows-only function (`mnemo::config::global_config_dir()`).
3. src/host/laya.rs `fn with_serve_command` (~line 300) is `#[cfg(test)]` but its only callers are `#[cfg(windows)]` tests (~lines 1255-1351). On macOS the test build sees it as dead code. Fix: change its attribute to `#[cfg(all(test, windows))]`. If the `serve_override` field it sets then becomes unused on non-Windows test builds (check where it is read), gate the field, its initialiser and its readers the same way, or keep it `#[cfg(test)]` if it is read by non-Windows code.

Regression check: none of these reproduce on Windows locally except the Tauri one. Verify the Tauri fix with `cargo metadata --format-version 1 --no-deps --manifest-path src-tauri/Cargo.toml` showing default_run "mnemo-app" for the mnemo-app package; the macOS fixes are confirmed by the CI run. Locally run `cargo test --lib`, `cargo test -p mnemo-app --features mnemo2 --lib`, `cargo clippy --all-targets -- -D warnings`, `cargo clippy -p mnemo-app --all-targets -- -D warnings` and with `--features mnemo2`, and `cargo build -p mnemo-app` (the app binary).

- On macOS the workspace test build has no unused-import or dead-code error from main.rs or laya.rs
