# Plan: Change a working worker's model on its next call

## Goal
The user can change a running worker's model (and reasoning effort) from mission control. The current API call finishes on the old model and the worker's next call uses the new one, with no restart and its transcript kept. The worker's thread notes the switch.

## Kind
implementation

## Context
The user asked for this on 2026-11-02. They sometimes disagree with the model a worker runs on and want to change it at the next opportunity, meaning the next API call, without stopping the worker. Feeding these manual switches into Laya routing was explicitly deferred ("switch only, no laya yet"). Do not touch Laya or routing.jsonl.

Today:
- `TeamManager::change_model` in src-tauri/src/mnemo2/team.rs (around line 3092) refuses a busy worker ("pause or stop it before changing its model"). For an idle or stopped worker it stops the session and resumes it on the new model.
- In the UI, mnemo2/src/components/WorkerDetail.svelte shows the ModelEffortPicker only when `modelChangeable`. Otherwise it shows a locked badge, "Pause or stop the worker to change its model". `actions.setWorkerModel` in mnemo2/src/lib/store.ts calls `team_set_model` (mnemo2/src/lib/teamEngine.ts), which maps to `team_set_model` in src-tauri/src/mnemo2/ipc.rs.

The kernel already supports exactly the behaviour wanted. `AgentLoop::set_explicit_provider(provider, context_manager)` in src/agent/loop_impl.rs (around line 2330) is Mnemo1's per-agent picker switch. It pins the provider for that agent, and the turn loop applies it before the next request, even mid-run. When the new model's context window is smaller, the swap is deferred (`pending_swap` / `take_pending_swap`), so the conversation is compacted with the old model first. The kernel then emits `AgentEvent::ModelChanged` when the new model actually serves a request. Mnemo1's `set_model` in src-tauri/src/ipc/agent.rs (around line 607) shows how to build the provider and context manager for a spec and effort (it uses `crate::ipc::config_io::resolve_model_provider`) and call it. Mnemo2's headless session API (src/headless/types.rs `SessionCommand`, src/headless/session.rs, which holds a `Weak<AgentLoop>`) has no model command yet. That gap is the reason Mnemo2 refuses to switch.

Decisions:
- Add a headless way to switch a live session's model. Either add a `SessionCommand::SetModel { ... }` variant, or a session method that builds the provider and context manager the same way the session factory does and calls `set_explicit_provider` on the session's agent loop. Reuse the existing provider-building path; do not hand-roll a second resolver. Mnemo1's IPC behaviour must stay unchanged.
- `change_model` on a busy worker no longer refuses. It validates the model as today, updates the worker record (model, model_id cleared, reasoning_effort, tier cleared) and persists it, then applies the switch to the live session. No stop and no resume. Idle or stopped workers keep today's path.
- The UI unlocks the picker while a worker is working or dispatching. After a switch, the worker thread shows a muted note: "Model changed to <short model name> by you; it takes effect on the next call". When the kernel's ModelChanged event for that model arrives, the note can read "Now running on <model>". The worker list and badge show the new model at once.
- Audit workers' models are not user-switchable; keep whatever rule applies today.

## Acceptance scenarios
- With a worker mid-turn on model A, switching it to model B from mission control returns at once, and the worker stays working (no stop or resume, transcript intact).
- The worker's next provider request after the switch goes to model B; the request already in flight finishes on model A.
- Switching to a model with a smaller context window first compacts on the old model, then serves on the new one (the kernel's deferred-swap path), without a 400 from the smaller model.
- The worker thread shows "Model changed to B by you; it takes effect on the next call", and the worker's model badge shows B.
- Mnemo1's model picker behaves exactly as before, and the Mnemo1 binary builds.
- All listed cargo and mnemo2 checks pass.
