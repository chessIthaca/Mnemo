# Plan: Git graph: base indication, main collapse+expand, live refresh, solid tips

## Goal
Git graph: show each branch's base (fork point), collapse main's spine to the newest 20 commits with an expand/collapse control, auto-refresh the tab whenever an agent lands a git commit/branch/checkout/merge, and render branch/main tip commits as solid filled dots.

## Kind
implementation

## Context
Git tab today: frontend/src/components/views/GitView.tsx (452 lines) renders an SVG DAG from `git_history` IPC (src-tauri/ipc/files.rs git_history_at: branches[{name,tip_sha,is_main,is_current,merged_into_main}], commits[{sha,short_sha,parents,subject,...}] cap 400, main_spine). Pure lane engine frontend/src/components/views/gitLanes.ts (computeLanes/laneColor/shortDate, node-env tests in gitLanes.test.ts, registered in vitest.config.ts). Dots: spine filled/side hollow; connectors resolve parents via findIndex on the FULL list with a clipped-stub path for unknown parents (reuse for hidden-after-collapse parents). GitView refreshes on mount + manual + a 4s timer after entering the merge skill; no agent-event subscription. Transcript tool entries (agentEventReducer) are {kind:"tool", name, calls:[{args:string(JSON), result:{success,output}|null}]}, capped at 1000/agent (agentState.ts MAX_TRANSCRIPT_ENTRIES). Four asks, all frontend-only: (1) indicate each branch's BASE, (2) collapse main's spine to ~20 with expand, (3) auto-refresh when an agent commits/branches/merges, (4) branch/main tips render as filled solid circles.
