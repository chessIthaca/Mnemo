# Plan: Per-model reasoning-effort selector (endpoint card per-model rows)

## Goal
Add a persisted per-model reasoning-effort override — `ModelSpec.reasoning_effort` in endpoints.toml — editable via a dropdown in the per-model row of the endpoint card (Providers tab), resolved through `effective_reasoning_effort_for` so the provider receives it. The toolbar dropdown stays the runtime override; this is the persisted per-model default ('unset' inherits the endpoint-level value, then the app default "max").

## Kind
implementation

## Context
Findings from exploration:
- ModelSpec (src/config/endpoints.rs:163-208) has NO reasoning_effort today — only the reasoning_efforts allow-list. Endpoint.reasoning_effort (endpoint-level) exists and is editable in the Providers tab (EndpointCard.tsx:434-471, effortToSelectValue/effortFromSelectValue/REASONING_EFFORTS/REASONING_EFFORT_DEFAULT from ../types).
- effective_reasoning_effort_for(model_id) (endpoints.rs:352-391) resolves endpoint-level only, then applies off-encoding (DeepSeek "off"→"none" via policy.rs reasoning_effort_off_wire_value) + allow-list clamping. All consumers (config_io.rs resolve_reasoning_effort:117, client_factory.rs build_provider_for:193, console.rs initial_selection:527, main.rs build_brain_inner) call it — a model-level branch in the resolver flows everywhere automatically. The toolbar dropdown (StatusBar) stays the runtime override; its initial selection comes from initial_selection → effective_reasoning_effort_for, so it reflects the per-model default with no frontend change.
- Save path: EndpointDto.model_configs (ModelSpecDto, src-tauri/src/ipc/settings.rs:90-103) → into_endpoint (:115-129, uses ..Default::default()) → validate_endpoint (src/config/patch.rs:34) → apply_endpoints (patch.rs:217). Read path: ModelSpecWire (settings.rs:330-354, null-emitting Options — no skip_serializing_if) → ProvidersSection load (ProvidersSection.tsx:56-78) → EndpointEditable/ModelConfigEditable (frontend/src/lib/tauri.ts:1101-1143) + ModelConfigInfo (tauri.ts:310-320).
- Frontend per-model rows: ModelRowConfig (EndpointCard.tsx:789-895) — ctx/out/efforts/vision controls, gated by a `disabled` prop when !supports_reasoning_effort. The endpoint-level effort dropdown (442-464) is the control pattern to mirror.
- The user's "models tab" = the per-model rows in the endpoint card's Models list (Providers tab) — the fix direction's mechanics (endpoints.toml persistence + endpoint-level inheritance) pin it there; the Models tab proper (ModelsSection.tsx) is per-context slot overrides in a different config section.
- NO apply_endpoints carry-over for the new field: it rides the DTO (authoritative), same as endpoint-level reasoning_effort — carry-over is only for non-DTO fields (temperature/stop/etc.). The round-trip must be tested instead (2026-12-24 review lesson: fields must never be silently erased on Endpoints-tab save; 2026-08-22 M1 lesson: import must not drop per-model config).
- Dropdown options: "endpoint default" sentinel + REASONING_EFFORTS (max/high/medium/low/minimal/off) — "off" included to mirror the endpoint-level control; the machinery encodes it per provider.
- Frontend tests: vitest (npm test in frontend/). Rust: cargo test, deny(warnings).
