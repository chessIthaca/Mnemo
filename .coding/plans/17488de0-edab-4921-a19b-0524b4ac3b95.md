# Plan: Four-perspective code review of myharness

## Goal
Produce four independent review documents (Architecture, Quality, PRD, Performance) covering the myharness codebase, then STOP for user review. After the user approves, consolidate into one report + a fix plan.

## Context
Codebase is a Rust + Tauri + React coding-agent harness ("myharness"). The "brain" (config, project, provider, tools, memory, workflow, runtime, agent loop) is in src/, the Tauri shell in src-tauri/, and the React frontend in frontend/. 190 lib tests pass. Key subsystems: enforced plan-first workflow, multi-agent runtime (channel-decoupled), OpenAI-compatible streaming provider with reasoning-model support, four-tier memory (SQLite + FTS5 + in-Rust vector search), path sandbox, diff-based approval gate, context summarization. The user wants four independent review perspectives, then a consolidated report + fix plan — but wants to review the four reviews BEFORE the consolidation.

## Steps
- [x] 1. Architecture review: assess module boundaries, the agent↔UI decoupling (channels + IPC adapter), the multi-agent runtime, the workflow state machine, the provider abstraction, and the memory subsystem design. Identify coupling risks, layering violations, scalability concerns, and single-points-of-failure. Write to reviews/01-architecture.md.
- [x] 2. Quality review: assess code correctness, error handling, test coverage gaps, Rust idioms, unsafe/unwrap usage, concurrency correctness (locks, deadlocks, lock poisoning), and frontend state-management robustness. Write to reviews/02-quality.md.
- [x] 3. PRD review: assess the codebase against PLAN.md — does the implementation match the stated design? Check the enforced plan-first workflow, capability-aware provider strategy, sandbox/path-safety, approval gate, context management, memory consolidation, and UI phases A–E. Identify gaps between spec and reality. Write to reviews/03-prd.md.
- [x] 4. Performance review: assess hot paths — streaming SSE parsing, memory recall (load_all + cosine over all rows), token counting (tiktoken per-turn), context summarization, SQLite under a tokio Mutex, frontend re-render behavior on streaming deltas, and channel backpressure. Identify bottlenecks + scaling cliffs. Write to reviews/04-performance.md.
- [x] 5. STOP and present the four review documents to the user for review. Do NOT proceed to consolidation until the user approves.
- [x] 6. After user approval: consolidate the four reviews into a single report (reviews/00-consolidated-report.md) with prioritized findings, and a fix plan (reviews/fix-plan.md) with ordered, actionable steps.
