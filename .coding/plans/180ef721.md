# Plan: Adopt the Mnemo icon in the app UI (sidebar + About dialog)

## Goal
Replace the lucide Code2 placeholder with the real Mnemo app icon (full badge) in the Sidebar About button and the About dialog header, via a reusable inline-SVG React component sourced from icon-source.svg.

## Kind
implementation

## Context
User request + screenshot: the sidebar's top About button shows a generic lucide Code2 `</>` glyph; user asked to use the new Mnemo app icon there instead, and chose "Full icon badge" (complete icon: dark rounded square + M mark + blue accent node). Source of truth: src-tauri/icons/icon-source.svg (38-line self-contained SVG: linearGradient `bg` #0D1117→#171B23 rounded rect rx=190, radialGradient `glow` #587CFF with feGaussianBlur filter `blur`, white M strokes + 4 node circles, blue accent node at 814,700). Prior SPEC (plan 1f47090a, merged 5db371d) explicitly left the in-app Sidebar logo unchanged — this plan closes that gap. Code2 is used in exactly two places: Sidebar.tsx:45 (About button, h-10 w-10 cyan glyph) and AboutDialog.tsx:87 (dialog header, h-5 w-5). CSP (tauri.conf.json:15) allows img-src data:/self but we inline the SVG as JSX so CSP is irrelevant. No SVG assets/plugin exist in the frontend; all icons are inline components (lucide), so a small inline-SVG React component is the codebase-consistent approach. Gradient/filter defs need unique IDs per instance (two instances will coexist: sidebar + About dialog) — use React useId with colons stripped for url() safety. Tests: plain vitest; components are rendered via renderToStaticMarkup (markdownRendering.test.ts pattern); no @testing-library. Build must stay warning-free; npm run build = tsc + vite; PowerShell unpiped exit-code checks per agent.md.
