# Plan: Fetch + analyze the vision-mcp spec

## Goal
Retrieve the vision-mcp repo's tool list + per-tool input/output spec from GitHub so we can implement equivalent native tools.

## Kind
research

## Context
User wants to replace our existing vision tool (describe_image) with the image tools from https://github.com/Pelican0126/vision-mcp, built into our system as native tools (not an MCP server). Constraints: all our tools start with "image_", skip the video tools, implement ourselves (use the repo as spec, don't copy source). Our current vision plumbing: src/tool/agent/describe_image.rs (DescribeImageTool + shared helpers mime_from_ext/load_image_data_url/describe_image_data_url/describe_image_file), src/provider/vision.rs (ImageDescriber trait + VisionClient + SwappableVision), registered in src/agent/factory.rs build_registry when vision is Some. I'm in Complete state (read-only) so I cannot fetch the GitHub repo yet — this research plan grants shell access to retrieve the spec.

## Steps
- [x] 1. **Fetch the vision-mcp repo spec** — Use PowerShell to fetch the repo's README + source listing from https://github.com/Pelican0126/vision-mcp. Try: `Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/Pelican0126/vision-mcp/main/README.md' -UseBasicParsing` (fall back to `master` branch if `main` 404s). Also fetch the repo file tree via the GitHub API: `Invoke-RestMethod -Uri 'https://api.github.com/repos/Pelican0126/vision-mcp/git/trees/main?recursive=1'` (fall back to `master`). Print the README in full + the file tree. If the README references tool definitions in a specific source file (e.g. server.py / tools.py / index.ts), fetch that file's raw content too. Goal: enumerate every IMAGE tool (skip video) with its name, parameters, and what it returns.
- [x] 2. **Record the spec findings** — Write the enumerated image-tool spec to .coding/analysis/vision-mcp-spec.md: for each image tool, list (a) the tool name as it appears in the repo, (b) our prefixed name (image_ + the repo name, snake_case), (c) the input parameters with types, (d) what the tool does / returns, (e) whether it needs a vision model call or is pure image processing. Note which tools are video-only (to be skipped). Also note the repo's overall architecture (MCP server? stdio? what vision backend?) so the implementation plan can map it onto our Tool trait + ImageDescriber. This file is the spec the implementation plan will consume.
