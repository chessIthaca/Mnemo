# Plan: Make the smaller-context model-switch test independent of whether a summary request happens

## Goal
The test passes deterministically whether or not the deferred model swap sends a summarization request to the old model first, and still proves that a summarized switch never fails or idles a working worker.

## Kind
bug_fixing

## Context
ROOT CAUSE (lead diagnosis 2026-11-11): the test's StubServer serves its StubTurns in fixed order. Turn 5 is the deferred swap's summarization reply ("Summary of the earlier work.", gate: None) and turn 6 is the held post-swap reply (gate_last). The kernel only sends that summarization request when it decides the conversation needs one ("when the deferred swap decided the conversation needs one" — the test's own comment). When it skips it, the FIRST request on model-b consumes the UNGATED turn 5, the worker completes immediately, and the assertion that it is still Working fails. The CI log shows exactly that: models = [model-a, model-a, model-a, model-a, model-b] (no fifth model-a summary request) and status=Completed. Locally the summary request usually happens, so it passes.

REGRESSION TEST: the test itself, src-tauri/src/mnemo2/runtime/tests.rs `change_model_to_a_smaller_context_summarizes_without_failing_the_worker` (≈line 7989). Without the fix it fails whenever the summarization request is skipped; with the fix both paths hold the first model-b request so the record is inspected while the worker genuinely works on model-b.

CONSTRAINTS: test-only change in src-tauri/src/mnemo2/runtime/tests.rs. Do not change production code, the StubServer API in a way other tests notice, or what the test asserts about the worker (no error, compacting badge cleared, still Working, the next request served on model-b). No sleeps-as-synchronization.

VERIFY: cargo test -p mnemo-app --features mnemo2 --lib change_model_to_a_smaller_context (run it 20 times in a loop: all pass); cargo test -p mnemo-app --features mnemo2 --lib (all pass); cargo clippy -p mnemo-app --all-targets --features mnemo2 (no warnings).

## Acceptance scenarios
- When the deferred swap sends a summarization request, the test releases it and inspects the worker while the first model-b request is held; it passes.
- When the deferred swap skips summarization, the first model-b request is itself held (it cannot complete the worker); the test passes.
- Running the test 20 times in a row passes every time.
