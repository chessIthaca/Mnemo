# Plan: create_plan branch param: fork the feature branch inside the tool

## Goal
Extend the create_plan tool with an optional `branch` (+ `base`, default "main") parameter that forks the feature branch (carrying dirty .coding/ bookkeeping like the backlog InFlight flip) before the plan file is written — replacing the 5-6 command manual git dance every backlog item currently needs.

## Kind
implementation

## Context
Root cause: at run-all item start the tree is clean except .coding/backlog.json (harness InFlight flip written after the checkpoint commit). create_plan then writes .coding/plans/<uuid>.md (untracked) + .coding/plans/stack.json (tracked, differs across branches because each item commits its own stack). git checkout main then fails ("local changes would be overwritten"), so the agent burns 5-6 commands snapshotting/restoring. Design decisions: (1) implement the dance inside create_plan BEFORE it persists the plan — the branch switch happens while only harness bookkeeping is dirty; (2) snapshot-and-restore carry (never stash — no leftover stash entries on failure, no merge on pop); (3) only .coding/ bookkeeping is ever carried — any dirty file outside .coding/ (or staged adds/renames) skips the dance with a note; the plan is still created (create_plan must never fail because of git); (4) invalid branch names are a hard arg error; (5) optional base param defaults to "main"; (6) the dance is skipped (note in output) when the workflow is mid-executing (sub-plan) — a mid-work branch switch is never wanted; (7) git plumbing lives in src/project/git_ops.rs (spawn_blocking discipline + TestRepo infra already there), the tool stays thin; (8) extend RUN_ALL_STEER so future run-all agents actually pass branch. Untracked (??) files never block checkout so they are left in place; tracked-dirty .coding files are carried; memory DB sidecars (.db/.db-wal/.db-shm, *memory*) are never git-touched.
