# Plan: Show spawn_agent task as first prompt + 'Spawn Agent (name)' label

## Goal
Make spawn_agent's ToolCard read "Spawn Agent (name)" and emit a PromptDispatched event so the spawned agent's task shows as the first user message in its window.

## Context
Two related asks for the spawn_agent flow:

1. DISPLAY STRING: The ToolCard header currently shows "spawn_agent (reviewer)" — built in Message.tsx argLabel (lines 234-238) which extracts the `name` field. The user wants it to read "Spawn Agent (reviewer)". This is a frontend label change in Message.tsx (the `name` prop passed to ToolCard is the raw tool name "spawn_agent"; need to map it to a display label "Spawn Agent" while keeping the parenthetical name).

2. TASK AS FIRST PROMPT: When spawn_agent runs, spawn_agent_shared (src-tauri/src/ipc/commands.rs:339-345) sends the task as AgentCommand::Prompt to the new agent, but does NOT emit a PromptDispatched event. So the spawned agent's window is empty until its first token streams — the task doesn't show "as if typed by the prompt entry". The existing PromptDispatched event (channels.rs:212) + frontend reducer reducePromptDispatched (useAgentStore.ts:974-983) already appends a `kind: "user"` transcript entry — exactly the desired behavior. Backlog dispatch already uses emit_prompt_dispatched (commands.rs:1014). The fix: emit PromptDispatched for the spawned agent right after sending the initial prompt.

IpcSpawner (commands.rs:356-411) currently holds factory+manager+agent_loops but NOT the AppHandle. Need to add an AppHandle field so spawn_with_parent can emit the event. main.rs:86 constructs IpcSpawner::new(...) inside the setup closure where `app` is available.

Key constraint: spawn_agent_shared is also called by the UI-button spawn_agent command (commands.rs:264) with initial_prompt=None — that path should NOT emit PromptDispatched (no task). Only the tool path (IpcSpawner::spawn_with_parent, which always has a task) emits. So the emit belongs in IpcSpawner::spawn_with_parent, not in spawn_agent_shared.
