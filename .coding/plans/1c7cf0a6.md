# Plan: Light review for small and test-only changes

## Goal
Mnemo2 decides by itself when a worker's change is light (test/doc-only or small). A light change can be reviewed with the diff read and its intent only, while every other change keeps the full five-part evidence. Checks, findings, idle-worker and merge rules stay the same for both.

## Kind
implementation

## Context
WHY: the user (2026-11-15) found reviewing tiny test-only changes with the full evidence (intent, execution, integration, test_quality, residual_risk) overkill. CI re-runs everything anyway, but reading the diff still caught real problems today (a deleted doc comment, a contradictory comment), so the diff read stays mandatory. User preference: the app decides, no settings knob.
WHERE: src-tauri/src/mnemo2/phase3.rs ReviewEvidence (around line 46) and validate_review_evidence (around line 71); its two callers, team/review.rs `review` (around line 76) and team/merge.rs merge gate (around line 220); the team_review input schemas in team/lead_tools.rs (around line 176: required list and the error text around line 475) and src-tauri/src/mnemo2/mcp_server.rs (the team_review tool schema near line 1962 and its example near line 3450). The worker's diff base is the merge-base of the lead HEAD and the worker tip (team/audit.rs around line 50 computes it the same way). The test-file rule exists in src/codegraph/mod.rs is_test_file (private): reuse its rule (a `tests` path component, or a file name containing .test. .spec. _test. _tests.).
RULES:
- light = review_risk is not "high" AND (every changed file is a test file by that rule or ends in .md, OR the diff has at most 60 changed lines in total by git numstat, added plus deleted). Binary changes count as not light.
- Light: unanchored_pass must be true and intent non-empty; execution, integration, test_quality and residual_risk may be empty or omitted.
- Not light: today's rule, unchanged. When a non-light review omits fields, the error says why the change is not light (for example "62 changed lines in 3 non-test files") and names the missing fields.
- The merge gate applies the same decision at the same tip, so a light review can merge and a non-light one cannot without full evidence.
- The team_review result tells the lead which applied ("light review: test-only change" or "full review: …").
- Schemas: required becomes [unanchored_pass, intent]; the four other fields' descriptions say they are required unless the change is light. The ReviewEvidence fields gain serde defaults so old records still decode.
TESTS (phase3 and team test modules): `light_change_accepts_intent_only_evidence` (test-only diff), `small_change_is_light` (≤60 lines in a source file), `large_change_requires_full_evidence` (the error names the line count and the missing fields), `high_risk_is_never_light`, `merge_gate_accepts_a_light_review`, `missing_unanchored_pass_is_refused_even_when_light`.
VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::`, `cargo clippy -p mnemo-app --all-targets --features mnemo2`, `git diff --check`.

## Acceptance scenarios
- team_review of a worker whose diff only touches *.test.ts files succeeds with evidence {unanchored_pass: true, intent: "..."} and says 'light review'.
- team_review of a 200-line source change with the same evidence is refused, and the error names the changed-line count and the four missing fields.
