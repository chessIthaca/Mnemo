# Plan: Persistent index-staleness log: which files went stale, why, and a note that names them (backlog fc1d57fe)

## Goal
Land a persistent index-staleness log: every stale-index repair (content index via search/search_read, symbol index via the graph tools) appends one structured record per stale file to `<global_config_dir>/index-staleness.jsonl` — timestamp, tool, path, cause class, index-vs-disk mtime + size, inline-reindexed vs surfaced-only — with a size cap + rotation; the in-tool notes name the first few paths and point at the log; the path + format are documented in docs/CONFIGURATION.md. So "which files went stale, when, and what kind of change" is answerable from the log alone, and above-cap staleness logs EVERY path.
