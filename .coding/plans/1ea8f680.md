# Plan: State-scoped model-picker pin: configured phase model takes over on workflow-state change

## Goal
Make the per-agent model-picker pin state-scoped: on a workflow-state change, a configured `[models.*]` model takes over; with nothing configured for the new state the pin keeps serving; within the pin's own state it still beats that state's slot.

## Kind
implementation

## Context
User report: in a demo project, phase model switching (Planning→Executing) stopped working after the per-agent model picker was used once. Root cause: `explicit_provider` pin (set by `set_model` IPC via `set_explicit_provider`, loop_impl.rs:1243) permanently outranks the `[models.planning]`/`[models.executing]`/`[models.complete]` chain (resolve_turn_provider branch 2, loop_impl.rs:898-934) and is never cleared. User decision (2026-12-20): the pin is STATE-SCOPED. It holds in the workflow state where it was first served (lazily stamped), and in any other state only while no configured model would resolve there; on a state change WITH a configured slot for the new state, the configured model takes over. Skill turns keep today's behavior (a configured `[models.skill.<name>]` serves skill turns without consuming the pin; with none configured the pin serves — existing test at tests.rs:4506 pins that). Key files: src/agent/loop_impl.rs (fields ~180-268, from_config ~577-605, resolve_turn_provider 859-1014, set_explicit_provider 1243-1279), src/agent/turn.rs writes explicit_provider directly at 165-169/183-187 (pending-swap completion — must NOT reset the stamp, so keep the stamp out of those writes), src-tauri/src/ipc/config_io.rs (swap_provider_into_loop doc 205-260), src-tauri/src/ipc/agent.rs (set_model doc 501-543). Existing pin regression test at src/agent/tests.rs ~4380-4518 must keep passing (pin in same state beats state override). WorkflowState is Copy+Eq (used by value in ModelContext).
