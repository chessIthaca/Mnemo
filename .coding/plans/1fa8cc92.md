# Plan: The Tiers page stops touching Mnemo1's enforce setting

## Goal
The Tiers page's choice sets Mnemo2's routing mode and Laya's routing flag only. Mnemo1's `enforce` is never written or warned about there and stays under Mnemo1's own Classifier settings. Mnemo2 on auto with Mnemo1 only watching shows no warning.

## Kind
bug_fixing

## Context
Why: `tiers_top_control_writes` in src-tauri/src/mnemo2/laya_settings.rs ties three settings to one choice, with Auto writing enforce true and every other choice writing false. The design note .coding/design/unified-tiers.md chose that coupling, but the user now runs the two apps differently. Mnemo1 keeps its own enforce control in frontend/src/components/settings/sections/ClassifierSection.tsx, so nothing is lost.

Decisions:
- The page stops writing and stops reading enforce. Forcing it to false on every save would overwrite a choice made in Mnemo1 and bring the warning back.
- `[general.laya] routing` stays tied to the choice: off for No, on otherwise. It is still Mnemo1's master flag, so the copy says so, and the warning stays for that one setting.
- No new control and no new setting (the user prefers fewer knobs). Mnemo2's own auto-mode behaviour is unchanged.

Regression test: `auto_on_the_top_control_leaves_mnemo1_enforce_alone` in the tests module of src-tauri/src/mnemo2/laya_settings.rs. Without the fix it fails because enforce becomes true after picking Auto.

Do not touch ~/.mnemo, frontend/, or src/. Do not run release builds; the lead rebuilds.

## Acceptance scenarios
- Picking Auto on Settings > Tiers leaves Mnemo1's enforce as it was, whether it was off or on, and any other choice also leaves it alone.
- With mnemo2.toml on auto, enforce off and the Laya routing flag on, the Tiers page shows Auto selected and no warning.
- With the choice on Auto and the Laya routing flag off on disk, the page warns about that flag.
- The page's copy says the choice sets Mnemo2's routing and Laya's routing flag in Mnemo1, and that switching models in Mnemo1 stays in Mnemo1's own settings.

## Bug
Picking Auto on Mnemo2's Settings > Tiers also writes Mnemo1's `enforce = true`, so Mnemo1 starts switching models, and any other choice resets it to false. The user wants Mnemo2 on auto with Mnemo1 only watching, which the page can only show with a red 'gates do not match' warning; following that warning turns Mnemo1 on.
