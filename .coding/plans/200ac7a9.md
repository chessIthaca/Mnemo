# Plan: Three small lead-flow fixes: lead check guard, notice drain, screenshot ignore

## Goal
A lead check run is no longer failed by the lead's own .coding bookkeeping, a PostToolUse notice drain no longer builds the team summary it never uses, and worker screenshots no longer make a worker checkout dirty.

## Kind
implementation

## Context
Three defects found on 2026-11-23 while leading Mnemo2 from Claude Code. They are independent and touch disjoint files.

1. Lead check run vs bookkeeping. team_run_checks without worker_id runs the .coding/checks.toml commands in the lead checkout (src-tauri/src/mnemo2/team/check_run.rs, run_lead -> run_all -> build_report). Each command passes only when the run_checks tool measured the same content tree before and after (tree_before == tree_after per entry of data.checks; the counting rule is pump::counted_checks). The content tree hashes the whole working tree (git add -A into a temp index, mnemo::project::git_ops::content_tree). A lead that edits or commits its plan files under .coding/ during a 7-minute cargo test makes a green command count as failed with "but it changed the checkout's files". Merges already ignore the lead's bookkeeping: src-tauri/src/mnemo2/phase3.rs LEAD_BOOKKEEPING_PREFIXES (.coding/plans/, .coding/reviews/, .coding/knowledge/, .coding/openspec/, .coding/laya/) and is_lead_bookkeeping, used by require_clean_lead. Decision: only the LEAD checkout run forgives a tree change, and only when every path that differs between tree_before and tree_after is lead bookkeeping. Worker runs stay strict.

2. Notice drain cost. src-tauri/src/mnemo2/mcp_server.rs, async fn notices: it calls team.external_summary().await on every call, which locks the worker records and lists every plan on the board from disk. The hook client (src-tauri/mnemo2-app/src/mnemo2_mcp/hooks.rs) reads reply.summary only for SessionStart; PostToolUse (Drain) and Stop (peek) ignore it. Hooks have a short timeout, and the user saw a mnemo hook time out. Decision: build the summary only when the request carries session_start true; otherwise send "summary": "". The reply keeps the same JSON shape.

3. Worker screenshots dirty the checkout. offscreen_browser_screenshot writes PNGs to .coding/browser/screenshots/ (src/tool/browser/mod.rs SCREENSHOT_DIR). They are untracked files, so git status shows the worker checkout dirty, and Mnemo's check run, merge and other clean-checkout gates refuse until someone deletes them. Mnemo already archives them before releasing a checkout (src-tauri/src/mnemo2/workbench.rs archive_worker_screenshots, reading the directory itself, not git) and removes untracked ones after archiving. Decision: Mnemo makes git ignore that folder for every project it runs workers in, by adding the line `/.coding/browser/screenshots/` to the repository's shared exclude file `<git common dir>/info/exclude` (git rev-parse --git-common-dir from the checkout; all worktrees of the repo share it), idempotently, when it prepares a worker checkout. Not the project's .gitignore: this must work in any user project without committing anything. A tracked screenshot stays tracked (exclude only affects untracked files).

Verification: cargo test -p mnemo-app (the narrow module tests named in each step), cargo clippy --workspace --all-targets. Mnemo runs the full .coding/checks.toml at review.

## Acceptance scenarios
- A team_run_checks in the lead checkout where the lead commits or edits only .coding/plans files while the commands run reports each exit-0 command as PASS.
- A lead or worker check run where a command changes a file outside the lead bookkeeping prefixes still reports it as failed with "changed the checkout's files"; a worker run never forgives bookkeeping changes.
- A PostToolUse notice drain (no session_start) returns summary "" without calling external_summary; SessionStart still gets the team summary.
- After a worker takes a screenshot, git status in its checkout shows no untracked file under .coding/browser/screenshots/, and its check run and merge are not refused for it.

## Steps
- [ ] 1. **Lead check run ignores lead bookkeeping changes** — files: src-tauri/src/mnemo2/team/check_run.rs, src-tauri/src/mnemo2/phase3.rs (visibility only). Intent: in a LEAD checkout run, a command that exited 0 but whose tree_before != tree_after counts as passed when every changed path is lead bookkeeping. Worker runs are unchanged. Contract: make `phase3::is_lead_bookkeeping(path: &str) -> bool` `pub(crate)` (no behaviour change). Add a `lead: bool` parameter to `run_all` (run_lead passes true, the worker path false). After `build_report`, when `lead` is true, for each outcome with `changed_files == true`, take that entry's tree_before and tree_after from `result.data.checks` and run `git diff-tree -r --name-only -z <tree_before> <tree_after>` in the checkout (use phase3's existing async `git`/`git_value` helpers). If the command succeeds and the path list is non-empty and every path satisfies is_lead_bookkeeping, set `passed = true`, `changed_files = false`, `failing = String::new()`. Any git error or any non-bookkeeping path keeps the outcome as it was (fail closed). Keep build_report synchronous; do the forgiving in a small async helper, e.g. `async fn forgive_lead_bookkeeping(checkout: &Path, result: &ToolResult, report: &mut RunReport)`, called from run_all. Tests (in check_run.rs's test module, real temp git repo): `lead_run_forgives_a_bookkeeping_only_tree_change` — two trees differing only in .coding/plans/x.md -> outcome passes; `lead_run_still_fails_a_source_change` — trees differing in src/a.rs (or in both .coding/plans and src) -> still changed_files; `worker_run_never_forgives_bookkeeping` — the same bookkeeping-only change with lead=false stays failed. Build the trees with git hash-object/mktree or by committing and using `<commit>^{tree}`. Done: the three tests pass; existing check_run tests pass; clippy clean. Do not touch pump.rs, run_checks.rs or mcp_server.rs.
- [ ] 2. **Notice drain skips the team summary** — file: src-tauri/src/mnemo2/mcp_server.rs (fn notices and its tests). Intent: `team.external_summary()` and the knowledge map run only when the body has `session_start: true`; otherwise `summary` is the empty string. Move the `let session_start = ...` read above the summary and build `let summary = if session_start { let mut s = team.external_summary().await; /* knowledge map as today */ s } else { String::new() };`. Update the doc comment of `notices` to say the summary is built only for SessionStart. The reply JSON keeps every key. Tests: find the existing tests of the /lead/notices endpoint in mcp_server.rs (search `"/lead/notices"` or `session_start`) and add `notices_drain_without_session_start_sends_no_summary` (drain body without the flag -> summary is "") and make sure an existing or new test asserts a body with `session_start: true` still gets a summary starting with "Mnemo2 team:". Done: tests pass, clippy clean. Do not touch hooks.rs or external_lead.rs.
- [ ] 3. **Git ignores worker screenshots** — file: src/app/worktrees.rs (and its tests). Intent: whenever Mnemo prepares a worker checkout (a new pool checkout or a reused one, and a legacy worktree if that path still exists — find the function(s) that create or hand out a worker checkout, around pool_checkout_name / acquire_pool_claim), it first ensures the repository's shared exclude file ignores `/.coding/browser/screenshots/`. Contract: `pub(crate) fn ensure_screenshot_exclude(checkout_or_root: &Path) -> Result<(), String>`: resolve `git rev-parse --git-common-dir` in that directory (relative results are relative to that directory), path `<common>/info/exclude`, create `info/` if missing, read the file if present, and append `/.coding/browser/screenshots/` on its own line (adding a leading newline if the file does not end with one) only when no line equals it after trimming. Write with the same line endings the file already uses is not required; plain `\n` is fine. A failure is logged with tracing::warn and does not fail the dispatch (call site ignores the error after logging). Tests: `screenshot_exclude_is_added_once` — temp git repo, call twice, the line appears exactly once and `git check-ignore -q .coding/browser/screenshots/a.png` succeeds; `screenshot_exclude_keeps_existing_lines` — an exclude file with `foo` and no trailing newline keeps `foo` and gets the new line on its own line; `screenshot_exclude_works_from_a_linked_worktree` — call it from a `git worktree add` checkout and assert the line lands in the main repo's .git/info/exclude. Done: tests pass, clippy clean. Do not touch workbench.rs or the browser tool.

## Decisions
- 2026-11-23: no spec impact: Internal robustness fixes: the lead check guard, notice-drain cost and a git exclude line change no specified behaviour of a capability; the reply shapes stay the same.
