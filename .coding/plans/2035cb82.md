# Plan: Shell tool cards render readable command input/output instead of raw JSON

## Goal
Expanding a shell tool card shows the command human-readably (purpose label + command block, no raw {"cmd":...} JSON) and the result as stdout / labeled stderr / exit-code chip (backlog 8c1d8a47). Other tools keep the existing rendering.

## Kind
implementation

## Context
Investigation complete. Tool cards render in Message.tsx CallDetail (859-904): args section pretty-prints raw JSON (872: JSON.stringify(JSON.parse(call.args), null, 2)) — the unfriendly "json input"; result section dumps call.result.output in one <pre> (897-898). For shell, the display output is built in src/tool/agent/shell.rs:269-288 as stdout + "\n[stderr]\n" + stderr + "\n[exit code: N]" (capped, filter/nudge-prefixed), while the structured data (exit_code/stdout/stderr raw, shell.rs:297-301) is present in the frontend event (types.ts:76-77 data?: unknown) but never rendered. The ToolCard header chip already shows the shell purpose via argLabel (toolCardPaths.ts:56). CallDetail receives the tool name. toolCardPaths.ts is the established home for React-free card presentation helpers (browserArgLabel/browserResultInfo/searchResultInfo pattern) with unit tests in toolCardPaths.test.ts. Message.tsx has no test file — helpers carry the logic. Backlog item 8c1d8a47-f83c-42be-824a-f7508a28ce32. Frontend-only change; Rust untouched. Design decisions: parse the display output markers (not data) for the result sections — the display output is exactly the filtered+capped text meant for humans; strict trailer match so command output containing "[exit code: 42]" mid-text is untouched; generic JSON render stays for all other tools.
