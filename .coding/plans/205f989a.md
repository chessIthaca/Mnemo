# Plan: macOS release artifact keeps Mnemo's dmg next to Mnemo2's

## Goal
The macOS artifact (and so the release) carries Mnemo_2.0.0_aarch64.dmg, Mnemo2_2.0.0_aarch64.dmg, mnemo.app.zip and mnemo2.app.zip.

## Kind
bug_fixing

## Context
.github/workflows/build.yml macos job, in order: "Tauri build (.app + .dmg, aarch64)" (Mnemo, line ~230), "Build the Mnemo2 frontend", "Tauri build Mnemo2 (.app + .dmg, aarch64)" (working-directory src-tauri/mnemo2-app), "Zip the .app bundles" (two ditto lines), "Upload macOS bundles" (paths mnemo.app.zip, mnemo2.app.zip, target/aarch64-apple-darwin/release/bundle/dmg/*.dmg, if-no-files-found: error). Fix: stage each app's outputs into a `dist-macos/` folder at the repo root right after its own tauri build. New step "Stage the Mnemo bundles" directly after the Mnemo tauri build: `mkdir -p dist-macos && cp target/aarch64-apple-darwin/release/bundle/dmg/*.dmg dist-macos/ && ditto -c -k --keepParent target/aarch64-apple-darwin/release/bundle/macos/Mnemo.app dist-macos/mnemo.app.zip`. Replace "Zip the .app bundles" with "Stage the Mnemo2 bundles" after the Mnemo2 build: `cp target/aarch64-apple-darwin/release/bundle/dmg/Mnemo2_*.dmg dist-macos/ && ditto -c -k --keepParent target/aarch64-apple-darwin/release/bundle/macos/Mnemo2.app dist-macos/mnemo2.app.zip`. Upload path becomes `dist-macos/*` (keep if-no-files-found: error). Keep the existing comments about ditto preserving the exec bit. The release job's globs (dist/macos/**/*.dmg and **/*.zip) still match. Extend tests/integration/ci_workflow.rs `build_workflow_bundles_both_apps` (or add `build_workflow_stages_each_macos_dmg`) to assert the macOS job copies a dmg to dist-macos after EACH of the two tauri builds and uploads dist-macos. Regression test: that guard. Verification: `cargo test --test integration ci_workflow`.
