# Plan: Index-based React keys misattribute row state at the transcript cap — stable entryId keys (mem-perf HIGH 3)

## Goal
Give every TranscriptEntry a stable monotonic entryId stamped at creation, and key Conversation's turn/run/entry lists by it instead of index — so at the 1000-entry transcript cap, appends no longer misattribute Message row state (arePropsEqual hits, local row state stays with its entry, list reconciliation is O(delta)). Pinned by store tests (stamping, monotonicity, stability across capTranscript + entry replacements) and a component source-contract test (keys are entryIds).

## Kind
implementation

## Context
mem-perf review HIGH 3 (.coding/reviews/2027-01-06-full-review-memory-perf.md). Conversation.tsx keys turns/runs/entries by index (key={ti}, key={ri}, renderEntry(e, i)); agentState.ts caps the transcript at the LAST 1000 entries, so once at cap every append shifts all indices — Message rows at those keys get different entry props (arePropsEqual fails → deep re-render), local row state (expanded tool card, copied flag) silently transfers to a DIFFERENT entry, and turn-count changes force O(n) list reconciliation per append.

DESIGN (key decisions): (1) The new field is named `entryId`, NOT `id` as the task text loosely says — the `memory` entry variant already owns `id?: string` (the owning tool call's correlation key, agentEventReducer.ts:504/639), so an `& { id?: number }` intersection would corrupt the correlation semantics and TS-intersect the memory member's id into never. (2) `entryId?: number` is OPTIONAL, following the ts precedent (types.ts intersection tail): stamped by the applyAgentEvent identity pass (agentEventReducer.ts:1415-1421 — the exact mechanism that stamps ts today; verified all entry-replacement sites spread the previous entry, so ids survive arg-deltas/finalizations exactly like ts) + manual stamps at the four direct-write sites that bypass applyAgentEvent: reduceQuestionAnswered (called directly via recordQuestionAnswer, stamps ts manually today at :1003), InputBar pushTranscriptMessage (:166), InputBar handleSend's user entry (:329), and InputBar /load (:522 — bulk-stamp via a stampEntryIds helper; also fixes legacy saves). (3) Counter: module-scope `let nextEntryId = 1` in agentState.ts with exported allocEntryId()/stampEntryIds() — the store is in-memory so ids only need session uniqueness; /save serializes them so they round-trip. (4) Keys fall back to prefixed position strings (`t${ti}`/`r${ri}`/`i${i}`) only for id-less legacy entries — all production paths stamp. renderEntry already takes `key: number | string` (anticipated). Complements the memoization (HIGH 2, landed) and windowing (b2cb83b6, queued) items.
