# Plan: Endpoints page: removing a model no longer trips over the config default model

## Goal
Removing a model from an endpoint in Mnemo2's Endpoints page succeeds even when that model is the legacy config.toml `default_model` of the default endpoint; the global default endpoint and model stay valid by being re-pointed to a remaining model.

## Kind
implementation

## Context
WHY: Mnemo2's Endpoints page saves through `Setup::upsert_endpoint_detail` (src/headless/setup/endpoint_detail.rs). Around lines 431-453 it refuses to save when the removed model is `[general] default_model` of the endpoint that hosts the default: "'{dm}' is the configured default model of '{prev_name}'; change the default model before removing it". Mnemo2's UI has no control for `default_provider`/`default_model` in config.toml, so the user cannot satisfy that message and is stuck. The user decided the per-endpoint default is not needed as long as a valid GLOBAL default endpoint + model exists; the global default (config.toml `[general] default_provider`/`default_model`, and the trivial tier) must STAY.

DECISION (taken by the lead from the user's words, not up for redesign): when the model being removed from the hosting endpoint equals `default_model`, do not refuse. Re-point `default_model` to the first remaining model id of the saved endpoint (`endpoint.models.first()`), so `default_provider` + `default_model` remain a valid pair. If the saved endpoint has no models left, set `default_model = None` and let the existing `validate_endpoint_set` call return its existing "has no models" error (do not change that function). Renames keep working exactly as now (`rename.get(&dm)` runs first). Do NOT touch `src/config/patch.rs`, `src/headless/setup.rs` (its two other validate_endpoint_set callers), `endpoint_usage`, the tier-ladder checks (the trivial tier must still keep a model, see `removing_the_last_trivial_model_is_refused_without_writing`), or any frontend file.

WHERE: the new `default_model` value must reach the same place the current value does: look at how `default_model` flows from line ~433 into the later `validate_endpoint_set(... default_model ...)` call at ~454 and the config write further down in `upsert_endpoint_detail`; make sure the re-pointed value is the one persisted to config.toml. Verify by reading the save code below line 484 before editing.

TEST (regression): in the `tests` module of the same file replace `default_model_removal_is_refused` with `default_model_removal_repoints_the_global_default`: using BASE (endpoint `a` has models m1 and m2, config default_provider "a", default_model "m1"), remove m1 from `a`, call `upsert_endpoint_detail(dto, None)`, assert Ok, reload `Config::load(dir.path())` and assert `default_provider == Some("a")` and `default_model == Some("m2")`. The old test fails without the fix would be refused; the new one fails without the fix because the call returns Err. Check first whether BASE tiers still reference a/m1 in a way that makes the save fail for the tier reason; if so the existing code drops removed models from tiers (see `upsert_preserves_pricing_and_drops_removed_model_from_tiers`), and only the trivial tier is protected (it holds a/m2 in BASE). Add `removing_the_only_model_of_the_default_endpoint_still_errors`: endpoint with a single model that is the default, remove it, assert Err and that config.toml is unchanged.

VERIFY: `cargo test -p mnemo --lib headless::setup` then `cargo clippy -p mnemo --all-targets -- -D warnings` (crate roots use #![deny(warnings)]; never add #[allow]). On Windows read $LASTEXITCODE from an unpiped command.
