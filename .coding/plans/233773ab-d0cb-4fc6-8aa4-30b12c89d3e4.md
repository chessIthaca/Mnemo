# Plan: Fix git_read stuck-running card (memory entry steals tool_result) + info chips

## Goal
Fix result routing so every tool card completes (correlate memory-entry finalization with tool_call_id), and make git_read + memory_search cards informative: git_read shows its op (diff/log/show + commit/path/limit) as a header chip; memory_search shows the query it searched (parsed from args) plus matched count.

## Kind
bug_fixing

## Context
Research + fix complete. Root cause confirmed in agentEventReducer.ts reduceToolResult: memory-finalization loop matched ANY running memory entry on ANY tool_result (no tool_call_id correlation — memory entries stored no call id) and its memoryFinalized flag skipped the tool-card loop, so a foreign parallel tool's card (git_read) never received its result. Fix: memory entries carry id/index/args (stamped at tool_call_start; arg deltas accumulate by index); finalization gated on entry.id === event.tool_call_id; parseMemoryEntry returns matched count (header regex with optional colon — zero-match output "no memories matched" has none). UX: git_read op chip via argLabel branch (log -N -- path / show <7-char commit> / diff path) + argPaths label-tool exclusion; memory_search query chip via memorySearchLabel(entry.args) + "N matched" count in MemoryEntryCard.
