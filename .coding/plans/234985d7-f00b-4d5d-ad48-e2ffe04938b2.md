# Plan: Backlog: gate Done on plan-loop closure + user reset of done tasks

## Goal
A backlog item may be marked Done ONLY when the main agent's workflow state is Complete at turn resolution (finish called / research plan auto-completed) — mandatory on every dispatch path (run-all, auto-feed, single ▶). Anything else (Executing/Reviewing/Skill/Planning at turn end) fails the item: run-all rolls back to its checkpoint and marks CantResolve; single/auto-feed marks Failed. If the workflow state can't be verified, run-all marks CantResolve WITHOUT rollback and halts the run. Plus: a user-facing way to reset tasks marked done (re-queue to Pending), and removal of the now-obsolete opt-in run_all_strict_success config flag.

## Kind
implementation

## Context
User report: "the backlog autorun must wait for the cycle to finish — a task can not be marked as done until the full loop closed (planning, executing, reviewing); only once finish on its plan is called can it be marked as done and the next task start. There is no other way. Also, we need a way for me to reset tasks you mark as done." Evidence of the bug: git log showed "backlog: #50/#51" commits touching only .coding/backlog.json (items marked done) BEFORE the actual work happened in a later session. Current code: src-tauri/src/ipc/run_all.rs on_main_turn_resolved marks Done on success with only an opt-in strict gate (run_all_strict_success, default false, allows Complete|Planning); single-dispatch/auto-feed path has no gate. src/backlog.rs BacklogStore has set_status; backlog_retry IPC (backlog_cmds.rs:141) re-queues any status but UI (BacklogView.tsx:423 canRetry) only shows it for failed/cant_resolve. WorkflowState (src/workflow/mod.rs:22): Planning/Executing/Reviewing/Complete/Skill; Complete persists to turn end (resting state) and requires finish for implementation plans. run_all_strict_success lives in src/config/general.rs:99 (+Default at :208, tests at :636-659); no deny_unknown_fields in src/config so removing the field is config-backward-compatible. RUN_ALL_STEER at run_all.rs:62 should tell the agent the item only counts as done after finish.
