# Plan: Graph tab says when the index is rebuilding and refreshes when it ends

## Goal
While a code-index pass runs, the Graph tab clearly says results may be incomplete and shows progress, and when the pass ends it reloads the overview, search results and the selected symbol so nothing stays stale or missing.

## Kind
implementation

## Context
Why: the user opened the Graph tab right after a rebuild and found no graph for a method; it "started indexing and refreshing. A minute later it had all the info." The cause was a one-time full re-index (the code graph's EXTRACTOR_VERSION bump forces every file to be re-parsed once; that pass ran ~10 minutes on a 270 MB index), during which files are replaced one at a time so some symbols are briefly missing. Normal startup passes are incremental and short, but any long pass (first run, version bump, big checkout) has the same window.

Verified facts:
- verified: `mnemo2/src/components/GraphView.svelte` already polls `graph_status` while `status.indexing` is true (the `$effect` around line 443, `INDEX_POLL_MS`) and shows a small "Indexing…" pulse in the status line (line ~708) and a spinning Refresh icon; nothing says results may be incomplete, and the overview, search results and selected neighbourhood are not reloaded when the pass ends.
- verified: `CodegraphStatus` (`src/headless/codegraph_api.rs` line 24) has `available`, `indexing`, `files`, `symbols`, `edges` and an indexed-at time.
- verified: the app already tracks the startup passes with progress: `IndexingSnapshot` in `mnemo2/src/lib/indexingEngine.ts` (`code: IndexPass | null` with `state` running/done/failed, `done`, `total`, `detail`), kept in `$app.indexing` (`mnemo2/src/lib/types.ts` line ~628) from the `mnemo2://indexing` event; `IndexingStatus.svelte` and `FirstIndexOverlay.svelte` already render it.

Decisions:
- When `status.indexing` is true (or `$app.indexing.code.state === "running"`), show a notice bar at the top of the canvas and above the left list: "Rebuilding the code index — results may be incomplete" plus "<done>/<total> files" when a total is known (from `$app.indexing.code`), else a symbol count from the polled status. Use theme tokens only (the app has a dark theme; components must not use literal colours).
- When indexing turns from true to false: reload the overview (or the current module drill-in), re-run the current search, and re-fetch the selected symbol's neighbourhood/context/impact; if the selected symbol no longer exists, keep the panel with a short "this symbol moved or was removed" note instead of an error.
- An error from a neighbourhood/context call while indexing is shown as "not indexed yet — retrying when the index is ready" and retried once on completion, not as the hard unknown-symbol error.
- Frontend only: `mnemo2/src/components/GraphView.svelte` (+ `GraphView.test.ts`) and, if needed, `mnemo2/src/lib/graph.ts`. Extend the existing `graph` preview scene in place with an indexing-in-progress state (seeded status with `indexing: true` and a code pass at e.g. 1200/2400).

Verification: in `mnemo2/`: `npx svelte-check --tsconfig ./tsconfig.json`, `npm run check:no-mock`, `npx vitest run` (tests: the notice appears with progress while indexing; overview/search/selection reload once when indexing ends; an error during indexing shows the soft note and retries). Never start a dev server or any command that does not exit on its own.

## Acceptance scenarios
- While the code index is rebuilding, the Graph tab shows 'Rebuilding the code index — results may be incomplete' with file progress.
- When the pass ends, the overview, the current search and the selected symbol reload without the user pressing Refresh.
- Opening a symbol that is not indexed yet shows a soft 'not indexed yet' note and retries when the index is ready, instead of the unknown-symbol error.
