## Bug
request_stats.ttft_ms is 0 on 99.2% of rows (28,267/28,506 — .coding/analysis/cache-hit-5-aggregates.txt) — the first-token metric is dead, so the "fastest agent" goal has no TTFT signal and the trace graph's Waiting bucket (connect_ms) silently absorbs the server prefill/queue wait. Root cause: the ttft anchor `request_start` is stamped when the POST response HEADERS arrive (src/provider/openai.rs spawn_stream :761, comment :756-760; src/provider/anthropic.rs :1344-1345) — LiteLLM and the direct providers only begin the HTTP response when the first token is ready, so headers and the first SSE chunk arrive in the same burst and the measured window (headers→first chunk, src/provider/openai/stream.rs :291-294 and the anthropic Usage arm :1565-1574) is structurally ~0ms.
