# Plan: Live token + trace updates during reasoning

## Goal
Live token/trace updates during reasoning streams: the toolbar's live token estimate climbs while reasoning deltas stream (not just answer deltas), and the trace's in-flight record shows streaming (estimated) reasoning/completion token usage that the final authoritative usage overwrites at stream end.

## Kind
implementation

## Context
Backlog b5503915 ("while reasoning the token toolbar and trace don't update... update them live even during reasoning"). Recon: (1) Toolbar — the frontend reducer keeps a live token estimate `liveTokens` (chars/4) incremented ONLY in the TextDelta arm (agentEventReducer.ts:272) and tool-arg arm (:312); the ReasoningDelta arm does NOT increment it, so during reasoning the live count freezes. reduceUsage (agentEventReducer.ts:744-790) resets liveTokens to 0 when the real AgentEvent::Usage arrives (:789) and accumulates sessionTiming ONLY for timed events (ttft/gen non-null), so a reasoning-delta estimate touches no stats. (2) Trace — the store already appends raw SSE chunks live (openai.rs:928-931, anthropic.rs:1030 via LlmRequestLog::append_response, trace.rs:538) and LlmTraceView polls list+detail every 1.5s while records are non-terminal (shouldStopPolling, LlmTraceView.tsx:110 — stops only when is_complete), so the raw response grows live — but usage/finish in the record are set ONLY at stream end (trace.rs:457 set_usage called from the providers' completion path), so the trace shows zero live token progress during a long reasoning phase. TokenAccountant-style BPE counting exists for contexts, but chars/4 is the established estimate convention in the FE. LlmUsage struct: {prompt, completion, reasoning, cached} (trace.rs:91). RequestStats to memory.db are recorded separately in the turn loop on the final LlmEvent::Usage only — estimate pushes must NOT touch that path.
