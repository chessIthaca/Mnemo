1. Boundary guard (tests/boundary.rs, `tauri_uses_only_public_api`): src-tauri production code may only use `mnemo::headless::*`, `mnemo::app::*` and crate-root re-exports. Mnemo2 code imports `mnemo::agent::...` directly in: src-tauri/src/bin/mnemo2_route_eval.rs:28 (route_question::OfferedLabels), src-tauri/src/ipc/finetune.rs:49 (failure_triage::training_log_dir), src-tauri/src/mnemo2/dispatch_routing.rs:40-42 (failure_triage::training_log_dir, route_knn::RouteKnn, route_question), src-tauri/src/mnemo2/laya_settings.rs:63-64 (RouteKnn, OfferedLabels), src-tauri/src/mnemo2/route_eval.rs:25-27 (training_log_dir, RouteKnn, route_question::{self, OfferedLabels}), src-tauri/src/mnemo2/team.rs:24, 33, 34 (route_question, failure_triage_knn::EmbedderGetter, RouteKnn) and team.rs:1294, 1398, 2128, 7947, 8402 (`mnemo::agent::model_routing::append_row(...)` call paths). Fix: add crate-root re-exports in src/lib.rs next to the existing `pub use crate::agent::...` lines: `pub use crate::agent::failure_triage::training_log_dir;`, `pub use crate::agent::failure_triage_knn::EmbedderGetter;`, `pub use crate::agent::route_knn::RouteKnn;`, `pub use crate::agent::route_question::{self, OfferedLabels};` (module re-export as `mnemo::route_question`), `pub use crate::agent::model_routing;` (module re-export), then rewrite every listed src-tauri line to the root path (`mnemo::training_log_dir`, `mnemo::RouteKnn`, `mnemo::route_question`, `mnemo::OfferedLabels`, `mnemo::EmbedderGetter`, `mnemo::model_routing::append_row`). If a name collides with an existing root export, pick the next-best unambiguous root name and say so. Run the guard: `cargo test --test boundary`.
2. macOS 503 reset: src-tauri/src/mnemo2/mcp_server.rs `reject_busy` (~line 493) writes the 503 and drops the stream without reading the request the client already sent. On macOS (BSD sockets) closing a socket with unread received data sends RST, so the client's read fails with ConnectionReset before it sees the 503. Fix (production): after writing the response, `stream.shutdown().await` (AsyncWriteExt) and then drain the read side until EOF or 500 ms (`tokio::time::timeout(Duration::from_millis(500), async { let mut buf = [0u8; 1024]; loop { match stream.read(&mut buf).await { Ok(0) | Err(_) => break, Ok(_) => {} } } })`), ignoring errors. Keep the existing 2 s write timeout.
3. Audit merge order: src-tauri/src/mnemo2/team.rs `merge_locked` (~line 5979) checks lead busy, worker busy, lead branch == main and a clean lead checkout BEFORE it loads the worker and refuses `kind == "audit"`. On a slow runner the audit worker is still busy (or the temp repo's branch differs), so a different refusal comes back. An audit worker is never mergeable whatever its state, so: load the worker record first (`self.worker(worker_id).await?`) and return the audit refusal before every other check; keep all other checks and their order unchanged after it. Also make the runtime.rs assertion (~line 6387) print the actual error (`"the audit merge refusal names the reviewer: {err}"`).

Regression tests: `tauri_uses_only_public_api` (tests/boundary.rs) is the guard for 1; `connections_over_the_cap_get_a_503_and_the_slots_come_back` for 2 (macOS-only failure; Windows cannot reproduce it); `high_risk_dispatch_and_review_require_substantive_evidence` for 3, plus a new unit test in team.rs tests `audit_merge_is_refused_even_while_the_audit_is_busy` if a busy worker can be simulated with the existing fixtures (otherwise say why not).
