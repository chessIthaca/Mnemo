# Plan: Never truncate git diff output (cap exception for the git tool's diff subcommand)

## Goal
Make the git tool's `diff` subcommand output never truncated — the user-mandated exception to the 100 KiB tool-output cap must apply to `git diff` too, mirroring the standalone git_diff tool.

## Kind
implementation

## Context
Backlog item: "git diff can't be truncated. please fix that. That has to be an exception." Exploration: the standalone `git_diff` tool (src/tool/agent/git_diff.rs) ALREADY implements the exception — module doc declares it, execute() skips cap_tool_output, regression test large_diff_is_not_truncated proves >100 KiB diffs arrive complete. The GAP is the `git` tool's `diff` subcommand: GitTool::run_git (src/tool/agent/git.rs:90-144) pipes EVERY subcommand through cap_tool_output (:131, 100 KiB cap in src/tool/agent/mod.rs:58-66 with "truncated: output exceeded size limit" marker), so `git diff` (including `git diff` with forwarded read args, added on fix/git-tool-read-args) can be truncated. Fix: the diff arm must skip the cap — run_git gains a cap flag (or an uncapped variant); all other subcommands keep the cap. Note the existing regression-test style to mirror (git_diff.rs:241-300 large_diff_is_not_truncated builds a ~550 KB diff via a 30k-line file rewrite).
