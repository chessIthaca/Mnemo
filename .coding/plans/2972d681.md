## Bug
On the native Anthropic path, cache activity is invisible — traces/usage always show cached_tokens: 0, and prompt_tokens under-reports the true context by the cached prefix (~5-10K tokens once the system+tools breakpoints are cached). Same class on the Responses API path (cached_tokens hardcoded 0 at src/provider/openai/sse.rs:104). Root cause: message_start.usage (src/provider/anthropic.rs:633) carries input_tokens, cache_read_input_tokens, cache_creation_input_tokens — we parse only input_tokens, which per Anthropic semantics EXCLUDES cached tokens; the Usage event (anthropic.rs:772) hardcodes cached_tokens: 0. The OpenAI chat path's prompt_tokens INCLUDES cached tokens, so the two paths feed different meanings into the same accounting (request_stats, trace usage, token counters).
