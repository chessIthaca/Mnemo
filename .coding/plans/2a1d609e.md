# Plan: Start Mnemo in a new folder from Claude Code, without reloading

## Goal
A Claude Code session started in a folder that is not a Mnemo project can list the registered projects and turn its folder into a Mnemo project; the team tools then appear in the same session without reloading the MCP server. A folder registered meanwhile through the Mnemo2 window is picked up the same way.

## Kind
implementation

## Context
WHY: the user (2026-11-16) tried to start a factory-game project from Claude Code and it failed until the MCP server was reloaded. The design stays one Mnemo2 per project folder and one Claude session per project (Claude Desktop runs several sessions side by side, each in its own folder); no session leads several projects.
HOW IT WORKS TODAY: src-tauri/mnemo2-app/src/mnemo2_mcp/serve.rs is the stdio bridge Claude Code starts in the session folder. Bridge::finish_resolve calls instance::resolve(env, cwd); Resolution::Unregistered becomes Target::Stub and is cached in Slot.target for the whole session. stub_answer (around line 589) answers initialize, ping and tools/list (empty) and refuses everything else with "Mnemo is inactive here…". instance.rs: registered_root reads projects.toml via mnemo_app::mnemo2::project::list; resolve starts `mnemo2 --hidden --project <root>` through start_instance when the folder is registered. Mnemo2 seeds .coding when it opens the project. mnemo_app::mnemo2::project::add(config_dir, folder) registers a folder (canonical path, derived name, -2 suffix on a name clash; an already-registered path is kept). The bridge already sends LIST_CHANGED (`notifications/tools/list_changed`) after a slow start.
EVIDENCE OF THE BUG: ~/.mnemo/projects.toml has both "Factory Game" (C:\Factory Game, a full project) and "FactoryGame" (C:\FactoryGame, only .git, never opened).
RULES:
- Outside a project, tools/list offers exactly two tools: `mnemo_projects` (no arguments; returns each registered project's name, path, whether a Mnemo2 is running for it, and whether the folder has .coding) and `mnemo_init_project` ({path?: string, defaulting to the session folder}).
- mnemo_init_project: the folder must exist. Refuse when the folder or a parent/child of it is already registered (name the existing entry and say to start the session there); refuse a folder that is not a git repository with a message saying to run `git init` first (no automatic git init). Otherwise register it with project::add, start its Mnemo2 through the same path resolve uses, switch the bridge's cached target to Live, send LIST_CHANGED, and return the project name, path and "team tools are now available in this session". A start failure leaves the folder registered and returns the start error.
- Re-check: while the target is Stub, every tools/list and tools/call first re-runs the registry check (cheap, no spawn when still unregistered); if the folder is now registered, resolve to Live, answer from the instance, and send LIST_CHANGED. A stub never needs a reload.
- Tool texts (descriptions, results, errors) are prompts read by Claude: plain, short, and they tell Claude what to do next. The lead refines them in review.
- Nothing changes inside a registered project.
TESTS (serve_tests.rs, instance_tests.rs, with the existing fakes): `stub_lists_the_project_tools`, `init_registers_and_goes_live_without_reload` (asserts LIST_CHANGED and that a later tools/call reaches the instance), `init_refuses_a_registered_or_nested_folder`, `init_refuses_a_folder_without_git`, `stub_picks_up_a_project_registered_meanwhile`, `projects_lists_running_and_initialized_state`.
VERIFY: `cargo test -p mnemo2-app --bin mnemo2-mcp` (or the target the existing serve/instance tests run under; check Cargo), `cargo clippy -p mnemo2-app --all-targets`, `git diff --check`.

## Acceptance scenarios
- A Claude Code session started in an unregistered git folder calls mnemo_init_project and, in the same session, gets the team tools (tools/list_changed sent; a following team_status call answers).
- mnemo_init_project in C:\FactoryGame while 'Factory Game' and 'FactoryGame' are registered refuses and names the existing registration.
- A session started in a folder that is registered later through the Mnemo2 window gets the team tools on its next tool call without a reload.
