# Plan: Token/sec + per-session/project stats + pricing + cache estimation

## Goal
Token-per-second measurement (input + output), per-session + per-project stats stored in .coding SQLite, a Stats tab (session + project views), per-model pricing in endpoints.toml for cost estimation, and cached-token estimation (API value + client heuristic).

## Context
ASSUMPTIONS (correct me if wrong):
1. Input tok/sec = prompt_tokens / TTFT (POST→first token). Output tok/sec = completion_tokens / (first→last token). Measured in the OpenAiClient stream loop.
2. Cache: parse BOTH the API's prompt_tokens_details.cached_tokens (truth, when available) AND compute a client-side heuristic (shared-prefix token overlap between consecutive requests in the same session). Store the API value when present; fall back to the heuristic for cost estimation when the API doesn't report it.
3. DB: add a `request_stats` table to the existing .coding/memory.db (sessions table is already there).
4. Pricing: a [[pricing]] table in endpoints.toml keyed by model name, $ per 1M tokens (input/output/cached).
5. Stats tab: per-session + project-total, broken down by token kind (input/output/reasoning/cached) AND per model. Project view shows cumulative totals + a simple per-day breakdown.

EXISTING WIRING:
- LlmEvent::Usage (src/provider/mod.rs:268) carries prompt/completion/reasoning tokens; parsed in openai.rs:476. No cached_tokens parsed. No timing.
- The stream loop (openai.rs:177-230) spawns a task reading SSE chunks — the place to measure TTFT (first chunk arrival) and generation time (first→last).
- AgentEvent::Usage (runtime/channels.rs:80) forwards to the UI; useAgentStore accumulates per-turn (resets on Started).
- AgentTask (runtime/agent.rs:109) starts a memory session on first prompt; session_id is threaded into run_turn for working-memory tagging.
- MemoryStore (.coding/memory.db) has sessions table (schema.rs:35). MemoryStoreTrait (memory/mod.rs:37) is the abstraction.
- Project (project/mod.rs:48) gives .coding/memory_db path.
- InflightBar (frontend/src/components/chat/InflightBar.tsx) shows per-turn tokens — the "session as seen on the status bar".
- RightPanel (frontend/src/components/layout/RightPanel.tsx) has 6 tabs; a Stats tab slots in as the 7th.
- Endpoint config (config/endpoints.rs) has models: Vec<String>; pricing needs a per-model map.
- set_model (ipc/commands.rs) rebuilds the provider; the model name is known there.

DESIGN:
- Provider: extend LlmEvent::Usage with ttft_ms, generation_ms, cached_tokens. Instrument the stream loop with Instant timestamps. Parse prompt_tokens_details.cached_tokens.
- Agent loop: on Usage, record a stats row (session_id, model, prompt/completion/reasoning/cached tokens, ttft/generation ms, timestamp) to the memory store via a new MemoryStoreTrait method record_request_stats. Also compute the cache heuristic (prefix overlap with last request in the session).
- Memory store: new request_stats table (id, session_id, model, prompt_tokens, completion_tokens, reasoning_tokens, cached_tokens, ttft_ms, generation_ms, created_at). New trait methods: record_request_stats, session_stats, project_stats, session_list.
- Config: [[pricing]] table in endpoints.toml → PricingEntry { model, input_per_1m, output_per_1m, cached_per_1m }. Config::pricing_for(model) lookup.
- IPC: get_session_stats(agent_id), get_project_stats(). The session_id comes from the agent's AgentTask (need a handle).
- Frontend: new Stats view (session card + project card), RightPanel tab, tauri.ts wrappers, store state.
- InflightBar: add tok/sec display (computed from the latest Usage event's timing).
