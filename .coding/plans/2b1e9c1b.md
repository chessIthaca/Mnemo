# Plan: Mnemo2 guards: boundary scan covers mnemo2-app, IPC command cross-check, spec Purpose texts

## Goal
Close three small enforcement gaps from the Mnemo2 architecture review: the G10 kernel-boundary test also scans the mnemo2-app crate (and tolerates test-only files, which the test-file moves of the team.rs/runtime.rs splits need), a Rust test proves every frontend invoke string is a registered Tauri command, and the two specs with an empty Purpose get one.

## Kind
implementation

## Context
Why: the Mnemo2 architecture review (findings ARCH-2, ARCH-5, ARCH-7) was verified against the current tree (wt/mnemo at ba6c266f; the review cites 3fe4f52, which exists and is an ancestor; the files in scope are unchanged since). What holds and what changed:
- ARCH-2 holds: tests/boundary.rs `tauri_uses_only_public_api` walks only `src-tauri/src` (`app_sources(Path::new("src-tauri/src"), ...)`); the separate crate `src-tauri/mnemo2-app` (src/ and examples/mnemo2_route_eval.rs) imports the kernel directly and is not scanned. NEW interplay found while verifying: the moved-out tests of the coming team.rs / runtime.rs splits (`src-tauri/src/mnemo2/team/tests.rs`, `runtime/tests.rs`) are plain files, so the scanner would read them as production code, and team.rs's tests contain `mnemo::agent::policy::...` and `mnemo::agent::route_question::...` (about 25 lines). Today those lines are exempt only because the scanner strips the inline `#[cfg(test)] mod tests { }`. So this plan's step 1 must land (and merge) BEFORE the test-file moves; it makes the scanner skip test-only files (`tests.rs`, `*_tests.rs`, `testutil.rs`), the same naming the mnemo2-app crate already uses (`hooks_tests.rs`, `serve_tests.rs`, `instance_tests.rs`, `permissions_tests.rs`, declared `#[cfg(test)] #[path = "..."] mod tests;`, and `testutil.rs`).
- ARCH-5 holds: one flat `tauri::generate_handler![ ... ]` list in `src-tauri/src/mnemo2/mod.rs` (starts at line 546, 139 entries, written as `module::command` or a bare `mnemo2_host_ping`), and the frontend calls commands by string in `mnemo2/src/lib/*.ts` (24 non-test files) plus one component, `mnemo2/src/components/WorkerPlanTab.svelte` (`invoke<string | null>("read_capability_spec", ...)`), so the scan must cover every non-test .ts/.svelte under `mnemo2/src`, not only lib/. Call shapes seen: `bindings.invoke<T>("name", {...})`, `invoke<T>("name")`, `invoke("name", {...})`, and calls whose string sits on the next line after `invoke<void>(`. `mod.rs` starts with `#![deny(warnings)]`, so unused code in a test there is a compile error.
- ARCH-6 is DROPPED, not planned: the premise is wrong. serve.rs:30 (`use mnemo_app::mnemo2::mcp_server::lead_instructions;`) is one of four imports the helper takes from the app crate (`mnemo_app::mnemo2::project::list` in src-tauri/mnemo2-app/src/mnemo2_mcp/instance.rs:470, `mnemo_app::instance_marker::pid_alive` in instance.rs:752 and quit.rs:114), and the helper is a `[[bin]]` of the same Cargo package as the app (`mnemo2-app`, whose `[dependencies]` hold `mnemo-app`), so building it compiles the app crate whatever serve.rs imports. Moving one constant would change nothing, and the kernel crate is the wrong home for Mnemo2-specific lead text. Decoupling the helper would be a separate, larger design (project registry + instance marker too); not part of this plan.
- ARCH-7 holds, and the same defect exists in a second spec the review missed: `.coding/openspec/specs/plan-board/spec.md` AND `.coding/openspec/specs/llm-trace/spec.md` both have an empty `## Purpose`.
Verification commands (run from the worker's checkout root, which is the repository root): `cargo test --test boundary`; `cargo clippy --test boundary -- -D warnings`; `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::tests`; `cargo clippy -p mnemo-app --features mnemo2 --all-targets -- -D warnings -A clippy::redundant_guards -A clippy::nonminimal_bool`; `git diff --check`. The repo is NOT rustfmt-clean: never run cargo fmt or rustfmt on whole files; format only the lines you add, in the surrounding style. Windows shell: use `git -C` and `--manifest-path`, never leave a shell inside another worker's checkout. Do not edit any file a step does not name.
