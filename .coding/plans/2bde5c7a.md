# Plan: backlog_add: optional position parameter — top or end, default end

## Goal
Add an optional `position` parameter ("top" | "end", default/absent = "end") to the backlog_add agent tool and, for symmetry, the IPC backlog_add command, so an urgent item can be queued at the FRONT of the dispatch order (backlog 06a31736: the run-all stall item e33a07fd had to be manually sent to top via the UI because the agent tool could only append). Absent position appends byte-identically to today — every existing caller unchanged. Store-level: BacklogPosition enum + BacklogStore::add_at (insert-at-0 for Top). Union-merge safety verified and pinned by tests: a top-insert prepends one line (minimal diff, merges cleanly with concurrent appends) and parse_jsonl's first-occurrence dedup guarantees no loss/duplication in the union driver's worst case. The headline+body shape contract and detail bar stay enforced unchanged on both paths.

implementation

## Context
Backlog item 06a31736 (run-all batch, unattended). Exploration findings: BacklogStore::add (src/backlog.rs:460) appends via items.push — ~60 existing call sites (tests + the two production write paths). The agent tool (src/tool/workflow/backlog.rs: BacklogAddArgs{text}, schema at :111, execute at :155 → normalize_item_text → store.add(text, Vec::new())) and the IPC command (src-tauri/src/ipc/backlog_cmds.rs:159 → normalize_new_item_text(&text,&images) → store.add(text, images)) are the two sanctioned write paths; frontend helper tauri.ts:1562 backlogAdd invokes with {text, images} only (an optional Rust param is omitted → None → End, no frontend change). MERGE SAFETY (the task's NOTE, verified): .gitattributes pins .coding/backlog.jsonl merge=union; parse_jsonl (src/backlog.rs:1111) collapses same-id lines with FIRST occurrence winning. A store-level insert-at-0 + persist prepends one line — a minimal diff that merges cleanly with a concurrent append (non-overlapping hunks, union driver not even invoked); worst-case union concatenation dedups by first occurrence → no loss/duplication (same guarantee the existing UI send-to-top reorder rides). Decision: implement as store-level insert-at-0 (NOT append-then-reorder — the persisted file is identical, so append-then-reorder has no merge advantage) and pin the property with a union-merge simulation test. Decision: give the IPC command the optional param too (task suggests symmetry; both write paths symmetric is the codebase's established pattern). Decision: position is Option<BacklogPosition> + unwrap_or(End) so an explicit null is also tolerated. No UI change (composer has send-to-top; no vitest needed).
