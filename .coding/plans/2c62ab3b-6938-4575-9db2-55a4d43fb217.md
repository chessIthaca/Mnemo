# Plan: Abstract vision model behind a trait; mock it in tests

## Goal
Remove all live-network access from the always-run test suite by abstracting the vision model behind an `ImageDescriber` trait (mirroring how `LlmClient` abstracts the main model), then swapping every vision-touching test to a mock. No test should construct an unreachable-URL client or attempt a real connection.

## Context
The vision fallback + describe_image tool (just landed) hold `Arc<VisionClient>` concretely. The test `non_multimodal_with_vision_injects_image_description_text` (src/runtime/agent.rs) points a real VisionClient at http://localhost:1/v1/ and awaits a real connect failure — slow (~2.5s), timing-dependent, and a network syscall in the regular suite. The live provider tests in tests/provider_integration.rs are already #[ignore]d; unit tests should follow the same rule via mocks. Plan: add an `ImageDescriber` trait in src/provider/vision.rs (async describe_image, object-safe via async_trait) implemented by VisionClient; change AgentLoop (src/agent/mod.rs), AgentLoopFactory (src/agent/factory.rs), DescribeImageTool + shared helpers (src/tool/agent/describe_image.rs), and src-tauri/src/main.rs construction to `Arc<dyn ImageDescriber>`; then rewrite tests with mock describers — which also unlocks a real success-path test for the tool's execute (currently untestable without HTTP).
