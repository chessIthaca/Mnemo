# Plan: Descriptive ToolCard headers for read_files + search

## Goal
Make the ToolCard header for read_files and search/search_read more descriptive by extracting their meaningful args in argLabel (frontend/src/components/chat/Message.tsx): read_files shows the basenames of the files array; search/search_read show the pattern (+ glob).

## Context
The ToolCard header in Message.tsx calls argLabel(args, toolName) to build a parenthetical label. argLabel handles shell/spawn_agent/skill_start/git + a common path/file field, but NOT:
- read_files: args = {files: [{path, start_line?, max_lines?}, ...]} — an array, so the common path/file lookup misses. Header is bare "▶ read_files".
- search / search_read: args = {pattern, glob?, literal?, max_files?} — no path/file. Header is bare "▶ search".

The existing label format is `displayName (label)` e.g. "git (status)", "Spawn Agent (reviewer)". We extend argLabel with two more toolName branches:
- read_files: parse files[], map each spec's path to its basename, join ", ". Cap at ~3 names + "+N" to avoid overflow. Returns "mod.rs, agent.rs".
- search / search_read: show the pattern (quoted) + optional glob. Returns "\"WorkflowState\"" or "\"WorkflowState\" in **/*.rs".

No Rust changes; no new tools. Pure frontend argLabel extension. Tests: there are no existing frontend unit tests for argLabel (it's an unexported function), so verify via tsc + vite build, and manually reason about the output.

## Steps
- [x] 1. **Extend argLabel for read_files** — in frontend/src/components/chat/Message.tsx, add a `toolName === "read_files"` branch to argLabel (before the common path/file fallback): parse `parsed.files` as an array, for each element read `path` (string), map to basename (split on '/' after replacing '\'), collect non-empty, join with ", ". Cap the list at 3 names and append "+N" if there are more (e.g. "mod.rs, agent.rs, tests.rs +2"). Return null if files is missing/empty/not an array.
- [x] 2. **Extend argLabel for search + search_read** — in the same argLabel function, add a `toolName === "search" || toolName === "search_read"` branch: read `parsed.pattern` (string); if present, build a label `"<pattern>"` (quoted); if `parsed.glob` is also a non-empty string, append ` in <glob>`. Return null if pattern is missing/empty.
- [x] 3. **Build + typecheck** — run `npx tsc --noEmit` (or the project's build) from the frontend dir to confirm no type errors, then `npm run build` (vite) to confirm it bundles. Fix any errors.
