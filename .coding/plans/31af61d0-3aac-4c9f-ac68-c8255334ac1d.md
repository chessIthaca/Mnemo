## Goal

## Context
User report (backlog, unattended): "the default color scheme is pretty good. The others are terrible and unreadable. Review and find a better color scheme for light and default." Same branch as previous tasks (fix/compact-bugs).

Findings from exploration:
- Theme system: frontend/src/hooks/appearance.ts Theme = dark|light|system, applyTheme toggles `.light` on <html>; tokens in frontend/src/styles/globals.css — :root dark block (lines 10-33) and html.light block (35-44). No preset schemes beyond dark/light/system, so "the others" = the light theme.
- Core defect: html.light does NOT override --accent-color, so cyan-400 #22d3ee (≈1.9:1 on white) drives accent text/links/buttons in light mode — unreadable. Also --text-muted #64748b is only ~4.6:1 (borderline); accent-filled buttons pair white text with the bright accent (white on #22d3ee ≈ 1.7:1) in BOTH themes; .agent-running-dot glow is hardcoded rgba(34,211,238) (washed out in light). Light code highlighting (github-light subset) and inline-code pink are already contrast-tuned — leave them.
- Dark theme is contrast-solid (text 15.6:1, muted 7.2:1, accent-on-bg 10.6:1) — user calls it "pretty good", so keep its tokens unchanged; the only dark-side change is the shared accent-button text fix.
- User-customizable colors (appearance.ts DEFAULT_* + AppearanceSection reset) mirror the dark tokens — since dark tokens don't change, no sync needed there.
- No existing contrast test; ChatSection.test.ts shows the `?raw` import pattern for asserting on source files.
