# Plan: Suppress console windows + real-time plan window updates

## Goal
1. Suppress console window pop-ups when spawning shell/git processes on Windows (CREATE_NO_WINDOW flag). 2. Make the plan window update in real time when the agent creates a plan or completes a step, by emitting workflow events from the agent loop and having the frontend react to them.

## Context
Two issues:

1. SHELL WINDOW POP-UP: The shell tool (src/tool/agent/shell.rs), git tool (src/tool/agent/git.rs), and get_git_branch command (src-tauri/src/ipc/commands.rs) spawn processes without CREATE_NO_WINDOW. On Windows with windows_subsystem="windows", this causes a console window to flash/pop up. Fix: set creation_flags(0x08000000) on all Command spawns, guarded by #[cfg(windows)].

2. PLAN WINDOW NOT UPDATING: The AgentEvent::WorkflowStateChanged and AgentEvent::StepCompleted variants exist in src/runtime/channels.rs but are never emitted by anyone. The workflow tools (create_plan, complete_step in src/tool/workflow/plan.rs) modify the Workflow mutex directly but don't notify the agent loop. The PlanProgress component (frontend/src/components/views/PlanProgress.tsx) polls getWorkflowState() every 2s, but the store's step_completed handler is a no-op and workflow_state_changed only updates the state string (not the plan data). The user wants real-time updates.

Fix approach:
- Rust: In AgentLoop::run_turn (src/agent/mod.rs), after a create_plan or complete_step tool call succeeds, emit WorkflowStateChanged (and StepCompleted for complete_step) via fanin_tx. The agent loop has self.workflow (Arc<Mutex<Workflow>>) and fanin_tx.
- Frontend store: Add a planVersion counter that increments on workflow_state_changed and step_completed events, so PlanProgress can reactively re-fetch.
- Frontend PlanProgress: Subscribe to planVersion from the store and re-fetch when it changes (in addition to the 2s polling fallback).

The agent loop already has the tool name (tc.name) and can check the workflow state after the call.
