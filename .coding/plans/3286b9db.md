# Plan: One-command rebuild: Mnemo2 quits on request and the helper does not restart it mid-build

## Goal
`npm run rebuild:mnemo2` asks every running Mnemo2 to quit cleanly (Laya included), keeps the mnemo2-mcp helper from auto-starting Mnemo2 while the build runs, builds and installs, and fails with a clear error when a quit is refused or does not finish — no process kills needed.

## Kind
implementation

## Context
\## Why
Every rebuild of Mnemo2 (`npm run build:mnemo2:native`) fails with "Access is denied" on target/release/mnemo2.exe while any Mnemo2 runs. Closing the window only hides it to the tray, and the moment any Claude Code Mnemo tool call or hook runs, the mnemo2-mcp helper auto-starts a hidden Mnemo2 (`instance.rs` `start_instance` ~436 → `spawn_locked` → `spawn_app` ~895: `mnemo2 --hidden --project <root>`). So the user had to approve a force-kill each time, which in old builds also orphaned laya-serve trees (since fixed by the job object, plan d21bb4c0). The user's decision: a proper quit request plus a short-lived "rebuilding" marker; and **if the quit fails (refused, unreachable, wrong build, or the process does not exit in time) the script stops with a clear error and a non-zero exit. No rename-the-exe fallback, no kill fallback.**

\## Design
1. **`POST /app/quit`** on the endpoint (bearer token required like every route). Body `{"force": bool}` (missing = false). The handler asks the host for the number of running worker turns. If > 0 and not force → **409** `{"error": "N worker(s) are running; quit with force to interrupt them", "running": N}`. Otherwise → **200** `{"quitting": true, "pid": <pid>}` and the host quits *after* the response has been written (spawn a task that sleeps ~300 ms, then `app.exit(0)`), so the caller gets its answer. Add two `LeadHost` methods: `async fn running_workers(&self) -> usize` and `fn quit(&self)`; `AppLeadHost` implements them by reusing `mod.rs`'s `running_workers` (make it `pub(crate)` or move it) and `app.exit(0)`. The tray's `request_quit` keeps its dialog and behaviour.
2. **Rebuilding marker** `<config>/run/rebuilding` (JSON `{"pid": <script pid>, "started_ms": <ms>}`). While it exists **and** is younger than 15 minutes (by `started_ms`, falling back to file mtime if unparsable), `start_instance` (or the single place that decides to spawn) does **not** spawn Mnemo2 and returns `Err("Mnemo2 is being rebuilt (npm run rebuild:mnemo2); try again when the build finishes")`. An instance that is already running is still found and used (lookup is unchanged); only the spawn is gated. A marker older than 15 minutes is ignored (and may be deleted). Put the check in one small function `rebuild_in_progress(run_dir, now) -> bool` with unit tests.
3. **`mnemo2-mcp quit [--force] [--timeout <s>]`** (default timeout 60 s). Reads every run file in `env.run_dir` (all projects: any of them locks the exe), skipping files whose pid is not alive. For each: POST `/app/quit` with `{"force":…}` and its token. Then waits until every targeted pid has exited (poll ~250 ms) up to the timeout. Prints one line per instance (`quit pid 1234 (C:\Mnemo)`) and exits 0 when all are gone, also when none were running (`no Mnemo2 running`). **Any failure exits 1 with a clear stderr line and does nothing else**: connection refused/timeout ("pid 1234 did not answer the quit request"), 404 ("pid 1234 is an older build without /app/quit; quit it from the tray once"), 409 (the server's message plus "rerun with --force"), 401, or still alive after the timeout ("pid 1234 did not exit within 60 s"). Never kills a process. Does not delegate to another helper copy (like `wait`, runs in place). Add it to USAGE.
4. **`scripts/rebuild-mnemo2.mjs`** + package.json `"rebuild:mnemo2": "node scripts/rebuild-mnemo2.mjs"`. Steps: resolve config dir ($MNEMO_HOME or ~/.mnemo) → write the marker → run the installed helper `<config>/bin/mnemo2-mcp(.exe) quit [--force]` (pass `--force` through from the script's own args) → on non-zero exit: remove the marker, print `rebuild:mnemo2: quit failed — <helper stderr>`, exit 1 (do not build) → else run `npm run build:mnemo2:native` with inherited stdio → remove the marker in a `finally` (also on build failure and on SIGINT) → exit with the build's code. On success print that the next Mnemo call or open_mission_control starts the new build. If the installed helper does not exist, print that and exit 1.

\## Verification commands

- `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --bins`

Do NOT run `npm run build:mnemo2:native`, the release build, or start/stop any Mnemo2 or Laya process: a Mnemo2 is running from target/release and the lead does the live check.

\## Constraints
- No `std::process::exit`, no `taskkill`, no killing anywhere in this feature.
- No new `#[allow(...)]`.
- Error and status texts in plain English as above.

## Acceptance scenarios
- With Mnemo2 open and no workers running, `npm run rebuild:mnemo2` quits it (its run file disappears and no laya-serve process remains), builds without 'Access is denied', and exits 0.
- While the build runs, a Mnemo tool call from Claude Code does not start a hidden Mnemo2; it reports that Mnemo2 is being rebuilt.
- With a worker running, `npm run rebuild:mnemo2` exits 1 before building and says how many workers run and to rerun with --force.
- When a running Mnemo2 does not answer or does not exit in time, the script exits 1 naming the pid and the reason, and kills nothing.
- A marker older than 15 minutes does not stop the helper from starting Mnemo2.
