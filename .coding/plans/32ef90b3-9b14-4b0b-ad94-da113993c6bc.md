# Plan: read_files (plural) batch read tool with per-file line ranges

## Goal
Add a read_files (plural) tool that reads multiple files in one call, each with an optional per-file line range (start_line/max_lines) to optimize context usage. Cuts multi-file exploration from N round-trips to one.

## Context
file_read (src/tool/agent/file_read.rs) reads ONE file per call. Exploring 3-4 files costs 3-4 round-trips. A batch read cuts that to one call. file_read already supports start_line + max_lines per file; the batch tool supports the same per-file so the model can read just the relevant slice of each file (the user explicitly asked for per-file line ranges to optimize context usage).

Design: a NEW tool read_files (plural) taking an array of {path, start_line?, max_lines?}. Reads each file through the same sandbox validation + line-numbering + line/byte-cap logic as file_read. Output: each file's content prefixed with a header (e.g. '=== path (lines a-b of N) ===') and the numbered lines, separated by blank lines. Reuse file_read's constants (DEFAULT_MAX_LINES=2000, DEFAULT_MAX_BYTES=102400) and numbering format ('{:>4}: {}'). Per-file errors (missing/unreadable) reported inline for that file but don't fail the whole call. Cap files per call (MAX_FILES=10) + total output byte cap (~500 KB) with truncation note.

Registration: add ReadFilesTool to register_agent_tools in src/agent/factory.rs. SafetyLevel::AutoRun (read-only). ToolCategory::Agent. New file src/tool/agent/read_files.rs + mod entry in src/tool/agent/mod.rs. prompt.rs guidance: mention read_files for exploring multiple files at once.
