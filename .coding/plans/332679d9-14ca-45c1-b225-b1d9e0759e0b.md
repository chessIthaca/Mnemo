# Plan: Correction-detection memory hook

## Goal
Add an automatic correction-detection hook: when a user prompt matches correction patterns (rule violations, "that's wrong", "did that land", etc.), record a Working-tier memory capturing the correction so it's retained and later distillable — independent of the model's in-the-moment judgment.

## Context
The ≤3-line summary rule failed because nothing automatic captures rule violations/corrections — only tool calls are recorded (agent/mod.rs:843 record_tool_event). User corrections are chat text that evaporates. Fix: a correction-detection hook in the agent runtime. AgentTask::run's Prompt arm (src/runtime/agent.rs:106) is where user prompts enter; the memory session starts at :109. MemoryStoreTrait::record_tool_event (src/memory/mod.rs:516) writes a Working-tier memory with tool_name+input+output+error; working memories flow into consolidation. AgentLoop exposes memory_handle(). The hook detects correction patterns in the prompt text and records a Working memory tagged as a correction, so capture doesn't depend on the model remembering to memory_write.

## Steps
- [x] 1. Add a pure correction-detector: a function (e.g. detect_correction(text) -> Option<String>) with a list of case-insensitive correction patterns (rule-break phrases, 'that's wrong', 'you broke', 'did that land', 'not what i asked', 'you didn't', 'stop doing'). Put it in src/runtime/agent.rs (or a small new module). Return the matched trigger for context.
- [x] 2. In AgentTask::run's Prompt arm, after the memory session starts and before run_turn_with_retry, call detect_correction(&text); on a match, record a Working-tier memory via the loop's memory_handle().record_tool_event with tool_name 'user_correction', tool_input = the prompt text, tool_output = a note capturing the correction + matched trigger. No approval, no event — silent capture, mirroring the tool-event path.
- [x] 3. Keep it text-only prompts: run detection on the raw `text` before any image handling so image attachments don't interfere. Guard on memory_handle() being Some (tests may have no store).
- [x] 4. Add unit tests: detector matches known correction phrases, ignores normal prompts; and a Prompt with a correction writes a working memory tagged user_correction (using a mock/in-memory store), while a normal prompt writes nothing extra.
- [x] 5. Run cargo test (lib) and cargo build -p myharness-app to confirm no regressions.
