# Plan: Finish ticks appended review-fix steps — a Complete plan frame shows no open checkbox

## Goal
Make `Workflow::finish` tick every still-unchecked step of the active plan — top-level `## Steps` entries appended during Reviewing and unchecked `## Detailed steps` checkboxes — in memory and on disk before the Reviewing→Complete transition, so a completed plan frame never renders an open checkbox. Preserve every step's text and any already-appended `## Cost report` section. Regression test `finish_ticks_appended_review_fix_steps` must be red on today's code (two `- [ ]` lines after finish) and green after the fix.

## Kind
bug_fixing

## Context
Symptom + fixture: a plan that goes through review rounds reaches Complete with its appended review-fix steps still rendered as open checkboxes. Live case `.coding/plans/8813e7ab.md`: `- [x]` on steps 1-7, `- [ ]` on the six steps 8-13 that `update_plan append=true` added in Reviewing (review findings H1-H4, L1-L4, verify/commit), even though the work shipped and round 3 passed. The file itself is the reproduction fixture — do NOT hand-edit it.

Root cause (verified by read of `src/app/workflow/mod.rs:1062-1073`): the Reviewing→Complete transition never rewrites the plan frame. `Workflow::finish` only sets `state = Complete`, `reviewed = true`, persists `stack.json`. `complete_step` is hidden in Reviewing by design, and the documented behavior says appended steps stay unchecked: `src/app/tool/workflow/plan.rs:1102-1105` (update_plan schema: "complete_step stays hidden mid-review, so appended steps stay unchecked through the exit") and `src/app/workflow/mod.rs:758-763`, `:776-778`, `:800-807` (Reviewing-append comments). The frame writer is `src/app/workflow/plan_file.rs`: `serialize()` at :54-85 renders `- [x] N.` / `- [ ] N.` from `PlanFile.steps`; `write_to_dir` at :237; `complete_detailed_step` at :136-218 is the model for a raw-text checkbox flip that changes only the mark and preserves everything after `] ` (verified by read of :164-200).

Persistence-ordering constraint (verified by read of `src/app/tool/workflow/plan.rs:2437-2488`): `FinishTool` appends the per-plan `## Cost report` section to `.coding/plans/<id>.md` BEFORE `wf.finish()` runs. Therefore `finish()` must NOT re-serialize the plan model over the file (that would silently drop the cost report). It must flip the checkbox marks in the existing file text in place, falling back to `write_to_dir` only when the file is absent.

Fix design: add `PlanFile::complete_all_steps(&mut self) -> usize` in `src/app/workflow/plan_file.rs` — tick every unchecked top-level `Step` and every unchecked checkbox in `detailed_steps` (raw-rebuild, preserving the text after `] `), return the number flipped — and `PlanFile::persist_completed_marks(&self, plans_dir, id)` — read the frame text, flip only `- [ ]` marks to `- [x]` via `parse_checkbox`, preserve indentation and all non-checkbox content, write back; fall back to `write_to_dir` when missing. `Workflow::finish()` runs both on `self.stack.last_mut()` before the state flip (verified by read: `finish` is the sole Reviewing→Complete transition, `src/app/workflow/mod.rs:1049-1073`). Every step's TEXT is preserved (the frame is the crash-resumption document; never drop steps). `current_plan` reads the in-memory frame, so ticking in memory keeps it in agreement with the file.
