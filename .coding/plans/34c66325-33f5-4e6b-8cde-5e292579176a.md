# Plan: R5: byte-stable context footer for prompt-cache prefix reuse

## Goal
Implement R5 from the cache-hit analysis: append a byte-stable CONTEXT_FOOTER as the final system message after the volatile tail, so the provider's prompt-cache prefix survives complete_step/workflow-tail changes (empirical cache law: prefix reuse requires the last message byte-identical). Expected: eliminate ~10 of 17 post-R1 cache resets, hit rate 87% → ~97-99%.

## Kind
implementation

## Context
Empirical finding (cache-hit-2 analysis, .coding/analysis/cache-hit-2-report.md): DeepSeek's prompt cache reuses the byte prefix only when the request's LAST message is byte-identical to the previous request's last message. Proof pairs from traces.jsonl: 28→29 (tail identical, hit 87%), 29→30 (tail changed on complete_step: PROGRESS 0/7→1/7, hit 2.4% despite 93% identical bytes), 30→31 (tail identical, hit 99.9%). Post-R1 the stable head (messages[0]) is byte-identical across the whole session (1 variant), and the volatile tail (WORKFLOW STATE + RECALLED MEMORIES) is appended as the LAST message (src/agent/turn.rs:332-350: push tail → complete_with_retry → pop). Because the tail is last, every complete_step/new-turn tail change invalidates the entire ~150-240K-token prefix (~10 of 17 post-R1 resets, ~1.0M tokens wasted). R5 fix: append a byte-stable CONTEXT_FOOTER as a SEPARATE final system message AFTER the volatile tail. The last message then never changes, so per the cache law the prefix up to the changed tail is reused — tail changes cost only ~300-600 tokens to reprocess. Code sites: src/agent/prompt.rs (consts CODING_SYSTEM_PREAMBLE/WORKFLOW_LIFECYCLE at top, build_stable_head :108, build_volatile_tail :139, back-compat build_system_prompt :169 — do NOT touch back-compat wrapper), src/agent/turn.rs:332-350 (push/pop site; pop runs before stream? so it always executes), src/agent/tests.rs:1025-1080 CapturingProvider (captures system prompt via .find() — finds head, unaffected) + tests.rs full_turn tests assert persistent messages after run_turn (tail+footer popped → unaffected). Context summarization inserts at index 1 (unaffected). Frontend untouched. Currently on feat/diff-tab-plan-file-dropdown (clean, committed); create a NEW branch for this work. Windows PowerShell; cargo test unpiped, check test-result lines + $LASTEXITCODE; zero warnings under #![deny(warnings)].
