# Plan: Adding an OpenSpec schema never follows symlinks

## Goal
Settings > Specs "Add schema" (from a folder or a git URL) refuses sources that contain symbolic links, so a crafted schema cannot copy an arbitrary local file (e.g. a private key posing as a template) into the project's .coding/openspec/schemas/.

## Kind
implementation

## Context
Automated security review (2026-11-05) of the merged Specs page: `src-tauri/src/mnemo2/specs_settings.rs` `copy_tree` (~731) uses `source.is_dir()` and `std::fs::copy`, which both follow symlinks, so a cloned or local schema folder containing a link (e.g. `templates/proposal.md -> ~/.ssh/id_rsa`) copies the link's target into `.coding/openspec/schemas/<name>/`, where the Specs page shows it and it may be committed. `add_schema_from` (~623) clones git URLs with `clone_repo` (~662, already uses `--` before the URL) and finds the schema with `locate_schema_folder` (~692) before `Schema::load` validates it.

Fix:
1. `copy_tree`: use `entry.file_type()` (does not follow links). A symlink (file or dir) is an error naming the path ("schema sources may not contain symbolic links"); copy regular files and recurse into real directories only. The check must happen before anything is copied: walk the whole source first (or copy into a temp staging dir that is only moved into place after a clean walk), so a refused source copies nothing.
2. `locate_schema_folder` / `add_schema_from`: refuse when the located schema folder itself, its `schema.yaml`, or any template path is a symlink (`symlink_metadata`).
3. `clone_repo`: add `-c core.symlinks=false` to the git clone as defence in depth.
4. Forks of existing schemas (`fork_schema`) use the same copy path and get the same protection.

Tests (in specs_settings.rs): a folder source with a symlinked template is refused and copies nothing; a symlinked schema folder is refused; a normal folder still copies. Create the symlink with std::os::windows::fs::symlink_file on Windows / std::os::unix::fs::symlink on Unix; if creating a symlink is not permitted (Windows without developer mode), skip that test with a message instead of failing.

Verification: cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings ; cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --bins

## Acceptance scenarios
- Adding a schema folder whose templates/proposal.md is a symlink fails with an error naming that path, and nothing is copied into .coding/openspec/schemas/.
- Adding a normal schema folder still copies it and it resolves.

## Steps
- [x] 1. **Refuse symlinks when adding or forking a schema** — `src-tauri/src/mnemo2/specs_settings.rs`: `copy_tree` checks `file_type()` and refuses links before copying anything; `locate_schema_folder`/`add_schema_from` refuse a symlinked schema folder, schema.yaml or template; `clone_repo` passes `-c core.symlinks=false`; tests as in the context.
