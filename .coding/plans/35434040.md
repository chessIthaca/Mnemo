# Plan: Fix build workflow: secrets context in step if: conditionals (env-mirror gates)

## Goal
Make .github/workflows/build.yml load cleanly on GitHub by replacing the three secrets-referencing step if: conditionals with job-level env gate mirrors (the documented workaround), preserving the set-but-empty avoidance design (gate names must NOT be the APPLE_* names the tauri bundler reads).

## Kind
bug_fixing

## Context
Root cause confirmed from the official GitHub docs context-availability table (fetched this session): jobs.<job_id>.steps.if allows github, needs, strategy, matrix, job, runner, env, vars, steps, inputs — NOT secrets; jobs.<job_id>.env DOES allow secrets (the file's existing step-level env blocks at L122-124/L142-145 already use secrets legally — only the if: lines error). Fix design: add a job-level env: block to the macos job (after timeout-minutes: 90) computing three gate booleans from secrets — APPLE_SIGNING_GROUP_SET (cert+identity both set), APPLE_NOTARY_GROUP_SET (issuer+key+content all set), APPLE_GROUPS_INCONSISTENT (the L111 XOR consistency condition) — then switch the three ifs to ${{ env.<GATE> == 'true' }}. Gate names deliberately differ from the tauri-facing APPLE_* names: a statically-declared env of an unset secret is set-but-empty, which the tauri bundler treats as a real identity — the GITHUB_ENV export pattern in the gated steps stays untouched. Windows job has no secrets usage; .github/workflows/ contains only build.yml. Verification: PyYAML yaml.safe_load parse check (same guard as the L52 fix) + cargo test (constitution) + the workflow loading on GitHub when the user re-runs it (this error class is caught at workflow-load time, before any runner work). AMENDMENT (supersedes the planning-time "no cargo test can exercise it" claim): regression test added — tests/integration/ci_workflow.rs::build_workflow_step_ifs_never_reference_secrets (registered via `mod ci_workflow;` in tests/integration/main.rs, the single merged integration binary — no new link target). It asserts no `if:` line in .github/workflows/build.yml references `secrets.` — the exact defect class. Fail-proof demonstrated: the same assertion against HEAD's pre-fix copy flags exactly the 3 offending lines (L111/L121/L141); the test passes on the fixed tree (cargo test --test integration ci_workflow: 1 passed).
