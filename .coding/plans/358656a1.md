# Plan: Shell tool: PowerShell && auto-translate, empty-call note, required purpose (backlog 79a2755d)

## Goal
Kill the two observed shell failure classes — bash-style && / || chaining rejected by PowerShell 5.1 (auto-translate to if ($?) gates with a visible note) and empty-argument calls (description trap note + purpose genuinely required at deserialization) — each pinned by regression tests that fail without the fix.

## Kind
implementation

## Context
Backlog 79a2755d (observed 2027-01-24, wt/mnemo session): two shell failure classes. (1) 4x empty-argument shell calls — same class as read_files (backlog 26cdbaf8): a well-formed shell call, then the NEXT call in the same turn emitted with an empty argument object → "command is required"; the previous call's body appears to steer generation when calls are adjacent. (2) PowerShell vs bash syntax: wrote `cmd1 && cmd2`; PowerShell 5.1 rejected && ("not a valid statement separator"). The description says "PowerShell on Windows, sh on Unix" but doesn't warn the chaining is incompatible. Failed calls also dropped `purpose` — labeled "Always provide this" but Option<String> with #[serde(default)] at runtime (src/tool/agent/shell.rs:180-182), so the schema's required list (:286) is unenforced. Anchors: ShellArgs (166-183), schema/description (268-289), the Windows launch path (332-344: ("powershell", "-Command")), the result-assembly note pattern (459-470: GREP_NUDGE/REDIRECT_NOTE prepended via insert_str(0, …), raw data note-free), test call sites (747/777/789 lack purpose; 806 has it). The translation is semantics-preserving: each if ($?) gate checks $? of the last executed statement — exactly left-to-right && / || short-circuit semantics (a && b || c → a; if ($?) { b}; if (-not $?) { c}). Approval/classification (never_auto_for, cmd_class) run on the ORIGINAL command before execute; the translation happens inside execute_streaming on the cfg!(windows) path only. Verify: cargo test green + warning-free (#![deny(warnings)]).
