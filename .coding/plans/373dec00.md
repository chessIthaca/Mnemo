# Plan: Memory that earns its place: measure recall, stop the noise, record how facts are known, check them against the repo

## Goal
Mnemo's memory gets a measurable recall score, stops storing what the repo already shows, records how each fact is known, flags claims the repo has moved past, gives the external lead a small map of the knowledge, and can search past transcripts as ground truth. Every change is judged by the recall eval.

## Kind
implementation

## Context
WHY. Anthropic's article "The components of agent memory" (https://www.anthropic.com/research/components-of-agent-memory, 2026-11-06) describes five layers: searchable transcripts as ground truth, notes, representations (linked wikis), a small injected layer, and offline consolidation ("dreaming") that corrects notes against the transcripts. Its main lessons: store what the environment does not expose, and record how a fact is known (status: checked or unconfirmed); wrong notes are worse than no notes (in its Mt. Moon test, corrected memory reached the goal at action 1,935, while wrong memory and no memory never did); say what memory is for rather than imposing fixed salience rules (a "record only failures" rule cost Opus 5 0.234 of its memory gain); keep the injected layer small; and search stays essential (wiki plus search 61% vs search alone 53%; a wiki alone peaked at 48% and needed about 128 dreaming sessions to get there).

WHAT MNEMO HAS RIGHT, KEEP IT. One file per typed record with a single writer (the article's one-page-per-entity lost 0 of 57 facts where a shared table lost 16). Files are the truth, rows are digests, git history included. Supersede chains. Quarantine instead of delete. Plan-scoped notes retired at close. A read gate before planning. Transcripts held for resume.

MEASURED ON THIS REPO, 2026-11-08 (live store, read-only; `access_count` only counts explicit memory_search hits, because auto-recall and the primer are peek paths that do not bump it):
- 10,260 live rows; 8,434 (82%) never returned by an explicit search. Every row's stored `strength` is 1.0: it never differentiates anything, and decay exists only at ranking time.
- 2,086 untyped auto-extracted facts; 774 (37%) restate git or plan state ("was committed as", "plan X step 2 was completed"), and 492 of those were never searched. The extractor's only guidance is one sentence: "distinct, reusable facts" (src/memory/consolidation.rs:422).
- 1,331 of 2,000 episodic rows are synthetic "Session involved N tool calls" lines from the turn-boundary compressor (src/memory/mod.rs `maybe_consolidate_turn_boundary`); 1,305 were never searched. A real memory_search for "memory system design decisions" returned 5 of them in its top 14 hits.
- 1,081 knowledge files, 679 citing source paths; 106 cite a path that no longer exists. Only 17 files use [[links]], and 19 of their 21 links do not resolve by a simple name match.
- agent.md, injected every session: 252 lines, 23 KB. No size cap (the article reports longer instruction files lower adherence; Claude Code's auto memory loads only the first 200 lines or 25 KB).
- No memory eval or recall metric exists anywhere.

GAPS AGAINST THE ARTICLE'S LAYERS.
- Transcripts: no agent or background job can search them; trace search is UI-only (`trace_list`).
- Notes: no how-known, status or evidence field; extraction reads a session narrative, not the transcript.
- Representations: no index or map; link repair absent.
- Injected: the primer is `strongest(..., 8)` (src/agent/turn.rs:4241), which with every strength at 1.0 is effectively recency. The external Claude Code lead, the main way this project is led today, gets no primer and no auto-recall at all (src-tauri/mnemo2-app/src/mnemo2_mcp/hooks.rs SessionStart adds only a worker summary).
- Dreaming: `spawn_consolidation` runs at session end and every 8th auto-continue turn; it merges only when the LLM names an existing id. It never verifies a claim, prunes or repairs.

DECISIONS.
- Measure first. Step 1 builds the eval; each later step reports before and after, and is reverted or reworked if hit@5 drops.
- Deterministic before LLM: the cheap, certain fixes (steps 2 to 6) come before any model-driven pass. Step 8 is gated on what they show.
- Quarantine, never delete (existing rule): all cleanup stays recoverable through `include_quarantined`.
- No settings knobs: passes run by themselves and show on the existing indexing status line, like the code index and the Laya check.
- No LLM wiki now. The article's wiki gains need many dreaming sessions and show mainly on multi-document questions; one wiki grew to 1.77x its source. Mnemo has a code graph for code and typed records for history, so a generated index (step 6) is the proportionate version. Revisit if the eval shows multi-record questions failing.
- Guidance says what memory is for, instead of adding fixed rules.

OPEN, FOR THE USER (nothing in this plan depends on them):
1. The durable-record gate at plan close forces a write whether or not the plan taught anything. The article's evidence is against fixed write rules; its evidence for reading before answering supports the read gate. Proposal: keep the read gate, turn the write gate into a nudge. It is the user's deliberate rule, so no step changes it.
2. agent.md is near the article's limits. Trimming it (details move into knowledge records, links stay) is a content decision for the user. Step 5 only reports the size.

Steps 7 and 8 name their design but need a full spec after step 1's baseline and step 5's first report; refine them with plan_update before dispatch.

## Acceptance scenarios
- `mnemo2_memory_eval` prints hit@1, hit@5, MRR and noise@5 from a copy of the store, with a recorded baseline and before/after numbers from each later step.
- A memory_search no longer returns 'Session involved N tool calls' rows unless explicitly browsing the episodic tier.
- Existing facts that only restate git or plan state are quarantined and recoverable; a sample of 30 shows at most 2 wrong calls.
- memory_write accepts evidence, and memory_search marks rows without it as [unconfirmed].
- A record citing a moved or deleted file shows that in memory_search results, and .coding/knowledge/HEALTH.md lists it, without any authored file being edited.
- A Claude Code lead session starts with a small map of the knowledge under 1.5 KB.
- All cargo checks pass, and hit@5 never ends below the baseline.
