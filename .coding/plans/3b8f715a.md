# Plan: Count the worker's own passing checks so the lead stops rerunning them

## Goal
When a worker ends its turn, Mnemo2 records as checks the plain test/lint/build commands the worker itself ran with exit code 0 on exactly the tree it committed, so the lead no longer reruns the full suite before every merge (the user: running the tests twice is silly).

## Kind
implementation

## Context
WHY: today `team_check` is lead-only and the merge gate (src-tauri/src/mnemo2/team/merge.rs ~240) requires at least one check, all passed on the merge-time tip. Workers run `cargo test --workspace` and clippy (agent.md says so), then the lead runs the same commands again to record them: every worker's suite runs twice (measured 2026-11-16: 66-256 s per rerun). The user asked to stop that. Standing rule (DECISION in memory): the lead reviews every diff but runs things only when judgement says so.

FACTS:
- The worker pump (src-tauri/src/mnemo2/team/pump.rs, the `SerializableAgentEvent::ToolCallStart` / `ToolCallArgDelta` / `ToolResult` arms) already collects each tool call's name and raw JSON args in `pending_calls` and sees its `ToolResult`.
- The `shell` tool (src/tool/agent/shell.rs ~781) always returns `success: true` when the command ran; the exit code is `result.data["exit_code"]` (integer); `data` is serialized, so it reaches the pump. The args carry the original text in `command`.
- `WorkerCheck { name, status, detail, tip }` (team/record.rs) and `TeamRuntime::record_check` (team/review.rs ~238: merge lock, refuse during/after merge, retain-by-name, bind to `worker_tip`, persist) are the existing record path.
- Invariant from memory: a pump snapshot probes the tip outside the records lock and must never clobber a review recorded after its probe; do not overwrite review state here.

DECISIONS:
- A shell call COUNTS when: the tool name is `shell`; `command`, trimmed, is one plain command: none of `;` `|` `&` `>` `<` backtick, `$(`, or a newline; its first word (case-insensitive, `.exe`/`.cmd` stripped) is one of cargo, npm, npx, pnpm, yarn, node, python, py, pytest, uv, go, dotnet, mvn, gradle, gradlew, make, just, ctest; it contains one of the whole words test, clippy, check, lint, build, vet; `success` is true; `data.exit_code` is 0. Anything else is ignored (failed runs are not recorded; a later passing run replaces an earlier one of the same name).
- When a counting call finishes, Mnemo2 computes the worker checkout's CONTENT tree without touching the worker's index: copy the index file named by `git rev-parse --git-path index` to a temp file, then with `GIT_INDEX_FILE=<temp>` run `git add -A` and `git write-tree`, then delete the temp file. It keeps `(name = the trimmed command, tree)` in memory for that worker's turn. A failure to compute the tree just skips that observation.
- At the end of the worker's turn, BEFORE the finished notice is emitted: read the tip, `git rev-parse <tip>^{tree}`, and for every observation whose tree equals it record a check through the same path as `record_check` (merge lock, refuse during/after merge, retain-by-name, bound to that tip, persist): name = the command, status passed, detail = "run by the worker; Mnemo2 saw exit code 0 on this exact tree (tip <short sha>)". Observations that do not match (the worker edited after testing) are dropped.
- Lead-recorded checks keep working unchanged; the lead still adds or reruns anything missing or doubtful. The merge gate itself does not change.
- Docs: the lead skill and review skill say worker-run checks arrive recorded (their detail says so) and the lead reruns only what is missing or doubtful; agent.md tells workers to run the final battery as plain commands (nothing else on the line, no pipe or redirect) after their last edit.

VERIFY: `cargo test --workspace` and `cargo clippy --workspace --all-targets` warning-free; the named tests.

## Acceptance scenarios
- A worker runs `cargo test --workspace` and `cargo clippy --workspace --all-targets` as plain commands with exit code 0, commits exactly that tree and ends its turn: team_status shows both as passed checks on its tip, detail naming the worker, before the finished notice arrives, and team_merge accepts them without any lead-run check.
- A worker that edits a file after its passing test run and commits gets no recorded check for that run.
- A piped, redirected or chained command, or one with a non-zero exit code, is never recorded as a check.
- The lead can still record its own checks with team_check, replacing a worker-recorded one of the same name.

## Decisions
- 2026-11-16: no spec impact: Adds an automatic source for the existing per-tip checks; the merge gate, review evidence and dispatch routing requirements are unchanged, and no capability spec names who records checks.
- 2026-11-16: The worker may touch team/spawn.rs, team/control.rs and team.rs only to pass the merge lock into pump_worker (making merge_lock an Arc<Mutex<()>> if needed), so pump-side check recording takes the same lock as record_check.
- 2026-11-16: User decision after the first audit (2026-11-16): keep counting the worker's own runs, hardened. (1) Only exact commands listed in `.coding/checks.toml` (key `commands`, array of strings) count, read from the LEAD's project root, never from the worker's checkout; a missing file means no automatic checks. Matching is exact after trimming and collapsing whitespace runs; the generic runner/keyword filter is removed. (2) The shell call's `cwd` must be absent or canonicalize to the worker's checkout root. (3) The shell tool itself (src/tool/agent/shell.rs), for a worker session configured with that command list, computes the checkout's content tree immediately before spawning and immediately after the process exits, before returning, and adds `data.tree_before` / `data.tree_after`; the pump counts the run only when both are present and equal, and uses that tree. Content-tree computation moves into the mnemo lib so the shell tool can call it (phase3 may wrap it). (4) At least one test drives the real pump path with a shell ToolResult. Initial `.coding/checks.toml` for this repo: cargo test --workspace; cargo clippy --workspace --all-targets; npm test --workspace mnemo2; npm run check --workspace mnemo2.

## Interfaces
- 2026-11-16: `.coding/checks.toml` (project root, versioned): `commands = ["<exact command>", ...]`. Worker sessions receive the command list through their spawn options; non-worker sessions and other commands get no tree fields.
