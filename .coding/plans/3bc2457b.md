# Plan: drift_never_blocks_the_message proves "no wait" with a gate, not a 1 s clock

## Goal
Rewrite the test so it proves the same property (a lead message never waits on the detached drift classification, and the drift nudge still lands) by order of events instead of elapsed time, so it cannot fail because the machine is slow. Test-only change in src-tauri/src/mnemo2/team/tests.rs.

## Kind
bug_fixing

## Context
Why: design section 4.6 says the drift check on a delivered lead message runs detached (TeamRuntime::spawn_drift_check in src-tauri/src/mnemo2/team/control.rs spawns a tokio task that takes the routing permit, asks Laya with a 3 s timeout, and delivers a "drift" nudge row). drift_never_blocks_the_message (src-tauri/src/mnemo2/team/tests.rs, around line 4480) is the only test guarding "the message never waits on Laya". Today it uses StubDispatchClassifier::slow(answer, 1 s) and asserts `elapsed < 1_000 ms` around fixture.team.message(...) and `fixture.classifier.calls() == 1` right after it. message_inner_with_kind persists team.json three times and sends the session command, which on a loaded Windows machine can take over 1 s without Laya being involved; and whether the drift task has already called the classifier when the test reads the counter is also timing. That is the root cause of the flake: the assertions measure machine speed, not the property.

Regression test: `drift_never_blocks_the_message` in src-tauri/src/mnemo2/team/tests.rs. Without the fix it fails under heavy parallel load on one of its two timing assertions (the 1 s bound or calls() == 1 after the message). After the fix it holds Laya back with a gate the test controls: the dispatch's own classification (call 1) answers at once, the drift classification (call 2) blocks until the test opens the gate. The message must return while the gate is closed; then the test opens the gate and the drift nudge must land. An implementation in which the message waits on the drift classification either hangs (caught by a 20 s guard) or lets the drift check hit its 3 s timeout behind the closed gate, so no nudge lands and the test fails.

Constraints and decisions:
- Test-only: change only src-tauri/src/mnemo2/team/tests.rs. No production code changes, no other test files.
- Keep StubDispatchClassifier::new, ::slow, the `delay` field and nudge_fixture_with's signature: other tests call them (nudge_fixture_with has 8 callers, StubDispatchClassifier::slow 3).
- The gate is a tokio::sync::watch channel (tokio 1.54, `Receiver::wait_for`). No new dependencies.
- No wall-clock bound on the message. The only time limits left are generous hang guards (20 s) and the existing eventually() helper (20 s).
- team.rs and src-tauri/src/mnemo2/mod.rs carry #![deny(warnings)]: no unused fields, functions or imports may be left behind.
