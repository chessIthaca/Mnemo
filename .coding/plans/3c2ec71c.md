# Plan: Recurring review findings become proposals to enforce them

## Goal
Every review finding can name its kind and how it could be stopped for good. When the same kind recurs across workers, Mnemo2 proposes enforcing it (a type, lint, policy test or check) as a backlog item instead of the lead correcting it again.

## Kind
implementation

## Context
WHY: review findings are the most expensive way to catch a mistake: late, inconsistent, and the next worker can repeat it. Findings live per worker in the team ledger, and nothing notices that the same kind of mistake keeps coming back, so the lesson never moves into the code or the build. This plan makes recurrence visible and turns it into a proposal.

DATA (decided):
- `crate::mnemo2::phase3::Finding` (src-tauri/src/mnemo2/phase3.rs) gains two optional fields, both `#[serde(default, skip_serializing_if = "Option::is_none")]` so old ledgers decode:
  - `category: Option<String>`: a kebab-case slug, `^[a-z0-9]+(-[a-z0-9]+)*$`, 3-40 chars;
  - `enforce: Option<String>`: one of `code` | `build` | `test` | `review`.
- Append-only ledger `.coding/reviews/findings.jsonl` (committed, like reviews). One JSON object per line, written when a finding id is first recorded for a worker, or when its category or enforce changes:
  `{"ts":ms,"worker_id","plan_id","step","finding_id","severity","title","file","category","enforce","model","tier"}`
  (absent values are null). Mnemo2's own generated findings (ids starting `regression-` or `mutant-`) are logged too, with category null.
- `.gitattributes` gains `.coding/reviews/findings.jsonl merge=union` with a comment, like the backlog line.

RECURRENCE (decided): a category's count = the number of DISTINCT workers in the ledger with a row of that category. When a team_review makes a category's count reach exactly 3, and that category's latest `enforce` is code/build/test, Mnemo2 adds ONE backlog item through `add_item` (src-tauri/src/mnemo2/backlog.rs). Dedupe: the item text ends with the marker line `[finding-category:<category>]`; skip it if a live backlog item already contains that marker.

VERIFY (each alone on its line): `cargo test --workspace`; `cargo clippy --workspace --all-targets`.

## Acceptance scenarios
- team_review accepts findings with category and enforce, rejects a non-kebab category with a message naming the finding, and old ledgers still load.
- Each newly recorded finding appends one row to .coding/reviews/findings.jsonl; re-recording the same review appends nothing.
- The third distinct worker with category X (enforce test) creates exactly one backlog item ending with [finding-category:X]; a fourth does not.
- The team_review result lists the finding categories in use with counts.
