# Plan: Check failure notices hide the failing test behind git warnings

## Goal
A failing check's summary always names the failing tests (and panics or errors) first; noise such as git's line-ending warnings never pushes them out.

## Kind
bug_fixing

## Context
ROOT CAUSE: src/tool/agent/run_checks.rs `diagnostics_block` keeps the first MAX_DIAGNOSTIC_LINES (15) lines that `diagnostic_lines` matches, in order of appearance. `is_rustc_header` (~:510) matches every line starting with `warning:` or `error:`, and the team tests run real git, which prints "warning: in the working copy of '<file>', LF will be replaced by CRLF the next time Git touches it" dozens of times on Windows before cargo's `failures:` list and the `test <name> ... FAILED` lines. Those warnings fill all 15 slots, so the failing names are cut.

DECISIONS:
1. Rank, then cap: collect matched lines into tiers and emit them in tier order, keeping order of appearance within a tier, before applying the 15-line cap: (a) failing tests: `test <name> ... FAILED`, the `failures:` header and its indented names, `---- <name> stdout ----` headers, `panicked at` lines and the line after each (the message); JS failures (is_js_failure); (b) errors: rustc `error:`/`error[` headers with their `-->` location, `Error:` lines with their location; (c) warnings: rustc `warning:`/`warning[` headers with their location. The "... (N more diagnostic lines)" marker stays, counting everything dropped.
2. Git's line-ending noise is not a diagnostic: a line starting `warning: in the working copy of '` or `warning: LF will be replaced by CRLF` (git's two phrasings) is never matched.
3. No other behaviour changes: the fallback tail when nothing matched, the cap value, and the PASS/FAIL block format stay.

REGRESSION TEST: `failing_tests_outrank_git_warnings_in_the_summary` in src/tool/agent/run_checks.rs's test module: feed diagnostics_block an output with 30 git CRLF warning lines, then a cargo `failures:` list with two names, a `---- a::b stdout ----` header, a `panicked at src/x.rs:1:2:` line plus its message, and `test a::b ... FAILED`; assert the block contains both test names, the panic location and message, and no line containing 'in the working copy of'. It fails on today's code (the block is all git warnings).

VERIFY: `cargo test -p mnemo --lib run_checks`; `cargo test --workspace`; `cargo clippy --workspace --all-targets`.
