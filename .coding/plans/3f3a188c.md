# Plan: git tool: allow read-only args on `branch list`

## Goal
Let the `git` tool's `branch list` action (and the default branch action, which is list) accept validated read-only listing flags like `-vv`, `-a`, `-r`, `--format=`, `--sort=` — so agents can run `git branch -vv` etc. through the tool instead of falling back to `shell`. `branch create`/`branch delete` (and all other write subcommands) keep rejecting `args`.

## Kind
implementation

## Context
The `git` tool (src/tool/agent/git.rs) blanket-rejects non-empty `args` for every subcommand except status/diff/log (the `is_read_sub` check at line ~542, error "args are not supported for git branch"). But `branch list` IS a read query — `git branch -vv`/`-a`/`--format=…` just list branches. The codebase's own principle (module doc lines 21-25: "free-form args are only forwarded for read queries") is violated for branch list.

The original plan 47472e35 was conservative because `git branch <name>` CREATES a branch (a positional arg mutates), and some single-arg flags mutate the current branch without a positional (`--set-upstream-to=origin/main`, `--unset-upstream`, `--edit-description`). So the status/diff/log denylist (validate_read_args) is NOT safe for branch — it allows positionals. A branch-list-specific ALLOWLIST of safe read-only flags is required: reject any positional (non-`-`-prefixed) arg, and reject any flag not on the safe list.

DECISION memory 2026-08-27-git-tool-args-is-read-only must be superseded: branch list is now a read that accepts args (allowlist), while create/delete and all other writes still reject. HOW memory 2026-08-26-git-tool-per-subcommand-parameter-reference row for branch list needs updating too.
