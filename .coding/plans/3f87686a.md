# Plan: Fix switch-restart window: same place, same size, on top

## Goal
Make the project-switch restart reopen the window exactly like the one it closed: same position, same size (re-maximized when it was maximized), and in the foreground (on top).

## Kind
bug_fixing

## Context
Root cause (verified by reading the flow): switching projects calls switch_project (src-tauri/src/ipc/projects.rs:201) → write_pending_project + tauri::process::restart (tauri 2.11.5: spawns the new process, then hard std::process::exit(0)). (1) Not on top: when the old window is destroyed Windows hands the foreground to another app; the relaunched process has no foreground right of its own (its parent is dead), so the new window opens behind whatever took focus. Fix: peek the pending-project marker before window creation in src-tauri/src/main.rs (~line 241) and call window.set_focus() after .build() — tao's force_window_active (vendor/tao/src/platform_impl/windows/window.rs:1500) does SetForegroundWindow + the ALT-key fallback. (2) Geometry gaps in frontend/src/App.tsx: the save path (line ~569) returns early when maximized so maximized:true is never persisted and the restore guard `if (saved && !saved.maximized)` (line ~504) skips — a maximized window restarts un-maximized at its last normal bounds; and the 400 ms debounced save + hard exit (no beforeunload) loses a move/resize made right before the switch. localStorage itself survives the restart (the old process releases the WebView2 UDF mutex within ms of the spawn; the new process reaches install_default_data_dir much later — src-tauri/src/webview_udf.rs). Regression tests: Rust unit tests for peek semantics (src/config/mod.rs tests ~line 1057), a main.rs include_str! source-contract test for the peek→set_focus wiring, windowRestore.test.ts source-contract additions for the maximize handling, windowGeometryFlush.test.ts for the registry, and a picker source-contract test that the flush precedes switchProject. Verify: cargo test (workspace, deny(warnings)) + cd frontend; npm test (vitest run).

## Bug
Opening a different project restarts Mnemo, but the new window does not open on top (foreground) like the window it closed, and does not reliably reopen at the same place/sizing — a maximized window restarts un-maximized at its last normal bounds, and a move/resize within the 400 ms save debounce is lost to the hard process exit.
