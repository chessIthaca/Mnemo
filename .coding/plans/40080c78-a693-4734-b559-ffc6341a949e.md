# Plan: Fix duplicate auto-recall lines after large tool outputs

## Goal
Stop redundant re-recalls + duplicate auto-recall transcript lines after large (>4 KiB) tool outputs by removing the now-understood-to-be-pointless cache invalidation; pin with a regression test.

## Kind
implementation

## Context
Research plan 0fd3bd99 verified the recall_peek fix works, and found one remaining defect: turn.rs:1303-1310 invalidates the per-turn auto-recall cache on any tool result >4 KiB, but the recall query is ONLY the latest User-role message text (turn.rs:366-370, `messages.iter().rev().find(|m| m.role == Role::User)`) — tool outputs are Role::Tool and can never change it. So every big file read re-runs an identical recall (re-embed + rescan) and re-emits a duplicate MemoryRecalled transcript line ("auto-recall after file read" spam; witnessed twice live this session). Root fix: delete the >4KiB invalidation branch; KEEP the summarize invalidation (turn.rs:323-325) because summarization can replace/rewrite the latest user message. Steers inject as Role::System (turn.rs:284-293) so they never affect the query either. Comments at turn.rs:141-145 and :359-364 reference the large-append invalidation and must be updated. User approved this fix via ask_user.
