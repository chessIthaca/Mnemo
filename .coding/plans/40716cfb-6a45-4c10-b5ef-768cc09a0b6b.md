# Plan: Fix: agent removed after every turn, blocking new prompts

## Goal
Stop the event forwarder from removing the agent on every `Finished` event. Add an `Exited` event emitted only when the agent task truly exits, so the forwarder removes the agent only then. This lets users send new prompts after a turn completes (especially in Complete state).

## Context
Root cause: src-tauri/src/ipc/events.rs calls mgr.remove(agent_id) on every Finished event. But Finished is emitted at the end of every turn (run_turn line 503), not just on Cancel. This drops the AgentHandle + command_tx, closing the channel and killing the AgentTask. Subsequent send_prompt calls fail because the agent is gone from the manager.

Fix: add an Exited variant to AgentEvent/SerializableAgentEvent. AgentTask::run emits Exited only when it actually exits (after the while loop — covers Cancel break and inbox-close). The forwarder removes the agent on Exited, not Finished. On Finished, just set running=false + clean up pending approvals.

## Steps
