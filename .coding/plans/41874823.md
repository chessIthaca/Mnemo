# Plan: Quality report passes a log-supplied commit to git unchecked

## Goal
The quality report only ever passes a plain hex commit id to git, after an explicit end of options, and treats anything else as an unknown commit.

## Kind
bug_fixing

## Context
Found by an automated security review right after plan dac2028d step 2 merged. Scope is src-tauri/src/mnemo2/quality.rs `changed_files_commits` (around line 442) only.

FIX (decided):
- Before calling git, accept `commit` only when it is 7 to 64 ASCII hex digits (`commit.len() >= 7 && commit.len() <= 64 && commit.bytes().all(|b| b.is_ascii_hexdigit())`). Otherwise cache `None` for it and skip, exactly like a commit git does not know.
- Also put `--` at the end of the git argument list (`["diff", "--name-only", &first_parent, &commit, "--"]`), so nothing after it can be read as an option.

REGRESSION TEST: `changed_files_rejects_option_like_commit` in quality.rs's test module. In a temp git repo (copy the init pattern from the module's existing tests if one exists, else `git init` plus one commit), call changed_files_commits with the commit `--output=<tempdir>/leak.txt`. Assert its entry is None AND `leak.txt` does not exist. Without the fix git writes leak.txt, so the file assertion fails.

Also add `changed_files_accepts_a_real_commit`: a real two-commit repo; the second commit's id returns Some with the changed file.

VERIFY (each alone on its line): `cargo test --workspace`; `cargo clippy --workspace --all-targets`.

## Bug
changed_files_commits in src-tauri/src/mnemo2/quality.rs passes `merge_commit` from .coding/laya/dispatch_routing.jsonl straight into `git diff --name-only <commit>^1 <commit>`. That log is committed and union-merged from other computers, so a crafted row such as merge_commit "--output=C:/x" becomes a git option, and `git diff --output` writes a file wherever it names.
