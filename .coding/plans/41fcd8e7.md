# Plan: team_dispatch's schema declares review_risk, so a schema-following lead can request a high-risk dispatch

## Goal
Declare review_risk (enum standard, high) in the team_dispatch tool schema, so a lead that follows the schema can request a high-risk dispatch and the worker's record says so. Guard it with tests that fail on today's code.

## Kind
bug_fixing

## Context
Why: `TeamRuntime::lead_host_tools` in src-tauri/src/mnemo2/team/lead_tools.rs (the team_dispatch HostToolSpec, around line 104) declares worker_id, plan_id, step, brief, tier, model, reasoning_effort and read_back. `handle_lead_host_tool_from` in the same file (around line 292) also reads `args.get("review_risk")` and passes it to `dispatch_request`, where dispatch.rs (around line 572) accepts None or "standard" as standard, "high" as high (plan with acceptance scenarios required), and refuses anything else. The tool description and the mnemo-lead skill both tell the lead to pass it. Only the schema is missing, and mcp_server.rs `tool_list` publishes `spec.parameters` unchanged as `inputSchema`, so an external Claude Code lead is never offered the parameter.

Root cause checked: comparing every branch of `handle_lead_host_tool_from` with the schemas in `lead_host_tools` (team_dispatch, team_audit_dispatch, team_status, session_search, team_message, team_stop, team_resume, team_compact, team_review, team_check, review_fix, team_route_fix, team_resolve_finding, team_merge, team_revert_merge), review_risk is the ONLY argument read but not declared. No other schema needs a change. The mcp_server.rs `tools/call` path forwards `args` unfiltered to `handle_lead_host_tool_from` (around line 1205), so no handler or dispatch change is needed.

Regression test: `team_dispatch_schema_offers_review_risk` in src-tauri/src/mnemo2/team/tests.rs. Without the fix it fails because `parameters["properties"]["review_risk"]` is null, so its type and enum assertions fail. `team_dispatch_schema_declares_every_argument_its_handler_reads` (same file) also fails without the fix, naming review_risk. `external_lead_high_risk_dispatch_over_mcp_records_the_risk` in the tests module of src-tauri/src/mnemo2/mcp_server.rs proves the external-lead path end to end: it fails at its first assertion without the fix, on the listed schema.

- src-tauri/src/mnemo2/team.rs and src-tauri/src/mnemo2/mod.rs carry #![deny(warnings)]: leave no unused imports or variables.

## Bug
The team_dispatch MCP schema has no review_risk property, although its handler reads the argument and its description tells the lead to pass review_risk='high' for persistence, concurrency and shared contracts. An external Claude Code lead that follows the schema cannot request a high-risk dispatch, so a dispatch meant as high-risk came back review_risk "standard" and the merge gate that requires a fresh independent audit never armed.
