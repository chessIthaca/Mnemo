# Plan: Split mnemo2/team.rs into a team/ module directory (tests file + 16 concern modules)

## Goal
Pure move, no behavior change: `src-tauri/src/mnemo2/team.rs` (17,707 lines, one 5,553-line `impl TeamRuntime`) becomes a small module root (the `TeamRuntime` struct, `open`, the shared helpers and re-exports) plus `src-tauri/src/mnemo2/team/tests.rs` (the 7,400-line inline test module) and sixteen child modules (record, persistence, guardrails, routing, nudge, escalation, external_lead, lead_tools, dispatch, spawn, audit, control, review, pump, merge, deletion), every external path `crate::mnemo2::team::X` unchanged, and the openspec governed-files map still covering every moved line.

## Kind
implementation

## Context
WHY. Mnemo2 architecture review finding ARCH-1 (Medium) and the team.rs half of ARCH-4: team.rs mixes nine concerns around one 5,500-line impl block and carries 7,400 lines of inline tests, so it is the file every plan edits and every merge conflicts on. VERIFIED against the current tree (wt/mnemo at ba6c266f; the review cites 3fe4f52, an ancestor): the shape holds, but team.rs has grown from 17,439 to 17,707 lines (plan baadab0b added the stuck-checkout retry: `retry_checkout_cleanups_locked`, `retry_leftover_cleanups`, `sweep_merged_branches` and four tests), so all line numbers in the review are stale. This plan locates everything by SYMBOL NAME. The review's module list is used with two changes: there is no child called `runtime.rs` (team.rs itself stays the module root and keeps the `TeamRuntime` struct, so its ~50 private fields stay private to `team` and visible to every child; a child named `runtime` would also be confusable with the sibling module `crate::mnemo2::runtime`), and the big impl block is split by concern across child modules, each with its own `impl TeamRuntime { ... }`, plus `pump`, `control`, `review`, `merge`, `dispatch`, `spawn`, `audit`, `external_lead`, `lead_tools`, `routing`.

RULES (non-negotiable).
R0 NO behavior change. Every moved line stays byte-identical, except: leading indentation inside a child that wraps methods in `impl TeamRuntime { }` (methods keep their 4-space indentation), `pub(super)` added where R3/R4 say, and `use`/`mod`/`pub use` lines. Never edit a moved function body. Never retype code: extract and delete with a script.
R1 Children are private modules of team.rs (`mod record;`), never `pub mod`.
R2 Re-exports keep every external path alive: every item that was `pub` or `pub(crate)` in team.rs and moves gets `pub use child::Item;` (or `pub(crate) use child::Item;` for pub(crate) items) in team.rs. No file outside team.rs / team/ may change in this plan; if one needs an edit, the move is wrong. (Externally used today, among others: WorkerRecord, WorkerStatus, WorkerCheck, MessageSender, InboxKind, InboxEntry, WorkerRouting, ChangeSource, ToolErrorNote, KICKOFF, READ_BACK_KICKOFF, WorkerSessionSpec, tool_errors_text, executor_prompt, audit_prompt, ExternalWait, ExternalWaitStatus, EXTERNAL_LEAD_IDLE_MS, EXTERNAL_LEAD_MEMORY_REMINDER, WorkerDeletion, WorkerDeletionResult, TeamDeleteOutcome, DeletionProgress, DeletionPhase, CleanupReport, cleanup_workspace.)
R3 A private moved item (no `pub`) that another module uses becomes `pub(super)`; siblings reach it as `super::<module>::Item`, the root through `use <module>::Item;` (only for names the root itself uses). Do not widen anything beyond `pub(super)` unless it already was `pub`/`pub(crate)`.
R4 A private method of impl TeamRuntime that moves to a child and is called from another module becomes `pub(super)`. Private fields of a moved struct that other modules read or write become `pub(super)`. TeamRuntime's own fields stay private (children see them).
R5 Each child begins with the repo licence header (the same three `//` lines as team.rs line 1-3), then a 1-3 line `//!` doc saying what the module holds, then ONLY the imports it uses (no `use super::*` outside tests.rs). team.rs trims its own `use` lines to what it still uses. `src-tauri/src/mnemo2/mod.rs` has `#![deny(warnings)]` (and team.rs has its own), so an unused import is a compile error: the compiler tells you.
R6 team/tests.rs: after items move, tests that name them through `use super::*` stop resolving. Fix ONLY the header of tests.rs by adding `use` lines (for example `use super::routing::*;`, or explicit names) for the names the compiler reports. Never touch a test body.
R7 `#[serde(default = "name")]`-style attribute strings resolve where the type lives: move the named function with the type (record.rs rule above) or give it a path.
R8 `#[cfg(...)]` items keep their cfg (is_link_or_junction has a unix and a windows variant: both move). Doc comments, attributes and the original relative ORDER of items (and of methods inside each impl block) are preserved.
R9 `tests.rs` is declared in team.rs only, never in a child.

HOW TO MOVE ITEMS MECHANICALLY (use a script in python, node or PowerShell, whichever the shell has; open the big files in the editor only to look at small windows).
1. Inventory: `grep -nE "^(    )?(pub(\([a-z]+\))? )?(async )?(unsafe )?(fn|struct|enum|const|static|impl|type|trait) " src-tauri/src/mnemo2/team.rs` prints every item header (column 0) and every method header (4-space indent).
2. An item's START is its header line extended UP over the contiguous lines directly above it that, ignoring indentation, begin with `///`, `#[` or `//` (its doc comment, attributes and its own plain comments), stopping at a blank line or code. Its END is the first line at or after the header that has the SAME indentation as the header and begins with `}` (this also matches `};` and `});`); an item without braces (`const X: T = ...;`, `use`, tuple struct) ends at the first line ending in `;`. A multi-line signature is fine: its closing `) -> T {` line begins with `)`.
3. Append START..END (inclusive) of each wanted item to the child file in ORIGINAL order, then delete exactly those lines from team.rs plus one adjacent blank line (no double blank lines). Process deletions bottom to top, or recompute ranges after each deletion.
4. In a child, wrap the methods of one concern in `impl TeamRuntime {` ... `}` (one block per child; keep a blank line between methods as in the original).
5. After each batch run `cargo check -p mnemo-app --features mnemo2 --lib` and fix ONLY imports, `mod`/`use`/`pub use` lines and visibility (R1-R7).

PURE-MOVE PROOF every step (2-7) must run and report (LC_ALL=C; Git Bash or equivalent): before editing, `git show HEAD:src-tauri/src/mnemo2/team.rs | sed 's/^[[:space:]]*//' | grep -v '^$' | sort > $SCRATCH/before.txt`; after the step, `( cat src-tauri/src/mnemo2/team.rs; for f in src-tauri/src/mnemo2/team/*.rs; do case "$f" in */tests.rs) ;; *) cat "$f";; esac; done ) | sed 's/^[[:space:]]*//' | sed 's/pub(super) //' | grep -v '^$' | sort > $SCRATCH/after.txt`; `diff $SCRATCH/before.txt $SCRATCH/after.txt`. The ONLY differences allowed are: `use ...;` lines, `mod ...;` lines, `pub use ...;`/`pub(crate) use ...;` lines, the licence-header and `//!` doc lines, `#![deny(warnings)]` repeats, lines that are just `}` or `impl TeamRuntime {` (the wrapper), and attribute lines `#[cfg(test)]`/`#[path = ...]` for the tests declaration. Paste the full diff output into the report.
TEST-INVENTORY PROOF every step must also run: BEFORE editing, `cargo test -p mnemo-app --features mnemo2 --lib -- --list 2>/dev/null | grep ': test$' | sort > $SCRATCH/tests-before.txt`; after the step the same command into tests-after.txt; `diff` must print nothing (test names are `mnemo2::team::tests::...` and never change).

VERIFICATION COMMANDS (checkout root = repository root): `cargo check -p mnemo-app --features mnemo2 --lib` (fast loop); at the end of each step `cargo test -p mnemo-app --features mnemo2 --lib`, `cargo clippy -p mnemo-app --features mnemo2 --all-targets -- -D warnings -A clippy::redundant_guards -A clippy::nonminimal_bool`, `cargo test --test boundary`, `git diff --check`. The repo is NOT rustfmt-clean: never run cargo fmt or rustfmt on any file. Windows shell hygiene: use `git -C` and `--manifest-path`, never leave a shell inside another worker's checkout.

ORDER AND PARALLELISM. Steps 1-7 each delete code from team.rs, so they run strictly one after another (the lead dispatches the next only after the previous merged); each child file is owned by exactly one step. tests.rs is created by step 1; steps 2-7 may only add `use` lines to its header (R6). Step 8 (governed files) touches only YAML and runs after step 7. Step 1 must not be dispatched before plan 2b1e9c1b step 1 (the boundary test exempting test-only files) has merged, otherwise `cargo test --test boundary` fails on `mnemo::agent::...` tokens in the moved tests.

GOVERNED FILES. team.rs is governed by four OpenSpec capabilities in `.coding/openspec/config.yaml` (dispatch-routing, external-lead, tier-ladder, worker-brief), matched by EXACT repo-relative path. The plan declares spec_impact none (pure move). Step 8 adds every new file to all four lists and to the two `.mnemo.yaml` glob lists so that later plans touching any moved code still need a spec delta or an explicit no-impact declaration. Stale pointers to `team.rs:<line>` in design docs and a doc comment in safety_settings.rs are line-number citations that were already stale; they are deliberately NOT edited.

OUT OF SCOPE: any behavior change; renaming items; splitting `pump_worker` (766 lines) or `route_implementation_dispatch` (303 lines) internally; changing the tests; runtime.rs (plan e7a6d30a); the plan board's other plans.
