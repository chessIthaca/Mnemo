# Plan: Raise the tools-panel ceiling to 75% and lower the chat floor to 360px (manual resize past 50%)

## Goal
Let the user resize the tools (right) panel larger by hand: raise the panel's flat ceiling from 50% to 75% of the window and lower the chat column's guaranteed minimum from 480px to 360px, keeping the single-source-of-truth band shared between the JS drag clamp and the inline CSS caps.

## Kind
bug_fixing

## Context
User report (2027-01-16, follow-up to plan 38b0e2eb / BUG memory 97200cbc): after the right-panel width became a window FRACTION, the tools panel can no longer be resized past 50% of the window — "that is too aggressive, I want to resize bigger if I do so by hand."

ROOT CAUSE: two independent ceilings in the band, and the flat one binds. frontend/src/hooks/appearance.ts:260-265 clampPanelFraction computes max = max(min, min(PANEL_MAX_FRAC, (w - CHAT_MIN_PX)/w)) with PANEL_MAX_FRAC = 0.5 (:249) and CHAT_MIN_PX = 480 (:244). The 0.5 ceiling is a flat cap that is tighter than the chat-column floor above ~960px, so every manual drag stops at exactly half the window regardless of viewport size. The JS clamp at App.tsx:868-869 (fracFromPx) is what stops the panel following the cursor; the same caps are ALSO interpolated into the inline CSS at RightPanel.tsx:46-48 (min(pct%, 50%, calc(100% - 480px))) so the layout engine re-clamps at every viewport (the round-1 review L1 invariant — must be preserved).

CHOSEN FIX (user-selected option D): raise the flat ceiling AND lower the chat floor — PANEL_MAX_FRAC 0.5 -> 0.75, CHAT_MIN_PX 480 -> 360. clampPanelFraction keeps its shape; only the constants move. Effect: max = max(min, min(0.75, (w - 360)/w)). The two ceilings CROSS AT w = 1440px: below 1440 the chat floor governs ((w-360)/w < 0.75), at/above 1440 the flat 75% governs and the chat keeps >= 25% of the window (360px at exactly 1440). Both bindings are intended — the floor protects small restored windows (the original 831px bug), the flat cap stops a runaway panel on large ones. Worked numbers: w=800 -> max 0.55 (440px panel, chat 360px); w=1000 -> 0.64; w=1280 -> 0.7188; w=1440 -> 0.75; w=1920 -> 0.75 (1440px panel, chat 480px).

## Bug
The tools (right) panel cannot be resized past 50% of the window width by hand — dragging the divider stops dead at half the window, which the user reports is "too aggressive, I want to resize bigger if I do so by hand." Symptom is reproducible on any viewport: drag the handle left and the panel halts at exactly 50% of innerWidth. Root cause is the flat PANEL_MAX_FRAC = 0.5 ceiling in clampPanelFraction (frontend/src/hooks/appearance.ts:249/263), which is tighter than the chat-column floor (w - 480)/w for every window wider than ~960px.
