# Plan: Hide the built-in lead chat while Claude Code leads

## Goal
While an external lead (Claude Code) is attached, Mnemo2's lead pane shows a clear "Claude Code is leading this project" panel with the team's live status instead of the idle built-in lead chat, and switches back to the chat by itself when the external lead detaches.

## Kind
implementation

## Context
WHY: with Claude Code as the external lead, the lead pane keeps showing the built-in lead's old conversation and composer. Nothing from Claude Code appears there, so it looks frozen and invites typing into a lead that is not leading. The user asked to hide it when an external lead is in use and show a short, well-worded pointer instead of a bare "see Claude".

WHERE:
- verified: reading mnemo2/src/App.svelte:30-35 -> on route "lead", `.lead-column` renders `<LeadChat />` and then the Workbench or the worker output panel (`WorkerPanel`) beside it.
- verified: reading mnemo2/src/components/LeadChat.svelte -> the transcript, live status lines ("Waiting on <workers>", "Needs you: <workers> (<status>)" with buttons calling `actions.openWorkerPanel(worker.id)`), lead error and pending notices, and at line 221 `<footer class="composer-dock"><PendingPrompt /><Composer /></footer>`.
- verified: reading mnemo2/src/components/ExternalLeadBadge.svelte -> `$app.externalLead.attached` drives the top-bar badge "Lead: Claude Code (external)"; `grep -n sinceMs mnemo2/src/lib/externalLeadEngine.ts` -> the state also carries `sinceMs: number | null` (attach time).
- verified: reading mnemo2/src/components/Composer.svelte:107 and :327 -> while attached, sending opens a "Send to the built-in lead?" confirmation sheet.
- verified: `grep -n` -> mnemo2/README.md:343-349 and mnemo2/plugin/README.md:54 describe the external-lead UI (badge, notices to Claude Code, send confirmation).

DECISIONS:
- New component `mnemo2/src/components/ExternalLeadPanel.svelte`, rendered by `LeadChat.svelte` in place of its scroll area and composer dock while `$app.externalLead.attached` is true. App.svelte stays unchanged, so the worker panel and Workbench beside the lead pane keep working.
- Panel copy (use exactly, styled like the existing lead notices and empty states): eyebrow "EXTERNAL LEAD"; title "Claude Code is leading this project"; body "Plans, briefs, reviews and merges come from your Claude Code session. Talk to the lead there and follow the team's work here."; a meta line "Leading since HH:MM" from `sinceMs` (omit the line when `sinceMs` is null).
- The panel shows the same live team lines LeadChat shows today, "Working: <worker buttons>" for running workers and "Needs you: <worker buttons> (<status>)" for workers that need the user, each worker a button opening its output panel via `actions.openWorkerPanel`; when no worker is running it says "No workers running right now." Reuse LeadChat's existing selection logic for those two lists (move it to a small shared helper if both components need it) instead of writing a second definition.
- Escape hatch: a quiet button "Open the built-in lead anyway" reveals the normal chat and composer for this view; the existing send confirmation still applies there. While revealed, a slim bar above the transcript reads "Claude Code is leading this project." with a "Back" button that returns to the panel. The reveal is local view state that resets to the panel whenever the external lead attaches again; when the external lead detaches, the normal chat shows with no extra bar.
- Keep the top-bar badge and the Composer confirmation as they are. No backend change.
- Update the two README passages to say the built-in lead chat is replaced by this panel while Claude Code leads, with the "Open the built-in lead anyway" escape.

VERIFY (run in `mnemo2/`):
- `npm run check`
- `npm test` (vitest), with new tests described in the acceptance scenarios.

## Acceptance scenarios
- With `externalLead.attached` true, the lead pane shows "Claude Code is leading this project" and does not render the built-in lead transcript, PendingPrompt or Composer (component test).
- The panel lists running workers and workers that need the user as buttons; clicking one calls `actions.openWorkerPanel` with that worker's id; with no running worker it shows "No workers running right now." (component test).
- "Open the built-in lead anyway" reveals the normal transcript and composer with a "Claude Code is leading this project." bar and a Back button that returns to the panel; after the external lead detaches the normal chat shows without the bar (component test).
- `npm run check` and `npm test` pass in mnemo2 with no new errors or warnings.
