# Plan: Notification sounds: complete ding / needs-input / doom on triple-error stop

## Goal
Three notification sounds — a ding when an agent reaches Complete, a distinct sound when an agent needs user input (approval/question), and a short doomy sound when three consecutive errors stop the agent — each independently disableable in the Settings dialog ([ui] config), synthesized via the Web Audio API (no assets).

## Kind
implementation

## Context
Findings: (1) Backend caps turns at MAX_RETRIES=3 consecutive tool errors (src/agent/mod.rs:38) — tool failures surface to the UI as tool_result events with success:false, and the stop surfaces as ONE final Error event (retrying:false, "Aborting turn: 3 consecutive tool errors", turn.rs:1493-1505); single fatal provider errors are also final Error events, so the doom trigger must distinguish by counting consecutive FAILED tool results, not Error events. (2) Sound trigger architecture: frontend event reducers (frontend/src/hooks/agentEventReducer.ts) are pure and return Effects executed by useAgentStore.handleAgentEvent (:943-957, where scheduleSteerRemoval already runs) — a new Effects.sound + gated execution there matches the pattern. workflow_state_changed fires ONLY on real transitions (Complete is resting), so state==="complete" is the correct ding trigger; approval_request + user_question reducers are the needs-input triggers. (3) Settings: GeneralConfig.ui (src/config/general.rs:264) holds show_token_usage/show_memory_activity with round-trip tests (:694-716); IPC round-trip in src-tauri/src/ipc/settings.rs (GetSettingsResponse :429/:605, SettingsSaveDto :799/:1050, tests :1342+); frontend Settings dialog uses SETTINGS_NAV + SettingsSectionId (components/settings/types.ts:6-116) + per-section draft components (ChatSection.tsx pattern) registered in SettingsDialog.tsx. (4) Sounds: synthesized via Web Audio API oscillators (lib/sounds.ts) — no binary assets in repo; lazy AudioContext + resume() for autoplay policy. Decisions: three independent config flags sound_complete/sound_input_needed/sound_stopped_errors (default ON) in [ui]; doom counts consecutive failed tool_results (reset on success + on started) and fires only when a FINAL error (retrying:false) arrives with streak>=3; preview buttons in the Sounds section play sounds regardless of the enable flags (explicit user gesture, so AudioContext unlock is safe); branch forked via create_plan's branch param (feat/notification-sounds from main — currently on unmerged feat/graph-browse-source).
