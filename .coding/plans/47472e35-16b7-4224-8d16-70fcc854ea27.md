# Plan: Forward validated read-side args in the git tool (precise queries without shell)

## Goal
Make the git tool support precise read queries (status/diff/log) by forwarding validated extra args, so agents no longer need the shell for them; keep write subcommands flag-free and safe; add the missing `stash list` query action.

## Kind
implementation

## Context
Backlog item: "The git tool wrapper drops extra flags — using the shell for precise git queries instead." Root cause (read src/tool/agent/git.rs in full): GitArgs has only fixed fields (subcommand/message/branch/action/remote) and serde silently drops unknown fields, so `args` like --stat/-n 5/--format can never reach git — every subcommand maps to a hardcoded argv (status --short, diff, log --oneline -20). Agents needing precise queries (git diff main..feat --stat, log -3, status --porcelain) must fall back to the shell tool. Gating: Tool::safety() is NeedsApproval for the whole tool; never_auto_for gates merge/push via a runtime list. Args go as discrete argv after the subcommand — no shell, so no shell-injection risk; the denylist only needs to cover git-level write/exec flags on read subcommands (--output, -o, --exec). Frontend: Message.tsx argLabel (lines 333-341) shows just the git subcommand; it should show appended args too.

## Steps
- [x] 1. **Add validated `args` forwarding for git read subcommands** — In src/tool/agent/git.rs: (1) add `#[serde(default)] args: Option<Vec<String>>` to GitArgs with a doc comment. (2) New private helper `fn validate_read_args(args: &[String]) -> Result<(), String>`: reject any arg that starts with `--output` or `--exec` or equals/starts with `-o` (short output flag) — these can write files/run commands; everything else (refs like main..feat, paths after --, -n/-5, --stat, --cached, --porcelain, --format=, --author=, etc.) is allowed since argv is discrete (no shell). (3) status/diff/log arms: build argv = builtin defaults + validated user args appended AFTER the defaults (git's later-wins: user -5 overrides the default -20); on validate error return ToolResult::error("git {sub}: unsafe flag rejected: {flag}"). (4) commit/merge/checkout/stash/branch/push arms: if args present and non-empty, ToolResult::error("args are not supported for git {sub} (flags are only forwarded for read queries: status, diff, log)") — silent dropping is the original defect, so erroring loudly is required. branch positional args especially must not leak in (they create branches). (5) stash: add action "list" → run_git(&["stash", "list"]); update the action doc comments + unknown-action error text to mention list. (6) Update the ToolSchema: add the `args` property (array of strings, description: extra flags/refs/paths for read queries only, appended after built-in defaults; refused for write subcommands; --output/-o/--exec rejected) and mention it in the tool description; fix the module doc which claims reads are auto-run while safety() is NeedsApproval (reconcile: note approval gating is uniform, never_auto_for gates core ops).
