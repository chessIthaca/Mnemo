# Plan: Chat URL clicks + agent-steered browser: keep the app UI intact, sync the URL box (backlog 3f838ea1)

## Goal
Fix both Browser-tab integration defects: (1) every markdown surface routes http(s) links through the sanctioned opener (MarkdownLink → openChatLink → Browser tab foregrounded) — no raw anchors whose default navigation replaces the app UI; (2) the child webview's page-load events flow to the frontend (browser://url-changed → store.browserUrl) and BrowserView's URL box syncs from them, so agent-steered navigations (and in-child link clicks) show the current URL — on change and on mount.

implementation

## Context
Two defects (user report 2027-01-24, backlog 3f838ea1):

(1) Chat URL clicks navigate the whole app away. ROOT CAUSE (verified): MarkdownImpl (frontend/src/components/chat/MarkdownImpl.tsx — the ONLY ReactMarkdown renderer, reached via the lazy Markdown wrapper) renders raw <a href> anchors when the caller passes no `components` override. Message.tsx:304-310 passes `a: MarkdownLink` (wired: preventDefault + openMarkdownTarget → openChatLink → requestBrowserOpen → pendingBrowserUrl → BrowserView), but three render sites pass NO override: PlanProgress.tsx:281 (<Markdown>{plan.goal}</Markdown>), BacklogView.tsx:906 (<Markdown remarkPlugins={[remarkBreaks]}>{body}</Markdown> — backlog bodies carry http(s) URLs), SourceEditor.tsx:523/529/535 (the markdown editor's live preview, also used by FileViewer). Clicking an anchor there runs the WebView's default navigation → the UI is replaced. AUDIT CLEAN: the chat's own surfaces (MarkdownLink both anchors preventDefault; ToolCard URL chip is a <button> Message.tsx:630-647; InlineMarkdown emits no anchors; streaming text is plain), and the only other raw <a> is AdvancedSection's programmatic blob-download anchor. FIX: make `a: MarkdownLink` the DEFAULT inside MarkdownImpl — `components={{ a: MarkdownLink, ...components }}` (caller's spread wins; Message.tsx passes the same component, no behavior change). MarkdownLink statically imported into the lazy chunk is fine (its deps are main-bundle modules, Vite dedupes).

(2) Agent-steered navigation leaves the URL box empty/stale. ROOT CAUSE (verified): BrowserView.tsx's `url` state is set only by loadIntoChild (user Open/Enter + chat-link pendingBrowserUrl). The agent's browser_* tools navigate the child webview over CDP — invisible to the frontend. browser://reveal fires only at bootstrap (ensure_for_agent_impl :461) and its handler (browserReveal.ts:23-25) only reveals the tab, ignoring the payload URL. FIX: wry's on_page_load handler (CONFIRMED available: vendor/wry/src/lib.rs:1365 with_on_page_load_handler, firing PageLoadEvent::Started/Finished with the URL string on WebView2 — vendor/wry/src/webview2/mod.rs:656/668) attached to the child WebviewBuilder at BOTH creation sites (browser_webview_ensure ~:335 and ensure_for_agent_impl ~:424 — the builder construction is duplicated; extract a shared helper), emitting a new `browser://url-changed` event. Frontend: a module-scope idempotent listener (mirror ensureBrowserRevealListenerStarted, useAgentEvents.ts:299-307) writes the URL into a new store field `browserUrl` (useAgentStore.ts, near pendingBrowserUrl :269/:682/:917) — module scope means NO mount-timing gap (the store tracks even while the Browser tab is hidden). BrowserView subscribes and syncs the box (setUrl + setLoadedUrl + setError(null)) on change AND on mount (the effect's initial run catches up). tauri.ts adds BROWSER_URL_CHANNEL + BrowserUrlPayload + onBrowserUrlChanged (mirror onBrowserReveal :1840-1847). The foregrounding for chat links already works (requestBrowserOpen sets rightPanelTab "browser" + visible, useAgentStore.ts:909-918).

TEST PATTERNS: BrowserView's consume side is pinned as a SOURCE-CONTRACT test (openChatLink.test.ts:30 `?raw` import, :135-141 describe block — the node env cannot mount the view); the reveal handler is a pure function tested in browserReveal.test.ts; store actions tested in useAgentStore.test.ts. Frontend tests: `npm --prefix frontend test` (vitest run, package.json "test"). Rust: cargo test (warning-free, #![deny(warnings)]).

VERIFICATION: cargo test green + warning-free; vitest green; acceptance = every markdown surface routes links through the sanctioned opener (no raw anchors anywhere), and an agent-steered navigation shows the current URL in the URL box (store-synced, mount-safe).
