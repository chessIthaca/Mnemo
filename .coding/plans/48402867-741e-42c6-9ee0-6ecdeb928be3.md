# Plan: Implement path (a): bare-window + two-add_child reconfigure

## Goal
Reconfigure main.rs's window model from WebviewWindowBuilder (window+webview combo) to a bare WindowBuilder + two ordered add_child webviews (agent-chat React + game-browser), delivering crash isolation while keeping React+IPC+brain untouched.

## Kind
implementation

## Context
Path (a) is fully de-risked: spike e9cd6fb1 confirmed two add_child webviews in a bare WindowBuilder window switch tabs correctly AND a renderer crash in tab1 leaves tab2 alive (shared browser process survives; each child has its own renderer). The user accepted the security tradeoff (both children share one WebView2 env → both get CDP; no isolation). Current architecture: tauri.conf.json auto-creates a WebviewWindow labeled "main" (React frontend); browser_webview.rs lazily creates a game-browser child via window.add_child(). Path (a) target: tauri.conf.json windows:[], main.rs creates a bare WindowBuilder + two add_child webviews (agent-chat React first, game-browser stays lazy). The game_* tools' select_child_target already distinguishes app URLs from child URLs, so no changes needed there. browser_webview.rs needs no changes (it already uses app.get_window("main").add_child(...)). Key risk: the agent-chat add_child webview must resize with the window (WebviewWindow auto-fills; add_child doesn't) — needs an on_window_event resize handler.

## Steps
- [x] 1. **Add agent-chat webview field to IpcState** — in `src-tauri/src/ipc/state.rs`, add a field to the `IpcState` struct: `pub agent_chat_webview: Arc<std::sync::Mutex<Option<tauri::webview::Webview>>>` with a doc comment explaining it holds the agent-chat (React) add_child webview handle for the window-resize handler + exit cleanup. This mirrors the existing `browser_webview` field (which holds the game-browser child handle). Use `std::sync::Mutex` (not tokio) because the resize handler is sync.
- [x] 2. **Reconfigure window creation** — (a) In `src-tauri/tauri.conf.json`, change `app.windows` from `[{...}]` to `[]` (no auto-created window; the bare window + agent-chat webview are created manually in setup). (b) In `src-tauri/src/main.rs`, add imports `tauri::{PhysicalPosition, PhysicalSize, WebviewUrl, WebviewBuilder, WindowBuilder, WindowEvent}` alongside the existing `Emitter, Manager`. (c) At the TOP of the `.setup(|app| { ... })` closure, BEFORE `build_brain()`: create `let agent_chat_handle: Arc<std::sync::Mutex<Option<tauri::webview::Webview>>> = Arc::new(std::sync::Mutex::new(None));`; clone it as `resize_handle` for the event closure; build a bare window: `tauri::WindowBuilder::new(app, "main").title("myharness").inner_size(1200.0, 720.0).min_inner_size(800.0, 560.0).center().on_window_event(move |event| { if let tauri::WindowEvent::Resized(size) = event { if let Ok(h) = resize_handle.lock() { if let Some(wv) = h.as_ref() { let _ = wv.set_size(*size); } } } }).build()?;`; then `add_child` the agent-chat webview: `let agent_chat = window.add_child(tauri::WebviewBuilder::new("agent-chat", tauri::WebviewUrl::App("index.html".into())), tauri::PhysicalPosition::new(0, 0), window.inner_size())?;` (if `inner_size()` returns Result, unwrap it); `let _ = agent_chat.show();`; store: `*agent_chat_handle.lock().expect("agent_chat handle poisoned") = Some(agent_chat);`.
