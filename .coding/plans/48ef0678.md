# Plan: A cancelled regression proof can leave the worker checkout reverse-applied

## Goal
Dropping a regression proof at any point, including while its `git apply -R` is still running, always leaves the worker checkout at its tip with a clean status.

## Kind
bug_fixing

## Context
ROOT CAUSE (verified by reading the code; confirm it with the regression test). prove_regression (src-tauri/src/mnemo2/team/proof.rs ~632) arms a RestoreGuard (~578) and then awaits `git(&checkout, &apply_args)` for `git apply -R` (~722). That `git` is phase3::git (src-tauri/src/mnemo2/phase3.rs:366), which uses tokio::process::Command::output() WITHOUT kill_on_drop. When the proof future is dropped during that await (Mnemo2 closing, a cancelled turn, the test's 5 s timeout on a loaded machine), RestoreGuard::drop restores synchronously (restore_now: reset --hard plus a clean), but the orphaned `git apply -R` child keeps running and reverse-applies AFTER the restore, leaving the checkout modified. The same applies to any other git child the proof awaits after arming the guard.

FIX DIRECTION (decided): every child process the proof awaits while the guard is armed must be killed AND reaped before the guard restores. Use kill_on_drop for those children, and make the guard's Drop wait for an in-flight child to exit (kill, then a blocking wait) before restore_now. A practical shape: a proof-local helper that spawns the git child, registers its handle where the guard can reach it (for example a shared Option<Child> or its pid behind a Mutex), and awaits it; Drop takes the handle, kills it, waits for it, then restores. Don't change phase3::git for every caller; keep the change inside proof.rs unless a small shared helper is clearly cleaner. The existing TreeKillGuard (~397) already handles the regression-script process tree; leave it as it is.

REGRESSION TEST: `dropped_proof_mid_apply_restores_the_checkout` in proof.rs's test module. It must make the reverse-apply slow DETERMINISTICALLY, not through machine load. Add a cfg(test) seam for the program that runs the apply (for example a script that sleeps about 3 s, then runs `git apply` with the same arguments), drop the proof future about 1 s after the apply started, then wait about 4 s and assert: HEAD is the tip, `git status --porcelain -uall` is empty, and src.txt reads "fixed". Without the fix the late apply dirties the checkout, so the test fails on every run regardless of load. Also keep dropped_proof_restores_the_checkout passing.

VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib -- proof::tests` (run the new test 3 times), then the four .coding/checks.toml commands.

## Acceptance scenarios
- A regression proof dropped while its git apply -R is still running leaves the checkout at its tip with a clean status, on every run.
