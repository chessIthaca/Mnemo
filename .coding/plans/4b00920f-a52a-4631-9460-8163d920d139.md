# Plan: Unify browser tabs: one interactive Browser tab + agent CDP control

## Goal
Unify the two browser tabs into one interactive "Browser" tab (the iframe the human sees), fix the URL-normalization bug so google.com loads google, and give the agent navigate/click/type control of that same iframe via CDP attach. Keep the headless Chromium as an agent-only surface (no tab).

## Kind
implementation

## Context
Two separate browser systems exist today. (1) BrowserView (frontend/src/components/views/BrowserView.tsx) drives a separate headless Chromium via BrowserManager launch-mode (src/browser/mod.rs navigate/list_pages/close_page/switch_page/screenshot/console/console_peek/snapshot/eval/click/type_text/close). 10 browser_* tools (src/tool/browser/mod.rs). Works in release. (2) GameView (frontend/src/components/views/GameView.tsx) is an interactive iframe in the app's WebView2; the agent inspects it via BrowserManager connect-mode (webview_screenshot/webview_eval/webview_snapshot/close_webview/ensure_webview/webview_page). 3 game_* tools. Debug-only (CDP port 9222 set in main.rs under cfg(debug_assertions)). THE BUG: GameView sets iframe.src from raw input — "google.com" is a relative path → loads the app SPA fallback (the full UI). The fix (normalize_url, src/browser/mod.rs:972, a private free fn) already turns "google.com"→"https://google.com" but GameView never calls it. USER DECISION: one "Browser" tab = the interactive iframe (human + agent both drive it); keep the headless Chromium as an agent-only surface (no tab) for release/overnight; agent gains navigate/click/type control of the iframe via CDP. The CDP input-dispatch + frame API was supposedly spiked (plan 7f8dfede) but the spike test was NOT kept in the codebase — must re-confirm before building click/type on it. CSP (tauri.conf.json:27-28) already allows frame-src http://localhost:* http://127.0.0.1:* https://* — google.com iframes load fine; the same-origin policy (NOT CSP) blocks the app's main-frame JS from reading a cross-origin iframe's DOM, but CDP (the debug protocol DevTools uses) CAN access cross-origin frames via page.frames() + per-frame execution contexts.
