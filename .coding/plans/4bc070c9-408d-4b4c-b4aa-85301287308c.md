# Plan: Backlog gate: require in-turn workflow transition, not just resting Complete

## Goal
Close the resting-Complete hole: a backlog item may be marked Done only when (a) the main agent's workflow state is Complete at turn resolution AND (b) at least one workflow state transition (WorkflowStateChanged event) was observed for the main agent during that turn — proof the plan loop actually ran ("a change in state and back to the done state"). A turn that rested in Complete the whole time (freeform answers, questions before planning) must NOT mark the item done: run-all → CantResolve with a clear note (no rollback — Complete has no write tools, the tree is provably clean), single/auto-feed → Failed.

## Kind
implementation

## Context
Follow-up to commit 7fff60b (feat/backlog-plan-gate — stay on this branch). User: "that is not enough — sometimes you ask questions in the complete state before getting into planning; it has to have a CHANGE in state and get back into the done state." Hole: plan_loop_allows_done checks WorkflowState==Complete at turn end, but Complete is a RESTING state — a turn that never created a plan (freeform answer / ask_user while resting in Complete) ends Complete and passes. Fix: latch per-turn workflow transitions in TurnResolveLatch (src-tauri/src/ipc/events.rs:58-133, has tests at :586+); the forwarder already observes every WorkflowStateChanged (events.rs:187-195); 4 resolution call sites (events.rs:267, 297, 301, 582) pass the evidence into on_main_turn_resolved (src-tauri/src/ipc/run_all.rs:270). Edge accepted+documented: a Skill excursion from Complete also counts (a change of state and back). Crash-mid-Reviewing resume emits Reviewing→Complete (a change) so legit resumes still count.
