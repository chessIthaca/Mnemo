# Plan: Announce skill start in the transcript (toolbar path) + light display-event refactor

## Goal
When a skill is started from the toolbar (enter_skill / "Merge to main" button), announce it in the agent's transcript like a tool call does — `[>skill "name" start]` — mirroring how skill_end already appears. Lightly refactor so backend-initiated transcript injections (prompt_dispatched, skill_started) share one emit path, and the agent-driven skill_start ToolCard shows the skill name too.

## Context
Two skill-entry paths exist. The agent-driven `skill_start` tool announces via the normal ToolCallStart→ToolResult flow (a ToolCard), but shows a bare "skill_start" with no skill name. The toolbar `enter_skill` Tauri command (StatusBar.tsx:66 → enterSkill → commands.rs:534) calls wf.start_skill + sends AgentCommand::Prompt but emits NO agent event, so the transcript gets nothing — the skill is invisible until get_workflow_state polling updates the status bar. The user wants the toolbar path to announce itself "like a tool," and suggests wiring display to "what is sent to agents/tools."

Existing pattern to mirror: emit_prompt_dispatched (commands.rs:978) — a backend-synthesized SerializableAgentEvent emitted right after sending a command, handled by reducePromptDispatched (useAgentStore.ts:922) which flushes streaming text + pushes a transcript entry. This is the established "display what was sent to the agent" mechanism.

DESIGN (bounded, low-risk):
- Add AgentEvent::SkillStarted { name, prompt } (+ SerializableAgentEvent variant + into_serializable arm + roundtrip test) to channels.rs.
- enter_skill (toolbar): emit SkillStarted right after start_skill succeeds, before sending the Prompt. Add `app: tauri::AppHandle` param (Tauri injects it; frontend invoke unchanged).
- Refactor: extract emit_agent_event(app, agent_id, SerializableAgentEvent) helper in commands.rs; rewrite emit_prompt_dispatched to use it; use it for skill_started too. One shared emit+log path.
- Frontend types.ts: add skill_started to SerializableAgentEvent union; add a `skill` TranscriptEntry kind { kind:"skill"; name:string; prompt:string }.
- useAgentStore.ts: add reduceSkillStarted reducer (flush + push a `skill` entry) + case in applyAgentEvent. Extract a pushTranscriptEntry(agent, entry) helper shared by reducePromptDispatched/reduceSkillStarted/reduceSuggestionInjected.
- Message.tsx: render the `skill` entry as a compact tool-card-like row: `▶ skill "merge_to_main" start` with the goal as a muted subtitle.
- argLabel (Message.tsx:191): add a skill_start branch extracting the `skill` arg, so the agent-driven ToolCard reads "skill_start (merge_to_main)" — both paths now show the skill name.
- Tests: Rust roundtrip for SkillStarted (channels.rs); frontend store test for reduceSkillStarted pushing a skill entry (useAgentStore.test.ts).

DELIBERATE SCOPE CHOICE: emit SkillStarted ONLY from the toolbar path (enter_skill). The agent-driven skill_start tool already announces via its ToolCard (now name-enhanced via argLabel), so emitting a second SkillStarted there would duplicate. Full unification (emit Skill* from turn.rs for the agent path + suppress the ToolCard) was considered but deferred — it adds suppression logic + turn.rs branches + Output-tab naming edge cases for little gain, and the user flagged this as "a little refactoring." Both paths now announce + show the skill name; the toolbar path (the actual bug) is fixed.
