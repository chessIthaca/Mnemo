## Context
RED BASELINE (reproducible): `cargo check --features embeddings` exits 101 at PR #67's head; the two errors are quoted verbatim in the `bug` field. Plain `cargo test` never sees them — fastembed is optional and off by default (Cargo.toml:22 `embeddings = ["dep:fastembed"]`, Cargo.toml:76 `fastembed = { version = "4", optional = true }`) and is selected only by src-tauri. That gap is why the PR's "Analyze (rust)" CodeQL check passed while the feature build fails: build.yml triggers on manual dispatch + v* tags only, and codeql.yml (the sole pull_request trigger) builds DEFAULT features.

ROOT CAUSE: our code, not the dependency — src/memory/embedder.rs was written against the fastembed 4.x API. fastembed 7.1.0 was published 2026-09-22 (crates.io versions API). Its 7.0.0 breaking changes include InitOptions becoming a deprecated alias of TextInitOptions, candle models caching under FASTEMBED_CACHE_DIR instead of ~/.cache/huggingface/hub, and changed image-embedding behavior for non-square inputs.

FIX SHAPE (contained, one file + the manifest):
- `model: Arc<fastembed::TextEmbedding>` at src/memory/embedder.rs:148 becomes `Arc<std::sync::Mutex<fastembed::TextEmbedding>>`; the Arc exists so the model can move into the `spawn_blocking` closure (line 216), and a std Mutex is safe there because that closure is SYNC — no guard ever crosses an `.await`.
- src/memory/embedder.rs:168 `fastembed::InitOptions::new(model)` -> `fastembed::TextInitOptions::new(model)`; keep `.with_cache_dir(...)` unless the 7.x API renamed it (the compiler is the spec — the 7.0.0 cache-dir notes make this worth a deliberate check).
- Keep the `Embedder for BundledEmbedder` trait impl's `&self` signature and the failure contract at src/memory/embedder.rs:215-242 (inference failure -> zero vector + status Fallback; dimension mismatch -> same) untouched.

REGRESSION-TEST DESIGN (no runtime test can assert a compile failure, so state this honestly): the red-check IS the feature-enabled compile — `cargo check --features embeddings` exits 101 before the fix and 0 after — paired with `cargo test --features embeddings` staying green. That is the same class of evidence the repo already accepts for compile-shaped defects (the vendored-patch guards in src-tauri/tests/ assert source-level invariants for exactly this reason). The durable prevention is the agent.md note in step 5, not a new unit test.

GUARD TO PRESERVE: tests/integration/ci_workflow.rs:304 `cargo_lock_keeps_the_vendored_patches` asserts the Cargo.lock carries no `[[patch.unused]]` and keeps tao/wry path-sourced from vendor/ — the fastembed bump must not disturb it (it should not: fastembed does not touch the tauri graph).
