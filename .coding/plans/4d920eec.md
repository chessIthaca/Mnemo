# Plan: Claude Code agents run in warm Mnemo pools through Claude's own worktree isolation

## Goal
An agent-tier step runs as an ordinary Claude Code agent with isolation "worktree": Claude Code shows it in its own folder, while that folder is the worker's warm Mnemo pool on its wt/agent-* branch, handed out by Mnemo's WorktreeCreate hook. At most 3 agent workers run at once, the agent prompt no longer uses Mnemo tools, and pools are released as soon as their worker no longer needs them.

## Kind
implementation

## Context
WHY (2026-11-22). Claude Code agent workers today run in the Mnemo pool checkout from the claude_agent block, while Claude Code thinks they work in the lead's folder: every shell command needs `cd "<pool>" &&`, every path is absolute, and Claude Code can't show the agent's changes or branch as its own. Launching them with Claude Code's own isolation instead ("isolation": "worktree") shows them properly but makes a new cold folder every time (FactoryGame: 22-25 GB cold builds per agent worktree, never reused). Warm builds only come from reusing a pool folder with its target/: sccache gives no hits across build folders on this machine (FactoryGame measured 0 of 396), and copying a target/ between folders does not help because cargo records absolute paths.

TESTED (scratch repo, 2026-11-22): a WorktreeCreate hook in project settings fired for an `isolation: "worktree"` subagent and printed the path of an EXISTING git worktree (a pool on branch wt/agent-test1 with target/WARM_MARKER). Claude Code accepted it without error: the agent's pwd was the pool, it saw the marker, and it was on the pool's branch. Claude Code created no folder of its own, and WorktreeRemove never ran when the agent ended (documented: hook-made subagent worktrees are kept). The hook input was {session_id, transcript_path, cwd, hook_event_name, name, prompt_id, scratchpad_dir}, and `name` was `agent-<agent id>`, the same id as the agent transcript file `agent-<id>.jsonl`. NOT yet tested: whether a hook shipped in a PLUGIN fires for subagents (only a project-settings hook was tested). Step 1 settles that before anything else is built.

PLUGIN CACHE (found 2026-11-22). Claude Code runs the Mnemo plugin from the copy `claude plugin install` made in ~/.claude/plugins/cache/mnemo/mnemo/<version>/ (today 2.5.0 from 2026-11-16; installed_plugins.json names its installPath). scripts/install-mnemo2-mcp.mjs refreshes only the helper binary, so the cached skills/ and hooks/ are stale: today's skill guidance and any new hook are not live until the cache is refreshed.

DECISIONS:
1. Hook commands. `mnemo2-mcp worktree-create` and `mnemo2-mcp worktree-remove` (src-tauri/mnemo2-app/src/mnemo2_mcp/hooks.rs), wired in mnemo2/plugin/hooks/hooks.json as WorktreeCreate and WorktreeRemove (timeout 60). worktree-create reads the hook JSON from stdin, asks the Mnemo2 instance serving `cwd` over its existing local HTTP route (new route `/lead/worktree-claim`, body {root, name, transcript_path}) for a folder, prints the folder as the LAST stdout line (diagnostics to stderr only), exits 0. A failure to claim from a Mnemo project with a waiting agent worker is an error (exit non-zero, reason on stderr), never a silent fallback.
2. Fallback. When no Mnemo2 instance serves `cwd`, or Mnemo answers {"fallback": true} (no agent worker is waiting), the hook makes the folder Claude Code itself would make: `git worktree add -b worktree-<name> <repo root>/.claude/worktrees/<name> HEAD` (git worktree add, run in the repo root that `git rev-parse --show-toplevel` gives for cwd), and prints it. worktree-remove removes only such fallback folders (path under <repo root>/.claude/worktrees/): `git worktree remove --force <path>` then `git branch -D worktree-<name>`; for any other path (a Mnemo pool) it does nothing and exits 0, because Mnemo releases pools itself.
3. Claim. TeamRuntime gets `claim_agent_checkout(name, transcript_path) -> Result<ClaimAnswer, String>` where ClaimAnswer is Pool{worktree} or Fallback. It takes the merge lock and picks the single agent worker that is Working or Fixing with claude_agent set and no claude_agent_id ("waiting for its agent"). It sets claude_agent_id = name without the "agent-" prefix and claude_agent_transcript = <transcript_path's folder>/<session id>/subagents/agent-<id>.jsonl only when that path passes agent_watch's confinement check (otherwise leaves it None so the watcher's glob finds it), persists, starts the agent watch (ensure_agent_watch), and returns the worker's worktree. No waiting worker → Fallback. The claim replaces team_agent_started for agents launched through the hook; team_agent_started stays for a manual re-registration.
4. One waiting agent at a time. A dispatch (or a hand-off by team_resume, auto escalation or usage-limit resume) that would create a second agent worker waiting for its agent is refused with `<waiting id> is waiting for its agent: launch it (Agent with isolation "worktree") before dispatching another agent step.`, so a launch can never be matched to the wrong worker. A team_message or team_route_fix continuation on an agent worker that already has claude_agent_id does not wait for a new launch and is unaffected; one on an agent worker WITHOUT a registered agent clears nothing and tells the lead to launch a new Agent with isolation "worktree" (the claim then hands it the same pool).
5. Cap. At most 3 agent workers that are Working or Fixing at once (AGENT_WORKER_CAP = 3, a constant, no setting). A dispatch or hand-off that would exceed it is refused with `3 Claude Code agent workers are already running (<ids>); wait for one to finish (team_agent_done) before starting another.`.
6. Plain agent prompt. agent_prompt (record.rs) drops the "Work only inside <worktree> ... cd" rule, the team_progress milestone rule and the "plan_show and team_progress are the only ones you may use" rule; it says instead: "You run in your own checkout of this project on branch <branch>; commit your work there." and "Do not use Mnemo's team_* or plan_* tools." The claude_agent block keeps {model, effort, worktree, branch, prompt} and adds "isolation": "worktree". The agent_continue_prompt paragraph (hand-off) is unchanged except it no longer names a folder.
7. Gate. The agent gate (mcp_server.rs gate_agent) answers "ask" with reason `Launch Mnemo agent workers with isolation "worktree" so they get their warm checkout.` when an agent worker is waiting for its agent and the Agent call has no isolation "worktree"; otherwise unchanged.
8. Pool leaks. held_checkouts (team.rs) stops counting (a) an audit that has reported (report_delivered) and (b) a worker that is Stopped or Failed whose plan step is already done on the board. When an audit reports, its pool is released (release_pool_checkout: detached, caches kept) and its record's worktree cleared, like a merge does; its report and record stay. A Stopped/Failed worker on a done step is released the same way the next time a pool is provisioned (provision_worker sweeps them first) so no background job is needed.
9. Plugin cache. scripts/install-mnemo2-mcp.mjs also refreshes the installed plugin copy: for each entry of ~/.claude/plugins/installed_plugins.json whose key starts with "mnemo@", copy mnemo2/plugin/{hooks,skills,.claude-plugin,.mcp.json,README.md} over its installPath (bin is already handled). It prints what it refreshed; a missing file is skipped silently.

ANCHORS: provision_worker (team/spawn.rs ~156), provision_agent_checkout / release_pool_checkout (src/app/worktrees.rs), held_checkouts (team.rs ~385), claude_agent_dispatch (routing.rs), claude_agent_block (dispatch.rs), agent_prompt / agent_continue_prompt (record.rs), agent_started / confined / ensure_agent_watch (agent_watch.rs), hand_to_agent_locked (control.rs), gate_agent (mcp_server.rs ~1061), hooks.rs and serve/http in src-tauri/mnemo2-app/src/mnemo2_mcp/, mnemo2/plugin/hooks/hooks.json, scripts/install-mnemo2-mcp.mjs.

VERIFY: the four .coding/checks.toml commands, plus a real run (step 6).

## Acceptance scenarios
- Launching an agent-tier step's Agent with isolation "worktree" runs it in the worker's warm Mnemo pool on its wt/agent-* branch, and Claude Code shows it as the agent's own worktree.
- The WorktreeCreate hook registers the agent (id and transcript) with Mnemo without team_agent_started.
- An isolated agent that is not Mnemo work, or any agent outside a Mnemo project, gets a normal .claude/worktrees folder from the hook.
- A second agent dispatch while one agent worker still waits for its launch is refused, and so is a fourth running agent worker.
- A reported audit and a stopped worker on a done step free their pool, and the next dispatch reuses it with its build output.

## Spec changes

### external-lead

#### ADDED Requirements

##### Requirement: Agent workers get their warm checkout through Claude Code's worktree isolation
When Claude Code leads and launches an agent worker's Agent with isolation "worktree", Mnemo's WorktreeCreate hook SHALL hand Claude Code the worker's Mnemo pool checkout and SHALL register the agent with the worker. Outside Mnemo work the hook SHALL create the folder Claude Code would create itself.

###### Scenario: Isolated agent worker
- **WHEN** an agent worker waits for its agent
- **WHEN** the lead launches an Agent with isolation "worktree"
- **THEN** the agent runs in the worker's pool checkout on its branch
- **AND** the worker records the agent's id

###### Scenario: Other isolated agent
- **WHEN** no agent worker waits for its agent
- **WHEN** an Agent starts with isolation "worktree"
- **THEN** the hook creates a folder under .claude/worktrees

### dispatch-routing

#### ADDED Requirements

##### Requirement: Agent worker dispatches wait for the previous launch and are capped
A dispatch or hand-off that would leave a second agent worker waiting for its agent SHALL be refused, and so SHALL one that would make more than three agent workers run at once.

###### Scenario: Second waiting agent
- **WHEN** one agent worker waits for its agent
- **WHEN** the lead dispatches another agent-tier step
- **THEN** the dispatch is refused and names the waiting worker

###### Scenario: Cap of three
- **WHEN** three agent workers are Working or Fixing
- **WHEN** another agent-tier dispatch arrives
- **THEN** it is refused

### worker-brief

#### ADDED Requirements

##### Requirement: Agent prompts use no Mnemo tools
The prompt of an agent worker SHALL tell the agent to commit on its branch in its own checkout and SHALL NOT ask it to use Mnemo tools or to change directory into a checkout.

###### Scenario: Plain agent prompt
- **WHEN** an agent-tier step is dispatched
- **THEN** the claude_agent prompt names the branch
- **AND** it names no team_* or plan_* tool and no cd rule

### tier-ladder

#### ADDED Requirements

##### Requirement: Pools return to the ladder's workers when no worker needs them
A pool checkout held by an audit that has reported, or by a stopped or failed worker whose plan step is done, SHALL be released with its build output kept, so a later dispatch on any tier can reuse it warm.

###### Scenario: Reported audit
- **WHEN** an audit worker delivers its report
- **THEN** its pool is released and its record keeps the report

## Decisions
- 2026-11-22: Step 1 result (2026-11-22): YES. A WorktreeCreate hook in the Mnemo plugin's hooks.json fired for an isolation "worktree" subagent in a new desktop session and handed it the existing scratch pool; the agent ran there (pwd = the pool, saw target/WARM_MARKER, branch wt/agent-test1), with no error. The Claude desktop app loads the Mnemo plugin straight from the repo (D:\Mnemo\mnemo2\plugin, the 'directory' marketplace), not from ~/.claude/plugins/cache: the same hook placed only in the cache copy never ran. So decision 9 matters only for the command-line `claude` (which uses the cache); keep it as a cheap refresh, but desktop sessions already see repo edits to skills and hooks at their next start.
- 2026-11-22: Step 3 (2026-11-22): the agent prompt also replaces "Run the commands in .coding/checks.toml exactly as written before your last commit" with narrow verification ("Verify with the narrowest tests that cover your change ... Mnemo runs the full checks in .coding/checks.toml on your final commit"): agents run outside Mnemo's heavy slots, so full suites from several agents would contend; the clean review's automatic team_run_checks runs the full set once. When the waiting rule or the cap blocks an automatic hand-off (auto escalation, usage-limit resume), Mnemo falls back to today's model switch on that tier instead of failing; an explicit team_resume onto an agent tier is refused with the reason.
- 2026-11-22: Step 4 (2026-11-22): pools are released by one sweep, release_idle_checkouts (team.rs), that runs right before a pool is handed out (provision_worker and the audit provisioning), instead of releasing an audit's pool at the moment it reports. The effect for reuse is the same and there is a single code path. Also fixed: active_workers_for_slots now counts Fixing agent workers.
