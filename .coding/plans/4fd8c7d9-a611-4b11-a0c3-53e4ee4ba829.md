# Plan: Memory learning agent: prompt strategy + consolidation fix + config-gated memory display

## Goal
Make the agent a genuine learning agent: (1) revise the system prompt so it efficiently explains the process AND gives concise tool-strategy guidance for every tool (especially when to proactively memory_write distilled facts); (2) review the memory system and fix the manual memory_consolidate tool so it does full semantic/procedural extraction (not synthetic-only); (3) add a config-gated memory-activity display so memory reads/writes print as readable lines in the agent window when the user opts in.

## Kind
implementation

## Context
Investigation findings (all verified by reading code):

PROMPTS (src/agent/prompt.rs): The stable head (CODING_SYSTEM_PREAMBLE + WORKFLOW_LIFECYCLE + APP_RULES) explains the *process* well but gives tool *strategy* ("when to use which tool") for only a handful: create_plan, complete_step, file_edit, read_files, file_write/file_append. Tools with NO strategy guidance: memory_write/recall/consolidate, search/search_read, spawn_agent, ask_user, browser_*, describe_image. The memory tools especially need guidance — the model has memory_write but isn't told to proactively persist distilled project facts (semantic/procedural) when it learns something durable. This is the biggest "learning agent" gap: recall/consolidation machinery is solid, but the model isn't prompted to FEED it distilled facts.

MEMORY SYSTEM (src/memory/): Four-tier (working/episodic/semantic/procedural), SQLite+FTS5+in-Rust vector. Solid: per-turn auto-recall (top-5, turn.rs:264), session primer (top-8 strongest, turn.rs:330), working-memory capture (durable tools only, is_durable_tool), consolidation at session end (spawn_consolidation, agent.rs:401 — already automatic, passes Some(provider)), crash-safe episodic capture at Complete (turn.rs:1216). Stale-working-tier issue already remediated (working excluded from recall by default, decayed strength, tier weight 0). REAL GAP: the manual memory_consolidate TOOL (tool/memory/mod.rs:245) calls consolidate_session(..., None) — synthetic-only, no semantic/procedural extraction — because MemoryConsolidateTool::new(store) (factory.rs:549) gets no provider handle. The automatic session-end path is strictly better. Fix: give the tool a swappable provider handle (mirror DescribeImageTool/SwappableVision pattern) so manual consolidation matches automatic.

MEMORY DISPLAY: Every tool call (incl. memory_write/recall/consolidate) already emits a ToolResult event → renders as a collapsible ToolCard (Message.tsx ToolCard). There is NO config toggle controlling this. User wants: a config toggle (in the config dialog) that, when ON, prints memory read/write activity as a dedicated readable memory-activity line (tier/title/content snippet) in the agent window; when OFF (default), memory tool calls are not printed (hidden — they're bookkeeping). Config home: [ui] section (alongside show_token_usage), rendered in AppearanceSection.tsx.

FRONTEND event flow: SerializableAgentEvent → useAgentStore.handleAgentEvent → agentEventReducer.ts pure reducers (reduceToolCallStart pushes a "tool" transcript entry; reduceToolResult updates it + emits toolOutputEntry effect). TranscriptEntry kinds (types.ts): user/assistant/tool/error/steer/skill/qa. To add a readable memory-activity line, add a "memory" TranscriptEntry kind + emit it in reduceToolResult when the tool is memory_write/recall/consolidate AND the showMemoryActivity flag is on; suppress the generic ToolCard for memory tools when the flag is off. The flag must be readable inside the pure reducer → carry it on AgentState (set when config loads).

CONFIG flow: UiConfig (src/config/general.rs) has theme + show_token_usage. GetSettingsUi (src-tauri/src/ipc/settings.rs) mirrors it. save_settings patch DTO carries optional overrides. Frontend tauri.ts types + useAgentStore state + AppearanceSection render the [ui] fields. Add show_memory_activity: bool (default false) through this whole chain.

This is an implementation plan (changes source code) → review required at completion.
