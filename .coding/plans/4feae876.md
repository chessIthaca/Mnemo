# Plan: Panel widths are saved as whole pixels

## Goal
Every panel width Mnemo2 stores or saves is a whole number of pixels, so preference saves never fail on fractional mouse positions.

## Kind
bug_fixing

## Context
Why: on scaled displays pointer coordinates are fractional, and the drag handlers compute widths from them; the backend `ProjectPreferences` fields `workbench_width: u32` and `board_width: Option<u32>` (`src-tauri/src/mnemo2/project.rs`) reject floats, so the save fails.

Verified facts:
- verified: the error popup text above, recorded at ts 1793638591646 with route "team" in `.coding/logs/mnemo2-ui.jsonl`.
- verified: `mnemo2/src/lib/store.ts`: `clampWorkbenchWidth` (line ~1193) and `clampBoardWidth` (~1238) return `Math.min/Math.max` of the incoming value without rounding; `setWorkbenchWidth` (~1197), `reclampWorkbenchWidth` (~1209), `setBoardWidth` (~1248), `reclampBoardWidth` (~1260) store the clamped value; the save sends `workbench_width: state.workbenchWidth` and `board_width: state.boardWidth` (~404-407). Drag callers: `Workbench.svelte`/`WorkerPanel.svelte` (`window.innerWidth - event.clientX`) and `ControlRoom.svelte` (`dragStartWidth + (event.clientX - dragStartX)`).
- verified: `defaultBoardWidth` already rounds (`Math.round(windowWidth * DEFAULT_BOARD_SHARE)`, ~line 1244).

Fix: round inside `clampWorkbenchWidth` and `clampBoardWidth` (so every setter and re-clamp yields an integer), and round the two widths again where the preference payload is built as a last line of defence. Frontend only.

Regression test (to be written by the worker; it does not exist yet): a vitest named `panel_widths_are_saved_as_whole_pixels` in `mnemo2/src/lib/store.workbenchWidth.test.ts` that sets fractional workbench and board widths and asserts the stored widths and the saved preference payload are integers; it must fail before the fix.

Verification: in `mnemo2/`: `npx svelte-check --tsconfig ./tsconfig.json`, `npm run check:no-mock`, `npx vitest run`. Never start a dev server or any command that does not exit on its own.

## Acceptance scenarios
- Dragging the side panel or the mission control divider on a scaled display never shows the 'Could not save workbench preferences … expected u32' popup, and the width is remembered.
