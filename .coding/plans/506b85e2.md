# Plan: DeepSeek: stop folding the volatile tail into the leading system message (cache reset per check-off)

## Goal
Restore DeepSeek prefix-cache reuse across plan-item check-offs: stop folding the volatile tail into the leading system message. For fold vendors (DeepSeek-vendor + Local/Ollama) messages[0] stays the byte-stable stable head, and the volatile tail + constant CONTEXT_FOOTER ride at the end as USER-role messages, so complete_step progress bumps cost only the tail instead of re-reading the whole ~100-120K-token history. Keep the echo-safe invariant (no trailing system block) and the single policy flag as the rollback.

## Kind
bug_fixing

## Context
ROOT CAUSE (confirmed, fixed): `ProviderPolicy::fold_volatile_tail = true` for DeepSeek-vendor (`src/provider/policy.rs:429`) made `src/agent/turn.rs` append the volatile tail (workflow PROGRESS / CURRENT STEP / recalled memories — `prompt.rs::build_volatile_tail:541`) into messages[0] and skip both trailing pushes. Every progress bump therefore mutated the leading system message and the provider's prefix cache died at ~6.9K tokens (tools array + head prefix), re-processing the whole history.

FIX DESIGN (user-approved, "trailing user-role annex"): for fold vendors messages[0] is the pure stable head and the volatile tail + constant CONTEXT_FOOTER ride at the END as USER-role messages — the request still ends the way a normal client turn does (the echo trigger was the SYSTEM role in the tail position), and the footer stays the byte-stable final message so the empirical cache law (`prompt.rs:526-540`) holds.

Landed design — (1) `ProviderPolicy::tail_as_user_messages` (renamed from `fold_volatile_tail`; the old name described a fold that no longer happens) marks vendors that must not receive trailing SYSTEM messages: DeepSeek-vendor (echo/mirror) and Local/Ollama (a system message may occupy first position only). (2) `AgentLoop::tail_is_user_role` (`src/agent/turn.rs`, `pub(crate)`) is the SINGLE decision point — `ProviderKind::Local || policy.tail_as_user_messages` — replacing the duplicated inline `is_local || …` computation. (3) `install_system_messages` no longer touches the head when building messages[0]: the head is installed identically on every vendor, and the volatile tail + CONTEXT_FOOTER are pushed after the history as `Message::user_text` (user role) for those vendors / `Message::system` elsewhere; both are still popped right after the request — the function's `-> bool` return and the caller's conditional pops are gone (the caller now always pops twice). (4) `AgentLoop::push_suggestion_message` (`pub(crate)`) routes all THREE text-only suggestion-steer sites (`handle_pending_swap`, the summarization re-injection, `runtime/agent.rs::compact_context`) through the same role decision, closing the review 2026-09-11 L2 residual that previously accepted a trailing system block there. (5) Test-helper change: `CapturingProvider` gained `captured_trailing` (role, content of the last two messages) + `trailing_handle()`; the constructors' signatures are unchanged. (6) Invariants to preserve: messages[0] is byte-stable across progress bumps; the final message is always CONTEXT_FOOTER; no trailing SYSTEM message may exist on `tail_as_user_messages` vendors; the empirical cache law (constant last message) still governs the footer. (7) Docs moved with the code: `prompt.rs` (CONTEXT_FOOTER + build_stable_head + build_volatile_tail docs), `policy.rs` (field + deepseek() docs), `PLAN.md:188-197`.
