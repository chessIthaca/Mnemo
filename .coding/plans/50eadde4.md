# Plan: Laya routing learns: real confidence, every model change recorded, kNN overlay, mode that saves

## Goal

## Context
\## Why (facts verified live on 2026-11-04)
1. **Wrong confidence field.** A live `/v1/systemone` answer looks like `{"answers":{"question":{"type":"choice","choice":"hard","probabilities":{"trivial":0.0328,"routine":0.0559,"hard":0.9113},"confidence":0.6742,"answer_confidence":0.9113,...}}}`. `answer_confidence` is the top probability (floor 1/labels), which the design's gates (`DEFAULT_MIN_CONFIDENCE_3` 0.475, `_2` 0.60 in `src/agent/route_question.rs`) are calibrated for. Mnemo's parser `src/memory/classifier.rs` `parse_answer_for` (~348) reads only `confidence` (a lower, margin-like score), so routing gates almost never clear. The parser already keeps `probabilities` in `Answer::Choice { label, confidence, probabilities }`. Routing consumers: `src-tauri/src/mnemo2/dispatch_routing.rs` `classify_dispatch` (~196, destructures at ~203, `cleared` at ~212), `src-tauri/src/mnemo2/route_eval.rs` (~469), `src/agent/model_routing.rs` (~137, Mnemo1 route-once). Do NOT change `parse_answer_for` or `Answer`: failure triage, auto-typing and tool-choice gates are calibrated on `confidence` and must not move.
2. **Model changes are not recorded.** The user switched worker quitRoute172 from the difficult tier (Kimi) to deepseek-v4.1-flash in mission control. `TeamRuntime::change_model` (team.rs ~4281) built a reroute row (`reroute_row` ~4203), pushed it to `worker.reroutes` and set `worker.tier = None`, but appended nothing because `logs_routing(record, mode)` (team.rs ~854: `record.routing.is_some() || mode != Off`) is false with routing off; `~/.mnemo/laya/training/dispatch_routing.jsonl` does not exist. The earlier decision "off mode writes nothing" (memory: routing-row gating fix, P1) is **superseded by the user's instruction (2026-11-04): a user or lead model change is a learning and is always recorded.** New rule: reroute rows (user and lead) are appended in every mode, and a worker that has at least one reroute also gets its terminal outcome row in every mode (outcome labels are what the kNN learns from). Laya-derived rows (`route`, `nudge`, etc.) stay gated as today. Also `team_status` shows `tier: null` after a switch; set `worker.tier` to the destination tier when the new model belongs to a tier (keep None for a custom model), and make sure `final_tier` still works.
3. **The mode never saved.** The user picked Shadow on Settings > Laya, but `~/.mnemo/mnemo2.toml` does not exist, so the mode is Off. `mnemo2/src/components/LayaPage.svelte` keeps the mode in `dispatchDraft` (`selectMode` ~295, `forceMode` ~302) and only writes on the separate "Save dispatch routing" button (~572), one of three Save buttons on the page ("Save flags" ~465, "Save routing" ~680). Picking a mode must save at once through the existing `saveDispatch()` path (Tauri `save_routing_settings` → `apply_routing_settings`, which also reloads the open team), showing the existing "Saved to mnemo2.toml." note or the error; a failed save reverts the radio to the saved mode. Other draft fields keep their Save button, and the page warns before navigating away with unsaved dispatch edits.
4. **No fine-tune is possible in-app.** The managed venv has laya 0.3.20 with no `laya.finetune` module (src-tauri/src/ipc/finetune.rs already treats that as "ineligible"). The in-repo online-learning pattern is `src/agent/failure_triage_knn.rs` `KnnClassifier`: embed the text with the app's shared embedder, retrieve the K nearest labelled rows from the JSONL (re-indexing only new rows when the file grows), majority vote, vote share = confidence, consulted before Laya, `None` on cold start. Build the same for dispatch routing.

\## Design of the kNN overlay (step 4)
- New `src/agent/route_knn.rs`: `RouteKnn` reads `dispatch_routing.jsonl` and indexes rows that carry a routing text and a trustworthy tier label: terminal outcome rows with a derived label (`outcome_label`), user/lead reroute rows (label = destination tier; text = that worker's route text, joined by worker_id from its route row when the reroute row has no text), and lead_override rows (label = lead tier). Labels are tier names; map them to the offered labels with the existing `route_question` folding, and skip labels for tiers no longer offered.
- `classify_dispatch` asks the overlay first: a vote whose share is ≥ `knn_min_share` (default 0.80, `[routing] knn_min_share` in mnemo2.toml) with at least `knn_min_rows` (default 30) indexed rows answers with source `knn`; otherwise Laya answers as today. The route row records `source: "knn" | "laya"` and the vote (`knn_label`, `knn_share`, `knn_k`).
- Cold start or an embedder failure → `None` → Laya. Never panics, never blocks dispatch beyond the existing 3 s classification timeout.
- Eval (`route_eval.rs`) reports Laya-only and kNN+Laya accuracy side by side.

- A Laya answer with probabilities {hard: 0.91, routine: 0.06, trivial: 0.03} and confidence 0.67 is logged and gated with confidence 0.91 and clears the 3-label gate of 0.475.
- With routing Off, switching a worker's model in mission control appends one user reroute row to ~/.mnemo/laya/training/dispatch_routing.jsonl, and team_status shows the destination tier, not null.
- Clicking Shadow on Settings > Laya writes mode = "shadow" to ~/.mnemo/mnemo2.toml without pressing another button.
- With at least 30 labelled rows whose texts are close to a new brief and agree on one tier (≥ 80% of K), the route row says source knn with that tier; with no labelled rows it says source laya.
- Failure triage and memory auto-typing still gate on Laya's `confidence` field (unchanged behaviour).
