# Plan: A worker folder Mnemo2 cannot delete names what holds it

## Goal
When Mnemo2 gives up removing a worker's checkout folder on Windows, the error names the processes that hold files in it (name and pid), so the user knows what to close; elsewhere the message stays as today.

## Kind
implementation

## Context
WHY: in the 2026-11-01 session two worker folders stayed behind after delete with "os error 32" (file in use). The cause was the lead's own shell and a running Vite preview sitting inside the folder, but the message did not say so; finding the holder took guesswork.

FINDINGS (probed while planning):
- verified: remove_leftover_checkout in src-tauri/src/mnemo2/team.rs (near line 4153) already revalidates and retries remove_dir_all 12 times, 250 ms apart, then returns "could not remove leftover checkout <path>: <last error>". The merge and delete paths and the startup sweep (around line 5055) report that string.
- verified: windows-sys 0.61 is already a Windows-only dependency of src-tauri (src-tauri/Cargo.toml line 83-84); the Restart Manager API (RmStartSession, RmRegisterResources, RmGetList, RmEndSession) lives behind the Win32_System_RestartManager feature.
- verified: earlier work (DECISION: worker checkout removal waits for every owner of the worktree code graph) already releases Mnemo2's own handles before removal; this plan only improves the final error.

DECISIONS:
- New module src-tauri/src/mnemo2/lock_holders.rs with `pub fn holders(paths: &[PathBuf]) -> Vec<LockHolder>` (name, pid). On Windows it uses the Restart Manager on the files under the folder (cap the list at a few hundred files, newest first or any order, so a node_modules tree cannot stall it); on other platforms it returns an empty list.
- remove_leftover_checkout appends "; held by <name> (pid N), ..." when holders are found, and "(no process found holding it)" otherwise. Never kills or closes anything.
- Best effort: any Restart Manager failure yields an empty list, never a different error.

VERIFY:
- cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::
- cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests clean
- A Windows-only test opens a file in a temp folder, calls holders on it, and finds the test's own pid.
- Fresh worker worktrees need `npm ci --no-audit --no-fund` at the worktree root first.

## Acceptance scenarios
- On Windows, holders() on a folder with a file the test process keeps open returns an entry with the test's own pid.
- remove_leftover_checkout's final error names the holding processes when any are found.
