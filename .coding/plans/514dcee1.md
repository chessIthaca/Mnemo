# Plan: Add structured `restore` subcommand to the git tool

## Goal
Add a `restore` subcommand to the git tool (structured fields: paths/source/target) so agents can restore files from a ref or discard uncommitted/staged changes without the shell tool — no free-form args on write subcommands, per the read-only-args decision.

## Kind
implementation

## Context
Follow-up to DECISION 2026-08-27 (git tool args is read-only): the clean way to support `git checkout -- <path>`-style restores is a structured subcommand, not free-form args. Design grounded in src/tool/agent/git.rs (1780 lines): subcommands resolve forgivingly via resolve_git_subcommand (GIT_SUBCOMMANDS at :77, consumed only in this file); GitArgs (:59) has message/branch/remote/args; the write-subcommand args gate at :481 errors loudly for any non-read subcommand with non-empty args (restore inherits this automatically — no change needed there); validation helper valid_branch_name (imported from crate::project::git_ops, rejects leading '-' and whitespace) is reusable for tree-ish sources like HEAD~1/abc123/v1.0. Dispatch arms run :489-669; tests live in the same file's tests module with an init_repo tempdir fixture. Frontend: argLabel git branch in frontend/src/components/chat/Message.tsx:423 (exported), tests in frontend/src/components/chat/messageArgLabel.test.ts (git describe block at :14). Rationale: restore DISCARDS uncommitted work, so it takes structured fields only (paths array, source tree-ish, target enum) with flag-shaped values rejected — never free-form args. Not a core operation (needs the normal NeedsApproval prompt like checkout, not the merge/push hard gate).
