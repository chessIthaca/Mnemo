# Plan: Drop the specialized (Ollama) embedding model — use HashEmbedder only

## Goal
Remove the external Ollama embedding model from the memory system so memory recall never depends on a reachable/authenticated external service. The store keeps its SQLite + FTS5 + in-Rust cosine architecture but always uses the built-in deterministic HashEmbedder. Remove the now-dead `[memory]` config section, the `OllamaEmbedder` code, and the IPC/Settings plumbing for embedding_model/embedding_provider. Existing user config.toml `[memory]` sections are silently ignored on load (no deny_unknown_fields) and dropped on next save.

## Context
Bug: memory_recall fails with "ollama embed returned status 401 Unauthorized" — OllamaEmbedder sends no auth and there is no runtime fallback, so recall dies. User decided they don't need a specialized embedding model. History note: OllamaEmbedder + embedding BLOBs were in the initial commit (c449dd6), so this is a removal, not a revert. Scope surface (all found via search): src/memory/embedder.rs (OllamaEmbedder struct/impl + normalize_ollama_base + test), src/memory/mod.rs (re-export), src/config/general.rs (MemoryConfig + GeneralConfig.memory field + 2 tests), src/config/mod.rs (3 test fixtures + 1 assert), src/provider/client_factory.rs (build_embedder + import + 2 tests), src-tauri/src/main.rs (call site), src-tauri/src/ipc/commands.rs (get_settings memory block, patch struct fields, validation block, apply lines, rewire eprintln). No frontend references to embedding settings. MemoryStore keeps its Embedder trait + set_embedder/embedder_handle plumbing (valid abstraction, harmless, always holds HashEmbedder now) — not refactoring the store internals. Note for user: any pre-existing rows embedded by Ollama live in a different vector space than HashEmbedder, so their vector scores become noise (FTS5 keyword match still works); optionally delete memory.db to reset.

REVIEW FINDINGS (main-agent self-review, since the spawned reviewer subagents could not write their reports — see the gating bug below):
1. CORRECTNESS/BUG (frontend, real): The backend removed `embedding_model`/`embedding_provider` and the `memory` block from get_settings, but the FRONTEND still references them. `MemorySection.tsx` reads `s.memory.embedding_model`/`embedding_provider` (now undefined → runtime crash) and a whole Memory settings tab; `AdvancedSection.tsx` import path sends `patch.embedding_model`/`embedding_provider`; `tauri.ts` AppSettings + SettingsSavePatch types still declare the fields; `types.ts`/`types.test.ts` reference `memory`. Must remove the Memory tab + all these references for consistency.
2. BUG (tool gating, real, blocks our own review): `Workflow::allowed_tools()` (src/workflow/mod.rs:183-187) early-returns `ToolFilter::Planning` when `plan_mutations_allowed` is false (sub-agents). The Planning filter only allows `SafetyLevel::AutoRun` agent tools, so EVERY sub-agent is denied all write/exec tools (file_write, file_edit, file_append, shell, git, spawn_agent, describe_image) even in Executing state. This is why the reviewer subagents could not file_write their reports. The Phase 4 "main-agent-only plan mutations" intent was to restrict ONLY the four plan-mutation tools — which is already enforced in FOUR other places (dispatch.rs:113, turn.rs:295 retain, plan.rs wrappers, prompt.rs). The allowed_tools() collapse is an over-broad regression. Fix: derive the filter from the real state normally; leave plan-mut restriction to the existing targeted gates. No test codifies the buggy Planning-for-subs behavior.
