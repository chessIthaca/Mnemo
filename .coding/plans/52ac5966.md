# Plan: Escalation lane ladder — user-chosen per-lane models + step-granular routing (backlog ad56c7bd)

## Goal
Ship the escalation lane ladder (backlog ad56c7bd): user-chosen per-lane models — lane_medium/lane_high/escalate as optional ModelRefs in [general.routing] (never hardcoded or built-in ids; unset falls through to the main default model) — plus step-granular routing: at each plan-step boundary the compound reflex call classifies the step and resolves the lane cheap → default → medium → high → escalate, re-classifying only after a failed cycle (a confident failure_triage permanent/flaky_test verdict is the escalation trigger — never before the first attempt). DESIGN DECISIONS (decided, rationale):
- Lane targets live in RoutingConfig ([general.routing]) — the item allows 'or sibling [general.lanes]', but the Settings UI extends the EXISTING routing block (one surface, one Settings section) and the resolver already reads this section per request. NEVER built-in ids: fields default None, only user picks populate.
- NO new opt-in flags: the ladder arms under [general.laya] routing (the routing surface; also the source of enforce + threshold via routing_policy()) AND [general.laya] reflex (ReflexHandle self-gates: flag off = zero classifier calls). Shadow-first = [general.routing] enforce false (classify + log, model never switched). Confidence gate = the reflex call's own 0.80 gate (REFLEX_THRESHOLD, inclusive).
- Lane resolution: complexity small→RouteTarget::Cheap (the existing cheap target), medium→Medium, high→High, escalate→Escalate; action == Escalate → Escalate rung override (the compound decision's action is the direct escalate signal). risk_flag is logged, never routed on. 'default' rung = the fall-through when a target is unset (resolve_routed None → the turn's configured model — the fail-safe; NO 'default to SMALL' bias).
- Re-classification ONLY at (a) a step boundary (plan title or step index changed) or (b) after a failed cycle — a per-loop escalation_epoch (AtomicU64) advanced by a confident Permanent/FlakyTest triage verdict; never routes up before the first attempt. First-attempt state text = the step text; post-failure re-classification state = step text + a failure appendage naming the triage verdict (so the re-ask can legitimately answer higher — the compound decision's action answers this). Per-loop LaneState {plan_title, step_index, target, shadow, label, confidence, epoch} dedups calls (same step + no new failure → no second call).
- Row logging (best-effort, never fails a turn): every lane classification writes a routing row (RouteDecisionRow extended: lane = Some(rung) on decided rows, step_index = Some(step.index) — 0-based, matching Step.index; fallback rows log the keep-reason as label with lane: None — the calibration signal, mirroring the pre-prompt contract) + decided outcomes also write the reflex corpus row (ReflexHandle::log_decision — the shipped ReflexDecisionRow gets its first writer). Old corpus rows keep parsing (serde defaults on the new fields).
- [models.reviewing] untouched — resolve_routed never consults it; bug-fixing/skill/subagent guards stay via the same resolve_routed path the lanes ride (bug-fixing plans classify + log but can never switch — the resolver guard is the single source of truth).
- Lane composition at the iteration seam (design, on top of a verified probe): resolve_iteration_provider already takes `route: Option<RouteTarget>` per iteration (verified: signature read at turn.rs:2230-2232) — the design is to compute the lane result first and compose it as `lane.or(route)` there, so a decided lane takes that iteration's precedence over the turn-level pre-prompt route; state.route (turn-level outcome rows) is untouched. Verified basis: the route param flows into resolve_turn_provider_routed inside that fn (read in the body).
- Ladder module = NEW src/agent/step_lanes.rs (the Laya-chain pattern: one decision layer per module — model_routing, failure_triage, reflex, step_lanes); pure logic free-function testable; the loop holds the state.
