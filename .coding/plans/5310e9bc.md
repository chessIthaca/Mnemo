# Plan: mnemo2.toml routing settings are rewritten with the new tier ids

## Goal
After the unified-tiers upgrade, the global ~/.mnemo/mnemo2.toml [routing] table stores ladder tier ids on disk (e.g. fallback_tier = "routine" instead of "average"), so the file and the app agree and old ids disappear from it.

## Kind
implementation

## Context
Live check of plan 87932c46 on 2026-11-04: the user's ~/.mnemo/mnemo2.toml still has `fallback_tier = "average"` after the rebuild. `src-tauri/src/mnemo2/dispatch_routing.rs` `load_routing_settings` converts old tier ids when it reads (via `TierLadder::convert_old_id`), but nothing writes the converted value back, so the file keeps the old id until the user happens to save routing settings. Also check `[routing.effort]` keys, which may be keyed by tier id.

Change: in `load_routing_settings` (or a small helper it calls), when any old tier id was converted (fallback_tier, effort keys, any other tier-valued field), write the converted table back once with the existing `save_routing_settings` (read-modify-write that keeps other tables of mnemo2.toml). A failed write-back only logs; loading still returns the converted settings. Do not write when nothing was converted.

Tests (dispatch_routing.rs): a temp mnemo2.toml with fallback_tier = "average" and an effort entry keyed "difficult" loads as routine/high and the file afterwards contains "routine"/"high" and no old ids, with other tables kept; a file with only new ids is not rewritten (unchanged bytes).

Verification: cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings ; cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --bins

## Acceptance scenarios
- Loading a mnemo2.toml with fallback_tier = "average" leaves the file with fallback_tier = "routine" and no old tier ids, other tables untouched.
- Loading a mnemo2.toml that already uses ladder ids does not rewrite it.
