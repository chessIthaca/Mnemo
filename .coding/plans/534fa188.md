# Plan: Backlog tab: headline rendering + card polish (backlog 40763a24)

## Goal
In the Backlog tab, split each item into headline (first line) + body and render the headline as a styled headline — status chip beside it, semibold/larger — with the body as collapsible details (rotating chevron, long bodies collapsed by default), mirroring the plan-steps pattern; light polish pass on chips, spacing, and note display. The split is display-only: editing/copy/preview keep operating on the raw text.

## Kind
implementation

## Context
Findings from exploration (backlog 40763a24, user-reported 2027-01-05):
- Current card (frontend/src/components/views/BacklogView.tsx, BacklogItemCard ~230-706): meta row (status chip + timestamp + up to 7 control buttons) then the WHOLE item text as one markdown block (the markdown stack already ships — backlog 991942af, <Markdown remarkPlugins={[remarkBreaks]}>), truncated at 200 chars with click-to-expand. No headline/body split — the user's complaint.
- Headline convention: first line of text IS the headline — the backlog_add ToolCard chip already extracts it (Message.tsx:628-637, text.split(/\r?\n/)[0].trim(), BACKLOG_TITLE_MAX=80). Data shape is {id, text, status, note} — no separate title field.
- Pattern to mirror: PlanStepRow.tsx (backlog af572504) — rotating ChevronRight (rotate-90 when expanded) + always-visible semibold headline + collapsible body, aria-expanded on the toggle button, spacer keeps header-only rows aligned; tested via renderToStaticMarkup markup pinning in PlanStepRow.test.tsx (node env, no DOM test infra).
- Layout decision: the meta row carries up to 7 icon buttons (edit/copy/dispatch/up/down/remove/retry) — putting chip+timestamp+controls+headline in ONE row would squeeze the headline to a sliver on the ~340px right panel. So: meta row keeps timestamp (moved left where the chip was) + controls; the NEW headline row below it = status chip + chevron + semibold headline at full remaining width ("chip beside it" honored where it fits).
- Body: keep the markdown stack (991942af's shipped behavior); long bodies (>200 chars) collapsed by default, short bodies expanded by default; chevron on every item with a body. The hover-preview portal (long text/images) stays as the see-everything escape hatch. The inline editor, copy (full raw text), and note box are untouched — the split is display-only.
- BacklogItemCard is currently module-private — export it (and splitHeadline) for the component test, mirroring PlanStepRow's export.
- Polish scope (light, per the task): chips get uppercase tracking-wide + slightly smaller size; card padding p-2 → p-2.5; list space-y-2 → space-y-2.5; note/images spacing mt-2. The add-item affordance (BacklogInput) is already polished (autosize, image paste/drop, thumbnails) — no change.
