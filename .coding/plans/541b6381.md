# Plan: Allow file:// URLs in the debug browsers (pure HTML debugging)

## Goal
Let the debug browsers load file:// URLs: add `file` to the normalize_url scheme allow-list (single choke point shared by offscreen_browser_navigate, the visible child-webview browser_navigate/browser_webview_* IPC, and the UI URL bar), sync all docs/comments that claim file:// is rejected, and update/extend the tests.

## Kind
implementation

## Context
Single choke point: normalize_url (src/browser/mod.rs:1391) enforces ALLOWED_SCHEMES = ["http","https","data"] (src/browser/mod.rs:96); file:// is explicitly rejected and this was a deliberate sandbox boundary (2026-08 review S1). User now wants file:// allowed for pure HTML debugging — a deliberate relaxation (javascript:, about:, etc. stay rejected; drive paths C:\foo stay rejected but should error-hint the file:///C:/ form). All consumers (tool src/tool/browser/mod.rs offscreen_browser_navigate schema :87-89 + browser_navigate doc/schema :930-959; IPC src-tauri/src/ipc/browser.rs browser_normalize_url doc :117-122 and src-tauri/src/ipc/browser_webview.rs doc :532-535; frontend src/lib/tauri.ts doc :1595-1602; BrowserView.tsx placeholder :144 + hint :173 + header :25-27; .coding/browser-debugging.md :48,:97-103) go through normalize_url, so one allow-list change covers everything; their texts must stop claiming file:// is rejected. web_fetch (src/tool/agent/web_fetch.rs) is a SEPARATE http(s)-only tool — NOT touched (SSRF surface). Tests to update: navigate_rejects_disallowed_schemes (:1580, remove file:// row), normalize_url_rejects_non_urls (:1626-1647, remove file:// rows), normalize_url_autodetects_bare_hostnames (:1598, add pass-through cases). Existing #[ignore]d integration tests spawn real headless Chromium via data: URLs — mirror that pattern to prove a real file:// load works end-to-end.
