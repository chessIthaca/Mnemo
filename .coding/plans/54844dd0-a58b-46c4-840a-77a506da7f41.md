# Plan: Trace panel: "log traces to file" checkbox → .coding/logs/traces.jsonl

## Goal
Add a "Log traces to file" checkbox to the Trace panel that, when enabled, appends/updates every captured LLM request record as a single-line JSON row in .coding/logs/traces.jsonl, so traces survive restarts and can be analyzed offline for cache-hit optimization.

## Context
The Trace tab's ring buffer (src/provider/trace.rs LlmRequestLog) is in-process + session-only, so traces vanish on restart — blocking the "look at all traces to optimize cache hit rate" analysis. Add a checkbox in the Trace panel header that toggles persisting every captured request to a newline-delimited JSON log file at <coding_dir>/logs/traces.jsonl. The shared LlmRequestLog is created in src-tauri/src/main.rs build_brain() (line 334) where project.coding_dir is known, and cloned into IpcState + every provider. The writer hooks into the private with_record() helper (trace.rs:286) — the single funnel all mutations (set_status/set_usage/append_response/finish/finish) pass through — so a record's file row is rewritten on every update. Frontend checkbox pattern: BacklogView.tsx:649 (label + accent-cyan-500 checkbox). Frontend trace types: types.ts:249-314; IPC wrappers: tauri.ts:751-774. Build must stay warning-free (cargo test, npm test, npm run build).

## Steps
- [x] 1. **Backend: file writer on LlmRequestLog** — src/provider/trace.rs: add fields `log_path: Mutex<Option<PathBuf>>` and `enabled: AtomicBool` to LlmRequestLog. Add `pub fn set_log_file(&self, path: Option<PathBuf>)` (enable: create parent dirs, set path + enabled=true; disable: enabled=false, clear path). Add `pub fn log_file_enabled(&self) -> bool`. In `with_record`, after applying `f`, if `enabled` call a private `write_record_to_file(&self, r: &LlmRequestRecord)` that serializes the record to one compact JSON line and upserts it into the file: read the file, replace the line whose parsed `"id"` matches (lines are keyed by id), else append; write back. To avoid O(file) rewrite on every streaming chunk, keep it simple and correct (whole-file rewrite under the records lock); document that the file is a debugging aid. Unit tests: enable→start→set_usage→finish produces one line with final state; disable stops writes; append across restarts keeps prior lines.
- [x] 2. **Wire default path at startup** — src-tauri/src/main.rs: in build_brain(), after `let trace = Arc::new(LlmRequestLog::new())` (line 334) and after `project` is resolved (line 345-352), call `trace.set_log_file(Some(project.coding_dir.join("logs").join("traces.jsonl")))` — but leave it DISABLED by default (set path only, enabled=false). So the path is known but writing is opt-in via the checkbox. Add `pub fn set_trace_logging(enabled: bool)` semantics: split into `set_log_file_path` (stores path, no enable) + `set_enabled(bool)`. Simpler: store path always, gate writes on the AtomicBool; IPC toggles the bool.
- [x] 3. **IPC commands** — src-tauri/src/ipc/trace.rs: add `#[tauri::command] pub fn get_trace_logging(state) -> bool` (returns state.trace.logging_enabled()) and `#[tauri::command] pub fn set_trace_logging(state, enabled: bool)` (calls state.trace.set_logging_enabled(enabled)). Register both in src-tauri/src/main.rs invoke_handler (after clear_llm_requests, line 266).
- [x] 4. **Frontend: IPC wrappers + types** — frontend/src/lib/tauri.ts (after clearLlmRequests, line 774): add `getTraceLogging(): Promise<boolean>` and `setTraceLogging(enabled: boolean): Promise<void>` invoking the new commands. No type changes needed (both primitives).
- [x] 5. **Frontend: checkbox in Trace header** — frontend/src/components/views/LlmTraceView.tsx header (around line 690, next to the Clear button): add a label+checkbox (pattern from BacklogView.tsx:649) bound to a `logToFile` state. On mount, fetch initial state via getTraceLogging(). onChange: setTraceLogging(checked) then update local state; on error, revert and show in the error banner.
