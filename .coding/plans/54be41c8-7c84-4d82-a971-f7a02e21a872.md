# Plan: Address full-review findings

## Goal
Address every actionable finding from the full-codebase review (fullreview.md), in severity order. No critical/security issues — these are perf + architecture + code-quality hardening.

## Context
Full-codebase review (fullreview.md) found 11 actionable findings across architecture, code quality, performance, and security. No critical/security-breaking issues — the codebase is in strong shape. The findings are prioritized in the review's action list. This sub-plan addresses them in severity order.

Key findings to address:
- P1 (high): per-turn reqwest::Client rebuild when [models] overrides active — cache providers by (endpoint, model) in ConfigModelResolver, invalidate on set_config.
- P2 (medium-high): O(N) memory recall full-scan fallback — avoid to_lowercase() allocations, return empty when FTS returns None instead of full scan, cap the fallback.
- A3 (medium): undocumented lock-ordering invariant between manager + agent_loops — refactor list_agents to snapshot-then-drop (also fixes P4).
- A1 (medium): per-turn provider resolution leaks across module boundaries — split ModelResolver into selection + construction, or move construction to a cached factory (folded into P1's cache).
- A2 (medium): AgentLoop trending god-object (16 fields) — extract TurnContext + SessionState structs.
- P3 (medium): is_project_scoped sync canonicalize on async runtime — wrap in spawn_blocking at dispatch (only if multi-agent scale matters; documented trade-off).
- P4 (low): list_agents holds two locks — fixed by A3's refactor.
- Q4 (low): PausingMockProvider leaks Capabilities via Box::leak — store caps as a field.
- Q2 (low): cap_tool_output misplaced in shell.rs — move to mod.rs.
- Q1 (low): truncate_raw/truncate_string near-duplicate — rename.
- S9 (low): Run-All git reset --hard destructive — document in UI.

The review also has many positive findings (security model, channel contract, docs, rAF batching, spawn path) — no action needed on those.
