# Plan: graph_search stale-index miss — inline reindex-and-reserve (F10 pattern for the symbol index)

## Goal
Make graph_search self-healing against a stale symbol index, mirroring the search tool's F10 reindex-instead-of-warn fix (backlog 42302c2d): on a TOTAL symbol miss, detect staleness (indexed source files whose on-disk mtime differs from the stored mtime — stats only), reindex the stale files inline via the existing CodeGraph::reindex_stale_files (capped at 8, coordinating with the watcher through the indexing flag), re-resolve ONCE from the fresh view, and serve the fresh result with a disclosure note ("reindexed N stale file(s) — serving fresh graph results"). Staleness that cannot be repaired (above the cap, a pass already running, reindex failure) serves the normal miss_hint PLUS a staleness note ("symbol index may be stale — N file(s) on disk are newer than the index"). Everything best-effort: errors fall through to the plain miss, never failing the lookup. New machinery: CodeGraph::stale_source_files() (the symbol-index sibling of the search tool's fts_page sweep). Tests: the red-without-fix regression (a symbol added to an existing .rs file after the index build is found without a restart), a genuinely-absent miss stays fast (no reindex, no note), and a vanished stale file degrades gracefully (pruned, lookup unbroken).

## Context
Root cause diagnosed during planning (2027-01-07): the watcher (src/codegraph/watcher.rs) DOES update the symbol index in-session — debounce_loop runs incremental CodeGraph::index() passes on indexable file changes (watcher_reindexes_on_new_source_file proves new symbols get indexed) — but it is best-effort by design: a failed spawn, a missed OS event, a dead debounce loop, or a failed pass leaves the index stale, and graph_search (src/tool/agent/codegraph.rs:274-303) serves the empty result with no query-time repair. The search tool's F10 pattern (src/tool/agent/search.rs:833-994) is the template: fts_page detects staleness via graph.stored_mtimes() vs disk mtimes, try_index reindexes inline (CodeGraph::reindex_stale_files, src/codegraph/mod.rs:397 — atomic indexing-flag claim, containment guards, source vs content-only arms, edge rebuild) capped at STALE_REINDEX_CAP=8 (search.rs:348) and re-queries ONCE; the note wording is "reindexed N stale file(s) — serving fresh index results". Key asymmetry: search can WALK around a stale index (the walk is authoritative); graph_search has no fallback — the empty result IS the answer. DESIGN DECISIONS: (1) scope = graph_search only (the mandated first call; graph_context/impact/path are reached with its ids — name-misses there are rarer; the helper is reusable if that changes); (2) the sweep covers files ALREADY in the index (edits to known files — the live symptom); brand-new files not yet indexed stay watcher-dependent (documented residual, same class as F10's zero-fetch case which walks); (3) mtime comparison mirrors F10 exactly (unix-millis inequality — a same-millis rewrite is missed, accepted residual); (4) the sweep stats only indexed SOURCE files (Lang::from_extension filter — symbols only come from source files), so a steady-state miss costs one stored_mtimes() SELECT + a few hundred stats on the blocking pool — no reindex on a genuinely-absent miss; (5) the reindex side effect is ALWAYS disclosed (a read tool mutated the index — same disclosure rule as the search tool); (6) best-effort: any sweep/reindex error falls through to the plain miss_hint, never fails the lookup (a broken DB still errors via view() as today); (7) miss_hint and the "No symbols matched" steering marker stay byte-identical — a repaired miss serves symbols (no marker, correct), an unrepaired miss keeps the marker (correct).
