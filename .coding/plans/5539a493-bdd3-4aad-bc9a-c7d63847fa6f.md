# Plan: Unified File viewer + clickable file links + syntax highlighting

## Goal
Unify the file browser + Markdown viewer into a single resizable "Files" viewer (tree on top, content below) that renders Markdown + syntax-highlights other text formats via the shared react-markdown/rehype-highlight stack, and make file names in tool cards clickable links that open the file in that viewer (auto-opening the right panel + Files tab).

## Kind
implementation

## Context
User request: (1) file names in tool cards (file_read, file_write, file_edit, write_review_report, read_files, etc.) become clickable links that open the file in the viewer; (2) the viewer handles multiple text formats with syntax highlighting (Markdown key); (3) merge the file browser into the Markdown viewer, renamed "File viewer", tree as top part, resizable, click a file to display it if it's a text file. User confirmed clicking a tool-card link should AUTO-OPEN the right panel + Files tab.

DECISION (formatting source): highlight comes from the EXISTING react-markdown + remark-gfm + rehype-highlight stack (highlight.js via lowlight), themed by the .hljs-* CSS-custom-property rules in frontend/src/styles/globals.css (dark + html.light variants) — the same renderer chat already uses. The File viewer renders EVERY text file through the shared <Markdown> component: .md as-is, code files wrapped via wrapCodeFence(content, lang). NO direct highlight.js import (was briefly added then uninstalled). DONE (step 1): frontend/src/lib/language.ts (languageForPath/isTextPath/isMarkdownPath/wrapCodeFence) + language.test.ts (10 tests) + registered in vitest.config.ts. 181 frontend tests green. Next: extract Message.tsx's CodeBlock into a reusable component, build FileViewer, merge tabs, wire tool-card links, IPC verify, review+commit on branch feat/file-viewer.
