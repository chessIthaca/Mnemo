# Plan: Trace tab: stack charts vertically + dither cache overlay

## Goal
Stack the Trace tab's two remaining charts vertically and fold the cache-hit chart into the token chart as a dithered overlay on the prompt segment.

## Kind
implementation

## Context
TraceStats.tsx renders 3 charts in a 3-col grid (phase / tokens / cache-hit). The token chart already overlays the cached share as a SOLID emerald block at the bottom of the prompt segment (height = cached/prompt = the cache-hit %); the separate CacheChart shows that same hit% again as green/amber/red bars — redundant. Consolidating removes the redundancy; a dithered diagonal-stripe overlay (emerald hatch over the sky-blue prompt base) makes the cached region read as a textured overlay instead of a flat block. Stacking the remaining two charts vertically gives each full width (better column legibility than 1/3-width). Default section height is 260px (sized for 3-across); two stacked charts need more height. Pure helpers cacheHitSeries/cacheTipRows/CacheHitRow in traceStats.ts stay exported (tested, harmless) — only their imports in TraceStats.tsx are removed.

## Steps
- [x] 1. **Consolidate cache into token chart + dither overlay** — In `frontend/src/components/views/TraceStats.tsx`: (a) delete the `CacheChart` component entirely; (b) remove the now-unused imports `cacheHitSeries`, `cacheTipRows`, `CacheHitRow` from the `../../lib/traceStats` import block, and delete the `const hits = cacheHitSeries(rows);` line in `TraceStats`; (c) in `TokenChart`, replace the solid `bg-emerald-500/70` cached overlay div with a dithered overlay — keep the same `absolute inset-x-0 bottom-0` positioning and `height: ${cachedPct}%`, but set an inline style `backgroundImage: repeating-linear-gradient(45deg, rgba(16,185,129,0.85) 0 2px, transparent 2px 5px)` plus `backgroundColor: rgba(16,185,129,0.22)` so emerald diagonal stripes hatch over the sky-blue prompt base with the sky showing through the gaps; (d) keep the legend's existing `cached` emerald swatch. The tooltip already shows `cached X (Y%)` via tokenTipRows — no change needed there.
- [x] 2. **Stack the two charts vertically** — In `frontend/src/components/views/TraceStats.tsx`, change the chart container (currently `<div className="grid min-h-0 flex-1 grid-cols-3 grid-rows-1 gap-2 overflow-hidden p-2">`) to `<div className="flex min-h-0 flex-1 flex-col gap-2 overflow-hidden p-2">`. Add `flex-1 min-h-0` to each chart's root div (PhaseChart and TokenChart both start `<div className="flex min-h-0 min-w-0 flex-col rounded border border-border p-2">` — append `flex-1`) so phase (top) and tokens (bottom) share the vertical space equally. Remove the `<CacheChart rows={hits} />` line from the container.
- [x] 3. **Bump default stats height** — In `frontend/src/components/views/LlmTraceView.tsx`, change `const STATS_DEFAULT = 260;` to `const STATS_DEFAULT = 360;` so two stacked charts each get comfortable height (~165px). Leave `STATS_MIN = 140` and the clamp logic untouched — the drag splitter still lets users adjust, and the clamp `[140, total*0.7]` already bounds it.
- [x] 4. **Tests + build** — Check `frontend/src/lib/traceStats.test.ts` and `frontend/src/components/views/TraceStats.tooltip.test.ts` for anything that pins the 3-column grid layout or the CacheChart component (CacheChart is not exported, so unlikely); update any stale assertions. Run the frontend test suite (check `frontend/package.json` for the exact script — likely `npm test` / vitest) and the type-check/build (`npm run build` or `tsc`) to confirm zero type/lint errors and green tests. This is a frontend-only change — no Rust touched.
