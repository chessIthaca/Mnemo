# Plan: Finished audits release their slot and cannot be revived

## Goal
An audit worker's session ends automatically once its read-only report is delivered, so it never holds a worker slot. A finished or stopped audit cannot be resumed, continued, compacted or steered back to life, in either the UI or the backend.

## Kind
bug_fixing

## Context
Root cause, read 2026-11-03:
1. Worker slots count LIVE sessions (src-tauri/src/mnemo2/team.rs ~3061 `let active = self.live.lock().await.len(); if active >= slots`, the same at ~3251, ~3548 and ~4089). An audit worker (kind "audit", read-only, audit_prompt() ~7602 tells it to 'Report findings … through message_parent, then end your turn') keeps its live session after its turn ends, because executor and audit sessions both use TurnEndPolicy::Stop and stay quiescent but live. So every finished audit holds a slot until the lead or user stops it. The lead hit 'all 9 worker slots are busy' twice today and had to team_stop completed audits by hand.
2. Stopped audits are revivable. Mission control shows Resume (mnemo2/src/components/WorkerDetail.svelte ~168-170, shown for paused, stopped or interrupted), Continue (mnemo2/src/components/WorkerPanel.svelte ~126-128, the blocked banner), Compact (~165; team.rs compact() ~4392-4420 resumes a stopped session) and Steer for audit workers too. Backend resume (team.rs ~4077-4100), compact and route_fix (~4806 resume_inner) do not refuse audits. Reviving an audit that already reported gives it nothing to do: it sits idle and holds a slot.
Related earlier record: 'BUG: Old workers can be deleted…' (finished audits must be deletable).

Decisions:
- When an audit worker's turn ends after it has reported (the same point that queues the 'finished its read-only audit' lead notice; find it by grepping that text), Mnemo2 stops its session automatically (stop_inner semantics: keep the record, report and worktree) and sets status Completed, so the live map no longer holds it. If the turn ended WITHOUT a report (failure or interrupt), keep today's behaviour so the lead can resume it.
- Backend: resume(), compact(), change_model() and team_message/steer on an audit worker whose report was delivered are refused with: "audit worker '<id>' already delivered its report; dispatch a new audit with team_audit_dispatch". route_fix never targets audits.
- UI: for kind 'audit' workers whose report is delivered, mission control hides Resume, Continue, Compact and Steer, and shows Delete and the status. An audit that failed before reporting keeps Resume.
- Add a durable `report_delivered: bool` to WorkerRecord (serde default false), set where the audit report is recorded, so the backend and UI can tell 'finished' from 'failed before reporting'. Records written before this change (audits with status Completed) count as delivered.

Regression test (bug_fixing): `finished_audit_releases_its_slot` in team.rs. Without the fix, the audit's session is still in `live` after its report, and a dispatch needing that slot fails with 'all N worker slots are busy'.

## Acceptance scenarios
- After an audit worker delivers its report, its session ends on its own: it is Completed and no longer counts against the worker slots.
- Resume, Continue, Compact, Steer and change_model on a finished audit are refused (backend) and not offered (mission control).
- An audit that failed before reporting can still be resumed.
- Implementation workers keep their live session after a turn, as today.
