# Plan: Remove hard memory budgets; encourage short via auto-truncation + prompt

## Goal
Remove the hard character-budget reject from the memory write/supersede tools (file-backed memories are already unbounded; extend that to DB-only rows too), and instead encourage short memories through (a) the indexer/finish_capture auto-truncation — now wired to the configurable budgets — and (b) a soft prompt guideline. No information is lost: the file is the truth, the derived digest is auto-truncated, and the exact values stay in the file.

## Kind
implementation

## Context
The hard budget reject (`budget_violation()` in src/tool/memory/mod.rs:276-289) fires only for DB-only typed rows in memory_write (line 158) and memory_supersede (line 877) — file-backed knowledge writes already skip it (H4 fix, 2026-08-23). The reject is the wrong enforcement point: the DB row is a pointer to a file (plan/review/knowledge), and the file is unbounded. Shortness already comes from a DIFFERENT place — the indexer's `budgeted_digest()` (src/memory/indexer.rs, 4 call sites) and finish_capture.rs (2 call sites) auto-truncate the gist while preserving the pointer, never rejecting. But those read `MemoryRecordType::content_budget()` (hardcoded), NOT the config. The config budgets (MemorySearchConfig: plan_budget/bug_budget/spec_budget/decision_budget/review_budget + digest_budget()) currently ONLY feed budget_violation — remove the reject and they go dead. Wiring them to the indexer makes them the tunable knob for auto-truncation length. The prompt (MEMORY_RECORDS const, prompt.rs:180-201) hard-cites budgets + "over-budget errors"; test stable_head_carries_memory_records_block asserts ≤500/≤300/≤600/≤400 markers. Tool schemas also cite budgets. content_budget() on MemoryRecordType stays (it's the default source for MemorySearchConfig::default() and still used by the indexer/finish_capture as the fallback).
