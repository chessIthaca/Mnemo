# Plan: Cost tab stops listing the retired delta-read and skeleton levers

## Goal
The Cost tab (and the Mnemo1 dashboard, which reads the same engine report) no longer shows rows, totals or day-chart savings for the removed delta-read and signature-skeleton levers. Their ledger rows stay in the database untouched.

## Kind
implementation

## Context
WHY: the delta-read and signature-skeleton re-read serves were removed from read_files (merged e34ba637). The Cost tab's savings are all-time, so the old ledger rows (3 delta_read events / 3,096 tokens, 139 skeleton events / 132,619 tokens, out of ~54.5M saved) keep their own lever rows forever, labelled "Retired". The user still sees "Delta reads" in the Cost panel and wants the retired levers gone from it.

DECISION (taken): hide, don't delete. The engine's two report reads — `MemoryStore::savings_stats` and `MemoryStore::savings_valuation` in src/memory/mod.rs — skip rows whose kind is retired. Ledger rows are NOT deleted (no DELETE, no migration), and the raw row reader `savings_events_rows` still returns them (it is the audit reader). Filtering at the engine keeps the headline total, the lever list, the per-day chart, the recent list and the dollar valuation consistent with each other; filtering only in the Svelte view would leave the total and the day chart including tokens no row explains.

CONSTRAINTS: no new setting; no schema change (do not edit the DDL text in src/memory/schema.rs); src-tauri/src/mnemo2/insights.rs needs no code change (it builds rows from `savings.per_kind` and `valuation.rows`, which no longer carry retired kinds) and its tests stay as they are; Mnemo1 frontend needs no change (DashboardView renders whatever kinds the report carries). The config key `delta_reads` (now the outline-reads flag) is unrelated and must not be touched.

FILE ANCHORS: src/memory/mod.rs (`saved_tokens_sql` ~l.213, trait docs for savings_stats ~l.498 and savings_valuation ~l.505, impl savings_stats ~l.2660, impl savings_valuation ~l.2763 with its `WHERE kind <> 'compaction_checkpoint'`), src/memory/tests.rs (savings_events_round_trip_and_negative_expansions ~l.2738, savings_stats_aggregates_kinds_days_recent_and_cache ~l.2899, savings_stats_clamps_archive_and_compression_to_the_result_cap ~l.3567, savings_valuation_counts_later_requests_up_to_the_lifetime ~l.3633), src/memory/types.rs (doc lines ~l.658-661 and ~l.761), mnemo2/src/lib/cost.ts (LEVERS table ~l.174, fallbackLabel comment ~l.222), mnemo2/src/lib/cost.test.ts, mnemo2/src/components/CostView.test.ts, mnemo2/src/test/previewScenes.ts (~l.1366-1380), mnemo2/src/preview/previewScenes.test.ts (~l.250).

VERIFY: `cargo test --lib savings` and `cargo test --lib memory::` (all green), `cargo build --tests`, `npm --prefix mnemo2 run check` (0 errors), `npm --prefix mnemo2 test` (all green).

## Acceptance scenarios
- With ledger rows of kinds delta_read, skeleton, compression and outline, savings_stats reports only compression and outline in its total, per-kind, per-day and recent fields, and savings_valuation values only those two kinds.
- savings_events_rows still returns all four rows: no ledger row is deleted.
- The Cost tab's lever list has no 'Delta reads' or 'Signature skeletons' row, and its headline total equals the sum of the rows it lists.
