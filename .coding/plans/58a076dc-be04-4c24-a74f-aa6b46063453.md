# Plan: Harden ask_user: require ≥2 options + choice-framing guidance

## Goal
Harden ask_user: require ≥2 options (open-ended questions skip the tool) and guide the agent to frame questions as a choice.

## Kind
implementation

## Context
The ask_user tool currently accepts 0 or 1 options (parse_ask_user_args validates only that the question is non-empty; there's a test parses_args_with_no_options asserting 0 options succeeds). The user wants: (1) the tool should require at least 2 options — open-ended questions should skip the tool and just post as text in the response; (2) the tool description should guide the agent to frame the question as a choice between the options, not as an open-ended question after listing choices. The dispatch path (dispatch.rs:305-310) returns parse_ask_user_args errors as ToolResult::error, so enforcing ≥2 options is by-construction — the agent gets an error and can react (post as text). Changes are localized to src/tool/workflow/ask_user.rs.

## Steps
- [x] 1. **Require ≥2 options in parse_ask_user_args + schema** — In `src/tool/workflow/ask_user.rs`: (1) In `parse_ask_user_args`, after the empty-question check, add a check that `a.options.len() >= 2` — if fewer, return an error like `"ask_user requires at least 2 options (got N) — for an open-ended question, skip this tool and post the question as text in your response"`. (2) In the `schema()` method: add `"options"` to the `required` array (so it becomes `required: ["question", "options"]`), and add `"minItems": 2` to the options array property. (3) Update the options array description from "1–6 recommended" to "At least 2 (2–6 recommended)".
- [x] 2. **Update the tool description to guide choice-framing + when to skip** — In `src/tool/workflow/ask_user.rs` `schema()` description string: rewrite to state that ask_user is for when there is a choice between at least two concrete options; for open-ended questions, do NOT use this tool — just post the question as text in the response. Add guidance to frame the question as a choice between the options (e.g. "Which approach?" not "What do you think?"), and keep the one-question-at-a-time + pause-until-answered notes. Keep it concise.
- [x] 3. **Update tests for the ≥2-options rule** — In `src/tool/workflow/ask_user.rs` tests: (1) Flip `parses_args_with_no_options` to assert it now ERRORS (rename to `rejects_zero_options` or keep name + assert is_err with a message mentioning "at least 2"). (2) Add `rejects_single_option` — 1 option → error. (3) Confirm `parses_args_with_options` (2 options) still succeeds. (4) The `execute_fallback_returns_clear_error` test passes `options: []` — that still works (execute doesn't call parse_ask_user_args, it just formats the "use the question path" error), but verify it still passes. Run `cargo test --lib tool::workflow::ask_user` to confirm green + warning-free.
