# Plan: Fix git branch defaulting to list

## Goal
Make the git tool's `branch` subcommand default to `list` when no `action` field is provided, so `{"subcommand": "branch"}` lists branches instead of erroring.

## Context
In src/tool/agent/git.rs, the "branch" subcommand requires an explicit `action` field (list/delete/create) and errors when it's missing. But `git branch` with no args lists branches in git itself, so the natural default is `list`. The `stash` subcommand already follows this pattern — it defaults to "push" when no action is given. The fix: default `action` to "list" for the branch subcommand when none is provided, mirroring stash's defaulting behavior.
