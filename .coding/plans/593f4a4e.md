# Plan: Relax the subagent state-transition gate to review-exit transitions only (backlog 569b5922)

## Goal
Replace the blanket descendant gate (all 8 state-touching tools refused while any spawned subagent runs) with precise review-exit gating: finish is always refused while descendants run, and complete_step is refused only when the call would complete the ROOT plan (Executing→Reviewing on implementation/bug-fixing plans, →Complete on research plans). create_plan, update_plan, abandon_plan, skill_start/skill_end/abandon_skill, and non-final complete_step become ungated so parallel subagent work (spawn-step bookkeeping, sub-plan pushes, the abandon escape hatch) proceeds while descendants run.

## Kind
bug_fixing

## Context
Root cause (known, from backlog 569b5922): the dispatch-layer gate matches ALL state-touching tool names (create_plan/update_plan/complete_step/abandon_plan/skill_start/skill_end/abandon_skill/finish) and refuses them whenever DescendantTracker::has_running_descendants(agent_id) is true — it protects the right invariant (don't exit a phase while work feeding that exit runs) at the wrong layer (every state-touching call instead of the phase-exit transitions). DESIGN DECISION: the checks stay in the dispatch layer (which already holds descendant_tracker + agent_id + the workflow Mutex handle, and hosts every other dispatch gate: ToolFilter, plan-mutations, reviewer-failure latch) rather than moving into the tool handlers as the item's letter suggested — the sync Workflow cannot hold the async tracker, and injecting it into CompleteStepTool/FinishTool would ripple constructors through ~25 test sites. The Workflow instead gains a pure finality query. Semantics per the item: finish always gated (closing reviewer must land first; the non-empty-report finish gate stays as the second lock); complete_step gated ONLY when the call would complete the ROOT plan (stack.len()==1 — sub-plan completion pops to Executing and is not a phase exit); everything else ungated (non-final complete_step is a checklist tick; update_plan edits in place; create_plan pushes a sub-plan while the parent keeps executing; abandon_plan is the designated escape hatch; skill_* are plan-stack-like). Do NOT add a blocking/non-blocking spawn classification. Key code: gate at src/agent/dispatch.rs:152-192 (parsed_call.arguments available at line 72; workflow lock pattern at line 100 — never held across the tracker await); Workflow::complete_step at src/workflow/mod.rs:668-705 (finality = frame.plan.is_complete() after tick; root vs sub-plan branch at 682-701); Plan at src/workflow/plan_file.rs (steps with done flags, is_complete at 309-311, complete_step at 319-329 — args are 1-INDEXED at the tool layer, numeric strings accepted); test pattern: FixedDescendantTracker + execute_tool_call fixture at src/agent/tests.rs:3495-3655 (dispatch_blocks_state_transition_when_descendants_running asserts the OLD behavior and must be rewritten). NOTE: the tree may carry the pre-existing uncommitted run_all.rs #[allow(dead_code)] delta (backlog 212c14af) — leave it untouched, exclude it from this fix's commit, and flag it to the reviewer as out of scope.
