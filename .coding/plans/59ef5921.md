# Plan: Fix Mnemo2 host macOS test-build plist collision

## Goal
Fix the macOS test-build plist collision in both the new context test and the pre-existing lib/main double-embed, so `cargo test --workspace` remains green on macOS and the Mnemo2 host is feature-gated without weakening its tests.

## Kind
bug_fixing

## Context
Reviewer report `.coding/reviews/2026-10-24-mnemo2-native-host-startup-fix-review.md` (verdict FINDINGS, 1 high, 1 low) verified against pinned tauri-macros 2.7.0 / tauri-codegen 2.7.0 / embed_plist 1.2.2. F1: `src-tauri/src/mnemo2/mod.rs`'s test calls `tauri::generate_context!("mnemo2-app/tauri.conf.json")` without `test = true`; on macOS dev builds every non-test expansion emits `embed_info_plist!`, and the lib test binary contains both `run()` and the test, so embed_plist's reuse guard fails the compile. F2 (pre-existing since Phase 1): the lib's `run()` context and `src-tauri/src/main.rs:1095`'s context collide in the main-bin test target on macOS; release builds are safe because `custom-protocol` sets dev=false. Fix direction: add `test = true` to the test expansion; add a `mnemo2` feature in `src-tauri/Cargo.toml`, cfg-gate `pub mod mnemo2` in `src-tauri/src/lib.rs`, declare `[[bin]] name="mnemo2" required-features=["mnemo2"]`, and update `package.json` native scripts plus `mnemo2/README.md` to pass `--features mnemo2`. Verification: default `cargo test --workspace` (main bin, feature off) must not link the Mnemo2 context; `cargo test -p mnemo-app --features mnemo2 --lib` must compile/run the Mnemo2 tests; `cargo build -p mnemo-app --features mnemo2 --bin mnemo2` must build; native launch with the feature. Regression test: `context_uses_mnemo2_identifier` (plus the compile-time feature split).

Landed F1: `src-tauri/src/mnemo2/mod.rs`'s context test now calls `generate_context!("mnemo2-app/tauri.conf.json", test = true)`. Landed F2: `src-tauri/Cargo.toml` has `mnemo2 = []` and `[[bin]] name="mnemo2" required-features=["mnemo2"]`; `src-tauri/src/lib.rs` cfg-gates `pub mod mnemo2`; `package.json` native scripts pass `--features mnemo2` and add `test:mnemo2:native`; `mnemo2/README.md` and the design doc document the feature; `.github/workflows/build.yml` runs `cargo build -p mnemo-app --features mnemo2 --bin mnemo2` + `cargo test -p mnemo-app --features mnemo2 --lib` in both Windows and macOS jobs. Verified: default `cargo test --workspace` exit 0 (feature off; main bin no longer links the Mnemo2 context); feature `cargo test -p mnemo-app --features mnemo2 --lib` 10 passed; `cargo build -p mnemo-app --features mnemo2 --bin mnemo2` exit 0; Mnemo2 npm 57 tests and build/svelte-check clean; feature-enabled launch smoke produced a titled Mnemo2 window with the `com.mnemo.mnemo2` WebView2 profile and no 9222; `git diff --check` clean. `rustfmt --check` on changed files only reports pre-existing formatting drift in untouched `src-tauri/src/mnemo2/ipc.rs` and `runtime.rs`; no formatting changes were made there.

## Bug
On macOS dev/test builds, `cargo test --workspace` cannot compile the mnemo-app test targets: the new Mnemo2 context test omits `test = true` and double-embeds `_EMBED_INFO_PLIST` with `run()`, while the pre-existing lib `mnemo2::run()` context and `src-tauri/src/main.rs`'s own context also double-embed in the main-bin test target.
