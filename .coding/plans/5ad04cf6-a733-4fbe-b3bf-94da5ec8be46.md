# Plan: Optimize memory: session-start primer + Complete hook

## Goal
Inject a standing project-memory primer at session start (top strongest semantic+procedural facts) so the agent begins with project knowledge instead of re-discovering it, and auto-write a concise episodic memory when a plan reaches Complete so finished work is captured immediately (survives crashes, available to the next plan) instead of only on shutdown consolidation.

## Kind
implementation

## Context
Investigation grounded in code:
- NO session-start memory load exists. Auto-recall is per-turn only (turn.rs:243-279), keyed on the latest user message, limit 5, content capped 160 chars (prompt.rs:224-236), lives in the volatile tail (reprocessed every turn).
- NOTHING fires at Complete. The Complete workflow section (prompt.rs:336-344) just says plan-first. Consolidation only happens on shutdown (runtime/agent.rs doc line 5).
- Working-tier exclusion (#3) is ALREADY DONE: MemoryFilter::exclude_working defaults true (types.rs:166), recall honors it (mod.rs:615), test recall_excludes_working_by_default passes. No code change needed — verify only.
- The stable head (build_stable_head, prompt.rs:123) is byte-stable across turns (cache-friendly), placed in messages[0] (turn.rs:305-318). A session-stable primer can live there without breaking cache-friendliness (stable within a session).
- Two paths to Complete: finish tool (impl plans, plan.rs:514) and complete_step on a research root plan (workflow/mod.rs:540-543). The turn.rs workflow-event block (line 894-900) lists create_plan/update_plan/complete_step/abandon_plan/skill_* but NOT finish — so finish doesn't emit WorkflowStateChanged from that block.
- record_tool_event pattern (turn.rs:836-855) is the template for silent background memory capture. record_request_stats (turn.rs:495) is the template for fire-and-forget spawned writes.
- AgentLoop.session (SessionState, loop_impl.rs:22-43) holds per-session state behind Mutex — the right place to cache a once-per-session primer.
- MemoryStoreTrait (memory/mod.rs ~line 79) is the store trait; MemoryStore is the impl. Need to check for other impls/mocks when adding a method.
