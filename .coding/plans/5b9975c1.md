# Plan: Installers ship the Claude Code plugin: bundled helper, startup install, Settings → Claude Code with Connect

## Goal
A user who installs a Mnemo2 release can lead with Claude Code: the installers contain the mnemo2-mcp helper, Mnemo2 installs the plugin and helper into ~/.mnemo/claude-plugin at every start, and Settings → Claude Code → Connect Claude Code registers the plugin with Claude Code in one click.

## Kind
implementation

## Context
WHY: the user decided (2026-11-14) that Claude Code must be part of the installers, and chose a Connect button (the app sets up files itself; Claude Code's settings change only when the user clicks). Today the plugin needs `bin/mnemo2-mcp`, which is not checked in and only a source build creates (scripts/install-mnemo2-mcp.mjs), and the installers do not contain it (src-tauri/mnemo2-app/tauri.conf.json bundles only `laya/dispatch_routing.jsonl`; .github/workflows/build.yml never builds the helper).

EXISTING MECHANISMS TO REUSE (verified 2026-11-14):
- Any helper copy delegates to `<config>/bin/mnemo2-mcp[.exe]` when that copy's mtime is >= its own (`delegate_target`, src-tauri/mnemo2-app/src/mnemo2_mcp.rs:90). So Claude Code's cached plugin copy keeps working after Mnemo2 updates the `<config>/bin` copy, as long as the installed copy keeps a fresh mtime.
- The helper finds the app via `MNEMO2_EXE`, then the first line of `<helper dir>/mnemo2-path.txt`, then a sibling `mnemo2[.exe]`, then PATH (`resolve_app`, src-tauri/mnemo2-app/src/mnemo2_mcp/instance.rs:861).
- `<config>` = `mnemo::config::resolve_config_dir(None)` ($MNEMO_HOME or ~/.mnemo).
- The app's startup hook is `.setup(move |app| { ... })` in `pub fn run()` (src-tauri/src/mnemo2/mod.rs about line 603); `config_dir` is resolved there.
- Tauri's build script refuses to compile when a configured `externalBin` file is missing, and the helper is built from the same package, so `externalBin` must NOT go into tauri.conf.json (it would break every plain `cargo build`/`cargo test`). It goes into a separate `tauri.bundle.conf.json` passed only to `npx tauri build --config`, after a script has built and staged the helper as `binaries/mnemo2-mcp-<target triple>[.exe]`. Tauri then installs it next to the main executable (Windows: the install folder; macOS: Mnemo2.app/Contents/MacOS/).
- Claude Code CLI 2.1.138 (verified): `claude plugin marketplace list --json` returns `[{"name","source","path"|"url","installLocation"}]`; `claude plugin list --json` returns `[{"id":"<plugin>@<marketplace>","version",...}]`; `claude plugin marketplace add <path>`, `claude plugin marketplace update <name>`, `claude plugin install mnemo@mnemo`, `claude plugin update mnemo@mnemo`. A developer machine may already have a marketplace named `mnemo` pointing at a source checkout (here: C:\Mnemo); Connect must leave that alone.
- Frontend invoke strings are cross-checked against the Rust `generate_handler!` list by `every_frontend_invoke_string_is_a_registered_command` (src-tauri/src/mnemo2/mod.rs tests).

DESIGN (decided): the plugin files (plugin.json, .mcp.json, hooks.json, the four SKILL.md, README.md) are compiled into the app with `include_str!` and written at every start into `<config>/claude-plugin/` as a ready local marketplace: `<config>/claude-plugin/.claude-plugin/marketplace.json` (marketplace `mnemo`, plugin `mnemo` with source `./plugin`) and `<config>/claude-plugin/plugin/...`. The helper next to the running app (`<exe dir>/mnemo2-mcp[.exe]`, present in installs and in target/release after a source build) is copied to `<config>/bin/` and `<config>/claude-plugin/plugin/bin/` when missing or older, keeping the source mtime, and `mnemo2-path.txt` (the running exe path) is written beside both. A new Settings page "Claude Code" (rail group "All projects", right after MCP) shows the helper, CLI and plugin state, runs Connect, and shows the manual path (Claude Desktop, or the two commands). After this lands, a release (2.4.0) ships it; that is a separate plan.

VERIFY (each step plus its own): `git diff --check` clean; commit on your branch and report the commit and the commands you ran. Rust: `#![deny(warnings)]`, no `#[allow]`.

- Settings shows a "Claude Code" rail entry after MCP; its page lists helper, CLI and plugin state, the Connect Claude Code button runs claude_code_connect and shows the steps, and a marketplace named mnemo that points elsewhere is left alone (vitest).
