# Plan: Implement GLM-5.3-Flash stop tokens, sampling parameters, and stream guard

## Goal
Implement the GLM-5.3-Flash specification across config (Endpoint/ModelSpec), client factory (OpenAiClientConfig), request payload building (temperature, top_p, stop, stop_token_ids, extra_body), default GLM-5.3 boundaries (<|observation|>, 4-newline cascade), and client-side SSE stream guard.

## Kind
implementation

## Context
We wrote a knowledge spec in .coding/knowledge/spec/2026-12-21-glm-5-3-flash-stop-token-boundaries-sampling-par.md outlining the requirements for GLM-5.3-Flash stability: stop tokens, stop_token_ids, temperature/top_p, extra_body, and SSE client-side stream guards. Prior work (commit ec0d794) hardcoded partial stop boundaries in build_request_json; the full spec architecture requires configurability in Endpoint/ModelSpec, propagation through client_factory, full stop boundary set (<|observation|>, \n\n\n\n), and client-side SSE stream guard.

## Steps
- [x] 1. **Config layer (endpoints.rs and patch.rs)** — Add optional `temperature`, `top_p`, `stop`, `stop_token_ids`, and `extra_body` fields to `Endpoint` and `ModelSpec` in `src/config/endpoints.rs`. Update resolution helpers (`model_temperature`, `model_top_p`, `model_stop`, `model_stop_token_ids`, `model_extra_body`) and update `src/config/patch.rs` (and test constructors) to keep validation and constructors intact. Add unit tests for parsing endpoints.toml with these fields.
- [x] 2. **Client factory and OpenAiClientConfig** — Extend `OpenAiClientConfig` in `src/provider/openai.rs` with `temperature: Option<f64>`, `top_p: Option<f64>`, `stop: Vec<String>`, `stop_token_ids: Vec<u64>`, and `extra_body: Option<serde_json::Map<String, serde_json::Value>>`. Update `client_factory.rs` to propagate these resolved fields from the endpoint and model spec into `OpenAiClientConfig`.
- [x] 3. **Payload builder and GLM-5.3 defaults** — Update `build_request_json` in `src/provider/openai.rs` to inject configured `temperature`, `top_p`, `stop`, `stop_token_ids`, and merge `extra_body` into the outgoing JSON payload. Update the built-in GLM-5.3 fallback stop boundaries to include `<|observation|>` and `\n\n\n\n` as specified in the spec.
- [x] 4. **Client-side stream guard** — In `src/provider/openai.rs`, add client-side stream boundary detection in the SSE reading loop. If raw boundary strings (`<|user|>`, `<|assistant|>`, `<|endoftext|>`, `<|observation|>`, or configured stops) appear in stream deltas, truncate preceding content, emit FinishReason::Stop, and terminate the turn early, preventing runaway generation and garbage output leakage.
- [x] 5. **Regression and unit tests** — Add unit and integration tests asserting: endpoint TOML parsing with sampling/stop/extra_body fields; request payload generation with explicit and default GLM stop tokens, stop_token_ids, temperature, top_p, and extra_body; and client-side stream termination upon encountering boundary tokens in text deltas. Run `cargo test` to verify warning-free compilation and passing tests.
