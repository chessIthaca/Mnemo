# Plan: Configurable git core-operations approval gate + regression-test rule

## Goal
Replace the hardcoded git core-operations list (merge/push) with a configurable, runtime-mutable list exposed in a new Settings → Git section, and add an agent.md rule requiring a regression test for every defect fixed.

## Kind
implementation

## Context
GitTool::is_core_operation (src/tool/agent/git.rs:61-63) hardcodes merge|push as the subcommands that force the approval prompt (never_auto_for → dispatch.rs:195 force_prompt). The user wants this configurable via a Settings page instead of hardcoded. The runtime-mutable shared-handle pattern already exists for safety_mode (Arc<RwLock<SafetyMode>> on the factory, shared across all agents, toggled by save_settings, read per tool call). The MarkdownConfig{skip_dirs} chain (config struct → GitWire → GetSettingsResponse → SettingsSaveDto → save_settings apply → tauri.ts types → AdvancedSection UI) is the end-to-end template. GitTool::new(project_root) is called in 3 places: factory.rs:486 (production), spawn.rs:531 + tests.rs:629 (tests). The factory is Arc<AgentLoopFactory> shared via IpcState.runtime.factory, accessible from save_settings. User chose a dedicated Git settings section (not the Advanced field).
