# Plan: Remote workers, phase 4: Claude Code agent workers on a paired host

## Goal
A worker whose tier runs as a Claude Code agent can run on a paired Windows or Mac host: the lead starts it as a Claude Code session on that host through the desktop app's SSH sessions, in the node's warm pool checkout, and Mnemo tracks, finishes, checks, reviews and merges it from the hub exactly like a local agent worker.

## Kind
implementation

## Context
WHY: roadmap phase 4 of remote workers (design: plan c8a1a6f5; node runtime: a040713f; hub placement, sync, remote checks: 9a2f4b67, all merged on wt/mnemo). Phase 3 keeps Claude-agent tiers local (spec dispatch-routing "Workers are placed on a host after the tier is chosen": "Claude-agent-tier workers MUST stay local"). The user wants Claude workers on the other machine too. Remote hosts are Windows or Mac only. Never propose a Claude subscription endpoint, CLI-wrapping or the Agent SDK inside Mnemo: Mnemo NEVER launches `claude` itself. The Claude Code lead starts the remote Claude session with its own desktop-app tools.

HOW CLAUDE-AGENT WORKERS RUN TODAY (local; anchors to read): a dispatch on an agent tier returns a `claude_agent` block {branch, effort, isolation:"worktree", model, prompt with a one-time launch token} (team/spawn.rs start_agent_worker ~:300, team/dispatch.rs); the lead launches the Agent tool with that prompt; the plugin's WorktreeCreate hook (`mnemo2-mcp worktree-create`, src-tauri/mnemo2-app/src/mnemo2_mcp/hooks.rs ~:321-420) gives the agent the worker's warm pool checkout; the PreToolUse gate (`gate-agent`) admits it via the launch token; team/agent_watch.rs finds the agent's transcript under ~/.claude/projects (find_transcript, look, tick), derives agent_phase, detects stalls (STALL_MS) and finishes the worker when the agent ends (meta_finished); team/agent_log.rs reads the transcript into a Transcript; hand-back to a Mnemo model happens only when the lead is really gone (SPEC "Mnemo owns the lifecycle of a worker it hands to a Claude Code agent"; BUG "Hand Claude-agent workers back to Mnemo only when the lead is really gone"). Plugin: mnemo2/plugin (hooks/hooks.json, bin/mnemo2-mcp, skills). External lead attach: src-tauri/src/mnemo2/mcp_server.rs and team/external_lead.rs.

THE DESKTOP APP SIDE (what the lead can do, not Mnemo): the Claude Code desktop app's start_session tool can start a session `target: "ssh"` on a saved SSH connection (`host` = the connection name from list_start_targets, `cwd` = a folder on that host), with a prompt. The started session reports back to the lead when it ends a turn (a note with its report), and the lead can message it (SendMessage). Today the user has NO saved SSH connections, so nothing in this phase can be tested against a real SSH session; every automated test must stand in for the session. The remote machine needs Claude Code installed and signed in by the user; Mnemo never stores or handles Claude credentials.

WHAT EXISTS FOR REMOTE HOSTS (phase 3): team/remote.rs RemoteWorkers (prepare_checkout -> RemoteCheckout {node_id, node_name, os, project, checkout, path, synced_tip}, sync_shadow, run_checks, reserve/release_reservation, qualify, the monitor and reconciler), team/placement.rs place_worker (Claude-agent workers always Local today), WorkerRecord.remote, team_hosts (list/pair/revoke, NeedsApproval), remote_hub.rs AppHub, src/remote/repo.rs node checkouts, src/remote/node.rs NodeExtension seam, mnemo2-node binary. Rules learned: never hold the team's records and live locks together; tests bind loopback only; no cfg(windows) outside the policy list; tests keep temp dirs under target/.

SETTLED FOR THIS PHASE (lead decisions):
1. The remote Claude worker is a Claude Code session on the host started by the LEAD through the desktop app's SSH sessions (start_session target "ssh"), never by Mnemo. Mnemo's job: decide placement, prepare the node checkout, hand the lead a launch block naming the SSH connection, the folder on the host and the prompt, then track, finish, check, review and merge the worker from the hub.
2. The session works directly in the node's pool checkout (the path RemoteCheckout.path), committing on the worker's wt/agent-* branch there; the hub syncs it back with the existing shadow sync. No WorktreeCreate hook on the host.
3. Placement: an agent-tier worker may go to a host only when that host is qualified for the project AND has a known SSH connection the lead can start sessions on; otherwise it stays local exactly as today. A lead pin with host wins as for Mnemo workers.
4. Tracking: the hub must see the remote session's liveness, activity and end. The research step decides between (a) the node watching the Claude Code transcript files on its own machine and serving an AgentView-like status over the link, (b) the lead reporting through team_agent_done when the session's end note arrives, or a combination. Hand-back to a Mnemo model stays as strict as today.
5. Approval: whether the lead may start each remote session directly or each start needs the user's click is a user decision taken after the research step; the research step only names what each choice requires.
6. Phase 5 (Settings → Worker hosts UI, pairing UI, link-loss UI, user docs) is out of scope.

VERIFY: the four .coding/checks.toml commands (cargo test --workspace, cargo clippy --workspace --all-targets, npm test --workspace mnemo2, npm run check --workspace mnemo2). Team code compiles only with --features mnemo2. Existing local agent-worker tests must pass unchanged.

## Acceptance scenarios
- With a qualified host that has a linked SSH connection, an agent-tier team_dispatch without a host places the worker on that host and the dispatch answer tells the lead to start a Claude Code session there via start_session target "ssh" in the worker's node checkout.
- The remote Claude worker's commits reach the hub shadow; team_run_checks runs on the node; team_review and team_merge work exactly as for a local agent worker.
- team_status shows the remote agent worker's host, phase and activity, and the worker finishes when its session ends.
- With no linked SSH connection (the user's current setup), agent-tier dispatch behaves exactly as today: local, with the existing claude_agent block.
- Mnemo never launches claude itself and never handles Claude credentials.

## Spec changes

### dispatch-routing

#### MODIFIED Requirements

##### Requirement: Workers are placed on a host after the tier is chosen
After the tier is chosen, dispatch SHALL place a Mnemo-model worker on a connected paired worker node that has a free slot and whose operating system can run the project's checks, and SHALL run it locally otherwise. A lead-supplied host MUST win over automatic placement. A Claude-agent-tier worker MAY be placed on such a node only when the node also has a linked SSH connection on which the lead can start a Claude Code session; otherwise it MUST stay local. Mnemo MUST NOT start the Claude Code session itself.

###### Scenario: No node connected
- **WHEN** the lead dispatches a Mnemo-model worker
- **WHEN** no worker node is connected
- **THEN** the worker runs locally exactly as before

###### Scenario: Idle suitable node
- **WHEN** the lead dispatches a Mnemo-model worker without a host
- **WHEN** a connected node has a free slot and passed the project's checks
- **THEN** the worker runs on that node
- **AND** team_status shows the node as the worker's host

###### Scenario: Lead pins local
- **WHEN** the lead dispatches with host "local"
- **THEN** the worker runs locally even when a node is idle

###### Scenario: Agent tier without an SSH link
- **WHEN** the lead dispatches an agent-tier worker
- **WHEN** no qualified node has a linked SSH connection
- **THEN** the worker stays local and the dispatch answer is the existing claude_agent block

###### Scenario: Agent tier on a linked host
- **WHEN** the lead dispatches an agent-tier worker without a host
- **WHEN** a qualified node with a free slot has a linked SSH connection
- **THEN** the worker is placed on that node
- **AND** the dispatch answer tells the lead to start a Claude Code session on that SSH connection in the worker's node checkout

### external-lead

#### ADDED Requirements

##### Requirement: A remote Claude-agent worker's session is started by the lead
The dispatch answer for an agent-tier worker placed on a host SHALL carry a claude_session block naming the SSH connection, the node checkout and the prompt. Mnemo MUST NOT start the session or launch claude itself. Mnemo SHALL follow the session through the host node and finish the worker when the session ends its turn, and team_agent_done SHALL remain authoritative.

###### Scenario: Remote agent dispatch
- **WHEN** the lead dispatches an agent-tier worker that is placed on a linked host
- **THEN** the answer carries a claude_session block with target "ssh", the SSH connection, the node checkout path and the prompt
- **AND** the answer carries no claude_agent block and no launch token

###### Scenario: Session ends its turn
- **WHEN** the remote session's transcript on the host ends its turn
- **THEN** Mnemo finishes the worker with the session's last answer as the report
