# Plan: Flaky team tests fail the workspace check under load

## Goal
Both tests pass deterministically under a loaded parallel `cargo test --workspace`, so Mnemo's check runs stop failing on unrelated changes.

## Kind
bug_fixing

## Context
EVIDENCE: Mnemo's own check runs at 418468e3 (shotArchive01, 2026-11-23) and 97ee42d8 (agentPhaseUi01, a frontend-only change) both failed `cargo test --workspace` with exit 1; the lead's rerun in the 97ee42d8 checkout named the failure: `resume_refuses_an_idle_live_worker_once_closing` panicked at tests.rs:11205, the FIRST assertion, which reads the worker back from team.json on disk right after `usage_limited_failed_worker()` and expects (Failed, error set). So under load the persisted ledger does not (yet) show the fixture's state: either the fixture's save has not landed (debounced or telemetry-delayed writes; persistence.rs LEDGER_FLUSH_DELAY is 1 s for telemetry-only changes) or something already moved the worker (a usage-limit auto resume, the agent watcher, a routing write). The test then also relies on `sleep(200ms)` to get the resume past its entry check before `closed` is set. A separate run saw `mnemo_check_run_refuses_a_configured_core_operation` fail once in a parallel run of the team tests (passed alone). Diagnose both from the code; do not just raise timeouts or add retries.

RULES: fix the root cause in the test fixture/test (deterministic synchronization: await the save or a notify/barrier instead of wall-clock sleeps) and, only if the diagnosis shows the product code races, in the product code with its own test. Keep each test's intent: the first proves a resume that passed its entry check is refused once the runtime closes and nothing is persisted; the second its own refusal.

REGRESSION TEST: `resume_refuses_an_idle_live_worker_once_closing` itself, made deterministic (plus `mnemo_check_run_refuses_a_configured_core_operation` if its diagnosis finds a race). Proof of the flake before the fix: run it in a loop under load, e.g. `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::team::tests::resume_refuses_an_idle_live_worker_once_closing` 30 times while `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::team` runs in parallel, and record how often it fails before and after.

VERIFY: the loop above with 0 failures after the fix; `cargo test --workspace`; `cargo clippy --workspace --all-targets`.
