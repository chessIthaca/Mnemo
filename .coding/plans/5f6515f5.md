# Plan: Run-All orphaned in-flight items — drain requeues + adopt-on-dispatch

## Goal
Make run-all orphaning impossible: no backlog item is ever left InFlight without a live owner. (1) The main-agent-exit drain requeues its item to Pending (checkpoint sha preserved at the note head) instead of leaving it InFlight — the queue becomes the recovery. (2) Run-all start adopts orphaned InFlight items (no live dispatch pointer in this instance): requeues them to Pending so the normal dispatch order picks them up — this also reclaims crash leftovers and the live orphan 35b94671 on the next run-all start. (3) The forwarder's Exited arm clears single_in_flight on main-agent exit so a stale pointer cannot misattribute the next agent's first turn resolution or block adoption. The mid-session intervention contract (backlog b83e891f: steer keeps a run-all item InFlight with its stopped run so the completing turn resolves it) is untouched — only dead-owner paths change.

## Context

Design agreed with the user: exit-drain requeues to Pending (the queue is the recovery — "finish the executing item before starting a new one" happens by queue order); run-all start adopts unowned InFlight items (crash belt-and-braces); the b83e891f mid-session contract (steer keeps InFlight with the stopped run) stays untouched — only dead-owner paths change. The InFlight → Pending transition row already exists (backlog.rs transition table; handle_user_intervention's single-arm uses store.transition(id, BacklogStatus::Pending, Some(full)) at run_all.rs:2288 — the exact shape to mirror). The guarded requeue stays strict (requeue_refuses_pending_in_flight_and_unknown pins it) — adoption/drain use transition, never requeue.
