# Plan: Harden plan-lifecycle tools + clickable plan staircase

## Goal
Harden the plan-lifecycle tools so the agent can't silently complete a step in the wrong stacked plan: (1) echo the active plan name in every complete_step result, (2) add an optional plan_id arg to complete_step that errors on a mismatch, (3) add a current_plan() read-only command for recovery.

## Context
The plan-completion miscount happened because complete_step is positional + plan-agnostic: when two stacked plans share an index range, completing a step in the wrong plan is silent. Three hardening changes to the plan-lifecycle tools (all in the .coding/ plan state — bookkeeping, AutoRun, no approval gate):

1. Echo the plan name + step in every complete_step result (passive orientation).
2. Add an optional plan_id arg to complete_step that verifies it matches the active plan (active catch).
3. Add a current_plan() read-only command returning the active plan's id + title + step count (recovery).

Explored the plan tools: create_plan returns the plan id (already available). complete_step(step_index) is the only completion path. The workflow state already tracks the plan stack. The plan tools live in the agent's tool layer (src/tool/workflow/plan.rs area) OR the .coding/ state — need to find where complete_step is implemented to wire these.
