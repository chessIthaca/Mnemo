# Plan: Add web_fetch tool (read-only URL fetch for research)

## Goal
Add a read-only `web_fetch` agent tool: fetch an http/https URL, strip HTML to readable text, cap the output, return status + content-type + final URL + body. AutoRun so it's usable in Planning/Complete for research (e.g. reading craby.rs docs).

## Kind
implementation

## Context
The agent has no way to fetch a URL — it couldn't read craby.rs to assess it as an architecture option. reqwest is already a dep (Cargo.toml:51, rustls-tls+json+gzip+brotli+deflate). regex is already a dep (Cargo.toml:38). The tool pattern: a struct impl Tool (name/category/schema/safety/execute), registered in register_agent_tools (factory.rs:513), listed in the expected_tool_names test (factory.rs:1085), mod entry in src/tool/agent/mod.rs, strategy mention in prompt.rs TOOL STRATEGY (line 147). AutoRun Agent tools are visible in ALL workflow states incl Planning/Complete (mod.rs:199) — the research use case. cap_tool_output (mod.rs:45) caps output at 100KB.

## Steps
- [x] 1. **Create the web_fetch tool module** — Create `src/tool/agent/web_fetch.rs`. A `WebFetchTool` struct with `pub fn new() -> Self`. Implements `Tool`: name="web_fetch", category=ToolCategory::Agent, safety=SafetyLevel::AutoRun (read-only GET, no project mutation — usable in Planning/Complete for research). Schema: properties { url: string (required, "The http/https URL to fetch"), max_length: integer (optional, "Max chars of body text to return (default 50000)") }. In execute: (1) parse args; (2) validate URL — reject anything whose lowercase form doesn't start with `http://` or `https://` (blocks file://, javascript:, data:, etc.); (3) build a reqwest::Client with .timeout(Duration::from_secs(30)).redirect(Policy::limited(5)).user_agent("myharness-agent/0.1") (rustls-tls is already enabled); (4) GET the URL; (5) on error return ToolResult::error with the message; (6) read status + content-type header + the response .text().await; (7) if content-type contains "html", strip to readable text via a pure `html_to_text(html: &str) -> String` helper (regex: remove `(?is)<script[^>]*>.*?</script>`, remove `(?is)<style[^>]*>.*?</style>`, replace all `<[^>]+>` with a space, collapse `\s+` to single space, trim); (8) cap to max_length (default 50000) with a truncation note if cut; (9) return ToolResult::success with a header line `GET {url} → {status} ({content_type})\nFinal URL: {final_url}\n` then the body text. Wrap the whole thing in cap_tool_output (from src/tool/agent/mod.rs) as a second safety net. Add doc comments on the struct + pub fn + the html_to_text helper. Use `use crate::tool::agent::cap_tool_output;` + the standard tool imports (async_trait, serde::Deserialize, serde_json::json, crate::provider::ToolSchema, crate::tool::{SafetyLevel,Tool,ToolCategory,ToolResult}).
