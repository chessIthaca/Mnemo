# Plan: Fix console mode on Windows: attach/alloc console + rewire stdio (CONIN$/CONOUT$)

## Goal
Make `--console` work when the release (GUI-subsystem) exe is launched from a terminal or shortcut: attach (or allocate) a console AND rewire the process std handles to CONIN$/CONOUT$/CONERR$ so the REPL displays output and accepts typed input.

## Kind
bug_fixing

## Context
Release builds are GUI-subsystem (#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")], main.rs:10). console::attach_parent_console() (src-tauri/src/console.rs:1502-1523) only calls AttachConsole(ATTACH_PARENT_PROCESS) — it never rewires the process std handles (AttachConsole does NOT populate the standard-handle table) and has no AllocConsole fallback. PowerShell launches GUI-subsystem children with NULL std handles → stdout prints go nowhere and stdin.lock().lines() errors/EOFs instantly → REPL treats it as stdin-EOF ("— stdin closed") → invisible exit. Also migrate_legacy_config_dir() (main.rs:111) runs before the console check and can eprintln; Rust caches the stdout handle on first use, so the console check + attach must move to the very top of main(). Debug builds (console subsystem) work — why it never showed in dev. REPL logic itself is sound (shipped 488d675; review 2026-08-21 findings already fixed). No past decision covers console stdio (context_pack checked).
