# Plan: Mission control split can be resized by dragging

## Goal
Mission control's split between the worker list (left) and the worker output (right) has a draggable divider, keyboard-resizable, remembered per project.

## Kind
implementation

## Context
Why: the user: "In mission control the screen is split with left showing all the workers and right showing the LLM output. There is no way for me to have a horizontal slider to resize these to my liking."

Verified facts:
- verified: the split is a fixed CSS grid in `mnemo2/src/components/ControlRoom.svelte` line 183: `.control-layout { display: grid; ... grid-template-columns: minmax(340px, 0.88fr) minmax(430px, 1.12fr); }`, with narrower variants at `@media (max-width: 980px)` (line 201) and a stacked one-column layout at `@media (max-width: 760px)` (line 207). The right side is `.worker-pane` (line 196).
- verified: the lead's side panel already has the pattern to copy: `mnemo2/src/components/Workbench.svelte` / `WorkerPanel.svelte` use a `.resizer` button (pointer capture drag, ArrowLeft/ArrowRight ±24, `aria-label`, `title`), and the width is clamped in `mnemo2/src/lib/store.ts` (`clampWorkbenchWidth`, `MIN_LEAD_WIDTH`, `reclampWorkbenchWidth` on window resize) and persisted per project through `ProjectPreferences` (`workbench_width` in `mnemo2/src/lib/projectEngine.ts` line 21 and `src-tauri/src/mnemo2/project.rs` ~line 102, validated around line 126; saved via `schedulePreferenceSave`).
- verified: worker rows keep a fixed 152px status column (`mnemo2/src/components/WorkerRow.svelte` `.worker-meta`), so the list has a practical minimum width.

Decisions:
- Replace the fixed columns with `grid-template-columns: <boardWidth>px minmax(<min-right>, 1fr)` driven by a new `boardWidth` preference, plus a divider between the two panes styled like the existing `.resizer` (a thin line that highlights on hover/drag, `col-resize` cursor, focusable, ArrowLeft/ArrowRight ±24, Home/End not required). Double-click on the divider resets to the default.
- Bounds: list min 300px (fits the status column), right pane min 420px; the list max is the available width minus the right minimum; re-clamp on window resize like `reclampWorkbenchWidth`. Default: today's proportion (about 44% of the width) when nothing is saved.
- Persist as `board_width: Option<u32>` in `ProjectPreferences` (Rust, `#[serde(default)]` so old saved files still load; None = default proportion) and `board_width: number | null` in `projectEngine.ts`; validate 300..=8192 when present. Add the field and its validation next to `workbench_width`, not near `WORKBENCH_TABS` (another worker is appending a tab id there).
- Keep the ≤760px stacked layout as it is (no divider there); the 980px media variant is replaced by the clamp.
- Store: `setBoardWidth` / `reclampBoardWidth` placed directly after `reclampWorkbenchWidth` in `store.ts`, exported at the END of the actions object.

Verification: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::project`, `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`; in `mnemo2/`: `npx svelte-check --tsconfig ./tsconfig.json`, `npm run check:no-mock`, `npx vitest run` (store tests for clamp/re-clamp/default, a ControlRoom test for the divider's keyboard resize and aria). Never start a dev server or any command that does not exit on its own.

## Acceptance scenarios
- Dragging the divider between the worker list and the worker output resizes both panes; the list never gets narrower than its status column needs and the output keeps at least 420px.
- The chosen width is remembered after switching projects or restarting Mnemo2; a project with no saved width uses today's proportions.
- The divider is focusable and ArrowLeft/ArrowRight resize it; double-click resets it.
