# Plan: Mnemo2 opens in the light appearance by default

## Goal
A config that never set `[ui] theme` makes Mnemo2 open in the light palette, not dark. Existing explicit choices (light, dark, system) are unchanged.

## Kind
implementation

## Context
WHY: the user asked for Mnemo2's default appearance to be "light".

The theme word is `[ui] theme` in the shared engine config. `UiConfig::default()` (src/config/general.rs ~l.1185) sets it to "dark", and Mnemo2 reads it through src-tauri/src/mnemo2/appearance_settings.rs. Because `UiConfig` deserializes with that default, Mnemo2 cannot tell "unset" from "dark", so the engine default itself must become "light".

On the Mnemo2 side, three more places hold the dark default:
- `DEFAULT_THEME` in mnemo2/src/lib/theme.ts: the fallback for an unknown word and for the pre-paint cache when nothing is mirrored.
- The static `<html data-theme="dark">` and `<meta name="theme-color" content="#141510">` in mnemo2/index.html: what paints before any script runs.
- The preview's stored Appearance sample, `theme: "dark"` in mnemo2/src/test/previewAppearance.ts.

DECISIONS:
- Change the shared engine default to "light" rather than adding an Option or a Mnemo2-only default. Mnemo1 keeps its own localStorage choice (`mh.theme`) and reads the backend word only when it has none, so only a fresh Mnemo1 install sees light. That is accepted.
- app.css needs no change: its light tokens are on `:root`, and dark overrides sit under `:root[data-theme="dark"]`.
- TOML fixtures in tests that write `theme = "dark"` explicitly stay as they are; they test explicit values, not the default.

CONSTRAINTS:
- Don't touch frontend/ (Mnemo1), app.css or the Appearance page component.
- No new setting.

VERIFY:
- `cargo test --lib config::`
- `cargo test --manifest-path src-tauri/Cargo.toml appearance_settings`, or the src-tauri package's test filter for that module
- `cargo check --workspace --tests`
- `npm --prefix mnemo2 run check`
- `npm --prefix mnemo2 test`

## Acceptance scenarios
- With no `[ui] theme` in config.toml and nothing mirrored in localStorage, Mnemo2 paints the light palette from the first frame (index.html, the pre-paint cache and the authoritative read all agree on light).
- An explicit `[ui] theme = "dark"` or `"system"` keeps working exactly as before.
