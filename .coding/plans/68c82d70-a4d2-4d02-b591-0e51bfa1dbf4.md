# Plan: Show diff in DiffViewer after a file edit completes

## Goal
After a file_edit or file_write completes (tool_result arrives), keep showing the diff in the right-panel DiffViewer instead of reverting to the empty state.

## Context
The DiffViewer (frontend/src/components/views/DiffViewer.tsx) only shows a diff while a `pendingApproval` exists. When the `tool_result` event arrives, `handleAgentEvent` in useAgentStore.ts clears `pendingApproval` to null, so DiffViewer reverts to its empty "No pending edits" state — the diff vanishes the moment the edit completes. The tool_result handler already locates the matching call in the transcript (which holds the args: path/old_string/new_string/content) and the result (success). We can capture that into a `lastDiff` field and have DiffViewer fall back to showing it.

## Steps
- [x] 1. Add a `LastDiff` interface + `lastDiff: LastDiff | null` field to the store (useAgentStore.ts), with the tool name, path, old_string, new_string, content, success, and timestamp.
- [x] 2. In the `tool_result` handler, when the completed tool is `file_edit` or `file_write`, parse the call's args and store them as `lastDiff`; also switch the right panel to the diff tab so the user sees it.
- [x] 3. Update `DiffViewer` to fall back to `lastDiff` when there is no pending approval, rendering the same diff view with a 'completed' label + success/fail indicator.
- [x] 4. Build the frontend (tsc/vite) to verify it compiles.
