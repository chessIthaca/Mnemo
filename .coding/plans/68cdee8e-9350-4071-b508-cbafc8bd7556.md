# Plan: Retry mid-stream provider errors (connection reset)

## Goal
When the LLM provider resets the connection mid-stream (e.g. `os error 10054` / `WSAECONNRESET`) before any useful output, retry the whole `complete` call with backoff instead of killing the turn. Currently `complete_with_retry` only retries *connection-establishment* failures (when `provider.complete()` returns `Err`); a mid-stream `LlmEvent::Error` with no partial text/tool-calls is surfaced as a final error and the turn stops.

## Context
Two retry layers exist:
1. `complete_with_retry` (src/agent/dispatch.rs:180-208) — retries `provider.complete()` returning `Err` (connection failure), 3 attempts, 1s/2s/4s backoff. Does NOT cover mid-stream errors.
2. `run_turn_with_retry` (src/runtime/agent.rs:54-108) — retries `run_turn()` returning `Err`, 3 attempts, 1s/2s/4s backoff. But `run_turn` returns `Ok(TurnOutcome)` even on a mid-stream error (turn.rs:417-424), so this layer never fires for mid-stream errors.

The gap: a mid-stream `LlmEvent::Error` (openai.rs:293-316, emitted when reqwest's body decode fails — connection reset, unexpected EOF, etc.) is caught in turn.rs:332-337, emitted as `AgentEvent::Error { retrying: false }`, and since `text.is_empty() && !acc.saw_tool_calls()`, the turn returns `Ok(TurnOutcome{...})` at turn.rs:417-424 — a "successful" turn with no output. The outer `run_turn_with_retry` sees `Ok` and doesn't retry.

Fix approach: in `run_turn`, when a mid-stream error occurs with no partial output (no text, no tool calls), return an `Err` instead of `Ok`. This makes the existing `run_turn_with_retry` layer (agent.rs:54-108) kick in — it already emits `retrying: true` + backoff + retries the whole turn. This is the minimal, correct fix: it reuses the existing retry machinery rather than adding a third retry loop.

Key constraint: only convert to `Err` when there's NO partial output. If text or tool-call deltas already arrived, the stream produced useful content and we must NOT silently retry (would duplicate the partial response / re-execute side-effecting tool calls). The existing `had_error && text.is_empty() && !acc.saw_tool_calls()` branch (turn.rs:417) is exactly the right condition — just change its return from `Ok` to `Err`.

The `AgentEvent::Error { retrying: false }` emitted at turn.rs:332-336 must change to NOT be emitted on the retry path (the outer layer emits its own `retrying: true`). But if we return `Err` immediately, the outer layer handles the retry messaging. So we should remove the inner `AgentEvent::Error` emit for the no-partial-output case and let the `Err` propagate. However, the inner emit also covers the case where `had_error` is true but there IS partial output (text/tool calls) — in that case the turn continues and the error is surfaced. Need to preserve that.

Cleanest approach: keep the `LlmEvent::Error` handler setting `had_error = true` but DON'T emit the error event there. Instead, after the stream loop, in the `had_error && text.is_empty() && !acc.saw_tool_calls()` branch, return `Err` (which the outer layer retries). For the case where there IS partial output, the existing flow continues (text/tool-calls are processed) and the error is implicitly swallowed — but that's the existing behavior and acceptable (partial output is used).
