# Plan: Plan staircase, subagent close-x, model label, backlog edit, approval auto-switch, cleanup-on-spawn

## Goal
Six UI/UX improvements: (1) visualize the plan stack as a staircase in the Plan tab; (2) add a close-x to subagent tabs (never main); (3) show the model name as a second line in agent tabs; (4) add an edit button to backlog items; (5) auto-switch to a subagent when it hits a security approval; (6) clean up completed subagents when a new agent is spawned (not before).

## Context
Findings from exploration:

PARENT PLANS: Already wired correctly (Workflow.create_plan pushes sub-plan stack; get_workflow_state returns depth+parents; PlanProgress shows a flat badge). User wants a visual staircase.

PLAN WINDOW / TOOLBAR STATE: StatusBar.tsx reads `workflowState` from `workflowStates[activeAgent]` and `plan` via getWorkflowState(activeAgent). It DOES reflect the active agent. But the user perceives it doesn't reflect "the main agent" — likely because when viewing a subagent, the toolbar shows the subagent's state, and the model/provider shown is the GLOBAL default (s.model/s.provider), not per-agent. The model label is global. This ties into request #3 (model name per subagent).

AGENT TABS (MainPanel.tsx): Each tab shows name + status dot + "approve" badge. No close-x. No model name. Single line.

BACKLOG (BacklogView.tsx + backlog.rs): Has add/remove/reorder/retry/dispatch/clear-finished. NO edit command. BacklogItem has text/images/status/note. Need a backlog_edit command + UI.

SUBAGENT CLEANUP (events.rs): cleanup_inactive_subagents runs on Complete→Executing transition (fresh plan from Complete). User wants: clean up completed subagents when a NEW agent is spawned (not before). Currently cleanup only happens on the Complete→Executing transition. The user's rule: "cleaned up if all sub agents are done processing AND a new agent is spawned." So trigger cleanup in spawn_agent_shared: cancel inactive (not-running) subagents before/after spawning the new one. Don't clean up unless a new agent is spawned or someone presses the x.

APPROVAL AUTO-SWITCH: MainPanel.tsx has a "Switch & review" banner for non-active agents with pending approvals (never auto-steals focus). User wants: when a subagent hits a security approval, auto-switch to it. The approval_request event flows through useAgentEvents.ts → handleAgentEvent. Need to setActiveAgent to the subagent on approval_request IF it's a subagent (has parent_id) and not already active.

MODEL NAME PER AGENT: AgentLoop.provider() returns Arc<dyn LlmClient>; LlmClient::model() returns &str. Need to expose model per agent. Options: (a) add `model` to AgentInfo via list_agents (read from agent_loops), or (b) add a get_agent_model command. Simplest: extend AgentInfo with `model: Option<String>` populated from agent_loops in list_agents. Then store per-agent model in agentModels map; show in tab second line.

CONTRACT FIXTURES: AgentInfo fixture (dto-agent-info.json) + contract test will need updating if I add a field to AgentInfo. WorkflowStateInfo already has depth+parents (no change needed for staircase — pure frontend).

KEY FILES:
- Backend: src-tauri/src/ipc/agent.rs (AgentInfo, list_agents), src-tauri/src/ipc/spawn.rs (spawn_agent_shared), src-tauri/src/ipc/events.rs (cleanup), src-tauri/src/ipc/backlog.rs + backlog_cmds.rs (edit), src-tauri/src/main.rs (register cmd), src-tauri/src/ipc/contract_fixtures.rs + frontend ipc-contract.test.ts (fixture)
- Frontend: MainPanel.tsx (tabs + close-x + model line + approval auto-switch), PlanProgress.tsx (staircase), BacklogView.tsx (edit), useAgentStore.ts (agentModels map), useAgentEvents.ts (approval auto-switch), lib/tauri.ts (backlog_edit), lib/types.ts (AgentInfo.model)
