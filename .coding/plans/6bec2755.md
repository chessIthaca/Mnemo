# Plan: Backlog section in the Plans tab

## Goal
The Plans tab shows the project's backlog (ideas not yet planned) above the plans: the user can add, edit, reorder, defer and remove items, and mark one as planned, while plans stay below.

## Kind
implementation

## Context
Why: Mnemo1 had a Backlog view (`frontend/src/components/views/BacklogView.tsx`, commands in `src-tauri/src/ipc/backlog_cmds.rs`, Mnemo1-binary-only so Mnemo2 cannot call them); the user accepted the lead's proposal to bring it into Mnemo2 as a section of the Plans tab, because backlog items are plans-to-be.

Verified facts:
- verified: the kernel store is `mnemo::app::backlog::BacklogStore` (`src/app/backlog.rs` line 378): `open(path)` (394), `add(text, images)` (546), `remove(id)` (559), `reorder(&[ids])` (578), `edit(id, text, images)` (780), `set_deferred(id, bool)` (854), `set_plan_id(..)` (712), `set_status(..)` (734), `clear_finished()` (882), `items()` (907); `BacklogItem` (228) and `BacklogStatus` with `allowed_destinations` (306-311). Text goes through `normalize_new_item_text` (211).
- verified: the project backlog file is `.coding/backlog.jsonl` (104 lines today).
- verified: a known bug class: `.coding/knowledge/bug/2026-08-31-backlog-jsonl-clobbered-to-empty-by-stale-in-mem.md` — stale in-memory state persisted over committed entries after git operations. Open the store fresh for every command (or re-read before every write); never keep a long-lived in-memory copy in Mnemo2.
- verified: the Plans tab is `mnemo2/src/components/PlansView.svelte` (header + `PlanTab`), reached via Route "plans".

Decisions:
- New file `src-tauri/src/mnemo2/backlog.rs` with commands `backlog_items`, `backlog_add(text)`, `backlog_edit(id, text)`, `backlog_remove(id)`, `backlog_reorder(ids)`, `backlog_set_deferred(id, deferred)`, `backlog_clear_finished`, each opening `BacklogStore` on `<project root>/.coding/backlog.jsonl` per call. Register them in `src-tauri/src/mnemo2/mod.rs` directly after `ipc::board_plan_document` (other plans use other anchors). Emit the existing `mnemo2://board-changed` event (or a `mnemo2://backlog-changed` one) after writes so open views refresh. Images: keep existing image references intact; no image upload in this plan.
- Frontend: a collapsible "Backlog" section at the top of `PlansView.svelte` (only in PlansView, not the Workbench's Plan tab), in a new `BacklogSection.svelte` + `lib/backlog.ts`: pending items first in their order, an add box, inline edit, drag or up/down reorder, defer toggle, remove with confirm, a count of finished items with "Clear finished". Match the plan cards' look.
- Do not build "dispatch from backlog" or run-all: Mnemo2 plans work on the plan board; a later plan may add "Plan this" (lead planning from an item).
- Preview: add rows to the existing `plans` scene in `mnemo2/src/test/previewScenes.ts` (in place) through a dev-only seed in `lib/backlog.ts`.

Verification: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::backlog`, `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`; in `mnemo2/`: `npm run check`, `npm run check:no-mock`, `npx vitest run`. Never start a dev server or any command that does not exit on its own; the lead renders the preview.

## Acceptance scenarios
- The Plans tab shows a Backlog section above the plans listing the pending items of .coding/backlog.jsonl in order.
- Adding, editing, reordering, deferring and removing items updates .coding/backlog.jsonl, and an entry appended to the file by someone else is not lost on the next write.
- The Workbench's Plan tab does not show the backlog.
