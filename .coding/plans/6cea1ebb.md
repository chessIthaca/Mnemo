# Plan: Specs page keeps config.yaml intact, section headings keep the plan title, finished audits stop looking unfinished

## Goal
Saving from the Specs page changes only the key it edits and keeps every other byte of config.yaml. A heading inside a plan section never changes the plan's title or structure. A finished audit is not reported as waiting, and mission control offers no Stop for it.

## Kind
bug_fixing

## Context
Why: these four bugs came out of the live checks for plans 3ec1abde and 5779641d. The worst is the first: losing governed_files silently turns off plan_create's spec-impact gate, because a missing map means no gating.

Root causes, read in the code:
1. `ConfigFile` in src-tauri/src/mnemo2/specs_settings.rs (the write shape of `write_config`) has schema, context, rules and extra, but not governed_files. That key became a known field of `OpenSpecConfig` after the Specs page was built, so it is no longer in `extra` and is dropped. The re-serialization also drops every comment. Both `activate_schema` and `store_config` go through it.
2. `render_schema_sections` in src/app/workflow/plan_file.rs writes section text unescaped. `PlanFile::parse` in src/memory/plan_format.rs takes any `# ` line as the title and any `## ` line as structure. `escape_section_markers` in src/app/tool/workflow/plan.rs exists for exactly this and already guards goal and context; this path misses it.
3. `external_summary` in src-tauri/src/mnemo2/team/external_lead.rs counts every WorkerStatus::Completed as waiting, and a finished audit stays Completed for good.
4. mnemo2/src/components/WorkerDetail.svelte renders Stop for every worker; the earlier fix hid Resume, Compact and Steer for a finished audit but not Stop.

Decisions:
- config.yaml is edited in place, one top-level key at a time, rather than re-serialized. Its comments explain why each capability's files are governed, so they are worth keeping. An edit that would not read back as exactly the intended config is refused and the file is left untouched.
- The fix escapes at render time. board.json keeps the raw section text, so template comparison and the archive's research.md are unaffected.
- The plan parser in src/memory/plan_format.rs is not changed: it is kernel code shared with Mnemo1 and the render fix is enough.

Regression tests: `make_active_keeps_governed_files_and_comments` in src-tauri/src/mnemo2/specs_settings.rs fails without the fix because governed_files is empty after Make active. `a_section_heading_does_not_rename_the_plan` in src/app/plan_board.rs fails because the title becomes the heading. `external_summary_does_not_count_finished_audits` in src-tauri/src/mnemo2/team/tests.rs fails because the waiting count includes the audit.

Do not touch mnemo2.toml or any file under ~/.mnemo. Do not run release builds; the lead rebuilds.

## Acceptance scenarios
- After Make active on Settings > Specs, .coding/openspec/config.yaml differs from before only by its schema line: governed_files and every comment are byte-for-byte the same.
- Saving context and rules on the Specs page changes only those keys and keeps governed_files, unknown keys and comments.
- A config.yaml that cannot be edited safely (for example a one-line flow mapping) gives an error and is left unchanged.
- plan_update with a section whose text starts with '# Findings' leaves the plan's title unchanged, and the archive's research.md still holds the text as written.
- With one finished audit, one implementation worker awaiting review and one audit that failed before reporting, the session-start summary says 2 waiting on you.
- Mission control shows no Stop for a finished audit and keeps Stop for an audit that failed before reporting.
