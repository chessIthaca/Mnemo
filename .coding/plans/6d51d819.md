# Plan: Chat transcript: fill width + prompt/response/activity indent ladder

## Goal
Make the agent output window fill the available width and introduce a readability indent ladder: drop the max-w-4xl centered column and all max-w-3xl content caps (text fills the space); prompts (user + steer) left-aligned flush left; response text indented 1em; tool/memory/activity cards indented 2em; plus turn-grouping spacing before prompts. Display-layer only — no data/store/IPC changes.

## Kind
implementation

## Context
User request (two messages): (1) the agent output window has relative left/right spacing that wastes screen space — fill more of the available width so more text shows; (2) prompts of all kinds are right-aligned — make them left-aligned, sticking out further LEFT than response text (response a little indented), with tools and memory indented a little more; suggest additional readability improvements. Exploration: Conversation.tsx:107 wraps the transcript in `mx-auto max-w-4xl space-y-[0.5em]` (896px centered cap — the wasted side space); the scroll container (Conversation root, `h-full overflow-y-auto px-4 py-4`) is the available width. Message.tsx MessageImpl kinds: user (line ~312, `flex flex-col items-end`, cyan bubble `max-w-3xl rounded-br-sm`, images `max-w-3xl`), steer (~385, `flex justify-end`, amber `max-w-3xl rounded-br-sm`), assistant streaming (~336) + final (~346) both `max-w-3xl` wrappers, error (~375, full-width card with px-4 — cannot add pl directly, px conflict), qa (~416, bordered card), tool (~372, ToolCard root `py-[0.125em]`), memory (~431, MemoryEntryCard), vision (~436, VisionEntryCard), skill (~397, `py-[0.125em]` div). Conversation.tsx also renders ApprovalPrompt + QuestionPrompt directly (~126-139). Existing Conversation.test.ts pins only the show_tool_activity filter contracts (isActivityEntry/isKnowledgeActivityEntry/null branch/store flags) — untouched by this change. Conversation mounts in MainPanel.tsx (no change needed — the scroll container is Conversation's own root). Test infra: vitest node env, explicit include allowlist in frontend/vitest.config.ts, ?raw source-contract pattern (Conversation.test.ts is the in-file example). Design decisions: em-based indents (pl-[1em]/pl-[2em]) so the ladder scales with the app font-size setting; prompts left-aligned with the bubble corner cue flipped rounded-br-sm → rounded-bl-sm and max-w-3xl dropped (flex items-start shrink-to-fit, wraps at container width); turn-grouping via pt-[0.75em] on prompts (padding, not margin — avoids the Tailwind space-y vs mt conflict); level rule = who is speaking: user prompts (0), agent prose (1), agent tool-work (2); ApprovalPrompt + QuestionPrompt at level 1 (the agent asking the user). Additional suggestions to LIST in the final summary (not implement): vertical thread line on the activity channel, ~100ch prose cap with full-width code blocks, alternating turn tint, hover timestamps.
