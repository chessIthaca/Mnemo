# Plan: Investigate Rust build + test cycle bottlenecks

## Goal
Identify the key bottlenecks in the Rust build + test cycle (compile vs link vs test-execution) and produce concrete, ranked recommendations to speed it up — without changing shipped behavior. Output is an analysis report + recommendations, not source changes.

## Kind
research

## Context


## Steps
- [x] 1. **Measure compile vs link vs test-execution breakdown (lib crate, warm cache, no rebuilds). Run `cargo build --lib --timings` (warm) and capture the HTML timing report location; then `cargo test --lib --no-run --timings` (compile+link only, no test execution) to isolate compile+link from test-run time. Then `cargo test --lib` and note total wall time. Compute: compile_time = (test --no-run time), test_execution_time = (full test time) - (test --no-run time). Record all three numbers. Also run `cargo build --lib` (warm) once first to ensure the cache is hot so we measure incremental, not cold. Goal: know whether the pain is compile, link, or test-execution.**
- [x] 2. **Measure src-tauri (app crate) build time + link time separately. Run `cd src-tauri; cargo build --timings` (warm) and capture the timing report. The app crate pulls in Tauri + the whole lib; its link step is typically the single slowest operation in the workspace. Note whether the app's link dominates. Also check: does `cargo test` at the workspace root even build src-tauri's tests? (Run `cargo test --workspace --no-run --timings` and compare to lib-only to see the app's marginal cost.)**
- [x] 3. **Identify the heaviest dependencies by compile time. Run `cargo build --lib --timings` and open/read the generated `target/cargo-timings/cargo-timing-*.html` (or use `cargo tree --depth 1` + the timing report) to rank the top compile-time crates. Suspects: fastembed (ONNX Runtime), rusqlite (bundled C SQLite compile), chromiumoxide, tree-sitter (+ grammars), tauri, tiktoken-rs, image, reqwest. Record the top 5 by build time. Also run `cargo tree --prefix none --no-dedupe | Measure-Object -Line` (or count) to get the total transitive crate count — a rough proxy for compile cost.**
- [x] 4. **Check linker + toolchain configuration. Run `rustc --print target-libdir` and `rustc --version` to confirm the toolchain. Check whether `lld` (the faster linker) is available: look for `rustup component add rust-src` style — actually check `where lld-link` and `where lld` (lld ships with the LLVM toolchain that comes with rustup on Windows). Check `.cargo/config.toml` (none exists — confirmed). Check `rustc -C linker` defaults. Determine: is the default MSVC `link.exe` being used (slow) vs `lld-link` (much faster)? This is often the single biggest win on Windows.**
- [x] 5. **Audit Cargo profile settings + dev-dependency cost. Confirm there are no `[profile.dev]` / `[profile.test]` / `[profile.dev.package.*]` overrides (confirmed none in Cargo.toml). Identify opportunities: (a) `opt-level = 0` for the local crate is correct for dev, but heavy deps like fastembed/ONNX, tiktoken-rs, and image processing compile at opt-level 0 too — consider `[profile.dev.package.**
