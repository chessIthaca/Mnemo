# Plan: Spawned reviewer runs on the [models.reviewing] model (spawn-time pin)

## Goal
Make a spawned reviewer (spawn_agent with role:"reviewer", no explicit model) run on the [models.reviewing] model — falling back to [models.executing], then [models.subagent], then the default — via the existing forced-model pin, without changing any workflow-state transitions or gates.

## Kind
implementation

## Context
User question: the main agent switches to [models.reviewing] when the workflow enters Reviewing, but the actual review runs in a spawned reviewer agent — which model does IT get? Grounded findings: (1) spawn_agent_shared (src-tauri/src/ipc/spawn.rs:86, single choke point for IPC + console spawn) sets is_subagent=true via set_is_subagent, applies with_role("reviewer") + reviewer allowlist, and calls set_forced_model ONLY for an explicit model param (loop_impl.rs:573). (2) A spawned loop's workflow is born in Planning and never transitions (workflow/mod.rs:167) — so the reviewer's per-turn resolution today is: skill → [models.subagent] → [models.planning] → default; it NEVER sees [models.reviewing]. With no [models.subagent], a reviewer silently runs on the PLANNING model — the latent quirk. (3) The main agent's exit gate is structurally tied to ITS Reviewing state: finish is only exposed by the reviewing tool filter and denied outright to subagents (test dispatch_denies_finish_for_subagent_even_in_reviewing) — a spawn-time model pin changes no transitions and moves no gate (user concern resolved: state machine and model routing are orthogonal; only routing changes). (4) The spawn_agent TOOL already holds a ModelResolver (wired at src/agent/factory.rs:991) and already resolves an explicit model id via resolve_model_id before calling the spawner (tests: model_arg_resolves_and_is_passed_to_spawner, reviewer_role_is_forwarded_to_spawner in src/tool/agent/spawn_agent.rs). Design (user chose spawn-time forced model): in the TOOL layer, when role=reviewer and no explicit model arg, resolve the reviewer chain — resolver.resolve(ModelContext{Reviewing, skill:None, is_subagent:false}) (= [models.reviewing].or([models.executing]), model_resolver.rs:217 back-compat) → else resolve with is_subagent:true (= [models.subagent]) → else None (default provider) — and feed it through the existing explicit-model path so spawn_agent_shared's set_forced_model pins it. Precedence: explicit arg > reviewing.or(executing) > subagent > default (reviewing beats the generic subagent slot, mirroring the main agent where reviewing wins in Reviewing state). Documented limitation: the pin is snapshot-at-spawn (a Settings save mid-review does not re-route the reviewer — same as today's explicit-model semantics). Non-reviewer roles and the console.rs direct-spawn paths are unchanged (console spawns its own reviewers via spawn_agent_shared — out of scope, noted in docs step).
