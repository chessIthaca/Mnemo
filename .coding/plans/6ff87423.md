# Plan: Tool cards show the turn's elapsed time without the word Completed

## Goal
Every tool card in a worker thread and the lead chat shows how long the current turn has run when that call finished (live while it runs), drops the word "Completed", and keeps the call's own duration in the tooltip.

## Kind
implementation

## Context
Why: tool cards render `Completed · 0:00` for almost every call (components/ToolActivity.svelte, the `.tool-status` span: `{statusLabel}<ElapsedTime startedAtMs={entry.startedAtMs} endedAtMs={entry.endedAtMs} />`). Most calls finish in under a second, so the per-call time is 0:00 and the label is noise. The user wants a cumulative time and no word "Completed".

History to respect: plan b2052a9c (BUG "batch tool timers included earlier calls") made `startedAtMs`/`endedAtMs` on tool entries measure each call's own execution, because timers started at the batch announcement looked accidentally cumulative. That data stays exactly as it is. This plan does not touch the reducer or any timestamp; the cumulative figure is derived in the view from the existing per-call stamps, and the per-call duration moves to the tooltip.

Definition (decided): a "turn" starts at the first tool entry after a turn boundary. Boundaries: in the lead chat (LeadEntry[]), an entry with kind "message" and author "user"; in a worker thread (WorkerThreadEntry[]), a WorkerMessage (kind undefined or "message") with from "lead". The very start of the list is also a boundary. The turn start time is the `startedAtMs` of the first tool entry in that turn that has a `startedAtMs`. A tool card's cumulative time = (its endedAtMs, or now while running) minus its turn start. A tool entry without `startedAtMs` gets no time at all (as today).

Display (decided), in `.tool-status`:
- running: spinner icon as today, text = live cumulative time (e.g. `2:41`), no word.
- completed: text = cumulative time only (e.g. `2:43`), no word "Completed".
- failed: `Failed · 2:43` (the word stays; failures must stand out).
- tooltip (title) on the time: `Turn time 2:43 · this call 0:01` (per-call from the entry's own startedAtMs/endedAtMs; while running `Turn time 2:41 · running 0:03`).
- The article's aria-label keeps the status word (`<headline> — Completed`) for screen readers.

Files: mnemo2/src/lib/elapsed.ts (+ its test file if one exists, else new mnemo2/src/lib/elapsed.test.ts), mnemo2/src/components/ElapsedTime.svelte, mnemo2/src/components/ToolActivity.svelte (+ ToolActivity.test.ts), mnemo2/src/components/WorkerThread.svelte (+ WorkerThread.test.ts), mnemo2/src/components/LeadChat.svelte (+ LeadChat.test.ts). Tokens/CSS unchanged except as needed. Do not touch lib/teamState.ts, lib/store.ts or any Rust.

Verification: in mnemo2/: `npx vitest run src/lib src/components/ToolActivity.test.ts src/components/WorkerThread.test.ts src/components/LeadChat.test.ts`, `npm test`, `npm run check`.

## Acceptance scenarios
- A worker thread whose turn started at 0:00 shows its later fast tool calls as 0:12, 0:47, 2:43 instead of Completed · 0:00
- A running tool card's time counts up from the turn start, not from 0:00
- A failed call reads Failed · <turn time>; the tooltip on any time reads Turn time X · this call Y
