# Plan: Fix dead_code warning on ShellArgs.purpose

## Goal
Eliminate the `field purpose is never read` warning in src/tool/agent/shell.rs without changing behavior.

## Context
The `purpose` field on `ShellArgs` is deserialized but never read in Rust. It was added in plan d39ca7be so the frontend (frontend/src/components/chat/Message.tsx `argLabel`) can display "shell (running tests)" in the ToolCard — the frontend reads it from the raw tool-call args JSON, not from the Rust struct. So the field is intentionally consumed outside the crate; the Rust side only needs it for serde parsing/validation. Toolchain is rustc 1.95, so `#[expect(dead_code)]` (stabilized 1.81) is available — it documents intent and warns if the field ever becomes read in Rust (stale expectation).

## Steps
- [x] 1. Add `#[expect(dead_code, reason = ...)]` to the `purpose` field in src/tool/agent/shell.rs, updating the doc comment to note the field is consumed by the frontend from raw tool-call args.
- [x] 2. Run `cargo build` (and `cargo test`) to confirm the warning is gone and nothing regressed.
