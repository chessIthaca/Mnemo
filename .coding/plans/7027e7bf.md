# Plan: Landed workers' screenshots no longer open in the preview

## Goal
A worker's screenshots stay viewable in the preview after it merges, after its pool checkout is reused by another worker, and after Mnemo2 restarts; they go away only when the worker itself is deleted.

## Kind
bug_fixing

## Context
ROOT CAUSE (user report 2026-11-23, screenshot of a Landed worker): the window lists screenshot paths from the worker's transcript (mnemo2/src/lib/workbenchState.ts workerScreenshotPaths, `.coding/browser/screenshots/<name>.png`) and opens one through IPC `workbench_screenshot` (src-tauri/src/mnemo2/ipc.rs ~:1364) → `workbench::worker_screenshot(root, worker, relative)` (src-tauri/src/mnemo2/workbench.rs ~:630), which reads the file from the worker's checkout via `checkout_path` (~:355). Two faults:
1. After a merge the record's `worktree` is empty (the pool checkout was released, or the legacy folder removed), so `checkout_path` falls through to the legacy `.worktrees/agent-<id8>` derivation and fails with os error 2.
2. Even with a correct lookup the files are gone or soon will be: the offscreen browser writes PNGs inside the checkout (src/tool/browser/mod.rs SCREENSHOT_DIR = ".coding/browser/screenshots"); a legacy checkout is deleted at merge, and a released pool checkout is wiped by `git clean -ffdx` when the next worker reuses it (src/app/worktrees.rs provision_pool_checkout). In a repo where that folder is not ignored (Mnemo itself: `git check-ignore .coding/browser/screenshots/x.png` finds no rule), an untracked screenshot also makes `release_pool_checkout` refuse ("uncommitted work is retained"), so the merge leaves a "merged, but" note.

DECISIONS:
- Archive: before a worker's checkout is released or removed, copy every regular PNG file under `<checkout>/.coding/browser/screenshots/` (recursively; skip symlinks/junctions, files over the 20 MiB preview limit MAX_SCREENSHOT_BYTES, and files not starting with the PNG signature) into Mnemo2's state dir: `<state_dir>/screenshots/<worker_id>/<path relative to .coding/browser/screenshots>`. `state_dir` is TeamRuntimeOptions.state_dir (the dir of team.json; transcripts already live in `<state_dir>/transcripts/`). Never inside the project tree (the lead checkout must stay clean). Copy is idempotent: an existing archive file with the same size is kept; copy via a temp name + rename. The worker id must pass the existing validation (ASCII alphanumeric, ≥ 8) before it is used as a folder name.
- After a successful archive, remove the screenshot files from the checkout that Git does not track: `git -C <checkout> clean -fdx -- .coding/browser/screenshots` (tracked files are never touched). This keeps the pool release from refusing over screenshots. If the archive copy fails, do NOT clean; log with eprintln and let the release proceed as today (it may then refuse as before).
- Call the archive (+ clean) at every path that releases or removes a worker checkout: merge cleanup `cleanup_agent_worktree` (src-tauri/src/mnemo2/team/merge.rs ~:84; its callers merge.rs ~:512 and the retry ~:612, and control.rs ~:1216 merge recovery), and the start-screen `cleanup_workspace` (deletion.rs ~:636, release at ~:760). For both checkout kinds (Pool and Legacy). The confirmed user delete (`remove_checkout`, deletion.rs ~:1203) does not archive: deleting a worker deletes its archive folder `<state_dir>/screenshots/<worker_id>` too (where its transcript file is removed).
- Read: `worker_screenshot` gains the archive dir. Order: when the record holds a checkout (non-empty `worktree` that `checkout_path` resolves) and the file exists there, read it there; otherwise read `<archive>/<path relative to .coding/browser/screenshots>`. Keep every existing guard (relative path under `.coding/browser/screenshots`, Normal components only, `.png`, canonical path inside its base, regular non-link file, size limit, PNG signature) and apply the same guards to the archive base. When neither has the file, return exactly: "This screenshot is no longer available: the worker's checkout was released before Mnemo kept screenshots." (Workers merged before this fix lost theirs; nothing to recover.)
- No change to the window (mnemo2/src), the transcript format, team.json or the screenshot tool itself.

REGRESSION TEST: `a_merged_workers_screenshot_still_opens` in src-tauri/src/mnemo2/team/tests.rs (follow the existing real-repo team tests such as `a_merged_workers_pool_is_reused_by_the_next_dispatch`). Dispatch a worker into a pool checkout, write an untracked valid PNG to `<checkout>/.coding/browser/screenshots/shot-1.png`, commit some other change, review and merge. Assert: the merge leaves no "merged, but" error, the pool checkout is released, and `workbench::worker_screenshot` for that worker and `.coding/browser/screenshots/shot-1.png` returns a `data:image/png;base64,` URL. Then dispatch a second worker (it reuses the pool, whose clean wipes ignored files) and assert the first worker's screenshot still opens. Without the fix it fails with "checkout is unavailable".

VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::team` and `mnemo2::workbench` while iterating; at the end `cargo test --workspace` and `cargo clippy --workspace --all-targets` (warning-free).

## Acceptance scenarios
- After a worker that took a screenshot merges, clicking that screenshot in its thread shows the PNG in the preview pane instead of 'checkout is unavailable'.
- The screenshot still opens after the next worker reuses the same pool checkout and after Mnemo2 restarts.
- A merge whose worker left an untracked screenshot in a repo that does not ignore .coding/browser/screenshots releases the checkout without a 'merged, but' note.
- Deleting the worker removes its archived screenshots; a screenshot of a worker merged before this fix shows 'This screenshot is no longer available: …' instead of an OS error.

## Bug
Clicking a screenshot of a merged (Landed) worker opens the browser pane with "worker '<name>' checkout is unavailable: The system cannot find the file specified. (os error 2)". The screenshots are lost once the worker's checkout is released or removed.

## Regression test
a_merged_workers_screenshot_still_opens

## Decisions
- 2026-11-23: no spec impact: Where Mnemo2 keeps worker screenshots for the preview is not specified by any capability; review, merge and checkout behaviour are unchanged apart from removing untracked screenshot files after they are archived.
- 2026-11-23: Tool-card thumbnails use the same fallback: the IPC that serves a worker's tool images (ipc.rs, the command after `workbench_screenshot`, which calls `workbench::worker_checkout` then `read_tool_image`) must, for a path under `.coding/browser/screenshots/`, use the same checkout-then-archive lookup as `worker_screenshot` instead of failing when the record no longer holds a checkout. Other image paths keep today's behaviour. Test: `a_merged_workers_screenshot_thumbnail_still_loads`.
