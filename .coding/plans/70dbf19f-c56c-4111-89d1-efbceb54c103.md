# Plan: Accept string-or-map steps in create_plan/update_plan

## Goal
Make `create_plan` (and `update_plan`) accept steps as either plain strings OR `{header, body}` map objects, so a model's natural structured step input no longer fails with "invalid type: map, expected a string". Normalize map steps to the documented `**header** — body` string form at the tool-arg boundary; keep the workflow layer (Vec<String>) unchanged.

## Kind
implementation

## Context
Backlog item #38: `create_plan` rejects map-shaped steps. Confirmed live: passing `steps: [{header, body}]` fails with `invalid arguments: invalid type: map, expected a string`. The tool's own schema description tells the agent each step is a bold header + a body, which naturally leads models to emit a structured object per step — but the serde type `Vec<String>` only accepts flat strings, so a well-formed model call errors. Same gap in `update_plan` (`steps: Option<Vec<String>>`, src/tool/workflow/plan.rs:61). The workflow layer takes `Vec<String>` (src/workflow/mod.rs:350, plan_file.rs:114), so normalization must happen at the tool-arg boundary. Fix: introduce a shared `StepInput` untagged serde enum (string OR {header, body}) with a `to_text()` that joins map parts as `**{header}** — {body}` (matches the documented format), use it for `steps` in both CreatePlanArgs and UpdatePlanArgs, update both JSON schemas (`items` oneOf string/object), and keep the rest of the pipeline (Vec<String> downstream) unchanged. Regression tests: map-step, string-step, and mixed-step inputs for create_plan; map-step for update_plan.

## Steps
- [x] 1. **Add StepInput enum + to_text normalization** — In src/tool/workflow/plan.rs, add a private `StepInput` enum with `#[serde(untagged)]`: variant `Text(String)` and variant `Map { header: String, #[serde(default)] body: String }`. Add `impl StepInput { fn to_text(self) -> String }` returning the string verbatim for Text, and for Map `format!("**{}** — {}", header, body)` (body-only when header is empty: `format!("**{}**", header)` trimmed — actually: if body empty → `**{header}**`; else `**{header}** — {body}`). Doc-comment both the enum and `to_text` explaining untagged acceptance of string-or-map and the join rule. Unit tests for to_text (string passthrough; header+body join; header-only).
- [x] 2. **Wire StepInput into CreatePlanArgs + execute** — In src/tool/workflow/plan.rs: change `CreatePlanArgs.steps` from `Vec<String>` to `Vec<StepInput>`. In `CreatePlanTool::execute`, after deserializing, map `args.steps` through `StepInput::to_text` into a `Vec<String>` (`let steps: Vec<String> = args.steps.into_iter().map(StepInput::to_text).collect();`) and use that for the `is_empty` check, the `create_plan_with_kind` call, and the success output/data `step_count`. Update the `steps` JSON schema in `CreatePlanTool::schema` so `items` is `{"oneOf": [{"type":"string"},{"type":"object","properties":{"header":{"type":"string"},"body":{"type":"string"}},"required":["header"]}]}` and append to the description: "A step may also be an object {header, body} — it is normalized to the **header** — body string form."

Update the update_plan `steps` schema description to note the string-or-object acceptance.
