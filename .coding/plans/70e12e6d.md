# Plan: PR gate: build, clippy and tests on every pull request

## Goal
Every pull request to main (and every push to main) runs the builds, both clippy runs and the Rust and frontend tests on GitHub Actions, and fails when any of them fails.

## Kind
implementation

## Context
WHY: today only CodeQL (.github/workflows/codeql.yml) runs on pull requests; .github/workflows/build.yml runs only on manual dispatch or v* tags. That is how v2.2.0 shipped with clippy red under #![deny(warnings)], and how nine Dependabot PRs looked green while three of them broke the build or tests (jsdom 31 broke Mnemo2's vitest suite; the two codeql-action bumps failed alone). The 2.2 retrospective (2026-11-11) named a missing PR gate as the common cause. The repo is public, so GitHub-hosted runner minutes are free.

DECISIONS:
- A NEW workflow file, .github/workflows/ci.yml. build.yml stays the release pipeline; do not edit it.
- One job on windows-latest, mirroring build.yml's Windows job setup (checkout, setup-node 22 with npm cache, dtolnay/rust-toolchain@stable, Swatinem/rust-cache) at the SAME pinned SHAs. Add the clippy component to the toolchain step.
- The frontends build before any cargo command: Tauri's generate_context! needs target/frontend-dist and target/mnemo2-dist (knowledge record "fresh Mnemo2 worker worktree needs npm ci + npm run build before cargo test").
- A guard test in tests/integration/ci_workflow.rs keeps the gate from being silently removed or weakened.

REPO RULES THE WORKFLOW MUST SATISFY (all enforced by tests/integration/ci_workflow.rs):
- workflows_pin_actions_to_full_shas checks EVERY *.yml in .github/workflows: each `uses:` must pin a full 40-char commit SHA with a `# vN` comment. The one allowed exception is `dtolnay/rust-toolchain@stable`.
- The workflow-level `CI` env var must be "true" or "false" (the tauri CLI reads it as a clap bool).
- The workflow-level permissions are exactly `contents: read`.
- Never put an unquoted `: ` (colon-space) inside a YAML scalar such as a step name. It broke build.yml once (knowledge record "BUG: GitHub build action invalid workflow — colon-space in unquoted YAML scalar").
- .gitattributes forces LF, so string checks with "\n" are safe.

VERIFY (worker): `cargo test --test integration ci_workflow` (all guard tests pass, including the new one). Only GitHub can run the workflow itself: the lead verifies the first live run on the wt/mnemo → main PR.

## Acceptance scenarios
- `cargo test --test integration ci_workflow` passes, including ci_workflow_gates_pull_requests_with_clippy_and_tests and workflows_pin_actions_to_full_shas
- A pull request to main shows a `ci / check` run that builds both frontends, runs both vitest suites, both clippy runs and the Rust tests, and is green on the current tree
