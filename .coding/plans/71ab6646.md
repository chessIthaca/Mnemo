# Plan: Browser tab: always hard-reload (bypass cache)

## Goal
The Browser tab's Reload button must always perform a hard reload that bypasses the HTTP cache (CDP Page.reload with ignoreCache, with a Reload() fallback), so pages never come back out of sync with their server state.

## Kind
implementation

## Context
Current state: browser_webview_reload (src-tauri/src/ipc/browser_webview.rs:593-605) calls wv.reload() → tauri 2.11.5 Webview::reload → vendored wry 0.55.2 webview2 reload() (vendor/wry/src/webview2/mod.rs:1413-1415) → ICoreWebView2::Reload() — a normal reload that serves cached subresources (the out-of-sync source). Mechanism chosen: CDP Page.reload with {"ignoreCache":true} via ICoreWebView2::CallDevToolsProtocolMethodAsync — the MS Learn documented example method for that API; no native hard-reload API exists in WebView2, and location.reload(true) is deprecated/ignored by Chromium. Plumbing: tauri 2.11.5 exposes no hard-reload hook and the app holds only tauri handles (with_webview would need webview2-com + windows as new direct src-tauri deps with version-matching risk + COM boilerplate), so the change goes into the vendored wry — the established convention (SSO patch: "Tauri 2 exposes no environment hook, so the flag lives in the vendored crate", vendor/wry/PATCHES.md, guarded by src-tauri/tests/wry_sso_patch.rs). Blast radius verified via graph search: browser_webview_reload is the ONLY caller of .reload() in app code, so patching wry's webview2 reload() affects exactly the Browser tab's Reload button. wry's webview2 backend already imports webview2_com::{Microsoft::Web::WebView2::Win32::*, *} and creates callback handlers manually (see the with_with_bump sites at vendor/wry/src/webview2/mod.rs:352/380/1639 — mirror that style for the ICoreWebView2CallDevToolsProtocolMethodCompletedHandler). Renumber convention: each vendored-patch state gets a distinct version (tao 0.35.4, wry 0.55.2) — bump to 0.55.3 so the lockfile visibly updates and no published-version ambiguity arises; [patch.crates-io] wry = { path = "vendor/wry" } already wired in the root Cargo.toml (~line 180 comment documents 0.55.2). Existing contract test stop_and_reload_commands_follow_navigate_pattern (browser_webview.rs:925) asserts the command body contains ".reload()" — still true after the change. Docs to sync: vendor/wry/PATCHES.md, README.md:81 (Browser tab bullet), PLAN.md:316 (wry row), root Cargo.toml comment, browser_webview.rs module + command docs, wry_sso_patch.rs version assertion (0.55.2 → 0.55.3). Verification: cargo test (root + src-tauri) green + warning-free under #![deny(warnings)]; after cargo update -p wry confirm NO "Patch `wry ...` was not used in the crate graph" warning; the new source-contract test fails on pristine wry (guards the patch). Windows-only by design (the Browser tab is the sanctioned Windows-only WebView2 exception; wry's webview2 module is cfg-gated upstream).
