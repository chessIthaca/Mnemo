# Plan: Spike path (a): bare Tauri Window + two ordered add_child webviews (game browser CDP + agent chat)

## Goal
Throwaway standalone Tauri spike to prove/disprove path (a) of the MIX architecture: a bare Window (no webview) + two ordered add_child webviews where the first grabs CDP port 9222 and the second renders without CDP. Produce a go/no-go verdict + cleanup. No changes to the real app; no commit.

## Kind
research

## Context
Scoping memo (.coding/scoping-native-mix-architecture.md) established the MIX architecture: native core (bare Tauri Window, no webview of its own) + two sibling add_child webviews in creation order — game browser FIRST (grabs 9222 → CDP), agent chat SECOND (renders React, no CDP). The make-or-break unknown is path (a): does a bare Tauri Window let the first add_child grab 9222, does the second render without CDP, and does IPC work inside an add_child webview? None of this is proven; Spike B (add_child + own port 9223) crashed the real app, so we spike in an ISOLATED standalone crate to avoid crashing the real app again.

Key source references: real app sets WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=9222 process-global before the builder (src-tauri/src/main.rs:60-65); Window::add_child (tauri-2.x src/window/mod.rs:1129) calls webview_builder.build() → fresh env per child; the real app uses tauri features=["unstable"] (gates add_child) + tauri-build. The real app's tauri.conf.json + Cargo.toml are the template to mirror for the spike crate.

The spike is a standalone Tauri binary in spike/mix-spike/ — isolated from the root workspace, deleted at the end. No commit.
