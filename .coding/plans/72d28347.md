# Plan: Actionable emission-artifact guard: per-op delta attribution + artifact_check opt-out (backlog 08d2125d)

## Goal
Make file_edit's ops path as resilient and diagnosable as multi_edit (backlog 08d2125d): (1) the shared emission-artifact brace guard must attribute a positive delimiter delta to the exact op(s) that caused it and report the call's before → after deficit, instead of the generic rejection; (2) prove and pin parity — the same ops array gets the same verdict through file_edit and multi_edit; (3) add an explicit, approval-gated `artifact_check: false` escape hatch on file_edit and multi_edit for a legitimate unbalanced restructure the agent has verified itself. Acceptance (from the item): the four reported call shapes apply as-is or fail with the explicit offending-op delta message; a ~1.6 KB / 20-op net-zero-delta file_edit call succeeds, matching the accepted multi_edit call; new edit_ops.rs tests cover (i) `}` → `} else {` + a compensating deletion → applied, (ii) the same op alone → actionable per-op error (documented choice), (iii) a genuinely truncated payload → still rejected.

## Context

Reported (2027-01-16, wt/mnemo, src-tauri/src/main.rs ~1404-1460, a `match (mode, enabled)` → `if enabled` restructure): file_edit rejected four ops/line payloads with the generic "emission artifact detected (unbalanced delimiters ...)" error while a larger multi_edit call on the same region was accepted, costing ~10 round-trips of hand-rebalancing.

EXPLORATION FINDINGS (verified by reading, not assumed):
- The guard IS already shared and already whole-file delta-scoped. `apply_ops` (src/tool/agent/edit_ops.rs:1185-1199) runs per-op LINE checks (anchor new_string / line-op payload) and ONE combined brace check `validate_emission_artifacts_braces(path, content, &current)` — `content` = the file before, `current` = the combined result. file_edit's ops path (prepare_edit_ops, src/tool/agent/file_edit.rs:421-431) and multi_edit's per-file path (prepare_files, src/tool/agent/multi_edit.rs:178-179 `apply_ops(...)`) both route through it, so both tools get the SAME verdict for the same ops array. The accepted multi_edit call and the accepted file_edit variant (the 10 ops PLUS `d1417`) both had a net-zero delimiter delta; the four rejected calls had a net +1. => The report's "multi_edit applies a weaker rule" premise is not what the code shows; the real defects are (1) the rejection is UNACTIONABLE — it names neither the offending op nor the deficit numbers, so the agent cannot rebalance in one shot, and (2) there is no explicit opt-out for a legitimate unbalanced restructure the agent verified itself.
- Single-path callers of the full validator: file_edit.rs:325 (lines), :396 (literal), :514 (append), :638 (regex) — all `validate_emission_artifacts(path, content, new_string, new_content)` (edit_ops.rs:97) = lines checks + `validate_emission_artifacts_braces` (edit_ops.rs:173-190: reject iff `rust_brace_deficit(new_content) > rust_brace_deficit(content)`).
- `rust_brace_deficit` (edit_ops.rs:214+) is a scoped Rust lexer (comments/strings/raw strings/chars skipped) returning unclosed openers + mismatched closers.
- Existing tests to keep green: edit_ops.rs:1617 `emission_artifact_checks_cover_line_payloads` (asserts the substrings "emission artifact" + "unbalanced delimiters"), file_edit.rs:1374 `emission_artifacts_are_rejected_pre_write` (:1401 asserts "unbalanced delimiters"), file_edit.rs:1409 `emission_artifact_validation_allows_legit_content`. multi_edit prefixes per-file errors with files[i] + path (file_error, multi_edit.rs:82-91).

DESIGN (decided):
- Attribution by EXACT running deficit: in `apply_ops`, for .rs only, track `deficits: Vec<usize>` (initial + after each op) with `rust_brace_deficit`. On a growth rejection, name every op whose step grew the deficit (index of total, the op's raw/verb, its delta) plus the call's before → after. Fragment-level arithmetic is NOT used — it is wrong when a closer closes a previously-unclosed opener (fragment deficit +1, file delta −1). Cost is O(ops × file) lexer passes, negligible vs the O(n) unified diff the same call already computes.
- Chosen semantics for a lone unbalancing op (acceptance allows "applied or an actionable per-op error — pick and document one"): REJECT with the actionable message; the truncation-artifact guard keeps its value, and the agent can now rebalance in one shot.
- Escape hatch: `artifact_check: Option<bool>` (default true) on file_edit and multi_edit, threaded into `apply_ops` (new param) and gating the four single-path validator calls in file_edit.rs; skips the whole emission-artifact family (line + brace classes). Both tools are already NeedsApproval, so the opt-out is approval-gated by construction. Documented as last resort: verify first (`cargo check`, `rustfmt --check <file>`).
- Error text must keep the substrings "emission artifact" and "unbalanced delimiters" (existing assertions) and must NOT carry the EditStaleRead marker (it is not a drift failure).

VERIFY: `cargo test edit_ops`, `cargo test multi_edit`, `cargo test tool::agent`, then full un-piped root `cargo test` + `cargo test -p mnemo-app` (both crate roots are #![deny(warnings)]).
