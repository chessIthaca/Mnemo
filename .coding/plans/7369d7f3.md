# Plan: Auto-compact between run-all items (auto_compact_on_plan_complete)

## Goal
Add an `auto_compact_on_plan_complete` setting (default false, [general] in config.toml, edited in Advanced settings) that, when on AND a run-all loop is active, compacts the main agent's context between items — after a plan completes and before the next backlog item is dispatched — by sending AgentCommand::Compact and waiting for the Compacted event (with failure/timeout proceeding anyway; compaction is an optimization, never a blocker). Interactive completions never trigger it (placement in the run-all branch only). Surface a brief "compacting…" state in the run-all progress line.

## Kind
implementation

## Context
Backlog item (advanced config): auto-compact after every plan completion, run-all only. Exploration findings at HEAD on wt/agenticcoding: (1) Compaction: AgentCommand::Compact is processed between turns (src/runtime/agent.rs:731-741 → compact_context :883, emitting CompactStarted → Compacted{before,after} on success — a no-op still emits Compacted — or Error on failure; the pairing contract is documented at agent.rs:869). Manager send is sync try_send: src/runtime/mod.rs:63-71 `mgr.send(id, cmd) -> Result<(), AgentCommand>`. (2) Trigger point: on_main_turn_resolved (src-tauri/src/ipc/run_all.rs:1129-1412) — its run-all branch resolves the item then calls run_all_dispatch_next at ~:1325; the stopped/halt paths return before :1325 (no compaction there — correct). CRITICAL: on_main_turn_resolved is awaited INLINE in the event forwarder (events.rs:530/562/572/890/911) — awaiting a compaction latch there would deadlock on its own output (the Compacted event flows through the blocked forwarder), so the wait+dispatch MUST be tokio::spawn'd. (3) Setting plumbing to mirror (enable_browser_inspection end-to-end): GeneralSection field src/config/general.rs:119 + Default :223 + tests :910/:918; SettingsSaveDto field src/config/settings_dto.rs:239 + apply arm :556-557 in validate_and_apply_settings_patch (:258-624); GetSettingsGeneral src-tauri/src/ipc/settings.rs:541 + from_config :769 + fixtures :1246/:1358; frontend tauri.ts:397 (get) + :513-517 (patch); AdvancedSection.tsx state/snap :60, load :93-94, dirty :131, save :163-164, checkbox :526. Live config is readable via state.project.config (Arc<Mutex<Config>>, path .general.general.<field>). (4) BacklogContext (src-tauri/src/ipc/state.rs:171-197) holds run-all state (auto_feed AtomicBool pattern); constructed at main.rs:450-456 + two more IpcState sites (~:575/:650). (5) Forwarder (events.rs) has local per-agent sets (notified_children) to mirror for compact_in_flight pairing; Compacted currently falls into the catch-all. (6) Progress line: RunAllProgress (backlog_cmds.rs:84-91, active/done/total) built in emit_backlog_changed :104-133; frontend types.ts:46, useAgentStore.ts:360, ipc-contract.test.ts:392-394. DESIGN DECISIONS: (a) wait via a shared watch::channel<u64> counter in BacklogContext — the spawned task subscribes BEFORE sending, records `before`, waits for counter > before with a 600s timeout (generous: summarization on a near-full context is slow; timeout proceeds anyway — never stall); (b) the forwarder increments on Compacted for the main agent AND on the pairing Error (tracked via a forwarder-local compact_in_flight HashSet keyed on CompactStarted) so a FAILED compaction resolves the wait immediately instead of burning the timeout; (c) if manager.send fails or there is no main agent, skip the wait entirely and dispatch; (d) compact unconditionally before every next-dispatch attempt when the setting is on (including the last item — spec-faithful "one per completed plan", harmless at run end); (e) implement the optional "compacting…" progress state (overnight observability); (f) tests follow the established run_all.rs patterns: fn_body source-contract assertions for AppHandle-bound wiring + pure behavioral tests for the wait helper.
