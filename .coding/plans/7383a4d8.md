# Plan: Test factory helpers for Endpoint/ModelSpec/OpenAiClientConfig

## Goal
Eliminate raw struct-literal duplication of Endpoint, ModelSpec, and OpenAiClientConfig across the test suite by adding feature-gated test_default() factories, so future config-field additions (sampling params, stops, capabilities) require updating only the struct definition, its Default impl, and the factory — never dozens of test literals.

## Kind
implementation

## Context
Survey findings: (1) src/provider/openai.rs tests hold ~57 OpenAiClientConfig literals (lines ~3424-6661), all the same shape: base_url "http://localhost/v1/", api_key "dummy", model "test-model", kind OpenAI, provider "test", plus 5-6 default-valued fields and ..Default::default(). (2) Endpoint literals: src/config/endpoints.rs tests (lines 749, 783, 933, 975, 1016, 1045, 1224, 1237), src/provider/client_factory.rs (helper fn endpoint at 415 + literals 529, 624, 665, 741, 891), src/agent/tests.rs (4615, 4721, 4860, 5943 + pin_test_endpoint helper at 4991), src/model_resolver.rs (423, 436, 796, 809), src/config/patch.rs (1054, 1078), src-tauri/src/console.rs (cfg_endpoint helper 2112), src-tauri/src/ipc/config_io.rs (ep helper 323). (3) ModelSpec literals: endpoints.rs (755, 787, 939, 979, 1020, 1049), patch.rs (869, 877, 915, 1058, 1082), client_factory.rs (671, 896, 905). (4) src/provider/vision.rs make_vision_client (319) builds OpenAiClientConfig. DESIGN: console.rs/config_io.rs are in the src-tauri crate and construct mnemo::config::Endpoint, so cfg(test)-gated helpers are invisible cross-crate — factories must be pub behind a new `test-support` cargo feature on the mnemo lib, enabled only via src-tauri's [dev-dependencies] (dev-deps never affect release builds; feature unification during cargo test is harmless). Baselines chosen from the dominant test conventions: Endpoint::test_default = name "test", kind OpenAI (the Default), base_url "http://localhost:9999/v1/", models [ModelSpec "m"], rest Default; ModelSpec::test_default = id "m", rest Default; OpenAiClientConfig::test_default = base_url "http://localhost/v1/", api_key "dummy", model "test-model", kind OpenAI, provider "test", rest Default. Uniform rule: every refactored literal ends with ..<Type>::test_default() so the factory is the single extension point. tests/integration/provider_integration.rs (#[ignore], env-driven values) keeps its raw literal — the crate's own integration tests cannot see cfg(test)/feature-gated items without changing the test command; out of scope. Production constructors (client_factory.rs openai_client_config :87, patch.rs validate_endpoint :127, src-tauri main.rs :1080, settings.rs DTO mappings) are NOT touched. deny(warnings) is active at both crate roots: removing literals will orphan imports (e.g. EndpointKind in agent/tests.rs test fns) — every file needs an import cleanup pass. README §Building (~line 108) documents cargo features and must mention the new one (docs-sync review check). This is a pure refactor: existing tests are the safety net; no new regression tests needed (no defect fixed).
