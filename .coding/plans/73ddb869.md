# Plan: Tool-call discipline: system-prompt block + runtime enforcement

## Goal
Harden tool-call discipline in two aligned layers: (1) a TOOL-CALL DISCIPLINE block in the compiled stable head (src/agent/prompt.rs — the system-level agent.md equivalent every project inherits) carrying the generation-time rules: content-first (never draft inside the call — create_plan/update_plan content must already exist in the same message), schema-first field checklist, pre-flight (non-empty args, non-blank required fields, no illegal JSON escapes — Windows paths with forward slashes), chunk-large-payloads, malformed-JSON → rewrite the COMPLETE call, two identical failures → stop and re-read the schema, never retry unchanged; (2) mechanical enforcement where the runtime can catch misses: create_plan rejects blank title/goal, update_plan rejects nothing-changed calls, and the turn.rs malformed-JSON feedback teaches back rewrite-complete/no-empty-args.

- [x] 1. **Add the TOOL-CALL DISCIPLINE block to the compiled stable head** — In src/agent/prompt.rs add `const TOOL_CALL_DISCIPLINE: &str` after APP_RULES (ends ~line 135), and push it in build_stable_head between APP_RULES and TOOL_STRATEGY (~line 397). Content, adapted to house style (backslash continuations, lean — head is cached but token-costed, target ≤250 tokens):
(1) CONTENT FIRST, CALL SECOND — the JSON body delivers text you already wrote; it is never where text gets invented. create_plan/update_plan are valid only when title/goal/steps are fully written in this same message; if you catch yourself opening a call with no content drafted, you are not ready to call — write the content, then emit the call carrying it.
(2) SCHEMA-FIRST PRE-FLIGHT — before emitting, name the tool and its required fields, check each is present and NON-BLANK in the call: create_plan → title, goal, steps (+bug when kind=bug_fixing); update_plan → steps (or steps+append:true); complete_step → step_index; memory_write → tier, title, content; ask_user → question + options (≥2); spawn_agent → name, task; file_edit/file_write → path (+new_string/content); shell → command, purpose; search → pattern. If you cannot name the fields, re-read the schema BEFORE emitting — never emit to find out.
(3) An empty argument object is valid only for the few genuine no-arg tools (current_plan, backlog_list, memory_search browse); for any tool with required fields it means the call body was never written.
(4) NO ESCAPE TRAPS — a lone backslash starts an illegal JSON escape (\x, \d): write Windows paths with forward slashes (C:/repo/path). Chunk large payloads: file_write the first section then mode:"append", update_plan append=true — never one giant body.
(5) A malformed-JSON error ("arguments JSON was malformed or truncated") means the args were empty, cut off, or illegally escaped — it is NOT a hint to shrink the call or tweak one field: re-read the schema, rewrite the COMPLETE call with every required field, emit the corrected call once, immediately.
(6) TWO identical failures in a row = stop emitting calls: re-read the tool's schema, re-draft the complete arguments from scratch, then emit one carefully built call. An identical call fails identically every time — never retry unchanged (the APP_RULES never-resend rule applies verbatim to parse failures too).
