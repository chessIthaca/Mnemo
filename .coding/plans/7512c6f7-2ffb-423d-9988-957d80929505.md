# Plan: Prompt cache-hit optimization (R1-R3): split stable head from volatile tail

## Goal
Lift provider prompt-cache hit rate from ~80.7% to ~98.5% by moving volatile sections (workflow state + recalled memories) out of the system-message head into a trailing message after the conversation history, where the provider's prefix cache is immune. Plus deterministic tool-schema ordering (R2) and recall ordering (R3) for cross-restart byte-stability.

## Context
From .coding/analysis/cache-hit-analysis.md (2026-08-13): measured 80.7% cache-hit rate over 82 requests; 15 full-prefix resets wasted 2,001,688 tokens (17.8% of all prompt tokens). Root cause: build_system_prompt (src/agent/prompt.rs:43-79) concatenates preamble → constitution → RECALLED MEMORIES (volatile) → WORKFLOW STATE (volatile) into messages[0], BEFORE the conversation history. Any complete_step / state transition / new turn changes messages[0] → firstDiff=0 → entire cache prefix invalidated. Projected hit rate if fixed: 98.5%.

Verified current state: build_system_prompt still builds one monolithic system message; turn.rs:316 does messages[0].content = system_prompt in place. build_system_prompt is called only from turn.rs:294 (production) + 5 test sites in prompt.rs. ToolRegistry::schemas (src/tool/mod.rs:355-375) iterates self.tools.values() (HashMap) with no sort. recall sorts by score desc (src/memory/mod.rs:590) with Ordering::Equal fallback on ties (not cross-restart deterministic). LlmClient::complete (src/provider/mod.rs:317-322) takes &[Message] and returns BoxStream<'_, LlmEvent> where '_ is the &self lifetime — the stream does NOT borrow the messages slice (messages are serialized into the request body inside complete). complete_with_retry (src/agent/dispatch.rs:401-429) retries up to 3x then returns the stream. Summarization (context.rs:126/228) clones messages[0] (the head) — with a stable head this is smaller and correct; no change needed.
