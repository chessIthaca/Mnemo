# Plan: Event-driven active model display (ModelChanged event)

## Goal
Make the toolbar (StatusBar) and agent tab (MainPanel) always reflect the active model correctly by driving updates through a new `ModelChanged` agent event fired on model switching, instead of ad-hoc `listAgents` re-fetches.

## Kind
implementation

## Context
ROOT CAUSE: `agentModels` (the per-agent model map the StatusBar + agent tab read) is only written by `registerAgents` (startup + unknown-agent name resolution) — never by an event. So after a model switch it goes stale. StatusBar manually calls `listAgents().then(registerAgents)` after `set_model` (duplicated in selectModel + selectReasoningEffort), but `save_endpoints` (Settings→Endpoints) ALSO swaps the provider yet does neither a re-fetch NOR a `resolved_model` clear (bug: list_agents reports a stale override after an endpoints save).

FIX: Add a `ModelChanged { model: String }` variant to AgentEvent/SerializableAgentEvent. Emit it per live agent from the two provider-swap Tauri commands — `set_model` (agent.rs) and `save_endpoints` (settings.rs, only when provider_swapped) — via the existing `emit_agent_event` helper (direct app.emit, like SkillStarted/PromptDispatched). Also clear each loop's `resolved_model` in save_endpoints (mirrors set_model — fixes the stale-override bug). Frontend: add a `model_changed` reducer that stamps `agentModels[agent_id] = event.model` (new `Effects.agentModels` field, merged in applyAgentEvent like `agentNames`). Remove the manual `listAgents().then(registerAgents)` calls from StatusBar (now event-driven). The global `model`/`provider`/`reasoningEffort` stay updated by the existing local setModelStore (set_model) + configVersion→resyncFromBackend (save_endpoints).

SCOPE: model-switching only (set_model + save_endpoints). Per-turn per-context override resolution (resolve_turn_provider) is a pre-existing separate concern (visible on startup via listAgents) — NOT in scope; no turn.rs/brain changes.

CONTRACTS: ModelChanged is a new SerializableAgentEvent variant → must add a golden fixture (tests/contract_fixtures.rs + frontend/src/lib/ipc-fixtures/event-model-changed.json) + a contract-test row (ipc-contract.test.ts) + a reducer-test row (useAgentStore.test.ts) + a roundtrip test (channels.rs). Windows/PowerShell; cargo test unpiped; npm run build + npm test from frontend/; zero warnings under #![deny(warnings)].
