# Plan: Shell results show stderr before stdout

## Goal
An agent sees a failing command's error first: the shell tool's model-facing text puts stderr ahead of stdout, so the error survives the 1,500-char head of an archived preview and the 100 KiB head-keeping cap, and agents stop calling expand_result just to find it.

## Kind
implementation

## Context
WHY (user observation 2026-11-16: agents often go back to read the actual error): src/tool/agent/shell.rs (~711) builds the model-facing text as `{stdout}\n[stderr]\n{stderr}` and then `\n[exit code: N]`. Results over 20,000 chars (OptimizerConfig DEFAULT_ARCHIVE_MIN_CHARS) are archived and replaced by archive_preview (src/agent/turn.rs ~4788): the first 1,500 and last 500 chars only, so an error in stderr after a long stdout sits in the hidden middle and the agent must call expand_result. cap_tool_output (src/tool/agent/mod.rs ~72) keeps the head of anything over 100 KiB, so a huge stdout can push stderr out entirely. The raw `data.stdout` / `data.stderr` / `data.exit_code` go only to the host and stay unchanged.

DECISIONS:
- When stderr (after the shell filter) is non-empty, the model-facing text becomes `[stderr]\n{stderr}\n[stdout]\n{stdout}` (the `[stdout]` label only when stdout is non-empty), followed by `\n[exit code: N]` exactly as today. When stderr is empty, the text stays exactly as today (plain stdout, then the exit code line), so clean runs read the same.
- The prepended notes (GREP_NUDGE, REDIRECT_NOTE, CHAIN_TRANSLATION_NOTE, BACKGROUND_HOLD_NOTE) stay first, above the stderr section.
- output_compactor::compress (lever 2) builds its own text from stdout and stderr: if it emits per-stream sections or lines, list the stderr-derived ones first too; if it already merges them by severity, leave it.
- No change to data fields, the shell filter's per-stream rules, cap_tool_output, or archive_preview.

TESTS (in src/tool/agent/shell.rs tests, real processes as the existing tests do): `stderr_comes_before_stdout_in_the_model_text` (a command writing "OUT-LINE" to stdout and "ERR-LINE" to stderr: the result output contains "[stderr]" before "ERR-LINE" before "[stdout]" before "OUT-LINE", and ends with "[exit code: ...]"); `a_clean_run_reads_as_before` (stdout only: no "[stderr]" or "[stdout]" labels); and an archive-level test (in src/agent/turn.rs tests near archive_preview, or wherever archived shell results are tested) proving that a shell result of 30,000 chars of stdout plus a short stderr line shows that stderr line inside the preview head. Update any existing test that pinned the old order.

VERIFY: `cargo test --workspace`, `cargo clippy --workspace --all-targets` as plain commands.

## Acceptance scenarios
- A failing command with a long stdout and a short stderr error shows the error within the first lines of the result the agent sees, including when the result is archived to a head+tail preview.
- A command that writes nothing to stderr produces exactly the same model-facing text as before.
