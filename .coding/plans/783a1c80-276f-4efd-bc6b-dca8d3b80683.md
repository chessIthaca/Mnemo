# Plan: Live vision-capable model picker + remove datalist white bubble

## Goal
Make the Settings → Vision model picker query the endpoint's /models API live and filter to vision-capable models (auto-detecting modality where the provider exposes it, e.g. OpenRouter; falling back to all models with a note when modality is unknown). Also remove the native HTML datalist "white bubble" from the Endpoints tab's model rows, keeping the custom dropdown.

## Context
Two issues in the Settings dialog:

1. VisionSection.tsx (lines 149-175) renders the Model field from `host.models` — the endpoint's statically-configured list from endpoints.toml. It never queries the endpoint live, so vision-capable models absent from that configured list never show. The backend `fetch_models` (src/provider/openai.rs:127) returns only Vec<String> (no modality info). OpenRouter's /models response includes `architecture.input_modalities` (array with "image") which lets us detect vision capability; vanilla OpenAI/Ollama /models has no modality field.

2. EndpointCard.tsx:509 sets `list="all-models-datalist"`, backed by a native <datalist> in ProvidersSection.tsx:325-329. The native datalist popup renders as a white bubble ignoring the dark theme. The custom ModelPickerDropdown (already used on focus) provides the dropdown — the datalist is redundant.

Existing patterns to mirror: EndpointCard.tsx fetches via `listModels(endpoint.name, endpoint.base_url, apiKey)` with a fetchReqId race guard + outside-click (pickerRef). ModelPickerDropdown.tsx is a reusable dropdown taking {status, error, models, query, onQueryChange, onRefresh, onPick}. The `list_models` IPC command (src-tauri/src/ipc/settings.rs:195) resolves base_url+api_key from override args → saved endpoint → env vars → "dummy", then calls `myharness::provider::openai::fetch_models`. parse_model_ids (openai.rs:201) handles OpenAI `{data:[{id}]}` + Ollama `{models:[{name|model}]}` shapes, returning None on unknown/malformed. Six existing parse_model_ids tests must keep passing. IPC commands are registered in src-tauri/src/main.rs invoke_handler (~line 230). Frontend wrappers live in frontend/src/lib/tauri.ts. No component-test setup (no @testing-library); backend uses cargo test, frontend uses `npm run build` (tsc) + vitest for contract tests only.
