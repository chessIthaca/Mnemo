# Plan: Make git commit auto-stage all changes

## Goal
The git tool's `commit` subcommand should stage all changes (`git add -A`) before committing, so a commit call succeeds without a separate staging step. Removes the footgun where `commit` fails with "no changes added to commit".

## Context
git.rs `commit` arm (line 175-181) runs only `git commit -m <message>`. The git tool has no `add` subcommand, so the agent cannot stage via the structured tool — it would have to drop to `shell`. Fix: in the `commit` arm, run `git add -A` first (via run_git), abort if it fails, then `git commit -m <message>`. `git add -A` respects .gitignore. commit is already SafetyLevel::NeedsApproval (approval-gated), and never_auto_for is false for commit (only merge/push are core ops), so this doesn't change gating. Update the schema description + module doc comment to note commit stages all changes. Add a test: init_repo, write an untracked file, commit, assert the file is tracked + commit message in log.
