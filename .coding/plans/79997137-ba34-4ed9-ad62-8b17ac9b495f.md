# Plan: prompts.toml: tool descriptors + workflow-state texts

## Goal
Make the agent's tool descriptors (tools-array descriptions) and the static workflow-state texts user-editable via ~/.mnemo/prompts.toml, following the existing per-section fallback pattern: missing entries fall back to compiled defaults, the seeded file carries copies, edits hot-apply via mtime reload.

## Kind
implementation

## Context
Investigation (this session): prompts.toml (PromptBlocks, src/agent/prompt.rs) covers only the 5 stable-head blocks. Missing from it but present in the agent's LLM context: (1) tool descriptors — every tool's schema() description string sent in the tools array (turn.rs:612 self.tools.schemas()); (2) workflow-state static texts — the per-state guidance strings compiled into workflow_section (prompt.rs:632-758), interpolated with dynamic plan data. Deliberately NOT configurable: constitution (agent.md files), session primer/recalled memories (dynamic data), CONTEXT_FOOTER (fixed cache sentinel). Also verified for the user: file tools don't hook indexers directly (codegraph GraphWatcher at src-tauri/src/main.rs:1535 catches all FS changes; memory corpus is .coding/knowledge/*, sandbox-protected from file tools, startup reconcile heals drift); memory tools ARE file-backed (factory.rs:883-928 wires with_knowledge; write→file+targeted reindex mod.rs:170-175; update→file mod.rs:735; supersede→successor file+full scan mod.rs:903-916; untyped/working/episodic stay DB-only by design).
