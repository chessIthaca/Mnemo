# Plan: Search productivity: FTS5 content index + regex/CRLF resilience

## Goal
Make `search` fast and resilient: literal queries served by an FTS5 content index (seeded at project creation, watcher-maintained, rebuildable from Settings), and regex resilience (compile-error handling + CRLF/multi-line matching) shared across search, search_read, and file_edit — with engine transparency in output and the agent-window card.

## Kind
implementation

## Context
Design agreed in discussion: FTS5 content index in the codegraph DB + regex→literal fallback + CRLF/multi-line resilience for `search`. Key facts: search.rs compiles the pattern per call at line 201 (`regex::Regex::new`, error at 203), matches per-line at 243 (`content.lines()` strips \r\n terminators, so single-line patterns are CRLF-safe; multi-line patterns can never match). codegraph schema.rs: cg_files/cg_symbols/cg_edges/cg_refs; DB is a derivable gitignored cache; WAL+busy_timeout pragmas on; FTS5 available with bundled SQLite (memory::schema test proves it). Project::seed_stores (src/project/mod.rs:158) seeds memory DB + indexes graph on project creation, gated by codegraph_enabled. Existing Settings: MemorySection.tsx has "Rebuild semantic search" (memory FTS) via src-tauri/src/ipc/memory_maintenance.rs (progress-event pattern to copy); codegraph_cmds.rs has graph reindex machinery. Agent window: search card already shows a pattern chip (frontend/src/lib/toolCardPaths.ts); add engine+count. Existing-project backfill is REQUIRED (additive FTS table → existing DBs would have an empty index forever; watcher only touches changed files). Feed FTS through should_search rules (ignored dirs, >1MB, binary). unicode61 tokenizer splits snake_case (underscore=punctuation) — literal queries become FTS phrase queries; pin in tests. Fallback must be transparent: engine field in output ('index' vs 'walk'), walk fallback when index empty/disabled/mid-backfill. Windows 11, PowerShell, root C:\AgenticCoder\AgenticCoder; cargo test unpiped + check $LASTEXITCODE; #![deny(warnings)]; regression tests for every defect fixed; never commit to main.
