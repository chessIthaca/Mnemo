# Plan: Cut per-iteration O(history) request-rebuild costs (L3)

## Goal
Cut the per-iteration O(history) request-rebuild cost (~25-60ms on 503-message conversations) to ~O(new tail): borrow instead of clone on the no-mutation echo path, serialize each message exactly once into a pre-serialized body (RawValue splice — no reqwest .json() re-serialization), cache the serialized message prefix across iterations with a sound fingerprint (age-dependent strip/re-add decisions included; trailing system run excluded), and skip the estimate walk on prefix hits.

## Kind
implementation

## Context
L3 from .coding/reviews/2026-09-09-perf-comm-review.md (2027-01-09 perf review, LOW): every provider call rebuilds the request from scratch — (1) a deep clone of every assistant message's raw JSON (src/provider/openai/request.rs:103 `let mut echoed = raw.clone()`, even when the reasoning-retention policy makes no mutation), (2) a full re-walk of all message content + tool schemas for the token estimate (src/provider/mod.rs:710-725 estimate_prompt_tokens — as_text() allocates a String per message, tools_chars does t.parameters.to_string() per request), (3) a full ~1.4MB re-serialization by reqwest .json(). ~25-60ms per iteration on 503-message conversations. DESIGN (settled during exploration): pre-serialize the body — a RequestBody struct with `messages: &[Arc<RawValue>]` splices each message's JSON verbatim exactly once (borrowed raws serialize directly via serde_json::value::to_raw_value — NO Value clone ever), killing costs 1 and 3 and enabling the serialized-prefix cache (fix 2). build_request_json keeps its Value signature as a build+parse lens so ~130 existing test call sites are unchanged. KEY CORRECTNESS FACTS: the echo path (request.rs:100-152) mutates ONLY when strips_reasoning(age, pressure) (policy.rs:129: false when age==0, keep_recent==usize::MAX, or age<keep_recent; else historical_droppable||under_pressure) OR the age-0 DeepSeek re-add applies (age==0 && policy.reasoning_required && reasoning_field==Some("reasoning_content") && raw lacks the key — live-verified wire contract, SPEC memory e010881d; historical turns tolerate the key but Rule 1 says byte-identical echo, so it must NOT leak into aged messages). The prefix cache fingerprint MUST therefore include, per assistant message, the two age-dependent mutation decisions (strip? re-add?) — ages are counted from the END of history and grow each iteration, so each message's decisions flip at most once (age-0→1 for the re-add; age crossing keep_recent for the strip) — a stale cache would leak unstripped reasoning cross-vendor or inject the rc key on aged turns. The cache covers messages[0..len] EXCLUDING the trailing system-message run (the volatile tail + CONTEXT_FOOTER are pushed after the token accounting at src/agent/turn.rs:335 and popped after the request — they disappear between iterations, so caching them would make the cache never hit); they are always serialized fresh. The fingerprint is a fresh O(n) no-alloc fold per build (role, content walk without as_text()'s String alloc, tool_calls id+arguments, tool_call_id, name, reasoning_content, reasoning_stripped flag, structural raw hash, + the two decision bools per assistant) — sound by construction (detects the Rule-5 strip at src/provider/mod.rs:488-528 which mutates mid-history raws in place and flips reasoning_stripped, compaction len-shrink, head swaps, pressure flips), ~1-2ms for 1.4MB vs 25-60ms today. FIX 3 DEVIATION (deliberate, document in code): TokenAccounting's total is NOT fed into the cap — it is computed at turn.rs:335 BEFORE the per-request head/tail scaffolding is installed (turn.rs:2094-2101), so it understates the actual request input by the scaffolding size, and its BPE basis differs from the builder's bytes/4 basis (would loosen the cap). Instead the estimate rides the prefix cache: prefix_chars cached, tail chars fresh, tools_chars fresh — same formula, same result, walk skipped on hits (the instruction's goal: "instead of re-walking all content per request"). RETRY: the reasoning_effort 400 retry (src/provider/openai.rs:631-645) mutates prepared.body in place today; with a String body, open_stream gains (messages, tools, tool_choice) params and rebuilds via the same builder with omit_effort (cheap — the prefix cache hits). TRACE: prepare_request deep-clones the body for the trace today (openai.rs:~493, on the ASYNC worker); with a String body the parse to Value for log.start moves into the existing blocking-pool trace closure (same cost class as the serialize-for-cap it replaces; the async worker's deep clone disappears). Responses-API path (Rule 3 stateful): its Value body is to_string-ed once; no cache (chat path is the hot one). serde_json's `raw_value` feature may need enabling in Cargo.toml (check first). Acceptance: per-iteration build cost drops (spot-check prep_ms in the Trace tab), all request-body tests green, cargo test --workspace green.
