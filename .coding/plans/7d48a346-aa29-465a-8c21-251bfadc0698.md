# Plan: list_models tool + spawn_agent model override

## Goal
Add a `list_models` tool that returns the configured endpoints + their models, and an optional `model` parameter on `spawn_agent` that runs the spawned agent on a specific model. Thread the chosen model through the spawner to the agent loop's per-turn model resolution.

## Context
GOAL: Let the agent (a) discover configured models and (b) spawn a background agent on a specific model. Two user-facing additions only: a `list_models` tool and an optional `model` param on `spawn_agent`. Everything else is internal plumbing.

INVESTIGATION FINDINGS:
- Model resolution: `AgentLoop::resolve_turn_provider` (loop_impl.rs:306) calls `resolver.resolve(ModelContext{workflow_state, skill_name, is_subagent})` → returns Option<ModelRef> → `resolver.build_turn_provider(&model_ref, fill_rate)`. The `ConfigModelResolver` (model_resolver.rs) holds the live `Arc<RwLock<Config>>` and a provider cache. Resolution priority: skill > subagent > workflow-state > None(default).
- Config access for tools: tools don't currently hold Config. The `ModelResolver` trait (model_resolver.rs:63) is the seam that does — `ConfigModelResolver` reads config per call. Adding `list_models()` + `resolve_model_id(model_id) -> Option<ModelRef>` to this trait lets both new features reach config without a new dependency.
- spawn_agent path: `SpawnAgentTool::execute` (spawn_agent.rs:105) → `spawner.parent_aware().spawn_with_parent(name, task, parent_id)` → `IpcSpawner::spawn_with_parent` (spawn.rs:199) → `spawn_agent_shared` (spawn.rs:78) → `factory.build_with_id(id)` → sets is_subagent. The built `AgentLoop` gets the shared `model_resolver` wired in factory.rs:315.
- `spawn_agent_shared` has 3 callers: IpcSpawner (tool path), the UI spawn button (spawn.rs:39), and main.rs:104 (main agent). Only the tool path needs the model param; the others pass None.
- `ParentAwareSpawner` trait (runtime/mod.rs:212) has 2 impls: `IpcSpawner` + `ParentAwareMock` (test in spawn_agent.rs). `AgentSpawner::spawn` has 3 impls: MockSpawner, ParentAwareMock, IpcSpawner.
- `AgentLoop` fields (loop_impl.rs): `model_resolver: Option<Arc<dyn ModelResolver>>`, `is_subagent: Mutex<bool>`, `fill_rate`. No `forced_model` yet.
- ToolResult { success, output, data: Option<Value> } — `data` can carry structured JSON for list_models.
- Factory `register_spawn_tool` (factory.rs:435) builds SpawnAgentTool from the shared spawner. The model_resolver is on the factory (field `model_resolver`), available at build time.
- Live config: endpoint "openai" serves ["glm-5.2","qwen-3.6","deepseek-v4-flash-gcp"]. default_model=glm-5.2.

DESIGN DECISIONS:
1. `list_models` is a tool (not an IPC command) — the agent calls it to discover models, then passes a model id to spawn_agent. Returns endpoint→models via ToolResult.data. Needs the model_resolver; omitted when no resolver is wired (tests).
2. `spawn_agent`'s `model` param is a bare model id string (e.g. "deepseek-v4-flash-gcp"). The tool resolves it to a ModelRef via `resolver.resolve_model_id(model)`. If unresolvable → error. If no resolver → error ("model selection unavailable").
3. The forced model threads through: SpawnAgentTool → ParentAwareSpawner::spawn_with_parent (new `model: Option<ModelRef>` param) → spawn_agent_shared → AgentLoop::set_forced_model. `resolve_turn_provider` checks `forced_model` FIRST (before the normal resolve chain) and builds via `resolver.build_turn_provider`.
4. `AgentSpawner::spawn` (the plain, non-parent path) is unchanged — model override only works on the parent-aware path (the production path). The tool errors if a model is requested but the spawner isn't parent-aware.
5. `forced_model` on AgentLoop is `Mutex<Option<ModelRef>>` (set once at spawn, read each turn).
