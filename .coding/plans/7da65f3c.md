# Plan: Memory tab paths open the file or plan they name

## Goal
In Mnemo2's Memory tab, every repository path a record shows can be clicked: its own path, its Links, and paths in its text. A plan document (.coding/plans/<id>.md) opens the Plans view with that plan expanded; any other file opens in the side panel's Files tab, at the line when one is given.

## Kind
implementation

## Context
The user reported on 2026-11-02 that paths in the Memory tab, for example .coding/plans/fc536488.md on plan records, are not clickable.

Findings from the lead's probe:
- verified: `sed -n 355,380p mnemo2/src/components/MemoryView.svelte` shows the record path rendered as `<code>{detail.path}</code>`, each `detail.links` entry as `<li><code>{link}</code></li>`, and the body as `<Markdown source={detail.markdown} />`.
- verified: `grep -n onOpenLink mnemo2/src/components/Markdown.svelte` shows the prop `onOpenLink?: (url: string) => void`, called only when the anchor href matches `/^https?:\/\//i`.
- verified: `grep -n "openFile\|selectedFile\|openPlan(" mnemo2/src/lib/store.ts` returns nothing, so the store has no action that opens a file or a plan from another view.
- verified: FilesTab.svelte keeps local state (`openFile`, `async function openPath(path)` at line 67), and PlansView.svelte keeps local `expanded` and `details` records keyed by plan id (lines 35-36, `toggleDetails(plan)` at line 66).
- verified: TraceView.svelte consumes `$app.traceEntry` and calls `actions.clearTraceEntry()`, the existing pattern for a cross-view hand-over set by `actions.openTrace(entry)`.

Decisions (new code to write; none of it exists yet):
- Two new store actions in mnemo2/src/lib/store.ts, following the openTrace/traceEntry hand-over pattern:
  - One opens a plan document by plan id: it should switch to the Plans route and leave a pending plan id for PlansView to consume, expanding that plan's Details, loading its document and scrolling it into view. An unknown id shows a short "plan not found" note.
  - The other opens a file in the Workbench: it should open the side panel's Files tab and leave a pending path and optional line for FilesTab to consume through its existing openPath, scrolling to the line.
- Path detection: one helper in a new mnemo2/src/lib/repoPaths.ts.
  - It recognizes a repository-relative path with an extension and an optional `:line` suffix, for example `.coding/plans/fc536488.md`, `src/agent/turn.rs:4352`, `mnemo2/src/lib/store.ts`.
  - It rejects URLs, absolute paths and bare words.
  - It classifies `.coding/plans/<id>.md` as a plan, and everything else as a file.
  - Link entries that are not paths stay plain text.
- In MemoryView, the record path and every path-like link become link-styled buttons: accent colour, underline on hover, keyboard focusable, with a title saying where they open.
- Markdown.svelte gets a new optional path callback prop that makes recognized inline-code and plain-text paths clickable. Only MemoryView passes it; every other Markdown user is unchanged.
- Do not touch the trace files or ToolActivity.

Verification, from mnemo2/: `npx svelte-check --tsconfig ./tsconfig.json`, `npx vitest run src/lib src/components src/preview`, `npm run check:no-mock`.

## Acceptance scenarios
- In the Memory tab, clicking a plan record's path .coding/plans/fc536488.md opens the Plans view with that plan's Details expanded and scrolled into view.
- Clicking a knowledge record's path, or a path such as src/agent/turn.rs:4352 in its text, opens the side panel's Files tab on that file at that line.
- URLs, absolute paths and non-path link entries are not turned into file links; the other Markdown users (lead chat, plans) behave exactly as before.
- svelte-check is clean, and vitest over src/lib, src/components and src/preview passes.
