# Plan: Show backlog-dispatched prompts as the goal in the agent transcript

## Goal
Make backlog-dispatched prompts appear prominently in the agent's transcript as the goal, just like main-input prompts do.

## Context
Root cause: when a prompt is sent from the main input (InputBar.handleSend), the user message is added to the transcript immediately (InputBar.tsx:191-211) before sendPrompt. But when a backlog item is dispatched, the backend (dispatch_next_impl at commands.rs:1061-1063 and run_all_dispatch_next at commands.rs:1190-1192) sends AgentCommand::Prompt directly to the agent — no frontend code adds the user message to the transcript. So the dispatched prompt never appears as a "goal" in the agent's conversation.

Fix: add a new AgentEvent::PromptDispatched { text, images } variant. The backend emits it from both dispatch paths (dispatch_next_impl + run_all_dispatch_next) right after sending the Prompt command, tagged with the main agent's id. The frontend handles it in applyAgentEvent by appending a user transcript entry (mirroring handleSend's optimistic append). This makes backlog-dispatched prompts display prominently as the goal, just like main-input prompts.

The event must arrive BEFORE the agent's `Started` event so the user message is at the top of the transcript when streaming begins. Since the backend sends Prompt then emits the event, and the agent emits Started after receiving Prompt, ordering is: PromptDispatched (from dispatch) → Started (from agent). The forwarder emits events in fan-in order, so PromptDispatched lands first. Good.
