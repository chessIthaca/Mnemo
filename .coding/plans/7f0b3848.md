# Plan: Models settings show only what Mnemo2 uses; the lead ignores Mnemo1's per-task models

## Goal
Mnemo2's Models settings page drops the Mnemo1-only "Models for each kind of work" (Planning, Executing, Bug fixing, Reviewing) and keeps only settings Mnemo2 actually uses (the compaction/summarize model, vision, code indexing, budget); and Mnemo2's built-in lead never silently switches to a Mnemo1 per-task model.

## Kind
implementation

## Context
Why: the user: in the settings dialog, "models for each kind of work really don't make much sense, in mnemo2 that workflow is not used. It only makes sense for mnemo."

Verified facts:
- verified: `mnemo2/src/components/ModelsPage.svelte` has a section "Models for each kind of work" (line ~240) listing the per-task overrides from `mnemo2/src/lib/modelSettings.ts` (lines ~115-119): planning, executing, bug_fixing, reviewing, summarize; then Vision (~286), Code indexing (~320), Budget (~374). The page saves through `model_settings_save(section, value)` (`src-tauri/src/mnemo2/model_settings.rs`).
- verified: Mnemo2 workers are spawned with `policy: None` and an explicit tier model (`src-tauri/src/mnemo2/team.rs` ~line 2751-2760), so workflow-state overrides ([models.planning]/[models.executing]/[models.bug_fixing]) never choose a worker's model.
- verified: `[models.reviewing]` drives Mnemo1's built-in reviewer subagents (`src/agent/dispatch.rs` ~1708-1770); Mnemo2 reviews are done by the lead and audit workers on tier models.
- verified: `[models.summarize]` is used for context compaction by any agent (`src/agent/turn.rs` ~1681 and ~2994, `src/agent/context.rs`), so it applies in Mnemo2 too.
- verified: Mnemo2's built-in lead runs under the `mnemo.workflow` policy (`WorkflowPolicyFactory::new(...).with_team_lead(ledger, board)`, `src-tauri/src/mnemo2/runtime.rs` ~line 974), and the model chain in `src/agent/loop_impl.rs` (~1840-1860, ~2058, ~2511) lets a configured `[models.<state>]` slot take over from the lead's picker pin when the workflow state changes.
- verified: the user's shared `~/.mnemo/config.toml` (also used by Mnemo1) sets `[models.planning]` kimi-k3.1-pro, `[models.executing]` deepseek-v4.1-flash, `[models.bug_fixing]` kimi, `[models.reviewing]` glm-5.3, `[models.complete]` kimi, `[models.summarize]` deepseek-v4.1-flash.
- assumption: Mnemo2's built-in team lead may move through Planning/Executing/Complete states and therefore silently switch to those Mnemo1 models; step 1 verifies with a test.

Decisions:
- Step 1 (engine/runtime): find out whether Mnemo2's built-in lead's model ever comes from `[models.planning|executing|bug_fixing|complete]`. If it does, make Mnemo2's lead ignore per-state model slots: its model is the lead picker's choice (or the default model) in every state. Do this through an option on the lead's spawn/policy in `src-tauri/src/mnemo2/runtime.rs` (or a narrowly scoped flag in the model chain that Mnemo2 sets), never by changing Mnemo1's behaviour. `[models.summarize]` keeps working for compaction. Add a test that the lead keeps its picked model across a Planning → Executing transition even with `[models.executing]` configured. If it never happens, say so with evidence and change no engine code.
- Step 2 (UI): remove Planning, Executing, Bug fixing and Reviewing from the Models page; keep Summarize as its own small section "Compaction model" with a one-line explanation ("Summarizes the conversation when the context fills; empty = the agent's own model"). Add one quiet line saying Mnemo1's per-task models are kept in the shared config but Mnemo2 does not use them. Never clear or rewrite those Mnemo1 keys: saves must patch only the summarize slot (check that `model_settings_save` for the summarize section does not drop the other `[models.*]` entries; add a Rust test). Theme tokens only (dark theme).

Verification: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::` and `cargo test --lib` if engine code changes, both clippy runs (`cargo clippy --lib --tests -- -D warnings`; `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`); in `mnemo2/`: `npx svelte-check --tsconfig ./tsconfig.json`, `npm run check:no-mock`, `npx vitest run`. Never start a dev server or any command that does not exit on its own.

## Acceptance scenarios
- The Models settings page no longer shows Planning, Executing, Bug fixing or Reviewing; it shows a Compaction model, Vision, Code indexing and Budget.
- Saving the compaction model leaves [models.planning], [models.executing], [models.bug_fixing], [models.reviewing] and [models.complete] in config.toml unchanged.
- Mnemo2's built-in lead keeps the model picked in its picker through every workflow state even when Mnemo1 per-task models are configured; Mnemo1 behaves as before.
