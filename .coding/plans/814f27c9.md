# Plan: Classify user cancels as Cancelled, not provider errors (D1)

## Goal
User interrupts (Interrupt/Cancel/Compact/Clear) that drop a live stream mid-flight stop being classified as provider failures: no provider-errors.jsonl row, the trace record stamped cancelled (terminal, not failed, healthy http_status preserved), and a request_stats row with outcome='cancelled' so aborted requests stay countable in the latency/token aggregates. A genuine stream error keeps its fail classification even when the consumer exits right after it.

## Bug
45+ rows in .coding/logs/provider-errors.jsonl carry "stream aborted — consumer dropped" — these are USER interrupts (Interrupt/Cancel/Compact/Clear), not provider failures. The trace records are marked failed even though the HTTP response was healthy, and no request_stats row is written, so cancelled requests are invisible to latency/token accounting even though the provider billed the tokens generated so far. A genuine stream error can also be masked when the consumer exits right after it.
