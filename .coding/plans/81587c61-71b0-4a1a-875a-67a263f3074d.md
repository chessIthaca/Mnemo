# Plan: Interactive game browser: CDP attach infra + Game panel + agent inspection tools

## Goal
Add the interactive-game-browser infra to the harness: a debug-gated CDP port on the Tauri WebView2, a BrowserManager connect mode that attaches to the live WebView2, a Game panel with an interactive iframe (human plays), and agent tools to screenshot/eval/snapshot the live game. No game is wired in — the human loads a game URL from a separate project.

## Kind
implementation

## Context
Architecture (decided + spike-proven 2026-11-22): human plays a game in an <iframe> embedded in the Tauri WebView2 (shares GPU/WebGPU); the agent attaches to that SAME WebView2 via its CDP debug port (chromiumoxide Browser::connect) and inspects the live game state. The spike (plan 7eaafb95) proved: Browser::connect exists in chromiumoxide 0.7, the connect flow works end-to-end (launch→connect→enumerate→eval→screenshot), and Tauri WebView2 honors --remote-debugging-port via additionalBrowserArgs (manually confirmed: Invoke-RestMethod http://localhost:9222/json/version returned a standard webSocketDebuggerUrl on Edge/WebView2 151).

USER CLARIFICATION: the harness provides the INFRA only — a Game panel with an iframe (human enters a URL from a separate game project's dev server) + CDP attach so the agent can inspect it. No game is wired into the harness; the game is a separate project loaded via URL.

KEY FILES: src/browser/mod.rs (BrowserManager — currently launch-mode only, headless Chromium; agent tools + right-panel Browser tab share one Arc via the factory), src/agent/factory.rs (register_browser_tools at :508, Ctx pattern at :510-513), src/tool/browser/ (existing tools: NavigateTool/ScreenshotTool/EvalTool/SnapshotTool etc. using pub(crate) Ctx { manager, sandbox }), src-tauri/src/main.rs (main() at :34, build_brain creates BrowserManager at :638), src-tauri/tauri.conf.json (CSP at :27-28, additionalBrowserArgs at :23 currently "--disable-extensions"), frontend/src/hooks/agentState.ts (RightPanelTab union :190-199, ALL_RIGHT_PANEL_TABS :202-212), frontend/src/hooks/rightPanelViews.tsx (RIGHT_PANEL_VIEWS registry :49-59), frontend/src/components/views/BrowserView.tsx (existing headless browser tab — screenshot-based, NOT interactive).

CDP PORT GATING: WebView2 reads the WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS env var at creation time. Setting it in main() under cfg!(debug_assertions) means dev builds expose port 9222 (agent can attach) and release builds don't (security — reviewer's HIGH finding from the spike). No tauri.conf.json port change needed; keep additionalBrowserArgs: "--disable-extensions" there. Set the env var to "--disable-extensions --remote-debugging-port=9222" so both args are present regardless of env-var/config merge behavior.

CSP: the current CSP has no frame-src directive, so it falls back to default-src 'self' — a cross-origin game iframe (e.g. http://localhost:3000) would be BLOCKED. Must add frame-src to devCsp (dev) and csp (prod) allowing localhost + https.

CONNECT MODE DESIGN: separate from the existing launch-mode browser. State gains webview: Option<Arc<Browser>> + webview_handler: Option<JoinHandle<()>>. ensure_webview lazily connects to http://localhost:9222 (15s timeout, retry on failure since the WebView2 may not be ready yet), spawns the handler task, respawns if the handler died (mirrors ensure_browser). webview_page() ensures the connection + returns the first page target (the app's main WebView2 page, which contains the game iframe). webview_screenshot/eval/snapshot operate against that page. A screenshot of the main page shows the game visually (the iframe is visible). Eval against the main page works for same-origin iframes; for cross-origin iframe DOM access, investigate chromiumoxide's frame API (page.frames()) during implementation — if not readily available, fall back to main-page eval and note the limitation.

BRANCH: currently on fix/aggregate-tok-sec-inflation. Create feat/interactive-game-browser.
