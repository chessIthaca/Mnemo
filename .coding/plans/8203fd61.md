# Plan: Owner id lives where every launch path shares it: no more stamp refusals under Claude Desktop

## Goal
Mnemo2 reads one machine owner id from the Mnemo config dir (~/.mnemo or MNEMO_HOME) for every launch path, migrating an existing app-data id once, so a project stamped by one launch path is never refused by another; the refusal message also names both ids.

## Kind
bug_fixing

REGRESSION TEST (required, named, fails without the fix): `two_app_data_views_converge_on_one_shared_owner_id` in the tests module of src-tauri/src/mnemo2/project.rs, beside `the_machine_owner_id_is_created_once_and_reused` (around line 925). Instance A: `machine_owner_id_shared(config, view_a)` returns X and `open_state_dir(P, &X, true)` stamps P. DESIGN (decided; do not redesign): (1) src-tauri/src/mnemo2/project.rs keeps `pub fn machine_owner_id(dir: &Path) -> Result<String, String>` unchanged (location-agnostic) and adds `pub fn machine_owner_id_shared(config_dir: &Path, legacy_app_data: &Path) -> Result<String, String>`: if `config_dir/state-owner-id` is absent and `legacy_app_data/state-owner-id` holds a valid 32-hex id, copy it into config_dir with create_new (first wins, never overwrite an existing config-dir id; if another instance created it first, use theirs), then return `machine_owner_id(config_dir)`. A missing or invalid legacy file is ignored. (2) src-tauri/src/mnemo2/ipc.rs `state_owner` (line 272) resolves `mnemo::config::resolve_config_dir(None)` (honours MNEMO_HOME; already used by src-tauri/src/bin/mnemo2_mcp.rs:104 and mnemo2/mcp_server.rs:1454, so tests/boundary.rs allows it) and the Tauri app_data_dir, and calls `machine_owner_id_shared`. All other callers (ipc.rs 422, 503, 566, 1145, 1162 and the shutdown path mod.rs:713) go through state_owner and need no change. (3) The refusal in `open_state_dir` (project.rs:342-346) keeps its leading sentence 'was not created by Mnemo2 on this machine' and the 'Delete or rename that folder to start a fresh session here.' guidance verbatim, and adds the folder's stamp value when an `owner` file exists and is a plain 32-hex string (never echo other file content), this instance's owner id, and the stamp file path, so the message says what to compare. Existing tests assert substrings at project.rs:878 and :882 and must keep passing unchanged.

CONSTRAINTS: the stamp check is a security control (a repository or archive can ship its own .coding/mnemo2 with a planted lead.json or team.json; see the comment at project.rs:861-864 and test `shipped_or_foreign_state_is_refused_never_loaded`). That test must pass unchanged: a folder shipped in a clone is still refused, a refused folder is never stamped, and nothing deletes or rewrites a stamp. Never write over an existing config-dir id. Never touch the real stores (C:\Users\hessc\.mnemo, the real app-data dir, any project's .coding/mnemo2): tests use tempdirs only. Both crate roots use #![deny(warnings)]; no #[allow]. A different MNEMO_HOME between launches reintroduces divergence by explicit choice; document it. Projects stamped with the id that loses the migration are refused once more; the existing guidance (rename .coding/mnemo2 aside) is the recovery; say so in the README.

## Bug
Mnemo2 refuses a project folder it created itself: "C:\mnemo\.coding\mnemo2 was not created by Mnemo2 on this machine (it may have come with the repository)…". Under Claude Desktop (an MSIX package) Windows gives processes below it a private copy of AppData\Roaming\com.mnemo.mnemo2, so a Mnemo2 started by the plugin and one started by the user hold two different state-owner-id values and each refuses the other's project stamps.
