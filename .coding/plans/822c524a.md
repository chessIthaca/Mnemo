# Plan: Record the item↔plan linkage on the agent-side in-flight stamp (chat-driven items strand at InFlight)

## Goal
Record the item↔plan linkage (`plan_id` + `plan_title`) whenever an agent-driven in-flight stamp happens — on `backlog_status → InFlight` and at the `create_plan` seam — and add a linkage-driven resolution arm so a session with no dispatch pointer (a chat-driven plan, never dispatched by Run-All) still flips its item to Done through the EXISTING `plan_linkage_allows_done` guard instead of stranding at InFlight until a human or agent stamps it by hand.

## Kind
implementation

## Context

BUG (symptom + repro, observed 2026-09-26 on wt/mnemo, plan 6d8cbe94). Item 30bacfa2-4110-4df1-a1a0-f19750eb5595 reached the agent as a CHAT MESSAGE (never dispatched by Run-All). The agent stamped it InFlight via backlog_status; the plan ran to `finish` (state Complete); at turn resolution the item was NOT stamped Done and rested at InFlight until the agent stamped Done by hand with a note. Repro: paste a backlog item's text into chat, backlog_status it to in_flight, run the plan to finish, observe the item still in_flight. Same shape as the earlier manual stamp of item 45a4eb88 (memory d6ce70aa).

ROOT CAUSE (verified by reading the code, two independent gaps):
1. NO LINKAGE IS WRITTEN ON THE AGENT PATH. The item↔plan linkage is the item's own fields `plan_id` + `plan_title` (src/backlog.rs:260-276; `#[serde(skip_serializing_if = "Option::is_none")]`, which is why the stranded item's JSONL line simply has no `plan_id` key). The only writers are `BacklogStore::set_plan_id` (src/backlog.rs:704-718, "record the linkage WITHOUT touching status") called from `stamp_backlog_in_flight` (src-tauri/src/ipc/run_all.rs:7034) and `stamp_spawned_in_flight` (src-tauri/src/ipc/run_all.rs:5267) — both IPC/dispatch paths. The agent tool `backlog_status` (src/tool/workflow/backlog.rs) stamps status only.
2. THE RESOLUTION HAS NO ARM FOR A NON-DISPATCHED SESSION. `on_main_turn_resolved` (src-tauri/src/ipc/run_all.rs:5328-5478) ends with exactly two modes: `run_all_active` → `resolve_run_all_turn` (:5450-5464), otherwise → `resolve_single_dispatch_turn` (:5466-5477). Both act on a DISPATCH POINTER (`state.backlog.run_all.current_item` / the single-dispatch in-flight pointer). A chat session has no pointer, so there is nothing to resolve. Even if an item were reached, the Done guard refuses an unlinked item: `plan_linkage_allows_done(item_status, item_plan_id, completed_plan_id)` (src-tauri/src/ipc/run_all.rs:477-493) requires InFlight AND `(Some(pid), Some(cpid)) => pid == cpid`, with the deliberate `(None, Some(_)) => false` ("The item never planned; the completing plan is not its."). `flip_done_if_linked` (src-tauri/src/ipc/run_all.rs:5740-5791) applies it and annotates "completing plan is not this item's plan — item kept, no transition". The second escape hatch, `closed_earlier`, needs a `plan_id` too (`orphan_work_landed(state, item.plan_id.as_deref(), ...)`, :6025-6028 with the note at :6010-6014).

DESIGN — do NOT relax the guard; make the linkage exist.
(A) Agent path records the linkage: on the `→ InFlight` transition in src/tool/workflow/backlog.rs, record `set_plan_id(item, root_plan_id, plan_title)` when a root plan is already active (covers stamp-after-plan); and at the `create_plan` seam in src/tool/workflow/plan.rs, after the plan is created, record it for a live InFlight item with `plan_id == None` (covers stamp-before-plan, the observed order). Share ONE helper. Both sides need the backlog store + the workflow's root plan id/title from the tool context — the recon step confirms that plumbing (the title is read from the plan file's `# Plan: <title>` heading, mirroring `stamp_backlog_in_flight`).
(B) A linkage-driven resolution arm for a session with no dispatch pointer: after both existing branches find no in-flight item, if the plan loop closed (`plan_loop_allows_done(main_state, loop_evidence)`) and `main_agent_top_plan_id` is readable, look up the live InFlight item whose `plan_id` EQUALS the completed plan id and flip it Done by REUSING `flip_done_if_linked` — the guard's `(Some, Some)` equality arm, semantics unchanged. Refuse (no transition, annotate as today) when zero or ≥2 items match; never resolve a Pending/re-queued item. FALLBACK if the recon shows the tool context cannot reach the root plan id: repair the linkage at resolution time instead — one live InFlight item with `plan_id == None` + loop closed → `set_plan_id` with the completed plan id, then flip through the unchanged guard.

REGRESSION TEST DESIGN (must fail before the fix): an app-crate test in src-tauri/src/ipc/run_all.rs's test module driving the pure/helper seams (mirroring the existing `on_main_turn_resolved_is_plan_tied` source-contract style): (a) unlinked InFlight item + completed plan → NO Done (the pre-fix behaviour, pinned as the guard's contract); (b) linked InFlight item whose `plan_id` IS the completed plan, no dispatch pointer → Done; (c) two InFlight items → no transition.
