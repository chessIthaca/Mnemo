# Plan: Backlog images → gitignored sidecar files + path refs in JSONL

## Goal
Move backlog image attachments out of the git-tracked `.coding/backlog.jsonl` (where inline base64 data URLs make diffs huge) into gitignored sidecar files under `.coding/backlog-images/`, referenced by relative path in the JSONL. Resolve paths back to data URLs at the IPC boundary so the frontend and agent dispatch are unchanged. Clean up orphaned image files on remove/edit/clear-finished.

The `images: Vec<String>` field currently holds base64 data URLs serialized inline. Change it to hold RELATIVE PATHS (e.g. `backlog-images/<id>/<0>.png`).

Add a private helper `fn image_dir(&self) -> PathBuf` returning `self.path.parent().unwrap_or(Path::new(".")).join("backlog-images")`. Add `fn write_image_files(&self, item_id: &str, data_urls: &[String]) -> Vec<String>`: for each data URL at index i, parse `data:<mime>;base64,<data>` (split on `;base64,` — if it doesn't start with `data:` or lacks `;base64,`, skip it, storing the raw string as the path for backward-compat), map mime→ext (image/png→png, image/jpeg→jpg, image/webp→webp, image/gif→gif, default bin), base64-decode (use `base64::engine::general_purpose::STANDARD.decode` — add `use base64::Engine as _;` at top), write bytes to `image_dir/<item_id>/<i>.<ext>` (create_dir_all the item dir first), return the relative path string `backlog-images/<item_id>/<i>.<ext>`. Add `pub fn resolve_images(&self, item: &BacklogItem) -> Vec<String>`: for each path, if it starts with `data:` (legacy inline, shouldn't happen post-migration but be defensive) return it as-is; else read the file bytes (std::fs::read), map ext→mime (png→image/png, jpg/jpeg→image/jpeg, webp→image/webp, gif→image/gif, default application/octet-stream), build the data URL via `crate::tool::agent::image_tools::bytes_to_data_url(mime, &bytes)` (it's pub(crate)). On any IO error (file missing — cross-worktree, manually deleted), skip that image (graceful degradation: fewer thumbnails, never a panic). Add `fn delete_item_images(&self, item_id: &str)`: best-effort remove_dir_all on `image_dir/<item_id>` (ignore errors — never fail a mutation over cleanup).

Modify `add(text, images)`: call `write_image_files(&id, &images)` to get paths, store those in the item's `images` field (NOT the data URLs). Modify `edit(id, text, images)`: BEFORE writing new files, call `delete_item_images(id)` to clean up old images; then `write_image_files(id, &images)` for the new set. Modify `remove(id)`: after retaining, if removed, call `delete_item_images(id)`. Modify `clear_finished()`: collect the ids of finished items BEFORE the retain, then delete each one's images after the retain. Modify `open()`: AFTER parsing items, run a migration pass — for each item, if any `images` entry starts with `data:` (legacy inline data URL), call `write_image_files(&item.id, &item.images)` and replace the item's `images` with the returned paths; if any migration happened, call `persist()` once at the end. Add unit tests: (a) add with a data URL → item.images is a path, the file exists with decoded bytes, resolve_images returns the original data URL; (b) edit replaces images (old file deleted, new file exists); (c) remove deletes the image dir; (d) clear_finished deletes finished items' image dirs; (e) resolve_images skips a missing file gracefully (delete the file, resolve returns empty); (f) legacy migration: seed a JSONL with an inline `data:image/png;base64,...` entry, open() migrates it to a file + path, persist writes the path.
