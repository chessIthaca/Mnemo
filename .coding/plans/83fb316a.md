KNOWN MECHANISMS TO DISCRIMINATE (do not assume the answer):
1. FOLD-VENDOR TAIL-IN-HEAD BUG — fixed in main TODAY (2027-01-11) at d53546e: for DeepSeek-vendor + Local/Ollama ("fold") providers the volatile tail (workflow state, plan rider, recall, footer) USED TO be folded into the leading system message, so any tail change (a plan check-off, progress bump, recall swap) mutated messages[0] and reset the entire prefix. Fix: messages[0] stays the byte-stable cache prefix and the volatile tail rides as trailing user-role messages with no trailing system block; regression test `deepseek_head_stays_byte_stable_across_plan_progress_bumps` (src/agent/tests.rs). Full record: `.coding/knowledge/bug/506b85e2.md`. DECISIVE CHECK: if the last records' messages[0] CONTAINS the volatile-tail signature ("WORKFLOW STATE", a "PROGRESS n/m" line, "RECALLED MEMORIES", or the context footer) and that content differs between consecutive records, the RUNNING backend predates d53546e (merged but the app not rebuilt/restarted) — that explains a big reset on consecutive calls. If messages[0] is byte-identical across the last records, this is NOT the cause.
2. PLAN-LIFECYCLE HEAD CHANGE — this very session finished a plan moments ago (Executing → Reviewing → Complete). The workflow/plan section lives in the head; a plan completing removes the plan frame, so the head changes at the boundary → a full-prefix reset on the calls right after it.
3. COMPACTION / HEAD SWAP — a `purpose='summarize'` row (or a trace record whose messages[] shrink / whose head is a summary) immediately before the reset means history was rewritten; the R21/D1 segmentation identifies it.
4. MID-HISTORY MUTATION (R14/hysteresis shape) — `compact_old_tool_results` (src/agent/context.rs, called from src/agent/turn.rs) truncates old tool results once per high-water crossing; an already-sent message mutates in place (its content gains COMPACT_MARKER), so cached ≈ tokens before that message index (measured precedent: prompt 45,495 / cached 20,928 = exactly the prefix up to the newly-truncated result). Regression tests: compact_below_high_water_mark_mutates_nothing / compact_fires_at_high_water_mark.
5. COLD START / UNRELATED PREFIX — a new session, a spawned subagent (entirely different system prompt + read-only tool set), a model/endpoint switch, or a backend restart with an empty conversation; classification UNRELATED (different session/model) — structural, not a defect.
6. PURE APPEND (healthy) — record N+1 strictly extends record N; cached should then be ≈ the previous prompt_tokens minus the new tail. A LOW cached value with NO byte difference means a provider/proxy-side limit (the ~340K cliff) rather than our own mutation.

FALSIFIABLE PREDICTION to apply (round-4/5/6 technique): if the prefix up to message k is byte-identical, provider cached_tokens ≈ tokens(messages[0..k]) + tools; a large gap means our own mutation, no gap with low cached means the provider/proxy limit. Approximate tokens as chars/4 and SAY SO in the artifact (it is an approximation).
