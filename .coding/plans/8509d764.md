# Plan: Mnemo2 Phase 1 — real lead engine + model registry

## Goal
Implement Mnemo2 Phase 1: a minimal dedicated Tauri IPC host backed by the existing headless Engine and workflow policy, a real lead conversation with streaming/cancel/restore, a config-backed lead model registry and picker, pending-interaction forwarding, and a browser mock fallback. Preserve the Phase 0b minimalist UI and leave parallel workers/team runtime for Phase 2.

## Kind
implementation

## Context
Phase 0b is committed on wt/mnemo at df09678. Verified integration points: src/headless/engine.rs:203-375 exposes Engine::spawn(SpawnOptions) -> AgentSession; src/headless/engine.rs:383 is only lookup of an existing session. src/headless/session.rs:226-469 exposes events(), send(), interrupt(), history(), export(), snapshot(), and stored_stats(); src/headless/types.rs:149-211 defines Prompt/Interrupt/Approve/Answer commands and SessionEvent. SpawnOptions supports model, policy, resume, and permissions; no SetModel command exists, so a model change must resume-respawn while idle. src/headless/setup.rs:1363 exposes Setup::list_models and EngineOptions carries explicit workspace/config_dir. src/app/policy_factory.rs:117-121 provides WorkflowPolicyFactory::default; Engine::register_policy (src/headless/engine.rs:187) can register it as "mnemo.workflow" before spawning. Existing Mnemo1 src-tauri/src/main.rs:1095 uses tauri::generate_context! and frontendDist target/frontend-dist; mnemo2/vite.config.ts uses port 5180 and target/mnemo2-dist, so a separate minimal Mnemo2 Tauri host/config avoids changing Mnemo1. Architecture: new src-tauri library module + src-tauri/src/bin/mnemo2.rs, with runtime/IPC in src-tauri/src/mnemo2/, and @tauri-apps/api in mnemo2 for native mode with the current mock store as browser fallback. Assumption to validate by compiling in step 1: the installed Tauri generate_context! explicit-config-path form accepts the new config location; adjust to its supported path without changing Mnemo1 config. No live provider credentials will be printed or committed; runtime tests use mock LLMs/tempdirs. Do not launch extra Chrome/headless/CDP instances during verification (user objection). Acceptance: a native Mnemo2 lead turn uses the real Engine and configured model, streams deltas, can interrupt, restores its saved transcript after reopen, and exposes configured model choices; ordinary Vite browser mode remains mock-only.

## Steps
- [x] 1. **Add the minimal Mnemo2 host and configuration** — Create src-tauri/mnemo2.conf.json with productName Mnemo2, a distinct identifier, one window, devUrl http://localhost:5180, and frontendDist ../target/mnemo2-dist. Add src-tauri/src/lib.rs exporting mnemo2, src-tauri/src/bin/mnemo2.rs calling mnemo_app::mnemo2::run(), and src-tauri/src/mnemo2/mod.rs with the host builder/command registration skeleton. Use the explicit Tauri context path supported by the installed version and compile the new binary before proceeding. Add root package.json scripts for the Mnemo2 native dev/build commands; do not alter the existing Mnemo1 main/config.
- [x] 2. **Implement the headless lead runtime** — Implement src-tauri/src/mnemo2/runtime.rs with LeadRuntime and a small session store. It must start Engine with explicit workspace/config paths, register WorkflowPolicyFactory::default() as mnemo.workflow, spawn one lead with SpawnOptions policy/model/resume, expose events/send/interrupt/history/snapshot, and persist the transcript + selected model under an explicit Mnemo2 state directory (not a tracked project file). Reject model changes while a turn is active; otherwise resume-respawn with the saved transcript because SessionCommand has no SetModel. Forward approval/question events and provide the corresponding commands. Add tempfile/mock-LLM tests for streaming, interrupt, restore, and model change.
- [x] 3. **Add typed lead IPC and event forwarding** — Implement src-tauri/src/mnemo2/ipc.rs with serde DTOs and commands for open lead, send prompt, interrupt, snapshot/restore, list models, set model, close, and resolve approval/question. Emit a single namespaced lead-event channel with session/generation identity so stale forwarders cannot update a replaced session. Register commands in the new host and keep all Tauri-specific emission out of the runtime's core logic. Add DTO/state tests and document the channel contract.
- [x] 4. **Wire the frontend lead engine adapter** — Add @tauri-apps/api to mnemo2 and create src/lib/leadEngine.ts with a typed native adapter plus a null/browser fallback. Extend the existing lead state/actions to load native snapshots, append streamed deltas, handle completion/errors, expose cancellation and model choices, and ignore stale session events. Preserve current mock behavior and worker/team actions when Tauri is unavailable. Add unit tests for native event accumulation, cancellation, restore, model selection, and fallback; update package-lock through npm.
- [x] 5. **Connect the minimalist lead UI and documentation** — Update LeadChat.svelte, Composer.svelte, and the lead-model settings surface to use the native adapter when present: show actual configured model, a compact model picker, streaming/stop state, restore/error/pending-interaction feedback, and no extra explanatory chrome. Keep the Phase 0b worker/team mock views unchanged. Update mnemo2/README.md, README.md, and the Phase 1 section of .coding/design/mnemo2.md with the implemented host commands, state location, and acceptance behavior.
- [x] 6. **Run full verification and the real-lead smoke check** — Run npm test/build --workspace mnemo2, npm test/build --workspace frontend, cargo test --workspace, and cargo check -p mnemo-app --bin mnemo2; fix all failures and warnings. Add/execute focused runtime and adapter regression tests for streaming, interrupt, restore, model changes, and pending interactions. Verify the real native lead path with the configured provider when available without printing secrets, and otherwise record the provider-dependent smoke as not run. Use only the existing live Browser tab for any UI inspection; never launch extra Chrome/headless/CDP instances. Complete the required review/fix/commit closing sequence.
