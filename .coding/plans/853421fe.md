# Plan: Fix: finish↔update_plan deadlock blocks closing bug_fixing plans

## Goal
Break the finish↔update_plan deadlock so bug_fixing plans can be closed out. Two paths: (A) update_plan is callable in Reviewing for regression_test-only (title/goal/context/steps stay frozen), and (B) finish accepts an optional regression_test param that records the test on the plan frame right before the gate check.

## Kind
bug_fixing

## Context
Root cause: 4 stacked guards create the deadlock.

1. ToolFilter::Reviewing (src/tool/mod.rs:425-436) — the Workflow arm explicitly excludes update_plan. Comment: "complete_step/create_plan/update_plan are NOT: the plan is finished, so no step or new-plan work is allowed mid-review."
2. dispatch.rs:102 — filter.allows() returns false → "tool 'update_plan' is not allowed in the current workflow state (Reviewing)"
3. mod.rs:510 — `if self.state != WorkflowState::Executing` → WorkflowWrongState
4. plan.rs:1256-1268 — finish gate blocks without plan.regression_test: "bug_fixing plan has no regression test recorded — the verify step must call update_plan with regression_test before finish"

So finish says "call update_plan first" but update_plan is invisible+blocked at 2 layers in Reviewing. The only escape today is abandon_plan → re-create → re-record during Executing (absurd for a one-field update).

The natural order fights the gate: the regression test name is often only known AFTER running tests (end of verify step), but complete_step(4) flips to Reviewing before you can record it.

FIX (user chose "Both" — relax update_plan for regression_test in Reviewing AND let finish accept the param):

Part A — Relax update_plan for regression_test-only in Reviewing:
- tool/mod.rs:425 — add update_plan to the Reviewing Workflow allow-list (the filter is static, can't inspect args; the workflow method rejects non-regression_test updates in Reviewing)
- mod.rs:510 — change the state guard: Executing allows all fields; Reviewing allows ONLY regression_test (title/goal/context/steps all None); else WorkflowWrongState
- plan.rs:567 — update the UpdatePlanTool schema doc ("Executing only" → "Executing; in Reviewing, regression_test only")

Part B — finish accepts regression_test param:
- plan.rs:1036 (FinishArgs) — add `regression_test: Option<String>`
- plan.rs:1162 (finish schema) — add the regression_test property + update description
- plan.rs:1192 (finish execute) — in the first lock block, before the plan snapshot, if args.regression_test is Some, call wf.update_plan(None,None,None,None,false,Some(rt)) to record it (works because Part A relaxed Reviewing). Change `let wf` to `let mut wf`. The snapshot then includes the test, and the existing gate (plan.rs:1256) passes. The existing code-graph validation (plan.rs:1271) still runs on the recorded name.

Tests to update/add:

Add `finish_accepts_regression_test_param` mirroring `finish_passes_bug_plan_with_test_in_graph_and_captures` (plan.rs:3202) but WITHOUT pre-recording the test (pass it via the finish param instead)
