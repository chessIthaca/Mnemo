# Plan: Shell grep and rg searches also get the Mnemo search hint

## Goal
When Claude Code runs a shell command like `grep -rn Foo src` or `rg "DECISION: x"` to look up a symbol or a project decision, it gets the same non-blocking hint that already points Grep and Glob at Mnemo's graph_search, search and memory_search.

## Kind
implementation

## Context
Why: the user asked whether Claude actually uses the code graph. In the lead's own session the counts were about 90 Grep and 40 Glob tool calls plus several hundred shell `grep` commands, against 11 graph calls. The existing `hint --pre-search` hook only fires for the Grep and Glob tools, so `grep`/`rg` typed in a Bash or PowerShell command bypasses it entirely.

Verified facts:
- verified: the hook is `hint` in `src-tauri/src/bin/mnemo2_mcp/hooks.rs` (~line 442): `search_input` (~line 428) returns the `tool_input` only when `tool_name` is "Grep" or "Glob"; `classify` reads `tool_input.pattern` / `path` and returns a code hint (single identifier, or `fn X`/`struct X` style) or a memory hint (typed title like `DECISION: …`, or a `.coding/knowledge` path), and stays silent for regexes, paths, prose and file globs; output is PreToolUse `additionalContext`, never a block.
- verified: the plugin registers it in `mnemo2/plugin/hooks/hooks.json` with `"matcher": "Grep|Glob"` (line ~54) and `args: ["hint", "--pre-search"]`.
- verified: tests live in `src-tauri/src/bin/mnemo2_mcp/hooks_tests.rs` (helper `hint_context(sandbox, tool_name, tool_input)` ~line 425).
- verified: plugin changes reach Claude Code only after a plugin version bump + `claude plugin update` + a new session (knowledge HOW record); the lead does that after the merge, not the worker.

Decisions:
- Extend `search_input`/`classify` so a Bash or PowerShell tool call is examined: from `tool_input.command`, find a search invocation (`grep`, `rg`, `git grep`, `findstr`, `Select-String`), possibly after `cd … &&`/`;` or inside a pipeline, extract its pattern argument (skip flags such as `-rn`, `-i`, `-E`, `--glob X`, `-g X`, `-t rust`, `-A 3`; strip quotes), and feed that pattern (and the search path when given) to the existing `classify`. Anything that cannot be parsed confidently stays silent. Never hint for commands that merely pipe other output through grep (e.g. `cargo test 2>&1 | grep FAILED`, `git log | grep x`): only hint when grep/rg is searching files (it has a path argument or `-r`/`-R`, or is rg/git grep).
- Matcher becomes `"Grep|Glob|Bash|PowerShell"` in `hooks.json`; the hook stays fast (no network, one registration read) and never blocks.
- The hint text for a shell search says the same thing as today and that the shell command still runs.
- Bump `mnemo2/plugin/.claude-plugin/plugin.json` version to 0.1.2.

Regression test: `shell_grep_for_an_identifier_gets_the_code_hint` in `src-tauri/src/bin/mnemo2_mcp/hooks_tests.rs`: a Bash tool input `{"command":"grep -rn settle_held_manager_core src-tauri/src"}` produces the code hint; also cover `rg "DECISION: laya"` → memory hint, `cd src && rg -n LayaManager` → code hint, and silence for `cargo test 2>&1 | grep FAILED`, `git log --oneline | grep fix`, a regex pattern, and a PowerShell `Select-String -Pattern Foo -Path src\\*.rs` → code hint. Without the change the Bash cases produce nothing.

Verification: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --bin mnemo2-mcp`, `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`. Never start a dev server or any command that does not exit on its own.

## Acceptance scenarios
- A Bash command `grep -rn settle_held_manager_core src-tauri/src` gets the graph_search/search hint; the command still runs.
- `rg "DECISION: laya"` gets the memory_search hint.
- `cargo test 2>&1 | grep FAILED` and other output filters get no hint.
