# Plan: Workers use the image tools: prompt line, stale describe_image text, visible vision-model errors

## Goal
Executor and audit workers check visual work with the image tools. Tool descriptions name tools that exist, and a vision model that doesn't resolve is visible in the app instead of only in stderr.

## Kind
implementation

## Context
WHY: on FactoryGame, workers take game screenshots (PNG files in the worktree, via the project's debug server) but never look at them. Visual work (a shader reveal, an animation, UI) is verified only by the lead. Investigation (2026-11-19) found the code already allows this: guardrails.rs gives executor and audit workers every tool group including the deferred `image` group, the image tools accept any png/jpg/gif/webp/bmp inside the sandbox (src/tool/agent/image_tools/mod.rs:49-108), and image_ui_diff takes image_a and image_b. The group was hidden because ~/.mnemo/config.toml named a vision endpoint `gemini` that endpoints.toml does not have. build_vision_client (src/provider/client_factory.rs:280-295) then returns None, only a stderr warning is printed (src/host/brain.rs:827), and the image tools report unavailable. The user has since pointed vision at `Ollama Cloud/deepseek-v4.1-flash:1017` (config change, not code).

DECISIONS:
- No new tool group and no always-on change: the deferred `image` group stays, listed under AVAILABLE TOOL GROUPS whenever a vision client exists.
- `describe_image` is not revived as a tool. Text that names it points at `image_analysis` instead.
- The worker prompt says to check visual changes with the image tools, conditionally: "when the image tools are available".
- An unresolved vision model is shown where the user sets it: Settings > Models, under the Vision field. The reason is one of: the endpoint is not in endpoints.toml; the endpoint is Anthropic-kind; or the model id is not listed for that endpoint, which is only a warning, since unlisted ids can still work.
- ~/.mnemo/prompts.toml is not read by any code (the override layer was removed, decision 2026-08-24), so it is not edited.

VERIFY (each alone on its line): `cargo test --workspace`; `cargo clippy --workspace --all-targets`; `npm test --workspace mnemo2`; `npm run check --workspace mnemo2`.

## Acceptance scenarios
- With vision_model pointing at an endpoint missing from endpoints.toml, Settings > Models shows a warning under Vision naming the missing endpoint; with a valid one, no warning.
- The offscreen_browser_screenshot and browser_screenshot tool descriptions name image_analysis, and no tool description in the repo names describe_image.
- An executor worker's and an audit worker's system prompt include the line about checking visual changes with the image tools.
