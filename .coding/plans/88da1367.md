# Plan: Compaction fallback: cumulative +10% temporary context-limit raise until it fits

## Goal
Add a bounded, per-session fallback lever so a boundary session whose compaction still does not fit continues instead of re-compacting and aborting: after a compaction pass that leaves the count at/over the effective summarize limit, raise the effective limit by +10% (cumulative: x1.1, x1.2, ...), use the raised limit for the next cycle, reset to 1.0 once a compaction fits or on a fresh session, and surface every raise in the transcript + stderr log. The provider's true window stays the hard limit (the raise is capped below it), so a provider length error remains a genuine error.

implementation

## Context
SYMPTOM/WHY: `effective_summarize_at()` (src/agent/context.rs:193-205, 274-278) is a fixed fill-rate threshold (max_context * fill_rate, capped by the proxy cache ceiling). When a compaction pass returns a result STILL >= that threshold (the kept-verbatim tail dominates the compaction budget), the turn loop's top-of-iteration trigger (src/agent/turn.rs:471, `token_count >= context_manager.effective_summarize_at()`) fires again; the post-compaction check at src/agent/turn.rs:2490-2492 (`if used < effective_summarize_at() { state.compact_attempts = 0 }`) never re-arms, so the attempt ladder climbs to the abort ("context stuck over threshold after N compaction attempts") or the per-turn ceiling (`MAX_COMPACTIONS_PER_TURN`, src/agent/turn.rs:95, "unbounded re-compaction loop"). There is no lever between "compaction did not bring it under the fill-rate dial" and "abort the turn".
