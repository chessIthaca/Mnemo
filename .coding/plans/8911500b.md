# Plan: Plan-scoped tool-set freeze: byte-stable tools array per plan (L4 prefill)

## Goal
Eliminate mid-plan tools-array churn so the provider prefix cache survives Executing→Reviewing: while a plan is active, the schema array is chosen once by plan kind (research → ExecutingResearch; implementation/bug_fixing → Executing ∪ finish) and stays byte-stable until the plan ends; dispatch keeps per-state enforcement. Preserves the CONTEXT_FOOTER stable-prefix discipline; coordinates with the 340K cliff item (211e215e) which owns the worst-case prefill cap.

## Kind
implementation

## Context
Perf review L4 (.coding/reviews/2026-09-09-perf-comm-review.md): the dominant per-turn cost is server-side prefill of the uncached prefix; the tools array rides at the head of the request body, so any array change (workflow-state transition) resets the whole cached prefix (~40-75s re-bill at late-plan context sizes). Facts verified in source: schemas are rebuilt per request at src/agent/turn.rs:292 from wf.allowed_tools() (per-state filter); the dispatch layer RE-CHECKS the per-state filter at src/agent/dispatch.rs:93-102, so freezing the ADVERTISED array is safe — enforcement stays per-state; Workflow::active_plan_kind() exists (src/workflow/mod.rs:307) and the research arm already keys on the active plan (mod.rs:419-423); CONTEXT_FOOTER is a tested const (src/agent/prompt.rs:460). The big >340K resets are the litellm proxy cache cliff — owned by backlog item 211e215e (send-gate + trigger margin); this plan deliberately does NOT touch compaction triggers/aggressiveness (instruction 1 of the item was scoped out; review D2 documents the information-loss tradeoff). Acceptance honesty: implementation-plan bodies keep the same schemas (+finish), so avgP moves little; the measurable win is hit-rate protection (no TOOLS-CHANGE resets mid-plan) — matching the item's "without a hit-rate regression" clause.
