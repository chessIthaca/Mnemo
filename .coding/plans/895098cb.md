# Plan: agent.md: read the shell tool's exit code, run checks alone on their line

## Goal
Workers run the .coding/checks.toml commands alone on their line, so Mnemo2 records them as checks; agent.md no longer tells them to append "exit=$LASTEXITCODE".

## Kind
implementation

## Context
WHY: the release worker ran every check as `cargo test --workspace; "exit=$LASTEXITCODE"`, following agent.md's Environment bullet (lines ~13-24), which shows `cargo test` followed by `"exit=$LASTEXITCODE"`. The `;` makes it a compound command, so Mnemo2's single-run check recording rightly ignored it; it would also be unsafe to count, because PowerShell then exits with the status of the last statement (the string, 0) even when cargo failed. The shell tool already ends every result with `[exit code: N]` for the whole command line (src/tool/agent/shell.rs), so the echo is unnecessary. Another worker that ran the commands plain had them recorded.

DECISION: replace the whole Environment bullet that starts "**Do not pipe a command through a cmdlet and then trust the reported exit code**" (including its powershell code block and the "…or, if you must filter noise" paragraph) with exactly:

- **Read the exit code the shell tool reports.** Every shell result ends with `[exit code: N]`, the exit code of the whole command line. Run a command whose exit code matters alone on its line, with nothing after it: piped through a cmdlet, the code is the pipe's and can read `1` although the command succeeded; followed by `; "exit=$LASTEXITCODE"` or any other statement, the code is that statement's, usually `0`, although the command failed. The commands in `.coding/checks.toml` count as your checks only when run exactly like that. If you must filter noise, rely on the command's own `test result:` / `error:` lines rather than the exit code.

No other change to agent.md.
