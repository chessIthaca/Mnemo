# Plan: Safeguard the WebView2 CDP port against multiple app instances

## Goal
When two or more mnemo instances run concurrently with browser inspection on, each instance gets a distinct CDP remote-debugging port: the WebView2 env var carries a per-instance free port (9222 first, then the next free), and BrowserManager attaches to that same port — no more silent cross-instance attachment to the first instance's WebView2. Single-instance behavior is unchanged (still 9222 when free).

## Kind
bug_fixing

## Context
Root cause (verified by code read): port 9222 is hardcoded in three places — (1) src/webview_args.rs::build_webview2_args (~line 30, `--remote-debugging-port=9222`) builds the `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` value that src-tauri/src/main.rs:194-201 sets before the Tauri builder (gate `cfg!(debug_assertions) || browser_inspection_enabled()`); (2) src/browser/mod.rs::BrowserManager::new (~288) and Default (~1601) hardcode `webview_url: "http://localhost:9222"`; (3) doc/UI text (.coding/browser-debugging.md:111-112, frontend/src/components/settings/sections/AdvancedSection.tsx:529). CORRECTION to the backlog item: `is_app_url` (src/browser/mod.rs:1219) does NOT special-case 9222 — it matches only tauri:// schemes, the 5179 dev devUrl, about:blank, and chrome://; the existing test (~1992, `!is_app_url("http://localhost:9222")`) stays valid with any port. No is_app_url change needed.

Fix design (no new deps — std TcpListener/OnceLock):
1. src/webview_args.rs: `pub const DEFAULT_CDP_PORT: u16 = 9222;` + `pub fn pick_cdp_port() -> u16` (probe 9222..=9231 on 127.0.0.1 by binding a TcpListener and dropping it — a single instance keeps the documented 9222; then any ephemeral port via bind(:0); last resort DEFAULT_CDP_PORT) + `static CDP_PORT: OnceLock<u16>` with `pub fn set_cdp_port(port)` / `pub fn cdp_port() -> u16` (default DEFAULT_CDP_PORT). `build_webview2_args(cdp_port: Option<u16>, disable_occlusion: bool)` — Some(port) appends `--remote-debugging-port=<port>`. The OnceLock is the single source of truth shared by the env var (set in main) and BrowserManager (read at construction); it mirrors the env var itself — a process-global set-before-use value. Set-before-read is guaranteed: main's top runs before the Tauri builder → before setup → before any BrowserManager exists. Startup-only accessors; no round-trip unit test (a test setting the OnceLock would poison parallel tests that construct managers — document this in the accessor doc comments).
2. src-tauri/src/main.rs (windows block, lines 194-201): when the CDP gate is on, `let port = pick_cdp_port(); set_cdp_port(port);` and pass `Some(port)` to build_webview2_args; when off, pass `None`. Non-Windows: no change (the block is cfg(windows); cdp_port() returns the default, matching today).
3. src/browser/mod.rs: `new()` (~288) and `Default` (~1601) use `webview_url: format!("http://localhost:{}", mnemo::webview_args::cdp_port())`. Update the two "probing localhost:9222 for 30s" comments (~933, ~952) to "probing the CDP endpoint". The three creation sites in main.rs (544, 630, 1482) stay `BrowserManager::new()` — no signature/closure churn (Tauri's setup closure is 'static-bound; threading the port through would require a move closure on a ~600-line closure + a build_brain param for no benefit over the OnceLock).
4. Docs/UI: .coding/browser-debugging.md:111-112 — "(9222)" → note each instance picks 9222 or the next free port when several run side by side; AdvancedSection.tsx:529 — "localhost:9222" → "localhost:9222 (next free port when multiple instances run)". Security gate + opt-in warning unchanged (still an unauthenticated localhost port; only the number becomes dynamic).

Regression-test design: (a) `cdp_port_avoids_an_occupied_default` — hold 9222 with a TcpListener, pick the port, build the args, parse the `--remote-debugging-port=` value back out, assert != 9222 (red against the current hardcoded args — they always say 9222; green after the fix). (b) `pick_cdp_port_returns_bindable_port` — the picked port can be re-bound immediately. (c) updated `args_all_combinations` — Option<u16> signature; Some(9222) keeps today's exact strings; plus a Some(9227) dynamic-port case. Browser-side tests are unaffected (OnceLock unset in tests → default 9222). The two-instance acceptance (each attaches only to its own WebView2) is inherently a two-process manual check — the unit tests prove the pieces (distinct port when 9222 is held, env var carries it, BrowserManager reads the same source); manual verification noted for the final summary.

## Bug
When two or more mnemo instances run at once — both live, both with the browser online (debug builds always expose CDP; release builds with the `enable_browser_inspection` opt-in) — they conflict on the web browser port. The CDP remote-debugging port is hardcoded 9222 (src/webview_args.rs::build_webview2_args ~line 30; src/browser/mod.rs::BrowserManager::new ~line 288 and Default ~line 1601). The first instance's WebView2 env binds 9222; the second's bind fails silently (a second env renders but gets no CDP — proven in .coding/scoping-native-mix-architecture.md), and the second instance's `ensure_webview` then attaches to the FIRST instance's WebView2 — cross-instance inspection/control of the wrong browser tab.
