# Plan: Re-add a real embedder (cloud + local) with failure protection, auto-start, and Settings UI

## Goal
Re-introduce a real text-embedding model (nomic-embed-text via Ollama, or any OpenAI-compatible /v1/embeddings endpoint) so memory recall ranks by genuine semantic similarity instead of keyword overlap. The old OllamaEmbedder was removed because it sent no auth (401) and used Ollama's native /api/embed path (broke non-Ollama endpoints). This plan fixes both root causes: a proper OpenAI-compatible /v1/embeddings client with auth, plus layered failure protection (short timeout, retry, circuit breaker, zero-vector fallback) so recall never dies. On startup, probe the configured endpoint; if it's a local Ollama endpoint that's down, auto-start `ollama serve` and auto-pull the model. Surface the embedder status to the user via a startup banner + StatusBar badge. Full Settings UI tab (mirroring Vision) so the user picks cloud or local.

## Context
CURRENT STATE (verified by reading the code):
- src/memory/embedder.rs: `Embedder` trait with `async fn embed(&self, text: &str) -> Result<Vec<f32>>`. Only impl is `HashEmbedder` (deterministic hash projection, semantically meaningless). `EMBEDDING_DIM = 768`.

Scoring (:745) is `sim*0.2 + decayed_strength*0.3 + keyword_boost + tier_weight`. `cosine()` (:322-331) returns 0.0 when either vector has zero norm — so a zero-vector query degrades to keyword+tier+strength ranking automatically.
- src/config/general.rs: `GeneralSection` has `vision_model: Option<VisionModel>` where `VisionModel { endpoint, model }`. This is the pattern to mirror for `embedding_model`.
- src/provider/client_factory.rs: `build_embedder()` is no-arg, always returns HashEmbedder. `build_vision_client(config)` is the pattern to mirror (reads config, returns Option).
- src-tauri/src/main.rs:577 calls `build_embedder()`. src-tauri/src/ipc/rewire.rs:31 calls `build_embedder()` (no config).
- src-tauri/src/ipc/settings.rs: `GetSettingsGeneral` has `vision_model` field. `SettingsSaveDto` has `vision_model` + `clear_vision_model`. Mirror for embedding.
- Frontend: VisionSection.tsx is the template. tauri.ts has AppSettings + SettingsSavePatch types. App.tsx startup sequence at :180+ calls getConfig/getSettings. useAgentEvents subscribes to events via `listen()`. No toast/banner component exists yet.
- debug.config.toml:32-35 has a dead [memory] section (embedding_model/embedding_provider) that's silently ignored (no deny_unknown_fields).
- reqwest is already a dependency (used by OpenAiClient). No new deps needed.
- tokio::process::Command is used in src/tool/agent/git.rs:86 — pattern for spawning processes.

KEY DESIGN DECISIONS:
1. Make Embedder::embed infallible (-> Vec<f32>, drop Result). The embedder owns its failure policy (zero vector). Callers (write/recall) can never die from embedding. Zero vector is in the same space as real vectors, so cosine is well-defined (returns 0). write() stores zero vectors as-is (is_empty() is false for a 768-zero vec, so no re-embed).
2. RemoteEmbedder uses OpenAI-compatible /v1/embeddings (works with Ollama, OpenAI, vLLM, LM Studio). Sends Authorization: Bearer header. This fixes both old bugs (no auth + wrong path).
3. Config via [general.embedding_model] mirroring [general.vision_model]. Unset → HashEmbedder (today's behavior, zero dependencies).
4. Auto-start: on startup, if embedding_model points at a Local-kind endpoint, health-check it; if down, spawn `ollama serve` detached, wait, re-check; if model missing, `ollama pull <model>` in background. Best-effort — if ollama isn't installed, falls back to hash silently.
