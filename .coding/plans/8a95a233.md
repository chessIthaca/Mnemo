# Plan: Skill tools: skill_reload (every state) + skill_create (Executing only)

## Goal
Add two agent tools to the skill subsystem and make the skill registry reloadable in place.

1. `skill_reload` — re-read `.coding/skills/*.toml` into the LIVE registry and report what changed (added/removed/current names). Available in EVERY workflow state: Planning, Executing, ExecutingResearch, PlanFrozen (the advertisement while a plan is active), Reviewing, Complete, and inside an active skill (auto-granted like ask_user/current_plan/backlog_*). NOT granted to reviewer subagents (their surface is a strict read-only allow-list by construction).
2. `skill_create` — author a new `.coding/skills/<name>.toml` from validated arguments, then hot-add it to the live registry so it is immediately startable. Restricted to Executing (Executing/ExecutingResearch dispatch + PlanFrozen advertisement).

Prerequisite (the real work): the factory today holds an immutable `Arc<SkillRegistry>` (src/agent/factory.rs:198, wired once at src-tauri/src/main.rs:1765). Introduce `SkillLibrary` — the skills dir + a live `RwLock<SkillRegistry>` — so a reload can swap the registry under every reader (skill_start, the UI enter_skill path, both new tools).
