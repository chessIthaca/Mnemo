# Plan: Memory tab: browse and search the project's knowledge

## Goal
Mnemo2 gets a top-level Memory tab (after Plans) where the user browses and searches the project's knowledge records (specs, decisions, bugs, how-tos) and memories, reads each record as Markdown, and can open Mnemo1's memory-debug tools in a collapsible section.

## Kind
implementation

## Context
Why: the user reviewed which Mnemo1 tools Mnemo2 still lacks; the lead proposed, and the user accepted, a top-level Memory tab because project knowledge is project-wide and large. Mnemo1 had a "Memory" debug view (`frontend/src/components/views/MemoryDebugView.tsx`: embedder status and model, stored vector fingerprints, per-tier counts, a recall test box, a browsable memory list) backed by commands in `src-tauri/src/ipc/memory_debug.rs`, which is Mnemo1-binary-only (Mnemo2 cannot call `src-tauri/src/ipc/*`).

Verified facts:
- verified: the kernel already has the API: `mnemo::headless::MemoryApi` (`src/headless/memory_api.rs`) with `overview()` (line 186), `list(..)` (226), `search(..)` (256), `resolve_link` (281), `backlinks` (296), `access_log` (310), `index_status` (322); `Engine::memory()` returns it (`src/headless/engine.rs` line 600).
- verified: Mnemo2 reaches the open project's engine through `LeadRuntime::engine_handle()` (`src-tauri/src/mnemo2/runtime.rs` line 444); graph commands use the same pattern via an `engine(state)` helper in `src-tauri/src/mnemo2/graph.rs`.
- verified: knowledge records are Markdown files under `.coding/knowledge/{spec,decision,bug,how}/` (303 spec files today) plus a few top-level notes.
- verified: top-level routes are `Route` in `mnemo2/src/lib/types.ts` ("start" | "lead" | "team" | "cost" | "graph" | "plans"), buttons in `mnemo2/src/components/TopBar.svelte` (Plans is last), `actions.open*` in `mnemo2/src/lib/store.ts`, the switch in `mnemo2/src/App.svelte`.

Decisions:
- New file `src-tauri/src/mnemo2/memory_view.rs` with commands built on `MemoryApi`: `memory_overview`, `memory_list` (type/tier filter, paging), `memory_search(query)`, `memory_read(id)` (the full record with its knowledge-file Markdown when it has one), `memory_backlinks(id)`, `memory_recall_test(query)`. Register them in `src-tauri/src/mnemo2/mod.rs` directly after `insights::insights_savings` (the last line of the handler list) — other plans add commands after other anchors.
- Frontend: Route `"memory"`, a "Memory" button after Plans in TopBar (lucide `Brain`), `actions.openMemory` placed directly after `openPlans` in store.ts, `MemoryView.svelte` + `lib/memoryView.ts`. Layout like Graph: a left list (search box, type chips SPEC / DECISION / BUG / HOW / other, newest first) and a reading pane rendering the record with `Markdown.svelte`, its path, date and backlinks (clickable). A collapsed "Diagnostics" section shows the overview (embedder status/model, per-tier counts, index status) and a recall-test box. Read-only: no editing or deleting in this plan.
- Preview: add a `memory` scene directly after the `plans` scene in `mnemo2/src/test/previewScenes.ts`, using the dev-only seed seam pattern (setter in the lib module, imported only from `src/test/*`; `npm run check:no-mock` enforces it).
- Use the type tokens in `mnemo2/src/app.css` and Inter.

Verification: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::memory_view`, `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`; in `mnemo2/`: `npm run check`, `npm run check:no-mock`, `npx vitest run`. Never start a dev server or any command that does not exit on its own; the lead renders the preview.

## Acceptance scenarios
- The top bar shows Lead, Team, Cost, Graph, Plans and Memory; Memory lists the project's knowledge records newest first with SPEC/DECISION/BUG/HOW filters.
- Searching finds records by text, and selecting one renders its Markdown with path, date and clickable backlinks.
- A collapsed Diagnostics section shows embedder status, per-tier counts and a recall test that returns ranked memories.
