# Plan: Fix Anthropic 400: stop echoing unsigned thinking blocks in request history

## Goal
Stop Anthropic requests from carrying fabricated unsigned thinking blocks: remove the reasoning echo from the anthropic.rs request builder so multi-turn conversations with stored reasoning stop 400ing, flip the echo test into a regression test asserting no thinking block is serialized, sync the stale error text, and keep the full suite green.

## Kind
bug_fixing

## Context
Root cause (traced 2026-12-19): src/provider/anthropic.rs Role::Assistant serialization (:372-381) fabricates `{"type":"thinking","thinking":r}` from the stored `reasoning_content` on EVERY prior assistant message in the outgoing request. Anthropic requires any `thinking` block in conversation history to carry the original per-block `signature` (delivered in the SSE `content_block_start`); the stream parser (:529-548) has no `thinking` arm so the signature is never captured, and the fabricated echo is unsigned → deterministic HTTP 400, retries can't help. DeepSeek/OpenAI genuinely require the reasoning echo (openai.rs:1323), but Anthropic does NOT — it only forbids unsigned echoes, so the correct fix is to DROP the fabricated echo on the Anthropic path (user-confirmed direction). The `reasoning_content` field itself stays (DeepSeek/OpenAI path + display use it); only anthropic.rs stops serializing it. Existing test `assistant_reasoning_echoes_as_thinking_block` (:1713-1724) asserts the buggy echo — it will be flipped into the regression test (asserts NO thinking block in the request body), failing before the fix and passing after. Error text at :413-417 ("no text, thinking, or tool calls") becomes stale once thinking is never sent — sync it. Failing request in the wild: 400 from api.anthropic.com/v1/messages with `messages.1.content.0.thinking.signature: Field required` (harness's own conversation, post-skill_end multi-turn request).
