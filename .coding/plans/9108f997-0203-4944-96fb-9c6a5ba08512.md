# Plan: Ignore .claude + workflow prompt + report path passback + visual-line ArrowUp

## Goal
Four independent improvements: (1) ignore all of `.claude/` in search tools + gitignore; (2) enhance the workflow-lifecycle system prompt to encourage planning even for research work + emphasize sub-plans; (3) pass the reviewer's report path back to the parent agent in the completion notification (instead of a generic "read its report" message); (4) make ArrowUp/Down in the InputBar multiline-safe based on visual lines, not just `\n`.

## Kind
implementation

## Context
Four independent asks researched against the current codebase:

1. IGNORE .claude: .gitignore:48 only ignores `.claude/settings.local.json` (not the whole dir). src/tool/agent/search.rs IGNORED_DIRS (lines 18-32) does NOT include `.claude`, so `search` + `search_read` (which reuses `should_search` at search_read.rs:136) index `.claude/` content. The markdown viewer already hides `.claude` via the dot-dir rule (per .coding/reviews/2026-04-md-viewer-hidden-browse-review.md), so only search + gitignore need changes.

2. WORKFLOW EXPLANATION: src/agent/prompt.rs already has a `WORKFLOW_LIFECYCLE` const (lines 52-77) in the stable head explaining states + tool availability + plan kind (research vs implementation). It mentions sub-plans ("Push nested work with create_plan (a sub-plan)") and plan kind. But it does NOT encourage making a plan even for research/investigation work to then execute, and doesn't strongly emphasize subplans. Enhancement only — the lifecycle map exists.

3. REPORT PATH PASSBACK: When a reviewer subagent finishes, notify_parent_on_completion (src-tauri/src/ipc/events.rs:411-452) sends the parent a generic Suggestion "[background agent "X" finished — read its report and combine the results into a plan]" with NO report path. The parent must then search for the report (unreliable with multiple agents). But: write_review_report (src/tool/agent/write_review_report.rs:183-188) returns the path in `result.data["path"]` via `.with_data`. The turn layer (src/agent/turn.rs:745-754) sees every tool result + has `&self` (the AgentLoop). The forwarder's `spawn` fn already receives `agent_loops: Arc<Mutex<HashMap<AgentId, Arc<AgentLoop>>>>` (events.rs:151) and calls notify_parent_on_completion at lines ~210/~219. AgentLoop (src/agent/loop_impl.rs) already has the pattern for Mutex-wrapped optional fields (session_id, last_prompt_tokens, forced_model). So: capture the report path on the child's AgentLoop when write_review_report succeeds, then read it in notify_parent_on_completion and include it in the Suggestion text.

4. ARROWUP VISUAL LINES: frontend/src/lib/promptHistory.ts isOnFirstLine/isOnLastLine (lines 36-45) only check for `\n`. A long prompt that wraps to 3 visual lines but has no `\n` returns isOnFirstLine=true at ANY cursor position, so ArrowUp loads history instead of moving the cursor up a visual line. InputBar.tsx handleKeyDown (lines 511-536) calls these. Fix: visual-line detection via a cached mirror div (replicate textarea styles, measure scrollHeight/lineHeight for text up to cursor → cursor visual line; full text → total lines). Fall back to the `\n` heuristic when layout is unavailable (jsdom / zero lineHeight). Keep existing isOnFirstLine/isOnLastLine as the fallback. Existing promptHistory.test.ts tests the `\n` path in jsdom.

All four are source-code changes → implementation plan (review required).
