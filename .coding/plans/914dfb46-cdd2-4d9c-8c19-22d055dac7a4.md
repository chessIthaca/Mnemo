# Plan: Spike: does Tauri IPC (invoke + listen) work inside an add_child webview?

## Goal
Throwaway standalone Tauri spike: a bare Window + one add_child webview loading a local index.html that calls __TAURI_INTERNALS__.invoke('ping') and listens for a 'spike-event'. Proves whether Tauri IPC (invoke + listen) works inside an add_child webview — the gate for the full bare-Window + two-add_child reconfigure.

## Kind
research

## Context
The path-(a) spike (plan 71bd2daa, Complete) proved a bare Tauri WindowBuilder + add_child gives CDP — but it only loaded EXTERNAL URLs (example.com/.org). It never tested whether Tauri injects __TAURI_INTERNALS__ (the IPC bridge) into an add_child webview loading the app's OWN HTML (WebviewUrl::App). The real React frontend's @tauri-apps/api invoke/listen both call window.__TAURI_INTERNALS__ under the hood. If that global is absent in an add_child, the full reconfigure is dead (React can't talk to the brain). This spike answers that one question in an isolated throwaway crate before touching the real app.

## Steps
- [x] 1. **Scaffold the isolated spike crate + all files** — Create spike/react-ipc-spike/ (outside the repo root workspace, deleted at the end). Files: (1) Cargo.toml — [package] name="react-ipc-spike", version="0.1.0", edition="2021"; an empty [workspace] table so it does NOT inherit the root workspace; [build-dependencies] tauri-build={version="2"}; [dependencies] tauri={version="2",features=["unstable"]}, serde={version="1",features=["derive"]}, serde_json="1". (2) build.rs — `fn main(){tauri_build::build()}`. (3) tauri.conf.json — mirror the mix-spike's (productName="react-ipc-spike", version, identifier="com.myharness.reactipcspike", app.windows=[], security.csp=null, bundle.active=false) BUT add a `build.frontendDist="dist"` field so Tauri embeds the local HTML. (4) dist/index.html — a page with a #status div; on load it checks `window.__TAURI_INTERNALS__`, calls `.invoke('ping')` and `.invoke('emit_test')`, listens for the 'spike-event' the emit_test command fires, and writes PASS/FAIL text + the returned values into #status (green for success, red for failure). (5) src/main.rs — `#![deny(warnings)]`; a `#[tauri::command] fn ping() -> &'static str { "pong" }`; a `#[tauri::command] fn emit_test(app: tauri::AppHandle) -> Result<(), String>` that calls `app.emit("spike-event", "hello-from-rust")` (import `tauri::Emitter`); in .setup, create a bare `tauri::window::WindowBuilder::new(app, "main").title("react-ipc-spike").inner_size(600.0,400.0).build()`, then `window.add_child(WebviewBuilder::new("app", WebviewUrl::App("index.html".into())), PhysicalPosition::new(0,0), PhysicalSize::new(600,400))` (import `tauri::{PhysicalPosition,PhysicalSize,WebviewUrl,Emitter}` + `tauri::webview::WebviewBuilder` + `tauri::window::WindowBuilder`); register ping+emit_test in invoke_handler; `.build(tauri::generate_context!()).expect(...).run(|_,_|{})`. Run `cargo build` from spike/react-ipc-spike/; fix compile errors against the pinned tauri source (the WebviewUrl::App + add_child API surface — read the tauri-2.x source under ~/.cargo/registry if the exact constructor differs). Confirm warning-free.
- [x] 2. **Run the spike + probe IPC** — Start the built exe (Start-Process spike/react-ipc-spike/target/debug/react-ipc-spike.exe). Wait ~4s for WebView2 init. The page should render visibly (not blank). GO signals: (a) the page shows green text `invoke(ping) => pong` (proves __TAURI_INTERNALS__.invoke works in an add_child — the same mechanism @tauri-apps/api uses); (b) the page shows the 'spike-event' payload `hello-from-rust` (proves listen/emit works in an add_child). If #status shows red `__TAURI_INTERNALS__ NOT present`, IPC is NOT injected into add_child → the full reconfigure is NO-GO. Ask the user to confirm what the page displays.
- [x] 3. **Record go/no-go + cleanup** — memory_write (semantic) the verdict: does Tauri inject __TAURI_INTERNALS__ into an add_child webview loading WebviewUrl::App? Does invoke work? Does listen work? If YES → the full bare-Window + two-add_child reconfigure is de-risked (React + IPC will work in the agent-chat child); the next step is a real implementation plan to reconfigure main.rs. If NO → path (a) is dead for the React-chat use case; fall back to path (b) (non-Tauri tao+wry shell) or keep the app as-is. Then CLEANUP: kill the spike process, delete the entire spike/ directory (`Remove-Item spike -Recurse -Force`), confirm `git status` shows no changes to the real project.
