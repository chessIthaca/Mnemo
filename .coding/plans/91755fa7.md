# Plan: Mnemo2 Phase 0 — clickable Svelte lead/team prototype

## Goal
Build a reusable `mnemo2` npm workspace with Svelte 5 + TypeScript + Vite: a polished warm-white, clickable single-project lead/team prototype using mock data. Cover the start screen, lead chat, beautiful Markdown, connected run timeline, Team peek/control room with 10 workers, worker review/findings/merge record, and Browser/Diff/Plan workbench. No Engine/Tauri/IPC/git mutations; reusable UI only.

## Kind
implementation

## Context
Design of record: `.coding/design/mnemo2.md` (committed ed3b1b1; review PASS). User refinements: no fixed three-worker ceiling; concurrency is a per-project setting separate from budget/rate limits, and the prototype must demonstrate a larger team (use 10 mock workers). Tiny lead/review_fix edits are EITHER up to 5 files with at most 10 changed lines per file OR one file with a larger edit; retain the scope exclusions (no new files, schema/API/dependency changes, cross-module refactors). Decision record: `.coding/knowledge/decision/2027-01-11-mnemo2-team-scaling-and-lead-tiny-work-cap.md`. Verified repo facts (read): root `package.json` currently has only the `frontend` workspace; `frontend/vite.config.ts` uses Vite 8, port 5179 and `../target/frontend-dist`; existing UI is React and must not be imported into the new prototype. Registry checks: Svelte 5.57.2, @sveltejs/vite-plugin-svelte 7.3.1 (Vite 8 peer), svelte-check 4.7.7 (TypeScript 5/6 peer), @testing-library/svelte 5.4.2, @lucide/svelte 1.61.0, markdown-it 15.0.3, DOMPurify 3.4.17, highlight.js 11.12.0, Fontsource Inter/Source Serif packages. Use TypeScript 6 in mnemo2 (not the existing frontend's TS 7). jsdom 30.1.3 has restrictive Node engines, so step 1 must check `node --version` and select a compatible jsdom release if necessary. New Vite port: 5180; output: `target/mnemo2-dist`. No `src/**` or `src-tauri/**` changes and no real IPC/git operations. Pre-existing `.coding` edits (`backlog.jsonl`, `plans/33a7341e.md`, `plans/44e57565.md`, and unrelated knowledge files) must remain uncommitted. Project constitution requires `cargo test --workspace` before every complete_step; each step lists its JS checks plus that command.
