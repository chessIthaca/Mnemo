# Plan: Fix: model picker label not updating after switch

## Goal
Make the toolbar model picker's label update immediately after switching model: backend set_model clears each loop's stale resolved_model, frontend selectModel refreshes agentModels via listAgents→registerAgents.

## Kind
implementation

## Context
Regression from commit a394506 ("surface effective model + add Reviewing slot", in main 2026-08-13): StatusBar.tsx:38 shows `agentModels[activeAgent] ?? model`, but agentModels is only written by registerAgents (App.tsx:163 startup + useAgentEvents.ts:195 unknown-agent), never after a model switch — so the label goes stale. Backend compounds it: set_model (agent.rs:488-494) swaps the provider but never clears the loop's resolved_model, and list_agents (agent.rs:376-379) prefers resolved_model over provider().model(), so even a manual listAgents re-fetch reports the OLD model until the next turn. Fix: (1) backend clears resolved_model per loop on switch; (2) frontend re-fetches listAgents→registerAgents after a successful switch. Working tree also has pre-existing uncommitted changes (build.bat tauri-CLI hoist, Sidebar.tsx Game tab) — reviewer must cover them too; all commits go on a new feature branch (currently on main). Windows/PowerShell, cargo test unpiped, npm run build + npm test from frontend/.
