# Plan: Bundled in-process embedder (fastembed) — drop Ollama, add model picker + download progress + cross-machine re-embed

## Goal
Replace the fragile Ollama/cloud remote embedder with a bundled in-process fastembed model. Add a model picker (curated fastembed catalog) + download progress bar to the config dialog. Store the selected model in app config. Store a per-row model fingerprint so memories traveling between machines (via git) auto re-embed on startup when the model differs. Make the green status dot honest (semantic-bundled vs keyword-fallback).

## Kind
implementation

## Context
Investigation findings (all verified by reading code):

ARCHITECTURE: `build_embedder` (src/provider/client_factory.rs:168) is the single switch point — returns RemoteEmbedder or HashEmbedder. `rewire_vision_and_embedder` (rewire.rs:31) calls build_embedder on every config save → live swap. EmbedderStatus enum (embedder.rs:77) + shared Arc<RwLock> plumbed to UI. The Embedder trait (embedder.rs:24) is dimension-agnostic: RemoteEmbedder latches dim on first success, rejects mismatched-length. HashEmbedder is fixed EMBEDDING_DIM=768. Cosine works on any equal-length pair. MemoryStore stores embeddings as BLOBs (memory/mod.rs:617). The Embedder trait's embed() is infallible (returns zero vec on failure).

CONFIG: [general.embedding_model] is Option<EmbeddingModel{endpoint,model}> tied to endpoints.toml. For the bundled path there's no endpoint — add a new [general.bundled_embedding_model]: Option<String> (a model-id string). EmbeddingSection.tsx currently has endpoint dropdown + free-text model input — replace with model picker + download progress.

FASTEMBED: the `fastembed` crate (thin ONNX Runtime wrapper, prebuilt native binaries, no Python) ships curated models: all-MiniLM-L6-v2 (384-dim, ~90MB), bge-small-en-v1.5 (384-dim), bge-base-en-v1.5 (77-dim), nomic-embed-text-v1.5 (768-dim). Downloads model on first use + caches it. Pure CPU inference. InitOptions lets you set a cache_dir + download progress callback.

CROSS-MACHINE MIGRATION (user-raised): the memory DB lives in .coding/ which is committed to git, so it can travel between machines running different bundled models. A 384-dim query vector against 768-dim stored vectors breaks cosine. SOLUTION: store a model fingerprint per memory row (model_id + dim). On startup, if the configured model's fingerprint differs from what's stored on any row, auto re-embed all. This also covers the model-switch case (replaces the explicit reembed-on-save trigger). The schema needs a new column `embed_model` (text, the model_id) + `embed_dim` (int) on the memories table. Schema migration: ALTER TABLE ADD COLUMN (SQLite supports this; existing rows get NULL → treated as stale → re-embedded on first startup). The startup check: SELECT DISTINCT embed_model FROM memories; if any != configured model_id (or NULL), run reembed_all. This is idempotent + safe across machines.

DROP OLLAMA: remove the RemoteEmbedder path + embedder_probe.rs (the ollama auto-start/pull) + the [general.embedding_model] endpoint-based config. Keep HashEmbedder as the ultimate fallback only if fastembed fails to init (no model selected yet).

This is an implementation plan (changes source code + adds a dependency) → review required at completion.
