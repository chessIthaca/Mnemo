# Plan: Harden reviewer tool surface + Continue button for stopped agents

## Goal
Two fixes from user learnings: (1) a stopped/failed agent (especially a locked subagent) must be continuable from the UI; (2) a review agent must not see plan tools or any other mutation commands — plan tools and every write-adjacent tool (memory writes, backlog mutations, ask_user) must be unavailable to role:reviewer agents, including the UI-spawned review-agent path.

## Kind
implementation

## Context
User reported (2026-09-04 chat): (a) when an agent fails and stops there is no way to continue it; (b) running grok as a review agent showed it can run plan tools like update_plan — plan must not be available to a review agent; asks what other commands a reviewer can see that it shouldn't.

Investigated code (semantic graph + reads):
- The tool-spawned role:"reviewer" allow-list (REVIEWER_BASE_TOOLS, src-tauri/src/ipc/spawn.rs:225) already excludes plan tools, and plan-mutation gates exist at 3 layers (turn.rs:612 schema filter, dispatch.rs:118 flag gate, plan.rs:329/491/588/690 tool-internal gates) for subagents (plan_mutations_allowed=false set in spawn_agent_shared when parent_id.is_some()).
- THE HOLES: (1) ToolFilter::Skill arm (tool/mod.rs:322) auto-grants ALL Memory-category tools + ask_user + current_plan + backlog_status regardless of allow-list → a reviewer can memory_write/memory_update/memory_supersede/memory_delete/memory_consolidate, backlog_status (a backlog mutation), and ask_user. (2) ToolRegistry::schemas (tool/mod.rs:379) unconditionally includes Memory-category tools, so they're even advertised. (3) UI-spawned agents (spawn_agent Tauri command, own_plans_dir, no parent, plan_mutations_allowed stays TRUE) are unrestricted — a user-created "review" agent can create/update plans (the grok case).
- Continue gap: after a final error the agent stays alive and a new Prompt works (runtime/agent.rs terminal-failure path pushes an in-context harness note), but frontend InputBar disables input for subagents entirely (isSubagent lock, InputBar.tsx:65-70,600,719) and there is no Continue affordance for any agent. Frontend already tracks final errors (agentEventReducer reduceError sets running=false) and Stop is deliberately available for subagents (InputBar.tsx:748) — the precedent for a Continue button.
- Reviewer base list today: file_read, read_files, search, search_read, image_* (7), list_models, git_diff, write_review_report. Missing read-only utilities a reviewer legitimately needs: git_log, git_show, web_fetch, and the read-only memory/retrieval tools (memory_recall, memory_list, plans_search, reviews_search, past_fixes, context_pack).

Design decisions:
- Add ToolFilter::Reviewer(Vec<String>) — a strict allow-list arm that does NOT auto-grant memory/backlog/ask_user; only listed tools + current_plan (read-only orientation) are visible. schemas() must stop unconditionally including Memory (all non-Reviewer arms keep Memory=>true so behavior is unchanged elsewhere; Skill keeps its current always-on list).
- Workflow gets set_reviewer_allowlist(list) (parallel to set_tool_allowlist, stores an allow-list kind flag) — allowed_tools() returns Reviewer when the reviewer flag is set, Skill otherwise. Only the role:"reviewer" spawn path (src-tauri/ipc/spawn.rs:156-161) calls the reviewer setter.
- Extend REVIEWER_BASE_TOOLS with the read-only tools above; keep intersection-with-parent semantics and ALWAYS_SAFE_ROLE_TOOLS.
- UI spawn command gains a "read-only review agent" option → role=Some("reviewer") → same restricted surface for grok-style UI-spawned review agents.
- Continue button: track failed flag in agent state (set on final non-retrying Error in agentEventReducer reduceError, cleared on Started/Finished/clear), render a Continue button in InputBar when idle && failed — enabled for subagents like the Stop button — sending "Continue from where you left off." via sendPrompt (the in-context harness note already tells the model why it failed).
- Doc sync required by constitution: prompt.rs closing-sequence + spawn_agent.rs schema text (reviewer surface description), agent.md reviewer expectations, PLAN.md feature list.

Plan kind implementation (source changes; will undergo review). No regression-test discipline issue: each gate change gets tests (tool/mod.rs, workflow/mod.rs, spawn.rs allow-list tests, reducer-level behavior).
