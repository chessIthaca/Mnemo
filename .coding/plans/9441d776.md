# Plan: Bug-fix plans: checkable detailed sub-steps survive restart

## Goal
Persist bug_fixing detailed steps as checkable sub-items with per-sub-step completion state, so a mid-fix restart shows exactly which sub-steps shipped and resumes without redoing finished work: plan_file parses/serializes the `## Detailed steps` section as structured steps with checkbox marks, complete_step gains a detailed_step_index tick, and the plan file becomes the complete crash-resumption document at sub-step granularity.

## Kind
bug_fixing

## Context
Root cause (verified in code): src/workflow/plan_file.rs parses Section::DetailedSteps by accumulating RAW lines into `detailed_steps: Option<String>` (parse_checkbox only runs in Section::Steps); serialize writes the raw body verbatim — no sub-step structure, no done state, and no tool can flip a mark. The tool layer (src/tool/workflow/plan.rs) renders the detail as plain `- {s}` bullets (escape_section_markers hardening stays); validate_plan_resumability (:244) and context_issue (:318) take Option<&str>; workflow/mod.rs:576 sets the field from the raw body. DESIGN (decided): (1) plan_file.rs: `detailed_steps: Vec<Step>` (empty = absent; reuse the Step struct) — parse checkbox lines (`- [ ]`/`- [x]` via parse_checkbox) as steps with done state, legacy plain `- text` lines as unchecked steps (backward compat), non-dash non-blank lines as continuations of the previous step's text (preserves the escape round-trip), blank lines skipped (documented: hand-edited blanks drop on rewrite; the render path never produces them); serialize writes `- [{x| }] {text}` per step; add `detailed_steps_text() -> Option<String>` (joined lines) so the gate/context consumers keep their Option<&str> signatures. (2) workflow/mod.rs: create_plan_with_kind_and_detail parses the raw body via the shared plan_file helper; new `complete_detailed_step(n)` — plan_mutations_allowed check, 1-indexed flip, persist_stack, returns a progress line ("Detailed step 2/5 done — {header}; N remaining"); NO state transitions (sub-steps never trigger Reviewing/Complete); out-of-range error mirrors complete_step_out_of_range_errors. (3) tool layer: the bug-branch render `- {s}` → `- [ ] {s}`; CompleteStepArgs gains `detailed_step_index` (1-indexed; exactly one of step_index/detailed_step_index — clear error on both/neither); create_plan result text says the sub-steps are tickable; tool description + steps schema + kind doc updated; update_plan/complete_step(step_index) must preserve the section + marks. (4) Docs: PLAN.md + README.md bug-plan bullets gain "checkable sub-steps ticked via complete_step detailed_step_index (text immutable, completion state mutable)"; memory_amend the 4405d82d spec record (its "immutable like the skeleton" claim → text immutable, marks tickable). ## Bug
A bug_fixing plan's "## Detailed steps" section persists as raw text with no per-sub-step completion state: after a session restart mid-fix, the resumed plan shows an unchecked "Minimal fix" skeleton step plus a wall of detail text — nothing records WHICH sub-steps already shipped, so a lesser model cannot tell without re-deriving from git diff, and work gets redone or dropped (live case 2027-01-11, plan c87093c1: gate disk-check broadening, 10 grammars, 7 visitors, HTML sub-parsing, docs — ~2000 lines across 5 files — collapsed into one unchecked step; the plan would not have survived continuation after restart).
