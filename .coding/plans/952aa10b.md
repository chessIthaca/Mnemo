# Plan: Backlog: edit images on existing items

## Goal
Let the user edit a backlog item's image attachments: remove existing images and add new ones (paste/drop screenshots) in the card's inline editor, on pending items.

## Kind
implementation

## Context
Root cause (user backlog item cb04ddea: "For items in the backlog I can't edit the images or add new screenshots"): the inline editor on a backlog card is text-only. In frontend/src/components/views/BacklogView.tsx, handleSaveEdit (line ~375) calls backlogEdit(item.id, editText, item.images) — passing the ORIGINAL images unchanged — and the edit branch (lines 520-558) has no image thumbnails, no remove buttons, no paste/drop handling. Image attach (paste/drop + removable thumbnails) exists only in BacklogInput (top input for NEW items, lines 70-222). Backend needs no changes: BacklogStore::edit (src/backlog.rs:300) and the backlog_edit IPC (src-tauri/src/ipc/backlog_cmds.rs:168) already persist images. Test style: static source-contract vitest tests in frontend/src/components/views/BacklogView.test.ts.

## Steps
- [x] 1. **Extend the inline editor with image editing** — In frontend/src/components/views/BacklogView.tsx: (a) lift the `fileToDataUrl` helper from BacklogInput to module level so both input and editor reuse it; (b) in BacklogItemCard add `editImages` state synced from `item.images` when not editing (mirror the editText sync effect); (c) in the edit branch render an attached-images strip (h-14 thumbnails like BacklogInput, hover X remove button); (d) add paste/drop/dragover handlers on the editing container that convert dropped/pasted image files to data URLs and append to `editImages`; (e) change handleSaveEdit to `backlogEdit(item.id, editText, editImages)`; (f) handleCancelEdit resets editImages too; (g) save button enabled when `editText.trim() || editImages.length > 0` (mirrors BacklogInput's canAdd, so image-only items stay valid).
