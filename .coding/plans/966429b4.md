# Plan: Tool rows name their files and expand to diffs

## Goal
In Mnemo2's lead chat and worker threads, a read/write/edit tool row names the files it touches ("Reading toolSummary.ts, types.ts") instead of a count ("Reading 2 files"). Expanding an edit or write row shows the change as a diff, and expanding a read row shows the files and line ranges read, instead of raw Arguments JSON and Result text.

## Kind
implementation

## Context
The user asked for this on 2026-11-02. Today a tool row's headline comes from `toolSummary()` in `mnemo2/src/lib/toolSummary.ts`. It falls back to Mnemo1's `actionPhrase()` in `frontend/src/lib/toolCardPaths.ts`, which says "Reading a file", "Reading 2 files", "Editing files" or "Writing files". The expanded body is `mnemo2/src/components/ToolActivity.svelte`, which shows an Arguments `<pre>` (prettyArguments) plus a Result/Error `<pre>` for every tool. ToolActivity is used by both `LeadChat.svelte` and `WorkerThread.svelte`, so one change covers the lead and the workers.

Decisions:
- Headlines list file basenames: "Reading toolSummary.ts, types.ts". When more than 3 files, show the first 3 and "+N more" ("Editing a.ts, b.ts, c.ts +2 more"). Use the full path in the title tooltip. This applies to read_files, file_edit, multi_edit, file_write / write_file, file_append, and their streaming state (a partially streamed argument string should still show whatever paths are parseable, falling back to today's phrase). Use Mnemo1's existing `argPaths(args, toolName)`, `dedupePaths` and `basename` from `frontend/src/lib/toolCardPaths.ts`. Do NOT change `actionPhrase` or other Mnemo1 code: Mnemo1 shares that file, so the Mnemo2 wording lives in `mnemo2/src/lib/toolSummary.ts`. Team-tool phrases, search, shell and git headlines are unchanged.
- The expanded body is per tool kind:
  - file_edit / multi_edit: render the unified diff from the result's `data.diff`. `fileEditDiff(result)` in toolCardPaths.ts reads it; `LeadToolResult` in `mnemo2/src/lib/types.ts` already keeps `data` via `normalizeToolResult` in `mnemo2/src/lib/leadState.ts`. When no `data.diff` exists (a replayed transcript, where `workerThread.ts` builds results from message text), build a diff from the arguments' old_string/new_string per file. Only when neither is possible, fall back to today's Arguments/Result view.
  - file_write / write_file: show the written content as an all-added diff for that path.
  - read_files: a compact list of path plus "lines X–Y of Z", using `parseReadFilesSections(output)`, with the raw output behind a "Show output" toggle.
  - Everything else (shell, git, team tools, search, ...) keeps today's Arguments/Result view.
  - A failed call always shows its error text.
  - A "Show raw call" toggle keeps the Arguments/Result view reachable for every tool.
- Diff rendering: build one small Svelte component, `mnemo2/src/components/ToolDiff.svelte`, that renders unified-diff text with added and removed lines coloured using the existing app.css tokens, plus a file header per file. Match the look of the line rendering in `mnemo2/src/components/DiffTab.svelte`. Keep it height-capped and scrollable, as today's `<pre>` is (max-height 240px, or a bit larger for diffs).
- Assumption (unverified): Mnemo2 workers use the tool names read_files, file_edit, multi_edit and file_write. The worker should check the argument shapes against `src/tool/agent/` (read_files.rs, file_edit.rs, file_write.rs) and the existing `argPaths` tests.

Verification, from mnemo2/: `npx svelte-check --tsconfig ./tsconfig.json`, `npx vitest run src/lib src/components`, `npm run check:no-mock`. Add a preview scene in `mnemo2/src/test/previewScenes.ts` (a lead chat with read, edit and write rows, one expanded) so the lead can look at it.

## Acceptance scenarios
- A read_files call on two files shows the headline "Reading toolSummary.ts, types.ts"; a call on five files shows three names plus "+2 more"; hovering shows the full paths.
- Expanding a successful file_edit row shows a coloured unified diff of the change (from data.diff), not the Arguments JSON.
- Expanding a file_edit row restored from a replayed transcript (no data.diff) still shows a diff built from old_string/new_string.
- Expanding a file_write row shows the new content as added lines; expanding read_files shows each path with its line range.
- Shell, git and team tool rows look exactly as before, and every row keeps a "Show raw call" toggle to the Arguments/Result view.
- svelte-check is clean, and vitest over src/lib and src/components passes.

## Decisions
- 2026-11-02: The user pointed out on 2026-11-02 that Mnemo1 already implements these expansions, in ToolCallDetail in frontend/src/components/chat/Message.tsx around lines 640-900. Mnemo2's ToolActivity should port that behaviour, in Svelte, for every kind of call Mnemo1 handles: (1) file_edit / multi_edit: the unified diff from fileEditDiff(result). (2) read_files: a per-file list with "lines X–Y of Z" from parseReadFilesSections. (3) shell: the command as a block, purpose and cwd labels, stdout, a separate red stderr section, and an exit-code chip, using shellCallFromArgs and parseShellOutput. (4) search / search_read: an engine and match-count chip from searchResultInfo. (5) browser tools: a result chip from browserResultInfo. (6) web_fetch: a URL chip (webFetchUrl). (7) Path chips from buildPathChips / argLabel for the call's files. Clicking one opens the file in Mnemo2's Files tab, or the Diff tab for edits, when the store has an action for that. Otherwise plain text. (8) The raw tool name, the duration and the start time in the detail header. (9) file_write: the new content as all added lines, like Mnemo1's NewFileView. Diff parsing: reuse Mnemo1's pure parseUnifiedDiff and computeDiff from frontend/src/components/chat/DiffView.tsx. If importing a .tsx into the Svelte build is a problem, extract those two pure functions (and the DiffLine type) into a new frontend/src/lib/diffLines.ts that DiffView.tsx re-imports. That one Mnemo1 change is allowed, provided Mnemo1's DiffView tests still pass (`npx vitest run src/components/chat/DiffView.test.ts` from frontend/). computeDiff is also the fallback that builds an edit diff from old_string/new_string when data.diff is missing. This supersedes the plan context's "Shell, git and team rows unchanged" for shell: shell gets Mnemo1's view. Git and team tools keep the generic view.
