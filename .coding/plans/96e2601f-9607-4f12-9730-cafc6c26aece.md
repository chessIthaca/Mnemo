# Plan: Chunked writes for review reports + long plans (file_write-style append)

## Goal
Long plan and review-report bodies can be written in several small tool calls: write_review_report gets mode:"append" (verdict enforced on create, fail-closed preserved) and update_plan gets a true append flag (steps/context added after existing without resending) so agents chunk like file_write.

## Kind
implementation

## Context
Backlog 0085ccc0: create_plan and write_review_report take the whole body in ONE tool call — for long plans/reviews the model generates a huge args JSON slowly and risks truncation. file_write.rs already solved this with mode:"overwrite"|"append" (schema lines 86-87, "adds to the end, creating the file if absent"). write_review_report.rs: content arg + verdict-line contract (FIRST non-blank line must be "## Verdict: PASS"/"## Verdict: FINDINGS", fail-closed, lines 185-199) + resolve_under_reviews bare-filename sandbox (lines 64-125) — 8 existing tests. create_plan (tool/workflow/plan.rs CreatePlanArgs: title/goal/context/steps/kind/bug/branch/base) is atomic via workflow create_plan_with_kind (workflow/mod.rs:421-451: writes plan file, pushes stack, → Executing). update_plan already edits the active plan in Executing state but its steps semantics REPLACE remaining steps (resend needed); bug_fixing plans lock the 4-step BUG_FIXING_SKELETON (update_plan refuses to replace). update_plan is the natural chunk vehicle for plans: create_plan(chunk 1) → Executing → update_plan(append) per chunk — no state-gate changes needed. Reviewer authorship protections (schema+dispatch+sandboxed reviews dir) must not weaken: append keeps bare-filename sandbox and verdict-on-create fail-closed.
