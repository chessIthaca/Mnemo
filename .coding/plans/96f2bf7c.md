# Plan: The gear opens Settings, with this project's settings as its first page

## Goal
The top-bar gear opens the Settings dialog directly; the per-project settings (worker slots, lead model, merge policy) become a "Project" page inside it, and the separate project sheet with its "Endpoints & pricing → Open" detour is gone.

## Kind
implementation

## Context
Why: the user: "The gear icon opens a 'per project settings' and then endpoints and pricing opens the config dialog. Shouldn't the per project settings just be a tab in the config dialog and the gear opens config?"

Verified facts:
- verified: `mnemo2/src/components/TopBar.svelte` line ~76: the gear (`aria-label="Project settings"`) sets `settingsOpen = true`, which opens a `Sheet` (line ~111, title "Project settings", eyebrow "PER-PROJECT") with: a copy line, "Worker slots" (number input 1-32, `setSlots` → `$currentProject.workerSlots`), "Lead model" (`<LeadModelPicker compact />`), "Merge policy" (a static "Guarded" note), and "Endpoints & pricing" with an Open button calling `openAppSettings()`, which closes the sheet and opens `<SettingsDialog open={appSettingsOpen} ...>` (line ~125).
- verified: `mnemo2/src/components/SettingsDialog.svelte` has a `pages` list (Endpoints, Tiers, Models, Savings, Decisions, Safety, MCP, Appearance & sounds) with `let page = $state<Page>("endpoints")` and one branch per page.
- verified: some existing pages already hold per-project parts (Safety's project rules, MCP's project servers), so the dialog already mixes install-wide and project settings.

Decisions:
- The gear opens `SettingsDialog` directly (keep `aria-label` meaningful, e.g. "Settings"). Delete the project `Sheet` from TopBar.
- New `ProjectPage.svelte` as the FIRST page in the rail, labelled with the project's name (fallback "Project"), containing: Worker slots (same input and `setSlots` behaviour, moved into the page or a store action), Lead model (`LeadModelPicker`), and the merge policy line. With no project open, the page says "Open a project to change its settings" and the dialog opens on Endpoints instead.
- Make the rail show two small group headings: "This project" (Project) and "All projects" (the rest), keeping the existing page order otherwise. Safety and MCP keep their own project sections; no move needed.
- `SettingsDialog` gets an optional `initialPage` prop so other callers (e.g. the cost chip or future links) can open a specific page; the gear opens "project".
- Theme tokens only (the app has a dark theme). Keep the existing settings preview scenes working; add a `settings-project` scene directly after the `settings-appearance` scene in `mnemo2/src/test/previewScenes.ts`.
- Another worker is editing `ModelsPage.svelte`/`modelSettings.ts` and another `store.ts`/`types.ts`/`Toast.svelte`: do not touch those files; if a store action is needed for slots, reuse the existing one.

Verification: in `mnemo2/`: `npx svelte-check --tsconfig ./tsconfig.json`, `npm run check:no-mock`, `npx vitest run` (tests: the gear opens SettingsDialog on the Project page; slots and lead model work from the page; with no project the dialog opens on Endpoints; update TopBar and SettingsDialog tests that referenced the sheet). Never start a dev server or any command that does not exit on its own.

## Acceptance scenarios
- Clicking the gear opens the Settings dialog on a Project page showing worker slots, the lead model and the merge policy.
- The rail groups the Project page under 'This project' and the other pages under 'All projects'; there is no separate project sheet anymore.
- With no project open, the gear opens Settings on Endpoints and the Project page explains that a project must be open.
