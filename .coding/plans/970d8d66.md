# Plan: Prove tests against the old code: regression red check and mutation findings

## Goal
Mnemo2 proves, without the lead reading code, that a bug fix's regression test fails without the fix, and (opt-in) reports changed code that no test catches as review findings.

## Kind
implementation

## Context
WHY: today "the regression test fails without the fix" and "the new tests really test the change" are rules in agent.md and review prose. Workers prove red by hand (or claim it), and the lead catches vacuous tests only by reading closely: a recent worker added a test that would have passed against a filter accepting everything. Mnemo2 should run these proofs itself and record the result as a check or finding, so the merge gate enforces them.

TWO MECHANISMS (decided):
A. REGRESSION RED CHECK (always on for bug fixes). In the worker's own pool checkout, while the worker is idle: confirm the plan's regression test passes at the tip; reverse-apply only the change's SOURCE hunks (keep its test hunks); run the test again. It must now fail (non-zero exit: a test failure or a compile error both count). Always restore the checkout to the tip afterwards. The worker's own checkout is used on purpose: its target/ is warm at the tip, so the build is incremental. A separate checkout would rebuild everything.
B. MUTATION FINDINGS (opt-in, configured per project). Run a mutation tool limited to the change's diff (for Rust, cargo-mutants `--in-diff`). Each mutant no test caught becomes a low-severity review finding. This is what catches a vacuous test. It is expensive, so it runs only on demand (a lead tool) and automatically for review_risk "high" workers. The tool works in its own temp copy, never in the worker checkout.

TEST VS SOURCE HUNKS (decided rule, used by A): a changed file is a TEST FILE when any path component is `tests` or `test`, or its file name contains `.test.`, `.spec.`, `_test.` or `_tests.`, or its file name is `tests.rs`. For any other `.rs` file, a hunk is a test hunk when its new-side start line is at or after the first line of the TIP file matching `^\s*#\[cfg\(test\)\]`. Every other hunk is a source hunk.

CONFIG: `.coding/checks.toml` (read from the lead's project root, like `load_check_commands` in src-tauri/src/mnemo2/team/spawn.rs) gains two optional tables. The existing `commands` key is unchanged.
```toml
[regression]
\# Runs one test by name; {name} is the plan's regression_test.
command = "cargo test --workspace -- {name}"
\# Text that proves the test ran (the output must contain it, {name} replaced).
ran = "{name} ... "

[mutation]
\# {diff} = a unified diff file of the change, {out} = an output folder.
command = "cargo mutants --in-diff {diff} --no-shuffle --jobs 2 --timeout 600 --output {out}"
\# A file under {out} listing the missed mutants, one per line.
missed = "{out}/mutants.out/missed.txt"
```
When `[regression]` is absent and the project root has a `Cargo.toml`, the values above are the default. With neither, proof A is skipped with a notice telling the lead to add the table. `[mutation]` has no default: without it, B is unavailable and the lead tool says so. This repository's checks.toml gets both tables, `[mutation]` included.

VERIFY (each alone on its line): `cargo test --workspace`; `cargo clippy --workspace --all-targets`. Focused: `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::team::proof`.

## Acceptance scenarios
- A bug_fixing worker whose diff adds the plan's regression test gets a passed check 'regression test fails without the fix' recorded automatically after its turn, with no lead action.
- A regression test that passes against the old source opens finding regression-not-red (high), and team_merge refuses until it is resolved.
- After any proof, the worker checkout is at the same tip with a clean status, and its target/ folder still exists (incremental build preserved).
- team_mutation_check on a worker with a vacuous test opens a 'No test catches: ...' finding naming the uncaught code.
- While a proof runs, team_message and team_merge for that worker are refused with a message naming the proof.

## Steps
- [x] 1. **Proof engine: hunk split, config, red-check runner, mutation runner** New file `src-tauri/src/mnemo2/team/proof.rs`, declared in `src-tauri/src/mnemo2/team/mod.rs` (or wherever the team submodules are declared). No wiring into the runtime in this step. Public contract, `pub(crate)` unless noted: ```rust pub struct ProofConfig { pub regression: Option<RegressionCfg>, pub mutation: Option<MutationCfg> } pub struct RegressionCfg { pub command: String, pub ran: String } pub struct MutationCfg { pub command: String, pub missed: String } pub fn load_proof_config(workspace_root: &Path) -> ProofConfig; pub fn is_test_path(rel: &str) -> bool; pub fn source_hunks_patch(diff: &str, tip_file: &dyn Fn(&str) -> Option<String>) -> String; pub enum RedOutcome { Red { output: String }, NotRed { output: String }, Inconclusive { reason: String } } pub async fn prove_regression(checkout: PathBuf, base: String, tip: String, cfg: RegressionCfg, test: String) -> Result<RedOutcome, String>; pub struct Mutant { pub file: String, pub line: u32, pub text: String } pub async fn run_mutation(main_root: PathBuf, checkout: PathBuf, base: String, tip: String, cfg: MutationCfg, worker_id: String) -> Result<Vec<Mutant>, String>; ``` Rules: - **`load_proof_config`** parses the two optional tables from `<root>/.coding/checks.toml`. It falls back to the cargo defaults for `regression` when the table is absent and `<root>/Cargo.toml` exists. Malformed TOML gives an empty config and one `eprintln!`. - **`is_test_path`** implements the TEST FILE rule from the plan context. Split on both `/` and `\\`. - **`source_hunks_patch`** takes the output of `git diff --no-color --no-ext-diff -U0 <base> <tip>` and returns a patch with only the SOURCE hunks (the rule in the plan context). For the `#[cfg(test)]` boundary it reads the tip file's text through `tip_file(rel)`. - Keep each kept file's `diff --git`, mode and `---`/`+++` header lines. - Drop files whose hunks are all test hunks. - Binary files (`Binary files ... differ`) are always kept as source. - Use `-U0` so hunks are minimal and can be split cleanly. `git apply -R` must then be called with `--unidiff-zero`. - **`prove_regression`**: all git and commands run in `checkout`; blocking work goes through `spawn_blocking`. 1. Preconditions: `git rev-parse HEAD` == tip, and `git status --porcelain -uall` is empty. Otherwise return Ok(Inconclusive{reason}) and touch nothing. 2. Run the command with `{name}` replaced (via the platform shell: `powershell -NoProfile -Command` on Windows, `sh -c` elsewhere), with a 20-minute timeout. - If the exit code is non-zero or the output (stdout+stderr) lacks the `ran` text: Inconclusive{"the regression test does not pass at the tip, or was not found: <last 1500 chars>"}. 3. Compute the merge base (`git merge-base <base> <tip>`), take the -U0 diff, and build the source patch. - If it is empty: Inconclusive{"the change has no source hunks"}. - Otherwise write it to a temp file and run `git apply -R --unidiff-zero --whitespace=nowarn <file>`. If that fails: restore, then Inconclusive{reason with git's stderr}. 4. Run the command again. - Exit non-zero: Red{output tail}. - Exit zero and the `ran` text present: NotRed{output tail}. - Exit zero and the `ran` text missing: Inconclusive{"the test did not run without the change (it may live in a file the change adds)"}. 5. RESTORE ALWAYS, including on every error path after step 3 (use a guard or an explicit finally): `git reset --hard <tip>` then `git clean -ffd`. Never pass `-x`: the ignored target/ is the warm cache. Then verify HEAD == tip and the status is clean. If the restore cannot be verified, return Err("checkout could not be restored: ..."); that error is serious and the caller must surface it. - Output tails are capped at 1500 chars, cut on a char boundary. - **`run_mutation`**: 1. Write `git diff <merge-base> <tip>` to `<main_root>/.coding/tmp/mutation/<worker_id>/change.diff`; `{out}` is that folder. Create it and clear an old run first. 2. Run the command with `{diff}`/`{out}` substituted, in `checkout`, with a 3-hour timeout. Never modify the checkout: cargo-mutants copies the tree by default, and the step must not add `--in-place`. 3. Read the `missed` file. - Each non-empty line is `path:line:col: description` (cargo-mutants format); parse it into Mutant. A line that does not parse becomes Mutant{file:"", line:0, text: line}. - If the command failed to start or the missed file is missing after a non-zero exit, return Err with the output tail. 4. Afterwards verify the checkout is still clean at the tip; if not, Err. Tests, in `proof.rs`'s test module: - `is_test_path_table`: `src/memory/indexer/tests/openspec.rs`, `mnemo2/src/lib/x.test.ts`, `src-tauri/src/mnemo2/team/tests.rs` and `a\\tests\\b.rs` are true; `src/host/brain.rs` and `src/latest.rs` are false. - `source_patch_drops_inline_test_module_hunks`: a synthetic -U0 diff of one `.rs` file with one hunk before and one after the tip's `#[cfg(test)]` line keeps only the first. - `source_patch_drops_test_files_keeps_binaries`. - `prove_regression_red_on_real_repo` (`#[tokio::test]`): a temp git repo with a tiny cargo-free setup. Use a regression command that runs a script, e.g. on Windows `powershell -NoProfile -Command "if ((Get-Content src.txt) -eq 'fixed') { 'demo ... ok' } else { 'demo ... FAILED'; exit 1 }"`; on other OS an `sh -c` equivalent selected with `cfg!`. - Base commit: src.txt = `broken`. Tip commit: src.txt = `fixed`, plus `tests/demo.txt`. - Assert Red, then assert HEAD == tip and the tree is clean afterwards. - `prove_regression_not_red_when_test_ignores_the_fix`: the command always prints `demo ... ok` and exits 0; assert NotRed and a restored checkout. - `prove_regression_refuses_a_dirty_checkout`: an untracked file present gives Inconclusive, and the file is untouched. - `parse_missed_mutants`: three sample lines, one malformed. Keep the scripted commands portable through `cfg!(windows)`; the macOS CI leg runs these tests. Done (each alone on its line): - `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::team::proof` - `cargo test --workspace` - `cargo clippy --workspace --all-targets` - Commit. ## Decisions
- 2026-11-17: no spec impact: Adds a new proof mechanism and merge-gate condition; no requirement of dispatch-routing, external-lead, tier-ladder or worker-brief changes (routing, lead attachment, tiers and worker briefs behave as before).
- 2026-11-17: Binary sections are DROPPED from the source patch, not kept. A plain git diff carries no binary data, so `git apply` rejects the whole patch and every proof touching an image would be inconclusive. A binary file is never the fix a regression test proves. (Supersedes 'binary sections are always kept as source' in step 1; from audit proofAudit1 F4.)
- 2026-11-17: Merge-gate waiver for the regression proof: only a proof finding resolved as wontfix (with a written reason) waives the red check. A 'fixed' resolution never waives it; fixed must be shown by the red check at the tip. Proof findings carry their tip on the first detail line, and a new tip re-proves. A proof claim is serialized with every turn start through merge_lock, with an idle check. (Audit wireAudit1 F1/F6.)
