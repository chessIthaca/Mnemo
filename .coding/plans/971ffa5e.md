# Plan: Claude Code prefers Mnemo's code and memory tools over plain search

## Goal
In a Mnemo2 project, Claude Code can call Mnemo's code search (search, search_read) as MCP tools next to graph_* and memory_*. When Claude reaches for Grep or Glob to find a symbol or a project decision, it is pointed to the Mnemo tool that answers better.

## Kind
implementation

## Context
WHY: the user (2026-11-01): "make the source code tools and memory tools available to the mcp so that claude can use them and prefers them over search".

FINDINGS (probed while planning):
- verified: the Mnemo MCP server already lists memory_search, memory_write, memory_amend, memory_update, memory_supersede, graph_search, graph_context, graph_impact and graph_path (src-tauri/src/mnemo2/mcp_server.rs ~line 2114, test list). Claude Code shows them as deferred tools that must be loaded with ToolSearch before use, so in practice Claude rarely calls them and uses Grep/Glob.
- verified: the engine's code-search tools are src/tool/agent/search.rs (`search`: literal queries are answered from the CodeGraph FTS content index when populated, regex falls back to a tree walk, and queries naming an indexed symbol auto-delegate to the code graph; memory-targeted queries auto-delegate to memory) and src/tool/agent/search_read.rs (`search_read`: the same search plus reading the top matched files with line numbers in one call). Neither is exposed over MCP.
- verified: the plugin's hooks are declared in mnemo2/plugin/hooks/hooks.json (a PreToolUse matcher for Agent|Task|Workflow exists; PostToolUse matcher "*") and implemented in src-tauri/src/bin/mnemo2_mcp/hooks.rs.
- verified: the lead instructions LEAD_INSTRUCTIONS in mcp_server.rs must stay under 2048 characters (test the_lead_instructions_fit_claude_codes_limit_and_name_real_tools); the current text sits at the limit.

DECISIONS:
- Expose `search` and `search_read` as MCP tools with the engine's own schemas and descriptions, read-only, run against the open project's engine, with output size caps so a broad query cannot flood Claude's context.
- Steering, not blocking: a PreToolUse hook on Grep and Glob in a registered Mnemo2 project adds additionalContext when the pattern looks like a code identifier (CamelCase, snake_case, `fn X`, `struct X`, `X::y`) or a knowledge lookup (SPEC:/DECISION:/BUG:/HOW:, words like "decision", "why"). The context names the Mnemo tool and the exact call (graph_search {query}, search {pattern}, memory_search {query}) and the ToolSearch select string to load it. It never denies the call and stays silent for plain text, paths and regexes, and outside Mnemo2 projects.
- Update LEAD_INSTRUCTIONS (keep it under 2048 chars by tightening other lines) and mnemo2/plugin/skills/mnemo-lead/SKILL.md so they say: for code use search / graph_* first; for project history use memory_search first; use Grep/Glob for exact text in known files.

## Acceptance scenarios
- Claude Code's Mnemo tool list includes search and search_read, and a search call for an identifier returns graph-backed results.
- A Grep for an identifier like attach_external_lead in a Mnemo2 project gets a hint naming graph_search / search and how to load them; a Grep for a plain sentence gets no hint; nothing is ever blocked.
- The lead instructions and the mnemo-lead skill tell Claude to prefer search, graph_* and memory_search over Grep/Glob for code and project history.
