# Plan: Command-aware shell-output filtering (PandaFilter idea, in-process)

## Goal
Add a deterministic, regex-based, in-process output filter to the shell tool so plan-step commands (cargo build/test, npm test/build, git status) collapse noise lines before they reach the LLM transcript — with hard safety rules (error lines never dropped, unknown commands passthrough) and an optional [shell_filter] config section.

## Kind
implementation

## Context
MEASURED (real captured plan-step `cargo test --lib`, 1233 tests, warm build): raw combined output 1245 lines / 91,635 bytes → filtered 7 lines / 407 bytes = 99.4% line / 99.6% byte reduction (target >80%, exceeded). Filtered transcript keeps: 1 ignored-test line, `test result: ok. 1233 passed…` summary, `Finished` + `Running` (stderr), `[exit code: 0]`. Structural-pass refinement landed: passing-test/asset/compile lines are dropped even when a NAME contains a marker word (test error_recovery … ok, Compiling thiserror, dist/assets/error-404.js) — documented as the single exception to the error-marker veto; user overrides remain strictly vetoed. Full suite: 1232 lib + 1 fixture + 9 ipc + 5 integration = 1247 passed, 0 failed, warning-free.
