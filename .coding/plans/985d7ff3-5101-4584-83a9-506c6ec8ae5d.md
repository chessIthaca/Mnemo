# Plan: Comprehensive git-HEAD diff in the Diff tab

## Goal
The Diff tab shows the comprehensive diff of the working tree vs git HEAD (per selected file or all files), with the existing last-edit view kept as a secondary mode.

## Kind
implementation

## Context
User report (2 items, continuing on feat/memory-access-log): (1) The right-panel Diff tab (frontend/src/components/views/DiffViewer.tsx) "only shows the last diff, not the diff against git — it should show a comprehensive diff". ROOT CAUSE CONFIRMED: the tab's data is `planDiffs` (frontend/src/hooks/agentEventReducer.ts) — one LastDiff entry per distinct path via `upsertPlanDiff` (:125), each REPLACED on every new edit to that path, holding only the newest tool call's diff (reducer :402-439). No git-backed view exists anywhere in the UI. (2) The graph-keyword question is ANSWERED (graphCallLabel chip shipped in 70d2cc6; needs rebuilt frontend) — no new work unless the user asks.

Design for (1) — new "vs Git" mode in the Diff tab:
- Backend: new IPC command `git_diff_head(path: Option<String>) -> Result<String, IpcError>` in src-tauri/src/ipc/files.rs. Sync core `fn git_diff_head_at(root: &Path, path: Option<&str>) -> Result<String, String>` mirroring `read_git_branch` (:274-297): std Command "git diff HEAD -- <path>" (no path → whole tree), current_dir(root), env_remove GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE (review L5), CREATE_NO_WINDOW on Windows, --no-color. When a path IS given, sandbox-validate it FIRST (Sandbox::validate — same as read_file :31-34) so the UI can't diff a file outside the project root; the `--` separator prevents flag injection. Runs via spawn_blocking with the project root CLONED before spawn (lock dropped; F1 freeze lesson — same as get_git_branch :299-308). Ok("") = no changes; Err carries git's stderr (e.g. not a repo). `git diff HEAD` covers staged + unstaged tracked changes vs HEAD (comprehensive); untracked files are NOT included — document this limitation in the doc comment.
- Frontend: wrapper `gitDiffHead(path: string | null)` in frontend/src/lib/tauri.ts. DiffViewer.tsx gets a view-mode toggle — local useState<"git" | "edit">, DEFAULT "git" (the user's ask): in git mode the body fetches gitDiffHead(selectedDiffPath) on selection/mode change (+ a small Refresh button, RefreshCw icon, disabled while loading); dropdown gains a top option "all changed files (vs Git)" (value "" → null path → whole-tree diff); empty result renders "No changes vs git HEAD"; errors render the message. The pending-approval flow stays on the per-edit preview UNTOUCHED (that's the approval UX). Header shows a "vs Git" chip; "last edit" mode preserves the existing DiffEntryBody path.
- Testability: extract pure `shouldFetchGitDiff(mode, showPending): boolean` exported from DiffViewer.tsx, mirroring GraphView's shouldReloadOnIndexingEdge pattern; new colocated DiffViewer.test.ts MUST be added to frontend/vitest.config.ts include list (repo convention — colocated tests are not auto-discovered).
- Backend tests in files.rs mod tests (tempdir repo pattern already used by read_git_branch_reports_branch :94-119): (a) commit file, modify → git_diff_head_at contains -old/+new lines; (b) two files changed, path filter returns only that file's hunks; (c) clean tree → Ok(""); (d) non-repo dir → Err; (e) path outside root rejected by the sandbox validation before git runs.
- Constraints: Windows 11 + PowerShell, unpiped commands reading $LASTEXITCODE; #![deny(warnings)] — no #[allow], doc comments on all pub items; root cargo test does not compile src-tauri — run both; preserve line endings (write LF); commit to feat/memory-access-log (current branch, per user), never main; commit includes the review report. Frontend matrix: npm test + npx tsc --noEmit + npm run build.
