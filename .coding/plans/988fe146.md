# Plan: Workers show what the model is doing, with a live timer

## Goal
While a worker runs, mission control and the worker thread show an animated status like the lead's "Thinking… · 1m 12s": Starting, Thinking, Writing, Running <tool>, or Waiting on you. It comes with a live timer for the current turn, and each worker row shows how long the worker has been running.

## Kind
implementation

## Context
WHY: the user (2026-11-01): "the workers don't have any indication that the model is thinking. Can we add something like claude or the mnemo lead has with an animation that shows status of the model like waiting, thinking, etc and time since the worker started?" Today a working worker's thread just stops growing while the model thinks, and the row shows only a static progress bar and a final elapsed value.

FINDINGS (probed while planning):
- verified: the lead chat already has this. In mnemo2/src/components/LeadChat.svelte (around line 204) a `.thinking-status` row shows a pulsing `.thinking-dot` (keyframes thinking-pulse, styles around line 271-277), the text "Thinking…" and <ElapsedTime startedAtMs={$app.leadRuntime.turnStartedAtMs} />. mnemo2/src/components/ElapsedTime.svelte ticks every second and formats with lib/elapsed.ts.
- verified: workers stream TeamEvents that mnemo2/src/lib/workerThread.ts applyWorkerLiveEvent handles: started, finished, exited, text_delta, reasoning_delta (listed near line 269), tool_call_start, tool_call_arg_delta, tool_execution_start, tool_output_delta, plus tool results. mnemo2/src/lib/store.ts streamWorkerEvent (around line 2124) applies them only to a worker whose saved thread is loaded (workerSaved), so rows of other workers never see them.
- verified: Worker status values (mnemo2/src/lib/types.ts WorkerStatus) include dispatching, working, needs_you, idle, paused, interrupted and more; teamState.ts maps elapsed_ms to elapsedMs.
- verified: the dev preview page exists: mnemo2/preview.html?scene=<name> with scenes in mnemo2/src/test/previewScenes.ts (HOW: Review Mnemo2 UI changes with the preview page).

DECISIONS:
- Phase from events, for every worker, in the store: a small per-worker activity record {phase, toolName, turnStartedAtMs, phaseSinceMs}, updated by every TeamEvent whether or not that worker's thread is open. Phases: `starting` (dispatching, or turn started and nothing streamed yet), `thinking` (reasoning_delta, or between a tool result and the next output), `writing` (text_delta), `tool` (tool_call_start through the tool's result, with its name and a friendly label from lib/toolSummary.ts when available), `waiting` (needs_you or blocked on approval or answer: no pulse, shown as "Waiting on you"). Finished, idle, paused, failed and merged workers show no live status.
- Thread: the worker thread (WorkerThread.svelte, used in mission control and the side panel) ends with the same `.thinking-status` row as the lead chat: pulsing dot, the phase label, and ElapsedTime from turnStartedAtMs. Reuse the lead's look; extract a shared component (for example components/ActivityStatus.svelte) so both use one implementation instead of copying CSS.
- Row: while a worker runs, WorkerRow shows a small pulsing dot with the phase label (meta size) and a live elapsed timer since the worker started (created_at_ms), replacing the static elapsed. Finished workers keep today's final elapsed.
- Respect prefers-reduced-motion (no pulse, dot stays solid). Use the type tokens (--text-meta / --text-body); no new font sizes.
- Add preview scenes or extend existing ones so the mission-control scene shows one worker in each live phase.

VERIFY (in mnemo2/):
- npm run check (0 errors, 0 warnings)
- npm run check:no-mock
- npx vitest run
- Unit tests for the phase reducer: each event moves to the right phase; a tool's result returns to thinking; finished clears it; events for a worker whose thread is not open still update its phase.
- Render preview.html?scene=mission-control at 127.0.0.1 and report what the rows and the thread show.
- Fresh worker worktrees need `npm ci --no-audit --no-fund` at the worktree root first.

## Acceptance scenarios
- A working worker's thread ends with a pulsing status row reading Thinking…, Writing…, Running <tool>… or Starting… with a ticking timer for the current turn.
- A worker that needs an answer shows "Waiting on you" without a pulse; finished workers show no live status.
- Every running worker row shows its phase and a live timer since it started, even when its thread is not open.
- The lead chat's Thinking row looks the same as before.
