# Plan: ToolCard headers: unique file-name chips + salvage names from truncated args

## Goal
Guarantee the ToolCard header shows each file name exactly once (unique chip texts, no repeated bare basenames) and recovers a clickable file name even from truncated/unparseable tool-call args.

## Kind
bug_fixing

## Context
Prior related fixes, all merged to main: 30820ec (dedupePaths — cross-call dedupe by FULL normalized path), 5c37673 (read_files single-file `path` shorthand yields a link). Both are pinned by tests in frontend/src/lib/toolCardPaths.test.ts. Remaining leak-through mechanisms found by tracing current code: (A) Duplicate-looking names — frontend/src/lib/toolCardPaths.ts buildPathChips() (lines ~118-145) computes chip text = basename(p) AFTER path-level dedup, so src/a/main.rs and src/b/main.rs produce TWO chips with IDENTICAL text "main.rs" (test line 286 pins this at the dedupePaths level — only chip TEXTS need to change, not dedupePaths semantics); (B) Missing name — ToolInvocation.args is assembled incrementally from streaming tool_call_arg_delta fragments (frontend/src/lib/types.ts lines 260, 286-291), so an aborted call permanently stores TRUNCATED JSON; argPaths() (toolCardPaths.ts lines 30-36) bails out returning [] whenever JSON.parse fails, leaving a nameless header. Fix must stay pure TS so node-env vitest can exercise it (module doc comment requirement).
