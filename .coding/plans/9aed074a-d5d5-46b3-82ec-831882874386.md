# Plan: Per-agent workflow state (fix stale planning display)

## Goal
Track workflow state per agent so the top-bar/status/backlog always reflect the active agent's real phase, refreshed on turn lifecycle events — eliminating the stale 'planning' shown when a prompt is queued to a Complete agent.

## Context
Backend never resets workflow state on prompt dispatch (verified in dispatch_next_impl + run_turn). Root cause is frontend: useAgentStore keeps a single global `workflowState` (line 266) updated only by the `workflow_state_changed` event (line 962-970) and one-shot getWorkflowState fetches in App.tsx/StatusBar.tsx. Each agent owns its own Workflow (per-agent via factory), so a global value goes stale / shows the wrong agent's phase. When a prompt is dispatched to an idle agent, no state_changed event fires (still complete) → nothing refreshes → the display can show a stale/subagent's 'planning'. Fix: make workflow state per-agent and have StatusBar/BacklogView read the active agent's value, refreshed on started/finished/state_changed.

## Steps
- [x] 1. Store: replace the single global `workflowState` with a per-agent map `workflowStates: Record<AgentId, WorkflowState>`; add `setWorkflowState(id, state)` action; keep a derived helper for the active agent. Update the `workflow_state_changed` handler to write into the per-agent map (keyed by the event's agent_id) and still bump planVersion.
- [x] 2. Store: on `started` for an agent, optimistically leave state as-is but ensure the agent has an entry; on `finished`, re-fetch is handled by components (no store fetch).
- [x] 3. StatusBar: read the active agent's workflow state from the per-agent map (fall back to a getWorkflowState(activeAgent) fetch when missing); replace direct `workflowState` global reads. Keep the existing refreshPlan on planVersion/activeAgent.
- [x] 4. BacklogView: read the main agent's workflow state from the per-agent map (the in-flight item mirrors the main agent). Use the per-agent value for the badge, falling back to the in-flight status.
- [x] 5. App.tsx: on startup, seed workflowStates for the active agent via getWorkflowState (already fetches; now write into the per-agent map).
- [x] 6. Run cargo test + frontend tsc to confirm no regressions.
