# Plan: ask_user redesign: collapse-to-answer, numbered options, command-box selection, subagent input lock

## Goal
Redesign the ask_user question UX: (1) after answering, the live dialog collapses into a static Q→A transcript entry instead of vanishing; (2) options are numbered `1)`, `2)`, … and the freeform "Let's talk about it" becomes a final numbered choice (no inline textarea in the prompt); (3) typing `1)`, `2)`, … in the standard InputBar resolves the pending question by choice index, and picking the "Let's talk about it" number switches the InputBar into freeform-answer mode; (4) the InputBar is disabled when the active agent is a subagent (no sending commands to subagents).

## Context
Findings from investigation (all in frontend/src):

CURRENT FLOW:
- Backend emits `user_question` → `reduceUserQuestion` (agentEventReducer.ts:387) sets `agent.pendingQuestion = {questionId, question, options}`.
- `Conversation.tsx:116` renders `<QuestionPrompt key={questionId} question=…>` when `state.pendingQuestion` is set.
- `QuestionPrompt.tsx` renders clickable option buttons + an always-present inline `<textarea>` ("💬 Let's talk about it") + Send button. `answerChoice(i)` / `answerFreeform()` call `answerQuestion(questionId, {kind:"choice",index}|{kind:"freeform",text})` (tauri.ts:74).
- On answer, `pendingQuestion` is cleared on the NEXT event (`reduceStarted` sets it null at agentEventReducer.ts:103). So the prompt just disappears — no record of Q or A survives in the transcript.
- `TranscriptEntry` (types.ts:208) has variants: user | assistant | tool | error | steer | skill. No "question"/"qa" variant exists today.

INPUTBAR (InputBar.tsx):
- `handleSend()` (line 164): if `steerMode` (agent running) → `addSteer` + `sendSuggestion`; else parse slash, else `sendPrompt`. No awareness of a pending question.
- `handleKeyDown` (line 373): Enter sends; slash-menu nav; prompt history up/down. No `N)` numeric-answer interception.
- `canSend` (line 457): `(text.trim() || images) && activeAgent !== null`.

SUBAGENT DETECTION:
- `agentParents: Record<AgentId, AgentId|null>` (useAgentStore.ts:164). `null` = parentless (main). A subagent = `agentParents[activeAgent] !== null`. MainPanel.tsx:91 already uses `const isSubagent = t.parentId !== null;` for the close-x.

DESIGN DECISIONS (confirmed with user):
- "Let's talk about it" = a final numbered choice (its own number), NOT an inline textarea. Picking it (click or type its number) switches the InputBar into "answer mode": placeholder → "Type your answer to '<question>'… (Enter to send)", a small banner shows which question is being answered, Enter sends the typed text as `{kind:"freeform",text}`.
- Numbered options: `1)`, `2)`, `3)` … then `N) 💬 Let's talk about it`.
- Command-box selection: typing `1)`, `2)`, … (digit(s) + `)`) in the InputBar while a question is pending resolves it by choice index. This must take precedence over sending a prompt/steer.
- Collapse-to-answer: on answer, push a new `TranscriptEntry` variant `{kind:"qa", question, answer}` (question text + the chosen label or typed text) so the Q→A persists in the conversation right where the prompt was. The live dialog then disappears (pendingQuestion cleared).

TESTS:
- useAgentStore.test.ts:179 has a `user_question` reducer test (asserts pendingQuestion shape + cleared on `started`). Must stay green; add a test for the new qa transcript entry on answer.
- ipc-contract.test.ts:210 asserts pendingQuestion shape from a fixture — keep the fixture shape (questionId/question/options) unchanged.
- No QuestionPrompt.test.ts exists today.

CONSTRAINTS:
- Windows/PowerShell; preserve line endings; doc comments on public fns (Rust) — but this is all frontend (TS), so follow existing TS style. Run `npx vitest run` + `npm run build` before marking complete.
- Plan-first is enforced; this plan is created from Complete (allowed).
