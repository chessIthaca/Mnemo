# Plan: Tool-card expanded views: file_edit diff, read_files line ranges, line-aware links

## Goal
Update the expandable tool-card views in the chat: expanding a file_edit card shows the edit's unified diff (from result.data.diff, rendered with the existing UnifiedDiffView); expanding a read_files card shows just the per-file line ranges read (parsed from the result's section headers) instead of the full file-content dump; and file links open the Files viewer at the line the read started (openFileInViewer gains a line parameter, plumbed through pendingFileOpen into SourceEditor's existing revealLine).

## Kind
implementation

## Context
Findings: (1) file_edit's Rust ToolResult carries the unified diff in data: {"diff": ...} (src/tool/agent/file_edit.rs:905, compute_diff at :103); the frontend ToolResult type (frontend/src/lib/types.ts:74-78) has data?: unknown and the tool_result event ({ kind: "tool_result"; tool_call_id; result: ToolResult }, types.ts:126) delivers it — useAgentStore.preview.test.ts:53 ("carries unifiedDiff into lastDiff on tool_result") confirms the flow. So the expanded file_edit card can render the REAL Rust-side diff via the existing UnifiedDiffView (frontend/src/components/chat/DiffView.tsx) — no backend changes. (2) read_files results (src/tool/agent/read_files.rs:364-374) are sections joined by blank lines, each headed "=== {path} (lines {first}-{last} of {total}) ===" with "(error)" and "(empty range)" variants; a possible "SYMBOL NUDGE: ..." prefix line and "... (truncated ...)" tails must be ignored by the parser. Args: files: [{path, start_line?, max_lines?}] or single-file shorthand (top-level path + start_line/max_lines). (3) SourceEditor (frontend/src/components/common/SourceEditor.tsx) already supports revealLine (1-based, scrolls after content loads, shows a :L{n} chip, no-op for markdown) — used by the Graph tab; FileViewer (frontend/src/components/views/FileViewer.tsx:198-210) consumes pendingFileOpen (string | null) via requestFileOpen/clearPendingFileOpen (useAgentStore.ts) but never passes revealLine. (4) CallDetail (frontend/src/components/chat/Message.tsx:859-953) is the expanded per-call body: pretty-JSON args + raw result output, with a tool-specific branch precedent (shell → shellCallFromArgs/parseShellOutput custom rendering). ToolCard (Message.tsx:657-857) renders header path chips built by frontend/src/lib/toolCardPaths.ts (argPaths extracts read_files files[].path; chips open via openFileInViewer/openDiffInViewer from frontend/src/lib/openFile.ts). DESIGN: file_edit success with data.diff → expanded body becomes the diff (UnifiedDiffView), replacing args JSON + raw output; failures/running keep the generic rendering (error text matters). read_files success → expanded body becomes a compact clickable per-file line-range list (path + "lines X–Y of Z" or error/empty note), replacing the full-content dump; unparseable output falls back to generic. Links open at the read line: openFileInViewer(path, line?) → store pendingFileOpen becomes {path, line} → FileViewer sets a revealLine state passed to SourceEditor (cleared on manual tree/Browse opens so a stale line never re-scrolls); read_files chips carry the spec's start_line ?? 1, expanded rows carry the parsed actual first line. Pure helpers go in a new frontend/src/lib/toolCallDetail.ts with vitest tests (project test commands: npm test in frontend/, cargo test at root — no Rust changes expected).
