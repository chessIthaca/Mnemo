# Plan: The live-incumbent attach test uses a child that really stays alive

## Goal
mnemo2::project::tests::attach_requires_confirmation_for_a_live_incumbent passes reliably in the full suite, because its "live incumbent" process stays running for the whole test.

## Kind
bug_fixing

## Context
ROOT CAUSE (probed while planning):
- verified: the test (src-tauri/src/mnemo2/project.rs ~line 605) spawns `cmd /c timeout /t 5` on Windows as the "live incumbent". `timeout` exits at once when stdin is redirected (a worker measured ~163 ms), so the child can be gone before the asserts run.
- verified: since pid_alive was corrected to check GetExitCodeProcess == STILL_ACTIVE (src-tauri/src/instance_marker.rs), an exited child correctly reads as dead, so the expected conflict disappears. Before that fix the bug was hidden because an exited process with a held handle read as alive.
- verified: running the test alone passed 3/3 on 2026-11-01; failures appear under full-suite load.

FIX: spawn a child that genuinely stays alive and does not depend on stdin. On Windows use `ping -n 30 127.0.0.1` (output to null) or `powershell -NoProfile -Command Start-Sleep 30`; keep `sleep 30` elsewhere. Kill and wait for the child at the end of the test (also on assert failure, via a guard), so no process is left behind.

REGRESSION TEST: the test itself, `attach_requires_confirmation_for_a_live_incumbent`; it must pass 10 runs in a row in the full mnemo2 suite.
