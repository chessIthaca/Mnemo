# Plan: Split reasoning from completion: parser coverage, reasoning phase + timing, dual-channel reasoning box

## Goal
Split reasoning from completion end-to-end so thinking is always visible and correctly timed: (1) the SSE chunk parser recognizes delta.reasoning and inline <think>…</think> content in addition to delta.reasoning_content; (2) the inflight phase machine distinguishes "reasoning…" from "answering…"; (3) the trace record measures reasoning_ms (first reasoning delta → first content/tool delta) and the Trace-tab phase chart shows a purple reasoning segment; (4) the reasoning box displays both the thinking and the answer as they stream. Same branch: fix/git-action-subcommand-forgiving.

## Kind
implementation

## Context
User report: in the new Trace-tab phase stats, reasoning time is invisible — it lands in send/wait/generate — and reasoning text often isn't displayed at all. Root causes found: (1) parse_sse_chunk (src/provider/openai.rs:1344) recognizes ONLY delta.reasoning_content; providers also emit delta.reasoning (Fireworks/OpenRouter style) or inline <think>...</think> inside delta.content (Ollama-served thinking models) — those stream invisibly (counted in usage.reasoning, never shown). (2) The phase machine (turn.rs ~773-858) has a single one-shot Waiting→Streaming flip on any content-bearing delta; unparsed reasoning leaves the bar stuck in "waiting…" looking like a fat send. (3) The trace record (src/provider/trace.rs LlmRequestRecord/LlmRequestSummary) has no reasoning-time field; the phase chart (frontend/src/lib/traceStats.ts + components/views/TraceStats.tsx) stacks prep/compact/send/wait/generate/tools only. (4) The reasoning box (InflightBar activity log, kinds reasoning/error/info) shows only reasoning; streamed answer text (text_delta) never appears there. User decision (ask_user): FULL split — new reasoning phase + reasoning_ms timing in the trace record + both channels in the reasoning box + parser learns the variants. NOTE on attribution limits: send_ms = POST→headers; if a gateway delays headers while the model thinks, that window is genuinely unobservable client-side — the new reasoning_ms covers first-chunk→first-content, which is where SSE providers actually stream thinking. STAY ON BRANCH fix/git-action-subcommand-forgiving (user explicit); the branch already contains the committed forgiving-git work (2bebfc3). Key mechanics: PhaseKind is mapped to wire strings in src/runtime/channels.rs (~1066: sending/compacting/waiting/streaming/running_tools); frontend TurnPhase union in frontend/src/lib/types.ts; InflightBar phaseLabel switch is exhaustive (TS forces the new case); agent phase-sequence tests exist at src/agent/tests.rs:721-727; openai stream loop enriches Usage with ttft/generation at ~862-909 and mirrors via log.set_usage(id, usage, ttft, generation, Some(send)) ~888-900; anthropic.rs has a parallel stream loop (~801-997) that maps thinking_delta→ReasoningDelta (~495); reasoning text is accumulated in turn.rs reasoning_text and echoed back on assistant messages (DeepSeek 400 requirement) — tag-extracted reasoning flows through the same path unchanged.
