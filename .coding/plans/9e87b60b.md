# Plan: Tool activity says what a command is for, not "Using Bash"

## Goal
Wherever Mnemo2 shows a running or finished tool call (the worker's live status line, collapsed tool rows, grouped runs), it says what the call is for: "Running tests", "Building the app", "Reading agent_watch.rs", never "Using Bash" or "Running shell…".

## Kind
implementation

## Context
WHY (user, 2026-11-23): Mission Control shows "Using Bash" for Claude Code agent workers; the user wants the reason instead ("Running tests", "running creation script", whatever helps a human).

DECISIONS (exact phrases):
1. Claude Code tools in actionPhrase:
   - Bash / PowerShell: the `description`, turned into a gerund sentence: if its first word (case-insensitive) is a known imperative verb, replace it with the -ing form and keep the rest ("Run the workspace tests" → "Running the workspace tests"); map at least run, build, check, list, show, install, create, remove, delete, find, read, start, stop, count, compare, commit, format, test, search, print, copy, move, update, write, fetch, open, verify, confirm, inspect, get, look, time, wait, rebuild, clean, kill, launch, measure, view, diff, rerun, re-run (re-run → Re-running). Otherwise use the description as written, first letter capitalized. Without a description, use rule 3 on `command`.
   - Read → "Reading <basename>"; Edit, MultiEdit → "Editing <basename>"; Write → "Writing <basename>"; NotebookEdit → "Editing <basename>"; Grep → `Searching for "<pattern>"` (+ ` in <glob>` when glob is set); Glob → `Finding files matching <pattern>`; WebFetch → "Fetching <host>"; WebSearch → `Searching the web for "<query>"`; TodoWrite → "Updating its task list"; Task / Agent → "Starting a helper agent" + `: <description>` when set; ToolSearch → "Loading tools".
   - `mcp__plugin_mnemo_mnemo__<tool>`: the phrase Mnemo already has for `<tool>` (strip the prefix, reuse actionPhrase/teamPhrase); other `mcp__<server>__<tool>`: "Using <tool> (<server>)" with underscores as spaces.
2. Mnemo `shell` (and `job`) keep their `purpose`; without one, rule 3 on `command`.
3. A phrase from a bare command (first program token, its path and .exe dropped; look past `cd x &&`/`;` prefixes and env assignments): tests (`cargo test`, `npm test`, `npm run test`, `npx vitest`, `pytest`, `go test`, `dotnet test`) → "Running tests"; builds (`cargo build`, `npm run build*`, `npx vite build`, `tsc -b`, `dotnet build`) → "Building"; checks (`cargo clippy`, `cargo check`, `npm run check`, `npm run lint`, `eslint`, `tsc --noEmit`) → "Checking the code"; formatters (`cargo fmt`, `prettier`) → "Formatting code"; `npm ci`/`npm install`/`pnpm install` → "Installing dependencies"; `git <sub>` → the existing git verb map ("Committing", "Checking git status", …); `node|python|py|bash|sh|pwsh|powershell <script>` → "Running <script basename>"; anything else → "Running <program>".
4. The live status line shows the running call's phrase: WorkerActivity gains `toolArgs: string | null` (the call's argument JSON when the tool-start payload carries it, otherwise null), and toolPhaseLabel uses `toolSummary(toolName, toolArgs ?? "")`; its "Running <toolName>…" fallback applies only when no phrase exists. Phrases end with "…" on the status line as today.
5. Phrases are clamped by the existing compactHeadline; tool-card bodies (the expanded view) are unchanged.

VERIFY: `npm test --workspace mnemo2`; `npm run check --workspace mnemo2`.

- A Mnemo worker's shell call with purpose 'building game' shows 'Building game…' on its live status line instead of 'Running shell…'.
