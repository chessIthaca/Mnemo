# Plan: Lead review_fix rounds no longer count as a worker failing to fix a finding

## Goal
The repeated-finding escalation only fires when the worker actually had a turn between the two reviews in which the finding stayed open; lead review_fix rounds and back-to-back reviews never count as a worker failure.

## Kind
bug_fixing

## Context
ROOT CAUSE: src-tauri/src/mnemo2/team/review.rs `review` computes `repeated` (around line 93) as: review_rounds+1 >= 2 and some finding is open in both the previous and the new finding list. Nothing checks whether the worker worked in between. review_fix (same file, around line 285) commits the lead's edit, marks one finding fixed and clears review and checks, so the lead re-reviews with the remaining findings still open, and each such re-review looks like a failed worker round.
FIX INTENT: remember the worker's turn count when a review is recorded, and count a finding as "stayed open" only if the worker's turn count has grown since the previous review. WorkerRecord (team/record.rs) has `turns: u32` (around line 272) and `review_rounds` (around line 309). Persisted records written before this change must still decode (serde default) and must not suddenly escalate: treat a missing value as "unknown" and do not fire on it.
Leave untouched: the route_fix trigger (fixer_finding_id) and the audit trigger, which already depend on a worker fix round; the escalation's wording and auto-switch path.
REGRESSION TEST (src-tauri/src/mnemo2/team/tests.rs): `lead_review_fix_rounds_do_not_escalate` — review with two open findings, review_fix one, re-review with the other still open, all without a worker turn: no nudge is sent and the worker's tier and model are unchanged (fails on today's code). Keep or add `finding_open_after_a_worker_turn_still_escalates` — a worker turn happens between the two reviews and the nudge fires as before.
VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::`, `cargo clippy -p mnemo-app --all-targets --features mnemo2`, `git diff --check`.
