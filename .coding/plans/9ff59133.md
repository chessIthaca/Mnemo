# Plan: Clamp startup window-geometry restore: min size + fully on-screen

## Goal
At startup, Mnemo's restore of the persisted window geometry clamps the restored size to a minimum (800×560 logical, mirroring main.rs min_inner_size) and to the anchor monitor's work area, and adjusts the position so the window shows fully on screen. Interactive resize behavior and the Rust-side min_inner_size are untouched — the clamp applies only to the startup restore.

Landed design — 2027-01-14 (review round 1: 0 high / 8 low, all fixed). Architecture: the startup restore in frontend/src/App.tsx (mount effect) delegates the whole geometry decision to a new pure module frontend/src/lib/windowRestore.ts — clampRestoredGeometry({saved, factor, monitors, chrome, minOverlapPx?}) → {width, height, x: number|null, y: number|null}, all logical px. Unit convention (the load-bearing decision): the save path stores OUTER bounds in logical px while setSize applies an INNER (client) size that tao expands to the frame — tao has no outer-size setter — so the restore measures chrome = outerSize() − innerSize() and subtracts it (inner = savedOuter − chrome); the 800×560 minimum (mirroring main.rs min_inner_size) is applied in inner units, so the chrome is never double-subtracted. Anchor split: the SIZING anchor is the monitor with the largest positive overlap of the saved rect (falling back to the best overlap overall when none clears the gate, so an off-screen save still gets a work-area bound); the POSITION anchor must clear the usability gate (MIN_VISIBLE_PX = 80 logical px on both axes, compared as 80 × factor physical — exact parity with the pre-clamp gate). When no monitor clears the gate the clamped window is CENTERED in the sizing anchor's work area (the OS default origin comes from the initial 1200×720 window and can clip the clamped size); x/y are null only when NO monitor is known. Invariants to preserve: (1) startup-only — nothing here constrains interactive resizing (the Rust min_inner_size stays authoritative; the helper is called exactly once, from the mount restore, and the resize listeners / debounced save / beforeunload path are untouched); (2) every probe degrades independently — factor → 1 (also guarding a resolved 0/NaN), monitors → [] (the size is then bounded by the MINIMUM ONLY, never shrunk), chrome → {0,0}; (3) each monitor's own scaleFactor is deliberately NOT consulted — the saved rect uses the window's factor, the pre-clamp approximation, pinned by the mixed-DPI case; (4) fully visible geometries pass through unchanged. Round-1 findings fixed: L1 drift direction corrected (the window would GROW by the chrome, not shrink, because tao expands an inner request to the frame), L2 centering fallback, L3 gate parity ×factor, L4 minOverlapPx pinned by a test, L5 factor guard, L6 no-shrink on an unavailable monitor list, L7 seven new cases + the two pin nits (the setMinSize check is scoped to the restore block; an exactly-one-call assertion replaces the near-vacuous pin), L8 this amendment. Skipped: L7.7 (marked optional) — pinning the mirrored 800×560 against src-tauri/src/main.rs would need a cross-root ?raw import plus a vite fs.allow escape for a constant documented in three places; the mirror is now explicitly documented as prose-only in the module. ## Bug
At startup Mnemo restores the persisted window size/position verbatim: the user observed a tiny window at the top-left of the screen. The OS-level min_inner_size (main.rs:244) does not constrain the restore's programmatic setSize() (frontend/src/App.tsx:524), and the position gate (≥80px overlap on any monitor) passes near-origin rects — a saved geometry from a different monitor/DPI (e.g. RDP resolution change) restores unusably small and mispositioned. Root cause: no clamp in the startup restore path (frontend/src/App.tsx:478-531), plus outer/inner size asymmetry causing cross-restart drift.
