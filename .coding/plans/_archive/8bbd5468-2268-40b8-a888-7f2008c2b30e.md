# Plan: Fix: thread session_id into run_turn so consolidation isn't a no-op

## Goal
Thread the memory session_id from AgentTask through AgentLoop::run_turn into record_tool_event, so working-memory events are tagged with their session and consolidation actually has events to consolidate.

## Context
Code review of commits 20f2a92 (memory wiring) and 5cceeb8 (Complete-state tools) found a bug in the memory wiring: AgentLoop::run_turn records every tool event via record_tool_event(None, ...) — the session_id is hardcoded to None. But consolidate_session filters working memories by source_session_ids containing the session_id, so with None the filter matches nothing and consolidation returns early as a no-op. The plan doc itself noted "None // session_id — set in Part 4" but Part 4 (AgentTask session lifecycle) never threaded the session_id back into run_turn. Fix: add a session_id: Option<&str> parameter to run_turn, pass it through to record_tool_event, and have AgentTask::run pass self.session_id.as_deref(). Add a test that verifies the session_id is recorded.

## Steps
- [ ] 1. Add `session_id: Option<&str>` parameter to `AgentLoop::run_turn` and pass it to `record_tool_event` instead of the hardcoded `None`.
- [ ] 2. Update `AgentTask::run` (src/runtime/agent.rs) to pass `self.session_id.as_deref()` into `run_turn`.
- [ ] 3. Update all existing test call sites of `run_turn` (5 in src/agent/mod.rs, 2 in tests/workflow_integration.rs) to pass `None`.
- [ ] 4. Add a test in src/agent/mod.rs that runs a turn with a real in-memory MemoryStore + a tool call, passing `Some("test-session")`, then verifies a working-memory event was recorded with that session_id.
- [ ] 5. Run `cargo test` and ensure all tests pass.
