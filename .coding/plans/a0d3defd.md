# Plan: Un-inline run-all dispatch from the event forwarder (perf review L2)

## Goal
Fire the run-all resolution→dispatch continuations (on_spawned_turn_resolved / on_main_turn_resolved) via tokio::spawn instead of awaiting them inline in the event forwarder, so the forwarder returns to recv() immediately and every agent's events keep flowing while dispatch/landing work (git checkpoints, embedder recall, worktree provisioning, landings) runs during a parallel run-all.

## Kind
bug_fixing

## Context
Root cause: src-tauri/src/ipc/events.rs::spawn (the forwarder, :332-942) awaits the resolution→dispatch continuations INLINE at six sites — error arm spawned-lane :651-660, error arm main :672-680, finished spawned Success :716-725 / Failure :728-737, finished main Success :744-752 / Failure :755-763 — and the two deferred-flush helpers the loop calls (child-finished arm :774-781, Exited arm :828-834) do the same inside (try_flush_deferred_main_resolution :1339-1347 / :1361-1369; try_flush_deferred_spawned_resolutions :1416-1425 / :1437-1446). The locks are correct (double-dispatch + serialized-landing protection); the defect is WHO awaits them — the one task that must keep pumping events.

Fix: new private helper spawn_resolution_continuation(fut) in events.rs wrapping tokio::spawn (precedent: run_all.rs:6064 already spawns compact_then_dispatch_next on this exact contract, so dispatch already runs concurrently with the forwarder today). Latch consumption (on_finished / on_final_error / flush_deferred_main_failure), the wf_complete gate, and remark_pending_finished stay INLINE. LANDING_LOCK/DISPATCH_LOCK untouched. Exited-arm drains (drain_run_all_on_main_exit / drain_spawned_on_exit) stay inline — out of scope (crash/cancel recovery, not the steady-state resolution→dispatch path).

Existing source-contract tests pinning events.rs stay green UNCHANGED: run_all.rs:1199 events.contains("on_spawned_turn_resolved(") (call remains, inside the spawned block); :1298-1319 try_flush interleaving [lane, main, lane, main] (flush call sites untouched); :1332 owns_spawned_run(&app, agent_id).await count >= 4; :2607/:2822/:3169/:3194 pins untouched. ## Bug
During a parallel run-all, the single event-forwarder task stops recv()-ing from the bounded fan-in channel (capacity 256, src/runtime/mod.rs:38) while it awaits turn-resolution→dispatch work inline — git checkpoint commits, embedder recall round-trips, worktree checkout/branch-fork provisioning (tens of seconds when multiple lanes provision), and serialized landings. The channel fills; every agent's fanin_tx.send(...).await blocks; mid-stream lanes stall (TCP backpressure, stall_ms accumulates); the UI shows nothing app-wide. No data is lost — everything freezes. (2027-01-09 perf review, finding L2 / executive-summary BUG 3, HIGH, run-all scoped.)
