# Plan: Budget layer — spend caps, pause, spend ledger, per-plan cost report (backlog a25a5323)

## Goal
Ship the deterministic budget layer (backlog a25a5323, cost-saving chain item 4): (1) `[general.budget]` config — enabled flag, max_tokens_per_plan u64 (0 = off), max_escalations_per_plan u32 (default 1), max_retries_per_lane u32 (default 3), following the OptimizerConfig/RoutingConfig section conventions; (2) a per-decision spend ledger — a `spend_events` table beside `savings_events` in the same DB layer, one row per main plan request written by the turn layer with the ladder's attribution (turn_id, plan_id, step_index, lane, model, tokens in/out, cached_tokens, reason route|retry|escalate plus documented default|verify extensions) so the bill traces to a decision; (3) cap behavior — on a cap reached the harness PAUSES the plan via a pending UserQuestion (the ask_user channel, never a hard kill; answers: bypass for this plan / double the token cap / end the turn — the plan stays Executing and resumable), with max_retries_per_lane enforced where the ladder retries (the failed-cycle re-run) and escalations counted on enforced arms; (4) a per-plan cost report appended to `.coding/plans/<id>.md` at finish — lane used per step, tokens per lane, retries, escalations + reasons, deterministic checks with results, cache hits — REAL numbers only, NO counterfactual column; (5) a Settings budget section (toggle + three numbers) that round-trips. Invariants: budget off = exactly today's behavior (no rows gated on it, no caps fired); counters never fabricate numbers; no new dependencies; multi-platform neutral.

DESIGN DECISIONS (decided, rationale):
- Pause = a pending UserQuestion + the turn awaiting it (the ask_user mirror); NO new WorkflowState::Paused variant — the state machine + UI reducer is a large surface, and the item's own rationale (plans are crash-resumable; the plan file is the resumption doc) is satisfied by the plan staying Executing while the question pends. Never hard-kill. Answers: [Continue — pause budget checks for this plan] (bypass), [Double the token cap and continue] (override = 2× cap), [End the turn — the plan stays paused] (early-exit, plan resumable); freeform = bypass (the human spoke); channel-closed/Interrupt/Cancel = end the turn safely. In unattended runs an unanswered question pends by design; budget defaults OFF.
- Ledger rows are written for every MAIN plan request while a plan is active (plan_id NOT NULL), INDEPENDENT of budget.enabled — the bill is the plan's audit trail and the report's source; enabled gates only the caps. Summarize/compaction requests stay session-scoped in request_stats (no spend rows).
- Reason set = route|retry|escalate per the item PLUS documented extensions: 'default' (plan requests with no lane decision — the token cap must count ALL plan requests) and 'verify' (deterministic-check evidence rows carrying the compact outcome in detail, so the report cites real results; tool-recorded rows may NULL turn_id). Documented in the schema comment.
- Counters live on the loop (PlanSpend keyed by plan id, reset on plan change): tokens updated inline at the spend-write site (gate reads fresh numbers), escalations counted on enforced arm at the gate, retries counted at the gate via the pending-retry flag note_lane_escalation sets (applies to the step that runs next). In-memory = live-session enforcement; a crash-resume restarts the count while the durable ledger still backs the report — documented boundary.
- Report: REAL numbers only — NO counterfactual "vs single-model baseline" column (rejected in the DECISION memory). Savings cited as cached-token hits from the plan's spend rows; savings_events is session-scoped (not plan-scoped) — boundary documented in the report header. Fail-open at finish: a report failure logs and never blocks completion.
- turn_id on spend rows: the pre-prompt route's turn_id when present, else model_routing::new_turn_id generated once per turn (held on TurnState so iterations share it).
- No new dependencies; multi-platform neutral; no hardcoded vendor models anywhere.
