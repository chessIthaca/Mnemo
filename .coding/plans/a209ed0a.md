# Plan: Ship the mnemo-workers mod with the mnemo plugin

## Goal
"Connect Claude Code" in Mnemo2 installs the mnemo-workers mod (the worker band above the prompt) together with the mnemo plugin, and a source checkout's `mnemo` marketplace offers it too, so nobody has to set CLAUDE_CODE_PLUGIN_DIRS.

## Kind
implementation

## Context
WHY: the mnemo-workers mod (mnemo2/claude-desktop-mod/mnemo-workers: .claude-plugin/plugin.json, hooks/hooks.json, hooks/register.tsx, types/index.d.ts, README.md, tests/) is only usable today through CLAUDE_CODE_PLUGIN_DIRS or --plugin-dir. The user wants it installed together with mnemo.

TODAY:
- Repo root `.claude-plugin/marketplace.json` is the `mnemo` marketplace developers register from a source checkout (the user's own Claude Code points its `mnemo` marketplace at C:\Mnemo). It lists one plugin, `mnemo`, source `./mnemo2/plugin`.
- src-tauri/src/mnemo2/claude_code.rs: `PLUGIN_FILES` embeds mnemo2/plugin with include_str!; `MARKETPLACE_JSON` (one plugin `mnemo`, source `./plugin`); `install_bundled` writes `<config>/claude-plugin/.claude-plugin/marketplace.json` and the plugin under `<config>/claude-plugin/plugin/`; `plugin_state(list_json)` finds `mnemo@mnemo` in `claude plugin list --json`; `ClaudeCodeStatus` has `plugin_installed`/`plugin_version`; `connect_plan(marketplace, plugin_installed, plugin_dir)` returns the `claude` commands (marketplace add/update, then `plugin install|update mnemo@mnemo`); a marketplace in state `Other` (a source checkout) gets an empty plan and is left alone; test `embedded_plugin_covers_every_plugin_file` keeps PLUGIN_FILES complete.

DECISIONS:
- Plugin name `mnemo-workers`, installed as `mnemo-workers@mnemo` from the same `mnemo` marketplace. Description in both marketplace files: "Shows the running Mnemo2 workers and their models above the prompt in Claude Desktop's Code tab; click a worker to open it in mission control."
- Repo marketplace source: `./mnemo2/claude-desktop-mod/mnemo-workers`. Generated marketplace source: `./mnemo-workers`, written to `<config>/claude-plugin/mnemo-workers/`.
- Embed the mod's shipped files only (plugin.json, hooks/hooks.json, hooks/register.tsx, types/index.d.ts, README.md); never tests/.
- The `Other` (source checkout) rule stays: Connect still leaves a developer's marketplace alone; such a user installs with `claude plugin install mnemo-workers@mnemo` once.
- No Settings UI change: the status gains a `workers_installed` field the UI may ignore.
- The band only appears in a new or restarted Claude Code session; the README says so.

VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib claude_code`, then `cargo test --workspace` and `cargo clippy --workspace --all-targets` warning-free. If the `claude` CLI is on PATH, also run `claude plugin validate .` at the checkout root and report the output (do not install anything).

## Acceptance scenarios
- After a Mnemo2 start, `<config>/claude-plugin/.claude-plugin/marketplace.json` lists `mnemo` and `mnemo-workers`, and `<config>/claude-plugin/mnemo-workers/` holds the mod's shipped files (no tests).
- Connect on a machine with no `mnemo` marketplace runs: marketplace add, install mnemo@mnemo, install mnemo-workers@mnemo; with both installed it runs marketplace update and updates both.
- The repo's `.claude-plugin/marketplace.json` offers `mnemo-workers` from `./mnemo2/claude-desktop-mod/mnemo-workers`, so `claude plugin install mnemo-workers@mnemo` works from a source checkout.
