# Plan: Mnemo owns the life of a worker it hands to a Claude Code agent

## Goal
A step that Mnemo hands to a Claude Code agent never looks stuck and never stays in an odd state. It shows "waiting for its Claude Code agent" until the agent is launched, Mnemo finishes the worker itself when the agent ends, and a worker whose lead left without (or while) running its agent goes back to an ordinary resumable state.

## Kind
implementation

## Context
WHY (user, 2026-11-23): when a step lands on a tier that runs as a Claude Code agent (dispatch, team_resume, auto escalation or a usage-limit resume; src-tauri/src/mnemo2/team/control.rs `hand_to_agent_locked` ~:600 and the dispatch path in spawn.rs/dispatch.rs), the worker record goes straight to `Working` with `claude_agent` set and no session. Until the lead launches its Agent, team_status and Mission Control show a working worker with nothing behind it; a lead in another project read it as stuck. The user: Mnemo moved the work to Claude, so Mnemo has to keep that item clean itself, so the lead does not have to, and today these items "stay in an odd state".

DECISIONS:
1. Visible phase (derived, never persisted in team.json): every worker JSON that team_status and the window receive carries `agent_phase`: "awaiting_launch" (waits_for_agent), "running" (registered, not finished, not stalled), "stalled", "finished" (registered and its transcript says finished but the worker is still Working/Fixing for a moment), or absent/null for a worker that is not a Claude Code agent worker. team_status's compact entry shows it too.
2. Mnemo finishes the worker itself: when agent_watch sees a registered agent's transcript finished while the worker is Working or Fixing, it calls the same completion as `agent_done` with failed=false and report = the agent's last assistant text from its transcript (agent_log), or "The Claude Code agent finished without a final message." when there is none. The lead then gets the ordinary "finished its turn" notice (with the report), not "call team_agent_done". `team_agent_done` stays: called on a worker Mnemo already finished for the same agent run (same generation and turns as the auto-finish; an in-memory marker is enough, a restart may forget it) it succeeds without a second notice and replaces the report with the lead's when the lead's is non-empty; with failed=true it marks the worker Failed as today. Otherwise its behaviour is unchanged.
3. Lead leaves: when the external lead detaches (session end or idle-out) or Mnemo2 starts with no external lead attached, every agent worker that is still awaiting_launch, or whose agent is stalled, is handed back: `claude_agent`, `claude_agent_effort` and `claude_agent_id` are cleared, status becomes Interrupted, error = "Its Claude Code lead left before the agent finished; resume it to continue on a Mnemo model." Record, branch, checkout, commits, findings and review history stay. It is then an ordinary interrupted Mnemo worker: team_resume (or Mission Control's resume) restarts it on its tier's Mnemo models; when a Claude Code lead later resumes it onto an agent tier, the existing hand-off applies. A running (not stalled) agent is left alone: its transcript may still be written.
4. Mission Control (mnemo2/src) shows the phase on the worker's status line: awaiting_launch → "Waiting for Claude Code agent", running → "Claude Code agent running", stalled → "Claude Code agent silent for 10+ min". A worker without agent_phase renders exactly as today.

## Acceptance scenarios
- Right after a dispatch lands on an agent tier, team_status and Mission Control show the worker as waiting for its Claude Code agent, not plain working.
- When the agent ends, the worker becomes Completed with the agent's last message as its report and the lead gets one 'finished its turn' notice, without calling team_agent_done.
- When the Claude Code lead leaves before launching the agent, or while its agent is stalled, the worker becomes Interrupted with a clear reason, keeps its branch and commits, and can be resumed on a Mnemo model.

## Spec changes

### external-lead

#### ADDED Requirements

##### Requirement: Agent workers are handed back when their lead leaves
When the external lead detaches, or Mnemo2 starts without one, every agent worker whose agent was never launched or has stalled SHALL be handed back: it stops being an agent worker, becomes interrupted with the reason, keeps its record, branch, checkout and commits, and can be resumed on a Mnemo model. An agent that is still running SHALL be left alone.

###### Scenario: Lead leaves before launching
- **WHEN** an agent worker waits for its agent
- **WHEN** the external lead detaches
- **THEN** the worker is interrupted with the reason and is no longer an agent worker
- **AND** team_resume restarts it on its tier's Mnemo model with its branch and commits

###### Scenario: Running agent survives a detach
- **WHEN** an agent worker's agent is running and not stalled
- **WHEN** the external lead detaches
- **THEN** the worker stays an agent worker and keeps working

#### MODIFIED Requirements

##### Requirement: The lead finishes a Claude Code agent worker
A worker handed to a Claude Code agent SHALL be finished by Mnemo when its registered agent's transcript says it finished, with the agent's last message as its report, marking the worker completed and delivering the finished notice to the external lead. The lead MAY still call team_agent_done to report a failed run or to replace the report; after Mnemo finished the same run it SHALL NOT deliver a second notice. While such a worker is working, the agent gate SHALL allow the lead's Agent calls without asking.

###### Scenario: Agent worker reaches review
- **WHEN** the lead's agent committed in the worker's worktree
- **WHEN** the agent's transcript says it finished
- **THEN** the worker is completed with the agent's last message as its report
- **AND** one finished notice reaches the lead
- **AND** team_check, team_review and team_merge work as for any worker

###### Scenario: Lead reports after Mnemo finished the run
- **WHEN** Mnemo finished an agent worker's run
- **WHEN** the lead calls team_agent_done with a report for that run
- **THEN** the worker keeps its completed state with the lead's report
- **AND** no second finished notice is sent

###### Scenario: Gate lets the agent run
- **WHEN** an agent-tier worker is working
- **WHEN** the gate-agent hook asks about subagent_type general-purpose
- **THEN** the decision is allow

##### Requirement: Agent workers are observable
Every Claude Code agent worker SHALL show its agent phase (awaiting_launch, running, stalled or finished) in team_status and Mission Control from the moment it is handed to an agent. The lead SHALL be able to register a running Claude Code agent for a worker with team_agent_started. Mnemo SHALL then report the agent's transcript, last activity, tool calls, tokens and finish state in team_status, flag it stalled after ten silent minutes and notify the lead once per stall. The agent MAY post progress notes with team_progress, which land in the worker's log and as notices.

###### Scenario: Agent not launched yet
- **WHEN** a dispatch lands on a tier that runs as a Claude Code agent
- **WHEN** the lead has not launched the agent
- **THEN** team_status and Mission Control show the worker waiting for its Claude Code agent

###### Scenario: Stalled agent
- **WHEN** an agent worker is registered
- **WHEN** its transcript has not changed for ten minutes
- **THEN** team_status shows it stalled
- **AND** the lead gets one notice

###### Scenario: Progress note
- **WHEN** the agent calls team_progress with a note
- **THEN** the note is in the worker's log and reaches the lead
