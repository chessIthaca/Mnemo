# Plan: Unified interrupt/cancel/steer safe-stop propagation

## Goal
Make Interrupt, Cancel, and Steer all flow through the same "find a safe stopping point" pattern. Currently only Steer (soft_stop) propagates correctly; Interrupt/Cancel are consumed at the detection point and mapped to a tool error, so the turn continues (Bug 1) or the agent stays alive (Bug 2). Fix all 5 bugs: (1) Interrupt/Cancel during approval denies one tool, turn continues; (2) Cancel during streaming doesn't exit the agent; (3) no interrupt check between tool calls; (4) tool execution has no interrupt check; (5) complete_with_retry has no interrupt check.

## Kind
implementation

## Context
Design: introduce a `StopReason` enum (Steer(String) | Interrupt | Cancel) that replaces the three separate variables (soft_stop: bool, pending_steer_text: Option<String>, interrupted: bool) in run_turn. TurnOutcome.pending_steer becomes stop_reason: Option<StopReason>. ApprovalOutcome gains a Cancelled variant (split from Interrupted). execute_tool_call gains a stop_signal: &mut Option<StopReason> parameter. summarize_with_interrupt returns Option<StopReason>. run_turn_with_retry returns bool (cancelled). AgentTask::run breaks on cancel (Exited fires). Mid-tool interrupt wraps tools.dispatch() in a pinned select! loop (drop-safe for shell via kill_on_drop; git needs kill_on_drop added; spawn_blocking tasks complete in background). complete_with_retry wrapped in a pinned select! loop. Between-tool-call try_recv safe point + synthesized "not run" results for un-run tools in a partial batch (message consistency: N tool calls → N tool results).
