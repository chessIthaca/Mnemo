# Plan: Land jsdom 31 for Mnemo2's tests

## Goal
Mnemo2's vitest suite runs on jsdom 31, so Dependabot PR #110 (jsdom 30.1.3 → 31.0.0) is no longer needed and Dependabot closes it once this reaches main.

## Kind
implementation

## Context
WHY: Dependabot PR #110 bumps mnemo2's devDependency jsdom ^30.1.3 → ^31.0.0. It was left out of the Dependabot batch (PR #116, merged into main and then into wt/mnemo as c317165c) because it breaks Mnemo2's tests in two ways. PR CI runs only CodeQL, so GitHub showed it green anyway.

PROBLEM 1, lockfile placement: Dependabot's package-lock.json puts jsdom at "mnemo2/node_modules/jsdom". vitest is hoisted to the root node_modules and imports 'jsdom' from there, so it cannot see a nested copy: every mnemo2 test file fails with "Cannot find package 'jsdom'" (ERR_MODULE_NOT_FOUND). With jsdom at "node_modules/jsdom" (root), the suite runs.

PROBLEM 2, getComputedStyle now resolves var(): jsdom 30 returned the raw declared text "var(--token)" from getComputedStyle. jsdom 31 substitutes custom properties. A token with no definition makes the property invalid at computed-value time, so it falls back to the inherited or initial value. In the tests no token is defined: app.css (where the tokens live on :root) is not imported by any test; fixtures.ts and theme.ts only mention it in text. So six assertions that expect the literal "var(--…)" text fail:
- LeadChat.test.ts:645 (fontSize "var(--text-body)")
- WorkerRow.test.ts:42-44 and :81 (--font-ui, --text-meta, --muted)
- WorkerThread.test.ts:94, :132 and :139 (--danger, --muted)

Probe with jsdom 31.0.0 (lead, 2026-11-11). A stylesheet rule `.a { font-family: var(--font-ui); font-size: var(--text-meta); color: var(--muted) }` computes to monospace / 16px / rgb(0, 0, 0) with no tokens. After document.documentElement.style.setProperty("--font-ui","sentinel-ui"), ("--text-meta","17px") and ("--muted","rgb(1, 2, 3)") it computes to "sentinel-ui" / "17px" / "rgb(1, 2, 3)". A `.p { font-size: var(--text-body); max-width: 100ch }` with --text-body 13px computes max-width "650px": 1ch = 0.5em in jsdom. removeProperty restores the defaults.

DECISION: tests prove a component uses a design token by defining a sentinel value for that token on :root (inline style on document.documentElement) and asserting that the computed style equals the sentinel. Sentinels are values no default or inherited style can produce. They live in one shared helper, mnemo2/src/test/tokens.ts, which a test sets before rendering and removes afterwards. No component (.svelte) changes, no vitest.config.ts changes, no assertion is loosened or deleted.

CONSTRAINTS: frontend/ uses vitest environment "node" and does not use jsdom; leave it alone. Keep jsdom at the root of package-lock.json. A fresh worker worktree has no node_modules, so run `npm ci --no-audit --no-fund` at the worktree root before testing. No cargo build is needed for this plan.

VERIFY (from the worktree root): `npm test --workspace mnemo2` (all files pass), `npm run check --workspace mnemo2` (0 errors, 0 warnings), `grep -rn 'toBe("var(--' mnemo2/src` (no matches), `grep -n '"mnemo2/node_modules/jsdom"' package-lock.json` (no matches).

## Decisions
- 2026-11-11: no spec impact: Test-only change plus a devDependency bump: no component, app behavior or spec'd capability changes.
- 2026-11-11: The seventh changed assertion is WorkerRow.test.ts "puts every row's status in one fixed-width column". jsdom 31 blockifies flex items (Flexbox §4), so the .status-label pill (inline-flex inside the flex .worker-meta) computes display "flex", as browsers report too. The assertion becomes "flex", which still proves the pill is a flex container (a plain inline element would blockify to "block"). The pill's natural width is covered by the column's align-items: flex-start, which the test already asserts.
