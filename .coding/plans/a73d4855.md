# Plan: Map reasoning_effort "off" → "none" for DeepSeek-family endpoints

## Goal
Eliminate the DeepSeek instant-400 trigger and honor the user's explicit off: a literal "off" must never reach the wire, and DeepSeek-family models encode the harness's "off" as the enum's explicit "none". Policy-driven (ProviderPolicy vendor detection, ProviderKind/model aware), applied at both config resolvers and guarded at the OpenAI request builder, with failing-first regression tests at both layers.

## Kind
bug_fixing

## Context
Exploration findings (2026-12-29): The backlog item's claim that the harness "sends 'off' verbatim" is stale — both resolvers already map Some("off")→None (config_io.rs resolve_reasoning_effort :86/:101; endpoints.rs effective_reasoning_effort_for :342/:354), so no production path emits literal "off" today. The real defects: (1) the emission site openai.rs:1763 (`body["reasoning_effort"] = json!(effort)`) has NO policy guard — a hand-built or future path carrying Some("off") emits the exact 400 trigger; (2) DeepSeek-family models get the field OMITTED for "off" instead of the enum's explicit thinking-off value "none", so the user's selection is silently ignored on thinking models (provider default applies). Detection seam: ProviderPolicy::for_kind_and_model(kind, model) (src/provider/policy.rs:225) is the pure (kind, model) DeepSeek detector (model id contains "deepseek" → vendor Vendor::DeepSeek; Anthropic kind → claude policy, gated out). EndpointKind→ProviderKind conversion exists as client_factory.rs provider_kind (:61, currently private). OpenAiClientConfig carries kind: ProviderKind + model (openai.rs:91), so the builder guard is fully policy-driven. Safety against bug-1042 regression: the reasoning_content age-0 injection (openai.rs:1574-1577) consults policy.reasoning_required — a pure (kind, model) function, NOT effort-gated — so every assistant turn is already keyed on DeepSeek requests whether the effort field is present, "none", or absent; emitting "none" at most enables tail validation the injection already satisfies. Existing tests that must keep passing: resolve_reasoning_effort_off_maps_to_none (config_io.rs:367) and resolve_reasoning_effort_off_only_list_never_sends_literal_off (config_io.rs:431) — they use non-DeepSeek models and must still resolve to None. Frontend needs no change: the StatusBar dropdown label "off" is UI-only state; the configured endpoints.toml reasoning_effort value is untouched (only the resolved wire value changes).
