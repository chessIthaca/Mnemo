# Plan: Stop tripping over LF/CRLF: mixed-ending matching, eol=lf policy, new-file determinism

## Goal
Stop tripping over LF/CRLF: (a) mixed-ending files match correctly (majority-vote detection + dual-attempt fallback in file_edit), (b) the repo gets a deterministic LF policy via .gitattributes (no more autocrlf warnings), (c) new files are written LF deterministically, (d) regression tests for every fix.

## Kind
implementation

## Context
Backlog item #48 (in_flight): "tools automatically convert \n to \r\n — too often do we trip over that". VERIFIED ALREADY DONE: all agent file tools normalize caller strings to the file's detected line-ending style — file_edit literal/regex/line-range/fuzzy (src/tool/agent/file_edit.rs, tests crlf_file_matches_lf_old_string etc.), file_write overwrite preserves style, file_append chunks normalize (src/tool/agent/line_endings.rs: detect_line_ending + normalize_line_endings); FileViewer md editor normalizeForSave heals on save (shipped 2026-04-20). REMAINING GAPS = the actual trips: (1) detect_line_ending (line_endings.rs:18-24) returns CRLF if the content contains ANY "\r\n" — a mostly-LF file with one stray CRLF detects as CRLF, so multi-line literal/regex needles (normalized to CRLF) miss on the LF lines → "old_string not found". (2) No .gitattributes in the repo root + global autocrlf in effect (warnings seen 3x this session: "LF will be replaced by CRLF") → no deterministic ending policy; new files written by tools/app default to whatever the model emitted. ENV: Windows/PowerShell; cargo test unpiped (read test result: lines + $LASTEXITCODE; src-tauri is a separate package needing its own cargo test); #![deny(warnings)] both crates, doc comments on pub fns, no #[allow]. .coding/backlog.json is a PROTECTED write target for agent file tools (refuse_if_protected) — item #48 CANNOT be updated with file_edit; completion must be recorded via commit message + memory + user/UI action. DECISIONS: blanket "\n → \r\n" conversion rejected (would rewrite LF files and cause diff churn); the fix is majority-vote detection + a dual-attempt match fallback (ending-agnostic matching) + repo-level .gitattributes pinning eol=lf (overrides global autocrlf, makes LF the deterministic everywhere-ending, kills the warnings) + new files written LF for determinism. Existing tests that must stay green: line_endings.rs detect_mixed_treats_as_crlf ("a\r\nb\nc" 1v1 tie → CRLF), all crlf_* cross-style tests, file_write empty_existing_file_keeps_content_as_is, file_append creates_new_file.
