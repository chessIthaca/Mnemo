# Plan: Live check: a steered worker sends no false finished notice

## Goal
Prove on the rebuilt Mnemo2 that steering a busy worker keeps it Working and produces exactly one finished notice, after its follow-up turn really ends.

## Kind
research

## Context
Why: the fix for false finished notices has passed unit tests but has never run in the real app. A steer ends a turn with a Finished event and starts a follow-up turn; the old build read that Finished as completed and told the lead the worker was done. It reproduced live when the lead edited a plan while a worker was busy, because a plan decision steers working workers on that plan. This plan repeats that exact sequence on the rebuilt app using one throwaway worker. Constraints: the worker changes no files, makes no commit and is never merged; nothing here is meant to land. It only runs harmless shell commands, so that it is demonstrably busy inside a tool call when the steer arrives. The lead judges the result from the notices it receives and from team_status, not from anything the worker claims. Relevant code for the record: src-tauri/src/mnemo2/team.rs (pump_worker, FOLLOW_UP_GRACE, current_notices) and src-tauri/src/mnemo2/notice_tag.rs.

## Acceptance scenarios
- A plan decision recorded while the worker is inside its wait command leaves team_status at working, with no finished notice delivered for that steered turn end.
- Exactly one finished notice arrives, after the worker's follow-up turn ends, and its first line carries turn= and state=finished.

## Steps
