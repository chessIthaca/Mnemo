# Plan: Run-All checkpoint: branch guard — fork wt/* before checkpointing, never commit to main

## Goal
Run-All's pre-item checkpoint never commits to main: run_all_dispatch_next checkpoints on the per-directory wt/* working branch. A new checkpoint_on_work_branch core (ensure_work_branch → checkpoint) forks/reuses the wt/* branch before committing — matching create_plan's auto-fork semantics — and a refused fork (dirty tree outside .coding/) stops the run through the existing checkpoint-failure path (item stays Pending, reason in its note) instead of committing to main. Regression test: repo on main + dirty tree → dispatching produces no commit on main (the commit lands on wt/*).

## Bug
Run-All's pre-item checkpoint can commit directly to main (security review MEDIUM; verified). run_all_dispatch_next (src-tauri/src/ipc/run_all.rs:962-984) calls checkpoint() before dispatching the next backlog item, and checkpoint_impl (src/project/git_ops.rs:104-123) runs git add -A + git commit on whatever branch is checked out — no branch check. The per-directory wt/* auto-fork only happens later inside create_plan (ensure_work_branch, git_ops.rs:588-642). So when the session sits on main — e.g. right after merge_to_main lands a branch — the next Run-All tick commits the dirty tree (typically .coding/backlog.jsonl status flips) straight to main, violating the never-commit-to-main constitution.
