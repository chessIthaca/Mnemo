# Plan: General skill framework + rework merge-to-main onto it

## Goal
Introduce a general skill framework (file-based registry, skill_start/skill_end/abandon_skill tools, Skill workflow state with allow-list tool filter + prompt overlay) and rework merge-to-main onto it as the first skill — agent-driven, with conflict resolution, returning to Planning on success. Core git operations (merge/push) are always approval-gated via never_auto, enforcing the constitution regardless of safety mode.

## Context
DESIGN (agreed with user):
- A "skill" is a named, activatable overlay on the workflow. It runs in the main agent window — it just changes which tools are visible + what the system prompt says. Normal security controls (the approval gate, per safety mode) apply to every tool call inside the skill exactly as outside it.
- Registry: `.coding/skills/<name>.toml` — name, available_in (states), target_state, tools (allow-list), prompt. Loaded at startup into a SkillRegistry. Adding a skill = dropping a file.
- skill_start(skill, skill_prompt, target_state) — skill_prompt + target_state override registry defaults; skill selects the entry (tool filter + available_in validation). Ungated (AutoRun) — protection is on the operations, not the entry.
- skill_end() — exits the skill, transitions to target_state.
- abandon_skill() — exits the skill, returns to the pre-skill state (stored on the active skill when entered). Rollback.
- No per-skill workflow_state enum variant. While a skill is active, the workflow is in a single hardcoded internal state (Skill). The skill's tools list drives the filter (an allow-list variant of ToolFilter). The frontend displays the skill name.
- HARD RULE (write into agent.md): core operations — any tool call that lands commits on main or pushes to a remote — always go through the approval gate, regardless of safety mode or active skill. Nothing bypasses the security check on core operations.
- The current `git` tool only supports status/diff/log/commit. To make the hard rule enforceable, EXTEND the git tool to cover merge/checkout/stash/branch/push as structured subcommands, with merge+push never_auto (always prompt, even in Autonomous, even inside a skill). The agent uses `git` (not `shell`) for git ops during the skill.
- merge_to_main becomes the first skill. The old atomic MergeToMainTool (which aborted on conflict) is removed — the agent resolves conflicts itself using file_edit + git during the skill.
- Both entry paths stay alive: (a) UI "Merge to main" button (Complete/Planning only) → confirm dialog IS the approval → backend enters the skill + sends a prompt to the agent telling it to drive the merge. (b) agent calls skill_start("merge_to_main", ...) directly.
- Gating: skill_start available in Complete + Planning only (not Executing). Merge button shows in Complete + Planning.
- Interrupt/steer works naturally — the skill state persists across turns + restart (persist in stack.json alongside the plan).
