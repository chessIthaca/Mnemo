# Plan: Mnemo closes an audit once its verdict is used

## Goal
An independent audit never lingers as a "completed" worker: Mnemo ends its session and closes it as soon as the lead has adjudicated it (or its target merged, was stopped or deleted), so no lead has to remember to stop audits and the window never shows a used audit as waiting for review.

## Kind
implementation

## Context
WHY (user, 2026-11-23, from another project): after an audit reported, it sat as "completed" in the window's review column until the lead stopped it by hand; that lead then adopted a working rule to stop every audit after use. The user wants Mnemo to do this itself.

Its session stays live on purpose so the lead can ask follow-ups (pump.rs `ask_audit_for_its_report` comment), and it stays `Completed` until `team_stop`. While live it holds a worker slot.

DECISIONS:
1. Close points: Mnemo closes an audit (a) when a team_review on its target is recorded with independent_reviewer_id == the audit's id (the verdict is used), or (b) when its target worker is merged, stopped, or deleted while the audit has reported. An audit that has NOT reported is never closed by (a) or (b) except deletion of the target, which stops it (it can no longer be adjudicated).
2. Closing = the same path as team_stop for the session (ends it, frees the slot), then release its pool checkout (it is read-only; nothing to keep), set status `Stopped`, keep the record (report, findings, routing) for history, and add no lead notice (the lead caused it). Idempotent; a failure is logged and never fails the review or merge that triggered it.
3. Window: a worker with kind "audit" whose report was delivered shows the status text "Audit used" when Stopped by this close and "Reported" when Completed (adjudication pending); both sit in Mission Control's Done group, never in Needs you or Active, and "Delete old workers" offers them as today.
4. Refresh check: after team_merge, team_stop and this close, the board must emit its changed signal so the window refreshes every worker's state without another event (the other lead suspected the window only reloaded merged workers when the audit was stopped). If a path does not emit it, add the emit and a test; if all do, note that in the report.

VERIFY: cargo test --workspace; cargo clippy --workspace --all-targets; npm test --workspace mnemo2; npm run check --workspace mnemo2.

## Acceptance scenarios
- After the lead records a team_review that links an audit as its independent reviewer, the audit worker is Stopped, its session and checkout are released, and Mission Control shows it under Done as 'Audit used' without anyone stopping it.
- When an audit's target merges, a reported audit is closed the same way; an audit that has not reported yet keeps running.
- After a merge, every worker's state in the window is current without any further event.
