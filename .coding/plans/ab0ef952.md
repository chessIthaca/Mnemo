# Plan: Pasted images: downscale on paste + transcript image byte budget (mem-perf LOW 4)

## Goal
Stop pasted images from being retained full-size base64 for the whole session: downscale on paste via canvas (long edge ≤1568 px, JPEG re-encode) and bound the transcript's retained image payload with a rolling byte budget (evicted images render a placeholder chip).

## Kind
implementation

## Context
Mem-perf review LOW 4 (.coding/reviews/2027-01-06-full-review-memory-perf.md): InputBar.tsx:120 reads pasted files as raw data URLs (no canvas downscale), :328 embeds them in transcript entries, and the transcript cap is entry-count only — a 4K screenshot (~5-10 MB base64) stays full-size in the zustand store AND DOM for the whole session. Key facts: capTranscript (agentState.ts:393) is the single choke point for all 13 transcript-append sites; BacklogView.tsx:75 has an identical local fileToDataUrl whose dispatched images land in the transcript via prompt_dispatched (agentEventReducer.ts:1096); the Rust provider path parses MIME from the data-URL prefix (anthropic.rs:544 image_block) so JPEG data URLs pass through unchanged — no Rust changes needed; vitest runs in node env (no DOM) so canvas code gets pure-logic + source-contract tests (established repo pattern, InputBar.test.ts), while the eviction pass is fully unit-testable. Decisions: 1568 px long-edge cap (vision-API input limit) + JPEG q0.85; 512 KiB keep-original fast path; 32 MiB rolling transcript image budget enforced inside capTranscript (newest-first retention, imagesEvicted placeholder field); graceful fallback to the original data URL on any decode/canvas failure so an image is never lost.
