# Plan: Trace log cache-hit analysis: prompt management optimization

## Goal
Analyze the LLM request trace log (.coding/logs/traces.jsonl) to quantify current cache-hit rates and identify exactly which prompt-management factors break the provider's cache prefix, then deliver a findings report with concrete optimization recommendations.

## Context
User request: review .coding/logs/traces.jsonl (LLM request traces) and analyze whether prompt management can be optimized to improve provider cache-hit rates. The trace log currently has 2 records (id 1-2, deepseek-v4-pro). Each line: {id, ts_ms, model, base_url, request_json{messages[], tools[], stream...}, usage{prompt, completion, reasoning, cached}, finish_reason, ttft_ms, generation_ms}. Request 1: prompt=6665, cached=2176 (32.6% hit). Request 2 usage needs parsing. Cache-hit depends on stable prefix: system prompt, constitution, tool schemas, and stable message order/content; volatile content (timestamps, memory blocks, plan text, changing file contents) breaks the prefix. Trace view already implements a compare-with-previous feature (frontend/src/components/views/LlmTraceView.tsx compareMessages) as a reference. This is an ANALYSIS-ONLY plan: no production code changes; deliverable is a findings report under .coding/analysis/ plus a summary to the user. Shell is gated to Executing state, which is why a plan is required.

## Steps
- [x] 1. **Parse trace log into per-request summary** — in PowerShell (project root): read .coding/logs/traces.jsonl line by line, ConvertFrom-Json each line, and for each request print a compact row: id, ts (HH:mm:ss), model, prompt, cached, hitPct=round(100*cached/prompt,1), completion, reasoning, finish_reason, ttft_ms, generation_ms, nMessages, role sequence, system-prompt length. Save the table to .coding/analysis/traces-summary.txt (New-Item -Force the dir). Also compute: overall hit%, per-request hit%, and whether hit% grows monotonically across consecutive requests.
- [x] 2. **Read the prompt-assembly code** — read src/agent/prompt.rs (system prompt + constitution injection), src/agent/context.rs (context building, summarization, memory blocks), and src/tool/mod.rs factory/tool schema construction (are tool schemas stable strings or rebuilt per turn?). Identify every element that could differ between consecutive requests: timestamps, memory recall blocks, plan file content, conversation history growth, summarization, tool descriptions. Note file paths + line numbers for each dynamic element.
- [x] 3. **Diff consecutive requests to find cache-breakers** — PowerShell: for each adjacent pair (i, i+1) in traces.jsonl, compare request_json.messages index-by-index (JSON.stringify equality per message, mirroring LlmTraceView compareMessages), print: k = length of identical leading prefix, first changed index + role, whether system message [0] is byte-identical, whether the tools array is byte-identical, and any top-level request_json field differences (stream, max_completion_tokens, etc.). Write results to .coding/analysis/traces-diff.txt.
- [x] 4. **Write the analysis report** — create .coding/analysis/cache-hit-analysis.md: current hit-rate numbers (per request + overall), the exact cache-breaking factors found (with evidence: which message/field changed and why, referencing the code locations from step 2), and ranked recommendations (e.g. keep system prompt byte-stable, move volatile content (timestamps/memory/plan) to the tail, stabilize tool schemas, avoid re-serialization drift, minify stable blocks). Distinguish what's actionable in this codebase vs. provider-side behavior. Present a short summary to the user at the end.
- [x] 5. **Commit + finish (review waived)** — per user instruction: skip the reviewer because this plan changed no source code (only .coding/analysis/ docs + bookkeeping). cargo test already ran green (726 passed). Commit the analysis artifacts to a feature branch (create feat/cache-hit-analysis), write a brief note under .coding/reviews/ documenting the review waiver (no source changes → no findings), then call finish with that note.
