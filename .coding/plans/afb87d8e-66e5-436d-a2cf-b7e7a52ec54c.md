# Plan: Unify tab style: right's underline + left's height on both sidebars

## Goal
Unify the left sidebar tool toggles and the right panel's tabs onto one style: the right's cyan light-underline active indicator, and the left's 40px (h-10) button height on both sides.

## Kind
implementation

## Context
User request (screenshot of the app, dark theme): the left sidebar tool toggles (Sidebar.tsx, icon-only h-10 w-10 buttons, active = cyan icon, no underline) look different from the right panel's tabs (RightPanel.tsx, underline indicator: border-b-2 border-cyan-500 when active, border-transparent when not) and the two sides have different heights (left 40px, right ~32px via py-2). The user wants them unified: the right's light underline style + the left's height on both sides. Visual reference: the Backlog/Plan tabs in the right panel carry the active-cyan-underline look.

Facts gathered:
- Left sidebar: frontend/src/components/layout/Sidebar.tsx lines 55-67 — per-tool toggle buttons, className `flex h-10 w-10 items-center justify-center rounded-lg transition-colors` + enabled ? "text-cyan-400 hover:bg-bg-tertiary" : "text-slate-600 line-through opacity-50 ...". The 10 toggles derive from RIGHT_PANEL_VIEWS via VIEW_BY_ID; above them sit the About button + divider, below them (mt-auto) Project/Settings/PanelRight buttons — those non-toggle buttons keep their current style (no underline; they are not tabs).
- Right panel (xfrontend/src/components/layout/RightPanel.tsx lines 55-65) — Radix TabsTrigger className `group flex items-center gap-1.5 border-b-2 px-3 py-2 text-xs font-medium transition-colors` + isActive ? "border-cyan-500 text-cyan-400" : "border-transparent text-slate-500 hover:text-slate-300".
- Both sides already derive their tabs from the single RIGHT_PANEL_VIEWS registry — no structural change needed, only className tweaks.
- No existing tests cover either component's styling (no Sidebar/RightPanel .test file); verify via npm test + npm run build (tsc) + a live UI screenshot (dev-mode vite hot-reloads the frontend; browser_screenshot falls back to the app UI).
- No Rust changes: cargo test not required. Docs (README/PLAN.md) make no claims about tab styling — no doc updates.
