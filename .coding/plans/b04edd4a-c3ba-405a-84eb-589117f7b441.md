# Plan: Add search_read combo tool (search + auto-read matched files in one call)

## Goal
Add a `search_read` tool that searches file contents and auto-reads the top-N matched files (with line numbers) in a single call, collapsing the search→read roundtrip.

## Context
Files of interest:
- src/tool/agent/search.rs — SearchTool: IGNORED_DIRS const, is_ignored_component, should_search (walk filter), SearchArgs, execute() inlines regex compile + glob walk + match loop in a spawn_blocking closure. MAX_MATCHES=100.
- src/tool/agent/read_files.rs — ReadFilesTool: ReadSpec{path,start_line,max_lines}, read_one(sandbox, spec) -> "=== path (lines a-b of n) ===\n<numbered body>" with per-file DEFAULT_MAX_LINES=2000 / DEFAULT_MAX_BYTES=102_400 caps + truncation notes, truncate_to_boundary helper, TOTAL_BYTE_CAP=512_000, MAX_FILES=10.
- src/tool/agent/mod.rs — module list + doc comment listing each tool.
- src/agent/factory.rs — register_agent_tools (line 354) registers SearchTool at 361; expected_tool_names test (line 785) lists "search" in the agent/file tools row.
- src/tool/mod.rs — Tool trait, ToolResult, ToolCategory, SafetyLevel, ToolFilter.allows (Agent+AutoRun visible in Planning).
- src/tool/agent/sandbox.rs — Sandbox::validate + root().

Design: a new `search_read` tool (AutoRun, ToolCategory::Agent) that (1) runs the same regex+glob+walk as search, (2) takes the first N matched files (by discovery order), (3) reads each via the existing read_one formatter (relative path through sandbox), (4) returns a search summary header followed by each file's numbered content. Reuse existing helpers by promoting them to pub(crate) — no logic duplication. Caps: MAX_FILES_TO_READ=5, reuse read_files' per-file + total byte caps.

## Steps
- [x] 1. **Promote shared helpers to pub(crate)** — In src/tool/agent/search.rs make `is_ignored_component` and `should_search` `pub(crate)`. In src/tool/agent/read_files.rs make `truncate_to_boundary`, `read_one`, `ReadSpec`, and the constants `DEFAULT_MAX_LINES`/`DEFAULT_MAX_BYTES`/`TOTAL_BYTE_CAP` `pub(crate)` (keep MAX_FILES private — search_read has its own file cap). No behavior change; just visibility.
- [x] 2. **Create search_read tool** — Create src/tool/agent/search_read.rs: a `SearchReadTool { sandbox: Sandbox }` implementing Tool (name "search_read", category Agent, safety AutoRun). Args: pattern (regex), glob (optional), literal (bool, default false), max_files (optional, default 5, capped at 5). execute(): clone sandbox root, spawn_blocking, compile regex (escape if literal — reuse the escape pattern from search.rs), glob walk with should_search filter, collect matched files in discovery order (dedup by path), stop once max_files distinct matched files are found (but keep counting total matches for the summary). Then for each matched file: convert its absolute path to a project-relative path, build a `ReadSpec{ path, start_line: None, max_lines: None }`, call `read_one(&sandbox, &spec)`, collect sections. Output: a summary line ("N matches in M files (searched X, skipped Y); reading top K") then the joined file sections, then apply the TOTAL_BYTE_CAP via truncate_to_boundary with a truncation note. Handle empty matches ("no matches found…") and invalid regex (error). Add a module doc comment.
