# Plan: Plans page: white plan cards on gray, and a resizable backlog column with checkboxes

## Goal
On the Plans page (the app's Plans route, not mission control) each plan is a distinct white card separated by gray, and the backlog moves to a resizable column on the right where every idea has a done checkbox and expands to show its full text and actions.

## Kind
implementation

## Context
Why: the user finds the Plans page hard to scan. Plans run into each other (they sit directly on the page background, separated only by a 20px margin), and the backlog is a plain list above the plans that pushes them down. They asked: plans should be white cards with gray between one plan and the next, and the backlog should be a more prominent column to the right of the plans, with a slider to resize it horizontally, a checkbox per idea and per-idea expansion. The lead (Claude) wrote this design; the user asked that DeepSeek implement it.

Decisions (taken by the lead):
1. Checkbox meaning: checking an idea marks it done (status pending -> done, the store's guarded `transition`); unchecking a done, failed or cant_resolve idea puts it back in the queue (`requeue`). This needs one new command `backlog_set_done(id, done)` and transport method `setDone(id, done)` (step 1).
2. Backlog groups, top to bottom: the queue (pending, in store order, reorderable), then "With the lead" (in_flight items, read-only: checkbox disabled, no actions except expand), then a collapsible "Done" group (done/failed/cant_resolve, checkbox checked, title struck through, closed by default, holding "Clear finished"). A failed or cant_resolve item shows its status word as a small badge.
3. Rows are collapsed by default: checkbox, a chevron toggle, the idea's first line (`ideaTitle(item, 90)`), and badges (Deferred, status). Clicking the chevron or the title expands the row to show the full text (pre-wrap) and the existing action buttons, unchanged in behaviour and aria-labels. Edit mode works inside an expanded row as today. Expansion state is per item id, local to the component, not persisted.
4. Layout: PlansView body becomes two columns. Left: the plans scroll area, background var(--surface-soft) (the gray), cards white. Right: the backlog column, background var(--surface), border-left 1px var(--line), its own vertical scroll, width default 380px, clamped to [280px, 60% of the PlansView width], saved per viewer in localStorage key `mnemo2.plans.backlogWidth` (wrap every localStorage access in try/catch). Between them a splitter like the Workbench's: dragging it left widens the backlog; ArrowLeft/ArrowRight change it by 24px; aria-label "Resize backlog". Under 760px total width the columns stack (backlog first, full width) and the splitter is hidden.
5. Plan cards: `article.plan` gets background var(--surface), border 1px solid var(--line), border-radius 12px, padding 14px 16px, box-shadow 0 1px 2px rgb(0 0 0 / 0.04); cards are separated by 14px of the gray column (margin-bottom 14px instead of 20px). The expanded `.plan-details` inside a white card uses background var(--canvas) so it still reads as an inset. The Closed group's summary sits on the gray like a section label. Remove PlansView's 880px max-width for the plans column; cap cards at max-width 920px instead.
6. No change to plan data, the Workbench layout, or any Rust outside src-tauri/src/mnemo2/backlog.rs and mod.rs.

## Acceptance scenarios
- Checking a pending idea's checkbox moves it to the collapsed Done group with a checked box; unchecking it there puts it back at the end of the queue; .coding/backlog.jsonl shows status done then pending
- Each backlog row shows one line by default; clicking its chevron shows the full text and the Plan this / Edit / Up / Down / Defer / Remove actions
- Dragging the splitter between plans and backlog resizes the backlog between 280px and 60% of the page, and the width survives switching tabs and restarting the app
- Each plan on the Plans page is a white card with gray space before the next plan, in light and dark mode
