# Plan: Mission Control shows a Claude Code agent worker's real model

## Goal
A worker that runs as a Claude Code agent shows "claude-code/<agent>" (and its agent effort) in Mission Control, with the model picker locked, instead of the tier's Mnemo model it never ran on.

## Kind
implementation

## Context
WHY: on 2026-11-23 the user saw FactoryGame's worker fluidmachine2 labelled "Ollama Cloud / glm-5.3" in the worker detail's model picker while its Claude Code agent (Opus) did all the work (168 tool calls; the worker record shows 0 requests). Every agent worker keeps the tier's Mnemo model in `record.model` ON PURPOSE: if the agent is handed back to Mnemo (detached lead / stall) the worker resumes on that model, so the host record must NOT change. The lead-facing team_status already shows `claude-code/<agent>` (src-tauri/src/mnemo2/team/lead_tools.rs:1081-1094); the window does not: mnemo2/src/lib/store/workerView.ts:165-166 maps `model: record.model_id ?? record.model`, `modelSpec: record.model`, and WorkerDetail.svelte shows an editable ModelEffortPicker on that spec. The host already serializes `claude_agent` (string, e.g. "opus") and `claude_agent_effort` (string|null) on every worker record in the snapshot; the TS type TeamWorkerRecord (mnemo2/src/lib/teamState.ts:115) just lacks the fields.

DECISIONS: frontend only, no Rust change. A worker runs as an agent iff `record.claude_agent` is a non-empty string. Then: view `model` = `claude-code/${claude_agent}` (same spelling as team_status), view `reasoningEffort` = claude_agent_effort ?? undefined, new view flag `runsAsAgent: true`; `modelSpec` stays record.model (unused while locked). WorkerDetail: modelChangeable is false when runsAsAgent; the locked badge's title for an agent worker reads "This worker runs as a Claude Code agent; its tier's agent setting chooses the model". Rows (WorkerRow, WorkerPanel, MergeCard) already render `worker.model`/`record.model` of the view, so they follow automatically — verify MergeCard's `entry.record.model` is the view model, not the wire record; if it is the wire record, apply the same mapping there.

VERIFY: npm test --workspace mnemo2 ; npm run check --workspace mnemo2 (run from the checkout root).

## Acceptance scenarios
- A FactoryGame-style worker with model 'Ollama Cloud/glm-5.3' and claude_agent 'opus' shows 'claude-code/opus' in its Mission Control row and detail, with no model picker.
- A normal Mnemo worker still shows its session model and the editable picker.
