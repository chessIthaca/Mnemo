# Plan: Browser URL autodetection + no-plugins webview hardening

## Goal
Make the browser URL bar accept scheme-less hostnames (autodetect https:// or http:// like a browser omnibox), and ensure no third-party browser extensions/plugins can load in the app's webview or the headless browser.

## Kind
implementation

## Context
src/browser/mod.rs `validate_url` (line ~654) rejects any input whose first `:`-token isn't http/https/data — so "www.google.com" errors with "unsupported URL scheme 'www.google.com'". Both the UI (`browser_open` IPC → `navigate`) and the agent tool (`browser_navigate`) go through this single choke point. The app UI is a Tauri 2.11.5 WebView2 webview; window config lives in src-tauri/tauri.conf.json (single "main" window). The headless browser (chromiumoxide 0.7, fresh temp profile, so no extensions by default) is launched in `ensure_browser` (src/browser/mod.rs ~line 172). Frontend passes the raw trimmed input straight through (frontend/src/components/views/BrowserView.tsx openUrl).

## Steps
- [x] 1. **Add URL scheme autodetection in src/browser/mod.rs** — Replace `validate_url` (line ~654) with `normalize_url(input: &str) -> Result<String>`: trim; empty → existing "empty URL" error. If first `:`-token (lowercased) is http/https/data → Ok(trimmed) unchanged. Else if token is scheme-like (`[a-z][a-z0-9+.-]*`) AND the remainder after `:` is NOT all digits → keep existing "unsupported URL scheme '{token}' in '{url}' — only http, https, data are allowed" error (keeps file:/javascript:/about: rejects). Otherwise autodetect: reject if input has whitespace; authority = input up to first `/ ? #`; empty authority → None; starts with `[` → http; rsplit_once(':') port must be empty or all digits else None; host after trimming trailing dots: "localhost" → http; all digits+dots containing a dot → http (IPv4); contains '.' → https; else None. None → Err(InvalidInput("'{input}' is not a valid URL — expected http(s)://, data:, or a hostname like example.com")). Return Ok(format!("{scheme}://{trimmed}")). Update `navigate()` to call `let url = normalize_url(url)?;` and use the normalized `url` in `new_page`, the error message, and the returned PageInfo. Update the module doc (lines ~16-19) to mention autodetection. Add table-driven unit tests for normalize_url (www.google.com → https://www.google.com; google.com/path?q=1; localhost:3000 → http://localhost:3000; 127.0.0.1:8080 → http://…; [::1]:3000 → http://[::1]:3000; example.com:8080 → https://…; data:/http(s) passthrough; rejects: about:blank, javascript:alert(1), file:///C:/Windows/win.ini, "hello world", "C:\\foo", ""). The existing navigate_rejects_disallowed_schemes test must still pass unchanged.
- [x] 2. **Update tool docs + frontend placeholder** — In src/tool/browser/mod.rs NavigateTool::schema (line ~62-67), extend the description: after "Only http(s) and data: URLs are allowed (enforced)" add that scheme-less hostnames like `www.google.com` are auto-prefixed with https:// (http:// for localhost/IPs). In frontend/src/components/views/BrowserView.tsx line ~146 change the placeholder to "e.g. www.google.com — https:// is added automatically". No logic changes; the frontend already passes the raw input through to browser_open.
- [x] 3. **No-plugins hardening for app webview + headless browser** — Add `"additionalBrowserArgs": "--disable-extensions"` to the window object in src-tauri/tauri.conf.json (app.windows[0]) — the Tauri v2 WebView2 knob that forbids browser-extension-style plugins in the app UI webview. In src/browser/mod.rs `ensure_browser` BrowserConfig::builder() add `.args(vec!["--disable-extensions".into()])` so pages opened in the Browser tab / by browser_navigate are plugin-free too (fresh temp profile already blocks extensions; this makes the policy explicit). Add a short comment citing the intent ("no plugins in this app"). Note: OS-level injectors (Grammarly-for-Windows style overlays) inject from outside the app and cannot be blocked from inside — the webview/browser flags are the app-side mechanism.
