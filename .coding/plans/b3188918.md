# Plan: Anthropic reasoning (output_config.effort) + endpoint-dialog effort controls + caps autofill

## Goal
Wire the existing reasoning-effort pipeline through to Anthropic's `output_config.effort` (toolbar + endpoint/model config dialogs both effective, no `thinking` field ever sent), and make the config dialog auto-detect Anthropic model caps (context window via max_input_tokens, max output via max_tokens, vision, and the supported effort levels) from /v1/models so picking a model auto-fills them — using the existing autofill/Apply-discovered machinery, not new UI plumbing.

## Kind
implementation

## Context
DESIGN CORRECTED mid-step-1 against live Anthropic docs (fetched 2027-01-11), superseding the original extended-thinking-budget sketch:

- `thinking: {type:"enabled", budget_tokens:N}` is DEPRECATED on Claude 4.6 and REJECTED with a 400 by 4.7+ ("Claude 4.7 and later models do not support it and reject requests that use it"). A budget table would break on current models → dropped.
- The modern control is the top-level `output_config.effort` (low|medium|high|max|xhigh), available with NO beta header; docs: "Where adaptive thinking is available, effort is the recommended way to control thinking depth", and effort "works whether or not thinking is enabled". Wire shape per the Effort page example: `output_config: {"effort": "medium"}`.
- A `thinking` field must NEVER be sent by us: `{"type":"disabled"}` is a 400 on models whose thinking is always on (Opus 5.5 "at every effort level"; Opus 5 at xhigh/max), and `{"type":"enabled"}` is a 400 on 4.7+. Omission = the model's own default (thinking is already on by default on Opus 5.x / Sonnet 5, which is exactly the reasoning the user wants to control).
- Our display ladder is off|minimal|low|medium|high|max; the API has no `minimal` → maps to `low`; `off`/unknown/unset → omit the field entirely (the pre-effort behavior, which the existing normalize path already produces since anthropic "off" resolves to None).
- Discovery: /v1/models entries carry `max_input_tokens`, `max_tokens`, `capabilities.image_input.supported`, and `capabilities.effort.{low,medium,high,max,xhigh}.supported` — the effort allow-list the dialog should autofill comes from exactly there, which is what gates per-model effort levels.
