# Plan: Seed shipped skills into new projects at init

## Goal
Seed the shipped skills (currently merge_to_main) into every project at Project::init time — embedded in the binary via include_str! so installed copies work without the source repo — so new (and existing, via self-heal) projects get .coding/skills/ populated automatically; existing user-modified skill files are never overwritten.

## Kind
implementation

## Context
Skills are TOML files in .coding/skills/<name>.toml, loaded by SkillRegistry::load_dir (src/skill/mod.rs:79) which returns an EMPTY registry when the dir is missing — so a fresh project (Project::init, src/project/mod.rs:131) which scaffolds .coding/ + plans_dir + agent.md but NOT skills_dir, has no skills at all. The main installation's skills live in the app repo's own .coding/skills/ (currently one: merge_to_main.toml; a parse-rot test shipped_skill_files_parse_and_merge_to_main_cleans_up_memories at src/skill/mod.rs:225 guards them). Project::init has a self-heal precedent: on an already-initialized project it still re-scaffolds a missing agent.md (:134-137) — seeding missing skill files in both paths matches that philosophy and lets older projects backfill on next init. init() is called from src-tauri/src/ipc/projects.rs:99 (create-project IPC) and src-tauri/src/main.rs:1014 (CLI). Compile-time embedding via include_str! (path relative to src/skill/mod.rs: ../../.coding/skills/merge_to_main.toml) ships the TOMLs inside the binary — no dependence on the source repo at runtime, multi-platform safe. Constitution: doc comments on public items, no #[allow], cargo test unpiped (check "test result:" lines), regression tests, never commit to main directly (working branch wt/*), reviewer subagent before finish, docs sync (PLAN.md/README mention skills?).
