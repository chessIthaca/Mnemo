# Plan: finish gate self-freshens stale codegraph (no more manual reindex dance)

## Goal
Make finish's regression-test gate self-freshen the codegraph (one incremental reindex + retry on miss) so a stale index never blocks a valid regression test, while a wrong test name still fails closed.

## Kind
bug_fixing

## Context
Root cause verified by reading src/tool/workflow/plan.rs:998-1014: the gate does graph.view().resolve(test) — a pure in-memory snapshot of the LAST-INDEXED state. Scenarios that leave the index stale: (1) headless/agent sessions with no file watcher running (backlog #90/#91 dance), (2) in-app finish racing the watcher's debounced reindex. CodeGraph::index(None) is incremental + content-hash based (src/codegraph/mod.rs:171-190: only changed files re-parse; per-file store lock; indexing flag managed by drop guard), so a self-freshen on miss is cheap and safe. Fix scope: the finish gate only — graph_* tools already return actionable stale-index hints and are a separate concern. Existing tests: finish_blocks_bug_plan_when_test_symbol_missing_from_graph (wrong name must still block) and finish_passes_bug_plan_with_test_in_graph_and_captures (indexed symbol passes). New behavior: on miss → one spawn_blocking index(None) pass → re-resolve → found = pass (with a "graph reindexed" note); still missing → original error (fail closed); reindex/panic errors → also fail closed.
