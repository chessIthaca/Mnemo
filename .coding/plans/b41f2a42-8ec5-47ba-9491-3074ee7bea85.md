# Plan: Async/blocking hygiene: spawn_blocking for memory store + browser sweep, reqwest redirect policy

## Goal
Move blocking I/O off the async runtime: (R2) wrap memory-store rusqlite calls in spawn_blocking, (M1-perf) move browser temp-dir sweep off the locked async path, (L1) set explicit reqwest redirect policy. L2 (cap shell stdout/stderr) dropped — false premise (uncapped data never reaches LLM context).

## Kind
implementation

## Context
From the 2026-08-13 whole-app review, the "top-5 impact" batch is done+committed. This plan addresses remaining items R2 (memory spawn_blocking), M1-perf (browser sweep off lock), and L1 (reqwest redirect policy). L2 (cap shell stdout/stderr) was DROPPED after investigation: the LLM tool message at turn.rs:1090-1096 uses result.output (already capped via cap_tool_output), NOT result.data — the uncapped data only goes to the frontend event, never LLM context. So L2 fixes a non-issue.

## Steps
- [x] 1. **M1-perf: browser temp sweep off the locked async path** — In `src/browser/mod.rs` `ensure_browser` (line ~168), replace `Self::sweep_stale_profiles();` with `let _ = tokio::task::spawn_blocking(Self::sweep_stale_profiles);` (fire-and-forget — the sweep only removes >1h-old dirs, not the current profile, so no need to await). `sweep_stale_profiles` (line 201) is `fn() -> ()` with no args, already `Send + 'static` as a function pointer. This moves the blocking `read_dir`+`remove_dir_all` off the async thread that holds the state lock. Run `cargo test` (browser tests: navigate_and_list_pages, respawn_after_close, profile_dir_is_removed_on_close).
- [x] 2. **L1: explicit reqwest redirect policy** — In `src/provider/openai.rs`, add `.redirect(reqwest::redirect::Policy::none())` to BOTH `reqwest::Client::builder()` chains: the main client (line ~99, in `new_with_trace`, after `.deflate(true)` before `.build()`) and the fetch_models client (line ~190, after `.deflate(true)` before `.build()`). This prevents any cross-host redirect from carrying the `Authorization: Bearer` header to a redirected host. LLM/embeddings API endpoints don't redirect, so `Policy::none()` is safe. Run `cargo test`.
- [x] 3. **R2a: switch MemoryStore mutex from tokio::sync to std::sync** — In `src/memory/mod.rs`: (1) line 15 change `use std::sync::{Arc, RwLock};` to `use std::sync::{Arc, Mutex, RwLock};`. (2) Remove `use tokio::sync::Mutex;` (line 19). (3) Field `conn` (line 181): `Arc<Mutex<Connection>>` now resolves to `std::sync::Mutex`. (4) Field `read_conn` (line 184): `Option<Arc<Mutex<Connection>>>` same. (5) Replace EVERY `.lock().await` in the file with `.lock().expect("conn lock poisoned")` for write-conn sites and `.lock().expect("read conn lock poisoned")` for read_conn sites. There are ~13 sites (write:605, recall:652, access:755, batch_access:772, load_all:406, strongest:818, delete_working_for_session:855, start_session:873, end_session:882, record_request_stats:930, session_stats:953, project_stats:1006, session_list:1073). Run `cargo test` — all 29 memory tests must pass (intermediate state: DB calls still block the async thread, fixed in R2b).
- [x] 4. **R2b: wrap memory-store DB work in spawn_blocking** — For each of the 13 DB-touching methods in `src/memory/mod.rs`, move the synchronous rusqlite work into `tokio::task::spawn_blocking`. Pattern for write-conn methods (e.g. `access`): `let conn = self.conn.clone(); let now = self.now(); let id = id.to_string(); tokio::task::spawn_blocking(move || -> Result<()> { let conn = conn.lock().expect("conn lock poisoned"); conn.execute(...)?; Ok(()) }).await.map_err(|e| Error::Memory(format!("access task failed: {e}")))?`. For read-conn methods (e.g. `load_all`): `let read_conn = self.read_conn().clone(); let tier = tier; tokio::task::spawn_blocking(move || -> Result<Vec<Memory>> { let conn = read_conn.lock().expect("read conn lock poisoned"); Self::load_all_locked(&conn, tier) }).await.map_err(|e| Error::Memory(format!("load_all task failed: {e}")))??` (double `?`: first for JoinError, second for inner Result). Special cases: (a) `write` — embedding is async BEFORE the DB work; clone self.conn + move owned memory into the closure, return memory.id. (b) `recall` — embedding async first, then spawn_blocking for the FTS+load block (clone query→String, tier/exclude_working/limits are Copy), then score in pure Rust (no DB), then `self.batch_access(&ids).await` (already wrapped). (c) `strongest` — spawn_blocking for the query+load, then sort/truncate in pure Rust after. (d) `record_request_stats` — clone `stats` (verify RequestStats: Clone+Send; if not Clone, clone its fields into a owned tuple). (e) `start_session` — build Session before DB, clone conn+session fields into closure, return Session. (f) `record_tool_event` — no direct DB work (calls self.write), no change. Mirror the error-handling pattern from describe_image.rs:107. Run `cargo test`.
