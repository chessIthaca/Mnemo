# Plan: Seed run-all worktree codegraphs from the main tree's DB

## Goal
Seed each parallel run-all worktree's codegraph.db from the main tree's DB at provision time (a consistent VACUUM INTO snapshot before the index pass), turning the per-lane cold full tree-sitter parse into a read+hash sweep that re-parses only branch-diff files — with a timing log on the index pass and a regression test proving a seeded DB with one changed file re-parses exactly that file.

## Kind
implementation

## Context
Backlog item 6c56a5a1 (2026-09-08 performance LOW-2 lever b; model-pipeline proposal 3 — convergent). Goal: eliminate the redundant cold code-graph parse every parallel run-all worktree agent pays at spawn. Verified facts from planning: (1) the cold pass lives in spawn_run_all_agent (src-tauri/src/ipc/spawn.rs:140-185) — a spawn_blocking task does CodeGraph::open(wt, wt/.coding/codegraph.db) + g.index(None); a fresh worktree checkout has no gitignored codegraph.db, so every searchable file is read+hashed+parsed. (2) The index loop (src/codegraph/mod.rs:260-381) is content-hash keyed: mtime fast-path (stored mtime == disk mtime → skip) then read+hash; needs_reindex = stored_hash != Some(hash) || !has_content — a hash match skips the parse entirely, so a seeded DB with fresh-checkout mtimes degrades to a read+hash sweep that re-parses only hash-mismatched (branch-diff) files. IndexStats carries files_scanned/files_reindexed/files_pruned/symbols/edges/elapsed_ms. (3) The factory exposes the MAIN tree's graph via codegraph_handle() (src/agent/factory.rs:582) whose root() derives the main DB path root/.coding/codegraph.db (project/mod.rs:65). (4) The caller is dispatch_spawned_item (src-tauri/src/ipc/run_all.rs:3630) — spawn_run_all_agent IS the provisioning-time hook. DESIGN DECISIONS: (a) the seed copy must be a CONSISTENT snapshot, not a file copy — the main DB is live WAL-mode; a torn copy (cg_files rows committed while cg_symbols rows sit in the WAL) is NOT self-healing because the index trusts stored content hashes, so a file whose row survived but whose symbols did not would be skipped with missing symbols. Use SQLite's VACUUM INTO (online backup, plain SQL, no rusqlite feature flag — Cargo.toml has rusqlite = { version = "0.32", features = ["bundled"] } only) from a read-only connection with busy_timeout(5000). (b) Seeding is best-effort: any failure (no main graph, missing DB, lock, IO) falls through to today's cold index — never worse than cold. (c) A partial seed (main index still running at dispatch time) degrades gracefully: files with rows skip, files without rows parse. (d) Concurrent lanes each seed from the same main DB — multiple WAL readers are fine. (e) The timing log uses eprintln! (the codegraph module's existing convention, mod.rs:311/355) printing seeded|cold + scanned/re-parsed/pruned/symbols/elapsed_ms. (f) The live-lane acceptance checks (timing delta on a real dispatch, in-lane graph_search spot-check) cannot be run unattended — the unit test proves the mechanism (re-parse exactly the changed file; seeded rows answer identically to a cold build) and the log line surfaces the delta on the next real run-all. Documented for the final summary.
