# Plan: Plan resumability gate: reject plans too thin to survive recompile+restart

## Goal
Add a structural plan-quality gate to the create_plan and update_plan workflow tools so a plan document too thin to resume from after a recompile+restart is rejected at the tool boundary with one actionable error naming everything missing — the same UX as backlog_add's detail bar. Enforced: substantive non-blank context (symptom/root-cause + file anchors + verification commands), every step naming concrete file paths (or an explicit no-code marker), and bug_fixing plans carrying the regression-test design.

## Kind
implementation

## Context
Root cause (2027-01-09, plan be16ea36): plan resumability depended on the planning model's diligence — the resume-hardening block (standing directives, helper paths, test baselines, resume protocol) had to be appended manually via update_plan because nothing enforced it. Fix: a structural validator at the tool layer, mirroring the backlog detail bar (SPEC 2a009a60, commit 08a9295, src/backlog.rs normalize_item_text + body_carries_detail_marker: MIN_BODY_CHARS=160 + path-ish regex + 'no-code research' markers, actionable one-shot errors).

Layer decision: the gate lives in the TOOL layer only (src/tool/workflow/plan.rs), exactly like the existing blank-title/blank-goal guard (:397/:404) — the engine (src/workflow/mod.rs create_plan :451 / create_plan_with_kind :482 / create_plan_with_kind_and_detail :503) stays permissive because its ~81 callers are almost entirely tests using thin placeholders (wf.create_plan("T", "G", "C", vec!["S"])) and production plan creation flows only through the tools (the engine calls at src-tauri/src/ipc/run_all.rs:1436 and src-tauri/src/ipc/spawn.rs:763 are test helpers; dispatched agents call the tool). This keeps existing engine tests green (acceptance criterion 5).

Validator design (pure fn in plan.rs, unit-testable): MIN_CONTEXT_CHARS=40; reuse crate::backlog::body_carries_detail_marker (made pub(crate)) for per-step path/marker checks — same regex + marker vocabulary as the backlog bar; bug_fixing plans skip the per-step check (the forced BUG_FIXING_SKELETON at plan.rs:40 is path-free by design) and instead require the regression-test design: context + detailed-steps text contains 'test' or 'regression'. create_plan wiring: after the existing title/goal/bug-param/steps-empty checks (so create_plan_requires_steps :2171, blank-title :2188, blank-goal :2209 keep their current errors), before the workflow lock; all issues joined into one error 'plan rejected by the resumability gate — (1)… (2)…'. update_plan wiring: new steps checked per-step (non-bug kinds; bug plans hit the engine's skeleton lock); context replace checks the new text, context append checks the COMBINED existing+new text (read via wf.plan()); title-only/regression_test-only calls ungated. The optional LLM self-check is skipped — it needs provider wiring inside the tool; the structural gate covers the acceptance criteria.

Verification: cargo test at the repo root, unpiped, reading the 'test result:' lines (PowerShell: cargo test; "exit=$LASTEXITCODE") — warning-free under #![deny(warnings)]. Known fallout to repair: ~45 thin tool-level fixtures in src/tool/workflow/plan.rs tests (many the identical json!({"title": "T", "goal": "G", "steps": ["a"]})), plus tool-driven tests in tests/integration/workflow_integration.rs (:135/:236/:498), src/agent/tests.rs (:1749 create_plan_never_needs_approval), src/agent/factory.rs (:2348), and any src/runtime/agent.rs tests dispatching thin create_plan calls — engine-level tests are unaffected.
