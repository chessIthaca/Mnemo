# Plan: Always-on provider-error log (.coding/logs/provider-errors.jsonl)

## Goal
Add an always-on provider-error log (.coding/logs/provider-errors.jsonl): one compact JSON line per failed LLM request (HTTP >=400, transport/stream errors), deduped per request id, written regardless of the Trace panel's opt-in "log to file" checkbox — so future sessions can answer "what provider error happened and why".

## Kind
implementation

## Context
User request: "we don't log provider errors if you don't know. Let's log them so you can answer this in the future. Holding them in a memory log is good enough." Verified: every LLM request error already funnels through LlmRequestLog::fail(id, status, error) (src/provider/openai.rs:404 stream-start failure, :414 non-2xx, :489/:572/:586/:597/:625 stream errors) into the single with_record funnel (src/provider/trace.rs:312). But records are only mirrored to traces.jsonl when the Trace tab's opt-in checkbox is on (log_enabled, off by default; main.rs:496-500 sets the path but not the flag). So provider errors are effectively invisible after a session unless the user opted in. Fix: an ALWAYS-ON compact error log — new error_log_path (set unconditionally at startup to <coding_dir>/logs/provider-errors.jsonl) + append-only one-line-per-failed-request, deduped by record id, gated on a terminal error state (http_status >= 400 OR error.is_some()). LlmRequestSummary (trace.rs:130-153) already serializes the compact shape {id, ts_ms, model, base_url, http_status, usage, finish_reason, ttft_ms, generation_ms, error, response_truncated} — reuse it for the line. Error logging is independent of the traces.jsonl opt-in checkbox. Tests: existing file-logging tests in trace.rs (set_log_file_path/set_logging_enabled) must stay green; new tests for append+dedupe+success-no-log+always-on-without-checkbox. main.rs sets the path next to set_log_file_path (line 500). On feat/per-state-model-effective (clean); new branch. Windows PowerShell; cargo test unpiped; zero warnings under #![deny(warnings)].
