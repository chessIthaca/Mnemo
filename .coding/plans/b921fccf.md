# Plan: Strengthen backlog item status semantics — status ⇔ plan lifecycle (backlog 45dcf577)

## Goal
Tie backlog item status to the plan lifecycle (backlog 45dcf577): in_flight ⇔ a plan dispatched for the item is ACTIVE (stays through interruptions, steering pauses, sub-plan pushes); done ⇔ the plan reached Complete (the existing turn-resolution gate — plan-finish-driven); failed ⇔ ONLY root-plan abandonment (abandon_plan) or an explicit dead end (cant_resolve) — never session end, crash, interrupt, deferral, or requeue. Concretely: record the root plan id on the dispatched item (item↔plan linkage), add the abandonment→failed transition driven from the workflow-state event, remove every spurious Failed/CantResolve setter (single-dispatch + run-all resolution arms, halt_run_all's approval stamp, the dispatch-failure stamp, and the plan-gate rollback), update the backlog_status tool contract, add the six regression scenarios from the task, and sync docs.
