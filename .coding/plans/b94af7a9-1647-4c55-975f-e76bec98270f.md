# Plan: Show stats row at startup — emit ContextUsage at agent registration + seed ctx max via context_caps IPC

## Goal
Show the full InflightBar stats row (token counters at 0 + ctx bar with the real context-window max) from app startup, before the first prompt — by emitting ContextUsage when an agent registers and seeding the max via a new context_caps IPC command at frontend startup.

## Kind
implementation

## Context
Bug (user-reported, screenshots): at startup the InflightBar shows only "idle"; the stats row (↑ prompt, ↓ completion, 🧠 reasoning, tok/s, ctx bar) appears only after the first command runs. Expected: full stats row visible from startup (zeros + ctx 0/max). ROOT CAUSE (verified): InflightBar.tsx:36-40 gates the counters on hasTokens (any token counter > 0) and the ctx bar on hasContext (contextUsage.max > 0); the bar itself renders because showTokenUsage defaults true (appearance.ts:203). contextUsage.max only arrives via the ContextUsage agent event, first emitted at the top of the first turn (src/agent/turn.rs:228-232; also /compact runtime/agent.rs:548-554 and /new runtime/agent.rs:561-573). The backend knows the max at spawn: AgentLoopFactory.build_inner snapshots the shared ContextManager into every loop (src/agent/factory.rs:338-343,358); agent_loop.context_manager().max_tokens() accessor exists (src/agent/loop_impl.rs:719). CHOSEN DESIGN (ask_user): emit ContextUsage at agent registration + frontend pull to plug the startup race. RACE (verified): spawn_agent_shared sends through the bounded fan-in channel (cap 256, main.rs:113) so events buffer even before the forwarder starts (main.rs:172), BUT the forwarder's app.emit (src-tauri/src/ipc/events.rs:395) is lossy until the frontend listener attaches (ensureListenerStarted, useAgentEvents.ts:296, on chat-UI mount) — and the main agent spawns in setup (main.rs:153-166) before the webview loads. So: (1) spawn-time emission covers all agents spawned while the UI is live; (2) a new context_caps IPC command returns per-agent max so the frontend can seed at startup right after registerAgents (App.tsx:167-172). Command returns ONLY max (not used) so a late call can never clobber a live used count; the store merge keeps existing used. Key code: spawn point src-tauri/src/ipc/spawn.rs:150-165 (fanin_tx cloned from mgr at :153, moved into task.run at :155 — clone it first; agent_loop available after register; ContextBreakdown::default() exists, runtime/agent.rs:570); IpcState holds manager + agent_loops (src-tauri/src/ipc/state.rs:41,73); list_agents pattern at src-tauri/src/ipc/agent.rs:353; command registration in main.rs invoke handler near :391; frontend registerAgents useAgentStore.ts:519-543; reduceContextUsage agentEventReducer.ts:486-492 (keep as-is); InflightBar hasTokens usages at :36-38, :173, :216. Frontend listener/list_agents: App.tsx:165-175. Environment: Windows/PowerShell; cargo test UNPIPED + read test-result lines (piped exit codes lie); deny(warnings) — no dead code, no #[allow], doc comments on all public items; preserve line endings. NOTE: root cargo test does NOT compile src-tauri tests — run cargo test in src-tauri too, and cargo build in src-tauri (bin crate, per merge-skill lesson). Fixtures: ContextUsage event shape unchanged (event-context-usage.json untouched); IPC commands have no fixtures (dto-only convention) — none needed.
