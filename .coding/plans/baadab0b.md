# Plan: A merged worker's stuck checkout is retried until it is gone

## Goal
When removing a merged worker's checkout fails (something held the folder), Mnemo2 retries the removal at every later merge and at every app start, clears the worker's cleanup note once it works, and lets the existing branch sweep delete the branch the stuck folder was blocking.

## Kind
bug_fixing

## Context
WHY. Observed live on 2026-11-06: worker consolDerived01 was merged but its folder `.worktrees/agent-consolDe` stayed on disk, unregistered with Git (`git worktree list` no longer shows it), and `team_status` still shows the note "merged, but worktree cleanup needs attention: could not remove leftover checkout C:\Mnemo\.worktrees\agent-consolDe: The process cannot access the file because it is being used by another process. (os error 32) (no process found holding a file in it; a terminal or program whose working folder is inside it can also block removal)". The holder was the lead session's own shell, whose working folder was inside the worktree; it moved away minutes later, but nothing tries again. `cleanup_agent_worktree` (src-tauri/src/mnemo2/team.rs, near line 7713) runs exactly twice per worker: once in `merge_locked` (near line 6527) and once in `recover_worker` (near line 7857). The note then stays for ever. An earlier fix (plan 5ce39273) taught `cleanup_agent_worktree` and the delete flow to finish half-removed checkouts, but added no retry for merged workers. Since plan 20b458d8 the branch delete runs only after a successful checkout cleanup (the `Ok(())` arm in `merge_locked`), and `sweep_merged_branches` (near line 6584) skips a merged worker whose checkout folder still exists, so the stuck folder also blocks the branch auto-delete (the leftover branch had to be deleted by hand).

DECISIONS ALREADY TAKEN.
1. Retry the removal for every worker whose status is `Merged` and whose `error` starts with one of two checkout-cleanup notes: the note `merge_locked` writes ("merged, but worktree cleanup needs attention") and the note `recover_worker` writes ("merge recovered, but worktree cleanup needs attention"). A retry that works, or that finds the folder already gone (`cleanup_agent_worktree` already returns `Ok(())` for a missing folder), clears the note (only while the error still starts with a cleanup note) and persists. A retry that fails leaves the record exactly as it was.
2. Two retry points. (a) Inside `merge_locked`, directly before the existing `self.sweep_merged_branches(worker_id).await;` call, with the merge lock already held. (b) Once at app start in `TeamRuntime::open`, directly after `schedule_trash_sweep(&runtime.workspace_root);`, awaited, under the merge lock, followed by `sweep_merged_branches("")` so branches the stuck folders were blocking go too.
3. The branch delete itself is NOT duplicated: after a retry clears a worker's folder, the existing `sweep_merged_branches` (which already requires `ledger::merged`, `owns_its_branch`, no other record sharing the branch, and no checkout folder) deletes the branch and clears a stale branch note.
4. `cleanup_agent_worktree` and `remove_leftover_checkout` stay unchanged: their guards (the checkout must be the worker's own direct child of `.worktrees`, links and junctions are refused, a registered checkout with new dirty work is retained) are what make the retry safe.
5. No setting, no new event, no UI change. Cost: a still-held leftover makes one retry take up to about 3 seconds (`remove_leftover_checkout` tries 12 times, 250 ms apart); only workers with a stuck folder pay it.

FILES. Step 1 owns `src-tauri/src/mnemo2/team.rs` only (production code and its `mod tests`). Step 2 owns `mnemo2/README.md`, `mnemo2/plugin/skills/mnemo-lead/SKILL.md` and `mnemo2/plugin/skills/mnemo-review/SKILL.md`. No file is shared between the steps.

REGRESSION TEST. `a_later_merge_retries_an_earlier_merged_workers_stuck_checkout` in the `mod tests` of src-tauri/src/mnemo2/team.rs. Without the fix it FAILS: after the later merge the earlier worker's leftover folder is still on disk, its note is still on the record and its branch still exists, because nothing retries. Supporting tests: `a_stuck_checkout_that_still_cannot_be_removed_keeps_its_note_and_branch`, `the_retry_ignores_a_merged_worker_whose_error_is_not_a_checkout_note`, `open_retries_a_stuck_checkout_left_by_an_earlier_run`.

VERIFY. In the worker's worktree: `cargo test -p mnemo-app --features mnemo2 --lib <filter>` then the full `cargo test -p mnemo-app --features mnemo2 --lib`, and `cargo clippy -p mnemo-app --features mnemo2 --all-targets -- -D warnings`. ## Acceptance scenarios
- After a merge, an earlier merged worker whose record carries the note 'merged, but worktree cleanup needs attention: ...' and whose checkout folder is now removable has its folder removed, its note cleared (in memory and in the persisted team file) and its branch deleted, without the user doing anything.
- A merged worker whose checkout still cannot be removed (the path is a link to a folder outside .worktrees) keeps its exact note, its folder and its branch after every retry, and the outside folder is never touched.
- A merged worker whose error is not one of the two checkout-cleanup notes is never retried: its folder and error are unchanged after a later merge.
- Opening Mnemo2 with a persisted merged worker that carries a checkout-cleanup note and a removable leftover folder removes the folder, clears the note and deletes the branch before the first merge.
- A merge by itself still behaves as before: a clean merge removes its own checkout, deletes its own branch and leaves no note, and the existing branch-sweep tests pass unchanged.

- 2026-11-06: no spec impact: Merge-time checkout and branch cleanup is not specified by any capability under .coding/openspec/specs (dispatch-routing, external-lead, tier-ladder and worker-brief govern routing, the external lead, tiers and briefs; a search of all specs finds no mention of checkout, worktree or cleanup). The plan only adds a retry of an existing best-effort cleanup in src-tauri/src/mnemo2/team.rs.
- 2026-11-06: added step 3 (Integration check) because steps 1 and 2 ran in parallel
- 2026-11-06: Test setup correction for step 1 (2026-11-06). The step text says to create the early worker's leftover folder AFTER open_test_team returns for tests A and B. That is wrong: `open` now retries, `cleanup_agent_worktree` returns Ok(()) for a MISSING folder, so open clears the note of a merged worker with a cleanup note before the later merge, and a folder created afterwards is never retried (the retry filter needs the note). Corrected setup. Test A: create a directory link (junction/symlink via `create_directory_link`) at `early.worktree` pointing to an outside tempdir BEFORE `open_test_team`; open's retry refuses the link (`validated_checkout`), so the note survives and the open-time sweep keeps the branch (the link path exists). After open, remove the link only (`std::fs::remove_dir`, falling back to `std::fs::remove_file` for a unix symlink; never touch the outside folder) and create the real leftover folder with `fragment.txt`; the merge-time retry then removes it, clears the note and the sweep deletes the branch. Test B: create the link BEFORE open instead of after (open and merge both refuse it; note, folder, outside file and branch stay). Tests C and D stay as written. Production edits are unchanged.
