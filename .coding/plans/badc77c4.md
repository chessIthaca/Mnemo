# Plan: Remove the plan board's unverified-symbol gate

## Goal
plan_create and plan_update stop refusing plans whose context names a function, method or member call that does not exist yet. Plans can describe new code directly and in detail. The other resumability checks (context length, file anchors per step, the regression-test design for bug fixes) stay exactly as they are.

## Kind
implementation

## Context
The user decided on 2026-11-02: "definitely lets remove that gate". The evidence rule (from backlog 5b232b8d) rejects any context line containing a dotted member call, like `actions.openPlanDocument(planId)`, or the phrases "exists at", "is callable", "callable from", "is reachable" or "reachable from", unless the same line carries an evidence word ("verified", "probe", "checked", ...) or an assumption label ("assumption", "unverified", ...). In practice it pushed the lead to describe new code vaguely, because a design names functions before they exist. That is the opposite of what cheap worker models need: they need exact names and signatures. Detailed plans are now the rule (see the mnemo-plan skill, "Write each step as a spec").

verified (read src/app/tool/workflow/plan.rs): the gate is entirely in this file, and nothing else in src, src-tauri/src or mnemo2/plugin refers to it. Pieces:
- `fn context_issue(context, kind, detailed_steps, check_evidence: bool)` (around line 289) runs `reachability_evidence_issue(ctx)` at its end when `check_evidence` is true (around line 320).
- The update path (around line 1324) calls `context_issue(&effective, kind, detailed, false).or_else(|| reachability_evidence_issue(new_ctx))`.
- The helpers used only by the gate: `fn holds_dotted_call(line)` (around 367), `fn contains_marker` (around 418), `fn carries_assumption_label` (around 437), `fn carries_evidence_marker` (around 452), `fn reachability_evidence_issue(text)` (around 478). Confirm with grep that each has no other caller before deleting it.
- The create_plan `context` schema description (around line 788) tells the model about the convention, from "and it carries FINDINGS, not assumptions" through the "verified (read src/tool/agent/search.rs:12-40)" example.
- Tests that pin the gate: validator_flags_unevidenced_reachability_claim (~3073), validator_accepts_evidenced_reachability_claim (~3107), validator_accepts_assumption_labelled_claim, validator_ignores_plain_symbol_mentions, create_plan_rejects_an_unevidenced_reachability_claim (~4086), and the context half of plan_tools_advertise_steps_shape_and_evidence_convention (~4861, the asserts on "SAME line as the claim" and "verified (read ").

## Acceptance scenarios
- plan_create accepts a context that names new code such as actions.openPlanDocument(planId) without any 'verified:' or 'assumption:' label.
- A plan with a context under 40 characters, a step without a file path, or a bug_fixing plan without a regression-test design is still refused exactly as before.
- The plan_create context description asks for detailed designs with signatures instead of the evidence convention.
- Root clippy and lib tests pass, and no trace of the evidence rule remains in plan.rs.
