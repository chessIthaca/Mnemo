# Plan: Memory search picks up .coding/ changes live

## Goal
A plan, review, knowledge record or OpenSpec spec written while Mnemo is open is findable with memory_search within a few seconds, without restarting Mnemo2.

## Kind
implementation

## Context
WHY: An agent in another project (FactoryGame) wrote six new `.coding/openspec/specs/<capability>/spec.md` files while Mnemo2 was open, and memory_search did not find them. The derived memory index (plans, reviews, knowledge files, OpenSpec requirements, backlog) is reconciled only ONCE, when Mnemo2 opens a project: `src/host/brain.rs` (around lines 517-736) spawns a task that runs sweeps, then `crate::memory::indexer::corpus_is_stale`, then `crate::memory::indexer::index_derived`. The only live path is the targeted `reindex_knowledge_files` that `memory_write` runs for knowledge files it writes itself. A file written any other way (a hand edit, a git merge, plan tools in another process, an agent writing specs) waits for the next app start. The code graph already has a live OS watcher (`src/codegraph/watcher.rs`, `GraphWatcher`, started in brain.rs around line 1140 and held on `Brain::_graph_watcher`), but it refreshes only the code graph and the text `search` content index, never the memory store.

DECISION: add a second, separate watcher for the memory index, modelled on `GraphWatcher` but in the host layer, file `src/host/memory_watcher.rs`. It does not touch `src/codegraph/watcher.rs`: the code graph can be disabled while memory is on, and coupling codegraph to memory is unwanted.

DECISION: the live reconcile is SILENT. It sends NO `HostEvent::Reconcile` events. In Mnemo1 those events open the full-screen reconcile splash dialog (App.tsx / BootSplash), which must not pop up on every plan edit. It logs one eprintln line when it indexed or removed something, and one warning on failure. The startup reconcile and its events stay exactly as they are.

DECISION: the live pass runs only `corpus_is_stale` and then `index_derived` (noop progress). The startup-only sweeps (authored-row migration, quarantine_malformed, quarantine_old_synthetic, quarantine_git_state_facts, quarantine_duplicate_digests) and the memory health pass stay startup-only.

DECISION: no indexing of `.coding/openspec/changes/`. Archived changes are deliberately not current-state sources (see the doc comment on `scan_openspec` in `src/memory/indexer/openspec.rs`). Mnemo's own open spec deltas live in the plan files, which are already indexed. This plan adds no new source kinds.

Serialization: the live pass must hold the process-wide maintenance guard (`crate::host::maintenance::{claim_busy, BusyGuard}`), the same one the startup reconcile and the manual "Rebuild derived index" hold, so it never interleaves with them.

VERIFY (run each alone on its line, nothing piped or appended): `cargo test --workspace`; `cargo clippy --workspace --all-targets`. Focused: `cargo test -p mnemo memory_watcher`.

## Acceptance scenarios
- With Mnemo running, writing `.coding/openspec/specs/<cap>/spec.md` makes its requirements returned by memory_search within ~3 s, without restarting.
- Deleting that spec folder removes its SPEC rows within ~3 s.
- Writes to `.coding/knowledge/INDEX.md`, `HEALTH.md`, `memory.db*` or `logs/` trigger no reconcile pass (no loop).
- A live pass sends no HostEvent::Reconcile, so no reconcile dialog appears in Mnemo1 or Mnemo2.
- A live pass never runs at the same time as the startup reconcile or a manual Rebuild derived index (shared maintenance guard); a change that arrives while one runs is still indexed afterwards.
