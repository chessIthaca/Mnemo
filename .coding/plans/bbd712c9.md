# Plan: Park auto-continue while spawned subagents are running

## Goal
Park auto-continue while an agent has running tool-spawned descendants (reviewers etc.), instead of synthesizing up to 12 "[harness note] continue from where you left off." turns that can make no plan progress; resume exactly once via the existing child-completion Suggestion. Consistent with the dispatch state-transition gate (f7f2e2fc).

## Kind
bug_fixing

## Context
User report (2026-12-20 session): after spawning a reviewer, the parent got repeated "[harness note] continue from where you left off." messages — the user asked "Are we leaking info into the main agent?" Investigation ruled out a leak (notes are synthesized per-agent in src/runtime/agent.rs:240-249; the only parent-bound message is the child-completion notification via notify_parent_on_completion, events.rs:447-475). Root cause: auto-continue's None-arm gate checks ONLY `auto_continue_streak < MAX_AUTO_CONTINUE (12) && is_workflow_executing()` (agent.rs:224-227). A parent that ends its turn to wait for spawned children is indistinguishable from a stalled agent, so it gets up to 12 synthetic turns. Meanwhile the subagent-permission model (plan f7f2e2fc, review 2026-09-15) deliberately blocks ALL workflow state transitions while descendants run — dispatch.rs:184-189 gates create_plan/skill_start/abandon_plan/finish/skill_end/abandon_skill/complete_step with the error "cannot change workflow state while spawned subagents are still running" — observed live in round 1. So auto-continue turns during a child wait can make NO plan progress: pure token burn + transcript noise. The designed resume path exists: child Finished/final-Error → notify_parent_on_completion → Suggestion to the parent → the Suggestion arm (agent.rs:181-205) runs a follow-up turn REGARDLESS of streak. 

ALL REQUIRED MACHINERY EXISTS: AgentLoop already carries `descendant_tracker: Option<Arc<dyn DescendantTracker>>` (loop_impl.rs:262; builder with_descendant_tracker :657; factory wiring factory.rs:670-675 via set_descendant_tracker; prod impl = IpcSpawner, wired main.rs:356 + console.rs:847; trait + method: runtime/mod.rs:271-276 has_running_descendants(agent_id)). Dispatch uses it at dispatch.rs:184 (pattern: `if let Some(tracker) = &self.descendant_tracker { if let Some(id) = self.agent_id() { tracker.has_running_descendants(id).await } }`, None → skip gate). Test mocks exist: MockDescendantTracker (factory.rs:1709, cfg(test)), FixedDescendantTracker (agent/tests.rs:3214). Auto-continue e2e harness in agent.rs tests: auto_resume_fires_when_workflow_is_executing etc. (~agent.rs:2000-2260, CountingMockProvider; workflow must be Executing via create_plan BEFORE building the loop; MAX_AUTO_CONTINUE=12 const :59; streak reset on Prompt :526; field comment :42-47).

FIX DIRECTION: (1) Add `AgentLoop::has_running_descendants(&self) -> bool` (async? tracker method is async — mirror dispatch's tracker-then-agent_id pattern, None → false) near is_workflow_executing (loop_impl.rs:1535-1543). (2) Extend the None-arm gate (agent.rs:225-226): `&& !self.agent_loop.has_running_descendants().await` + comment update (:42-47, :217-223): waiting on tool-spawned descendants is a genuine block (the state machine already forbids transitions); the child-completion Suggestion resumes via the Suggestion arm which bypasses the gate. Note for reviewer: parking pauses a parent's OWN non-step work while children run, but since complete_step is itself gated during a child wait, no plan progress is possible anyway — auto-continue during a child wait is always pure spinning today; Suggestion-driven resume is the designed flow. ## Bug
A parent agent waiting on its tool-spawned background agents (e.g. a reviewer) gets spammed with "[harness note] continue from where you left off." synthetic turns: every normal turn end while the workflow is Executing triggers auto-continue (src/runtime/agent.rs:224-227), even though the parent is genuinely blocked — the state machine refuses all workflow transitions while subagents run. In the 2026-12-20 session this produced 5 spurious notes/LLM turns before the agent parked via ask_user; the child-completion Suggestion is the designed resume but never gets a chance because auto-continue fires first.
