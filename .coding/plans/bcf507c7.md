# Plan: Reap offline browsers — watchdog + marker-aware profile sweep

## Goal
Stop offline browsers from accumulating throughout a session: a headless Chromium that goes offline (process death or dropped CDP connection) is reaped promptly by a periodic watchdog instead of lazily on the next browser operation, and orphaned `mnemo-browser-*` profile dirs are swept periodically (not only at launch, not only >1h old) without ever touching a live manager's profile — in this or another process.

## Kind
bug_fixing

## Context
Root causes (verified by code read): L1 — dead-browser detection is lazy: only `ensure_browser` (called from `navigate`, src/browser/mod.rs:356) checks `handler.is_finished()`; no background liveness check exists. L2 — `sweep_stale_profiles` (src/browser/mod.rs:320-339) is called only from `ensure_browser` at launch time (line 286) and removes only >1h-old dirs; it cannot distinguish a live long-running profile from an orphan (the 1h cutoff is the only protection for other live instances, incl. other mnemo processes). L3 — `schedule_profile_removal` (src/browser/mod.rs:675) retries removal for only ~15s; a dir that outlives it (AV/crashpad locks) is orphaned until a future session's launch-time sweep. Audited, NO change needed: `ensure_webview` reconnect (src/browser/mod.rs:705) aborts the old handler task — abort drops the handler future, closing the CDP WebSocket; connect-mode owns no process. Child-WebView2 teardown (`browser_webview_destroy` src-tauri/src/ipc/browser_webview.rs:670 + RunEvent::Exit `take_webview` src-tauri/src/main.rs:850) is complete; hide-vs-destroy on tab switch is intentional (tab state). App exit already kills the launch-mode browser (`close()` in the RunEvent::Exit teardown, src-tauri/src/main.rs:843).

Fix design (no new deps — std `LazyLock`, `File::set_modified`): (1) process-wide live-profile registry `static LIVE_PROFILES: LazyLock<Mutex<HashSet<PathBuf>>>` in src/browser/mod.rs — registered at profile creation, unregistered at every take-site + `Drop for State`; (2) liveness marker `.mnemo-live` inside each profile dir — created at profile creation, touched every watchdog tick for registered profiles, backdated past grace on unregistration ("declare dead" → immediately sweepable); (3) watchdog task spawned lazily on first browser launch (handle in `State.watchdog`, respawned if finished, holds `Weak` to the state Arc so it exits when the manager drops) — each tick: reap dead browser via a `reap_dead_browser` helper refactored out of `ensure_browser`'s dead path (lines 249-278), touch markers, run the sweep via `spawn_blocking`; (4) marker-aware `sweep_orphan_profiles()` (pub, replaces `sweep_stale_profiles`): skip dirs in the registry (ours, live); skip dirs whose marker mtime is within MARKER_GRACE 15min (another live instance); remove dirs with stale markers (dead manager — age-independent); remove marker-less dirs only when >1h old (legacy conservative fallback). Called from the existing launch-time site, the watchdog tick, and app startup (main.rs setup via `tauri::async_runtime::spawn_blocking` — covers sessions that never launch a browser). (5) fix the `ensure_webview` concurrent-winner leak (src/browser/mod.rs:748-752): abort our just-spawned handler task before returning the winner's handle (the loser's task + CDP WebSocket currently live forever).

Regression-test design: (a) non-ignored unit test `sweep_reaps_orphans_but_never_live_profiles` — five `mnemo-browser-*` temp dirs (registered+fresh marker / unregistered+fresh marker / unregistered+backdated marker / no marker+>1h mtime / no marker+fresh mtime) → run sweep → assert only live + legacy-fresh survive; then unregister the registered one and assert a second sweep removes it (prompt reaping of our own orphans). (b) `#[ignore]` integration test `watchdog_reaps_dead_browser_without_subsequent_operation` (mirrors `respawn_after_close`, src/browser/mod.rs:1810): short reap interval, navigate to spawn, abort the handler task to simulate death, poll until `state.browser` is None (watchdog reaped with NO subsequent operation), then poll for the profile dir's removal.

## Bug
Offline browsers accumulate throughout a session (user report 2027-01-12, backlog 2ccf92b0): a headless Chromium that goes offline (process death or dropped CDP connection) is only cleaned up when the NEXT browser operation runs (`ensure_browser`, src/browser/mod.rs:248) — if none comes, the process (if the connection dropped while the process lives) and its `mnemo-browser-*` temp profile dir linger until app exit. Every respawn creates a fresh profile dir, and `sweep_stale_profiles` (src/browser/mod.rs:320) runs only at launch time and only removes dirs >1h old — so in-session orphans accumulate all session, and while the browser stays alive the sweep never runs at all.
