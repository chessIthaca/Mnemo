# Plan: Expose spawn_agent as an agent tool

## Goal
Add a spawn_agent agent tool so the LLM can start a background agent (e.g. to run a code review). Wire it through the AgentLoopFactory via a spawner abstraction, and bridge it to the real AgentManager in the Tauri IPC layer.

## Context
spawn_agent exists only as a Tauri command (src-tauri/src/ipc/commands.rs:224) callable from the frontend Sidebar. The agent's ToolRegistry (built in src/agent/factory.rs build_registry) has no spawn tool, so the LLM cannot start background agents. AgentLoopFactory::build() creates per-agent Workflow+ToolRegistry. AgentManager (src/runtime/mod.rs) handles next_id/register/fanin; AgentTask::new(id, name, loop).run(cmd_rx, fanin_tx) runs an agent. Tools implement the Tool trait (src/tool/mod.rs). The tool layer (src/) must not depend on the Tauri IPC layer, so introduce an AgentSpawner trait in src/runtime that the IPC layer implements with the real manager.

## Steps
- [x] 1. Define an AgentSpawner trait (name+task -> agent id) in src/runtime, with the returned info the tool needs.
- [x] 2. Create SpawnAgentTool in src/tool/agent/ holding an Arc<dyn AgentSpawner>; name='spawn_agent', category Agent, NeedsApproval; schema takes {name, task}.
- [x] 3. Add an optional spawner field + setter to AgentLoopFactory and register SpawnAgentTool in build_registry when a spawner is present.
- [x] 4. In src-tauri IPC layer, implement AgentSpawner against IpcState's manager+factory+agent_loops (reusing spawn logic) and set it on the factory at startup.
- [x] 5. Refactor the existing spawn_agent Tauri command to share the same spawn helper so UI and tool paths stay in sync.
- [x] 6. Run cargo build + cargo test; add a unit test that the tool is registered when a spawner is present and omitted otherwise.
