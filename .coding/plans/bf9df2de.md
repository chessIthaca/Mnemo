# Plan: Claude Code lead's search: record stale-index repairs in the staleness log

## Goal
The external lead's `search` and `search_read` write every stale-index repair to `<config dir>/index-staleness.jsonl` and point at it in their note, exactly like the in-app lead's tools.

## Kind
bug_fixing

## Context
WHY: observed 2026-11-14. Claude Code's `search` calls reported "reindexed 4 stale file(s) ... serving fresh index results" and later "reindexed 2 stale file(s) (src/tool/agent/search.rs, src/tool/agent/search_read.rs)", without the "; full list: index-staleness.jsonl" suffix, and `~/.mnemo/index-staleness.jsonl` was last written 2026-10-31. So we cannot tell why files went stale. docs/CONFIGURATION.md says the log "records every stale-index repair", which is false for this path.

ROOT CAUSE: src-tauri/src/mnemo2/mcp_server.rs `fn code_search_tools(root, graph, memory)` (about line 1347) builds `SearchTool::new(..)` and `SearchReadTool::new(..)` without `.with_staleness_log(..)`. Both tools then keep `staleness_log: None` (src/tool/agent/search.rs about line 512; search_read.rs about line 85), and `log_stale` (search.rs about line 1396) records nothing. The in-app lead's registry wires the log: the engine factory uses `StalenessLog::global()` (src/agent/factory.rs about line 593) and Mnemo2's graph tool uses `mnemo::index_staleness::StalenessLog::at(self.config_dir.clone())` (src-tauri/src/mnemo2/runtime.rs about line 568). The MCP server knows the config dir as `self.host.config_dir()` (a `PathBuf`; `LeadHost::config_dir`, used at mcp_server.rs about line 991).

FIX (one file, src-tauri/src/mnemo2/mcp_server.rs): give `code_search_tools` a fourth parameter `staleness_dir: Option<&Path>` and, when it is `Some`, wire `mnemo::index_staleness::StalenessLog::at(dir)` onto both tools. `call_tool` passes the host's config dir; `tool_list` (schema listing only) passes `None`. No change in the mnemo library.

REGRESSION TEST: `code_search_repairs_are_recorded_in_the_staleness_log` in the `tests` module of src-tauri/src/mnemo2/mcp_server.rs. It builds the tools with `code_search_tools(project, Some(indexed in-memory graph), None, Some(config_dir))`, edits an indexed file and moves its mtime 5 s ahead (the edit-to-watcher gap), runs `search` then (after a second edit) `search_read`, and asserts that each answer's note ends its stale-file sentence with "full list: index-staleness.jsonl" and that `<config_dir>/index-staleness.jsonl` holds a record with `tool` = "search" and one with `tool` = "search_read", both with `path` = "notes.md". Without the fix it fails: the note has no "full list" suffix and the log file does not exist.

VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib mcp_server` (the new test and the existing MCP tests, including `the_code_search_tools_are_listed_with_the_engines_own_schemas` and `search_and_search_read_answer_over_mcp`); `cargo clippy -p mnemo-app --all-targets --features mnemo2`; `cargo test --workspace --no-fail-fast` per agent.md. `#![deny(warnings)]` applies.
