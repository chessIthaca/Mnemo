# Plan: Workflow output + status bar UX tweaks

## Goal
Three small UX tweaks to workflow tool output + status bar: (1) make `complete_step` result echo `(N/total, PlanName)` compactly, (2) reword `finish` success to lead with "Finish review step", (3) revert the status-bar executing label to just `Executing x/y` (drop the `· header` suffix that takes too much room; the headline stays visible in the popout dropdown).

## Context
Findings from exploration:

1. `complete_step` output (src/tool/workflow/plan.rs:336-341) currently: `Complete Step {n} ({completed}/{total} done, state: {state}) of '{title}'`. User wants compact `(N/total, PlanName)` form. Confirmed format: `Complete Step 1 (1/5, Build Feature X) — state: Executing.` (state kept, moved after em-dash). The `data` JSON field already carries `plan_title`/`completed`/`total`/`state` — no data change needed, only the `output` string.

2. `finish` success output (src/tool/workflow/plan.rs:541-544) currently: `Plan closed out: review passed, state → Complete (report: {})`. User wants it to lead with "Finish review step". Confirmed format: `Finish review step — review passed, state → Complete (report: {})`. No test asserts on this output text (finish tests check `res.success` + state only).

3. StatusBar executing label (frontend/src/components/layout/StatusBar.tsx:375-397): currently builds `Executing ${x}/${total}${headerSuffix}` where `headerSuffix = header ? \` · ${header}\` : ""`. User wants just `Executing ${x}/${total}` — the `· header` takes too much room. The current step's headline is already shown in the popout dropdown (lines 580-604 map all steps showing `step.header ?? step.text`), so removing it from the inline label loses no info. No frontend test asserts on this label string.

Test impact: only `complete_step_echo_includes_plan_title` (plan.rs:942-958) asserts `result.output.contains("of 'Build Feature X'")` — must update to match new format. The plan title is "Build Feature X", 1 step → new output `Complete Step 1 (1/1, Build Feature X) — state: Reviewing.` so assert on `(1/1, Build Feature X)`.

Project: Windows 11, npm workspace at C:\myHarness. Rust tests via `cargo test`, frontend via `npm test --workspace frontend` / `npm run build`.
