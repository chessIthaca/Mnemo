# Plan: Fix: agent backlog_add emits backlog://changed so the Backlog tab updates live

## Goal
Make agent-side backlog_add items appear live in the Backlog tab by wiring a Tauri event notifier into the BacklogAddTool.

## Kind
implementation

## Context
Root cause (verified): src/tool/workflow/backlog.rs BacklogAddTool writes to the shared BacklogStore (same Arc the IPC commands lock) but has no Tauri event emitter — module docs at backlog.rs:14-20 explicitly say "the brain has no Tauri event emitter, so no backlog://changed event fires from here". The frontend only updates the Backlog tab from: the startup snapshot (App.tsx:188), the backlog://changed event (useAgentEvents.ts:128-130 → applyBacklogChanged), or the one-time backlogList() at mount (useAgentEvents.ts:408). So an agent-added item (id 69 verified on disk) is invisible until restart. Fix: inject an optional on_changed callback (Arc<dyn Fn() + Send + Sync>) into BacklogAddTool; the factory's backlog slot gains a notifier setter; main.rs wires a closure that spawns emit_backlog_changed (src-tauri/src/ipc/backlog_cmds.rs:67) on the tauri async runtime using app.handle().clone() + app.state::<IpcState>() (state is managed at line 374, before any agent runs). Construction sites to update: src/agent/factory.rs:654, src/tool/mod.rs:648 (test), backlog.rs:140 (test helper). Docs to update: backlog.rs module docs + tool schema description ("appears in the UI after the Backlog tab refreshes or the app restarts" → live), factory.rs:118-123 + set_backlog doc. No frontend change needed (event path already exists).
