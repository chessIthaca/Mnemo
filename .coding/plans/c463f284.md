# Plan: Clean up the remaining Mnemo1 mentions and Mnemo1 controls in Mnemo2

## Goal
Nothing in the code, Mnemo2's screens or the project docs refers to Mnemo1 as a live app: Mnemo2's settings stop showing and writing Mnemo1's routing switches, Mnemo2 sessions ignore the per-step routing lane like they already ignore per-turn routing, and every remaining mention is rewritten to describe what the code does now.

## Kind
implementation

## Context
WHY: the user asked (2026-11-11) to clean up the Mnemo1 mentions left after Mnemo1's retirement (PR #120) and the core cleanup (plan a7cabd27). 209 mentions remain in 69 files outside .coding/ and CHANGELOG.md; most are comments, but four places still act on Mnemo1:

1. Settings → Tiers top control (src-tauri/src/mnemo2/laya_settings.rs `save_tiers_top_control_core` / `tiers_top_control_writes`, `TiersTopControl.laya_routing`; mnemo2/src/components/TiersPage.svelte): every choice also writes `[general.laya] routing` (the "Mnemo1 half"), the page warns "Mnemo1's Laya routing flag on disk does not match this choice", and its description says it "turns Laya's routing on or off in Mnemo1". VERIFIED: `[general.laya] routing` is read only by per-turn routing (src/model_resolver.rs:432), which every Mnemo2 session skips (`skip_turn_routing`); Mnemo2's dispatch routing never reads it. So the top control stops writing it — no Mnemo2 behaviour changes.
2. The Laya settings list shows "Reflex (plan-step tiers, Mnemo1)" (mnemo2/src/lib/layaSettings.ts) and the status wire carries Mnemo1's routing gates (`Mnemo1Routing`: first-prompt gate, step-lane threshold, enforce). These go from Mnemo2's UI and wire.
3. VERIFIED: the reflex per-step lane (src/agent/turn.rs `step_lane_target`, called at turn.rs:577) does NOT check `skip_turn_routing`, so a Mnemo2 worker with `[general.laya] reflex` on would classify each plan step (and could switch models when `[general.routing] enforce` is on — off in the user's config). Mnemo2 routes once at dispatch (recorded decision), so `skip_turn_routing` must also skip the step lane; then hiding the Reflex toggle leaves no hidden switch that affects Mnemo2.
4. Settings → Models shows "Mnemo1's per-task models (planning, executing, bug fixing, reviewing) stay in the shared config.toml; Mnemo2 doesn't use them."

THE CORE STAYS A PUBLIC LIBRARY: the kernel keeps per-turn routing, the reflex lane, `[general.laya] routing`/`reflex`, `[general.routing]` (enforce etc.), the per-task model slots, and the `SettingsSaveDto` laya_routing/laya_reflex patch fields — embedders may use them. Only Mnemo2's UI/wire stops exposing them and Mnemo2 sessions stop entering them.

WORDING RULE (all steps): Mnemo1 is retired. Rewrite a mention to describe the current behaviour without naming Mnemo1 (e.g. "per-turn routing — a kernel feature Mnemo2 turns off", "the shared config.toml", "the per-task model slots"). Keep a mention only where code deals with what the retired app left on disk or guards against it coming back (legacy `runall-*` worktrees, retired config keys tolerated on load, the CI guard against frontend/ paths); there say "the retired Mnemo1 app". Test names may keep "mnemo1" only in those guard cases. Do not edit .coding/**, CHANGELOG.md or package-lock.json.

ORDER: steps 1, 2, 3 and 4 edit disjoint files and may run in parallel. Step 5 is the integration check.

VERIFY (each step, plus its own checks): cargo build -p mnemo2-app; cargo clippy --workspace --all-targets; cargo clippy -p mnemo-app --all-targets --features mnemo2; cargo test --workspace --no-fail-fast; cargo test -p mnemo-app --features mnemo2 --lib; when a step touches mnemo2/: npm test --workspace mnemo2 and npm run check --workspace mnemo2. #![deny(warnings)] applies. Final count: `git grep -ciE "mnemo1" -- . ':!.coding' ':!CHANGELOG.md' ':!package-lock.json'` — every remaining hit is a deliberate retired-app reference.
