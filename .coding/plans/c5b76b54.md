# Plan: Closing the Mnemo2 window: say it went to the tray, and let the user choose

## Goal
When closing the Mnemo2 window only hides it to the tray, the user is told once per run with an OS notification. A new setting (Settings > Appearance, "When I close the window") chooses Automatic (today's behaviour), Hide to tray, or Quit, and takes effect immediately.

## Kind
implementation

## Context
User report (2026-11-03): after closing the Mnemo2 window the process keeps running, which locks target/release/mnemo2.exe and blocks rebuilds. This is NOT the old tray-Quit hang (that fix landed: RunEvent::ExitRequested plus spawn_orderly_shutdown in src-tauri/src/mnemo2/mod.rs, bug record 'Mnemo2 tray Quit hung…'). It is the designed close-to-tray behaviour: a Mnemo2 started with `--hidden` (as the Claude Code plugin's helper does, src-tauri/src/bin/mnemo2_mcp/instance.rs ~893-899: `mnemo2 --hidden --project <root>`, including automatically whenever a Mnemo tool is called while Mnemo2 is not running) lives in the tray, and its window's CloseRequested handler only hides (mod.rs ~344-353: `CloseRequested { api, .. } if hidden => { api.prevent_close(); hider.hide(); }`). A non-hidden start closes and exits normally. The user chose: a toast plus a setting (keep close-to-tray available, because an attached Claude Code lead needs the process alive).

Existing pieces to reuse:
- the tray in install_tray (mod.rs ~214-246): Open, a Workers line and Quit;
- request_quit(app) (mod.rs ~184-212), which asks first while workers are running and then calls app.exit(0);
- starts_hidden(hidden, tray_ok) (mod.rs ~316);
- tauri_plugin_notification, already initialised (mod.rs ~450);
- Mnemo2's own global settings file <config_dir>/mnemo2.toml, which already holds [routing] via src-tauri/src/mnemo2/dispatch_routing.rs save_routing_settings (read-modify-write that keeps other tables, ~306-335);
- the Appearance settings page mnemo2/src/components/AppearancePage.svelte with its commands in src-tauri/src/mnemo2/appearance_settings.rs (appearance_settings_get/save, registered in mod.rs ~495), and its transport in mnemo2/src/lib/settingsEngine.ts.

Decisions:
- The setting lives in mnemo2.toml as `[window] close = "auto" | "tray" | "quit"`, default "auto", NOT in the shared config.toml (Mnemo1 never reads it).
- "auto" is today's behaviour: hide to tray when the window started hidden and a tray exists, else close and exit.
- "tray" always hides when a tray exists. Without a tray it closes normally, because there would be no way back.
- "quit" closes the app through request_quit, so running workers still get the confirmation dialog.
- The notification is shown at most once per process run, the first time a close hides to tray: title 'Mnemo2 is still running', body 'It keeps running in the tray. Use Quit in the tray menu to exit, or change this in Settings > Appearance.'. A notification failure is ignored.
- The behaviour is read live, so a save takes effect without a restart.

Verification:
- src-tauri: `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`, `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --bins`, `cargo build --manifest-path src-tauri/Cargo.toml --bins`.
- From mnemo2/: `npx svelte-check --tsconfig ./tsconfig.json`, `npx vitest run src/lib src/components`.
- No new #[allow(...)].

## Acceptance scenarios
- With the default Automatic setting, a Claude-started (hidden) Mnemo2 hides to the tray on close and shows one OS notification per run saying it is still running and how to quit.
- With 'Quit Mnemo2' selected, closing the window exits the process (through the tray-quit path, so running workers still get the confirmation).
- With 'Hide to the tray' selected, closing hides whenever a tray icon exists.
- Changing the setting takes effect without a restart, and it is stored in <config_dir>/mnemo2.toml [window] without disturbing [routing].
