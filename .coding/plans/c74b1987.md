# Plan: Laya async: explicit-choice dispatches never wait for the classification

## Goal
When a dispatch carries an explicit lead/user tier or model choice, start the worker without waiting for the Laya classification: run it in the background under the same permit and timeout, and attach the label (laya_tier, confidence, cleared) to the worker's routing record when it lands — preserving every training/calibration write. Non-explicit dispatches keep today's gating behavior exactly.

## Kind
implementation

## Context
Why: the user watched every dispatch hit the little LLM then reroute (2026-11-05) and asked for the classification to be async. Measured flow: route_implementation_dispatch (src-tauri/src/mnemo2/team.rs:1827) awaits classify_dispatch (team.rs:1893-1923) under a 3s timeout (team.rs:1916) and a serialized routing_permit semaphore (team.rs:1900-1904) BEFORE the has_explicit_choice branch (team.rs:1930) — so even lead-pinned dispatches pay up to 3s each, and concurrent dispatches queue behind the permit. The decision never gates an explicit-choice dispatch: refusals only occur on non-explicit paths (team.rs:1938-1958), so the wait is pure overhead; the label is recorded because every override is a training label.

Design: on has_explicit_choice (explicit tier or model, mode != Off — Off already skips classification entirely at team.rs:1865-1880), do NOT await the classification inline. Spawn a background task running the same classify_dispatch (same permit, same 3s timeout, same corpus write), and when it completes attach laya_tier/confidence/cleared to the worker's routing record — the nudge machinery (team.rs:1236-1263, reroute_row at :5109/:5172) is the established precedent for mutating a live worker's routing record. The dispatch returns immediately with those fields null; they are already Option and the UI renders nulls today (Off-mode dispatches carry routing: None entirely).

Constraints: non-explicit dispatch paths MUST be unchanged (Suggest+auto unsure → refusal team.rs:1938-1947; Auto+cleared → Laya's tier :1932-1937; Auto fallback :1948-1955; skip reasons too_short/one_tier/offline :1893-1923). Mnemo1's first-prompt gate (src/agent/model_routing.rs) is OUT of scope — a follow-up if wanted.

Files: src-tauri/src/mnemo2/team.rs (route_implementation_dispatch + the record-attach path), src-tauri/src/mnemo2/dispatch_routing.rs (classify_dispatch, corpus write), tests in team.rs (routing tests around :1236-15200) and dispatch_routing.rs. ## Spec changes

### dispatch-routing

#### ADDED Requirements

##### Requirement: Non-gating classification never blocks dispatch
When a dispatch carries an explicit lead or user tier or model choice, the system SHALL start the worker without waiting for the routing classification, SHALL run the classification in the background under the same permit and timeout, and SHALL attach its label to the worker's routing record when it completes, logging it as calibration and training data.

###### Scenario: Explicit-tier dispatch starts without the classification
- **WHEN** a lead dispatches with an explicit tier
- **WHEN** the routing classifier is still pending
- **THEN** the worker starts immediately
- **AND** the routing block shows routed_by lead with a null Laya label

###### Scenario: The background label lands on the record
- **WHEN** the background classification completes
- **THEN** the worker's routing record carries the Laya tier, confidence and cleared flag
- **AND** the training data records the override label

###### Scenario: Non-explicit dispatches still gate on the classification
- **WHEN** a dispatch carries no explicit tier or model choice
- **THEN** an unsure classifier refuses a Suggest+auto dispatch
- **AND** a cleared decision runs Laya's tier in Auto mode
- **AND** offline or too-short text produces the same skip reasons as before
