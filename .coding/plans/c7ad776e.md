# Plan: Pin jsdom at the workspace root so vitest finds it on a clean install

## Goal
A fresh `npm ci` installs jsdom 31.0.0 where vitest can resolve it, and `npm test --workspace mnemo2` passes in CI.

## Kind
implementation

## Context
WHY: PR 143 (release 2.7.0) fails CI "check" → "Mnemo2 unit tests": every test file fails with `Cannot find package 'jsdom' imported from …\node_modules\vitest\dist\chunks\…` (ERR_MODULE_NOT_FOUND). The jsdom pin (commit 634b3b11) set "jsdom": "31.0.0" in mnemo2/package.json, and npm placed it NESTED at mnemo2/node_modules/jsdom while removing the root node_modules/jsdom entry. vitest is hoisted to the root node_modules and resolves 'jsdom' from there, so on a clean install it finds nothing. Local checkouts passed only because they still had a stale root jsdom installed.

DECISION: keep jsdom at 31.0.0 (31.0.1 breaks LeadChat's scoped-CSS tests, memory BUG 35c49772), but make the root resolve it. Add to the ROOT package.json an npm `overrides` entry `"jsdom": "31.0.0"` (create the overrides object if absent), and keep mnemo2/package.json's devDependency at "31.0.0", so the dedupe hoists one jsdom 31.0.0 to root node_modules/jsdom. Then refresh package-lock.json with `npm install --package-lock-only`. Acceptable lockfile changes: jsdom's install entry moves to node_modules/jsdom@31.0.0, plus any of jsdom's own dependency entries that move with it. No other package's version may change.

VERIFY exactly like CI, on a CLEAN install: delete node_modules at the repo root and in mnemo2 (both, if present), run `npm ci` at the repo root, then `npm test --workspace mnemo2` and `npm run check --workspace mnemo2`. Also confirm `node -e "require.resolve('jsdom')"` run from the repo root resolves to node_modules/jsdom with version 31.0.0.

## Acceptance scenarios
- After deleting node_modules and running `npm ci` at the repo root, `npm test --workspace mnemo2` passes with no 'Cannot find package jsdom' error.
- package-lock.json has one jsdom install entry at node_modules/jsdom, version 31.0.0, and no other package version changed.
