# Plan: Knowledge-export dating: monotonic artifact floor beats stale wall clock

## Goal
Knowledge exports (filename date prefix + created front matter) never back-date: the stamped date is max(wall clock, newest on-disk artifact date), so a stale or rolled-back OS clock can no longer pin every export to 2026-09-01.

## Kind
bug_fixing

## Context
ROOT CAUSE (investigated): no hardcoded date exists — KnowledgeStore (src/memory/knowledge.rs) stamps the filename date prefix AND the front-matter created solely from the OS wall clock (SystemTime::now() wired in KnowledgeStore::new:467). This machine's clock is stale/pinned at 2026-09-01 (fresh git commits also read 2026-09-01) while real artifact dates reach 2026-12-19 (review filenames, code comments), so every export is back-dated. FIX STRATEGY: monotonic date floor — stamp new records with max(wall clock, newest strict YYYY-MM-DD stem prefix found on disk across the knowledge subdirs AND the sibling .coding/reviews/*.md — the reviews dir is knowledge_dir.parent()/reviews, guard with existence). YYYY-MM-DD compares lexicographically, so no epoch math. update() must keep preserving the existing created (it already does). write_at keeps slug-derived created when present (already does); only its clock fallback gets floored. The floor scan runs per write (dirs are small; the write path is already fs-bound). Multi-platform: pure std fs. Existing tests: make_store (knowledge.rs:897) pins the clock with no review fixtures → floor absent → current expectations unchanged. Supersede successor dating (test at :989) flows through the same floored stamp.
