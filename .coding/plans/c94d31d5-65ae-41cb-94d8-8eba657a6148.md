# Plan: Clickable workflow-state step picker in the status bar

## Goal
Make the workflow-state label in the status bar clickable so the user can open a dropdown of plan steps and mark one complete from the UI.

## Context
The StatusBar (frontend/src/components/layout/StatusBar.tsx) shows the workflow state as plain text at line 46. The workflow is shared as Arc<Mutex<Workflow>> in IpcState (src-tauri/src/ipc/state.rs). Workflow::complete_step(step_index) already exists in src/workflow/mod.rs and is tested. The agent loop emits WorkflowStateChanged/StepCompleted events after a complete_step tool call; the store bumps planVersion on these (useAgentStore.ts lines 496-512). PlanProgress subscribes to planVersion and refetches via getWorkflowState(). There is no Tauri command to complete a step from the UI — only the agent's complete_step tool can do it. The store has planVersion; StatusBar currently only reads workflowState (not the plan).

## Steps
- [x] 1. Add a `complete_step` Tauri command in src-tauri/src/ipc/commands.rs that locks the shared workflow, calls Workflow::complete_step(step_index), and returns the updated WorkflowStateInfo (state + plan).
- [x] 2. Register `complete_step` in the invoke_handler list in src-tauri/src/main.rs.
- [x] 3. Add a typed `completeStep(stepIndex)` wrapper in frontend/src/lib/tauri.ts.
- [x] 4. Update frontend/src/components/layout/StatusBar.tsx: fetch the plan (subscribe to planVersion), make the workflow-state label a clickable button that opens an upward dropdown listing the plan steps, and call completeStep on click — then update the store's workflowState + bump planVersion.
- [x] 5. Run cargo test to verify nothing breaks, then build the frontend to verify it compiles.
