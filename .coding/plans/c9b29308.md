# Plan: Lead side panel resizes freely; Plan tab shows only open plans

## Goal
The lead's side panel (Workbench and worker output panel) can be dragged as wide as the window allows while the lead keeps a usable minimum, and its Plan tab shows only the plans in progress now that Plans is a top-level tab.

## Kind
implementation

## Context
Why: the user found the lead's side panel "can't be resized much as the lead takes too much fixed shape". The lead is not the cause: verified: `mnemo2/src/lib/store.ts` `setWorkbenchWidth` (line ~1130) clamps to `Math.min(720, Math.max(320, workbenchWidth))`, while the lead column is `flex: 1; min-width: 0` (`mnemo2/src/App.svelte` `.lead-column`, `mnemo2/src/components/LeadChat.svelte` `.lead-workspace`). verified: both side panels share the width — `mnemo2/src/components/Workbench.svelte` and `mnemo2/src/components/WorkerPanel.svelte` render `style="width: {$app.workbenchWidth}px"` and resize through `actions.setWorkbenchWidth(window.innerWidth - event.clientX)` plus ArrowLeft/ArrowRight ±24. The width persists via `schedulePreferenceSave` (`workbench_width`).

Required behaviour:
1. Replace the fixed 720px ceiling with a window-relative one: max = window.innerWidth − a minimum lead width (about 420px; name the constant), min stays 320. Re-clamp when the window shrinks (a resize listener or a derived effective width) so a saved wide panel never squeezes the lead below its minimum. Keyboard resizing follows the same bounds.
2. The lead stays readable when narrow: `LeadChat.svelte` uses 32px side padding (`.lead-content`, `.composer-dock`, `.external-lead-bar`); reduce it when the lead column is narrow (a container query on the lead column is preferred over a viewport media query, because the panel, not the window, makes it narrow).
3. verified: `PlanTab.svelte` is mounted in the Workbench's "plan" tab (`Workbench.svelte` default branch) and in `PlansView.svelte` (top-level Plans route). In the Workbench, show only open plans (no closed section) and a small link "All plans" that opens the Plans route (`actions.openPlans`). Do this with a prop on PlanTab (e.g. `scope: "all" | "open"`, default "all") rather than a second component.
4. Do not change the Workbench tab list (Browser, Diff, Plan): another plan adds Files, Trace and Git later.

Verification: in `mnemo2/`: `npm run check`, `npm run check:no-mock`, `npx vitest run` (add store tests for the window-relative clamp and re-clamp, and a PlanTab test for scope "open"). Never start a dev server or any command that does not exit on its own; the lead renders previews.

## Acceptance scenarios
- At a 1600px window the side panel can be dragged to about 1180px wide, and the lead never gets narrower than its minimum.
- Shrinking the window after widening the panel shrinks the panel instead of squeezing the lead.
- The Workbench's Plan tab lists only open plans and links to the Plans tab; the Plans tab still lists open and closed plans.
