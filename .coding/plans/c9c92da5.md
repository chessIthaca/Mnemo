# Plan: Backlog soft delete with 30-day startup purge

## Goal
Make backlog deletion a soft delete (item stays in .coding/backlog.jsonl marked deleted_at, invisible to UI/dispatch/indexer) with hard purge of 30-day-old deleted items at every startup (inside BacklogStore::open), fixing the union-merge resurrection problem for free.

## Kind
implementation

## Context
Backlog item ccad2743. BacklogStore (src/backlog.rs, ~1656 lines) persists .coding/backlog.jsonl — one JSON item per line, git UNION-merged across worktrees (union merge concatenates lines; UUID ids make it collision-free). Current remove() (line 203) hard-deletes: retain + delete_item_images + persist — which a union merge from another worktree resurrects. Design: add deleted_at: Option<u64> to BacklogItem (serde default + skip_serializing_if so existing lines parse and live lines serialize identically); remove() marks deleted_at instead of dropping; items()/next_pending()/pending_item() and the by-id mutators (transition/annotate/set_note/requeue/edit) treat deleted items as invisible; clear_finished() soft-deletes too (same resurrection fix); open() purges items deleted >= 30 days ago (hard-remove + sidecar cleanup). Production open() sites: src-tauri/src/main.rs:306, src-tauri/src/ipc/spawn.rs:649, src/tool/workflow/backlog.rs. Memory indexer scan_backlog (src/memory/indexer.rs:589) must skip soft-deleted pending items. Frontend needs only an optional type field — no trash UI requested; recovery window is the JSONL itself.
