# Plan: Fix empty-assistant-message corruption on null turns

## Goal
Fix the "agent stops, then continue fails until restart" bug. Root cause: on a null turn (model returns Finish with no text and no tool calls), run_turn pushes an empty assistant message into the persistent history. That message is then rejected by validate_request_messages on every subsequent request, so run_turn_attempt retries 3x on the same failing messages, exhausts, and the session is wedged until restart.

## Kind
implementation

## Context


## Steps
- [x] 1. **Root-cause fix: don't push an empty assistant message on a null turn** — In src/agent/turn.rs, the `if tool_calls.is_empty()` block (~lines 903-921) currently pushes `MessageContent::text(text.clone())` even when `text` is empty (the null-turn case: model returned Finish with no TextDelta and no tool calls). Change it so that when `text.trim().is_empty()`, the pushed assistant message carries a minimal non-empty placeholder (e.g. "(no output)") instead of an empty string. This keeps the conversation history valid for the provider (which rejects empty assistant messages) while still recording that the assistant turn occurred. Leave the non-empty-text path unchanged.
- [x] 2. **Defensive recovery: repair existing empty assistant messages at turn start** — Add a free function `repair_empty_assistant_messages(messages: &mut [Message])` in src/agent/turn.rs that scans for any assistant message whose content is empty text (or empty parts) AND has no tool calls, and replaces its content with the same "(no output)" placeholder. Call it once near the top of `run_turn`, right after the provider/context_manager snapshot is taken and before the loop begins (around line 90, after the `let _ = fanin_tx.send(Started)` line). This recovers sessions already corrupted by the bug without requiring a restart — the user's exact situation.
- [x] 3. **Regression test: null turn doesn't corrupt history and a follow-up turn succeeds** — In src/agent/tests.rs, add a test `null_turn_does_not_corrupt_history` using MockProvider::sequence: first response is a bare `LlmEvent::Finish { reason: FinishReason::Stop }` (no TextDelta, no tool calls — the null turn), second response is `TextDelta("ok")` + `Finish`. Run two turns on the same `messages` vec. Assert after turn 1: no assistant message in `messages` has empty content (the bug would leave one). Assert after turn 2: the turn succeeds (returns Ok, not Err) and `outcome.text == "ok"` — proving the empty-message validation error no longer wedges the session. Use the existing make_registry helper + MockProvider::sequence pattern already in tests.rs.
- [x] 4. **Run cargo test and verify warning-free build** — Run `cargo test` (unpiped, check `$LASTEXITCODE`) and confirm all tests pass including the new regression test. Under #![deny(warnings)] a green build proves zero warnings. Fix any failures before marking complete.
