# Plan: Fix DeepSeek reasoning_content round-trip

## Goal
Round-trip `reasoning_content` on assistant messages so DeepSeek thinking-mode requests stop 400ing: capture reasoning text during a turn, persist it on the stored assistant Message, and emit it (or an empty string for foreign/no-reasoning messages) in the OpenAI-compatible request body. Includes regression tests per the constitution.

## Kind
implementation

## Context
DeepSeek models in thinking mode require every prior assistant message in the request's messages[] to carry the `reasoning_content` field; a missing field → HTTP 400 `invalid_request_error` ("The `reasoning_content` in the thinking mode must be passed back to the API"). Our app only consumes reasoning_content one-way: openai.rs:1219 parses it into LlmEvent::ReasoningDelta → turn.rs:689 → frontend thinking UI. It is never stored on Message (src/provider/mod.rs:121 struct has role/content/tool_calls/tool_call_id/name only) and never sent back (request builder at openai.rs:895-918). This breaks every follow-up request once a DeepSeek reasoning model is in play (skill-start model switch, provider switch, or native DeepSeek multi-turn). Confirmed via .coding/logs/provider-errors.jsonl (deepseek-v4-flash, 400s). The fix is to round-trip reasoning_content on assistant messages and emit it (or "" when absent) in the request body. Message is a plain struct built at ~40 sites (only role/content/tool_calls/tool_call_id/name), so a new serde-defaulted field needs `reasoning_content: None` at each construction site. Regression tests required by the constitution.

Then update every `Message { ... }` literal across src/ (turn.rs, agent.rs, context.rs, consolidation.rs, openai.rs tests, agent/tests.rs) to include `reasoning_content: None` (except where step 2 sets a value). Confirm no `..Default::default()` spread exists (Message has no Default derive).

Do NOT add it to user/tool/system messages (only assistant). This makes both DeepSeek-native turns (real reasoning echoed) and provider-switch turns (empty string) valid.
