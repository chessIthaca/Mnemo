# Plan: Tool output strips LLM special tokens — boundary-token round-trip escaping (verify + fix)

## Goal
Make special-token-containing files round-trip faithfully through the agent: read_files → write leaves the file unchanged. Root cause (verified): the app-side pipeline is clean (tool results carry the raw token; the request serialization is plain), but the serving layer strips/maps it so the model's textual view shows an empty string — the agent then writes back corrupted content. Fix: config-driven escaping of known boundary tokens (stop_boundary_strings) in tool results sent to the API — a visible, deterministic, reversible marker (⟦raw:\uXXXX…⟧) — restored on write by the file tools (file_write content, file_edit old_string + new_string). Acceptance: a fixture containing the token round-trips read → write unchanged (regression tests: the request body escapes tool-result content; the file tools restore the marker; the composed escape→restore round-trip is identity); cargo test + vitest green; the app-side/server-side split recorded (echo test) and the BUG memory superseded with the verified root cause.
