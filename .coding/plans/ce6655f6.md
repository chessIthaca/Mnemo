# Plan: Mnemo workers in Claude Desktop and short model names

## Goal
Claude Desktop shows Mnemo2's workers live: a status entry and a band above the prompt with each worker's name, short model name and status. Clicking a worker's name opens that worker's page in Mnemo2's mission control. Mnemo2 itself shows the same short model names (kimi, glm, deepseek-f).

## Kind
implementation

## Context
WHY: the user wants to see in Claude Desktop which Mnemo2 workers run and on which model, without switching windows. Clicking a worker name should open its page in mission control. Model names should read like people say them ("kimi", "glm"), with "-f" for flash models, in Claude Desktop and in the Mnemo2 app too.

DESIGN (decided with the user):
- Claude Desktop mod (a Claude Code plugin module drawing into Desktop): `$.ui.status` shows "Mnemo ▶<running> ◆<waiting on you>". An AbovePrompt band lists one row per worker (glyph, worker name as a link, short model, status, elapsed), shown only while a worker is active or waiting on the user. Worker names use Markdown links with onLinkPress, so a click runs the mod's handler, not a URL. There is no separate Mission control link and no buttons. Quiet outside a Mnemo2 project; "Mnemo2 not running" when it is down.
- The mod gets data from the helper: `mnemo2-mcp team-summary --json --cwd <dir>` on a timer (about 3-5 s while workers are active, 30 s idle) and right after any mcp__plugin_mnemo_mnemo__* tool call. It opens a worker with `mnemo2-mcp show-worker <worker_id> --cwd <dir>`.
- Both helper commands are READ-ONLY with respect to leadership: they must NOT attach the external lead (never MCP tools/call; see the test `only_tool_calls_and_the_waiter_attach_the_external_lead` in src-tauri/src/mnemo2/mcp_server.rs) and must NOT drain notices.
- Short model name rule (one implementation per language, same tests): drop everything up to the last '/', take the model name up to its first '-', lowercase it, and append "-f" if the model name contains "flash" (case-insensitive). Examples: "Kimi/kimi-k3.1-pro" -> "kimi"; "Ollama Cloud/glm-5.3" -> "glm"; "Ollama Cloud/deepseek-v4.1-flash:1017" -> "deepseek-f"; a name with no '-' stays whole (lowercased); empty -> empty.

WHERE (verified by grep/reading):
- verified: the helper's subcommands live in src-tauri/src/bin/mnemo2_mcp/ (hooks.rs `notices --drain|--session-start|--stop-check`, instance.rs finds/starts the app, http.rs talks to it). The session-start summary comes from the app's `/lead/notices` endpoint (hooks.rs:130-150, mcp_server.rs:668).
- verified: mcp_server.rs routes `/lead/notices`, `/lead/wait`, `/lead/gate-agent`, `/lead/detach`, `/lead/open` (:573-576, :668-669); `LeadHost::show_window` (:119) brings the window up; `EXTERNAL_OPEN_REQUEST_CHANNEL` shows how the backend asks the frontend to act.
- verified: mnemo2/src/components/ModelBadge.svelte is the one badge that prints a worker/lead model (used by WorkerRow.svelte:37 and others). mnemo2/src/lib/workerSelection.ts exists for selecting a worker.
- verified: the mod authoring API offers `$.ui.status`, a `ui.render` hook on `{ component: 'AbovePrompt' }`, `Markdown` with `onLinkPress`, `$.clock.every`, `$.process.run`.

DECISIONS:
1. Add app endpoints `/lead/summary` (POST {root} -> {workers:[{id, name, model, model_short, tier, status, needs_you, elapsed_ms}], open_plans, running, waiting}) and `/lead/show-worker` (POST {root, worker_id} -> shows the window and asks the frontend to open that worker in mission control). Neither attaches the external lead nor drains notices.
2. The helper gets `team-summary --json --cwd` and `show-worker <id> --cwd`. They print `{}` / exit quietly outside a registered project or when Mnemo2 is not running. team-summary never starts Mnemo2. show-worker may start Mnemo2 like the helper already does for serve.
3. The Rust short-name function lives in one shared place used by the endpoint (e.g. src-tauri/src/mnemo2/model_label.rs); the frontend gets mnemo2/src/lib/modelLabel.ts with the same rule and tests.
4. ModelBadge shows the short name and keeps the full model in its title/aria-label. Pickers (LeadModelPicker, ModelEffortPicker) keep full names.
5. The Desktop mod is built by the lead in this repository at mnemo2/claude-desktop-mod/mnemo-workers/ (plugin.json, hooks/hooks.json, hooks/register.tsx, types/index.d.ts, a mod test). The lead checks with `claude plugin validate` and `claude plugin test`.

## Acceptance scenarios
- `mnemo2-mcp team-summary --json --cwd C:/Mnemo` with Mnemo2 running prints the workers with model_short values like kimi, glm, deepseek-f, and the external lead state is unchanged (not attached by the call).
- `mnemo2-mcp team-summary --json` outside a registered project or with Mnemo2 down prints {} and exits 0 within a second.
- `mnemo2-mcp show-worker <id> --cwd C:/Mnemo` brings Mnemo2 to the front on mission control with that worker selected.
- Mnemo2's worker rows show short model names (kimi, glm, deepseek-f) with the full model in the tooltip.
- In Claude Desktop the status entry reads 'Mnemo ▶N ◆M', the band lists running and waiting workers with short model names, and clicking a worker name opens its page in mission control.
