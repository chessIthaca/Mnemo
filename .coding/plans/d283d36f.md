# Plan: Fix the v2.0.0 tag build: macOS O_NOFOLLOW type and a racy savings-ledger test

## Goal
The tag build compiles Mnemo2 on macOS and Linux and the recall-delta savings test no longer races, so v2.0.0 can be re-tagged and published.

## Kind
bug_fixing

## Context
Root causes (diagnosed by the lead from the run log):
1. src-tauri/src/mnemo2/workbench.rs, the file-open helper around lines 385-403, declares `const O_NOFOLLOW: u32` in its `#[cfg(target_os = "linux")]` and `#[cfg(target_os = "macos")]` blocks, but `std::os::unix::fs::OpenOptionsExt::custom_flags` takes `i32` (only the Windows extension takes u32). Windows builds never compile those blocks, so local checks missed it. Fix: declare both constants as `i32` (values unchanged: linux 0o400000 = 0x20000, macOS 0x100). Do not touch the Windows block.
2. src/agent/tests.rs `recall_delta_all_elided_set_costs_one_sentinel_line` (around line 20490) reads `store.savings_events_rows(None)` right after the turns, but `AgentLoop::record_savings_event` (src/agent/turn.rs ~4450) writes the durable row in a spawned task (fire-and-forget), so on a slow CI runner the row is not there yet. Fix the TEST only (production fire-and-forget is intended): poll `savings_events_rows` until a recall_delta row whose detail contains "sentinel" appears or 5 s pass (loop with `tokio::time::sleep(Duration::from_millis(25))`), then assert as today. Check the same file for other tests that read `savings_events_rows` immediately after a turn and apply the same small polling helper to them (one shared private async helper `wait_for_savings_row(store, predicate, timeout)` in tests.rs is preferred over copies).

Regression test: the macOS/Linux branch has no local test runner on Windows; verify the type with `cargo check -p mnemo-app --features mnemo2 --target x86_64-unknown-linux-gnu` if that target is installed (`rustup target list --installed`), otherwise state it could not be cross-checked; the existing unit tests cover behaviour. For the race, the regression test IS recall_delta_all_elided_set_costs_one_sentinel_line itself (fails intermittently without the wait under load).

Verification: `cargo test --lib recall_delta` and `cargo test --lib savings` (root crate), `cargo test --lib` (whole root lib), `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::workbench`, `cargo clippy --all-targets -- -D warnings`, `cargo clippy -p mnemo-app --all-targets --features mnemo2 -- -D warnings`.

## Acceptance scenarios

- recall_delta_all_elided_set_costs_one_sentinel_line waits for the spawned savings write instead of reading the ledger once
- Root lib tests and mnemo-app tests and clippy stay green
