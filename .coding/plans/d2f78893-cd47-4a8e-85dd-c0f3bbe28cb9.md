# Plan: Sanitize non-leading system messages for Local providers

## Goal
Fix LM Studio 'System message must be at the beginning' 500s by guaranteeing, at the request-serialization choke point, that a Local provider never receives a system message that isn't the first message — regardless of which upstream path (summary at index 1, suggestion re-injection, stray tail) produced it.

## Kind
implementation

## Context
Engine error: Jinja template 'System message must be at the beginning' on a predict request. turn.rs already guards the volatile tail + CONTEXT_FOOTER behind is_local, but other non-leading system messages are unguarded: context.rs summarize() and summarize_with_interrupt() place a Role::System summary at index 1 (lines ~194, ~312), and suggestion re-injection pushes Role::System at the end (turn.rs:208-216, runtime/agent.rs:469-475). OpenAiClient::build_request_json (src/provider/openai.rs:663) is the single serialization choke point; self.kind identifies ProviderKind::Local. Central fix here covers all paths.

## Steps
- [x] 1. **Add sanitize fn + apply in build_request_json** — In src/provider/openai.rs, add a helper `fn sanitize_local_messages(messages: &[Message]) -> Vec<Message>` (or Cow to avoid clones): keep messages[0] if system; for every subsequent message with Role::System, demote to Role::User with content prefixed `System: ` (preserves tool messages untouched). In build_request_json, when self.kind == ProviderKind::Local, run the sanitizer before serializing. Add doc comments explaining the LM Studio Jinja constraint.
- [x] 2. **Add unit tests** — In src/provider/openai.rs tests module: (1) Local request with a system message at index 0 and another at index 1/last → serialized JSON has system only at index 0, the others become `user` with `System: ` prefix; (2) OpenAI-kind request passes roles through unchanged; (3) all-user/tool messages unchanged for Local. Build request JSON via build_request_json with a Local client (kind: ProviderKind::Local, see test at line 1451).
- [x] 3. **Run cargo test + close out** — Run `cargo test` unpiped, confirm green + warning-free (deny(warnings)). Then spawn reviewer subagent on all uncommitted changes, fix every finding, re-run cargo test, commit to the current feature branch including the review report.
