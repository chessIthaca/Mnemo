# Plan: Read-only plan step viewer in status bar with Executing x/y label

## Goal
Make the status-bar workflow dropdown read-only (no marking steps complete) and change the label to show "Executing x/y" progress instead of just the state name. Remove the now-unused complete_step Tauri command chain.

## Context
The StatusBar (frontend/src/components/layout/StatusBar.tsx) has a clickable workflow-state label that opens a dropdown of plan steps. Each step is a button calling completeStep() → the Tauri command complete_step (src-tauri/src/ipc/commands.rs:253, registered in src-tauri/src/main.rs:151). This lets users mutate workflow state, which should be agent-only. The agent has its own separate CompleteStepTool (src/tool/workflow/plan.rs) — the Tauri command is purely a UI affordance with no test coverage (integration tests use the agent tool, not the IPC command). The completeStep TS wrapper lives in frontend/src/lib/tauri.ts:99. PlanFile/PlanStep types (frontend/src/lib/types.ts) give us steps[].done and steps.length for computing x/y. WorkflowState serializes as capitalized "Planning"/"Executing"/"Complete" (src/workflow/mod.rs Display impl).

## Steps
- [x] 1. Update frontend/src/components/layout/StatusBar.tsx: remove completeStep import + handleCompleteStep function; make dropdown steps read-only (divs, not buttons); change the label to show 'Executing x/y' (x = completed+1 capped at total, y = total) when executing with a plan, 'Complete' when complete; update titles/header text to reflect view-only.
- [x] 2. Remove the completeStep wrapper from frontend/src/lib/tauri.ts.
- [x] 3. Remove the complete_step Tauri command from src-tauri/src/ipc/commands.rs.
- [x] 4. Remove ipc::commands::complete_step from the invoke_handler list in src-tauri/src/main.rs.
- [x] 5. Run cargo test to verify nothing breaks, then build the frontend to verify it compiles.
