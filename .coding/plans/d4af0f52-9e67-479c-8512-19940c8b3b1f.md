# Plan: Config editing tab in Settings dialog (endpoints, models, API keys)

## Goal
Add a new "Endpoints" tab to the Settings (ConfigDialog) that lists all configured endpoints/models with editable fields (base_url, kind, API key in a password field, model name as a combobox datalist of the endpoint's models but also typable, reasoning_effort, default model/provider), plus Add and Delete buttons for endpoints and models. Changes persist to endpoints.toml / keys.toml / config.toml and re-sync the live provider.

## Context
Existing surfaces:
- ConfigDialog.tsx (frontend/src/components/layout/ConfigDialog.tsx) currently has Appearance + Colors + Preview; uses Radix Dialog. No tabs yet — I'll add Radix Tabs (primitives exist in ui/tabs.tsx) to split Appearance vs the new Endpoints tab.
- tauri.ts has getConfig() returning {general, endpoints, pricing} (no API keys) and setModel(endpoint, model, reasoningEffort). No save-endpoints command exists yet.
- IPC: get_config (commands.rs ~711) returns config WITHOUT keys. set_model (commands.rs ~441) validates model is in endpoint's list and rebuilds/swaps the provider. No write-to-disk for endpoints/keys/config currently (only projects.toml has save()).
- Config schema (src/config/endpoints.rs, keys.rs, general.rs, mod.rs): EndpointsFile {endpoint: Vec<Endpoint>, pricing}; Endpoint{name,kind,base_url,models,max_context,max_output_tokens,multimodal,reasoning_effort}; EndpointKind OpenAI|Local (serde rename_all lowercase); KeyStore {keys: HashMap<name->key>}; GeneralSection {default_provider, default_model, safety, vision_model}. global_config_dir() = %USERPROFILE%\.myharness. projects.rs has the save() pattern (toml::to_string_pretty + fs::write) to mirror.
- IpcState has config: Arc<Mutex<Config>> and factory: Option<Arc<AgentLoopFactory>>. factory.set_provider() + context_manager_for() swap live providers (used by set_model).
- StatusBar resyncFromBackend() + selectModel() show the dropdown pattern; there's a global "model" / "provider" / "reasoningEffort" in useAgentStore.
- EndpointKind serializes as lowercase ("openai"/"local") on disk but get_config sends format!("{:?}", e.kind) = "OpenAI"/"Local". Need to be careful: the frontend dropdown should send the lowercase serde value, and the save command must parse it back. I'll make the new save command accept kind as a string and parse via EndpointKind's serde (or map "OpenAI"→OpenAI).

Design decisions:
- New IPC command save_endpoints(endpoints, api_keys, default_provider, default_model) that: validates (names unique, base_url ends with /, models non-empty per endpoint ideally), writes endpoints.toml + keys.toml + config.toml (general section preserving safety/context/memory/ui), reloads Config, swaps into IpcState.config, and rebuilds/ swaps the live provider if the default endpoint/model changed.
- get_config should ALSO return the api_key per endpoint (masked? No — the user explicitly wants to see/edit the key in a password field). The current get_config deliberately omits keys. I'll add a SEPARATE command get_api_keys() returning a map name->key so keys are only fetched when the config tab is open, keeping get_config's no-secrets guarantee intact. Actually, since the tab needs them to populate the password field, a dedicated get_api_keys command is cleanest and least risky.
- Frontend: ConfigDialog gains Tabs {Appearance, Endpoints}. Endpoints tab: for each endpoint a card with name (text), kind (select openai/local), base_url (text), API key (password input with show/hide toggle), reasoning_effort (select max/high/medium/low/minimal/off), and a models list where each model row has a combobox (datalist of existing models + free text) + a delete (x) button, plus an "Add model" button. An "Add endpoint" button at the bottom creates a blank endpoint. A "Save" button persists everything via save_endpoints, then re-syncs store + StatusBar.
- Mark default endpoint/model: radio/select to choose which endpoint is default + which model is default (drives default_provider/default_model in config.toml).
- Usability: password show/hide, datalist for model names, inline validation errors, dirty-state "Save" enabling, confirm on endpoint delete (deletes its key too).
