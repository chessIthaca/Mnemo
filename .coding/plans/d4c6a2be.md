# Plan: One message box for the lead and every agent: steers while busy, closed when the agent is done

## Goal
The lead's composer and the agent reply box are one component with the same look and behaviour. An agent's box steers it while it works, says why when it can't take a message, and is disabled once the agent is done.

## Kind
implementation

## Context
WHY: the user asked whether the box at the bottom of an agent is shared with the lead. It is not. mnemo2/src/components/Composer.svelte holds the lead's input; mnemo2/src/components/WorkerThread.svelte has its own plain textarea and Send button. Both Mission Control (WorkerDetail) and the side panel (WorkerPanel) render WorkerThread, so one fix covers both.

WHAT IS WRONG TODAY in the agent box:
- Disabled only for `cancelled`. A merged worker's box stays open, and the backend refuses with "not running; resume it first" because merge removes the live session (src-tauri/src/mnemo2/team.rs). A finished audit is also refused.
- It clears the text before the backend accepts, so a refused message is lost. The lead's box clears only after acceptance.
- Nothing shows whether a send steers or starts a turn. The backend already does the right thing: `TeamRuntime::message` sends a busy worker `SessionCommand::Steer` and an idle one `SessionCommand::Prompt`. No backend change is needed.
- The draft dies when switching tabs or workers.
- WorkerDetail's toolbar "Steer" button sends one canned sentence instead of what the user wants to say.

DECISIONS ALREADY TAKEN (do not reopen):
- Done means the task is over: status `merged`, `merging` or `cancelled`, or an audit that delivered its report (`kind === "audit"` and (`reportDelivered === true` or status `completed`)). The box is disabled and says so.
- A `completed`, `in_review`, `conflict` or `failed` implementation worker stays open: the user may still ask for a change before merge, and that prompts the session.
- `stopped` and `interrupted` have no live session (stop removes it): disabled with a message pointing at Resume. Compacting: disabled, because the backend refuses while compacting.
- Images stay lead-only: `team_message` carries text only, so the worker box has no paste handler.
- The lead's question-answering, freeform mode, external-lead confirm, image attachments, model picker and status line stay in Composer.svelte. Only the input shell moves.
- Stop in the worker box is Pause (`actions.pauseWorker`), the same interrupt as the lead's Stop. It keeps the session steerable. `actions.stopWorker` would end the session.
- The canned Steer toolbar button and `actions.steerWorker` are removed.
- No Rust changes.

VERIFY: in mnemo2/: `npx vitest run`, `npx svelte-check --tsconfig ./tsconfig.json` (0 errors, 0 warnings), `npx vite build`. The Composer test file must pass with no edits: that proves the lead box did not change.

Scrolling: the user likes how the lead keeps the latest message in view while they are at the bottom and leaves them alone when they scroll up to read, and wants agents to do the same. The rule lives twice as copied code (LeadChat.svelte and WorkerThread.svelte's compact mode, both 48 px), and Mission Control's agent view does not have it at all: there the whole page scrolls, so nothing follows new messages and the message box scrolls away with the content. Decision: one shared follow helper, and the agent view always scrolls its messages on their own with the box pinned below, in Mission Control too. A worker's `compact` prop keeps only its other meanings (no duplicate failure block, smaller margin). The rule itself does not change, including no forced jump when the user sends while scrolled up. No Jump-to-latest button in this plan.

## Acceptance scenarios
- The lead's box and an agent's box are the same ComposerBox component and look the same.
- While an agent works, its box says Steer and a send reaches it as a steer without ending the turn; while idle, a send starts a turn.
- A merged, cancelled or finished-audit agent's box is disabled and says the agent is done.
- A stopped or interrupted agent's box is disabled and points at Resume.
- A refused message stays in the box; a half-typed message survives switching tabs or agents.
- Everything about the lead's box behaves as before: Composer.test.ts passes unedited.
- A completed or in-review agent's box is disabled and says the agent is done, and the lead can still message that agent through team_message.
- In Mission Control and the side panel, an agent's newest message stays in view while the reader is at the bottom, and scrolling up to read stops the follow until they return.
- In Mission Control the agent's message box stays visible below the scrolling messages.
- The lead's scrolling behaves as before, using the same helper.

## Decisions
- 2026-11-05: User decision, replacing the earlier one: the box is closed once the agent has completed its work. In workerBox rule 1, statuses `completed` and `in_review` join merged, merging and cancelled: mode done, placeholder `${n} is done`. `in_review` goes with `completed` because it is the same finished work under review; closing one and not the other would reopen the box when a review starts. Rule 6 now covers idle, conflict, failed, paused and any other status. A later fix round moves the worker to `fixing`, which reopens the box as a steer. This closes the user's box only: the backend and the lead's team_message are unchanged, so the lead can still send a completed worker back to work.
