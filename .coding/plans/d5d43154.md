# Plan: Per-model vision (multimodal) option

## Goal
Make vision (multimodal) support a per-model option on top of the endpoint-level default: `ModelSpec.multimodal: Option<bool>` overrides `Endpoint.multimodal`, so one Ollama endpoint can mix text-only (GLM) and vision-capable (GLM flash) models — and a vision-capable active model never falls back to the separate vision model (already gated per-provider by is_multimodal, so it follows from per-model resolution).

## Kind
implementation

## Context
Currently vision = endpoint-level flag: `Endpoint.multimodal: bool` (src/config/endpoints.rs:73, serde default false; doc says image blocks are stripped when false and the separate [general.vision_model] handles image-to-text). Per-model overrides ALREADY exist on `ModelSpec` (endpoints.rs:108 — max_context/max_output_tokens/reasoning_efforts) with the accessor pattern `endpoint.max_context_for(model_id)` / `effective_reasoning_effort_for(Some(model))`, and the TOML `[[endpoint.models]]` table form (legacy bare-string models still supported via From impls). The settings patch layer reuses the config type (patch.rs:39 `model_configs: Vec<crate::config::ModelSpec>`), so the patch carries a new ModelSpec field automatically. Consumption: config-layer reads pass the endpoint flag into client construction — client_factory.rs:198 (build_provider_for), src-tauri/src/main.rs:1079 (main provider), ipc/settings.rs:242-246 (save re-sync), ipc/config_io.rs:155, ipc/agent.rs set_model (~:413), possibly model_resolver.rs (429 fallback chain builds clients per model). The vision client path FORCES multimodal=true (client_factory.rs:82/93, test multimodal_override_is_respected) and must stay. Provider-layer `ProviderCapabilities.multimodal` (provider/mod.rs:48) is derived, not config — clients (openai.rs:349, anthropic.rs) strip image blocks on !caps.multimodal; agent/loop_impl.rs:1371 is_multimodal() + runtime attachment fallback gate the vision-model fallback on it — so once the flag resolves PER MODEL, a vision-capable model (GLM flash) gets images directly (no vision-model fallback) while a text-only model (GLM) on the same endpoint strips + falls back: the user's ask falls out of the resolution change. IPC/frontend: ipc/settings.rs has an endpoint DTO (multimodal: bool at :73/:355, mapped :131/:246/:621) and a per-model config DTO feeding tauri.ts `ModelConfigEditable` (models travel as a parallel `model_configs` array on EndpointEditable, tauri.ts:1093). Frontend UI: EndpointCard.tsx has the endpoint-level multimodal checkbox (:423) and a per-model editor (~:794-870, onChange patch {max_context, max_output_tokens, reasoning_efforts}) where a per-model vision toggle belongs. Frontend mapping in ProvidersSection.tsx:72 + types.ts (:209, :335). Docs: PLAN.md:792 describes the endpoint multimodal flag; general.rs VisionModel doc comment mentions "when the main provider is not multimodal". Tests exist: endpoints.rs multimodal_defaults_false/:546 multimodal_true_parsed + round-trips (:925-959), client_factory multimodal_override_is_respected:492, frontend types.test.ts/endpoints.test.ts fixtures with multimodal: false. Backlog item a634835c-de78-4e90-8d6f-74d2cdc3537e tracks this.
