# Plan: Pre-prompt model routing via the Laya classifier (backlog 091e694d)

## Goal
Opt-in, confidence-gated pre-prompt model routing: every main-agent user turn is classified by the Laya classifier as trivial vs architectural, and — only when enforcement is on, the answer is confident, and a target model is configured — the turn runs on the configured cheap (trivial) or capable (architectural) model instead of the state/default chain. Shadow-first: with enforcement off, every turn is classified and logged (decision + outcome rows in ~/.mnemo/laya/training/routing.jsonl) while model choice stays byte-identical to today. Config surfaces as a 6th block in Settings → Classifier (user-chosen placement).

Step 6 implementation note (deviation, deliberate): the routed turn emits NO custom transcript note / stderr line. Enforcement visibility rides the existing `AgentEvent::ModelChanged` (fired by `resolve_iteration_provider` whenever the served model changes, which a routed switch does), and shadow-mode visibility rides the routing log itself plus the Settings block (step 8). Rationale: a per-turn note would spam the transcript on every turn in shadow mode, the log IS the shadow-phase surface the item asks for, and the compaction-raise note precedent (`AgentEvent::Error` with `retrying: true`) would mislabel an informational event as an error. Also landed in step 6: `RoutingGate` carries its own `log_path` (`new` = `routing_log_path()`, `with_log_path` for tests) mirroring `KnnClassifier::new(..., training_log_path())`, so a test suite never appends to the real `~/.mnemo/laya/training/routing.jsonl`.
