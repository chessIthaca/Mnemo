# Plan: Model settings in Mnemo2: per-task, vision, code indexing, savings and budget

## Goal
Mnemo2's settings dialog lets the user choose the models Mnemo2 actually uses beyond the lead and worker tiers. That means per-task models (planning, executing, bug fixing, reviewing, summarize), the vision model, the code indexing (embedding) model with install status and a download button, the token-savings levers and per-model pricing, and budget caps.

## Kind
implementation

## Context
WHY: the user (2026-11-01) wants "the options dialog to set up the AI models and decision making models" and stressed "the code indexing models? that is what we need". Laya (decision models) gets its own plan; this plan covers the settings that already take effect in Mnemo2.

FINDINGS:
- Mnemo2 shares Mnemo1's config dir (resolve_config_dir(None), src-tauri/src/mnemo2/mod.rs ~line 209). Its engine builds through wire_brain (src/headless/engine.rs:819, src/host/brain.rs:342) with the model resolver ([models]), optimizer config and budget config (brain.rs:1176-1223) and a vision client. So [models], [general.optimizer], [general.budget], general.vision_model and the embedding settings change Mnemo2's behaviour. Each is read when the engine starts, so a change applies after reopening the project or restarting the lead; the UI must say so.
- verified: src/config/general.rs:92-93 `bundled_embedding_model: Option<String>` defaults to MiniLM (default_bundled_embedding_model, :894); the value "hash" means keyword-only. There is also an optional remote `embedding_model` (general.rs:77).
- verified: Mnemo2 starts its engine with `auto_install_embedder: false` (src-tauri/src/mnemo2/runtime.rs:919). A configured but not yet downloaded embedding model therefore leaves recall keyword-only in Mnemo2, with no way to install it from Mnemo2.
- verified: Mnemo1's embedding commands are in src-tauri/src/ipc/embeddings.rs: `list_bundled_embedding_models` (:74, lists curated models with an installed flag) and `download_bundled_model` (:93, background download emitting embedder://status). Mnemo1's settings UI lives in frontend/src/components/settings/sections/ (ModelsSection, VisionSection, EmbeddingSection, SavingsSection; model pickers in ModelCombobox.tsx and modelOptions.ts), backed by get_settings/save_settings (src-tauri/src/ipc/settings.rs:920 / :1177).
- verified: Mnemo2's settings today: mnemo2/src/components/SettingsDialog.svelte with EndpointsPage.svelte and TiersPage.svelte, backed by settings_endpoints (src-tauri/src/mnemo2/ipc.rs:1148) and settings_tiers (ipc.rs:1246).

DECISIONS:
- SettingsDialog gets two new pages beside Endpoints and Tiers.
  - Models: per-task model overrides (planning, executing, bug_fixing, reviewing, summarize; "Default" clears an override); vision model; code indexing model (curated list with installed badges, "Keyword only" for hash, Install button with progress, current status); budget caps.
  - Savings: optimizer lever switches with one-line explanations and knobs, plus a per-model pricing table.
- Model pickers list models from the configured endpoints (reuse settings_list_provider_models where possible) and allow free text.
- Saving writes only the keys a page owns, preserving the rest of config.toml (comments and unknown keys must survive, as Mnemo1's save_settings does). Show "applies after reopening the project" after a save.
- Drop from Mnemo1: per-skill overrides, default provider/model (Mnemo2 uses tiers and the lead picker), and Laya (separate plan).
- New Rust code lives in a new module src-tauri/src/mnemo2/model_settings.rs, registered in mod.rs. Reuse Mnemo1's settings and embedding functions where the mnemo2 binary can link them; do not fork their logic.

## Acceptance scenarios
- Settings shows Models and Savings pages next to Endpoints and Tiers.
- Choosing a per-task model and saving writes it to config.toml's [models] without losing other keys, and the page says it applies after reopening the project.
- The code indexing model list shows which models are installed; Install downloads the chosen model with visible progress and the status turns Ready.
- The Savings page toggles optimizer levers and edits per-model prices, and the Cost tab's dollar figures use those prices.

## Decisions
- 2026-11-01: Settings saves go through the shared path Setup::patch_settings -> validate_and_apply_settings_patch -> Config::save_all, exactly as Mnemo1's save_settings does. That path rewrites config.toml from the in-memory Config, so comments and unknown keys are not preserved (same as Mnemo1); every schema key outside the saved section must survive. Step 1 may make settings_setup/settings_refresh in src-tauri/src/mnemo2/ipc.rs pub(crate) and default_bundled_embedding_model in src/config/general.rs pub (visibility only).
