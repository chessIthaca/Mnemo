# Plan: SSE parser: move (not clone) each chunk's delta into RawAssistantDelta (mem-perf LOW 6)

## Goal
Eliminate the per-chunk delta JSON-map clone in the OpenAI SSE parser: move each choice's parsed delta value into the RawAssistantDelta event instead of cloning it (mem-perf review LOW 6).

## Kind
implementation

## Context
Mem-perf review LOW 6 (.coding/reviews/2027-01-06-full-review-memory-perf.md): src/provider/openai/sse.rs:323 clones every SSE chunk's delta JSON map into LlmEvent::RawAssistantDelta for the raw-echo/fallback-replay path — thousands of small clones per response (allocation churn, not growth; the accumulator merges into one map freed at request end). Facts established: parse_sse_chunk (sse.rs:167) takes &serde_json::Value; the typed extraction (text/reasoning/tool-calls) borrows the delta BEFORE the raw push and delta is never used after line 323, so the value can be moved; all 19 callers own their json (parse_sse_buffer at sse.rs:495 + 18 test sites in openai/tests.rs, all `parse_sse_chunk(&json)` with no json reuse after the call); the accumulator (stream.rs:112-120) only reads the event's delta. The alternative fix ("clone only the keys the raw echo requires") would violate Rule 1 — the raw echo is the verbatim source of truth preserving EVERY provider key (sse.rs:314-320 comment), so the move-based fix is the only correct one. The Responses-API parser (parse_responses_sse_chunk) emits no RawAssistantDelta, and the Anthropic parser emits it once per response (message_stop), not per chunk — both out of scope. Existing Rule-1 tests (TextDelta/ReasoningDelta/ToolCall* + RawAssistantDelta from the same chunk) already pin that typed extraction and the raw move both work per chunk.
