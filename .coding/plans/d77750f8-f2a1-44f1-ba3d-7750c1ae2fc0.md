# Plan: Clickable full-resolution screenshot viewer with Close + Copy

## Goal
Make tool screenshots in the agent window clickable: clicking opens a full-resolution lightbox (Radix Dialog, useBrowserOverlay) with a Close button and a Copy-image button (PNG to clipboard via ClipboardItem, data-URL text fallback).

## Kind
implementation

## Context
User request: "screenshots in the agent window look great. Can you make them clickable to open in a separate window in full resolution? It should have a button to close and copy the image."

Current state (researched):
- ToolImage (frontend/src/components/chat/ToolImage.tsx, 88 lines) renders each tool-produced image (image_* vision tools' `image` arg; browser_screenshot/game_screenshot data.path) as a lazy-loaded max-h-40 thumbnail via readImageDataUrl IPC (already the FULL data URL — only CSS-scaled down). Rendered per-path from Message.tsx ToolCard (lines 605-611), gated by Settings showToolImages.
- Modal pattern exists: Radix Dialog wrappers in frontend/src/components/ui/dialog.tsx (Dialog/DialogContent/DialogTitle/DialogDescription; overlay bg-black/60 z-50; Content = fixed center) — used by AboutDialog.tsx (header with X close button). useBrowserOverlay(open) hook (frontend/src/hooks/useBrowserOverlay.ts) must be called by any full-viewport modal so the native child WebView2 is hidden while open (AboutDialog does this).
- Copy precedent: CodeBlock.tsx uses navigator.clipboard.writeText + Check icon swap + 2s timeout.
- Tests run in vitest NODE env (no jsdom — see vite.config.ts / BacklogView.test.ts): component tests are STATIC SOURCE-CONTRACT tests (import source from "*.tsx?raw" + toContain) or pure-function tests. ToolImage.test.ts (7 pure tests of toolImagePaths) is the existing file.
- README.md line 56 documents inline tool images; will need a small extension.

Design decisions:
- Clickable thumbnail: wrap the thumbnail in a <button> (opens the lightbox dialog). Lightbox = Radix Dialog in ToolImage.tsx (new ImageLightbox component, exported for static-contract tests): header row (title = path basename + Copy button + Close X button) + scrollable body rendering the SAME dataUrl at natural size (full resolution — the thumbnail was only CSS-scaled). useBrowserOverlay(open) hides the native WebView2 child while open.
- Copy image: navigator.clipboard.write([new ClipboardItem({ "image/png": blob })]) where blob is built by decoding the data URL with atob → Uint8Array → new Blob (CSP-independent, no fetch); fallback to navigator.clipboard.writeText(dataUrl) on any failure; Check icon feedback for 2s like CodeBlock. ClipboardItem is supported in WebView2 (Chromium); fallback covers the rest.
- No Rust changes; no IPC; image is already loaded in the thumbnail's state — no extra IPC round-trip when opening.
- Leave user-attachment thumbnails (Message.tsx lines 176-187) untouched — the request is about agent-window screenshots.
