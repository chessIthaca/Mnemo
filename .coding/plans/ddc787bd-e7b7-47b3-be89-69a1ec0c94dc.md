# Plan: Endpoints: fetch model picker + base_url in collapsed card

## Goal
In the ConfigDialog Endpoints tab, (1) make clicking a model name fetch the live model list from that endpoint's OpenAI-compatible /models endpoint and let the user pick one to add to that entry, and (2) move the base_url field into the always-visible collapsed section of each endpoint card.

## Context
ConfigDialog.tsx EndpointsTab + EndpointCard render endpoint cards. Collapsed view (lines 847-862) shows kind+base_url+model count; expanded (864-1012) has kind select, base_url input, API key, effort, multimodal, models list, default radio. Backend src-tauri has no list-models command; OpenAiClient (src/provider/openai.rs) builds reqwest requests with Authorization Bearer. Key resolution: client_factory.rs resolve_api_key (stored key -> OPENAI_API_KEY env -> ANTHROPIC_AUTH_TOKEN env -> "dummy"). Config.key_for(name) reads keys. IpcState.config = Arc<Mutex<Config>>. No Popover UI component; StatusBar builds its model dropdown manually with absolute positioning + useRef outside-click (pattern to follow). reqwest+serde_json available in src-tauri Cargo.toml. Models list UI uses text inputs + datalist + add/delete.

## Steps
- [x] 1. Add a `list_models` Tauri command in src-tauri/src/ipc/commands.rs: takes `endpoint_name` (and optionally base_url + api_key to support unsaved/new cards), resolves the endpoint from config when name matches a saved endpoint (else uses the passed base_url/key), builds a reqwest GET `{base_url_trimmed}/models` with `Authorization: Bearer {key}` + connect timeout, parses the OpenAI `{ data: [ { id }, ... ] }` shape, returns sorted unique Vec<String> of model ids; on HTTP/parse error returns Err(human-readable string). Register it in src-tauri/src/main.rs invoke_handler.
- [x] 2. Add a typed wrapper `listModels(endpointName, baseUrl?, apiKey?)` in frontend/src/lib/tauri.ts that invokes `list_models` and returns string[]. Also export an `EndpointInfo`-derived note if needed (already exists).
