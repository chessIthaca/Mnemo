# Plan: 429-fallback viability via live token count (a117e827)

## Goal
Make try_429_fallback decide alternate-endpoint viability against the LIVE conversation size (plus headroom ≈ the alternate's summarize threshold) instead of comparing context windows, so mixed-window configurations of the same model id keep 429 failover; keep the window comparison as the fallback when no live count exists. Acceptance: a 429 on a 200k-window model fails over to a 128k-window alternate when the live conversation is small (rejected today); the same 429 still rejects the alternate when the live conversation genuinely exceeds it; cargo test --workspace green.

## Bug
A 429 on a model served with a 200k-window endpoint never fails over to an endpoint serving the same model with a 128k cap even when the live conversation is 20k tokens — try_429_fallback (src/agent/loop_impl.rs:1701-1710) compares context WINDOWS (alt_cm.max_tokens() < the current CM's max_tokens()), not the live conversation size. The turn fails once with "no viable alternate" and later turns keep hitting the rate-limited endpoint. Fails safe (no stall, no data loss) but silently disables failover for mixed-window configurations of the same model id (e.g. a proxy capping context below the direct endpoint).
