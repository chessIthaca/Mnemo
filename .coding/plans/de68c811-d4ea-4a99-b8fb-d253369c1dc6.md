# Plan: Research: macOS port of myharness

## Goal
Produce a concrete, evidence-backed assessment of what it would take to build/run myharness on macOS: which subsystems are already portable, which are Windows-locked (and how hard each is to port), plus packaging/distribution requirements. Output: a research report in .coding/analysis/. No source-code changes.

## Kind
research

## Context
myharness = Tauri 2 (features=["unstable"]) + Rust brain (src/) + React frontend (frontend/). Already known from scouting: (1) CREATE_NO_WINDOW flags are all behind #[cfg(windows)] (git_ops.rs, git.rs, git_diff.rs, files.rs, shell.rs) — portable by construction; (2) shell.rs is documented "platform-aware: PowerShell on Windows, sh elsewhere"; (3) keys.rs has BOTH #[cfg(windows)] and unix 0o600 branches; (4) the big Windows-locked subsystem is the live WebView2 stack: src-tauri/src/ipc/browser_webview.rs (native child WebView2 via wry, with_environment is #[cfg(windows)] in Tauri), src/webview_args.rs (WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS, CDP port 9222), src/browser/mod.rs live-CDP-attach + game_* tools, src-tauri/src/console.rs #[cfg(windows)] at :1459; (5) tauri.conf.json already ships icons/icon.icns and bundle.targets="all"; (6) safety_rules/cmd_class.rs is a PowerShell-specific classifier; (7) agent.md constitution hardcodes Windows 11 + PowerShell for the dev environment. Unresolved: exact main.rs window/child-webview topology on wry-macOS, dependency portability (fastembed/ort, chromiumoxide), console.rs cfg scope, who calls cmd_class on the sh path, .github CI presence.

## Steps
- [x] 1. **Inventory Windows-gated code paths (read the actual cfg blocks)** — Read the Windows-specific sites and classify each as (a) already dual-platform, (b) cfg-gated no-op on mac, or (c) genuinely Windows-locked needing a port: src/config/keys.rs (full), src/tool/agent/shell.rs (how the shell is chosen + is PowerShell assumed anywhere in output parsing), src/safety_rules/cmd_class.rs callers (search for cmd_class / classify usage — does the sh path use it?), src-tauri/src/console.rs around :1459, src-tauri/src/main.rs (window creation + child-webview topology + windows_subsystem attr), src-tauri/src/ipc/browser_webview.rs (full — the add_child usage), src/webview_args.rs, src/thread_util.rs. Note line refs for the report.
- [x] 2. **Audit dependency + config portability for aarch64-apple-darwin** — Read root Cargo.toml + src-tauri/Cargo.toml fully. For each notable dep (fastembed/ort, chromiumoxide, rusqlite bundled, reqwest rustls, tree-sitter crates, tiktoken-rs, syntect, tokio full, tauri 2 + plugins shell/dialog) record macOS support status (known-good vs needs-verification). Check global_config_dir()/home-dir resolution (src/config/mod.rs ~:358) for Windows-only path assumptions. Check for .github/workflows or other CI files (search glob .github/**). Check src-tauri/capabilities/*.json + gen/schemas for platform gates. Check frontend package.json + any backslash/path-separator assumptions in frontend/src (search for '\\' literals in *.ts/*.tsx).
- [x] 3. **Assess the WebView2/CDP subsystem port (the crux)** — Determine the macOS story for: (1) wry/Tauri child webviews on macOS (does Window::add_child work with WKWebView? known limits?) — use web_fetch on Tauri/wry docs or GitHub issues if needed; (2) CDP attach replacement — WKWebView has no --remote-debugging-port; options: Safari Web Inspector protocol (isInspectable, macOS 13.3+), or falling back to the existing headless-Chromium browser for game_* tools; (3) what breaks functionally if browser_webview/game_* are cfg'd out on mac (which agent tools disappear, what the UI shows). Deliverable: a ranked set of porting options with effort estimates.
- [x] 4. **Research macOS packaging/signing/CI requirements** — Use web_fetch on Tauri v2 docs (tauri.app) for macOS bundling: .app/.dmg targets, minimum macOS version, code signing (Developer ID), notarization (notarytool), universal2-apple-darwin vs per-arch builds, updater signing if applicable. Check tauri.conf.json gaps (bundle.macOS section absent, category, minimumSystemVersion, entitlements for local-network/localhost fetch). Summarize what a GitHub Actions macos-latest + tauri-action pipeline would look like. Also note the agent.md constitution impact: a Mac dev machine needs the env section generalized (Windows paths/PowerShell assumptions).
- [x] 5. **Write the research report + memory** — Write .coding/analysis/2026-08-20-macos-port-research.md with: TL;DR verdict (effort class: small/medium/large), a per-subsystem table (portable as-is / cfg-gated trivial / needs port with effort estimate), the WebView2→WKWebView options ranked, packaging/signing/CI checklist, constitution/tooling changes (agent.md, shell defaults, safety classifier for sh), and a suggested phased implementation order (M1: compile on mac, M2: functional parity minus live-CDP, M3: packaging/CI). Also write a semantic memory 'DECISION/RESEARCH: macOS port assessment' pointing at the report. No source changes.
