# Plan: load_tools renders revealed tools' schemas in the success response (cc52264b)

## Goal
load_tools' success response renders each newly revealed tool's schemas — name + required-parameter names and types for every tool, full mode (name + description + required + optional params) for groups of ≤ 8 tools, compact mode (name + required only) for larger groups like browser — for both static groups (browser/image) and MCP reveals, so the agent can pre-flight its calls immediately instead of re-calling load_tools (backlog cc52264b, the app-side fix for HOW memory 669b26e9).

## Kind
implementation

## Context
Architecture (verified by exploration): LoadToolsTool (src/tool/agent/load_tools.rs:33-168) holds only the shared LoadedGroups reveal-set, the group table, and Option<McpReveal> — no tool instances. The factory (src/agent/factory.rs:840-864) registers all tools first (browser behind #[cfg(feature = "browser")] at :850, image via register_vision_tool at :845), then registers LoadToolsTool LAST with registry.loaded_groups() + mcp_table + mcp_reveal. ToolRegistry (src/tool/mod.rs:667-738) exposes iter() (static tools + dynamic slot) and load_group filters by t.deferred_group() == Some(group) && t.available() — the same filter the renderer must apply. Deferred tools: browser (15 impls in src/tool/browser/mod.rs), image (7 impls in src/tool/agent/image_tools/tools.rs), McpTool (src/mcp/tool.rs:178). McpReveal::reveal_group (src/mcp/tool.rs:259-364) currently returns Result<usize> (a count); callers: load_tools.rs:151 + five test sites in src/mcp/tool.rs (:504, :635, :656, +2). ToolSchema (already imported in load_tools.rs:29) = name + description + parameters JSON (properties: name → {type, description}, required: [names]). Six LoadToolsTool::new test call sites in load_tools.rs (:185, :201, :219, :328, :348, :393).

Design decisions: (1) data-passing, not handles — the factory passes Arc clones of the deferred static tools (they never change at runtime); MCP schemas come back as reveal_group's return value; no new shared-handle/cycle concerns. (2) One renderer over &[ToolSchema], two modes: FULL for groups with ≤ 8 tools (image = 7 → full: name + description first sentence + required + optional params with types), COMPACT beyond (browser = 15 → name + required params only) — keeps the browser response under a sane byte budget (~16 short lines) so the deferral's token savings aren't undone. (3) The already-loaded response stays unchanged (the tools are in the compiled list by then; the HOW memory 669b26e9 covers the retry lesson — this change makes the lesson unnecessary by giving the first response everything the agent needs to pre-flight). (4) The existing "appear in your tool list from your next message on" lines stay (accurate). The file_edit interceptor is frozen this session — Rust edits go through the Python-surgery route (anchored, count==1 asserts, LF/UTF-8 preserved; remember: Rust \-continuations need \\ in the Python source).
