# Plan: Empty-call sweep: no-zero-argument rule + recovery hint on the six fumbled tools

## Goal
Make the six fumbled tools hard to call with no arguments, mirroring the read_files precedent (backlog 26cdbaf8 / plan 9e0b266a): shell, graph_search, graph_context, graph_path, git_read, and memory_write each get the no-zero-argument-form rule + one inline example + the rewrite-don't-resend recovery rule in their advertised descriptions, the recovery hint riding their empty-call errors (via the existing invalid_args_error helper for serde-path tools; graph_context's semantic either-or error for it), and a description + empty-call-error test pair per tool. Budget ceilings raised per the documented measured+headroom pattern. No behavior change beyond error text and descriptions.

## Kind
implementation

## Context
INVESTIGATION (code-verified this turn):

DESIGN DECISIONS:
(a) Compact canonical wording per tool, modeled on read_files but tighter: "Always pass `X` — e.g. {…}. No zero-argument form; on a required-field error rewrite the full call, do not resend the empty shape." (~130-200 chars per tool). The example shows the EXACT call shape (the read_files lesson: the shape must be unambiguous).
(b) The error hints reuse the existing pub(crate) invalid_args_error helper (imported from read_files.rs, the file_read precedent) for the serde-path tools (shell, graph_search, graph_path, git_read, memory_write); graph_context's hint rides its semantic either-or error instead (its serde path cannot fire on empty calls).
(c) Tests mirror the read_files pair per tool: a description test (rule + example + recovery asserted in schema().description) + an empty-call error test (execute(json!({})) → !success, the param named, "rewrite the full call", "do not resend the empty shape"). shell's existing tests get extended rather than duplicated.
(d) NO behavior change beyond the error text and descriptions — the item is a documentation/error-hint sweep (the scope lesson from plan 50f36b1e: evidence-based short list only — the six tools that actually fumbled, not a blind sweep).
(e) graph_context's schema gains no "required" array (id/name are genuinely either-or — adding one would break the name-only form); its description rule says "Always pass `id` (or `name`)".

CLASSIFICATION: kind=implementation — a multi-module robustness sweep (6 tools, 4 files: shell.rs, codegraph.rs, git_read_tool.rs, memory/mod.rs) adding description rules, error hints, and tests; the live empty-call fumbles (plan 263a9e31: ~a dozen rejected empty calls — read_files, shell ×2, graph_search ×2, memory_write ×2, git_read) are the motivation.
