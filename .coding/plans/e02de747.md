# Plan: Laya decision models work in Mnemo2

## Goal
Mnemo2's engine uses the Laya classifier like Mnemo1 does, for model routing (cheap vs capable lanes), memory auto-typing, failure triage and tool-choice reflexes. The user can set it up and configure it from Mnemo2's settings.

## Kind
implementation

## Context
WHY: the user (2026-11-01) wants the "decision making models" configurable in Mnemo2 and chose to wire Laya into Mnemo2 first, then add its settings.

FINDINGS (read-only survey of the code, file:line):
- The engine Mnemo2 runs is built through wire_brain (src/headless/engine.rs:819 -> src/host/brain.rs:342). The factory accepts with_auto_typing, with_routing_gate and with_reflex (brain.rs:1176-1223). These read a classifier slot that is None unless a host fills it.
- Mnemo1's host fills it; Mnemo2 attaches none. A comment in src-tauri/src/mnemo2/runtime.rs (~line 481) says so.
- Mnemo1's Classifier settings (frontend/src/components/settings/sections/ClassifierSection.tsx) write [general.laya], [general.routing] (cheap, capable, lane_medium, lane_high, escalate, threshold, enforce) and [general.budget]. Its commands are get_classifier_status (src-tauri/src/ipc/settings.rs:43), laya_catalog (src-tauri/src/ipc/laya.rs:112), laya_setup (laya.rs:132) and the checkpoint list. A managed Laya runtime (uv, venv, laya[serve], checkpoint download with progress) exists for Mnemo1 (src-tauri/src/ipc/laya.rs; see also src-tauri/src/ipc/finetune.rs startup_finetune_checkpoint).
- Mnemo2 shares Mnemo1's config dir, so [general.laya] and [general.routing] are already readable.

APPROACH: step 1 is design research with no code. It decides how Mnemo2 starts or attaches the managed laya-serve, fills the classifier slot for the lead's and workers' engines, and handles Laya being absent or down. Implementation steps are added after the design is reviewed.

VERIFY (for later implementation steps):
- cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::
- cargo clippy for both crates (clean)
- in mnemo2/: npm run check, npx vitest run

## Acceptance scenarios
- A written design names exactly where Mnemo2 fills the classifier slot, how laya-serve is started and stopped, and how Mnemo2 behaves when Laya is off or unavailable, with an implementation step list.
- After implementation, with Laya enabled in settings, a Mnemo2 lead turn records a routing decision and a memory write is auto-typed; with Laya disabled nothing changes.
