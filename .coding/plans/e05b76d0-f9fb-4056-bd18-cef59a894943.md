# Plan: Headless browser debugging: agent tools + right-panel browser tab

## Goal
A debuggable, agent-drivable headless browser with multi-page support, screenshots+console+input tools, a right-panel Browser view, and a vision loop — landed on the feature branch with tests green and review findings fixed.

## Context
Add a headless-Chromium (chromiumoxide) debug browser: a shared BrowserManager in the lib, a new ToolCategory::Browser with 10 tools (navigate/list/close/switch/screenshot/console/eval/click/type/snapshot), factory registration, screenshot→describe_image vision loop, a right-panel Browser tab (new RightPanelTab + RIGHT_PANEL_VIEWS entry + BrowserView.tsx + src-tauri IPC), console-event ring buffer with live push, then the standard closing sequence (cargo test → reviewer → fix findings → commit). Read tools visible in all workflow states; mutations (navigate/close/switch/eval/click/type) NeedsApproval. Screenshot PNGs land under .coding/browser/screenshots/ so describe_image's sandbox accepts them. Frontend img via base64 data URL (CSP img-src allows data:).

## Steps
- [x] 1. **Phase A: Browser manager + ToolCategory scaffolding** — New `src/browser/mod.rs` exposing `BrowserManager`, `PageInfo`, `BrowserError`. `BrowserManager` (Arc + tokio Mutex) lazily spawns a headless `chromiumoxide::Browser` on first use, tracks `pages: HashMap<String, chromiumoxide::Page>`, and recovers on crash. Add `chromiumoxide = "0.7"` (or latest) to `[dependencies]` in Cargo.toml; `pub mod browser;` in src/lib.rs. Add `ToolCategory::Browser` to src/tool/mod.rs + gate it in `ToolFilter::allows` (all four base variants: read AutoRun tools visible everywhere incl. Planning/Complete; mutation NeedsApproval tools visible in Executing/Reviewing, hidden in Planning/Complete like other writes). Unit test: spawn + open a `data:` page + list pages.
- [x] 2. **Phase B: Read-only browser tools** — New module `src/tool/browser/mod.rs` (+ `pub mod browser;` in src/tool/mod.rs). Tools, all `ToolCategory::Browser`, taking an optional `page_id` (default = active page): `browser_navigate` (NeedsApproval — opens URL, returns page_id+title), `browser_list_pages` (AutoRun), `browser_close_page` (NeedsApproval), `browser_screenshot` (AutoRun — PNG to `.coding/browser/screenshots/<page>-<ts>.png`, returns sandbox-relative path via Sandbox), `browser_console` (AutoRun — drain buffered entries), `browser_snapshot` (AutoRun — accessibility/DOM text dump). Each tool holds `Arc<BrowserManager>` + `Sandbox`. Register in a new `register_browser_tools` in src/agent/factory.rs alongside the other groups. Tests per tool with a live headless instance (dev-dependency-friendly).
- [x] 3. **Phase C: Input/mutation tools** — In `src/tool/browser/`: `browser_eval` (NeedsApproval — run JS, return JSON value), `browser_click` (NeedsApproval — CSS selector click), `browser_type` (NeedsApproval — focus + type text), `browser_switch_page` (NeedsApproval — set active page). Reuse the manager's page map. Tests: click/type against a local `data:` form page; eval returns a value.
- [x] 4. **Phase D: Parallel fan-out (spawn subagents)** — After A+B+C compile green, `spawn_agent` two subagents in parallel, each with a self-contained task + told to write code but NOT commit (main agent reviews/integrates): (D1) **Frontend Browser tab** — add `"browser"` to `RightPanelTab` in frontend/src/hooks/agentState.ts + `ALL_RIGHT_PANEL_TABS`; add entry `{ id: "browser", label: "Browser", icon: Globe, component: BrowserView }` to RIGHT_PANEL_VIEWS in frontend/src/hooks/rightPanelViews.tsx; add TOOL_META entry in frontend/src/components/layout/Sidebar.tsx; new `frontend/src/components/views/BrowserView.tsx` (page dropdown, refresh-screenshot button, screenshot <img>, console log). Wire IPC wrappers in frontend/src/lib/tauri.ts + types in frontend/src/lib/types.ts. Run `npm test`/vitest. (D2) **Tauri IPC commands** — new `src-tauri/src/ipc/browser.rs` with `#[tauri::command]` fns `browser_pages`, `browser_screenshot_latest` (returns base64 PNG), `browser_console`, `browser_open` calling the shared BrowserManager; register in `src-tauri/src/ipc/mod.rs` + `invoke_handler` in src-tauri/src/main.rs; add `browser: Arc<BrowserManager>` to `IpcState`/`AgentRuntimeContext` in src-tauri/src/ipc/state.rs. Then MAIN agent integrates both, runs `cargo test` + frontend vitest, fixes conflicts.
- [x] 5. **Phase E: Vision loop + docs** — Verify the loop: `browser_screenshot` returns a sandbox-relative path, then `describe_image` (already sandbox-validated + vision-wired in factory.rs) describes it — no new provider code. Add a short `.coding/browser-debugging.md` (or README section) showing the navigate→screenshot→describe_image workflow. Test: screenshot a data: page, describe_image on the path with a mock vision client.
- [x] 6. **Phase F: Console-event streaming + live UI push** — Subscribe to chromiumoxide `Runtime.consoleAPICalled`/`Log.entryAdded` events into a per-page ring buffer (VecDeque capped at ~500 entries) in BrowserManager; `browser_console` + IPC read from it. Push live entries to the frontend via a Tauri event `browser://console` (emit from a tokio forwarder); BrowserView subscribes via `listen`. Fallback: periodic refresh if push is flaky.
- [x] 7. **Phase G: Closing sequence** — `cargo test` (must be warning-free under #![deny(warnings)]; no #[allow] added). `spawn_agent` a read-only reviewer over ALL uncommitted changes (git status/diff HEAD): correctness, bugs, security, constitution compliance (warning-free build, doc comments on public fns). Read `.coding/reviews/<report>.md`, fix every finding (never defer), re-run cargo test. `git` commit all changes (including the review report) to the current feature branch with a clear message. Never touch main.
