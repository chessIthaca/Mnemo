# Plan: Short worker summaries in mission control

## Goal
Mission control shows each worker's task as a summary of at most three lines, in the worker list and in the worker detail header, with the full brief one click away.

## Kind
implementation

## Context
WHY: the user finds mission control hard to scan because every worker shows its entire brief, which for a lead-written brief is a page of instructions (goal, order of work, files, verification). They asked for a summary of about three lines per worker, with the rest expandable.

WHERE:
- verified: `grep -n` at plan time -> mnemo2/src/lib/store.ts:1894 `task: record.brief,` (the UI's `Worker.task` is the raw brief) and mnemo2/src/lib/types.ts:186 `task: string;`.
- verified: `grep -n` at plan time -> mnemo2/src/components/WorkerRow.svelte:36 `<span class="worker-task">{worker.task}</span>`; reading the file shows no CSS rule for `.worker-task`, so the row grows with the whole brief. WorkerRow is a `<button>` used by ControlRoom.svelte and TeamPeek.svelte.
- verified: `grep -n` at plan time -> mnemo2/src/components/WorkerDetail.svelte:85 `<h3>{worker.task}</h3>` (the whole brief as a heading).
- verified: `grep -n` at plan time -> mnemo2/src/components/AvatarStack.svelte:9 uses `worker.task` in the avatar `title` tooltip.
- verified: reading mnemo2/src/components/Collapsible.svelte -> props `maxHeight` (px, default 96) and `label`; it measures overflow with a ResizeObserver and only then shows a "Show more" / "Show less" toggle with aria-expanded. WorkerThread.svelte already wraps messages as `<Collapsible maxHeight={160} label="message"><Markdown source={entry.body} .../></Collapsible>`.

DECISIONS:
- Summary text: add a pure helper `briefSummary(brief: string): string` in a new file `mnemo2/src/lib/brief.ts`. It returns plain one-paragraph text for display: strip leading Markdown heading markers (`#`), list bullets and emphasis/backtick markers that would show as noise, collapse whitespace and newlines into single spaces, trim. It does not truncate by character count; the three-line limit is CSS. Audit briefs start with "# Independent read-only audit" followed by a paragraph; the summary of such a brief starts with "Independent read-only audit".
- Worker list row: show `briefSummary(worker.task)` clamped to three lines with CSS (`display: -webkit-box; -webkit-line-clamp: 3; -webkit-box-orient: vertical; overflow: hidden;`). No toggle inside the row: the row is a `<button>`, so a nested button would be invalid HTML; the full brief is in the worker detail, which the row opens. Give the summary a `title` with the summary text.
- Worker detail header: replace `<h3>{worker.task}</h3>` with the brief rendered by `Markdown` inside `Collapsible` with a maxHeight equal to about three lines of the detail text (choose the px value from the actual font size and line height and say which), `label="worker brief"`, so a long brief shows three lines and a "Show more" that expands it fully; a short brief shows no toggle. Keep it out of heading semantics (not an h3).
- AvatarStack tooltip: use `briefSummary(worker.task)` so the tooltip is not a page long.
- Do not change the backend, the Worker type, the store mapping or the thread view. The full brief stays available unchanged.

VERIFY (run in `mnemo2/`):
- `npm run check`
- `npm test` (vitest; add tests, see acceptance)
- jsdom does not lay out text, so Collapsible's measurement does not trigger in tests: test the helper directly, and test components for structure (the clamp class on the row summary, the Collapsible wrapper and Markdown render of the full brief in the detail), not for measured heights.

## Acceptance scenarios
- `npm test` in mnemo2 passes, including new tests: `briefSummary` turns a multi-paragraph Markdown brief (heading, bullets, backticks) into one plain paragraph, and an audit brief's summary starts with "Independent read-only audit".
- In the worker list, a worker with a page-long brief takes at most three lines of task text (the row summary element carries the three-line clamp), and clicking the row still opens the worker.
- In the worker detail, a long brief shows about three lines with a "Show more" toggle (aria-expanded false) that expands to the full brief rendered as Markdown; a one-line brief shows no toggle.
- `npm run check` in mnemo2 passes with no new errors or warnings.
