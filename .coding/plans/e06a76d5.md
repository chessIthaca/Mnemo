# Plan: Persist user cancels + append-only trace history archive (F3)

## Goal
Close the diagnostics data-loss gap (backlog 20bd12c5, F3): a user-cancelled request leaves a permanent record in a dedicated append-only .coding/logs/cancels.jsonl (written at stamping time, model/timestamps/phase/tokens included), and terminal trace records archive append-only to .coding/logs/traces-history.jsonl (rotated at 64 MiB, keeping the 4 newest archives) so a turn making 30+ requests can no longer erase earlier records retrievably. ## Bug
The diagnostics failure window is unrecoverable within minutes: .coding/logs/traces.jsonl mirrors the bounded 32-record in-memory ring (write_records_to_file rewrites the file from the ring snapshot each batch — src/provider/trace.rs:1375-1446; oldest-eviction :566 plus raw-byte-budget eviction :895; the module doc :1365 admits "recent history past 8 MiB, not a complete log"), so one busy turn (~25-30+ requests — the 2027-01-07 analysis turn made ~25) erases the previous turn's records: the deepseek hello-turn analysis lost failure records ids 1-3 before they were read. User cancels compound the gap: D1 (plan 814f27c9, landed) stamps them cancelled in-ring (terminal, not failed) but they still rotate out with the ring, and no dedicated persistent cancel record exists — D1 deliberately removed the provider-errors.jsonl row because cancels are not provider errors.
