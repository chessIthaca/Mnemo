# Plan: Mission control lets an unreported audit switch its model

## Goal
An audit worker that has not reported shows the model/effort picker like any worker and switches through the existing setWorkerModel action; an audit that reported stays read-only with an accurate tooltip.

## Kind
bug_fixing

## Context
ROOT CAUSE (verified): mnemo2/src/components/WorkerDetail.svelte `modelChangeable = $derived(!audit && models.some(...) && !["merging","merged","cancelled"].includes(worker.status))` excludes every audit, and its locked tooltip says "An audit worker's model is not user-switchable". The backend disagrees: src-tauri/src/mnemo2/team/control.rs `change_model_locked` refuses only `audit_finished(&record)` (an audit that reported), and team/tests.rs (~8790, `audit_dispatch` ... `.expect("unreported audit model switch")`) proves an unreported audit switches, stays out of the routing training log, and keeps its reroutes in its ledger. The control.rs doc comment on change_model ("An audit worker's model is never switchable") is stale. The same component already derives `auditFinished = audit && (worker.reportDelivered === true || worker.status === "completed")`.

DECISIONS:
- Changeable when `(!audit || !auditFinished)` and the existing model/status conditions hold.
- Locked tooltip: a finished audit reads "This audit has reported, so its model cannot change"; everything else keeps "This worker's task is over, so its model cannot change".
- Backend behavior unchanged; only its doc comment is corrected to: "An audit that delivered its report is locked; an audit that has not reported switches like any worker (its switches are never routing training labels)."

REGRESSION TEST: mnemo2/src/components/WorkerModel.test.ts — replace "keeps an audit worker's model read-only, even mid-run" with `it("lets an audit that has not reported switch its model", ...)`: render WorkerDetail with `{ ...worker("working"), kind: "audit", auditTarget: "ana", reportDelivered: false }`, find the model combobox, change it, and assert setWorkerModel was called with the audit's id and the new spec. It fails on today's code (no combobox). Add `it("keeps an audit that reported read-only", ...)` with `reportDelivered: true` (and status "completed"): no combobox, tooltip "This audit has reported, so its model cannot change".

VERIFY: `npm test --workspace mnemo2`, `npm run check --workspace mnemo2`; for the control.rs doc comment `cargo clippy --workspace --all-targets` (a doc-only change; no Rust test run is needed beyond the build clippy does). Run `npm ci --no-audit --no-fund` at the checkout root first if node_modules is missing.

## Acceptance scenarios
- In mission control, a working or stopped audit worker that has not delivered its report shows the model/effort picker; choosing another model calls setWorkerModel with that audit's id and the backend switches it.
- An audit that delivered its report shows its model read-only with the tooltip "This audit has reported, so its model cannot change".
