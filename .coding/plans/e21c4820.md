# Plan: A tier can run as a Claude Code agent (Opus, Sonnet, Haiku, Fable)

## Goal
In Settings → Tiers the user can set a tier to run as a Claude Code agent with a chosen Claude model. When Claude Code leads and a dispatch lands on that tier, Mnemo prepares the worktree and branch and hands the step to the lead's own Agent (no approval prompt); review and merge stay the normal Mnemo flow.

## Kind
implementation

## Context
WHY: the user leads Mnemo projects from Claude Code. In FactoryGame they keep high-risk steps on Claude Opus agents (and Blender work on Fable), outside Mnemo's worker flow, and each Claude Agent launch is prompted by the Mnemo plugin's gate-agent hook even in bypass mode. They asked for the option in the Tiers dialog so a tier can say "this runs on a Claude Code agent", while everything else (plan board, review, audit, merge) stays Mnemo. Claude models cannot be Mnemo endpoints through the subscription (user ruled that out for ToS reasons), so the agent is run BY the Claude Code lead with its own Agent tool; Mnemo only prepares, gates and tracks it.

DECISIONS (taken; do not reopen):
1. Per-tier setting `claude_agent`: one of "opus", "sonnet", "haiku", "fable", or absent. Stored on the `[[tier]]` table in ~/.mnemo/endpoints.toml (src/config/endpoints.rs `Tier`, serde default, omitted when absent so existing files round-trip byte-identical). The `escalate` tier cannot carry it (validation error "the escalate tier cannot run as a Claude Code agent"). The model list stays as it is: it is what the tier runs on when no Claude Code lead is attached (the in-app lead), with normal fold-down. Trivial still must have a model.
2. Which tier counts: the tier routing SETTLED ON before fold-down (the lead's explicit tier, or Laya's cleared tier in auto/suggest). A `high` tier with claude_agent and no models is still an agent tier when Claude Code leads. When no external lead is attached, claude_agent is ignored and the tier resolves exactly as today.
3. Agent dispatch (team_dispatch from the external lead, routed to an agent tier): every gate and the provisioning run as today (plan/step gates, slots, pool checkout `.worktrees/pool-<n>` on `wt/agent-<id8>`, routing rows, the worker record), but no Mnemo LLM session is started: no `start_worker`/engine.spawn, no pump. The record gets `claude_agent: Some(model)` (new persisted WorkerRecord field, serde default None), status `Working`, `model` shows `claude-code/<model>`. The pending-classification spawn may still run (it only labels routing). The dispatch result gains `claude_agent: {model, worktree, branch, prompt}` in both the text JSON (`result.claude_agent`) and `data`. `prompt` is the full self-contained task text for the Agent: the same plan/step/brief kickoff a Mnemo worker would get (reuse the existing kickoff/brief builder, do not duplicate it) plus the worker rules that matter outside Mnemo: work only inside <absolute worktree path> (cd there first; never touch C:\Mnemo or other checkouts), commit on <branch>, never push, never git stash, never merge, run the `.coding/checks.toml` commands before the last commit, end with a report of commit hash, checks run and results, and anything left open.
4. New lead tool `team_agent_done {worker_id: string, report: string, failed?: bool}`: only for workers with claude_agent set and status Working or Interrupted (anything else is refused with the reason). It records `report` as the worker's final report, sets status Completed (or Failed when failed=true) and bumps the turn as pump.rs does on Finished, persists, and delivers the normal "finished its turn" notice to the external lead (same text shape as finished_notice so the review skill applies; if the tagged notice path needs a session event, deliver an untagged notice through the external-lead notice queue instead). After it, team_check / team_review / team_merge work unchanged: the lead runs team_check on the tip because the agent's own shell runs are not recorded by Mnemo.
5. Tools that drive a Mnemo session refuse a claude_agent worker with guidance instead of acting: team_message, team_resume, team_route_fix, team_compact → "<id> runs as a Claude Code agent: continue it with your own Agent (SendMessage to it, or a new Agent with the fix), then call team_agent_done." team_stop still works (cancels the record; the lead stops its own agent). On reopen, recover_worker may turn it Interrupted; team_agent_done accepts that.
6. Agent gate: `gate_agent` (src-tauri/src/mnemo2/mcp_server.rs ~1038) also returns allow, reason "runs Mnemo worker <id> (<tier> tier) as a Claude Code agent", when the attached team has at least one claude_agent worker in status Working. Otherwise the decision is unchanged (agents_without_prompt, ask).
7. Tier guidance text the lead sees (routing.rs `tier_guidance` ~959, line format ~995): an agent tier's line appends exactly `; runs as a Claude Code agent (<model>) when Claude Code leads`. If the tier has no models, the line still appears, naming the fold target's model as today followed by that suffix. The TS preview `dispatchPreview` in TiersPage.svelte (~363) must produce the identical line.
8. UI: each tier card except escalate gets a "Run as" select: "Mnemo models" (null) / "Claude Code agent — Opus" / "— Sonnet" / "— Haiku" / "— Fable". Part of the ladder draft, saved with "Save tiers", tracked by the unsaved-edits guard like the other ladder fields. Hint under it when set: "When Claude Code leads, this tier runs on your Claude Code agent; the models above are used otherwise."

## Acceptance scenarios
- With Claude Code attached as lead and the High tier set to claude_agent=opus, team_dispatch(tier=high) returns a claude_agent block with model opus, an existing .worktrees/pool-<n> worktree on wt/agent-<id8>, and a prompt that names that worktree; team_status shows the worker Working with no Mnemo session and model claude-code/opus.
- While that worker is Working, the gate-agent hook endpoint (/lead/gate-agent) answers allow for subagent_type general-purpose; after team_agent_done it answers ask again.
- After the agent commits in the worktree, team_agent_done delivers a 'finished its turn' notice; team_check, team_review and team_merge then merge the branch into wt/mnemo exactly as for a Mnemo worker.
- With no external lead (in-app lead or IPC dispatch), the same High tier dispatch starts a normal Mnemo worker on High's models.
- In Settings → Tiers, choosing 'Claude Code agent — Opus' on High and saving writes `claude_agent = "opus"` under the high [[tier]] in ~/.mnemo/endpoints.toml; a ladder without the setting saves byte-identical to before; the escalate card has no Run as choice.
- 'What the lead sees' shows the High line ending in '; runs as a Claude Code agent (opus) when Claude Code leads', and the team_dispatch tier description shows the same line.

## Spec changes

### tier-ladder

#### ADDED Requirements

##### Requirement: A tier can run as a Claude Code agent
Every tier except escalate MAY carry `claude_agent` set to opus, sonnet, haiku or fable. When an external Claude Code lead is attached and a dispatch settles on such a tier, the step SHALL be handed to the lead's own Claude Code agent with that model instead of a Mnemo worker session; without an external lead the tier SHALL resolve to its models exactly as before.

###### Scenario: Agent tier with Claude Code leading
- **WHEN** Claude Code is attached as lead
- **WHEN** the high tier has claude_agent opus
- **WHEN** the lead dispatches a step on high
- **THEN** the result carries a claude_agent block with the worktree, branch and prompt
- **AND** no Mnemo worker session is started

###### Scenario: Agent tier with the in-app lead
- **WHEN** no external lead is attached
- **WHEN** the high tier has claude_agent opus and a model
- **THEN** the dispatch starts a Mnemo worker on that model

###### Scenario: Escalate cannot be an agent tier
- **WHEN** a ladder sets claude_agent on escalate
- **THEN** saving the ladder fails with a validation error

### external-lead

#### ADDED Requirements

##### Requirement: The lead finishes a Claude Code agent worker
A worker handed to a Claude Code agent SHALL become finished only through team_agent_done, which records the report, marks the worker completed or failed and delivers the finished notice to the external lead. While such a worker is working, the agent gate SHALL allow the lead's Agent calls without asking.

###### Scenario: Agent worker reaches review
- **WHEN** the lead's agent committed in the worker's worktree
- **WHEN** the lead calls team_agent_done with a report
- **THEN** the worker is completed and a finished notice reaches the lead
- **AND** team_check, team_review and team_merge work as for any worker

###### Scenario: Gate lets the agent run
- **WHEN** an agent-tier worker is working
- **WHEN** the gate-agent hook asks about subagent_type general-purpose
- **THEN** the decision is allow

### dispatch-routing

#### ADDED Requirements

##### Requirement: Agent tiers are decided before fold-down
Whether a dispatch goes to a Claude Code agent SHALL be decided from the tier routing settled on (the lead's explicit tier or Laya's cleared tier) before an empty tier folds down.

###### Scenario: Empty agent tier
- **WHEN** the high tier has claude_agent opus and no models
- **WHEN** Claude Code leads and dispatches on high
- **THEN** the step is handed to the Claude Code agent

### worker-brief

#### ADDED Requirements

##### Requirement: The agent prompt carries the worker brief
The prompt handed to a Claude Code agent SHALL contain the same plan, step and brief a Mnemo worker receives, plus the worktree it must work in, the branch to commit on, and the rules never push, never git stash, never merge, and run the project checks before the last commit.

###### Scenario: Prompt contents
- **WHEN** a step is handed to a Claude Code agent
- **THEN** the prompt names the worktree path and branch
- **AND** the prompt contains the step text and the brief

### settings-dialog

#### ADDED Requirements

##### Requirement: The Tiers page offers Run as a Claude Code agent
Each tier card except escalate SHALL offer a Run as choice between Mnemo models and a Claude Code agent with Opus, Sonnet, Haiku or Fable, saved with the ladder.

###### Scenario: Choose Opus for high
- **WHEN** the user picks Claude Code agent — Opus on the High card and saves
- **THEN** endpoints.toml stores claude_agent opus on the high tier
- **AND** the lead preview shows the agent suffix on the High line
