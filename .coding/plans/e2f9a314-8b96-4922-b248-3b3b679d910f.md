# Plan: Fix flaky agent_md mtime test

## Goal
Make the agent_md mtime tests deterministic: replace the wall-clock sleep in source_rereads_after_mtime_change with an explicit mtime bump via std::fs::FileTimes, remove the needless sleep in source_handles_missing_files, and prove the tests are stable under repetition.

## Kind
implementation

## Context
Flake seen once during the model-picker fix: `project::agent_md::tests::source_rereads_after_mtime_change` panicked ("reload should detect the mtime change"). Root cause: the test writes "GLOBAL v2" then sleeps 1100ms hoping the filesystem clock gives write #2 a different mtime than write #1, but reload_if_changed (agent_md.rs:70-98) compares `SystemTime` for EXACT equality — on a filesystem with coarse timestamp granularity (FAT = 2s) or when the wall clock steps backwards (NTP slew), both writes land on the same mtime and the change is missed. Wall-clock waiting is inherently racy; the fix is to set the mtime deterministically with std::fs::FileTimes (`File::set_times`, stable since Rust 1.75 — no new dependency). Sibling test `source_handles_missing_files` also sleeps 1100ms but is NOT flaky (missing→present is a None→Some mtime transition, tick-independent) — the sleep is pure slowdown, remove it. Production `reload_if_changed` semantics stay unchanged (exact-mtime comparison is the documented design; the same-tick-edit limitation is a pre-existing trade-off, out of scope). Current branch feat/fix-model-picker-label is clean + unmerged; create a NEW branch from main for this unrelated fix. Windows/PowerShell, cargo test unpiped.
