# Plan: multi_edit tool + compact line-op syntax for file_edit

## Goal
Cut the per-change cost of file edits: a shared op engine (src/tool/agent/edit_ops.rs) gains a compact line-op grammar (i/b/d/r verbs, ranges, payload) usable from file_edit's new `ops` field, and a new atomic multi-file tool (src/tool/agent/multi_edit.rs, files:[{path, ops}]) applies every file all-or-nothing with one combined diff preview — plus the frontend approval/card support, the dispatch/steering gates, the strict-schema and budget accounting, and a measured old-vs-new token delta.

## Kind
implementation

## Context
FEATURE (backlog 2e27f896). Today every change costs a byte-exact old_string anchor plus one approval per file; line-targeted changes must first read the text and then echo it byte-exact as the anchor — pure token overhead.

DESIGN (decided):
(1) NEW src/tool/agent/edit_ops.rs = the shared op engine (parse + apply), used by BOTH file_edit and the new multi_edit. file_edit's batch field is advertised as `ops` — a polymorphic array carrying compact strings AND EditItem anchor objects — with `edits` kept as a serde alias so every existing call and test keeps working ("one field carries both forms"). multi_edit's per-file array uses the same `ops` name (also aliasing `edits`, so the spec's files:[{path, edits:[...]}] shape deserializes too).
(2) Compact grammar: {i|b|d|r}{N|N-M|N-}[:payload], split on the FIRST colon (payload keeps later colons; d takes NO colon). 1-indexed inclusive, mirroring file_edit's `lines` semantics. i=insert after N (i0=top of file, N=line count=append at EOF, N>count errors), b=insert before N (1..=count only), d=delete inclusive (d100- = to EOF), r=replace range with payload (payload may be empty = one empty line; multi-line rides JSON newline escapes). Payload goes through the line-range pipeline (normalize_line_endings + denormalize_literal_newlines); rebuild joins with the detected LE and preserves the trailing newline — re-append only when the line list is non-empty (deleting every line yields empty content). Out-of-range mirrors file_edit.rs: end clamps (prepare_edit_lines ~:560, ~:2472 test), start-beyond-EOF errors (~:2524).
(3) NEW src/tool/agent/multi_edit.rs: files:[{path, ops}] applying every file ATOMICALLY — all files are prepared (sandbox + protected check + read + apply + diff) before ANY write; a failing op aborts with no write anywhere; errors are prefixed "multi_edit: {path}: op {i}: ..." so the steering observer can name the path. Result: one combined diff (per-file --- / +++ sections) under data.diff; approval preview is a NEW ApprovalPreview::MultiDiff { paths, diff } variant (src/provider/mod.rs:1066).
(4) multi_edit sits BESIDE file_edit (decided): absorbing it would double one schema on every filter and break the ^file_edit: safety-rule/prompt/dispatch anchors; file_edit stays the single-file default, multi_edit is the cross-file/compact path.
(5) Strict: multi_edit joins STRICT_TOOLS (src/provider/strict.rs:250) like file_edit; its polymorphic items schema must survive normalize_for_strict idempotently (the normalizer recurses into items/anyOf).
