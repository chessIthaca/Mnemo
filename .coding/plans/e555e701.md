# Plan: Remove delta reads and signature skeletons

## Goal
read_files no longer serves a signature skeleton for an unchanged re-read or a diff for a changed one: every whole re-read serves the file again. Outline reads of big files stay. The context-quality grade drops the two signals only skeletons fed and is graded from window fill alone.

## Kind
implementation

## Context
WHY: the real savings ledger (.coding/memory.db savings_events) shows the two levers are not worth their code. In six weeks: skeleton 139 events, 132,619 tokens (about $0.31); delta_read 3 events, 3,096 tokens, last on 2026-10-25. Together that is about 0.03% of the project's traffic. The user decided: remove both.

WHAT GOES:
- the unchanged-re-read skeleton serve and the changed-re-read diff serve in src/tool/agent/read_files.rs (`read_one_delta`'s `Some(old)` arms);
- the served-content baseline in src/tool/agent/read_cache.rs (`ReadCache::inner`, `FileSnapshot`, `snapshot`, `record`, `forget_served`, `diff_if_small`, `DIFF_FULL_SERVE_RATIO`);
- the "context was reduced" reset that existed only to keep skeletons truthful: `Tool::on_context_reduced` (src/tool/mod.rs), `ReadFilesTool::on_context_reduced`, `AgentLoop::note_context_reduced` (src/agent/turn.rs) and its two call sites;
- in the quality grade (src/agent/optimizer.rs): the stale-read and waste signals (`QualityReport::waste_tokens`, `QualityReport::stale_read_rate`, `QualitySignals::{reads_total, skeleton_serves, served_tokens, waste_tokens}`, the matching `OptimizerState` atomics, `waste_penalty`, `stale_penalty`, `OptimizerState::record`). Only skeleton serves ever fed waste and stale reads, so without skeletons they are always zero. The grade becomes `100 - fill_penalty(fill_pct)`.
- the Mnemo1 context popup rows that showed those two fields (frontend/src/components/chat/InflightBar.tsx "waste" and "stale reads").

WHAT STAYS (decisions already taken):
- Outline reads: the first whole read of a source file over OUTLINE_MIN_LINES (500) lines with at least one signature line serves its signature outline (`outline` ledger row), and later ranged reads are charged back as `outline_followup` against the outline's saving. `skeleton_for`, `Skeleton`, `SKELETON_MAX_LINES`, `is_signature_line` and the `outlined` debt map (`note_outline`, `charge_outline`, `MAX_CACHED_FILES`) stay in read_cache.rs. A whole re-read of an outlined file serves the outline again (unchanged behaviour).
- The persisted config key `[general.optimizer] delta_reads`, the settings DTO field `optimizer_delta_reads`, and the Mnemo2 wire field `delta_reads` keep their names so existing config.toml files and the settings wire keep working. The flag now gates only outline reads, so its doc comments and the two settings labels say so ("Outline reads"). Do NOT rename the key.
- Old ledger rows of kind `delta_read` and `skeleton` stay in the database as history; the Cost tab keeps labels for them (mnemo2/src/lib/cost.ts LEVERS), marked as retired.
- The `similar` crate stays (src/tool/agent/edit_ops.rs uses it).
- Keep the file and type names read_cache.rs / ReadCache to keep the diff small; fix their doc comments instead.
- QualityReport keeps `grade`, `fill_pct`, `decision_density`. Removing fields from a Serialize/Deserialize struct is wire-safe here: serde ignores unknown fields, and the ContextUsage event is not persisted.

NOT TOUCHED: ledger tests that use "skeleton" or "delta_read" only as sample kind strings (src/memory/tests.rs, src-tauri/src/mnemo2/insights.rs, src/tool/agent/optimizer.rs savings_event test), the Mnemo2 preview fixture mnemo2/src/test/previewScenes.ts, mnemo2/src/components/CostView.test.ts, docs/marketing/, and every "bug skeleton" / "locked skeleton" use of the word (plan workflow code, unrelated).

## Acceptance scenarios
- A whole read of an unchanged 300-line .rs file, done twice with the outline lever on, serves the full content both times and records no savings event.
- A whole re-read of a changed 300-line .rs file serves the new full content, not a diff.
- The first whole read of a 600-line .rs file with signatures still serves its outline with an `outline` savings event, and a later ranged read of it still records `outline_followup`.
- With `delta_reads = false`, a 600-line file is served whole; flipping it on outlines the next whole read.
- QualityReport serializes only grade, fill_pct and decision_density; the quality-drop nudge names the grades and the fill only.
- Mnemo2 Settings → Savings labels the `delta_reads` checkbox 'Outline reads'; the Cost tab still labels old `delta_read` and `skeleton` ledger rows.
- cargo test --lib, cargo build --tests, cargo check --workspace --tests, mnemo2 check + tests and frontend tests + tsc all pass.
