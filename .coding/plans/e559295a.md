# Plan: Trace Insights charts resize vertically with a horizontal split bar

## Goal
On the Trace tab the user can drag a horizontal split bar under the Insights charts to make them taller or shorter (the charts grow or shrink to fill the space), with arrow-key control and a saved height per project.

## Kind
implementation

## Context
WHY: the three Insights charts (Where did request time go, What did the tokens go to, What did calls cost over time) have fixed plot heights, so the user cannot give them more room or reclaim space for the call list. The Trace tab already has a vertical drag divider between the call list and the detail column; this adds the matching horizontal one.

CURRENT STATE (verified): mnemo2/src/components/TraceView.svelte renders `<section class="insights">` (lines ~940-949) with a toggle button and, when `insightsOpen`, `<div class="insights-body"><TraceCharts rows scopeLabel onbucket/></div>`; its CSS is `.insights { padding: 12px 26px 20px }` and `.insights-body { margin-top: 10px }` (lines ~1112-1115). The existing vertical divider is the pattern to copy: state `listWidth` (line 86) with LIST_WIDTH_MIN/MAX (lines 50-51), handlers onDividerPointerDown/Move/Up/Keydown (lines 639-670, pointer capture, shift = bigger step), a `<button class="divider">` with aria-label and title (lines 1054-1064), saved through `savePrefs()` (line 175) into `saveTracePrefs($app.projectId, { ...filters, insightsOpen, listWidth })` and restored in onMount (lines 679-689, clamped, type-checked with `typeof prefs.listWidth === "number"`). The saved shape is `TraceViewPrefs` in mnemo2/src/lib/trace.ts (lines 1412-1418; local storage key `mnemo2.trace.<projectId>`). mnemo2/src/components/TraceCharts.svelte draws bars as a percent of their chart box: the time and token charts use `.chart { height: 132px }` (line 790-795) and the cost chart `.cost-chart { height: 120px }` (line 910-912); everything else in the charts is already proportional. The plan page's splitter (PlansView.svelte lines 10-140) shows the app's splitter styling (`.splitter`, `body.resizing { user-select: none }`).

DESIGN (decided; the worker may change details if the code disagrees, and must say so in its report): (1) New state in TraceView.svelte: `insightsHeight = $state<number | null>(null)`; null keeps today's natural layout. Constants INSIGHTS_HEIGHT_MIN = 160 and INSIGHTS_HEIGHT_MAX = 900, and the drag also clamps to the trace view's height minus 220 px so the call list never disappears. (2) A horizontal split bar directly under `.insights-body`, shown only while `insightsOpen`: `<button type="button" class="insights-divider" role="separator" aria-orientation="horizontal" aria-label="Resize the charts (drag or arrow keys)" title="Drag or use arrow keys to resize the charts. Double-click resets." ...>` with pointer capture, ArrowUp/ArrowDown (20 px, 60 with Shift), Home and double-click reset to null, `cursor: row-resize`, the same hover and focus colours as the vertical `.divider`, and `touch-action: none`. Add the `body.resizing` class while dragging so text is not selected. It works in the narrow layout too. (3) When `insightsHeight` is not null, `.insights-body` gets `height: {insightsHeight}px; overflow: auto`. (4) TraceCharts.svelte takes a new optional prop `plotScale?: number` (default 1, clamped 0.5 to 3) that sets a CSS variable on its root, and `.chart` and `.cost-chart` heights become `calc(132px * var(--plot-scale, 1))` and `calc(120px * var(--plot-scale, 1))`, so with plotScale 1 the rendering is exactly today's. (5) TraceView computes `plotScale` so the charts' content height tracks `insightsHeight`: measure at runtime the stack's natural content height and the sum of the plot heights at scale 1 (for example the offsetHeight of the `.chart` and `.cost-chart` elements, which the worker may tag with a data attribute), then plotScale = clamp((insightsHeight - (natural - plotsBase)) / plotsBase, 0.5, 3); when insightsHeight is null the scale is 1. (6) Persistence: add `insightsHeight?: number | null` to TraceViewPrefs, include it in `savePrefs()`, restore it in onMount only when it is a finite number, clamped to the min and max (anything else leaves null), so older saved prefs keep working.

NOT IN SCOPE: the vertical list/detail divider, the chart contents or colours, the agent dropdown, anything in src-tauri or Rust.

## Acceptance scenarios
- With the Insights charts open, the Trace tab shows a horizontal split bar (role separator, aria-orientation horizontal) directly under the charts; dragging it down makes the three charts taller and dragging it up makes them shorter, bounded by 160 px at the smallest and by the space that leaves the call list visible.
- With insightsHeight at its default (never dragged), the charts render exactly as before: plotScale is 1 and the `.chart` and `.cost-chart` heights are 132 px and 120 px.
- ArrowDown and ArrowUp on the focused bar move the height by 20 px (60 px with Shift), and Home or a double-click returns it to the default natural layout.
- Reload the Trace tab after resizing: the same height comes back for the same project (local storage key mnemo2.trace.<projectId> holds insightsHeight); a stored non-numeric or out-of-range value is ignored or clamped; prefs saved by the previous version still load.
- Closing the charts with Hide charts hides the bar; reopening restores the last height. `npm run test --workspace mnemo2` and `npm run check --workspace mnemo2` pass.
