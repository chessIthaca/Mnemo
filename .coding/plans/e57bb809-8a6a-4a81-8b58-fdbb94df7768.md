# Plan: Live streaming display independent of rAF (RDP-safe)

## Goal
Make the streaming display as live as the model: every token must appear in the reasoning display AND the agent window as soon as it arrives — even when requestAnimationFrame stalls (RDP occlusion / WebView2 quirks), where today both surfaces stay blank and everything appears at once at turn end.

## Kind
implementation

## Context
User report (2026-08-22, backlog #84 follow-up, "Both lag"): neither the reasoning display nor the agent window updates during a response — everything shows up at once when the turn finishes. Verified by reading: the backend already streams per SSE chunk (openai.rs read loop → turn.rs TextDelta/ReasoningDelta per chunk �� forwarder app.emit per event, zero locks for deltas); the frontend buffers text/reasoning/tool-arg deltas in useAgentEvents.ts and flushes ONLY via requestAnimationFrame (scheduleFlush) plus a 64 KiB sync cap (deltaFlush.ts, R2 of .coding/reviews/2026-08-18-rdp-freeze-diagnosis.md). The user's environment is Remote Desktop: while occluded/covered or under WebView2 RDP quirks, rAF never fires (WebView2Feedback #4879 — no visibilitychange to compensate), so sub-64 KiB responses (typical reasoning + answers) sit in the buffers and only flush at structural-event boundaries (tool_call_start/usage/finished) or turn end — exactly the observed symptom. Fix: an rAF-independent hybrid flush policy in createAgentEventDispatcher — (a) flush immediately when >= MAX_FLUSH_INTERVAL_MS (40ms) elapsed since the last flush (sparse tokens land per-token, "as soon as it comes in"); (b) keep the per-frame rAF batch for dense streams; (c) arm a fallback setTimeout(40ms) alongside each rAF so a stalled rAF can never hold text indefinitely (first-wins, each cancels the other; occluded timers throttle to ~1s → bounded catch-up, never 'all at the end'); (d) keep the existing 64 KiB sync cap. Both displays read the same store, so one fix unblocks both. Windows/PowerShell; frontend-only change; npm test + npm run build + root cargo test; regression tests per constitution (rewrite the existing R2 wiring tests to the new policy with a fake clock + fake timers — note the existing 'deltas batch and wait for the frame' test's premise changes since the first delta now flushes immediately); no #[allow]; doc comments on new pub items; commit to fix/live-streaming-display (never main).
