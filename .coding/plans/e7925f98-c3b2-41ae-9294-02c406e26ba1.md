# Plan: Self-heal reasoning_effort 400 rejections + fix embedder model name

## Goal
Make the app resilient to providers that reject the app-default `reasoning_effort: "max"` (e.g. a local Qwen/LM Studio build accepting only none/minimal/low/medium/high/xhigh), so turns and backlog items stop failing with "Invalid 'reasoning_effort' value: 'max'"; and fix the embedding model display name "Nomic Embed Text v1.5 (matches prior target)" to a general description per the user's request.

## Kind
implementation

## Context
Backlog item #37 was marked "failed" because every provider request 400'd with `Invalid 'reasoning_effort' value: 'max'`. Root cause: src/config/endpoints.rs `effective_reasoning_effort()` defaults to "max" when unset; src/provider/openai.rs `build_request_json` (line 926-928) sends it verbatim; the Qwen3 endpoint at localhost:1234 only supports none/minimal/low/medium/high/xhigh. There is no fallback — `complete()` (openai.rs ~513-555) surfaces the 400 as a terminal error, so the turn retry burst (9 attempts) all fail and the backlog item lands in Failed with the provider error note. Fix: in `complete()`, when the response is HTTP 400 and the error body names `reasoning_effort` (and the client was configured with an effort), retry ONCE with `body["reasoning_effort"]` removed — self-healing, no config change, trace records only the final outcome. Error bodies for non-effort failures must keep their full body (the GLM code-1214 diagnostics at openai.rs:992 depend on it — avoid double-consuming the response). Second part of item #37: src/memory/embedder.rs:188 display name "(matches prior target)" → "Nomic Embed Text v1.5 (best quality)" (matches the catalog's descriptive pattern; no tests assert the name). Regression tests need a tiny in-test HTTP server (none exists in the repo — hand-rolled tokio TcpListener serving canned responses, recording request bodies).
