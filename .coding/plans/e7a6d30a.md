# Plan: Move runtime.rs's inline test modules to sibling files

## Goal
Pure mechanical move: `src-tauri/src/mnemo2/runtime.rs` keeps only production code (about 1,820 lines) and its two inline test modules (`trace_tests`, about 190 lines, and `tests`, about 8,490 lines) live in `src-tauri/src/mnemo2/runtime/trace_tests.rs` and `src-tauri/src/mnemo2/runtime/tests.rs`, with no change to any test name, test body or production behavior.

## Kind
implementation

## Context
Why: Mnemo2 architecture review finding ARCH-4 (runtime.rs half), verified on wt/mnemo at ba6c266f: runtime.rs is 10,507 lines of which about 81% is `#[cfg(test)]` test code, which buries the production code of the lead runtime. The review proposes `#[cfg(test)] #[path = "runtime/tests.rs"] mod tests;` and the mnemo2-app crate already uses exactly this idiom (`#[cfg(test)] #[path = "serve_tests.rs"] mod tests;`).

Facts verified in the tree (line numbers are as of ba6c266f; locate by text, not by line):
- Production code ends around line 1821 (a `.map(|endpoint| format!(\"{}/{}\", endpoint.name, model))` expression closing a function). Then comes a doc comment `/// Trace identity tests (plan c3ba2b58 step B) - in their own module so the append-heavy `mod tests` below stays untouched by concurrent work.`, then `#[cfg(test)]` and `mod trace_tests { use std::path::Path; use std::time::{Duration, Instant}; use super::*; use crate::mnemo2::team::{TeamRuntime, TeamRuntimeOptions, WorkerSessionSpec}; ... }` (to about line 2014).
- Then a DUPLICATED attribute (`#[cfg(test)]` twice) before `mod tests { use super::*; macro_rules! tiers_dto { ... } ... }` which runs to the end of the file (about line 2018 to 10507).
- Both modules are children of `runtime` and use `use super::*;` plus `crate::` paths, so moving them into files that are still children (`#[path]` declarations) needs NO visibility change and NO import change. No `include_str!`, `include_bytes!`, `file!()`, `env!(\"CARGO_MANIFEST_DIR\")` or nested `mod x;` exists in runtime.rs (checked), so nothing is path-sensitive. Nothing outside runtime.rs refers to `runtime::tests` or `runtime::trace_tests` (checked with grep).
- `#[path]` for a module declared in the non-mod-rs file `src-tauri/src/mnemo2/runtime.rs` is resolved relative to the directory that holds runtime.rs, so `#[path = \"runtime/tests.rs\"]` is `src-tauri/src/mnemo2/runtime/tests.rs` (the directory `runtime/` does not exist yet; create it).
- The G10 boundary test (`tests/boundary.rs`, `tauri_uses_only_public_api`) scans src-tauri production sources for kernel-internal paths. After plan 2b1e9c1b step 1 (merged before this plan is dispatched) it skips test-only files named `tests.rs`, `*_tests.rs` and `testutil.rs`, and it requires each such file to be declared under `#[cfg(test)]` by a sibling file with `#[path = \"...\"]` or `mod <stem>;` within two lines of the attribute. This plan's declarations follow exactly that shape.

Rules (non-negotiable): NO behavior change. Every moved line stays byte-identical except leading indentation (the module body loses exactly one level, 4 spaces). Test names must stay identical: the module paths `mnemo2::runtime::tests::*` and `mnemo2::runtime::trace_tests::*` do not change. Do NOT retype or paste test code through the editor; extract with a script (python, node or PowerShell, whichever the shell has) by line numbers you computed with grep, then delete the moved block from runtime.rs with a script too. The repo is NOT rustfmt-clean: never run cargo fmt or rustfmt on any file.

Dedent hazard: dedenting changes the content of a multi-line string literal (normal string spanning lines, or a raw string r#\"...\"#). Your script must therefore NOT dedent a line that starts inside an open string literal: track string state while scanning the body (normal strings with backslash escapes, raw strings with any hash count, char literals like '\"' and '{', and `//` line comments, which can contain quotes). Report how many lines were left undedented for that reason, and paste the first 10 of them into your report so the lead can check them.

Verification commands (run in your checkout root, the repository root): `cargo test -p mnemo-app --features mnemo2 --lib`; `cargo clippy -p mnemo-app --features mnemo2 --all-targets -- -D warnings -A clippy::redundant_guards -A clippy::nonminimal_bool`; `cargo test --test boundary`; `git diff --check`. Windows shell hygiene: use `git -C` and `--manifest-path`, never leave a shell inside another worker's checkout.
