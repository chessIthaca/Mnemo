# Plan: memory_update digest-rewrite data loss — refuse digest-shaped body replacements (63f882c9)

## Goal
Stop memory_update from destroying knowledge-file bodies with digest-style content: KnowledgeStore::update refuses digest-shaped replacements (shorter + knowledge-path pointer tail) with a contract-teaching error naming the file; a regression test pins that a full-bodied file never shrinks via memory_update; the three committed digest-tail files are repaired from git history.

## Kind

## Context
Root cause (verified by exploration): KnowledgeStore::update (src/memory/knowledge.rs:698-736) parses the file, then writes render_front_matter + new_body verbatim — no shape guard; MemoryUpdateTool::execute (src/tool/memory/mod.rs:705-769) routes knowledge-backed updates there and reports "file rewritten". Architecture constraint that picks the fix: rows are DERIVED from files by the indexer (reindex re-derives row content from the file body), so a row-only update would diverge and be clobbered — the only coherent update target is the FILE, and a digest-shaped replacement is incoherent input → refuse (backlog option c). Guard shape: new body is SHORTER than the parsed record's body AND its last non-empty line contains ".coding/knowledge/" and ends with ".md" (covers the observed tails: "path …", "Path: …", "Full detail path …", "File: …"). False positives (a legitimate body ending in a see-also link) are SAFE — refusal, no data loss; false negatives are the danger. The F1 test (src/tool/memory/mod.rs:1334, "We use postgres for storage. v4.") pins the legitimate shorter-update-without-path-tail path — it must stay green. Neighboring helper reconcile_file_pointers (F12, :829) shows the established pointer-line conventions. The three repair targets: the two self-referential tails sit on otherwise-full bodies (likely noise from digest-style writes at creation or update — git history decides); the decision file's whole body is a digest pointing at its superseded 2026-12-20 predecessor. Knowledge-corpus files are protected from the agent file tools — repairs go through the Python-surgery route (shell), LF + UTF-8 preserved. Supersede's thin-successor pattern (a digest as a NEW successor body) destroys no data (the predecessor keeps its body on disk) — out of scope here, noted for the reviewer to sanity-check.

ROOT CAUSE CONFIRMED (RED run, 2027-01-09): the regression test update_refuses_digest_style_content_that_would_shrink_the_file (src/tool/memory/mod.rs, inserted before reconcile_file_pointers_rewrites_only_stale_leading_pointers) panics at the !result.success assert — without the guard, memory_update with digest-style content (strictly shorter + "path .coding/knowledge/<rel>" tail) SUCCEEDS and the file's body is replaced verbatim. KnowledgeStore::update (src/memory/knowledge.rs:698-736) parses then writes new_body with no shape guard; the tool layer reports success. Fix: refuse digest-shaped replacements in update() (guard: strictly shorter than the current body AND last non-empty line contains ".coding/knowledge/" and ends ".md"); rows are derived from files by the indexer, so a row-only update would diverge and be clobbered by reindex — refusal is the only coherent handling.
