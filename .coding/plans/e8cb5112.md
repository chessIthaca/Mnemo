# Plan: Remote workers, phase 5: Worker hosts in the app (settings, pairing, host badges, link-loss states, docs)

## Goal
The user can pair, see, link, unlink and revoke worker hosts from Settings → Worker hosts in the Mnemo2 app. Every worker shows which computer runs it and whether its host is away. The user docs explain how to set up a Windows or Mac worker host with mnemo2-node. Two phase-4 leftovers are fixed: the continue answer names the live SSH connection, and a finished worker no longer reports its host as offline.

## Kind
implementation

## Context
WHY: phase 5 of remote workers (design in plan c8a1a6f5, "5. Settings → Worker hosts, pairing UI, host shown in team_status and Mission Control, link-loss states and resync"). Phases 1-4 are merged on wt/mnemo (unpushed, held for the next installer, which includes remoting). Remote hosts are Windows or Mac only, never Linux. Today hosts can only be managed through the lead's MCP tool `team_hosts` (src-tauri/src/mnemo2/team/lead_tools.rs:338-640). The app has no Tauri command and no UI for them, and the worker list does not show a worker's host. Resync after link loss already happens automatically (host reconciler, team.rs reconcile_hosts and mark_host_offline/mark_host_back/mark_host_restarted at team.rs:930-1030); this phase only SHOWS those states.

SETTLED DECISIONS:
- D1 One backend implementation. The UI and the lead tool share the same code: the bodies of team_hosts_list/pair/revoke/link/unlink move into a `TeamRuntime::hosts_action` that returns `Result<serde_json::Value, String>`. The `team_hosts` tool wraps it into a ToolResult (pretty JSON on Ok, error text on Err), so the tool's output text is byte-for-byte unchanged. The Tauri commands call the same function. No JSON re-parsing of tool output.
- D2 Linking a host to an SSH connection is the user's standing approval for the lead to start Claude Code workers there; unlinking withdraws it. The UI states this next to the link control. The app cannot list the desktop app's saved SSH connections, so the user types the connection's name.
- D3 Revoke is destructive (the host's running workers fail, resumably). The UI asks for a second click in an inline confirm ("Revoke {name}? Its running workers stop and can be resumed with team_resume.").
- D4 Hosts are app-wide (one AppHub per app), but check qualification is per project, and the commands go through the open project's TeamRuntime (`current_team`, src-tauri/src/mnemo2/ipc.rs:443). With no open lead or project the commands return its error ("Mnemo2 has no open lead; call lead_open first"), and the page shows "Open a project to manage worker hosts." The page sits in the "All projects" rail group after "Machine".
- D5 Host data for workers comes from the existing team snapshot: Rust WorkerRecord already serializes `remote: Option<RemoteCheckout>` ({node_id, node_name, os, project, checkout, path, synced_tip?, offline_since_ms?, ssh?}, record.rs:221-247, skipped when None) and `claude_session`. The frontend computes "away for N s" from offline_since_ms. No new backend snapshot field.
- D6 "Offline" is shown only for a worker that is still active. In TS that is status working / fixing / dispatching / needs-you / interrupted (mirror team.rs:1994 is_active). A finished, merged, failed or stopped worker shows its host name without the away state.

TAURI COMMAND CONTRACT (step 1 adds it; step 3 calls it; names are fixed):
- `worker_hosts_list() -> Value`: {"hub":{"listening":bool,"address":string|null},"hosts":[{name,node_id,os,connected,slots|null,busy|null,catalog_ready|null,checks:"passed"|"pending"|"failed: <reason>",last_seen_ms,ssh|null,claude_home|null}]}

- `worker_hosts_revoke(name: String) -> Value`: {"revoked":{name,node_id},"failed_workers":[...]}

## Acceptance scenarios
- In Settings → Worker hosts with no paired host, the page shows 'No worker hosts yet.' and a 'Get pairing code' button; clicking it shows a code, a mm:ss countdown and two mnemo2-node commands with Copy buttons.
- With a paired host, the page lists it with its OS, connected/away state, checks state and busy/slots; Link with an SSH name shows 'Linked to <name>', and Unlink removes it; the lead's team_hosts list shows the same ssh value.
- Revoke needs a second click on 'Confirm revoke'; afterwards the host is gone from the list and its running workers are failed resumably.
- The team_hosts lead tool's output text for list, pair, revoke, link and unlink is unchanged by the refactor (hosts_action_matches_the_team_hosts_tool_output).
- A worker running on host 'studio' shows a 'studio' badge in the worker list and 'host: studio' in its detail; while its host is away and the worker is active, the badge reads 'studio · away …' and the detail explains it; a merged worker shows no away state and team_status gives it no host_offline_s.
- After unlinking connection A and linking B, team_message to a remote Claude worker answers continue_session.host = B, and the stored record is unchanged.
- docs/WORKER-HOSTS.md explains install, pairing, Claude Code workers via SSH link, link loss and the mnemo2-node commands, matching the real CLI flags.

## Spec changes

### dispatch-routing

#### ADDED Requirements

##### Requirement: Host state is reported from the live link and only for active workers
A continue answer (team_message or team_route_fix to a remote Claude Code agent worker) SHALL name the host's currently linked SSH connection, never a connection stored on the worker record that has since been unlinked or replaced. With no linked connection it SHALL name none and explain how to proceed. A worker's host-away time (host_offline_s) SHALL be reported only while the worker is active, and a merge SHALL clear the worker's host-away mark.

###### Scenario: Continue after a relink
- **WHEN** a remote Claude worker was placed with SSH connection A
- **WHEN** the host is unlinked and linked to connection B
- **WHEN** the lead sends team_message to the worker
- **THEN** continue_session.host is B
- **AND** the stored worker record still names A

###### Scenario: Finished worker on an away host
- **WHEN** a worker's host went away and the worker then merged or finished
- **THEN** team_status shows no host_offline_s for that worker
