# Plan: macOS release build: two shared-service tests fail (dropped lease guard; zombie counted alive)

## Goal
The macOS (and Linux) `cargo test --workspace` passes, and on Unix a killed child process is never reported as alive, so the shared-service crash detection works there.

## Kind
bug_fixing

## Context
ROOT CAUSES (lead's analysis; the worker must confirm in WSL Ubuntu, which is installed on this machine):
1. service_and_lease_files_are_user_only (src/host/shared_service.rs ~:855-866, #[cfg(unix)]) calls `take_lease(&service, 4242).unwrap();` as a statement. The returned LeaseGuard is dropped at once and its token-checked Drop removes lease-4242.json, so the metadata read hits NotFound. This is a test bug: bind the guard (`let _lease = ...`) until after the mode checks.
2. watchdog_stops_service_after_idle: on Unix, process_tree::pid_alive uses `ps -p <pid>`, and a killed child that its parent has not reaped yet is a ZOMBIE that `ps -p` still lists. The test's StubChild holds the std Child without waiting, so after the watchdog's kill the stub is a zombie and wait_dead reports it alive. This is ALSO a production bug: an instance that spawned the shared laya-serve (or the mnemo-models host in step 2) drops its std Child without reaping, so after that server crashes or is killed, the spawning instance's own pid_alive still says alive, and it never recovers or respawns, while other instances (not the parent) see it gone.
FIX (decided):
(a) process_tree::pid_alive on Unix treats a zombie as dead: use `ps -o stat= -p <pid>`; it is alive only when ps succeeds, prints a state, and the state does not start with 'Z'. Keep Windows unchanged.
(b) Wherever shared_service or laya spawn a DETACHED shared server or watchdog and then drop the std Child, reap it so no zombie lingers. Spawn a small thread that calls child.wait() (std::process::Child), or keep the Child and try_wait() it in the monitor. shared_service::spawn_detached already has a reaper thread for the watchdog; check that every detached server spawn has one too (laya.rs's shared spawn path).
(c) Fix the test bug in (1).
REGRESSION TESTS (Unix, so they run on the macOS CI leg and in WSL): `pid_alive_treats_a_zombie_as_dead` in src/process_tree.rs: spawn `sh -c 'exit 0'`, wait until it has exited but do NOT reap it (keep the Child), then assert pid_alive(pid) == false; then reap. It must fail on today's code (ps -p lists the zombie). The two failing shared_service tests must pass in WSL.
VERIFY: in WSL Ubuntu (the repo is at /mnt/c/Mnemo; use a worktree copy or a separate CARGO_TARGET_DIR such as /tmp/mnemo-target so Windows and Linux builds don't share target/): `cargo test -p mnemo --lib host::shared_service process_tree`, and if feasible `cargo test --workspace`. If WSL lacks a Rust toolchain or system deps, install them with rustup (user-level) and apt (system packages need sudo: if sudo prompts for a password, stop and report instead). On Windows: the four checks.
