# Plan: Deduplicate file names in ToolCard headers (each shown once)

## Goal
Deduplicate ToolCard header file-path chips so each filename appears at most once (same file read in multiple grouped calls → one chip), keeping the first occurrence's clickable link.

## Kind
bug_fixing

## Context
Backlog 2a03710d (in_flight). Root cause (verified by reading code): the ToolCard header chip loop in frontend/src/components/chat/Message.tsx (~lines 498-516) renders one chip per path PER CALL with NO deduplication. When the agent reads the same file in two grouped read_files calls (common: read → edit → re-read to verify), the header shows the basename twice. The "not shown" edge case: when a read_files call's args carry no valid path (empty files array / malformed spec), argPaths (toolCardPaths.ts:57-68) returns [] and argLabel (Message.tsx:410-423) returns null → bare "read_files" header with no name. Also the >3-files cap hides names beyond the 3rd. The Rust read_files tool emits a per-file `=== <path> (lines X-Y of Z) ===` header in the result body (read_files.rs:286-290), so expanded cards show the name in the body too — that's the tool's output, leave it. Scope: dedup the HEADER path chips so each file appears once. Frontend test: `npm test` (vitest run) in frontend/.
