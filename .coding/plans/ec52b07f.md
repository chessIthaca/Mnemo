# Plan: Pricing model field: editable combobox of configured models (dropdown + free typing)

## Goal
Settings → Pricing: replace each [[pricing]] row's type-only model input with an editable combobox — a dropdown listing the models available from the configured endpoints (EndpointInfo.models via getSettings, grouped/deduped across endpoints and annotated with endpoint names) plus free-text entry for models not in the list. Selecting an entry fills the field with the model id; typing filters the list; save behavior stays exactly as-is (saveSettings({ pricing }) with trim + filter-non-empty, no forced validation), so a typo'd or custom model id still saves. Four vitest cases in the project's node-env convention: dropdown lists the configured models; selecting an entry sets the field value; free-typed values are preserved on save; a typed model not in the list still saves.

DESIGN DECISIONS: (1) Options come from the CONFIGURED endpoints' models lists only (EndpointInfo.models via getSettings) — NOT merged with the live list_models fetch the Endpoints tab uses: deterministic, no network/loading/error states, and free-text entry already covers models not in the list (new endpoints, stale cache). (2) Options are GROUPED by model id — { model: string; endpoints: string[] } — deduped across endpoints, sorted by model; the dropdown annotates each entry with its endpoint names (model ids can repeat across endpoints); selecting an entry fills ONLY the model id. (3) Filter rule (pure, testable): empty value → all options; value exactly matching an option → all options (reopening after a selection lets you pick an alternative); otherwise case-insensitive substring filter. (4) Save behavior UNCHANGED — handleSave keeps trim + filter-non-empty + saveSettings({ pricing: cleaned }); no forced validation against the list. (5) Component: ModelCombobox.tsx in sections/ (controlled input + chevron toggle + absolutely-positioned filtered dropdown; select → onChange(model) + close; Escape + transparent-overlay click-outside close; free text always allowed; styling follows the existing input classes — border-border bg-bg-secondary text-xs rounded etc.). (6) Pure helpers live in modelOptions.ts (node-safe import for tests): ModelOption type, buildModelOptions(endpoints), filterModelOptions(options, value). TEST MAPPING (node-env convention): "dropdown lists the configured models" → buildModelOptions unit tests (grouping, dedup, annotation, sort) + source contract that PricingSection passes options from s.endpoints; "selecting an entry sets the field value" → source contracts: the combobox entry click calls onChange with the model id, PricingSection wires onChange to updateRow(i, { model: v }); "free-typed values are preserved on save" + "a typed model not in the list still saves" → source contracts: the input passes free text through onChange(e.target.value), handleSave unchanged (saveSettings({ pricing: cleaned }), no list-membership validation).
