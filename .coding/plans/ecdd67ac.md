# Plan: Fix memory_amend's double-stamped heading + add an in-tool record-repair path

## Goal
Land fix direction (c) from backlog 488248ce: (a) PREVENT — `KnowledgeStore::amend` strips a self-supplied leading heading ("Amended …:" / "AMENDED …:" / "Amendment (…):") before prefixing its own stamp, so a paragraph can never carry a doubled or contradictory heading and the stamped date stays authoritative; (b) REPAIR — `memory_update` gains a targeted-replace mode (`find` + `replace_with`, unique-match, body-only) so stray text in a knowledge record is fixable in-tool instead of via the sanctioned-but-last-resort shell fallback. Docs/tool descriptions + the compiled prompt + agent.md updated; regression tests pin both halves; cargo test green and warning-free under #![deny(warnings)].

## Context

Symptom: memory_amend prefixes "Amended {stamped_date}: " onto the caller's paragraph, so a paragraph that already opens with "Amended 2027-01-14 …" produced "Amended 2027-01-11: Amended 2027-01-14: …" in two live records — doubled heading, contradicting dates, repaired by hand via the shell fallback (unique-substring collapse). DESIGN (a) — strip rule, exactly: inspect only the paragraph's FIRST LINE after trim; if it starts case-insensitively with "amended"/"amendment" at a word boundary, take the head = text between that word and the first ':' on the line; strip the head + ':' when the head is ≤120 chars AND (after leading whitespace) starts with a 4-digit run (a year, e.g. 2027-01-14, or 2027-01-14 (plan 987fef4c, backlog 56168c38 — …)) OR contains a balanced "(…)" pair (e.g. "Amendment (plan 987fef4c)"); the remainder after ':' must be non-empty; loop until no further strip (each strip strictly shortens, so it terminates) to collapse "Amended A: Amended B: text". Real-world positives: "Amended 2027-01-14: …", "Amended 2027-01-14 (plan 987fef4c, …): …", "AMENDED 2027-01-11 (review L1, plan 9441d776 round-1): …" (uppercase, a form already present in a record), "Amendment (…): …". Must NOT strip: "Amended the readme and the changelog: both now mention the flag" (prose after the word), "Landed outcome (2027-01-14): …" (doesn't open with the word) — and "the zero-file hint's wording changed" style bodies. Emptiness is re-checked AFTER stripping, so a bare "Amended 2027-01-14:" errors "nothing to amend" instead of writing a header-only amendment.

DESIGN (b) — targeted repair: memory_update gains optional `find` + `replace_with`. Rules: both-or-neither; EXCLUSIVE with title/content (one call, one intent); find must be non-empty and must occur EXACTLY ONCE in the record BODY (front matter is machine-rendered and out of scope) — 0 matches → error, >1 → error naming the count and telling the caller to widen the substring; the result must not be empty/whitespace-only. Knowledge-backed records: new `KnowledgeStore::replace_in_body(rel, find, replace_with) -> Result<u64>` — lock, read, parse_file, refuse superseded (history is never edited, consistent with amend), re-render front matter identically to update()/amend(), write. It deliberately does NOT consult the digest guard, with a doc comment stating why: the guard exists so a condensed row digest can never REPLACE the body, while a unique-substring replace cannot lose the body — and a repair that shrinks a record (exactly this bug's collapse) would otherwise be wrongly refused when the record ends in a pointer tail. DB-only records: get_memory → the same pure helper → update_memory. Shared pure helper `pub fn replace_unique(body, find, replace_with) -> Result<String>` lives in src/memory/knowledge.rs so both paths enforce one rule. This is file-tools-first: it removes the last legitimate reason to shell-mutate .coding/knowledge/**.

TESTS (all fail without the fix): knowledge.rs — amend_strips_self_supplied_heading_and_stamps_its_own_date (count "Amended " occurrences == 1, tool date 2026-02-01 in tests, prose-preserving negatives), strip_self_headings_matches_stamp_shapes_only, replace_unique_requires_exactly_one_match, replace_in_body_repairs_record_text_without_digest_guard_interference (incl. a pointer-tail record that shrinks); tool/memory/mod.rs — update_targeted_replace_repairs_a_knowledge_record (+ row reindexed), update_targeted_replace_argument_rules, update_targeted_replace_works_on_db_only_records, amend_result_reports_a_stripped_self_heading.
