# Plan: Fail closed when a spawned agent's parent loop is missing

## Goal
Reject shared agent spawns whose supplied parent no longer has a registered loop, so roleless children cannot receive an implicitly permissive Skill filter.

## Kind
bug_fixing

## Context
Fix the open spawn security gap recorded in memory. Verified by independent audit and lead code reading: src/host/runtime.rs compute_subagent_allowlist returns Some(vec![]) when a supplied parent_id is absent from the agent-loop map. spawn_agent_shared then calls set_role_allowlist(role == Some(\"reviewer\"), list); with role None this selects set_tool_allowlist (src/app/workflow/mod.rs:3475-3483), which becomes ToolFilter::Skill([]) (mod.rs:498-502). Skill auto-grants memory tools, ask_user, backlog mutations, and other implicit tools (src/tool/mod.rs:1080-1139). A roleless child with a stale supplied parent therefore is not fail-closed. Reviewer roles become strict Reviewer([]), and ordinary live-parent spawns are unaffected. This predates the recent unknown-role fix. Fix at the real shared-spawn boundary: if a caller supplies Some(parent_id) but that parent's loop is not registered, return a clear Err from spawn_agent_shared BEFORE allocating an id, constructing agent state, spawning tasks, or registering anything. Do not silently substitute a restrictive filter. Parent None keeps its current behavior; reviewer behavior and live-parent intersection must remain unchanged. Regression test: in src/host/runtime.rs tests, replace/extend the helper-only missing_parent_loop_denies_all coverage with a shared-path test named `missing_parent_loop_rejects_roleless_spawn_before_registration`: call spawn_agent_shared with a nonexistent Some(parent_id), role None, and assert both the clear error and an empty agent-loop map. Prove it fails on the unfixed code (it currently returns Ok and registers a loop), then green after. Add reviewer-role missing-parent rejection coverage too, since the shared boundary should behave consistently. Run cargo test --workspace unpiped and check $LASTEXITCODE. Keep the diff focused on src/host/runtime.rs.

\## Acceptance scenarios
- A shared spawn with a nonexistent supplied parent id and role None returns a clear error and leaves the agent-loop map empty; the same test fails against the unfixed code.
- The same stale-parent condition with role reviewer is rejected consistently.
- Parentless role None still spawns with its existing permissions, and a valid live parent still produces the existing parent/subagent intersection.
- cargo test --workspace passes warning-free.

Audit follow-up: the initial contains_key guard is insufficient because parent_root_binding and compute_subagent_allowlist perform later independent map lookups. Parent exit between them can still produce permissive Skill([]) for a roleless child and lose worktree/root inheritance. Fix by capturing the validated parent Arc once before agent-id allocation and deriving both the root binding and permission intersection from that same snapshot; alternatively abort on any later disappearance before task spawn/registration. Do not retain an empty roleless list as a security fallback. Add a deterministic regression that removes a validated parent from the map before the later derivation and proves the child still uses the captured parent's permissions/root binding (or the spawn aborts), never permissive Skill([]) or the default root. The new regression must fail against 9dce514 and pass after. A fresh independent audit at the new exact tip is required.
