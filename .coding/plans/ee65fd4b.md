# Plan: Research plans may write .coding artifacts; close the sub-plan review leak

## Goal
A: a research-kind plan may write its own artifacts under `.coding/**` with the file tools (file_edit/file_write/file_append/convert_line_endings), enforced at dispatch as a path-scoped carve-out of `ToolFilter::ExecutingResearch`; every non-artifact target (source trees, protected side-car files, traversal escapes) stays denied, so "research produces no source diff" remains true and its review exemption stays honest. D: when an implementation or bug_fixing SUB-plan completes under a root that would skip review, that root becomes review-required — its completion lands in Reviewing (with the existing review-report gate) instead of Complete, so nested source edits are actually reviewed. Both changes ship with regression tests, updated doc comments, and synced docs.

## Kind
implementation

## Context
USER-APPROVED SCOPE (2027-01-11): options A + D from the design review of the research-plan write gate. A = research plans may use the file tools on artifact paths (`.coding/**`) but never on source; D = a completed implementation/bug_fixing sub-plan under a non-reviewing root forces review, closing the leak found today.

WHY (the contract being preserved): research skips review because it produces no source diff — the review's whole value is verifying a diff. The kind is chosen BY THE AGENT at create_plan time, so the write ban is what makes the skipped review honest: `ToolFilter::ExecutingResearch` (src/tool/mod.rs:411-425, doc comment :204-226) denies file_edit/file_write/file_append/convert_line_endings (+ mcp__*) at dispatch. A keeps that guarantee but draws the boundary at PATH level instead of TOOL level, so a research plan can write its own analysis artifacts with the sanctioned file tools (today it must fall back to shell — the code explicitly tolerates that — or be misfiled as `implementation`; precedent: plan c43ad4a3).

D — THE LEAK (recorded as a BUG memory + .coding/knowledge/bug/2027-01-11-unreviewed-source-edits-via-research-root-implem.md): the write filter keys on the ACTIVE plan (src/workflow/mod.rs:419-423 narrows only when the top-of-stack plan is Research; the comment explicitly endorses "a research root may push an implementation sub-plan, and that sub-plan does need to write"), while the review decision keys on the ROOT plan — `Workflow::complete_step` pops a finished sub-plan "regardless of kind (sub-plans never trigger the review sequence)" (:830-834) and only the root's kind selects the transition (:839-848). So research root → implementation sub-plan → edit source → complete → Complete with `reviewed = true`, unreviewed (and no commit step runs). D makes that path land in Reviewing.

TRAPS (must be handled, they are the review bait):
1. `..` traversal: a naive `starts_with(".coding/")` accepts `.coding/../src/main.rs` → the resolver MUST fold `.`/`..` lexically (no filesystem access, works for not-yet-existing files) and refuse anything escaping the root. Prefer reusing the existing creation-path normalizer (`validate_for_creation`, documented at sandbox.rs:190-196) if it is callable; otherwise add a small pure helper next to it.
2. Protected targets inside `.coding/` (plans/, reviews/, knowledge/, backlog, DBs) must NOT become writable via the artifact allowance → the predicate is `rel_str.starts_with(".coding/") && !self.is_protected_write_target(path)`.
3. `mcp__*` and every other denied name keep the blanket denial (no carve-out).
4. D needs persistence: the new flag must round-trip through the sidecar (`#[serde(default)]` so old sidecars still load) and must still force Reviewing when the restart happens BEFORE the root's completion (test: persist mid-flight, load_latest, then complete the root).
5. Reset the D flag when a fresh root plan is created (stack cleared), so a later unrelated research plan is not forced into review.
6. Conservatism accepted: if the implementation sub-plan is later abandoned, the root still goes to Reviewing — a reviewer PASS on an (almost) empty diff is cheap and safe; do not add "smart" clearing.

VERIFY: `cargo test` unpiped from the repo root and read `$LASTEXITCODE` + the `test result:` lines directly (never trust a piped exit code — agent.md); the crate is `#![deny(warnings)]`, so a green `cargo test` also proves zero warnings. Pre-fix reproduction check for both fixes: D — pre-fix the research root lands in Complete, so the new Reviewing assertion fails; A — pre-fix the artifact write is denied at dispatch, so the new dispatch test fails. Frontend untouched (no npm/vitest run needed). Windows/PowerShell; file mutations through file_edit/file_write.
