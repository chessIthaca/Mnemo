# Plan: Hand Claude-agent workers back to Mnemo only when the lead is really gone

## Goal
An agent worker goes back to Mnemo's models only when its lead has really been away for a grace period. A launched agent is found and registered rather than abandoned. A handed-back worker never gets a second writer in a dirty checkout. The lead can reclaim a handed-back worker that no Mnemo model has touched.

## Kind
bug_fixing

## Context
WHY: today the hand-back is immediate. TeamRuntime::leave_external_lead (src-tauri/src/mnemo2/team/external_lead.rs:275) calls hand_back_agent_workers (:292) the moment the lead detaches, including after the 10-minute idle release (EXTERNAL_LEAD_IDLE_MS, mcp_server.rs) and a brief disconnect. after_agent_watch (team/agent_watch.rs:733) does the same for a stalled agent, and TeamRuntime::open (team.rs:~594) hands back at app start. hand_back (agent_watch.rs:948) wipes claude_agent, claude_agent_effort, claude_agent_id and claude_agent_transcript and sets the worker Interrupted, so agent_worker_in_work (:1028) then refuses team_agent_started. Resume paths (team/control.rs resume :543, resume_on_tier :565, also used by Mnemo's own usage-limit auto-resume and the in-app lead) can restart the worker on a Mnemo model in its checkout while a launched agent may still be writing there.

DECISIONS:
1. Grace period. A new setting `agent_hand_back_minutes` in the `[routing]` table of mnemo2.toml, next to `cost_notice_usd` (src-tauri/src/mnemo2/dispatch_routing.rs RoutingSettings, load_routing_settings). Default 30. 0 means immediately (today's behaviour, for tests and users who want it). The team keeps an in-memory `lead_away_since_ms: Option<u64>`: it is set when the external lead detaches or leaves (any path: session end, idle release, project close) and at TeamRuntime::open (there is no lead at app start), and cleared whenever an external lead attaches or re-attaches. A hand-back is due only when no external lead is attached AND now - lead_away_since_ms >= the grace. Put the decision in a pure function `hand_back_grace_passed(away_since_ms: Option<u64>, now_ms: u64, grace_ms: u64) -> bool` so tests can drive it. leave_external_lead, after_agent_watch and open no longer hand back directly: they only start the clock. A periodic check (every 30-60 s; reuse the agent watch loop or the mcp_server idle sweep, whichever already runs while agent workers exist, and make sure it also runs for awaiting_launch workers, which the agent watch's `watched()` excludes today) calls hand_back_agent_workers, which hands back only when the grace has passed. A brief reconnect, or a lead stuck behind a permission prompt for less than the grace, therefore never triggers a hand-back.
2. Look for the agent before handing back. For an awaiting_launch worker that is due, first scan `~/.claude/projects/*/*/subagents/agent-*.jsonl` (the same roots and link rules the existing find_transcript / agent_watch helpers use; reuse them) for a transcript that is newer than the worker's dispatch or its last reroute to the agent tier (record.created_at_ms or the latest reroute ts), that is not already registered to another worker, and whose first user message names this worker's worktree path or its branch (`wt/agent-<id8>`). If exactly one matches, register it as team_agent_started would (claude_agent_id, transcript, last_activity), start following it, and do not hand back. With several matches, take the newest and say so in the log. With none, hand back.
3. No second writer. hand_back now records what it took away in a new persisted field on WorkerRecord (team/record.rs): `handed_back: Option<HandedBack>` with `at_ms`, `claude_agent`, `claude_agent_effort`, `status` (Working or Fixing before the hand-back), and serde(default) so old ledgers load. Resuming a worker whose `handed_back` is Some onto a Mnemo model (any path that would start a Mnemo session: team_resume with or without a tier, resume_on_tier, the usage-limit auto-resume, the in-app lead) is REFUSED while its checkout has uncommitted changes (`git status --porcelain` non-empty, ignored files excluded, like pool_is_free's check). The worker stays Interrupted, and the lead gets a notice naming the worker, the checkout and the recovery calls. The external lead's team_resume gains an optional `keep_changes: bool` (default false); only `keep_changes: true` lets a Mnemo model take over a dirty handed-back checkout. Mnemo's own automatic paths never pass it, and the in-app lead's tool does not expose it. Once a Mnemo session has started on the worker, `handed_back` is cleared (a Mnemo model ran). Resuming onto an agent tier (hand_to_agent_locked) is allowed, and also clears it.
4. Reclaim. team_agent_started on a worker that is Interrupted with `handed_back` Some (no Mnemo model ran since) is ACCEPTED. It restores claude_agent, claude_agent_effort and the recorded status (Working/Fixing), clears error and handed_back, registers the agent exactly as for a normal registration, persists, and answers "Restored <id> as a Claude Code agent worker and registered agent <agent_id>". With `handed_back` None (a Mnemo model ran since, or it was never handed back) the existing refusal stays, with a reason that says why.
5. The hand-back notice (handed_back_notice) names the worker, its checkout, whether the checkout has uncommitted changes, and the recovery calls: `team_agent_started` (worker_id, agent_id) to reclaim it with an agent you launched; `team_resume` (worker_id, an agent tier) to start a fresh agent; `team_resume` onto a Mnemo tier, refused while the checkout is dirty unless `keep_changes: true`. HANDED_BACK_REASON says the lead was away longer than the grace.

REGRESSION TEST: `agent_worker_is_not_handed_back_before_the_grace_period` in src-tauri/src/mnemo2/team/tests.rs. A worker awaiting launch, the lead leaves, a hand-back pass runs before the grace passes: the worker stays an agent worker. After the grace it is handed back. Without the fix, the leave hands it back at once.

VERIFY: the exact .coding/checks.toml commands from the checkout root. Test temp folders live in <checkout>/target (cargo [env]); the full cargo test --workspace is long, so run the team tests narrowly while iterating.

## Acceptance scenarios
- The lead detaches (session end or the 10-minute idle release) while an agent worker awaits launch: the worker is still an agent worker 29 minutes later, and if the lead re-attaches within 30 minutes nothing is ever handed back.
- With the lead away for longer than agent_hand_back_minutes, an awaiting_launch worker whose agent transcript (naming its worktree or branch) exists under ~/.claude/projects is registered to that agent instead of being handed back.
- A handed-back worker whose checkout has uncommitted changes is not resumed on a Mnemo model by the usage-limit auto-resume, the in-app lead, or team_resume without keep_changes; it stays Interrupted, and the lead gets a notice naming the checkout and the recovery calls.
- team_agent_started on a handed-back worker that no Mnemo model has run on restores it as a Working/Fixing agent worker with the agent registered; on a worker a Mnemo model ran on since, it is refused with a reason.
- A ledger written before this change (no handed_back field) loads unchanged.

## Bug
Mnemo hands Claude Code agent workers back to its own models too eagerly. Two incidents on 2026-11-24, in another project with Claude Code as the lead: - watersim1: the lead had launched the agent but not yet called team_agent_started when its connection dropped briefly. hand_back_due() handed back the "awaiting_launch" worker, which resumed on GLM-5.3 in the same pool checkout. Two writers worked on the same uncommitted files, and the GLM run cost $12. - ovendrill3x3: the Agent launch waited behind the user's permission prompt for about 35 minutes. The lead was treated as gone, the worker was handed back, and the lead's later team_agent_started was refused.

## Decisions
- 2026-11-24: no spec impact: Changes agent-worker hand-back timing and recovery inside the team runtime and the lead skill text; no OpenSpec capability requirement changes. The external-lead behaviour is described in the skill, which step 2 updates.
- 2026-11-24: added step 3 (Integration check) because steps 1 and 2 ran in parallel
- 2026-11-24: 2026-11-24 (step 1 audit): decision 2's match is tightened. A transcript matches a worker only when its first real user message (skipping isMeta and caveat lines) contains the phrase "on branch <the worker's branch>" (case-insensitive), as Mnemo's claude_agent prompt states it ("You run in your own checkout of this project on branch wt/agent-…"). A prompt that merely mentions another worker's checkout path or branch (e.g. "never touch pool-1") must not match. The checkout-path match is dropped. The re-dispatch branch (dispatch.rs existing-worker start_worker) gets the same dirty-checkout refusal, and start_worker clears handed_back whenever a Mnemo session starts.
