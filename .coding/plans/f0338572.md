# Plan: Anthropic workspace-id option + settings error dialog

## Goal
Add an optional per-endpoint workspace-id config for Anthropic endpoints (persisted in endpoints.toml, editable in the providers settings form, sent as the anthropic-workspace-id header on every Messages API request), and make settings save errors readable by showing the full error text in a dialog instead of a clipped inline strip.

## Kind
implementation

## Context
Confirmed: Anthropic workspace scoping on /v1/messages works via the anthropic-workspace-id HTTP header (LiteLLM issue #29272: sending workspace_id in the BODY is invalid — header only). Current header site: src/provider/anthropic.rs:850-860 (x-api-key + anthropic-version). Endpoint config: src/config/endpoints.rs Endpoint struct (serde, [[endpoint]] tables in endpoints.toml), validation in src/config/patch.rs::validate_endpoint (16 unit tests nearby), adapter DTOs in src-tauri settings.rs (save_endpoints/get_endpoints IPC), form in frontend/src/components/settings/sections/ProvidersSection.tsx. Error display: ProvidersSection renders save errors in a clipped inline element; project already has Radix Dialog primitives (frontend/src/components/ui/dialog.tsx) used by MergeToMainDialog/AboutDialog — reuse those for an error dialog showing the full text.
