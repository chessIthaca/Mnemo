# Plan: backlog_status tool (all states), structured tool errors, ask_user stuck fix

## Goal
Three fixes: (1) a backlog_status workflow tool available in all workflow states (base states AND inside skills) that changes a backlog item's status through one shared guarded transition table, with the harness's hardcoded set_status sites in src-tauri (run_all.rs, backlog_cmds.rs) rerouted through the same table; (2) structured tool-error feedback in the turn loop so the LLM parses the error and re-calls with corrected arguments instead of resending the identical call; (3) fix the stuck "waiting for your answer…" state after an ask_user answer — the frontend must clear the pending question on answer (it currently waits for a new `started` that never comes mid-turn), terminating the old display state so the resumed stream shows fresh.

implementation
