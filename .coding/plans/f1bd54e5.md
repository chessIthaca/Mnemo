# Plan: Settings: Safety, MCP servers, sounds and dark theme

## Goal
Mnemo2's settings dialog gains Safety (approval mode and rules), MCP servers (list, add, edit, test), and an Appearance & sounds page that turns on completion/needs-you sounds and a dark theme, closing the main gaps against Mnemo1's settings.

## Kind
implementation

## Context
Why: the user reviewed which Mnemo1 tools Mnemo2 still lacks; Mnemo1 Settings has Safety, MCP, Appearance and Sounds sections (`frontend/src/components/settings/sections/SafetySection.tsx`, `McpSection.tsx`, `AppearanceSection.tsx`, `SoundsSection.tsx`) backed by `src-tauri/src/ipc/agent.rs` (`get_safety_mode`/`set_safety_mode`/`get_safety_rules`/`save_safety_rules`) and `src-tauri/src/ipc/mcp.rs` (`mcp_list_servers`/`mcp_save_servers`/`mcp_status`/`mcp_test`), which are Mnemo1-binary-only (Mnemo2 cannot call `src-tauri/src/ipc/*`; port the logic). Safety is the most important: Mnemo2 has no switch for how much agents may do without asking.

Verified facts:
- verified: `SafetyMode` (`src/config/general.rs` line 909): `ApproveEachAction` (default), `AutoReadApproveWrites`, `AutoApproveProject`, and an autonomous no-prompt mode; stored as `[general] safety` (the user's `~/.mnemo/config.toml` has `safety = "autonomous"`).
- verified: Mnemo2 settings pages are the `pages` list in `mnemo2/src/components/SettingsDialog.svelte` (Endpoints, Tiers, Models, Savings, Decisions) with one branch per page; saves go through `Setup::patch_settings` via `settings_setup` (`src-tauri/src/mnemo2/ipc.rs` line ~1130), e.g. `model_settings_save(section, value)` in `src-tauri/src/mnemo2/model_settings.rs` line 552, followed by a runtime refresh.
- verified: MCP config API in `src/config/mcp.rs`: `McpServerDef` (38) with `validate` (119), `validate_set` (246), `merge_servers(global, project)` (267), `load_or_default(path)` (312), `save(path, servers)` (341), `save_split` (709); global and per-project files.
- verified: `[ui]` config already has `theme: String` (default "dark", `src/config/general.rs` 1061/1139) and `sound_complete`, `sound_input_needed`, `sound_stopped_errors` booleans (1125-1133).
- verified: Mnemo2 plays no sounds and has no dark theme today: `mnemo2/src/app.css` has no `prefers-color-scheme` or `data-theme` rule, and no component references Audio or sounds.
- assumption: Mnemo2 workers' and the lead's approval prompts honour `[general] safety` the same way Mnemo1's agent does; step 1 verifies how the mode reaches Mnemo2's engines and makes a change apply without restarting the app (or says it needs a restart).

Decisions:
- Steps run in order; each adds its page to the END of SettingsDialog's `pages` list and branch list, so they never edit the same lines at once.
- Backend per step in its own new file under `src-tauri/src/mnemo2/` (`safety_settings.rs`, `mcp_settings.rs`, `appearance_settings.rs`), registered in `src-tauri/src/mnemo2/mod.rs` directly after `laya_settings::save_laya_settings` in step order.
- Safety page: the four modes as a radio list with plain explanations and the autonomous mode visibly marked as risky, plus the safety rules editor (list, add, remove) if Mnemo2's engines use them.
- MCP page: global and project servers (project shadows global, as `merge_servers` does), add/edit/remove stdio and remote servers with validation, a Test button showing the server's tools or the error, and live status. OAuth login for remote servers may be left out with a clear note.
- Appearance & sounds page: the three sound toggles with short built-in sounds played on turn complete (lead or worker), needs-you (approval/question) and stopped-with-errors, generated with WebAudio or bundled tiny files, respecting the toggles; then the dark theme.
- Dark theme (step 4): define every color token in `mnemo2/src/app.css` for dark under `:root[data-theme="dark"]` (and follow the OS with a "System" choice), audit components for hard-coded colors (e.g. `rgb(255 255 255 / 85%)` in GraphView), and add a Light / Dark / System choice on the Appearance page saved to `[ui] theme`.
- Previews: one scene per page added directly after the `settings-laya` scene in `mnemo2/src/test/previewScenes.ts`, plus dark variants of `mission-control` and `lead-chat` for step 4, with dev-only seeds (`npm run check:no-mock`).

Verification per step: `cargo test --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib mnemo2::<module>`, `cargo clippy --manifest-path src-tauri/Cargo.toml --features mnemo2 --lib --tests --bins -- -D warnings`; in `mnemo2/`: `npm run check`, `npm run check:no-mock`, `npx vitest run`. Never start a dev server or any command that does not exit on its own; the lead renders previews.

## Acceptance scenarios
- Settings shows a Safety page where choosing a mode saves [general] safety and the next agent action follows it; the autonomous mode is visibly marked risky.
- Settings shows an MCP page listing global and project servers; adding a stdio server and pressing Test lists its tools or shows its error.
- With sounds on, a finished lead or worker turn and a needs-you prompt play distinct short sounds; turning a toggle off silences that sound.
- Choosing Dark renders mission control, lead chat, settings and the Graph tab in a readable dark palette; System follows the OS setting.
