# Plan: Plan-tool reliability: 1-indexed steps, short ids, forgiving guard

## Goal
Make the plan tools (create_plan / update_plan / complete_step) reliable for the model: 1-indexed step addressing end-to-end, short collision-checked plan ids, a forgiving plan_id guard with did-you-mean hints, plan_id echoed in every result, an out-of-order completion warning at completion time, and clearer index errors.

## Kind
implementation

## Context
Diagnosis (2026 session): (1) complete_step's step_index is 0-indexed (src/tool/workflow/plan.rs:593) but every read surface is 1-indexed — plan md `- [x] N.` (src/workflow/plan_file.rs:282), success echo n+1 (plan.rs:650), UI; console.rs:273 even prints the raw 0-index. (2) Plan id is a full 36-char UUIDv4 (src/workflow/mod.rs:441) and the complete_step plan_id guard (plan.rs:622-636) does exact string match only — transcription typos = retry noise, no hints. (3) complete_step allows out-of-order completion (plan_file.rs:309) but update_plan later refuses (mod.rs:583) — failure far from cause. (4) complete_step/update_plan success data omit plan_id. (5) out-of-range error doesn't state the convention; strict u32 rejects numeric strings. Event chain: turn.rs:1697-1725 parses step_index from tool args → AgentEvent::StepCompleted → channels.rs:392/547 → frontend types.ts:169 → console.rs:272; contract fixtures tests/contract_fixtures.rs:189 + frontend/src/lib/ipc-fixtures/event-step-completed.json pin payloads. Tauri command complete_step exists in src-tauri/src/ipc/commands.rs.
