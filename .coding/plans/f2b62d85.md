# Plan: Trace graphs: stall counts as generate with a dithered stall overlay

## Goal
In the trace graphs, stall time counts as generate: the generate segment includes the stalled byte-silence (value = generation_ms − reasoning_ms), and the stalled share renders as a dithered red hatch overlay inside the generate segment (coverage = stall / generate), mirroring the cached-token emerald hatch on the prompt segment. The stall legend chip toggles only the overlay (height-neutral, like `cached`). Applies to the Trace tab's phase-time chart (TraceStats.tsx) and the per-request detail bars (LlmTraceView.tsx PhaseTimes + UsageCard).

## Kind
implementation

## Context
User request (2026-12-30, follow-up to the stall-mechanics Q&A): stall_ms is a subset of generation_ms (byte-silence gaps inside the streaming window), so the trace graphs should COUNT it as generate rather than carving it out as a separate red segment — with a dithered overlay on the generate segment showing the stalled share, exactly like the cached-token emerald hatch on the prompt segment (TraceStats.tsx TokenChart, the precedent).

Current state (explored):
- frontend/src/lib/traceStats.ts: phaseSeries computes answerMs = max(0, genMs − reasoningMs − stallMs) (generate shown EXCLUSIVE of reason and stall; totalMs already includes full genMs). PHASE_SEGMENTS (9 keys) lists stall as its own additive segment { key: "stall", cls: "bg-red-400/80" }. phaseMsByKey maps generate: answerMs, stall: stallMs (single extractor for columns + tooltips). tokenHeightVisibility is the non-additive precedent (excludes `cached` from the height sum). phaseTipRows renders one row per PHASE_SEGMENTS key.
- frontend/src/components/views/TraceStats.tsx: PhaseChart (258-320) stacks all PHASE_SEGMENTS (stall additive) via stackSegments/stackTotal with chartVisibility; legend chips toggle via the persisted `hidden` set. TokenChart (329-424) is the overlay precedent: stacked = TOKEN_SEGMENTS.filter(key !== "cached"); heightVisibility = tokenHeightVisibility(visibility); the prompt segment renders `relative` with an absolutely-positioned bottom-anchored hatch (backgroundColor rgba(16,185,129,0.22), backgroundImage repeating-linear-gradient(45deg, rgba(16,185,129,0.85) 0 2px, transparent 2px 5px), height = cachedPct); the cached chip toggles ONLY the overlay (height-neutral).
- frontend/src/components/views/LlmTraceView.tsx: PhaseTimes (61-103) and UsageCard (210-291) both compute genShown = gen − reason − stall and render stall as its own segment/line; title text "prep / compact / backoff / connect / wait (ttft) / reason / generate / stall / tools".
- Tests: frontend/src/lib/traceStats.test.ts (fixtures at ~294-306 expect generate: 6000 = genMs − reasoningMs − stallMs; ~399 asserts the PHASE_SEGMENTS key list), frontend/src/components/views/LlmTraceView.test.ts (stall_ms: null fixture).
- Out of scope: the inflight timeline (live Phase state machine — stall stays a live waiting state there; different surface, not the recorded-ms graph the user asked about). The Σ stall summary line stays.

Design (mirrors the cached pattern): generate segment value = genMs − reasoningMs (stall included); stall becomes a non-additive overlay key — new phaseHeightVisibility excludes it from height math (chip stays height-neutral, persisted hidden key keeps working); the generate segment renders a bottom-anchored dithered RED hatch (stall's identity color, rgba(248,113,113,…)) with coverage = min(100, stallMs / (genMs − reasoningMs) × 100) — the clamp matters because a stall during the reasoning window is counted in BOTH reasoning_ms and stall_ms, so stall can exceed the generate remainder. Tooltip keeps an explicit stall row so the exact ms stays readable.
