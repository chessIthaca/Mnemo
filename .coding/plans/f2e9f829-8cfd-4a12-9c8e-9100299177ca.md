# Plan: Steer agents to semantic tools: hard prompt triggers, richer tool descriptions, semantic-first tool order

## Goal
Make the agent actually reach for the semantic tools (memory_recall, memory_write, graph_search/context/impact/path): hard usage triggers in the system prompt's TOOL_STRATEGY, trigger-rich per-tool schema descriptions, and a deterministic semantic-first tool order that preserves provider cache byte-stability.

## Context

3. Per-tool schema descriptions (the text the model reads at selection time): memory_write (src/tool/memory/mod.rs:76-92) and memory_recall (186-201) are purely descriptive, no usage triggers; graph_search (src/tool/agent/codegraph.rs:105-122) has a mild "Prefer this over grep"; graph_context (188-203) decent; graph_impact (267) / graph_path (345) unchecked but likely descriptive.

Decision (documented for review): three levers — (a) hard triggers in TOOL_STRATEGY (MUST/BEFORE/NEVER rules), the strongest lever since the head rides every request; (b) stronger per-tool descriptions with explicit when-to-use triggers, read at the exact selection point; (c) tool order: alphabetical → deterministic semantic-first order (priority class, then name). Order is the weakest lever but cheap and stays byte-stable across restarts (the cache-stability requirement only demands determinism, not alphabetical). All three are implemented; the order question is answered in the final summary.
