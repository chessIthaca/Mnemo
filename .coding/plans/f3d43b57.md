# Plan: Mnemo2 updates itself: background check, download, restart to update

## Goal
An installed Mnemo2 (Windows NSIS/MSI, macOS .app) checks GitHub for a newer release 30 s after start and every 6 hours, downloads it quietly, and shows "Mnemo2 X is ready — Restart now"; the restart installs it after the normal orderly shutdown. Source builds never update themselves. Each tagged release publishes signed update files and latest.json.

## Kind
implementation

## Context
WHY: installed users must download and reinstall every release by hand (review 2026-11-15; the user chose this as the next improvement). The repo is PUBLIC, so the updater fetches https://github.com/chessIthaca/Mnemo/releases/latest/download/latest.json without auth.

DECISIONS (taken; do not revisit):
- Use the official Tauri v2 updater (crate tauri-plugin-updater 2.x, Rust side only; NO npm @tauri-apps/plugin-updater and no new capability permission: the frontend talks to three Mnemo commands).
- Cadence: first check FIRST_CHECK_DELAY = 30 s after start, then every CHECK_INTERVAL = 6 h while running. No settings knob (user preference: automate, no knobs). About page gets "Check now".
- A found update downloads automatically; installation happens ONLY when the user clicks Restart now (banner). A plain quit does not install (Windows' passive NSIS installer would relaunch the app, which a quit must not do); the next session re-checks and re-downloads.
- Restart now asks first when workers are running (same wording as the tray Quit dialog). Install runs inside the existing orderly-shutdown exit closure (src-tauri/src/mnemo2/mod.rs run(), RunEvent::ExitRequested → spawn_orderly_shutdown), AFTER preferences are saved and runtimes/Laya/browser are stopped, then app.restart(). On Windows the plugin's install() starts the passive installer and exits the process itself.
- Cargo feature `auto-update` (mnemo-app: `auto-update = ["mnemo2", "dep:tauri-plugin-updater"]`; mnemo2-app: `auto-update = ["mnemo-app/auto-update"]`). build.yml passes `--features auto-update` on every Tauri build; `npm run rebuild:mnemo2` and local cargo builds do not, so a source build reports phase `disabled` with reason `source_build` and never updates.
- Update signing: minisign key from `npx tauri signer generate`. Public key is committed in src-tauri/mnemo2-app/tauri.conf.json `plugins.updater.pubkey`; the private key and its password live only in GitHub secrets TAURI_SIGNING_PRIVATE_KEY / TAURI_SIGNING_PRIVATE_KEY_PASSWORD (the user sets them). Updater artifacts are enabled through the overlay src-tauri/mnemo2-app/tauri.updater.conf.json (`{"bundle":{"createUpdaterArtifacts":true}}`) passed with `--config` only when the key secret is present; a v* tag build without the key FAILS (a release must never ship without latest.json); branch/PR builds without it just skip updater artifacts.
- latest.json platforms: `windows-x86_64-nsis` and `windows-x86_64` → the NSIS -setup.exe, `windows-x86_64-msi` → the .msi, `darwin-aarch64` → Mnemo2.app.tar.gz; signatures are the contents of the matching .sig files Tauri writes next to each artifact. Written by scripts/updater-manifest.mjs in the release job, uploaded to the draft release with the other assets (the repo uses immutable releases: assets go up while draft).
- First release that can update itself is 2.5.0; the first real self-update is 2.5.0 → the next release.

CONSTRAINTS: Cargo.lock must keep no [[patch.unused]] (guard `cargo test --test integration cargo_lock_keeps`); the workspace vendors wry. Keep existing build.yml step names (ci_workflow guards look for them). License header on new Rust files like src-tauri/src/mnemo2/claude_code.rs (`// Copyright (c) 2026 Carsten Hess` / `// SPDX-License-Identifier: MIT` / `// See LICENSE in the repository root.`).

VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib`, `cargo check -p mnemo2-app --features auto-update`, clippy (`cargo clippy --workspace --all-targets`, `cargo clippy -p mnemo-app --all-targets --features mnemo2`, `cargo clippy -p mnemo-app --all-targets --features mnemo2,auto-update`), `npm run test --workspace mnemo2`, `npm run check --workspace mnemo2`, `node --test scripts/updater-manifest.test.mjs`, `cargo test --test integration ci_workflow`.

## Acceptance scenarios
- A source build (npm run rebuild:mnemo2) answers update_state with {"phase":"disabled","reason":"source_build"} and never contacts GitHub; About shows that automatic updates are off in this build.
- With the auto-update feature, 30 s after start the state goes checking → idle (no newer release) or checking → downloading → ready, emitting each state on mnemo2://update-state; it re-checks every 6 h while idle or failed, and stops checking once ready.
- When ready, the banner shows "Mnemo2 <version> is ready." with Restart now / Later; Restart now with running workers first shows the worker warning, and Restart anyway runs the orderly shutdown, installs the update and relaunches.
- A v* tag build without TAURI_SIGNING_PRIVATE_KEY fails; with it, the release carries latest.json, the .sig files and Mnemo2.app.tar.gz, and latest.json names the NSIS, MSI and macOS URLs of that tag with the matching signatures.
