# Plan: Delta-scope reviewer rounds 2+ (plan-frame round stamps + harness-rendered reviewer preamble)

## Goal
Make reviewer rounds 2+ delta-scoped and prompt-contract-bound, deterministically in the app rather than by the dispatching agent's discipline: a re-review gets a mechanically-derived base revision, a delta instruction and its changed file set; every reviewer spawn carries the app-rendered standard preamble (verdict contract + one-line constitution checks + `.coding/**` accuracy-not-line-review rule); and the measured round-2+ cost drops.

## Kind
implementation

## Context
Backlog 85313a7e-6ee5-4e9c-9a26-6f0175bd6f88 (this item's text is the spec). Symptom: plan febcd6f5 (Savings) burned THREE review rounds in ~33 min; each round re-read the whole uncommitted diff (~28 files) to verify a 1-3 file fix. Round 3 found nothing — pure re-verification at full-diff price. Compounding: the dispatch prompt is enormous (plan recap + inventory + 6 verify questions + test evidence), and `.coding/**` bookkeeping rides the same diff and gets LINE-reviewed. Nothing is mechanically enforced; cost depends on the dispatcher's discipline.

ROOT CAUSE (read, not inferred): the reviewer spawn path has no notion of review ROUNDS and no scope. `SpawnAgentTool::execute` (src/tool/agent/spawn_agent.rs:215-330) forwards the caller's `task` verbatim (reviewer spawns even skip the memory rider so the task stays byte-identical — backlog 1d0332ca, spawn_agent.rs:106-112/323-330), and `reviewer_spawn_gate` (src/agent/dispatch.rs:1482-1533) only polices model/role. So round 2 gets the same "review the whole tree" framing as round 1. The plan frame has no review state at all: `PlanFile` (src/workflow/plan_file.rs:82-138) carries title/goal/context/kind/bug_symptom/regression_test/landed_design/detailed_steps/steps — nothing about reviews.

DESIGN (mechanical, app-side — no convention the dispatcher can forget):
1. ROUND STAMPS ON THE PLAN FRAME. `PlanFile` gains `reviews: Vec<ReviewRoundStamp>` (`#[serde(skip)]` off the frontend wire shape, like its siblings), persisted as a `## Reviews` section (`<round> <base>` per line) through the existing manual parse()/serialize() path (plan_file.rs:197-264 / :340-360; the writer is `PlanFile::save` at :514 — the writer `update_plan`'s tail uses). `Workflow::record_review_round(base)` + `Workflow::review_rounds()` in src/workflow/mod.rs. The stamp is the round's BASE REVISION = `git rev-parse HEAD` at dispatch time. Rationale: the dispatcher is suspended while a review runs (it ends its turn), so HEAD-at-dispatch IS the state that round verified — provided verified work is committed (item 6's step-boundary commits, agent.md). Rounds are stamped only after a SUCCESSFUL spawn: a rejected/failed spawn never advances the round, so a crashed reviewer can never narrow the next round's scope (fail-safe: worst case is a full-scope review).
2. GIT SCOPE HELPERS. src/project/git_ops.rs gains `head_commit_sha` / `changed_paths_since` (spawn_blocking + `RealGit`, mirroring `checkpoint_on_work_branch`:148-158) with `_impl(&dyn GitRunner, ...)` cores so the file's existing fake runner (git_ops.rs:817-960) drives hermetic tests. `changed_paths_since` = `git diff --name-status <base>` + untracked via `status --porcelain -uall`, with git_read.rs's option-injection guards (:32-62).
3. HARNESS-RENDERED PREAMBLE. New src/agent/review_scope.rs: a `ReviewScoper` trait (head/changed_paths — fakeable, house style: GitRunner/AgentSpawner/MemoryStoreTrait) with a `GitReviewScoper` production impl, and a pure `render_review_preamble(&ReviewScope) -> String`. The contract block is ALWAYS appended to a reviewer's task (so it cannot be forgotten): the exact verdict strings finish validates (src/tool/workflow/plan.rs:1865-1879), ONE line per constitution check (docs sync; macOS+Windows neutrality; file-tools-first; `#![deny(warnings)]`-clean), the `.coding/**` = accuracy-check-in-one-line / never-line-review rule, generated/lockfile/dist exclusion. Round ≥ 2 adds the delta block: base revision, "`git diff <base>` is your scope — verify only those hunks", the mechanically-derived changed file set, the empty-diff → PASS-without-re-reading rule, and the re-shown-because-uncommitted → one-line process remark (do not re-review) rule. Rendered in the spawn path (spawn_agent.rs) so it is structural, not conventional. Non-reviewer spawns are untouched — their task stays byte-identical (the 1d0332ca invariant is pinned by a test).
4. REPORT PROVENANCE. write_review_report appends a trailing `Reviewed-state: <sha>` line on create (best-effort; a git failure never fails the write). DEVIATION from the item's "front matter": the verdict MUST be the file's first non-blank line — this tool's own contract (write_review_report.rs:306-320, and finish/parse_verdict depend on it) — so provenance is trailing. To be recorded in the plan context amendment.

ACCEPTANCE (from the item): (a) a 2nd+ reviewer spawn automatically names base revision + delta instruction + changed file set (pinned by a test beside `reviewer_role_is_forwarded_to_spawner`, spawn_agent.rs:601-620); (b) the standard preamble is present WITHOUT the main agent supplying it; (c) measured round-2+ cost drops materially — record before/after in the plan + report; (d) `.coding/**` is not line-reviewed; (e) root `cargo test` (unpiped) + frontend tests green, warning-free.

No frontend source changes are expected (this is prompt/plumbing work) — the frontend suite is run for the acceptance requirement only.

MEASUREMENT METHOD for (c), decided up front because a controlled same-diff A/B wall-clock is NOT reproducible in one session: BEFORE = the recorded round wall-clocks/scope of the febcd6f5 evidence (.coding/reviews/2026-09-25-febcd6f5-savings-section-round*-review.md — file mtimes + the file counts each round names). AFTER = (i) the rendered round-2 preamble size vs the historical round-2 dispatch size, and (ii) the file count the mechanically-derived changed set names for a comparable case, and (iii) opportunistically, if THIS plan's own review returns findings, its round-2 wall-clock is the first live datapoint. Stated plainly as a proxy, not an A/B.

ARCHITECTURE. (1) Round state lives on the plan frame: `PlanFile.reviews: Vec<ReviewRoundStamp>` (`src/workflow/plan_file.rs`), persisted as the `## Reviews` section (one `<round> <base>` line each), so the delta scope survives a restart; `Workflow::record_review_round` / `Workflow::review_rounds` (`src/workflow/mod.rs`) mutate and read it. (2) The git reads: `head_commit_sha` / `changed_paths_since` (`src/project/git_ops.rs`, `spawn_blocking` over the file's fake-able `GitRunner`), with `validate_base_ref` refusing `-`-prefixed / whitespace / metacharacter bases before git is invoked (the stamp round-trips through a file, so it is untrusted). (3) The rendering: new `src/agent/review_scope.rs` — `ReviewScoper` trait (+ `GitReviewScoper`), `ReviewScope`, `render_review_preamble`. (4) The wiring: `SpawnAgentTool::with_review_scope` (`src/tool/agent/spawn_agent.rs`) appends the preamble in the reviewer branch of `execute` and stamps after a successful spawn; `WriteReviewReportTool::with_review_scoper` appends the trailing provenance line; both wired in `src/agent/factory.rs`.

INVARIANTS TO PRESERVE. (a) A stamp lands ONLY after a SUCCESSFUL spawn — a rejected/failed spawn never advances the round, so a crashed reviewer can only WIDEN the next round's scope, never narrow it to a diff nobody verified (fail-safe). (b) HEAD-at-dispatch is the round's base, which is sound because the dispatcher suspends (ends its turn) while the reviewer works. (c) Best-effort everywhere: a git failure degrades to the contract-only preamble / an unstamped round / an omitted provenance line and NEVER blocks a spawn or a report write. (d) NON-reviewer spawns stay byte-identical (the 1d0332ca invariant, pinned by a test) — the preamble is reviewer-only. (e) The plan file is the crash-resumption document, so the round stamps are persisted there, not held in memory.

DEVIATIONS from the plan/backlog sketch. (1) Provenance is TRAILING (`Reviewed-state: <sha>`), not front matter: the verdict line must remain the report's first non-blank line (this tool's own contract, re-read by finish/parse_verdict), so front matter is impossible by construction — documented in the module doc. (2) Dropped the sketched `branch` field from `ReviewScope`: the base sha is unambiguous and `git diff <sha>` needs no branch name, saving a git round-trip. (3) ADDED beyond the item: an Empty-diff rule in the contract, because the item's own convention (commit code at step boundaries) can leave an empty uncommitted diff at review time and a clean tree must never read as a vacuous PASS — the rule points the reviewer at `git merge-base main HEAD` → `git diff <that>`. (4) ADDED: a prompt-budget test pinning the rendered preamble size.
