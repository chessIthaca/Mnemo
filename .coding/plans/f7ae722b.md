# Plan: One consistent type scale across Mnemo2's UI

## Goal
Every text element in the Mnemo2 frontend uses the right font family and a size from one small, named type scale, so mission control reads consistently. No text falls back to the browser's 16px default, and no markup class is left without a style.

## Kind
implementation

## Context
WHY: the user compared two panes of mission control: "the font on the right seems good, the font on the left not so much. Can we review the stylesheets to make sure we use the right fonts everywhere to make it consistent?" Right: the worker thread and plan card, with prose in Source Serif (--font-prose) and small Inter labels. Left: the worker list, where each worker's task summary renders in large Inter at the browser default size, far bigger than the names and badges around it.

FINDINGS (probed while planning):
- verified: mnemo2/src/app.css defines --font-ui (Inter Variable), --font-prose (Source Serif 4 Variable), --font-mono, and `button, input, textarea, select { font: inherit; }`. The root sets font-family var(--font-ui) and no font-size, so any element without a size renders at the 16px default. Components use hard-coded px sizes from 7px to 26px, with no shared scale tokens.
- verified: `git log -S"worker-task {" -- mnemo2/src/components/WorkerRow.svelte`: 68133c0 deleted `.worker-task { ... color: var(--muted); font-size: 9px; ... }`, and 09d0fed re-added only `display: -webkit-box; line-clamp: 3; ...`. The worker list summary therefore has no size or colour now. This is the left pane in the user's screenshot.
- verified: a script listing classes used in markup but defined in no <style> block or app.css found: Collapsible.svelte [collapsible], LeadChat.svelte [lead-entries], WorkerInbox.svelte [inbox-entries], WorkerRow.svelte [worker-progress], WorkerThread.svelte [thread-panel], and WorkerDetail.svelte [active, checks-panel, detail-body, detail-tabs, file-areas, merge-panel, merge-reverted, model-locked, timeline-panel, worker-actions, worker-blocker]. Some are harmless hooks; worker-progress (the row's progress bar) and the WorkerDetail set lost real styling.
- WorkerDetail.svelte, TaskWorkflow.svelte and lib/workerThread.ts are being redesigned right now by another plan (compact pinned worker header); this plan must not edit them.

DECISIONS:
- Add a small named type scale to app.css :root, e.g. --text-2xs, --text-xs, --text-sm, --text-md, --text-lg, --text-xl (pick values that match the current visual scale: badges ~7-8px, meta ~8-9px, body/labels ~10-11px, prose ~13-14px, titles ~15-17px), plus the families above. Set a sane root size so nothing can fall back to 16px by accident.
- Family rules: --font-prose for long-form reading text (message bodies, plan text, briefs read in full, markdown); --font-ui for chrome (names, labels, buttons, badges, list summaries, meta); --font-mono for code, branches, paths and commits. The worker-list summary is chrome-sized muted text, not 16px.
- Migrate every component's font-size declarations to the tokens; fix elements with no size; restore the lost styling for worker-progress; give orphaned container classes a rule only where they need one (otherwise remove the dead class).
- Keep layout, colours and behaviour unchanged apart from fonts and the restored rules. No new dependencies.

VERIFY:
- npm --prefix mnemo2 run check
- npm --prefix mnemo2 test
- Fresh worker worktrees need `npm ci --no-audit --no-fund` at the worktree root.

## Acceptance scenarios
- In mission control the worker list's task summaries are small muted UI text, consistent with the names and badges around them, not large 16px text.
- Every font-size in mnemo2/src/components/*.svelte (except the two worker-header files until step 2) uses a --text-* token; grep finds no other px font-size outside app.css.
- Thread and plan prose stays in Source Serif; names, labels, buttons and summaries are Inter; branches, paths and commits are mono.
- The worker row progress bar is styled again.
- npm --prefix mnemo2 run check and npm --prefix mnemo2 test pass.
