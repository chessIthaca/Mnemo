# Plan: Scope the MIX architecture: native core + webview subcomponents (game browser CDP + agent chat React)

## Goal
Produce a scoping memo for the MIX architecture: native core (window + layout + webview hosting + creation order) with webview subcomponents (game browser = CDP webview created first; agent chat = React webview created second, no CDP). Identify the make-or-break unknown (Tauri bare-window ordered-children vs non-Tauri shell), what stays React vs goes native, effort estimate, and a phased plan. No source changes.

## Kind
research

## Context
REFRAMED by user insight: it's a MIX — a native core (window + layout + webview hosting) with webview subcomponents. Only the GAME BROWSER needs CDP; the AGENT CHAT can be a second webview that renders React without CDP — this is the CONFIRMED behavior of the shipped child webview (second env renders fine, just no CDP). So the agent chat, Markdown, diffs, panels — all the hard-to-port-natively stuff — STAY React. The native core's job is creation ORDER: game-browser webview first (grabs 9222 → CDP), agent-chat webview second (renders, no CDP — acceptable).

This is NONE of the exhausted paths: not browser-in-browser (siblings, not nested), not env-share (doesn't compile), not a second debug port (crashes), not a separate OS window (user-rejected sync/overlay). It's two sibling child webviews in ONE window, with the CDP one created first.

MAKE-OR-BREAK UNKNOWN: can creation order be controlled WITHIN Tauri (bare Window + ordered add_child → first child grabs 9222), or does it require a non-Tauri native shell (egui/iced/tao+wry with explicit webview creation)? If Tauri works → near-zero port (reconfigure window model, keep React + IPC + brain). If not → native shell (bigger). This is the linchpin and is untested.

Confirmed facts (from source + memory): main.rs:60-65 sets WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS process-global before builder; first env created binds 9222; second env's 9222 bind fails silently but env creates + renders (shipped child webview proves rendering); add_child is on Window (works on bare Window or WebviewWindow); Tauri 2 has WindowBuilder (bare window, no webview) vs WebviewWindowBuilder.
