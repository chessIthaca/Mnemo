# Plan: Enforced read-only reviewer subagent

## Goal
Make the reviewer subagent truly read-only by construction: a `role: "reviewer"` arg on `spawn_agent` constrains the spawned agent to a read-only tool allow-list (read tools + a new `git_diff` tool + a new `write_review_report` tool + memory), enforced via the existing `ToolFilter::Skill(Vec<String>)` mechanism. The reviewer can read code and write only its report under `.coding/reviews/`; it cannot edit project files, run shell, commit, spawn, or finish. The main agent (in Reviewing) keeps all its tools and does the fixing/committing.

## Context
Today the reviewer subagent is NOT actually constrained. spawn_agent builds the subagent via factory.build_inner, which calls Workflow::load_latest() — loading the SAME plan the main agent is on. Since the main agent is in Reviewing (plan complete, reviewed=false), the subagent ALSO enters Reviewing, and ToolFilter::Reviewing is `ToolCategory::Agent => true`. So the reviewer gets file_write/file_edit/file_append/shell/git/spawn_agent/finish. "Reviewer must not edit project files" is prompt-only.

Design (reuses existing machinery, no new workflow state):
- Workflow already has a per-agent tool-allow-list mechanism: ToolFilter::Skill(Vec<String>), returned by allowed_tools() when active_skill is Some. We add a parallel in-memory field `tool_allowlist: Option<Vec<String>>` on Workflow (NOT persisted in StackSidecar — it's a spawn-time property, like plan_mutations_allowed). allowed_tools() returns ToolFilter::Skill(list) when set, regardless of state. This is in-memory only so it can't clobber the shared plan state on disk.
- spawn_agent gains an optional `role: String` arg. When role=="reviewer", the spawner sets the allow-list to: file_read, read_files, search, search_read, describe_image, list_models, git_diff, write_review_report (+ memory tools are always available via the Skill filter's Memory=>true arm; ask_user + current_plan too).
- New tool `git_diff` (AutoRun, ToolCategory::Agent): runs `git diff HEAD --stat` + `git diff HEAD` + `git status --short` in project_root, capped via cap_tool_output. Read-only — the reviewer's only way to see uncommitted changes (it has no shell/git).
- New tool `write_review_report` (AutoRun, ToolCategory::Agent): writes content to a path under .coding/reviews/ only (canonicalize + starts_with check, mirroring FinishTool's report validation). Returns the written path. This is the reviewer's single output channel.
- Both new tools registered in factory.register_agent_tools (always present; gated by the allow-list, not registration).
- spawn_agent_shared / ParentAwareSpawner::spawn_with_parent gain a `role: Option<String>` param threaded from the tool. When role=="reviewer", after building the loop, set the workflow's tool_allowlist.
- The Reviewing prompt for the main agent is updated: tell it to spawn the reviewer WITH role:"reviewer", and that the reviewer is read-only and writes its report via write_review_report.

Key files: src/tool/mod.rs (ToolFilter allows + new field), src/workflow/mod.rs (tool_allowlist field + allowed_tools), src/tool/agent/spawn_agent.rs (role arg + threading), src/runtime/mod.rs (ParentAwareSpawner signature), src-tauri/src/ipc/spawn.rs (spawn_agent_shared + IpcSpawner), src/tool/agent/git_diff.rs (new), src/tool/agent/write_review_report.rs (new), src/tool/agent/mod.rs (pub mod), src/agent/factory.rs (register new tools), src/agent/prompt.rs (Reviewing prompt).
