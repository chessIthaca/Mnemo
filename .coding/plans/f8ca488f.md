# Plan: Provider layer: extract shared SSE/stream helpers into sse_util.rs (openai + anthropic)

## Goal
Extract the duplicated SSE/stream plumbing shared by the OpenAI and Anthropic providers into src/provider/sse_util.rs: the four byte-identical helpers (truncate_raw_stream, header_str, error_chain, finish_reason_label), the SseOutcome enum, and ONE parse_data_url with the deliberately-chosen png-default empty-media-type contract (documented). openai.rs and anthropic.rs import from the shared module and drop their local copies; backlog.rs keeps its intentionally-divergent local copy with a comment (MIME→extension mapping is a different concern — no behavior change). Unit tests live in the new module (the moved truncate_raw_stream + parse_data_url_variants tests plus a new finish_reason_label test); every existing provider test stays green.

implementation

## Context
Verified state: the four helpers are byte-identical between src/provider/openai.rs (:2453-2507 — header_str, error_chain, truncate_raw_stream, finish_reason_label) and src/provider/anthropic.rs (:1044-1097) — bodies identical, docs differ only in provider-specific references (openai's truncate doc has an extra first line; finish_reason_label's doc cites choices[].finish_reason vs stop_reason — the shared doc should cover both). SseOutcome (Event(LlmEvent)/ParseError(String)) identical at openai.rs:2819-2826 ≡ anthropic.rs:571-578. parse_data_url exists in exactly TWO copies, not three as the task text claimed — openai.rs holds NO copy (verified by tree-wide symbol search + a base64/data: scan of openai.rs; the quality review's count was stale): anthropic.rs:556-569 (empty media type → "image/png") and src/backlog.rs:905-913 (empty media type → "" as-is, feeding mime_to_ext whose default is "bin" — write_image_files :633-667 uses it for file extensions). Call sites: header_str ×3 per provider (content-encoding/transfer-encoding/content-type in stream-decode errors), finish_reason_label ×1 each (trace log), error_chain ×1 each, truncate_raw_stream in parse-error paths. Existing tests: openai.rs :2894-2907 (three truncate_raw_stream tests), anthropic.rs :2754-2768 (parse_data_url_variants incl. the png-default assertion); header_str/error_chain have no direct tests (reqwest types are hard to construct — leave untested), finish_reason_label gets a new trivial test. DESIGN DECISIONS: (1) New module src/provider/sse_util.rs holds the four helpers + SseOutcome + ONE parse_data_url, all pub(crate), declared in src/provider/mod.rs. (2) The shared parse_data_url takes the anthropic png-default contract (the task's direction: the safer contract for provider image payloads — an empty media type in an API source block would be invalid; png is the sane fallback) — documented in the module. (3) backlog.rs KEEPS its local copy with a comment noting the intentional divergence: its concern is MIME→extension mapping (empty → mime_to_ext's "bin" default), importing the provider module would be a layering smell (backlog is not a provider concern), and a refactor must not change backlog image-file extensions. (4) parse_sse_buffer stays provider-local — the protocols differ materially (openai choices[] chunks vs anthropic event-typed stream); only the verified byte-identical pieces move. (5) The moved tests keep their names (truncate_raw_stream_keeps_short_strings_intact, truncates_long_strings, backs_up_to_char_boundary, parse_data_url_variants) so history stays greppable; a new finish_reason_label test covers the snake_case mapping + Other passthrough. (6) The shared doc comments merge both providers' references (e.g. finish_reason_label cites both stop_reason and choices[].finish_reason). Test gates: root cargo test (1967 passed / 4 ignored baseline — the provider tests live there) + src-tauri cargo test (186+4, unaffected but run for the gate); frontend untouched. Docs: internal refactor — check README/PLAN provider sections during verify; likely no changes needed.
