# Plan: Mnemo2 runtime tests flake on 2 s fixed poll budgets under load

## Goal
Every runtime test that waits for something to BECOME true waits on the condition with a generous deadline (120 s) instead of a 1-10 s fixed poll budget, so loaded check runs stop failing it. Assertions are unchanged.

## Kind
bug_fixing

## Context
ROOT CAUSE: known class (BUG 'Mnemo2 team tests flake on fixed poll budgets — Completed precedes the terminal transcript refresh'; HOW 'write tests that stay green under a loaded machine (wait on the event, not on the clock)'). The worker is marked Completed before its transcript is attached (the pump's spawned refresh task), and other async work (inbox writes, deferred labels) lands later. src-tauri/src/mnemo2/team/tests.rs already uses an `eventually` helper (team/tests.rs:5931: polls every 25 ms, 800 tries = 20 s); src-tauri/src/mnemo2/runtime/tests.rs still polls with `for _ in 0..N { if cond { break } sleep(20ms) }` and then asserts the condition.

FIX (test-only, src-tauri/src/mnemo2/runtime/tests.rs): add one helper near the top of the tests module, `async fn wait_for<F, Fut>(what: &str, probe: F) where F: FnMut() -> Fut, Fut: Future<Output = bool>`. It polls every 20 ms until probe() is true and panics with `format!("timed out after 120 s waiting for {what}")` after a 120 s deadline (std::time::Instant, not a loop count). A value-returning variant `wait_for_value` (Option<T>) is fine if callers need it. Convert every POSITIVE wait loop (loops that break when a condition becomes true and are followed by an assert of that same condition) to the helper, keeping the assert message text as `what` or keeping the following assert unchanged. DO NOT convert NEGATIVE waits: loops or sleeps that check something does NOT happen within a window (e.g. 'no second call arrives', 'stays idle'); leave those exactly as they are and list them in the report. Do not touch wait_until_idle (:900) unless it uses a short fixed budget, in which case give it the same 120 s deadline. Do not change any assertion, fixture, or production code. No #[allow].

REGRESSION TEST: the bug's test larger_findings_route_to_the_tracked_worker_for_delta_review is the regression test (record with plan_update regression_test). Before the fix it fails under load; after the fix it must pass while another cargo build runs. Also run the four previously failing runtime tests named in the bug.

VERIFY: `cargo test -p mnemo-app --features mnemo2 --lib mnemo2::runtime` (whole runtime module) and `cargo clippy --workspace --all-targets`. Do not run `cargo test --workspace`.

## Acceptance scenarios
- No positive wait in runtime/tests.rs uses a fixed loop-count budget; each goes through wait_for with a 120 s deadline.
- The mnemo2::runtime test module passes, and larger_findings_route_to_the_tracked_worker_for_delta_review passes while another cargo build runs.
