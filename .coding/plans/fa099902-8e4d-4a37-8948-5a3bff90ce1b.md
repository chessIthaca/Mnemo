# Plan: Spike: two-tab draw order + browser crash isolation

## Goal
Throwaway standalone Tauri spike: bare Window + two add_child webviews (chat first loading local HTML, browser second loading example.com). Test (1) draw order + tab switching via show/hide, (2) crash isolation — crash the browser renderer and confirm the app + chat survive + the browser recovers.

## Kind
research

## Context
The path-(a) reconfigure (bare Window + two add_child: chat first, browser second) is de-risked for CDP (plan 71bd2daa) + IPC (plan 914dfb46). Two remaining unknowns gate the implementation: (1) does the second add_child draw ON TOP of the first (Z-order for tab overlay), and does show/hide work for tab switching? (2) if the game browser webview's renderer crashes, does the host app survive (process isolation), or does a wry/tao bug propagate the crash to the event loop? Both are answerable in an isolated throwaway spike before touching the real app.
