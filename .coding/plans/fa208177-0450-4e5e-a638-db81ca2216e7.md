# Plan: Plan-kind review gate + workflow lifecycle in system prompt

## Goal
Allow research/investigation plans to skip the code review by keying the review gate on a plan `kind` (research vs implementation), and explain the workflow lifecycle in the system prompt so the LLM can reason about states, tool availability, and when review is required.

## Context
Today every plan ends in Reviewing and `finish` is gated on a non-empty review report — research plans that never touch source code are forced through a pointless review. Decision (recorded in memory): add a `PlanKind` (Research/Implementation, default Implementation) set at create_plan time and persisted in the .md. At root-plan completion, `complete_step` reads the kind: Implementation → Reviewing (unchanged), Research → Complete directly (skip review). `finish` is unchanged — research plans never enter Reviewing. The skip happens at complete_step (not finish) because by finish time the diff is empty (just committed), so a git-based check can't distinguish the two; the kind flag is set at creation, not derived from transient git state. Also add a workflow-lifecycle block to the system prompt preamble (states + tool availability per state + when review is required) so the model reasons forward instead of reacting to per-state text.
