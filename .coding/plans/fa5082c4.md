# Plan: Side panel on every main tab; Memory, Graph and Trace move into it

## Goal
The Mnemo2 window's right-side slide-in panel (the Workbench) opens and works the same from every main tab, and Memory, Graph and Trace live in that panel instead of having their own main tabs. Main tabs become Lead, Team, Cost, Plans.

## Kind
implementation

## Context
WHY. The user's words: "on the lead panel, we have this ability to have a panel come in from the right side for diff, plan files, trace. This should be available for all tabs (lead, team, cost trace, etc). IN fact memory, graph and trace really should be in taht pnel."

TODAY. `mnemo2/src/App.svelte` renders `Workbench` only inside its Lead branch; `Route` has "trace", "graph", "memory" as main routes with buttons in `TopBar.svelte`; `openWorkbench`, `openScreenshot` and `navigateBrowser` force `route: "lead"`; `openTeam`, `openCost`, `openPlans`, `selectWorker`, `openPlanDocument` force `workbenchOpen: false`; the native Browser pane is only allowed on the lead route (`browserPaneAllowed` in `lib/store/browser.ts`); the Workbench has a compact `TraceTab.svelte` that hands over to the full `TraceView.svelte` route. The saved tab is validated natively: `WORKBENCH_TABS` in `src-tauri/src/mnemo2/project.rs` refuses unknown tabs, so a frontend-only change would make every preference save fail with "invalid workbench tab".

CONSTRAINTS. (1) No new setting or knob: the app decides widths and the user can drag (user's standing preference). (2) GraphView and TraceView stay lazy-loaded through `{#await import(...)}` with the `.view-load-error` message: this is a recorded performance decision (PERF-10), the d3-force code must stay out of the main chunk. (3) The live Mnemo2 window is shared with the user: never drive it, never run `npm run rebuild:mnemo2` (it closes the running app), never touch tags or release state. Verify through vitest, svelte-check, the build and preview scenes only. (4) Commit only on your own worker branch.

DECISIONS ALREADY TAKEN (do not reopen). (a) Main tabs: Lead, Team, Cost, Plans. Plans stays: the request does not name it and its plan documents are full-page reading. (b) The panel's open/closed state and tab are independent of the route: it stays open across main-tab switches, and opening it never changes the route. Exception: at window width <= 980px the panel covers the main tab, so choosing a main tab or anything that navigates the main area closes it, otherwise the click would appear to do nothing. (c) The panel's Trace tab is the full `TraceView`; the compact `TraceTab.svelte` is deleted with its test, because a second smaller Trace next to the full one in the same panel has no purpose once the main route is gone. (d) `WorkerPanel` stays Lead-only and keeps sharing the slot: it streams a worker beside the lead chat, and Mission Control already shows that on Team. (e) Trace, Graph and Memory are "wide tabs": they open at 62% of the window until dragged, and remember their dragged width separately from the narrow tabs (`workbenchWideWidth`, persisted as `workbench_wide_width`, same pattern as `board_width`), so going back to Diff returns to the diff width. (f) Tab strip order: Browser, Diff, Plan, Files, Git, Trace, Graph, Memory. (g) The top-bar panel button shows on every main tab and reopens the last tab rather than always Browser. (h) `openGraph` and `openMemory` are deleted: the top bar was their only caller. `openTrace` stays, for the worker hand-overs.

## Acceptance scenarios
- On each of Lead, Team, Cost and Plans the top-bar panel button opens the panel beside the main tab and the route does not change.
- The Workspace nav lists exactly Lead, Team, Cost, Plans; the panel strip lists Browser, Diff, Plan, Files, Git, Trace, Graph, Memory.
- Memory, Graph and Trace render inside the panel, Graph and Trace still as separate lazy chunks in the production build.
- The panel stays open while switching main tabs on a window wider than 980px; at 980px or narrower choosing a main tab closes the covering panel and shows the tab.
- Model calls on a worker opens the panel's Trace tab filtered to that worker, on Team and on Lead, with no route change; Diff on a worker opens the panel beside Mission Control; a Memory path link opens the Files tab in the panel at its line; a Memory plan link goes to the Plans tab.
- A preference save with the graph or memory tab and a wide width is accepted natively, and a project file without workbench_wide_width still loads.
- With the panel open beside Mission Control or Plans the page never scrolls sideways at a 1280px window, including with a large saved worker-list width.
- With the charts open in the panel at a 1100x720 window, the Trace call list can be scrolled to and is at least 420px tall.
- At a window width of 760px or less the top-bar panel button is clickable and the main-tab nav sits at the bottom of the window.
- In a Graph panel narrow enough to stack, the symbol list, canvas and detail do not overlap.
