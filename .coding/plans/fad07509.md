# Plan: Indexing progress dialog for project open (bar + counter)

## Goal
When opening/creating a project, show an indexing progress dialog with a progress bar and a "1/1452 files indexed" counter, driven by the existing index() progress callback via a new Tauri event stream.

## Kind
implementation

## Context
Findings: (1) `CodeGraph::index(progress: Option<&dyn Fn(usize, usize)>)` in src/codegraph/mod.rs already reports `(files_processed, files_total)` after every file. (2) The startup pass (src-tauri/src/main.rs:1456) and the create-project seed pass (src/project/mod.rs:181 via seed_stores, called from src-tauri/src/ipc/projects.rs:103) both pass `None`. (3) A proven event-stream pattern exists: `ReindexEvent`/`emit_reindex` on `codegraph://maintenance` (codegraph_cmds.rs) and `ReconcileEvent` on `memory://reconcile` (memory_maintenance.rs, Progress{done,total} without a phase field — the precedent to follow); throttling via pub(crate) `should_forward_progress(done, total, PROGRESS_EVERY=50)`. (4) Frontend: `onReindexEvent` in frontend/src/lib/tauri.ts shows the listen pattern; the App.tsx reconcile dialog (lines 592-649) is the established full-screen progress-dialog style; ProjectPicker.handleCreate just shows "Working…". (5) build_brain takes `Option<tauri::AppHandle>` (main.rs:920/937), so the startup task CAN emit events; headless console.rs passes None and stays silent. Design: new dedicated channel `codegraph://index-progress` with a minimal event enum (ReconcileEvent-shaped), a self-subscribing `<IndexingOverlay/>` mounted in both App.tsx and ProjectPicker, a 1-second time gate on the startup pass so fast passes emit nothing (no overlay flash), and immediate Started on the create-project seed pass (a new project always does a full first index).

## Steps
- [x] 1. **Add IndexProgressEvent + emit helper + startup gate to codegraph_cmds.rs** — In src-tauri/src/ipc/codegraph_cmds.rs (which already owns the codegraph event plumbing), add: `pub const INDEX_PROGRESS_CHANNEL: &str = "codegraph://index-progress";` and `#[derive(Debug, Clone, Serialize)] #[serde(tag = "type", rename_all = "kebab-case")] pub enum IndexProgressEvent { Started, Progress { done: usize, total: usize }, Done { summary: String }, Failed { error: String } }` (mirror the ReconcileEvent shape — Progress has NO phase field). Add `fn emit_index_progress(app: &AppHandle, event: &IndexProgressEvent)` (best-effort `let _ = app.emit(INDEX_PROGRESS_CHANNEL, event);`). Add a pure decision fn for the startup gate: `fn startup_should_forward(elapsed: std::time::Duration, done: usize, total: usize) -> bool` returning `elapsed >= Duration::from_secs(1) && should_forward_progress(done, total, PROGRESS_EVERY)` (reuse pub(crate) `should_forward_progress` + `PROGRESS_EVERY` from crate::ipc::memory_maintenance). Doc-comment the enum: pinned wire shape, distinct from codegraph://maintenance so the Settings card is unaffected. Add tests next to the existing `reindex_event_wire_shape` test: `index_progress_event_wire_shape` (serde_json pins: started → {"type":"started"}; Progress{done:1,total:1452} → {"type":"progress","done":1,"total":1452}; done/failed shapes) and a gate test table (false at 0ms/500ms even for done==total; false at 2s for done=2/total=500; true at 2s for done=50 and done==total).
- [x] 2. **Wire the startup indexing pass to emit progress (main.rs)** — In src-tauri/src/main.rs build_brain_inner (~line 1443-1482), inside the `Ok(graph)` arm: when `app` is Some(app_handle), replace `g.index(None)` in the spawned task with `g.index(Some(&callback))` where callback = move |done: usize, total: usize| { if startup_should_forward(t0.elapsed(), done, total) { emit_index_progress(&inner_app, &IndexProgressEvent::Progress { done, total }); forwarded.store(true, Ordering::Relaxed); } } with `let t0 = std::time::Instant::now();` and `let forwarded = std::sync::atomic::AtomicBool::new(false)` captured (AppHandle is Send+Sync; the callback runs inside spawn_blocking — clone the handle as inner_app before moving).
