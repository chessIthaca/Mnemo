# Plan: Trace tab: Lead-default agent dropdown scoping the top evolution charts

## Goal
The Trace tab opens scoped to the Lead: the agent dropdown gains a Lead option as its default selection, so the Insights charts at the top show the Lead's per-call token and time evolution, with any worker selectable from the same dropdown and All still available — and the llm-trace capability gets its first current-state spec via this plan's delta.

## Kind
implementation

## Context
Why: the user asked (2026-11-05) for a vertical graph at the top of the Trace tab showing how tokens and time evolve per agent, similar to Mnemo1, with an agent dropdown defaulting to Lead. The user also observed that the trace work never got OpenSpec specs — .coding/openspec/specs/ holds only dispatch-routing, external-lead, tier-ladder and worker-brief; there is NO trace capability. This plan carries the feature AND creates the llm-trace capability as its spec delta, bringing the current-state spec up to date for the shipped phase model plus this feature.

What already exists (verified by reading): the vertical graph IS there — TraceCharts.svelte (the Insights panel, TraceView.svelte:1062) renders per-call vertical columns with three tabs (timing phases incl. the new upload/server split, token segments, cost), legend toggles and tooltips, driven by the exact filtered rows the page passes. Mnemo1's reference is frontend/src/components/views/TraceStats.tsx. The rows carry full attribution (trace.ts:78, TraceAttribution with actor_kind/agent_id/agent_name/worker_id), and actorLabel (trace.ts:527) renders "Lead" for actor_kind lead.

The gap: the agent filter dropdown lists WORKERS ONLY — traceAgentOptions (trace.ts:1206-1226) skips null, lead and system attributions and pushes options keyed by worker_id ?? agent_id — and DEFAULT_TRACE_FILTERS.agent is "all" (trace.ts:1095-1108). So there is no way to scope the trace (and the charts) to the Lead alone, and no Lead default.

The change: (1) traceAgentOptions gains a first option "Lead" with a stable value "lead" (not a numeric agent_id — the lead's agent_id is not stable across runs); (2) the agent filter matching gains an actor_kind-based branch for the "lead" value (find where the agent value is applied — the trace.ts:959/1223 keying suggests agent_id matching); (3) DEFAULT_TRACE_FILTERS.agent becomes "lead"; (4) the TraceView reset path (TraceView.svelte:226 resets agent to "all") restores "lead"; (5) verify the Insights panel placement at the top and that it receives the agent-filtered rows so the Lead default scopes the charts on open. Saved prefs (loadTracePrefs) still override the default — only the no-saved-pref path changes.

Constraints: Svelte 5 runes style; no screenshots — source and tests only (standing correction); warning-free svelte-check; PowerShell — read $LASTEXITCODE, never a piped exit code. Files: mnemo2/src/lib/trace.ts, mnemo2/src/components/TraceView.svelte, tests in trace.test.ts and TraceView.test.ts (TraceTab.test.ts if the compact tab's chips are affected). No Rust changes — attribution is already served per row.

## Spec changes

### llm-trace

#### ADDED Requirements

##### Requirement: Every model call is traced with attribution
The Trace tab SHALL record every model request and response the engine makes — the lead's and every worker's alike — with full attribution (actor kind, agent name, worker id, plan and step), phase timings, token usage and cost, and SHALL keep them queryable by agent, model, status, purpose and time, and exportable.

###### Scenario: A worker's call appears with its attribution
- **WHEN** a worker makes an LLM call
- **THEN** the trace list shows the call with the worker's name, plan and step

###### Scenario: Calls are filterable
- **WHEN** the user filters by agent, model, status, purpose or time
- **THEN** only matching calls remain in the list and the charts

##### Requirement: Non-overlapping phase segments
The phase bar SHALL draw non-overlapping segments — Setup (containing Compaction), Upload, Server wait, Generation (containing Reasoning and Stall), Retry wait and Tools — and SHALL render Connect and First token as metric chips rather than bar segments. For SSE providers, response headers arrive with the first chunk, so Server wait carries the server's queue and prefill.

###### Scenario: The bar decomposes a call
- **WHEN** a call has prep, upload, server and generation windows
- **THEN** the bar shows those segments in order with no overlap and no double-counted window

###### Scenario: Legacy rows collapse absent segments
- **WHEN** a row predates the upload and server stamps
- **THEN** those segments collapse and the bar renders without NaN

##### Requirement: Finer live statuses
An in-flight call SHALL derive its live status from its stamped fields — preparing, uploading, waiting for first token, streaming, or stalled — and terminal calls SHALL classify as complete, failed, cancelled or guard-cut.

###### Scenario: The ladder walks a live call
- **WHEN** a polled row gains its stamps
- **THEN** the status walks uploading, then waiting for first token, then streaming

###### Scenario: A stalled stream is visible
- **WHEN** a streaming call goes silent past the stall threshold
- **THEN** its status shows stalled

##### Requirement: Agent scoping with Lead default
The Trace tab SHALL offer an agent dropdown listing Lead first, every observed worker, and All, SHALL default it to Lead, and SHALL scope both the call list and the top Insights charts to the selected agent's calls.

###### Scenario: The tab opens on the Lead
- **WHEN** the trace opens with no saved preference
- **THEN** the dropdown shows Lead selected and the charts show only the Lead's calls

###### Scenario: A worker is selectable
- **WHEN** the user picks a worker from the dropdown
- **THEN** the list and charts show only that worker's calls
