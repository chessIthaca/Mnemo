# Plan: Fix Run-All steer double-turn: next item dispatched before the active one resolves

## Goal
Stop Run-All from double-turning every backlog item: embed the unattended-mode steer IN the dispatched prompt (one command, one turn), guard dispatch against an in-flight turn, and pin both the runtime steer contract and the prompt shape with regression tests.

## Kind
implementation

## Context
User report: backlog Run-All "still starts new items before the active item is fully resolved, resulting in can't resolve state". ROOT CAUSE (verified by reading code, deterministic): run_all_dispatch_next (src-tauri/src/ipc/run_all.rs:324-333) sends `manager.send(main_id, AgentCommand::Suggestion(RUN_ALL_STEER))` and THEN `manager.send(main_id, AgentCommand::Prompt { item.text })`. The agent task's Suggestion arm (src/runtime/agent.rs:372-439) treats a steer landing on an IDLE agent as a full user prompt: converts it to a User message and runs a COMPLETE turn (run_turn_with_retry) — the real Prompt waits in the channel until that turn ends. mpsc FIFO makes this deterministic. Consequence per item: (turn 1) steer-text-only turn → Finished → forwarder on_finished → main idle + no descendants → on_main_turn_resolved(success=true) → workflow rests in Complete (no transition → "plan loop never ran this turn") or Planning ("plan loop did not close") → item N marked CantResolve (+rollback) → run_all_dispatch_next immediately dispatches item N+1; (turn 2) the real prompt for item N finally runs, but current_item now = N+1, so its resolution stamps N+1's status (sometimes wrongly Done + commit_success) and dispatches N+2 — cascading wrong statuses, rollbacks firing mid-turn against the wrong item's work. The ▶/auto-feed path (backlog_cmds.rs dispatch_item:267) sends only a Prompt — unaffected. notify_parent_on_completion also sends Suggestions but only to wake a parent legitimately. The forwarder is a single serialized consumer that awaits on_main_turn_resolved to completion (including the next dispatch), so within-forwarder ordering is safe once the extra turn is gone; remaining risk window: dispatching while a turn is somehow still in flight (guard added). RUN_ALL_STEER content itself (rules 1-4 incl. "marked done ONLY when plan reaches Complete") is good — it just must ride IN the prompt, not as a separate command. emit_prompt_dispatched should keep showing item.text (clean goal bubble; the steer is boilerplate) — document the divergence.
