# Plan: Settings → Savings: expose the token-optimizer levers (backlog ebe21e3c)

## Goal
Rename the Settings → Pricing section to Settings → Savings and give it the token-optimizer surface: the six levers (delta_reads, compress_output, archive, compaction_survival, quality_score, lean_output_nudge) plus their knobs, wired end to end so a toggle persists to config.toml's [general.optimizer] AND takes effect without an app restart. Backend: flat `optimizer_*` Option fields on the settings patch DTO mirroring the `laya_*` precedent (None = keep, so an untouched dialog never rewrites the section and the default-omitted serialization rule holds), exposed on the get_settings payload so the section can read current values. App: the reloaded config's optimizer section must be pushed into the live `Arc<RwLock<OptimizerConfig>>` on save (today only set at startup, so without this every toggle silently needs a restart). Frontend: rename the section (id + label "savings", ONE component covering model rates AND levers) in the nav registry, dialog wiring, section component and the id-pinning tests, then add the levers/knobs with the existing pricing rows in one save patch.
