# Plan: Reproduce release-only Rust build failure

## Goal
Find exactly why the release Rust build (start.bat) fails while debug `cargo test` passes, and identify the missing verification step.

## Kind
research

## Context
User reports start.bat usually fails at the RUST build step even though the loop's `cargo test` (debug) passes. `tauri build --no-bundle` compiles release with `--features custom-protocol` (Tauri v2 CLI), debug_assertions off, cfg(test) off — all different from `cargo test`. Under `#![deny(warnings)]`, any release-only dead_code/unused warning or any code referenced from debug-gated blocks breaks the release build. The repo has dev-only CDP/headless-browser code ("Requires a debug build — the CDP port is dev-only").

## Steps

Read src-tauri/src/main.rs (deny attr, generate_context!, any CDP/browser wiring) and src/lib.rs. Identify code that only compiles or only gets referenced under debug/cfg(test), which would go dead or missing under release.
- [x] 2. **Reproduce the release failure cheaply** — Run `cargo check --release -p myharness-app --features custom-protocol` unpiped (fast: macro expansion + typecheck, catches deny(warnings) errors + generate_context! embed failures without a full codegen). If clean, also run `cargo check --release` (workspace, default features). Read the exact error lines if it fails.
- [x] 3. **Write up root cause + missing step** — Conclude: which item breaks release-only, why cargo test can't see it, and the exact step to add to the standard closing sequence (release check mirroring start.bat, ideally `cargo check --release --features custom-protocol` or the real `tauri build --no-bundle`). No source changes — report in the final summary.
