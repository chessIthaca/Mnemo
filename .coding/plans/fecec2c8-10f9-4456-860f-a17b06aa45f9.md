# Plan: Status bar shows Planning/Skill states + always up-to-date

## Goal
Make the status-bar workflow label show all four states (Planning, Executing, Complete, Skill) with consistent capitalization, always reflecting the actual agent state, while keeping the Executing x/y and Complete logic and the step-picker popup.

## Context
StatusBar.tsx stateLabel (lines 304-317) only special-cases "complete" (→ "Complete") and "executing" (→ "Executing x/y"). For "planning" and "skill" it falls through to `workflowState ?? ""` — the raw lowercase string from the WorkflowStateChanged event / workflowStates map (TS type WorkflowState = "planning" | "executing" | "complete" | "skill"). So Planning shows as "planning" and Skill shows as "skill" — inconsistent casing, and the user wants them shown as "Planning" and "Skill".

The state IS kept up to date: reduceWorkflowStateChanged (useAgentStore.ts:922-930) updates workflowStates[agentId] on every WorkflowStateChanged event + bumps planVersion, and refreshPlan() (StatusBar.tsx:117-126) re-fetches via getWorkflowState on planVersion bump + agent switch + mount, calling setWorkflowState. So the data path is fine — only the label formatting is missing the two cases.

The step-picker dropdown (popup) is gated on hasPlan and opens via setPickerOpen — that's the "popup for Executing and Complete" the user wants kept. It already works for any state with a plan. No change needed there.

Plan: extend stateLabel to map all four states to capitalized labels, preserving the Executing x/y and Complete logic. Optionally enrich "Skill" with the skill name if available — but the StatusBar doesn't currently fetch/hold the active skill name (getWorkflowState returns skill info but StatusBar's refreshPlan only reads wf.plan + wf.state, discarding wf.skill). Keeping it simple: just capitalize the four states. The user said "Skill" and "Planning" so a plain capitalized label matches the ask.
