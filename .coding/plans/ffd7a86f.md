# Plan: Parallel run-all — concurrent main agents, one worktree branch each

## Goal
Run-all dispatches up to N backlog items concurrently: item 1 to the main agent (today's path, unchanged), items 2..N to spawned parentless agents, each working in its own git worktree on its own wt/runall-<item> branch, landing app-side via serialized --no-ff merges into main; backlog statuses resolve per-agent with no cross-agent corruption. N=1 (the default) keeps today's behavior byte-identical. Acceptance: two items dispatched concurrently run on separate branches with separate main agents, both land (item 1 via the existing merge_to_main flow, item 2 via the app-side landing path), statuses resolve to the right items, and cargo test covers concurrent dispatch + status resolution.

DESIGN DECISIONS: (D1) worktrees are mandatory — two agents cannot share one working tree; each spawned item gets git worktree add <root>/.worktrees/runall-<item8> -b wt/runall-<item8> main (unique branch per item, never two agents on one branch). (D2) item 1 → the main agent exactly as today; items 2..N → spawned parentless agents; N=1 keeps today's behavior byte-identical (no spawned runs, no worktrees). (D3) landing is app-side and serialized: the merge_to_main skill cannot run from a linked worktree (git refuses checkout main there), so when a spawned item resolves Done the app merges --no-ff its branch into main via a lazily-provisioned landing worktree (main checked out), deletes the branch, removes the item worktree; conflicts abort the merge, keep the branch+worktree, annotate the item — surfaced, never auto-resolved; this mirrors existing app-level bookkeeping git ops (checkpoint/commit_success) which already run ungated — the agent-facing approval gate is untouched. (D4) memory/knowledge/reviews stay shared (main root, in-process handles); only the code tree (sandbox/project_root/codegraph) is per-worktree; the spawned agent's plans dir is <worktree>/.coding/plans/agents/<id>/ so plan bookkeeping lands on the item's branch. (D5) steers on a spawned agent requeue its item (the simple safe path; the main-agent intervention latch is untouched). (D6) the orphan drain covers spawned runs (dead spawned agent → its item requeues, landed-evidence still auto-Dones). (D7) the spawned dispatch prompt is the standard run-all rules — the agent never merges (the app lands).
