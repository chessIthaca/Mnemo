# Plan: Stats: per-model table + totals row + unified US number formatting

## Goal
Redesign the Stats view's per-model breakdown into a compact, multi-column table (Model, Reqs, Prompt, Completion, Reasoning, Cached, In tok/s, Out tok/s, Cost) with a summary/totals row, and unify all number formatting to US-style comma-grouped integers + consistent $X,XXX.XX costs (replacing the k-suffix token format).

## Context
Verified during exploration:
- StatsView.tsx (394 lines) is the only consumer of three local formatters: fmtTokens (k-suffix), fmtRate (tok/s), fmtCost ($ with 2 or 4 decimals). All 24 usages are in this one file.
- Data available per ModelBreakdown (tauri.ts:462-472): model, prompt_tokens, completion_tokens, reasoning_tokens, cached_tokens, ttft_ms_total, generation_ms_total, timed_requests, request_count. So per-model In/Out tok/s is computable = tokens / (ms_total/timed_requests/1000), same formula the session/project cards use.
- modelCost(mb, pricing) already computes per-model cost from the pricing table. SessionCard shows per-model only when length>1; ProjectCard shows when length>0. Both render the same 2-line block (model / prompt↑ completion↓ / reqs·cost).
- User confirmed US format: comma thousands separators (6,000 / 1,000,000), costs as $X,XXX.XX.
- Right panel applies var(--app-font-size) as base (RightPanel.tsx:111), and StatsView uses em-based text utilities (text-[0.85em] etc.) so a table scales with font size. Panel min-width 300px, default ~40%. A 9-column table is wide; must be horizontally scrollable (overflow-x-auto) and use compact padding + tabular-nums.
- No shared number-format util exists; I'll add a small fmt module in StatsView.tsx (keep it local — only this view uses it). No backend changes needed; all data is already in ModelBreakdown.
- Tests: no StatsView test exists (searched). Frontend checks: npm run build (tsc+vite) + npm test (vitest, 89 tests). The change is render-only; existing tests unaffected.

## Steps
- [x] 1. **Unify number formatting** — in frontend/src/components/views/StatsView.tsx, replace the three formatters with a consistent US-style set: `fmtTokens(n)` → `n.toLocaleString("en-US")` (comma thousands, e.g. 6000→"6,000", 1000000→"1,000,000", no k-suffix); keep `fmtRate(n)` → tok/s with 1 decimal if <100 else rounded, but also group with toLocaleString for large values (e.g. "1,234.5"); `fmtCost(usd)` → always `$` + usd.toLocaleString("en-US", {minimumFractionDigits:2, maximumFractionDigits:2}) (e.g. "$6,000.00", "$1,000,000.00", "$0.0023"→"$0.00" — for sub-cent costs keep 4 decimals: if usd<0.01 use `$${usd.toFixed(4)}`). Add a `fmtInt(n)` helper = `Math.round(n).toLocaleString("en-US")` for request counts. Update the module doc comment to note US-style grouping. All existing call sites (fmtTokens/fmtRate/fmtCost) keep working since signatures are unchanged.
- [x] 2. **Add a per-model table component** — in StatsView.tsx, add a `ModelTable({ per_model, pricing }: { per_model: ModelBreakdown[]; pricing: PricingEntry[] })` component that renders a compact horizontally-scrollable table. Columns: Model | Reqs | Prompt | Compl | Reason | Cached | In/s | Out/s | Cost. For each ModelBreakdown row: Reqs=fmtInt(request_count), Prompt=fmtTokens(prompt_tokens), Compl=fmtTokens(completion_tokens), Reason=fmtTokens(reasoning_tokens), Cached=fmtTokens(cached_tokens), In/s = timed_requests>0 ? fmtRate(prompt_tokens/((ttft_ms_total/timed_requests)/1000)) : "—", Out/s = timed_requests>0 ? fmtRate(completion_tokens/((generation_ms_total/timed_requests)/1000)) : "—", Cost = fmtCost(modelCost(mb, pricing)). Use `<table className="w-full text-[0.75em]"><thead className="text-slate-500"><tr>` with `<th className="text-right font-normal px-1 py-0.5">` (Model column text-left). Body rows `<td className="text-right font-mono tabular-nums px-1 py-0.5 text-slate-300">`, model cell text-left + truncate + title=full model name. Wrap in `<div className="overflow-x-auto">`. Add a totals/summary row (tfoot or a bolded last <tr> with border-t): sum all numeric columns across models (reqs, prompt, completion, reasoning, cached), recompute aggregate In/s and Out/s from the summed totals (sum ttft_ms_total, generation_ms_total, timed_requests then same formula), and total cost = sum of modelCost. Label the row "Total" (text-left, font-semibold).
- [x] 3. **Replace the per-model blocks with ModelTable** — in StatsView.tsx: (a) SessionCard: replace the `{stats.per_model.length > 1 && (...)}` block (lines ~165-184) with `{stats.per_model.length > 0 && <ModelTable per_model={stats.per_model} pricing={pricing} />}` — show the table even for a single model (more useful than the old >1 gate), under the existing "Per model" heading which stays. (b) ProjectCard: replace the `{stats.per_model.length > 0 && (...)}` block (lines ~235-254) with `<ModelTable per_model={stats.per_model} pricing={pricing} />` under the existing "Per model" heading. Keep the per-day breakdown and session list unchanged. The summary/totals row in ModelTable gives the "summarize on the right side" the user asked for (a totals row at the bottom of the table).
