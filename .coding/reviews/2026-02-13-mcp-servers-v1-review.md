### Findings

**LOW 1 — `McpManager::call` can panic on a concurrent-failure race (`src/mcp/mod.rs:317-322`).**
`call()` runs `ensure()` (which releases the connections lock), then re-acquires the lock and does `conns.get_mut(name).expect("ensure() inserted the connection above")`. The invariant does not hold under concurrency: the manager is shared across agents (main + subagents each hold `McpTool` adapters over the same `Arc<McpManager>`), and calls are only serialized while the mutex is held. Sequence: A's `ensure` inserts the connection → B's `ensure` sees it (both release) → A's `call_tool` fails and removes the connection → B acquires the lock → `get_mut` is `None` → panic. `replace_servers` (Settings save) clearing connections between B's `ensure` and B's lock acquisition is the same trigger. Fix: on `None`, re-run `ensure` (or return a clear `Error::Mcp`) instead of `expect`.

**LOW 2 — `load_tools`'s schema enum advertises `mcp.<server>` groups in states where the reveal can never be used (`src/tool/agent/load_tools.rs:73-96`).**
The enum is generated from the full runtime table, while `hidden_groups_for` (the index + `load_tools` visibility) is filter-aware — so in Planning and research the model sees `mcp.*` values in the enum although the index doesn't advertise them. `load_tools` is Agent+AutoRun, so a model can call it in research: the reveal connects to the server (spawns a process / opens a connection that LINGERS in the manager's connections map) even though the resulting tools are hidden by the filter and denied at dispatch. Worst case is research (foreign code runs with no possible use); Planning/Complete are semi-benign (tools become usable once an Executing plan starts on the same agent). Fix options: filter the enum by the same `filter.allows(Agent, NeedsApproval, "mcp__probe")` probe the index uses (requires threading the filter into `schema()`), or gate the reveal itself on the filter.

**LOW 3 — server-name validation is laxer than the namespaced surface it feeds (`src/config/mcp.rs:90-146`).**
`validate` only rejects blank names. A hand-edited `mcp.toml` entry like `name = "fs "` (trailing space) passes validation, but its group `mcp.fs ` can never be revealed — `load_tools` trims the argument (`args.group.trim()`), and `"mcp.fs" != "mcp.fs "` → "unknown tool group". Similarly, `__` inside a server name can alias tool names across servers (`mcp_tool_name("a__b","x") == mcp_tool_name("a","b__x")` — the second reveal silently dedups away). The frontend trims names on save (`fromEdit`), so UI round-trips are safe; only hand-edited files hit this. Fix: reject/trim whitespace and `__` in `name` (backend + frontend validation in one place).
