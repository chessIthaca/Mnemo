## Findings

### LOW (constitution: regression-test-per-defect) — the F1 fix has no regression test

The F1 defect fix (the review's only Medium) ships with zero test coverage. The backend half — the idempotent early-out + synchronous `set_indexing(true)`-before-spawn ordering in `codegraph_refresh` (codegraph_cmds.rs:133-139) — is only indirectly covered by the pre-existing `indexing_flag_flips_around_pass` flag-semantics test; nothing asserts the refresh command's decision path. The frontend half — the falling-edge reload predicate (GraphView.tsx:204-211) — is untested: GraphView.test.ts covers only `buildGraphModel`/`kindColor`, and nothing asserts that a true→false transition triggers a reload while true→true and false→false do not. Per the constitution ("for every defect you fix, add a regression test that reproduces the defect and asserts the fix"), this is a compliance gap. The repo's pure-logic test pattern makes this cheap: extract the transition decision into an exported pure helper in GraphView.tsx (e.g. `export function shouldReloadOnIndexingEdge(was: boolean, is: boolean): boolean { return was && !is; }`), use it in the effect, and add a table-driven vitest case (true→false reloads; false→true, false→false, true→true don't). The backend ordering is a thin wrapper over already-tested flag semantics and is not reasonably unit-testable without the tauri runtime — acceptable if the frontend half is covered.

### NOTE — mount-time startup-pass micro-race leaves a stale-graph window

If the one-shot startup pass completes between the mount `loadGraph` (250 ms debounce, GraphView.tsx:195-198) and the mount status poll's server-side processing, the poll returns `indexing: false`, no falling edge is ever observed (prev was false), and the tab can display the pre-pass graph until the next filter interaction. In practice this is near-unreachable — the status invoke is issued ~250 ms earlier than the graph fetch and is strictly cheaper, so its response almost always reflects the pre-completion state (falling edge then fires) — and it is limited to the startup pass; the user-triggered refresh flow is deterministic under F1. Not blocking; if it ever matters, `loadGraph` after the first `available: true` status would close it.

### NOTE — `slice_unfiltered_caps_at_most_connected` fixture uses literal brace strings

query.rs:694/700 pass the literal `"l{i}.rs"` / `"t{i}.rs"` as the file argument (clearly intended as `format!("l{i}.rs")` etc.). Harmless — symbol ids remain unique because the *names* differ — and all assertions hold, but the fixture's file paths are all identical, which could mislead future readers extending the test.
