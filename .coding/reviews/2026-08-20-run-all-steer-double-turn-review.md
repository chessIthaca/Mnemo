# Review — Run-All steer double-turn fix (fix/run-all-steer-double-turn)

**Scope:** all uncommitted changes. `git status`: `src-tauri/src/ipc/run_all.rs` (prompt embedding + busy guard + docs + tests), `src/runtime/agent.rs` (new pin test `idle_suggestion_then_prompt_runs_two_sequential_turns`), plus `.coding/plans/*` session noise (glanced, ignored per instructions). The plan's goal: stop Run-All double-turning every item (idle-landing `Suggestion` ran as its own turn → steer-only resolution → `CantResolve` cascade + next item dispatched before the real prompt ran).

**Verdict:** the root fix is correct and complete. Two stale-doc findings and one low-severity residual-race observation. No correctness/security findings.

---

## Findings

### 1. LOW (docs — stale comment at the exact site of the fix) — `src-tauri/src/ipc/run_all.rs:414`

`// Inject the unattended-mode steer, then dispatch the prompt.` sits directly above the code that no longer injects a steer, and is immediately contradicted by the corrected comment at lines 420–424 ("ONE command, ONE turn … It must NOT be sent as a separate Suggestion"). This is the leftover from the old implementation at the one place a future reader will look first. Fix: replace with e.g. `// Lock the manager, then dispatch the single combined prompt.` (or just delete it — the 420–424 comment already covers the intent).

### 2. LOW (docs — stale module comment) — `src-tauri/src/ipc/backlog_cmds.rs:28-29`

Module header still says Run-All items get "a git checkpoint, **an unattended-mode steer**, and a commit/rollback on resolution". That describes the deleted `Suggestion` send — the preamble is now embedded in the dispatched `Prompt` text (`run_all::run_all_prompt`). Fix: "Each item gets a git checkpoint, an unattended-mode preamble embedded in its dispatched prompt, and a commit/rollback on resolution."

### 3. LOW (residual race — informational, narrow window; deterministic defect IS fixed) — `src-tauri/src/ipc/run_all.rs:349-376` (guard) vs `:415-427` (send)

The busy guard runs *before* the git checkpoint (lines 378–400, potentially multi-second `spawn_blocking` git ops), but the `Prompt` is sent only afterward — with the manager lock released in between. A turn starting inside that window (user submits a prompt via IPC, or a finishing child's `notify_parent_on_completion` wake-up `Suggestion` lands, events.rs:506) interleaves with the dispatched item and its resolution can stamp the wrong item — the same defect class, but probabilistic and narrow (pre-existing shape; the old code had *no* guard at all, so this diff strictly improves it). Note the single-dispatch path already demonstrates the tighter pattern — `dispatch_item` checks busy and sends under **one** manager-lock hold (backlog_cmds.rs:254-268).

Suggested cheap narrowing (optional, NOT required to merge): after re-acquiring the manager lock at line 415, re-check `is_running() || has_running_descendants(main_id)`; if busy, revert the item — `set_status(item.id, BacklogStatus::Pending, Some(checkpoint))` (set_status is transition-unrestricted, backlog.rs:163-169) and reset `r.current_item.store(0, Ordering::Relaxed)` so the in-flight turn's resolution can't stamp it — then `return Ok(())`; the resolution re-dispatches. Caveat: even this cannot fully eliminate the window (the forwarder flips `running` only when it *processes* the `Started` event, so a just-started turn can briefly read idle). Documenting the residual window in the guard comment would also satisfy this finding.

## Verified clean (review focus 1–5)

1. **No remaining Suggestion-then-Prompt senders.** Repo-wide `AgentCommand::Suggestion` grep: run_all.rs has **zero**. Remaining senders are all legitimate: `notify_parent_on_completion` (events.rs:506, child→parent wake-up), the user steer IPC (`src-tauri/src/ipc/agent.rs:218`), match arms (agent.rs:372/621, turn.rs:276/662/1210), and tests (incl. the new pin test itself).
2. **Image handling unaffected.** `images: item.images.clone()` unchanged at run_all.rs:426; the Prompt arm builds multipart/vision-fallback content from the `images` field independently of `text` (agent.rs:283-332). `run_all_prompt` only wraps text. Also checked the preamble text (run_all.rs:90-99) against every `detect_correction` trigger (correction.rs:21-70) — no phrase matches (incl. "your summary" vs the actual "your final summary"), so no spurious correction-memory events on every run-all item.
3. **Busy guard semantics.** `next_pending()` is genuinely read-only (`&self`, `iter().find().cloned()`, backlog.rs:209-214) — a deferred item stays `Pending`. Lock discipline correct: the guard block (360-376) holds the tokio manager mutex only across sync calls (`main_agent_id`/`get`/`is_running`/`has_running_descendants` — no awaits), dropped at block end before the git-checkpoint awaits; mirrors events.rs's brief-lock discipline. Same busy predicate as `dispatch_item` and the forwarder's resolution check (events.rs:293/325). **No permanent stall:** `on_main_turn_resolved` re-invokes `run_all_dispatch_next` unconditionally (run_all.rs:600) even when the in-flight-item lookup is `None` — so a deferred *first* dispatch (`backlog_run_all` while the agent is busy, backlog_cmds.rs:316-327) auto-recovers when the unrelated turn resolves (forwarder only resolves main when idle + no descendants). Deliberate-halt and question-pending stalls end the run or wait for the user — the documented ▶-recoverable tradeoff.
4. **Pin test genuinely pins.** If the idle-Suggestion arm (agent.rs:372-439) ever buffers instead of running a turn, the steer + queued Prompt merge into ONE turn → `started_count == 2` fails (agent.rs:1367-1368 area). Both valid timing paths hold: (a) Prompt dequeued by the task-loop Prompt arm after the steer turn → `[Injected, Started, Finished, Started, Finished]`; (b) Prompt absorbed mid-turn as a buffered steer (turn.rs:665-667 → `StopReason::Steer` soft-stop → follow-up turn) → still exactly 2 Started/2 Finished with second `Started` after first `Finished`. The command is consumed exactly once, so no third turn exists. `Started` fires once per `run_turn` (turn.rs:88); `MockProvider` (agent.rs:711-740) yields an immediate TextDelta+Finish(Stop), no tool calls — the 2s deadline matches the stable sibling test `between_turn_steer_is_converted_to_user_message_and_runs_turn` (agent.rs:1151-1247); low flake risk. The redundant inner 2000ms timeout mirrors the file's existing style.
5. **Docs.** Module bullet (run_all.rs:20-26), `RUN_ALL_STEER` doc (:79-89), `run_all_prompt` doc (:101-112), and the guard comment (:349-359) are accurate and cross-referenced; the emit divergence is documented at the call site (:429-432) and consistent with `emit_prompt_dispatched`'s contract (events.rs:823-841 — "show … as the goal"). Historical mentions in `.coding/plans|reviews/*` are records, not live docs. Only the two stale comments in findings 1–2 remain.
6. **Constitution.** `pub fn run_all_prompt` (module is `pub mod run_all`, ipc/mod.rs:33) has a doc comment; `RUN_ALL_STEER` is still used (by `run_all_prompt` — no dead code); no `#[allow]` in the diff; both crates built warning-free under `#![deny(warnings)]` (root 1112 passed, src-tauri 85 passed — CRLF "warning:" lines are git's own line-ending notices, not compiler warnings). Regression tests present and meaningful for the defect: `run_all_prompt_embeds_preamble_and_task_in_one_text` (run_all.rs:183-203) + the runtime pin test.
