## Findings

### Medium

**M1 — The two new vitest suites are not in the include list, so they never run.**
`frontend/vitest.config.ts:16-50` uses an explicit `include` list (project convention: every colocated `*.test.ts` must be registered there — see past reviews/plans, e.g. the InflightBar.test.ts precedent). Neither `frontend/src/lib/endpoints.test.ts` nor `frontend/src/lib/reasoningPanel.test.ts` is matched by `"src/components/settings/**/*.test.ts"` or listed explicitly. Result: `npm test` is green without ever executing the new regression tests — false confidence. Fix: add both paths to the include list (e.g. `"src/lib/endpoints.test.ts"` and `"src/lib/reasoningPanel.test.ts"`), re-run `npm test` and confirm the suites actually execute (their describe blocks appear in the output).

**M2 — PLAN.md is out of sync (docs sync, constitution check).**
`PLAN.md:269-272` still claims "the remaining constraint is that model/safety/config changes are global." That is now false for models: the status-bar picker switches only the active agent (the console `/model` REPL and `save_endpoints` remain global by design). Update this sentence to state the new split (GUI picker per-agent; safety/config + console REPL global). Optionally touch `PLAN.md:160-166` ("`/model` and `/provider` … require a restart") — that text is about the console slash-command surface and remains true there, so it only needs a clarifying clause that the GUI picker live-swaps the active agent.

### Low

**L1 — `activeAgent === null` path silently becomes a GLOBAL switch with a stale label.**
`StatusBar.tsx:390` passes `activeAgent` through; when it is `null` (startup before `registerAgents` lands, or all agents exited) `set_model` takes the legacy `None` branch — factory + every live loop are swapped, which contradicts the "only the active agent" decision. Worse, the optimistic stamp is guarded (`:395-399`) and the global `model`/`provider` stores are no longer written on the success path, so with no active agent the toolbar label/checkmark/`activeEndpoint` stay stale after a successful switch (the backend's per-agent `model_changed` events stamp `agentModels`, but `effectiveModel` reads the untouched global `model` store when `activeAgent === null`). Pre-fix, `setModelStore(modelId)` made the label update immediately. Fix options: disable the picker while `activeAgent === null`, or keep the global-store stamp on that path only, or `resyncFromBackend()` after a `None`-branch success. Narrow window, but a real regression vs. pre-fix behavior.

**L2 — The reasoning-effort label is global while effort is now per-agent.**
`selectReasoningEffort` (`StatusBar.tsx:428`) rebuilds only the ACTIVE agent's provider with the new effort, but the dropdown's selected value/checkmark (`:603`, `:632`) read the global `reasoningEffort` store. After switching agent tabs, the toolbar shows the last-chosen effort, not the active agent's actual effort (agents can now carry different efforts). Pre-fix this was truthful because effort was global; the per-agent swap makes the label able to lie. Consider a per-agent effort map or re-seeding the label when the active agent changes. (The plan deliberately kept the store global — flagging as a known consequence, not a blocker.)

**L3 — `endpointForModel` first-match can misresolve the endpoint for duplicated model ids.**
`endpoints.ts:24-26` returns the FIRST endpoint listing the id. If the same model id is listed under two endpoints (e.g. two OpenAI-compatible endpoints both listing `gpt-4o`) and the active agent's provider was built from the second, `activeEndpoint` resolves to the first: the label shows the wrong endpoint AND `selectReasoningEffort` would rebuild the provider from the first endpoint's base_url/key — a silent cross-endpoint switch. The helper's doc documents first-match-wins (the per-model list is the only available source of truth), so this is a documented limitation rather than an implementation bug; worth a code comment or a follow-up if it ever matters in practice.

**L4 — The new `useAgentStore.test.ts` case is an invariant pin, not a pre-fix-failing regression test.**
The test at `useAgentStore.test.ts:845-860` asserts the reducer stamps only the event's agent. `reduceModelChanged` (`agentEventReducer.ts:852-857`) was already per-agent before this change, so this test would pass pre-fix; the actual defect lived in the backend fan-out + StatusBar global-store writes. The genuine pre-fix-failing regression coverage is `swap_provider_into_loop_swaps_only_the_target_agent` in `config_io.rs` (new function + test). Keep the frontend test (it pins the required invariant), but the "Regression (backlog #83…)" comment slightly overstates — noting for the record so the constitution's fail-pre-fix requirement is understood to be satisfied by the backend test.

## Verified clean

- **Per-agent swap scoping (backend).** `swap_provider_into_loop` (config_io.rs:213-229) clones the target loop under the lock, drops the lock, then `set_provider` + `set_resolved_model(None)` — the factory and every other loop are untouched. Unknown id → `false` → `set_model` returns a clean `Err("no agent loop for agent {id}")` with NO event emitted and no partial swap (agent.rs:468-478). Both new tokio tests pin this (target-only swap, factory still `"initial"`, override cleared; missing id fails with the live loop untouched).
- **Legacy global path preserved.** `set_model`'s `None` branch (agent.rs:490-496) is byte-for-byte the old `swap_live_provider` call (factory + every loop + per-agent `ModelChanged`). `save_endpoints` (settings.rs:259) and the console REPL (console.rs:953) still use the global swap — intentional and now documented in the updated console.rs module comment.
- **Event targeting.** `ModelChanged` is emitted ONLY for the target agent in the `Some` branch (agent.rs:479-485) via the sync `emit_agent_event(&AppHandle, AgentId, …)` (events.rs:1016-1025) — call shape correct, no await needed. The optimistic frontend stamp (`agentModels[activeAgent] = modelId`) is idempotent with the event.
- **Wire shape.** `agentId` (JS) → `agent_id: Option<AgentId>` (Rust u64) follows the project's camelCase→snake_case convention already used by `save_endpoints` (`defaultProvider` → `default_provider`); `null` maps to `None`. No other callers of the `setModel` wrapper exist (only StatusBar.tsx:390/428).
- **Frontend consistency.** `activeEndpoint` is computed once from `effectiveModel` with the global-provider fallback (StatusBar.tsx:130) and used consistently for the label (`:525`), checkmark (`:574`, `:580`), effort options (`:624`), `activeSupportsEffort` (`:446`), and `prevSupports` (`:380`). No stale global model/provider reads remain in the picker UI; `setModelStore`/`setProviderStore` are still used by `resyncFromBackend` (config-save path, intact).
- **Auto-expand semantics.** `reasoningActive` (reasoningPanel.ts:18-24) is true during phase `"reasoning"` (even with an empty log — the first chunk) and stays true while a reasoning entry remains, so the panel stays open through streaming/running-tools/finished; `reduceStarted` clears `activityLog` (agentEventReducer.ts:178), dropping the flag to false and re-arming the next block (retry `Started`s re-arm per attempt — consistent with the documented "once per block"). `reasoningBlockStarted` fires only on the inactive→active edge; a manual collapse mid-block is never fought. Effect deps `[reasoningNow]` are correct, hooks order is legal (no early return before hooks), StrictMode double-invoke is harmless.
- **Streaming visibility.** Reasoning deltas already append to `activityLog` per flush (`appendStreamingReasoning`, useAgentStore.ts:923-949) and the auto-scroll effect exists — the auto-expand is the missing piece, and it fires when the backend flips to the reasoning phase, i.e. as the pieces start arriving.
- **Constitution.** Doc comments on all new pub items (Rust + TS); no `#[allow(...)]` suppressions; no OS-specific APIs/paths/shell syntax (macOS/Windows neutral); no new network/file-write/exec paths — the provider rebuild reuses `build_client` + the existing endpoint allowlist validation; the only behavior change is provider-swap scoping. README updated for both behaviors.
