### Findings

#### HIGH 1 — manager lock held across the recalled-context await (src-tauri/src/ipc/run_all.rs:2403)

In `run_all_dispatch_next`, the manager guard is acquired at line 2312 (`let manager = state.runtime.manager.lock().await;`) and lives until `drop(manager)` at line 2413 — the new `recalled_context_block(state, &item.text).await` (line 2403) runs UNDER that lock. `recall_peek` awaits `embedder.embed(query)` (src/memory/mod.rs:1290) — under a remote embedder that is a network round-trip (remote embeds are a supported config: the code's own comment plans for "a failed remote embed"), and under the default bundled MiniLM it is local ONNX inference — plus a spawn_blocking sqlite read.

This violates the lock discipline the same function documents and enforces for the git checkpoint (lines 2261-2267: the project root is cloned BEFORE the checkpoint precisely so no lock is held across multi-second ops; the busy re-check comment at 2317-2323 likewise notes the manager lock is released during the checkpoint). Impact: every manager-lock taker — IPC commands, status queries, the event forwarder — stalls for the embed duration on EVERY item dispatch; with a slow or hung remote embedder the app's agent interactions freeze for the HTTP timeout, repeatedly. It is not a deadlock (MemoryStore takes no manager lock), which is why the test suite stays green — it is a latent availability regression.

Fix (one move): hoist `let context_block = recalled_context_block(state, &item.text).await;` above the `let manager = state.runtime.manager.lock().await;` line — it depends only on `state` and `item.text`. The busy re-check + send stay atomic under the lock, and the source-contract test's two asserted strings (`recalled_context_block(state, &item.text)`, `run_all_prompt(&item.text, context_block.as_deref())`) are unaffected. Cost: a wasted recall in the rare defer-after-recheck path — trivial.

#### LOW 1 — the Template button's selection doesn't survive React's commit (frontend/src/components/views/BacklogView.tsx:208-214)

`handleTemplate` calls `setText(backlogItemTemplate())` then synchronously `textareaRef.current?.setSelectionRange(0, "Short headline".length)`. React 18 batches the state update — the DOM value is still the old (empty) text when `setSelectionRange` runs (clamped to 0,0), and when React commits the new value the browser resets the caret to the END of the textarea. So the documented behavior "selects the headline placeholder so typing replaces it" does not happen: the user's first keystroke appends after the whole template and "Short headline" must be replaced manually. The fill + focus work; only the selection nicety is broken (and the vitest source contract cannot see it). Fix: apply focus + selection after the commit — e.g. set a `templateJustInserted` ref/state flag and do the focus+select in a `useEffect` keyed on it (clearing the flag), or re-apply the selection in a `requestAnimationFrame` after the state lands.

#### LOW 2 — slash-dates satisfy the path marker (src/backlog.rs:73, `body_carries_detail_marker`)

The two-separator alternative `\S*[\\/]\S*[\\/]\S*` matches any whitespace-free token with two slashes — including M/D/Y dates ("10/10/2027", "01/07/27"). The detail bar itself demands dates in the problem section, so a ≥160-char body carrying a slash-date and NO file path passes the marker check — partially defeating the bar's purpose (the dispatched model still gets no exact pointer). Fix: require at least one alphabetic character in the two-separator token (dates are digits + separators only), and add regression cases to `detail_marker_recognizes_paths_but_not_prose`: "seen 10/10/2027" must NOT match; "src/lib/foo.rs" and "https://example.com/guide" still must.
