## Design decisions — verified, not just accepted

1. **Resolution arm placement/priority — CORRECT.** `ConfigModelResolver::resolve` (src/model_resolver.rs:261-337): arm 1 skill → arm 2 subagent → **arm 3 bug_fixing** → arm 4 state → None. Arm 3 fires only when `plan_kind == Some(PlanKind::BugFixing)` AND state ∈ {Executing, Reviewing}. Complete does not match the guard (the complete slot governs); subagents cannot match it — `enter_subagent_state` (src/workflow/mod.rs:285) stamps every parented agent's state to `WorkflowState::Subagent`, and arm 4 maps `Subagent => None`, so a subagent inside a bug plan gets the subagent slot or default, never bug_fixing; the Skill state can't match either (arm 1's skill slot is the only one that can fire there, preserving the "skill runs on one predictable model" design). Exactly the specified semantics.
2. **Unset/dangling fall-through — CORRECT.** Arm 3 resolves via `config.resolve_model_ref(models.bug_fixing.as_ref())`; `resolve_model_ref` (src/config/mod.rs:109-117) returns None unless the endpoint exists, so a dangling slot falls through to the state chain — each link validated independently, same as every other slot. Covered by `bug_fixing_slot_unset_or_dangling_inherits_the_state_chain`.
3. **No run-all dispatch change — reasoning verified against code.** `RUN_ALL_STEER` (src-tauri/src/ipc/run_all.rs:227-246) steers defect items to `create_plan(kind="bug_fixing")`; dispatch is a single `AgentCommand::Prompt` (`run_all_prompt`, :261-263); `resolve_iteration_provider` (src/agent/turn.rs:1439-1469) re-resolves on EVERY loop iteration, reading `wf.state()`, `active_skill()`, and `wf.active_plan_kind()` under one workflow lock (consistent snapshot). So the first provider request after the steered create_plan flips to Executing resolves `[models.bug_fixing]` — in-app plan creation and run-all dispatch are both covered with zero dispatch-side code. The integration test's direct-`ModelContext` shape (rather than driving `run_all_dispatch_next`) matches plan step 7 and its doc comment is honest about it.
4. **Pin yields to the bug-fixing slot — CORRECT.** The `pin_holds` gate (src/agent/loop_impl.rs:1133-1148) now builds its probe `ModelContext` with `plan_kind`, so a pin stamped in another state goes dormant when the bug_fixing slot resolves in the bug plan's Executing — identical to the existing executing-slot behavior. The `skill_only` probe (loop_impl.rs:1055-1063) passes `None` deliberately and correctly: its state is `Skill`, where arm 3 can never fire, so `None` is semantically identical.
5. **Reviewer chain unchanged — CONFIRMED.** `resolve_reviewer_model` (src/model_resolver.rs:339-354) is untouched: reviewing → executing → subagent, each link validated independently.

### LOW-2 — No test covers the pin-check threading with a non-None plan_kind (coverage gap on a changed path)

`src/agent/loop_impl.rs:1138-1143` — the `pin_holds` probe now receives `plan_kind` (design decision 4: the picker pin yields to the bug-fixing slot when configured). This is a changed production path with zero coverage: every existing pin test passes `None` (or exercises states where plan_kind is irrelevant), so a regression that reverts the probe to `None` would let a pin survive into a bug plan's Executing despite a configured `bug_fixing` slot — silently serving the wrong model — with no failing test. Fix: add a test mirroring `picker_pin_yields_to_configured_model_on_state_change` (src/agent/tests.rs:~6684): pin the agent in Planning, configure `bug_fixing`, then `resolve_turn_provider(WorkflowState::Executing, None, Some(PlanKind::BugFixing))` must serve the bug-fixing model (pin dormant), and return to the pin when the kind flips back / the slot is unset.
