## 1. Verification point 1 — the determinism argument is sound

The core structural property (read against context.rs:328-365, the actual select! loop): `GatedStream::poll_next` (agent.rs:6399-6414) polls the oneshot receiver with `cx` and returns `Pending` while the gate is held. In the select! loop, `stream.next()` therefore returns `Poll::Pending` on every poll until the test releases the gate — the stream branch can never be the picked branch, regardless of tokio::select!'s random branch-poll order. The round-2 race required the stream to yield TextDelta → Finish → None before cmd_rx was polled; every one of those events requires the gate released, and the test releases it only after the Prompt is already buffered. The failure mode is unreachable, not merely improbable.

Full interleaving trace on `#[tokio::test(flavor = "current_thread")]` (each step verified against the code):

1. `tokio::spawn` queues the compaction task; it cannot run until the test task yields (single thread).
2. The test awaits `stream_entered.notified()` → yields. The compaction task runs: the noop guards pass (10 messages > keep_recent+1 = 7; cut = 4 > 1 — round-2 verified, setup unchanged), `complete()` returns the GatedStream immediately (the complete()-level gate is gone — confirmed in the diff), and select! iteration 1 polls both branches: the stream's `poll_next` fires `notify_one()` then polls the oneshot → `Pending`; cmd_rx is empty → `Pending`. The compaction task parks. Notify permit semantics make the wakeup losable-proof in either registration order (waiter-registered or stored-permit).
3. The test resumes only once the compaction task has parked (single thread) — so the cmd_rx waker is registered — and sends the Prompt (mpsc channel(8), empty → the send completes without yielding; it wakes the compaction task).
4. `tokio::task::yield_now()` re-queues the test task behind the woken compaction task — this is yield_now's documented contract on the current-thread scheduler (other ready tasks run before the yielding task resumes). The compaction task runs: select! re-poll — the stream branch is `Pending` (gate still held; the release has not happened yet), cmd_rx is `Ready` → **the cmd branch is the only completable branch** → the Prompt is pushed to `buffered` (context.rs:359), deterministically. The loop continues (the cmd arm does not break), re-polls — stream gated-`Pending` (the oneshot waker re-registered), cmd empty-`Pending` — and parks.
5. The test resumes, sends `stream_gate_tx.send(())` → the oneshot resolves and wakes the select! waker → the test awaits `handle` → yields. The compaction task runs: the stream branch is now `Ready` (gate consumed, `*gate = None`) → TextDelta → Finish → `None` → break. The summary is applied, the buffered Prompt is re-injected through compact_context's Prompt arm (agent.rs:1082-1101: streak = 0, `unattended = text.starts_with(UNATTENDED_PROMPT_PREFIX)` → false for the plain prompt, message pushed), and `CompactOutcome::Completed` returns. All three assertions then hold by direct code path.

The ordering (prompt send → yield_now → gate release) is therefore sound: the release is sequenced strictly after the yield that guarantees the compaction task a scheduling slot with the Prompt in cmd_rx and the stream still gated. The one load-bearing assumption — current-thread yield_now fairness — is exactly what the explicit `flavor = "current_thread"` annotation and its comment pin (note: `#[tokio::test]` defaults to current_thread anyway, so the annotation documents an already-true property rather than changing behavior — good practice). The implementation matches the round-2 fix direction verbatim (signal from the stream's first poll, then release), and the noted short-circuit subtlety (select! may skip polling the stream in the picking iteration) is covered: the poll-signal fires in iteration 1, before the Prompt exists, and the post-buffering iteration re-registers the oneshot waker before the release.

## 4. Verification point 4 — no new issues from the GatedStream design

- **`Mutex<Option<oneshot::Receiver>>`** (agent.rs:6423): interior mutability is required because `complete(&self)` takes `&self`; the lock is acquired and dropped synchronously within `complete` (the guard is a statement temporary — no await is ever held across it); the only operation under the lock is `.take()`, which cannot panic, so lock poisoning is unreachable and the test-code `unwrap()` is sound. The gate is single-use by design; exactly one `complete()` call occurs in the test.
- **`poll_next`** (agent.rs:6399-6414): correct waker plumbing — the oneshot rx is polled with `cx` BEFORE returning `Pending`, so the select! future's waker is registered with the oneshot and the release wakes the compaction task (no lost wakeup). `notify_one()` fires on every gated poll; the inline comment correctly notes Notify's permit semantics make this idempotent for the test's single wait (later fires just store a permit nobody consumes). `*gate = None` consumes the gate exactly once; subsequent polls go straight to `events.next()`.
- **`Pin<&mut Self>` + `&mut *self`**: GatedStream is Unpin (all fields Unpin: `Arc<Notify>`, `Option<oneshot::Receiver<()>>`, `vec::IntoIter<LlmEvent>`), so the DerefMut through Pin is safe and sound.
- **Fully-qualified `std::future::Future::poll(std::pin::Pin::new(rx), cx)`**: correct — `Receiver<()>` is Unpin so `Pin::new` accepts `&mut Receiver`, `Pin<&mut Receiver<()>>` implements `Future`, and the qualified form avoids importing `Future` into the tests module. Pending-while-gated semantics are right; once resolved, the gate is dropped and events flow.
- **`let _ = stream_gate_tx.send(())`**: the receiver is provably alive at that point (the test waited for the stream's first poll, so the GatedStream exists holding the rx); ignoring the Result is fine.
- **Hygiene**: all new types are fully qualified (`std::sync::Mutex`, `tokio::sync::oneshot`, `futures::Stream`, …) — no new imports; the removed `entered`/`gate` Notify fields have zero remaining references (search: GatedStream/GatedMockProvider appear only in this test).
