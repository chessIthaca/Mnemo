### Findings

**LOW-1 — the `reparsed == 0` error can over-claim "no source file on disk contains the name" (plan.rs:1471-1478; root at mod.rs:559-565).**
`reindex_files_containing` counts only *successful* re-parses: a file whose bytes match the needle but whose `reindex_one` fails (the only `Err` path is the store's `upsert_file` — a SQLite write failure, logged and skipped at mod.rs:564) leaves `reparsed == 0`. The gate then errors "…not found in the code graph **and no source file on disk contains the name** (verified after a forced re-index)" — factually wrong in that case, and it steers the agent to exactly the phantom-rename damage this fix exists to prevent (the agent concludes the recorded name is wrong and renames it or records a wrong one). Note `index()` swallows per-file upsert errors the same way (mod.rs:339-344), so a store-level write failure can be silent in the incremental pass too — the escalation is the last line of defense, and in this edge it reports the wrong case instead of the inconclusive one. (Same conflation, much less likely: a needle living only in files the walk can't see — the 1 MB cap, ignored dirs — though there the symbol was never indexable, so the "record the actual test function name" nudge is still the right action.)
Fix suggestion: track the bytes-match count separately from the success count — e.g. have `reindex_files_containing` return both (or a small struct), and in the gate treat `matched > 0 && reparsed == 0` as the inconclusive arm ("re-run finish, do not rename the test"). Minimal alternative: hedge the 0-case message ("no source file on disk contains the name (or its re-parse failed)"). The method's doc comment ("Returns the number of files re-parsed — 0 means no source file on disk contains the needle") shares the over-claim and should match whatever wording lands. Severity LOW: it requires a SQLite write failure at exactly this point (rare — the store mutex rules out in-process contention), but the message taxonomy is this fix's core purpose, so the gap is worth closing.
