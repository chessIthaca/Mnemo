## Findings

### LOW 1 — Stale doc comment on `memory_debug_recall` contradicts the code it documents
- **Location**: `src-tauri/src/ipc/memory_debug.rs:225-238` (doc comment) vs `:255-258` (code).
- **Symptom**: The doc comment states: "**Side effect:** `MemoryStore::recall` bumps `access_count` + sets `last_accessed_at = now` on every returned memory (the same path production auto-recall takes)… This is inherent to the `recall` API (there is no read-only recall path today)". The code directly below calls `store.recall_peek(&query, &filter)` — the read-only path — with an inline comment saying the exact opposite ("Peek, not bump: a human previewing recall ranking must not freshen the memories it returns", 2026-05-21 review note). Both embedded claims are wrong today: the command does not bump, and production auto-recall also uses `recall_peek` (`turn.rs:1800-1803`).
- **Why it matters**: The comment is a pre-fix relic that actively misleads a maintainer auditing the self-reinforcement guarantees (the exact class of bug the peek path exists to prevent). Documentation-sync finding per the project constitution.
- **Fix direction**: Rewrite the doc comment to describe the peek behavior (no side effect, ranking preview is read-only) and delete the "no read-only recall path today" claim.

### LOW 4 — Worktree (run-all lane) agents get a knowledge path their own root cannot read
- **Location**: `src/agent/factory.rs:1140-1198` (binding) + `src/tool/memory/mod.rs:167-170` (tool result).
- **Symptom**: `register_memory_tools` binds every agent — including worktree-rooted run-all lanes (48a35ad) — to the factory's MAIN-tree knowledge store and plans dir (`self.knowledge`, `self.plans_dir`), unlike the file/shell/git/codegraph tools which take the root spec. A lane agent's typed `memory_write` therefore writes the truth file into the MAIN tree (outside its worktree sandbox root), and the success message reports "knowledge record at .coding/knowledge/<rel> (files are the truth; the memory row is a budgeted digest)". The lane's own file tools are rooted at the worktree, so a follow-up `read_files(".coding/knowledge/<rel>")` from that same lane returns not-found for a file it just wrote; the lane also cannot commit the file (its git tools are worktree-bound), so it rides the main tree untracked until a main-tree session commits it.
- **Why it matters**: The main-tree sharing itself is by design (the constitution's "shared by design" pattern for lane-written bookkeeping, same as reviewer reports; `finish_capture`'s unmerged hint shows it's deliberate) and there is no data loss — the file is safely in the main tree and the derived row is consistent. But the tool result hands the dispatched (possibly lesser-reasoning) model a path that is unreadable from its own root, inviting a confusing not-found detour mid-lane. Robustness gap in the fresh parallel run-all code.
- **Fix direction**: Cheapest: make the knowledge-backed tool result explicitly say the record landed in the main project tree (not this worktree) when the agent's root differs from the knowledge store's root — a one-line message change in `memory_write`/`memory_update`/`memory_supersede`. (Binding the knowledge store per root spec instead would fragment the shared corpus — likely worse.)

## Prioritized improvement suggestions (nothing-broken, explicitly requested)

1. **Memory tab list staleness** (`MemoryDebugView.tsx`): the overview polls every 2s but the record list refreshes only on filter change or manual Refresh — memories written mid-session don't appear in the list until the user interacts. Piggyback a list re-fetch on an overview count change (cheap: compare tier counts between polls).
2. **Mark gist truncation in the run-all recall block** (`run_all.rs:330-336`): the 300-char gist cut is mid-sentence with no ellipsis, so a truncated digest is indistinguishable from a complete one. Append "…" when `content.chars().count() > RECALL_BLOCK_GIST_CHARS` so the dispatched model knows there is more in the file.
3. **Surface lane-written knowledge files at run-all completion**: lane-authored knowledge files land untracked in the main tree and depend on a later main-tree commit. A line in the run-all completion summary ("lane wrote 2 knowledge records — uncommitted in the main tree") would close the loop deterministically instead of relying on the next session's commit-all.
4. **Auto-recall cache vs mid-turn writes** (`turn.rs:1805-1814`): the per-turn cache is invalidated only on summarization, so a typed record written mid-turn never enters the recalled context for that turn. Documented and defensible (the write is in the transcript), but a store version counter (bumped on write, checked alongside the query key) would let fresh writes surface without re-running identical recalls.
