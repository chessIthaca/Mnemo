### LOW-3 — Q1 doc comment: the "never 'started + idle' mid-`set_running(true)`" guarantee is overbroad for re-starts (turn 2+)

**Location:** src/runtime/channels.rs:1046-1064 (the `set_running` doc comment) and src-tauri/src/ipc/events.rs:1281-1288 (the filter comment).

**Symptom:** The guarantee holds fully for the **first** start (latch false→true — the case the fix targets, since a freshly spawned agent has latch=false until its first `set_running(true)`): a reader either sees latch=false (spared as pending) or sees latch=true via Acquire, which — through the Release/Acquire happens-before chain plus read-write coherence — forces the subsequent `is_running()` load to observe the pre-latch `running=true` store or a later store, never the pre-store `false`. For a **re-start** (turn 2+, latch already true from turn 1), the Acquire load can legally read-from turn-1's latch store (both stores write `true`; a read may read-from either), which only publishes turn-1's writes; the subsequent Relaxed `running` load may then legally read the stale `false` from turn 1's end (read-write coherence permits any write at-or-after the happens-before write in modification order). So "started + idle" is still theoretically presentable for an agent mid-second-`set_running(true)`.

**Why it matters:** Doc precision only — not a correctness regression. The residual window is nanosecond-scale and observationally identical to the cleanup winning the race cleanly a moment earlier, during the agent's genuine idle gap between turns, which is the pre-existing designed semantics (idle started subagents are cancellable; see the module doc at events.rs:1258-1266). The change strictly narrows the window: first starts are now fully protected, where before the fix even first starts were vulnerable. But the doc comment states an absolute that the memory model does not grant for re-starts, and this comment is the reference a future maintainer will trust when touching the latch.

**Fix direction:** One-line doc clarification in both places: scope the guarantee to the first latch transition (false→true), and note that for re-starts the Acquire may read the previous turn's latch store, leaving a residual equivalent to the pre-existing idle-gap semantics. (No code change needed; a full fix would require a different mechanism — e.g., a mutex or version counter — not worth it for a window equivalent to designed behavior.)

### LOW-4 — Q3 test: substring assertions don't pin the chain to the `onAgentEvent` call

**Symptom:** The test asserts `.then(` and `.catch(` appear in the `ensureListenerStarted` slice and that the catch body contains console.error + uiDiag + the FATAL marker. **Why it matters:** The test exists specifically to guard the 2026-09-08 blackout's root cause (the void-discarded rejection). Presence-based assertions leave a (contrived but real) hole in exactly that guard.

**Fix direction:** Add one assertion pinning the shape, e.g. a regex on the slice like `/onAgentEvent\([\s\S]*?\)\s*\.then\(/` (the call immediately followed by `.then`), or assert the slice does not contain `void onAgentEvent`.
