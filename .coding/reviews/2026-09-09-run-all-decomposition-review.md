## Findings

### LOW-1 — `on_main_turn_resolved_is_plan_tied`: the no-CantResolve/no-rollback negative loop no longer covers the single-dispatch disposition (run_all.rs:2186-2199)

The original pin asserted `!body.contains("BacklogStatus::CantResolve")` / `!body.contains("rollback(")` on the WHOLE `on_main_turn_resolved` body — which included the single-dispatch branch. The retargeted loop covers only `[&success, &done_flip, &failed_flip, &waiting]` (the run-all helpers). `single_dispatch_disposition` performs the Done/Failed transitions and is no longer checked; the comment "checked on every helper that could transition or annotate" is inaccurate for it. A future CantResolve/rollback regression on the single-dispatch path would ship unpinned. Fix: add `single_dispatch_disposition` (and optionally `resolve_single_dispatch_turn`) to the loop — the assert passes today (the helper contains neither string), so the change is purely additive.

### LOW-2 — `stall_arms_write_the_persistent_run_all_log`: the re-check busy arm's persistent log line lost its pin (run_all.rs:1917-1922)

The test's contract is "every dispatch-chain stall arm writes `.coding/logs/run-all.log`". Its assert (`run_all_dispatch_next` contains `run_all_diag(`) is now satisfied by the PRE-check busy arm alone (3811); the manager-lock RE-check arm's diag — "main agent became busy during checkpoint" (3928) — moved into `dispatch_run_all_to_main` and is no longer pinned (the old whole-function assert covered both arms). A regression dropping that log line would be unobservable in a launched app — the exact incident class the test exists for (a117e827). Fix: add `assert!(fn_body(..., "dispatch_run_all_to_main").contains("run_all_diag("))` — passes today (3928).
