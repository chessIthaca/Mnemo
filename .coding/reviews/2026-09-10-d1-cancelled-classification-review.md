It sets no error text and only the healthy status, so `maybe_log_error` (:940-941 — fires on `http_status >= 400 || error.is_some()`) can never mirror a cancelled record into provider-errors.jsonl; proven behaviorally by the provider-level test's file-not-exists assertion. The `version` bump on the cancelled mutation keeps the FE cheap-poll invalidation working.

### Findings

**LOW 1 — src/agent/turn.rs:2761: missing `!had_error` guard — an error-then-interrupt race double-records the request.**
The R21 error arm (:2700) guards `!had_error && !usage_recorded`; the new cancelled arm guards only `!usage_recorded`. The Error arm does not break the select loop, so after a mid-stream `LlmEvent::Error` (error row written, `had_error = true`) a queued hard-stop command can win the next select iteration before the stream ends → a second row with `outcome='cancelled'` for the same request. The request is then counted twice in the aggregates (once as error, once as cancelled), and the cancelled row misclassifies a genuinely errored request. The trace side handles this exact race (the `cancelled()` no-op guard) — the stats side lacks the mirror. Fix: `if !usage_recorded && !had_error {` (one line, mirroring the error arm's dual guard). A narrow race, but the guard is free and the pattern is already established ten lines up.

**LOW 2 — doc sync: the request_stats outcome value domain is not updated for 'cancelled'.**
src/memory/schema.rs:91-96 (the CREATE TABLE request_stats comment) enumerates the row classes — "One row per Usage event, plus error rows (outcome = 'error') and compaction's own calls (purpose = 'summarize')" — and the R21 migration comment (:219-228) likewise. Neither mentions `outcome = 'cancelled'` (consumer dropped mid-flight; our estimated prompt tokens, completion 0, cached_tokens NULL). The schema comment is the canonical documentation of the outcome column's value domain (README does not itemize request_stats); a future maintainer or analyst querying distinct outcome values has no in-repo doc that 'cancelled' exists. Fix: extend the comment by one clause. Optional follow-ups in the same spirit: (a) README.md's LLM-trace bullet (:75) describes error-record attribution — a half-clause noting that interrupted requests are stamped cancelled (not failed) would keep the trace-view description complete; (b) the cache-hit-5 extraction script's A6 section ("error + summarize" rows, selected on outcome/purpose non-NULL) will now also receive cancelled rows unlabeled — worth a line when the script is next run.

**LOW 3 — no test asserts the CANCELLED badge renders (the UI half of the fix has no regression pin).**
LlmTraceView.test.ts only gained `cancelled: false` in the full-shape literal; no test constructs a cancelled summary and asserts the badge renders (and that ERR does not). The plan's own test design said "the cancelled badge renders". The file's established pattern tests pure exported functions (shouldStopPolling, clampStatsHeight); the badge derivation (`failed` / `cancelled && !failed`) is inline in RequestRow — either extract it as a pure helper (testable like the others) or add a renderToStaticMarkup test (the BacklogView.test.tsx pattern). Without it, the badge can silently regress in a refactor. (The backend's `is_complete`-includes-cancelled behavior IS pinned transitively — the shouldStopPolling terminal-record tests cover it.)

**LOW 4 — coverage gap: a summarizer (compaction) request aborted mid-flight records no cancelled stats row.**
summarize_with_interrupt (src/agent/context.rs:400-409) breaks on Interrupt and drops its stream — the shared pump drop arm stamps the trace cancelled (good: no provider-errors row), but when the summarizer's Usage event hasn't arrived yet, no request_stats row is written (R21 records a summarize row only from captured usage). A cancelled compaction request — the most expensive aborted-request class (the mega-prompt) — remains invisible to the token/latency aggregates, which is exactly the blindness D1 fixes for the main loop. The D1 backlog marked the stats row "optionally", so this may be a deliberate scope cut — but the asymmetry should be either closed (record outcome='cancelled' + purpose='summarize' from the summarizer's interrupt path, mirroring the turn-loop arm) or captured as a follow-up backlog item. Related, defensible as-is: the `None => break` arm (turn.rs:2788, command channel closed) also drops the stream (trace stamped cancelled) without a stats row — shutdown, not a user action.
