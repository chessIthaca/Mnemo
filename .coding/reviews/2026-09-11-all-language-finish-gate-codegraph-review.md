### HIGH-1: Arrow-const regression tests in JS/TS still false-error at the finish gate — the bug's own class, for the shape modern JS tests actually use

**Where:** `src/codegraph/extract.rs` `visit_ts` (~lines 407-479, no `lexical_declaration`/`variable_declarator` arm) × the gate's final error arm `src/tool/workflow/plan.rs:1714-1732`.

**Trace:** a regression test written as `const testFoo = () => { … }` (or `export const testFoo = …`) — the dominant jest/vitest/mocha idiom — produces **no symbol**: `visit_ts` matches only `function_declaration`, `class_declaration`/`abstract_class_declaration`, `interface_declaration`, `type_alias_declaration`, `enum_declaration`, `method_definition`, `call_expression`, `new_expression`, `import_statement`; the `lexical_declaration` falls to the generic-recursion arm and the declarator name is never recorded. Gate flow for that test: `resolve("testFoo")` empty → incremental re-index → still empty → forced `reindex_files_containing`: the `.js` file is now *parseable* → `matched=1`, `reparsed=1`, `matched_unparsed=0` → re-resolve still empty → final `else` arm → error *"regression test symbol 'testFoo' not found in the code graph even after a forced re-index of 1 file(s) containing the name — the verify step must record the actual test function name"*. The recorded name IS the actual name; the agent is dead-ended and steered toward a phantom rename — the exact failure mode (backlog 648e0ad5) this machinery exists to prevent. Before this change the same test errored "no source file on disk contains the name" (the original bug); the change improves the message but not the outcome for this shape. The bug statement names `.js` first; the fix's JS fixture (`extracts_js_symbols_and_calls`) only covers `export function`/`export class`, so the gap is untested (the only `const` in any fixture is `const c = new Widget(1)` — a non-function binding, correctly symbol-less).

**Fix:** add a `lexical_declaration` arm to `visit_ts` that extracts function-valued `variable_declarator`s (value kind `arrow_function` or `function`) as `SymbolKind::Function` — recurse into the value for nested defs/calls, pop the scope after; non-function consts keep yielding nothing. This also closes the pre-existing `.ts`/`.tsx` gap. Add a fixture test (`const testFoo = () => {}` extracts as Function; `const c = new Widget(1)` still yields nothing) and ideally a gate-level test mirroring `finish_passes_when_regression_test_is_in_non_indexed_language` with a `.js` arrow-const test.
