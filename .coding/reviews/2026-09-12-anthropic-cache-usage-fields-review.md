The two new parses mirror the existing `input_tokens` shape (`.get(..).and_then(as_u64).unwrap_or(0) as u32`); absent fields → 0, so a provider not reporting cache details behaves exactly as before (backward compat — the untouched `parses_canonical_stream_fixture` still asserts prompt 25 with a cache-field-less fixture, and it's green).

**Usage emission (anthropic.rs:783-800).** `prompt_tokens = input + cache_read + cache_creation` and `cached_tokens = cache_read` is the right mapping: Anthropic's `input_tokens` excludes the cached prefix, so the sum is ALL billed prompt tokens — the same meaning OpenAI's inclusive `prompt_tokens` has. `cached_tokens` = read-only is the true hit signal (creation is a write, not a hit), matching `prompt_tokens_details.cached_tokens` semantics. The parity comment and the module doc (anthropic.rs:608-611) are accurate.

**Responses API (src/provider/openai/sse.rs:100-116).** The `input_tokens_details.cached_tokens` parse mirrors the chat path's `prompt_tokens_details.cached_tokens` parse (sse.rs:202-209) field-for-field, including the absent→0 comment.
