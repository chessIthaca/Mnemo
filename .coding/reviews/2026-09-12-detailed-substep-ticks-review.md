### Findings

**L1 (low) — BUG knowledge record misdescribes the shipped fix mechanism.**
`.coding/knowledge/bug/2027-01-11-bug-fix-plans-lose-sub-step-progress-across-rest.md:6` says "Fix: structured Vec<Step> with checkbox parse/serialize (legacy plain-dash lines = unchecked sub-steps, non-dash lines = continuations preserving the escape round-trip)". The shipped design — a deliberate refinement of that sketch, per the task framing — keeps `detailed_steps: Option<String>` as the single on-disk truth and does line surgery in `PlanFile::complete_detailed_step` (src/workflow/plan_file.rs:384). There is no `Vec<Step>`, no checkbox parse/serialize of the section, and `Workflow::complete_detailed_step` (src/workflow/mod.rs:843) deliberately skips `persist_stack` (the plan sketch included it). A future reader grepping for the structured field will not find it, and the record's mechanism claims are the durable root-cause knowledge the repo relies on. The root-cause half of the record is accurate. Fix: `memory_amend` the record's Fix sentence to describe the raw-body line-surgery design (Option<String> truth, nth-checkbox flip in place, legacy normalization on first tick, no state transition, no persist_stack).

**L2 (low) — the tick rewrites the line from `parse_checkbox`'s processed text, which strips a leading "N. " (and leading spaces): a persisted-text mutation beyond the mark flip.**
src/workflow/plan_file.rs:419-425 builds the ticked line from the `String` returned by `parse_checkbox`, which (plan_file.rs:522-527) `trim_start`s the text and calls `strip_leading_number` (plan_file.rs:673-688) — load-bearing for SKELETON steps, which serialize as `- [ ] 1. text` (serialize at plan_file.rs:325). Detailed steps render without numbers, but a step authored as "2. Guard the unwrap" persists as `- [ ] 2. Guard the unwrap` and, when ticked, becomes `- [x] Guard the unwrap` — the "2. " prefix is gone (extra spaces after the mark collapse the same way). That contradicts the "text immutable" contract now stated in PLAN.md:425, README.md:36, and the spec amendment, and the round-trip-verbatim claim, in that corner. No wrong-target risk (the tick is positional), no data loss beyond the redundant number; untested corner (the new tests use no leading-number step texts). Fix: rebuild the ticked line from the raw text after `] ` (a local slice of the original line) instead of the processed `String` — or, at minimum, document the edge in the method's doc comment alongside the other documented ambiguities.

**L3 (low) — legacy normalization turns plain-dash CONTINUATION lines of multi-line step texts into sub-steps, inflating the count and shifting numbering.**
`StepInput::Text` passes multi-line strings verbatim (src/tool/workflow/plan.rs:140-152), so a step "Fix — do:\n- guard X\n- add Y" renders `- [ ] Fix — do:` followed by plain `- guard X` / `- add Y` continuation lines. The normalization loop (src/workflow/plan_file.rs:396-411) converts EVERY plain `- ` line to `- [ ] `, so the first tick turns those continuations into tickable sub-steps: the file then shows more checkboxes than the create result's "your {m} detailed steps", and an agent ticking by the create-count can flip a nested bullet while the real sub-step stays unticked across a restart — the redo-risk this plan targets, in a corner. Recoverable (the tool surfaces the true count: "n/m detailed steps done", "have N checkable detailed steps"), no state corruption. Note: the task's "machine-rendered bodies never contain one" holds for `- [link](url)` but NOT for plain dash continuations — these ARE machine-reachable via multi-line step texts. The doc comment documents the `- [ ]`-quoting ambiguity but not this plain-dash variant. Fix (pick one): (a) extend the doc comment to name the plain-dash continuation edge; (b) close the new-plan hole at the render — escape plain `- `-leading continuation lines the way `escape_section_markers` escapes `## `/`# ` lines (a rendered first line always starts `- [ `, so any plain `- ` line in a fresh body is a continuation), leaving the normalization to genuinely-legacy files only.
