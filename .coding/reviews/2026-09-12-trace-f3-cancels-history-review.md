## Design decisions — all six verified

- **(a) Cancels log always-on, summary-only.** `Msg::CancelLine` is enqueued unconditionally after a successful stamp (no `log_enabled` gate at enqueue or drain — writer_main :1490 block); the line is a serialized `LlmRequestSummary` (no `request_json`/`response_raw` — privacy stance holds) with `redact_text` applied, matching `maybe_log_error`'s ErrorLine construction exactly (:1079-1087 vs :900-907). `restrict_log_file` applied. No cap — the documented "cancels are rare user actions" tradeoff.
- **(b) History archive gated on log_enabled** at enqueue (`with_record` :988) AND at drain (writer_main :1525) — the disable-between-enqueue-and-drain race is covered, mirroring the mirror's own drain-time check on `Dirty` ids (:1409).
- **(c) Terminal-transition enqueue, not a drain-time scan.** `with_record` captures `was_complete` before `f(r)`, recomputes `is_complete = finish_reason || error || cancelled`, and clones+sends only on the false→true flip (:967, :986-992). Terminal fields are never cleared anywhere (no resurrection path — `update_streaming_usage` early-returns on complete), so each record archives exactly once with no dedup set. The enqueue happens under the records lock while the record is guaranteed in-ring — the load-bearing choice that beats the drain-time scan (which the red test proved lossy).
- **(d) Same line shape as the mirror.** `redacted_record_line` (:1572-1582) is the extracted shared closure — `write_records_to_file` now calls the same helper (:1617). Identical redaction (request_json via `redact_json`, response_raw/error via `redact_text`).
- **(e) Best-effort rotation.** `rotate_history_if_over` swallows the rename error (`let _ =`), and the append then opens the original path — a failed rotation cannot break the append; the file just grows to the next batch. Prune is likewise best-effort.
- **(f) Scope guard held.** `MAX_RECORDS` still 32; ring eviction in `start()` untouched; `write_records_to_file`'s upsert-by-id merge + over-cap fresh-start semantics intact (the only change is the helper extraction — which also improves the unreachable-error path from drop-whole-batch to skip-one-record); provider-errors.jsonl path untouched; D1's stamp logic in `cancelled()` unchanged (only the post-stamp enqueue was added; `maybe_log_error` still never fires for cancels since `error` stays None).

## Lock-ordering invariant (the 2026-08-22 deadlock class)

- writer_main's new cancel/history blocks clone the path in a scoped `let` — the guard drops at the end of the statement, before any I/O — the same pattern as the existing `log_path`/`error_log_path` blocks. No path mutex is ever held while acquiring `records` or across I/O.
- `with_record`'s archive enqueue calls `ensure_writer()` under the records lock — the pre-existing `Dirty` send at :1003-1004 already does exactly this, and the writer thread never locks the handle's `writer` mutex, so no AB-BA cycle exists.
- `cancelled()` acquires `records` twice sequentially (via `with_record`, then the summary re-read) — never nested; the summary serialization under the lock is the same cost class as `list()`; no I/O under the lock.
- The lock-ordering regression test `writer_never_holds_log_path_while_waiting_for_records` survives untouched (:3204).
- Flush ordering: the cancel/history writes sit BEFORE the flush acks in writer_main (:1558-1561), so `flush_file_writes()` covers the new files — the trace.rs tests correctly rely on this.

## Non-blocking observations (no action required)

- **`cancelled()` re-read race:** between the stamp and the summary re-read the record could be evicted (no cancel line). The window is two adjacent lock acquisitions on one thread; eviction requires 32+ new records inside it. Documented in the code comment; acceptable.
- **Ungated CancelLine send:** `cancelled()` serializes and sends without checking `cancels_log_path` is configured (unlike `maybe_log_error`, which gates on `error_path_configured`). In the app the path is always set at startup; in path-less configs the message is dropped at drain — one wasted summary serialization, no functional impact.
- **Archive channel memory:** `Msg::ArchiveRecord` queues full-record clones (up to ~2.3 MiB each) on the unbounded channel — a transient spike the writer drains continuously, and the deliberate tradeoff that closes the eviction race (the drain-time-scan alternative was proven lossy by the red test). The clone fires once per request at its terminal transition, not per delta.
- **`clear()` mid-flight:** a record cleared before its terminal transition is never archived — same accepted class as ring eviction; `clear()` is an explicit discard.
