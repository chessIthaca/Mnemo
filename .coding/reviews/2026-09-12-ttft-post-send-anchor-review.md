## Findings

### H1 (high) — Three `set_ttft_ms` sites in stream.rs still use the headers-arrived anchor

**Location**: `src/provider/openai/stream.rs:540-551` (stream-guard cut arm, no-chunk else), `:573-585` (`SseOutcome::ParseError` arm, no-chunk else), `:617-625` (body-decode `Err(e)` arm, no-chunk else).

All three still stamp `log.set_ttft_ms(*id, request_start.elapsed()...)` with the comment `// ttft = headers→error`, while every other ttft site in both providers now uses `post_sent`. These are misses, not exclusions: the plan's site enumeration listed only six stream.rs sites and omitted these three; the implementation followed the plan, but the plan's own Goal ("redefine ttft_ms as first-chunk time − POST-send anchor") and the BUG knowledge file ("redefine ttft_ms = first-chunk − post_sent **at every ttft site**") demand completeness — and the Anthropic decode-error arm WAS swapped (anthropic.rs:1779-1790, "ttft = POST-send→error"), making the openai decode-error arm's old anchor an asymmetry.

**Reachability**: the `Err(e)` no-chunk case is genuinely reachable — headers arrived, then the connection resets or the body decode fails before any body bytes (first_chunk stays None), e.g. a proxy drop mid-prefill. The guard-cut and ParseError no-chunk elses are defensively unreachable (both arms only run after bytes arrived, which stamps first_chunk) but must stay consistent with the swapped arms.

**Impact**: on those error records, ttft_ms still measures headers→error, excluding the prefill wait — the exact structurally-under-measured window this plan set out to kill — so the record's ttft_ms contradicts the updated field docs (trace.rs, and types.ts once L1 is fixed) and the BUG knowledge record's "every ttft site" claim. request_stats is unaffected (error rows record ttft NULL per R21); the Trace view's error rows are affected.

**Fix** (mechanical, `post_sent` is already destructured in scope at :83): swap `request_start` → `post_sent` in the three `set_ttft_ms` expressions and update the three comments to `ttft = POST-send→error`, mirroring anthropic.rs. No test pins the old behavior on those arms (the existing error-path tests assert ttft None on the open_stream paths, which are untouched).
