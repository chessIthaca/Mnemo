## Findings

### L1 (LOW) — the F2a fix fails OPEN on the one branch where canonicalization is refused: a link inside `.coding/` pointing OUTSIDE the sandbox root is granted, and the write follows it out of the root

**What the fix does right:** `research_write_verdict` (`src/agent/dispatch.rs:86-96`) tries `validate` first. `validate` (`src/tool/agent/sandbox.rs:82-113`) fully canonicalizes an existing target (`:91-94`) and canonicalizes the PARENT for a new leaf (`:96-106`) — so for a link inside `.coding/` that resolves to an in-root source tree (`.coding/link/lib.rs`, `.coding/link/new.rs` with `.coding/link` → `src`), the judged path is `<root>/src/...`, `is_artifact_write_target` is false, and the verdict is `NotAnArtifact`. The two directions the task asks about are correct: existing target ✓ canonical, existing parent + new leaf ✓ canonical parent + leaf, genuinely new tree (parent missing) ✓ lexical (no link can exist there).

**The gap:** the fallback is unconditional — `validate(...).or_else(|_| validate_for_creation(...))` (`:86-88`) — and `validate_for_creation` (`:125-138`) is pure lexical. When `validate` fails with `PathOutsideRoot` (link/junction inside `.coding/` whose canonical target — or the target file itself, as a symlink FILE — lies outside the project root, or canonicalization otherwise errors), the lexical `<root>/.coding/link/x.md` is inside the root, first component `.coding`, unprotected → `is_artifact_write_target` returns TRUE (`sandbox.rs:287-309`) → **`Artifact` → dispatch grants**.

**Nothing downstream catches it:** the tool's ladder `validate_for_write` (`sandbox.rs:333-358`) step 1 fails again, step 2 returns the lexical path, step 3 sees no protection, step 4 finds the parent already present, and step 5's revalidation-failure fallback returns the LEXICAL path (`:352-357`) — which `file_write`/`file_append` then hand to `std::fs::write` (`file_write.rs:158`) / `OpenOptions::append` (`file_append.rs:131`). The OS follows the link: the bytes land OUTSIDE the sandbox root, AutoRun, with no approval prompt.

**Honest scoping:** the step-5 ladder fallback is PRE-EXISTING — today any plan kind can write through such a link, and this change does not create it. What this change adds is (a) a research plan reaching it (all four names were denied wholesale before) and (b) the doc claim at `src/agent/dispatch.rs:66-74` — "Source, docs, config, protected targets, `..` escapes and links out of `.coding/` all stay denied" — which is FALSE for this case. That is why it is LOW (a planted symlink/junction is required; round 1 rated the same precondition LOW) and why the cheap fix belongs in dispatch, not in the ladder.

**Fix direction (fail closed, one branch):** fall back to `validate_for_creation` only for the genuine "parent does not exist / would-be-created" case (`Error::InvalidInput`); on `Error::PathOutsideRoot` return `NotApplicable`/`NotAnArtifact` — never grant from a path whose canonical resolution was REFUSED. Then correct the doc claim. Test to add: plant `.coding/link` → a directory outside the root (and, if cheap, a symlink FILE inside `.coding/` → an out-of-root file) and assert the verdict is not `Artifact`; a second assertion that the file stays unwritten would close it end-to-end.
