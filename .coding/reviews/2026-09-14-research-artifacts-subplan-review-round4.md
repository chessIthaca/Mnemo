## H1 — CLOSED. Every `Ok` from `validate` is now judged only after the link walk, and no `Ok` shape carries an unresolved reparse point

**The guard is in both branches** (`src/agent/dispatch.rs:90-113`): the canonical branch requires `sandbox.lexical_path_is_link_free(&canonical)` before `judge_research_write` (`:97-100`) *and* the lexical branch requires it too (`:109`). Neither branch can return `Artifact` without the walk returning `true`.

**Why nothing else can slip through `validate` (`src/tool/agent/sandbox.rs:82-113`).** `validate` has exactly two `Ok` producers:
1. `candidate.exists()` → `candidate.canonicalize()` + `check_inside` (`:91-94`). A full canonicalization is link-free by construction (Windows `GetFinalPathNameByHandle` resolves symlinks *and* junctions; POSIX `realpath` likewise), and the walk confirms it as belt-and-braces.
2. parent fallback: `parent.canonicalize().join(candidate.file_name())` (`:99-105`). The parent is fully resolved, and the only unresolved component is the raw **leaf**: `file_name()` returns a single component and returns `None` for a path ending in `..`/`.`, which errors out of `validate` entirely (→ lexical branch). So the leaf is the only place a link can hide, and `lexical_path_is_link_free` lstats it (`symlink_metadata` does not follow the final component, so a *dangling* link still reports its own attributes) → `false` → `NotApplicable`.

**The cases you asked me to walk** (all inside `.coding/`, all verdicts re-derived from the code, not from tests):
