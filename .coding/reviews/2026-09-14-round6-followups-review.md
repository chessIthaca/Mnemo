## Findings

### HIGH-1 — Landing sync tolerance masks genuine failures (src/project/worktrees.rs:193-194)
`let _ = git_raw(&landing, &["fetch", "origin"]); let _ = git_raw(&landing, &["pull", "--no-rebase"]);` tolerates ALL errors. Requirement: tolerate only "no remote configured" / "no upstream" (local-only repos); genuine fetch/pull failures (network down, auth expired, upstream conflict) must surface — `Err(LandError::Git(...))` — so the landing is surfaced rather than silently landing on stale main. Suggested shape: `git_raw(&landing, &["remote", "get-url", "origin"])` first (its failure = the tolerated no-remote case → skip the sync); then propagate fetch/pull errors (or at minimum detect "no tracking information"/"no upstream" in the pull error and tolerate exactly that). Add a test: origin configured but unreachable (e.g. a nonexistent path) → the landing must FAIL with a surfaced error, not proceed on stale main. Also reconcile FEATURES.md/PLAN.md wording with the implemented tolerance.

### HIGH-2 — Stale doc bullet contradicts the shipped atomic write (src/provider/trace.rs:1608-1611)
The doc block on `write_records_to_file` still says: "**The write is not atomic** — `std::fs::write` can tear the file on a mid-write crash, losing previously logged lines (a write-to-temp-then-rename would be crash-safe but is skipped here as overkill for a debugging aid)." This change made the write exactly that temp+rename, and the new rationale (:1683-1694) documents why it is NOT overkill (the 444 KB corruption). Rewrite the bullet to describe the new guarantee (atomic replace; failed temp write leaves the previous mirror), and fix the lead-in "(unchanged from the synchronous implementation, plus one new one)" accordingly.
