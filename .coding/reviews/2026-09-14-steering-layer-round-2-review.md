### Findings

1. **LOW — dispatch.rs:425: channel-closed arm skips `observe_result`.** When the command channel closes mid-execution, the arm `return (&mut tool_fut).await;` returns the completed tool result without observing its markers — contradicting the module doc claim "every tool result is matched" (steering_stats.rs:13) and the dispatch doc (dispatch.rs:386-390). A nudge in that result is uncounted and no new per-agent note is set (the call's `observe_call` at :400 already consumed the previous note). Rare path (UI/channel teardown), advisory metric only; fix is one line: observe before returning.

2. **LOW — spawn_agent.rs:273-282 + 310-313: one erroring path pays the recall round-trip.** The "model override requires the parent-aware spawn path" error is returned after the rider was computed, so a spawn with a `model` arg against a non-parent-aware spawner performs the store recall and then fails. The comment's claim ("placed AFTER every arg-validation error") is technically true (the model arg itself is validated earlier at :226-241), but hoisting the parent-aware/forced-model check before the rider would avoid the wasted round-trip on the only rejected-after-validation path. Negligible cost; advisory.

3. **LOW — substring detection can misfire on content-bearing tool results.** `read_files` (file contents) and `web_fetch` (page text) embed arbitrary text in `output`; a file/page containing a marker string fires that kind spuriously and overwrites the agent's pending note (e.g. this repo's own `.coding/knowledge/spec/*.md` literally contain "RECALLED CONTEXT" and "is an indexed symbol" — reading one fires RecallRider/SearchNudge and a subsequent unrelated graph call counts as a switch). Inherent to the documented "detection is on output substrings only" design and fully advisory, but worth a doc note so a future reader doesn't misread the numbers as exact.

4. **LOW — first-match-wins misattributes two-marker results.** A result carrying two distinct markers (e.g. a read_files SYMBOL NUDGE prepended over file content that itself contains "is an indexed symbol") is classified as the earlier kind per `MARKERS` order (SearchNudge wins over ReadNudge). The comment at steering_stats.rs:106-108 argues stability from "no marker substring is a substring of another" — true for nesting, but irrelevant to co-occurrence. Rare, advisory; a `find`-first-per-kind could count both, but that changes the "one fired note per result" contract — current behavior is a defensible trade-off, just under-documented.
