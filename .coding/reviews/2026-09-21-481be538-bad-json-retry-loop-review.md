## Findings (all LOW — none block the mechanism; all are cheap, fix before commit)

**L1 — Wrong character-class example in the search remedy (src/agent/turn.rs:3552-3553; propagated to .coding/knowledge/bug/2027-01-11-bad-json-retry-loop-re-injected-identical-schema.md:10 and the BUG memory).** The remedy says: "for a literal `(?<`, write the character classes [(][?] and [(][<]". `(?<` is three characters (`(`, `?`, `<`); the correct metacharacter-free encoding is `[(][?][<]` (or `[(][?]<` — `<` is not a regex metacharacter). As written, the two groups concatenated yield `[(][?][(][<]`, which matches `(?(<` — a model that follows remedy (2) verbatim gets a silently wrong pattern (zero hits → "not found" reported as fact). Remedy (1) `literal: true` is correct and first-priority, which keeps this LOW, but the example is the deliverable's core content and the test only asserts "literal" so it cannot catch this. Fix: change the string to `[(][?][<]` in turn.rs, correct the knowledge file's "classes like [(][?] / [(][<]" to match, and amend the BUG memory. Optionally pin it: assert the correction contains "[(][?][<]".
