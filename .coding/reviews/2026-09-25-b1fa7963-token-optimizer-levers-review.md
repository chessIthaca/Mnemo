### LOW 1 — PLAN.md claims the post-compaction digest rides the volatile tail; the code persists it in the conversation

- **Claim**: PLAN.md:601-604 (new "Optimizer levers" invariants bullet): "The already-sent conversation prefix is never mutated: nudges **and the post-compaction digest** ride the *volatile tail*, popped right after the request, so the provider prefix cache stays valid." The same claim is in the review contract's hard-invariant list.
- **Code**: the lean-output nudge DOES ride the volatile tail (built in `nudge_for_request`, appended via `append_nudge(&mut volatile_tail, …)` src/agent/turn.rs:2818, pushed with the tail at :2820/:2823 and popped right after the request at :514-515 — verified). But the post-compaction digest is pushed as a **persistent system message** into the compacted conversation: src/agent/turn.rs:2347-2359 (`*messages = summarized; … messages.push(Message::system(format!("{dropped_digest}{pointer}")))`) and the twin in src/runtime/agent.rs:1264-1267 (`self.messages.push(…)`). It then rides every subsequent request (bounded in practice: prior digest notes fall into the next compaction's dropped region and get summarized away).
- **Failure scenario**: a future maintainer who trusts PLAN.md either "fixes" the code by moving the digest to the volatile tail (popping it after one request — which orphans the `expand_result id=…` checkpoint pointer and defeats lever 4's purpose), or audits a cache-stability report assuming the digest is transient while it is actually part of the stable prefix.
- **Note**: the plan file itself (`.coding/plans/b1fa7963.md`, step 5: "after `*messages = summarized`, push ONE system note behind the flag carrying build_digest + 'pre-compaction context archived (expand_result id=…)…'") prescribes exactly what the code does, and the persistent placement is cache-safe (it is appended to a freshly-compacted conversation and never rewritten afterwards). So this is a doc inaccuracy, not a code bug — the checkpoint pointer arguably *must* persist to stay retrievable.
- **Suggested fix**: reword PLAN.md:601-604 (only the bullet; README/FEATURES make no such claim) — "the lean-output nudge rides the volatile tail (popped right after the request); the post-compaction digest is a persistent system note appended to the freshly-compacted conversation, which never mutates already-sent content because the summary itself is the rewrite."
