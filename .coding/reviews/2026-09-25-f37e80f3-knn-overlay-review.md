### Findings

**LOW 1 — the overlay's only non-owned lock panics on poison (hardening gap, not a live bug).**
- Anchor: src/memory/mod.rs:507-512 (`embedder_handle`: `.expect("embedder lock poisoned")`), reached per classification through main.rs:1506's getter.
- The new module's contract is "an optional classifier must never panic a turn," and every lock IT owns degrades on poison — but `classify()`'s first act, `(self.embedder)()` (failure_triage_knn.rs:314), funnels into the store's `.expect`. Today this is practically unpoisonable: the embedder RwLock's only holders are `set_embedder` (a plain assignment, mod.rs:485) and `embedder_handle` (an Arc clone), neither of which can panic, and a poisoned store would panic recall/write identically (an already-dead store). It is also opt-in-only — the getter is never called with the flag off. Still, it is the one path where the overlay could panic a turn, and `embedder_handle` was previously a diagnostics/tests accessor; the overlay puts it on the triage hot path.
- Fix direction: make the getter's lock read poison-recovering — `self.embedder.read().unwrap_or_else(|poisoned| poisoned.into_inner()).clone()` in `embedder_handle` (read-only data, so `into_inner` recovery is sound), or a lossy variant for the overlay's getter. One line either way.
