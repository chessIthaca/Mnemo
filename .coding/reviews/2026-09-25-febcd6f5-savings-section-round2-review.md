- **Failure scenario:** Any `cargo test` of `mnemo-app` — including `cargo test --workspace`, the release gate on the macOS build leg — fails at compile time with "missing field `optimizer` in initializer of `GetSettingsGeneral`". It is invisible on this machine only because Application Control blocks compiling src-tauri here; the first CI run or the first developer on a compilable machine hits it immediately. The very fixture test designed to catch wire-shape drift is itself broken by the wire-shape change (it cannot even compile, let alone pass).

A repo-wide search for `GetSettingsGeneral {` (this round, covering `src-tauri/**` including `tests/`) finds exactly: settings.rs:905 (builder, `optimizer` at :924), settings.rs:1409/:1567 (test ctors, `optimizer` at :1428/:1589), and contract_fixtures.rs:235 (missing it). Round 1 evidently only swept settings.rs.
- **Confidence:** inspection-only like all of src-tauri on this machine (no compile possible) — but a struct literal missing a required field is not a judgment call: it is a definite compile error. This revises round 1's "compile-plausible" verdict: the changeset as it stands does **not** compile under `cargo test` for the app crate; the three sites round 1 checked are fine, the fourth it never enumerated is the break.
