## Findings

### LOW 1 — the preamble instructs commands outside the reviewer's read-only tool surface
src/agent/review_scope.rs — `render_review_preamble`: line 111 (`git merge-base main HEAD` → `git diff <that>`), line 137 ("Your scope is exactly `git diff {base}`"), lines 149-150 ("Derive it yourself: `git diff --name-status {base}`"), line 168 ("`git diff --name-only {base}` for the full list"), plus the `MAX_LISTED_PATHS` comment ("the reviewer can always run the git command itself").

The reviewer's allow-list (agent.md; `ToolFilter::Reviewer`) exposes `git_diff` (uncommitted diff only), `git_read` log/show (a single commit-ish each) and file reads — there is no arbitrary base-diff capability, so none of those four commands can be executed verbatim. The scope is recoverable by approximation (`git_read` log to enumerate commits since base, `git_read` show per commit, or reading the listed files), but two fallback paths — the >40-paths truncation and the changed-set-derivation failure — point the reviewer at exactly a command it cannot run; a literal-minded reviewer either burns effort discovering that or falls back to the full-tree read this change exists to kill. Fix: name the read-only equivalents in those lines (e.g. "the intervening commits are in `git_read` log — read each with `git_read` show", or "read the listed files' current state"), or extend `git_read`'s reviewer surface with a base-diff op; and drop the overstated "run the git command itself" comment.

### LOW 2 — the round-2+ no-change instructions can PASS over unresolved round-1 findings
src/agent/review_scope.rs — lines 153-158: "Changed file set: **empty** — `git diff {base}` should also be empty. If it is, the tree is unchanged since round {previous}: report PASS without re-reading a single file." and lines 174-178: "Uncommitted carry-over. If `git diff {base}` re-shows hunks a previous round **already verified** (that material was never committed) … do not re-line-review it, and do not treat it as a new finding."

Both lines are correct for their designed flows (a disputed finding needs no change; a passed round's material carried uncommitted should not be re-priced). But in the protocol-violating flow — a parent that re-spawns without fixing and without committing — the unchanged hunks carrying round 1's unresolved findings are exactly what these lines instruct the reviewer to PASS over: the empty-set line says PASS without reading, the carry-over line forbids re-raising as a new finding. "Already verified" is false in that state (round 1 found findings, it did not verify), yet the reviewer has no way to know round 1's verdict without hunting the prior report. The old full-diff re-review incidentally re-surfaced unfixed findings; that net is the deliberate trade of this change, but the current wording widens the hole beyond the trade. Fix: tie carry-over to a passed round ("hunks a round that ended PASS already verified") and add "if your task names unresolved findings, verify their fixes are present in the delta before reporting PASS".

### LOW 3 — the factory wiring has no test
src/agent/factory.rs:1484 (`register_spawn_tool` → `with_review_scope`) and :1093 (`WriteReviewReportTool` → `with_review_scoper`). Every behavior test constructs the tool with the builder directly (the spawn tests and the report tests), so dropping either registration call reverts the whole feature — reviewer spawns forward the task verbatim, no stamps, no provenance — with a green suite. Acceptance (b) is pinned down to the builder, not to the registration. Fix: one factory-level test that builds a registry with a mock spawner + a workflow carrying a plan and asserts the spawned reviewer's task carries the contract (or the registered tool's scope wiring is `Some`); the same test can assert the report tool stamps provenance.
## Risk-focus walk (the seven areas)

1. **Fail-safe semantics — PASS.** `stamped_base` is set only inside the reviewer branch (spawn_agent.rs:421-455) and recorded only in the `Ok(id)` arm (493-506); every rejection (empty args, unknown role, model-resolution failure, reviewer-with-model dispatch denial, parent-aware override check) returns before the preamble render; a spawner error takes the `Err` arm (no stamp — test: `a_failed_spawn_stamps_no_round`). `head` failure → `None` → no stamp → next round re-computes the same round number and deltas against the older base (wider) and the output names it (`a_head_failure_stamps_no_round`). `changed_paths` failure → degraded note, round still stamped with the readable head (`a_changed_paths_failure_degrades_to_the_command_not_a_file_list`). No plan in flight → `record_review_round` errors (WorkflowNoPlan) and the note lands in the output, spawn unaffected (`an_unstampable_round_is_reported_not_silent`). The workflow lock is a tokio mutex (no poisoning) and is never held across the git round-trips (snapshot-and-drop documented at 423-436). No path leaves a stamp claiming more verification than happened.

2. **Round arithmetic — fails open.** round = stamps.len()+1, base = last stamp. Parse skips malformed `## Reviews` lines (plan_file.rs tests) — a deleted last stamp widens the next scope (older base), a deleted first stamp keeps the correct last base, duplicates inflate the label only, reordering can only make the base older (wider). Hand-edited garbage bases are rejected by `validate_base_ref` at use time and degrade to the named-command scope, never a wrong tree. Plan swaps are safe: stamps are per-plan-frame. Only deliberate fabrication of a newer valid sha could narrow the scope — the file is agent-owned bookkeeping at the same trust level as the review flow itself; the injection class (the actual untrusted surface) is blocked (risk 3).

3. **Trust boundary — injection-safe.** `validate_base_ref` rejects empty/leading-`-`/whitespace/shell-metacharacter bases, and `GitRunner::run` invokes git via `Command::new("git").args()` (argv, no shell) — option injection and shell injection both closed; `changed_paths_since_impl` validates BEFORE invoking; `head_commit_sha` uses fixed argv (`rev-parse HEAD`) with no untrusted input at all. MockGit dispatches on exact argument arrays, so the invocation shape is pinned by the git_ops tests.

4. **Vacuous-PASS hole — round 1 closed; round 2+ edges = LOW 2.** The contract's Empty-diff rule ("a clean working tree … is not a review … `git merge-base main HEAD` → `git diff <that>` … Never report PASS without saying what you actually read") forces a clean-tree round-1 reviewer to review the branch's delta from the fork point rather than PASS on an empty diff. (The named commands exceed the reviewer's tool surface — LOW 1.)

5. **Best-effort boundaries — all three confirmed by code AND tests.** Git failure never blocks a spawn (all scoper results `.ok()`/matched to notes; spawn proceeds in every path); provenance never fails a report write (`provenance_line` → `Option`, `a_git_failure_omits_provenance_and_still_writes`); non-reviewer spawns stay byte-identical AND stamp nothing — `non_reviewer_spawn_task_is_byte_identical` asserts the task equality and `review_rounds().is_empty()` (the 1d0332ca invariant is fully pinned).

6. **Preamble correctness — PASS.** The verdict literals are byte-compatible with `parse_verdict` (src/tool/workflow/plan.rs:1649 — prefix match `## Verdict: PASS` → Pass, `## Verdict: FINDINGS` → Findings, anything else fails closed to Unparseable). The block is explicitly labeled "rendered by the harness — the dispatching agent does not supply this", so it does not read as the dispatcher's words; a malicious dispatcher could mimic the block but cannot remove the harness's copy (it is appended last, and following it is always safe). The delta block cannot license a narrower-than-real review: the changed set is mechanically derived by the app, not supplied by the dispatcher, and the no-base / blank-base / git-failure paths all fall back to a full-review instruction.

7. **Test honesty — no vacuous tests found.** Every new test asserts concrete strings or state; the FakeScoper design splits the concern correctly: rendering/preamble/stamping pinned in the spawn tests with canned answers, the git facts pinned in git_ops tests with an exact-argv MockGit (`head_commit_sha_impl_reads_rev_parse_head`, `changed_paths_since_*`). The production `GitReviewScoper` is a two-line delegation to those tested impls (the untested async `spawn_blocking` wrappers are trivial and match the house pattern). The remaining untested seam is the factory registration — LOW 3.
