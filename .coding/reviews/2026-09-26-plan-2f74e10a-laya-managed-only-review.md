### HIGH-1 (PRE-EXISTING since 7b7691b — surfaced by check 3, adjacent to check 4a): the `steer_tool_choice` Settings toggle cannot be saved — dead write-path contract gap

The frontend sends `laya_steer_tool_choice` in every Settings save (`frontend/src/components/settings/sections/ClassifierSection.tsx:222`, declared at `frontend/src/lib/tauri.ts:606` in `SettingsSavePatch`), but the backend save DTO — `src/config/settings_dto.rs::SettingsSaveDto` (:230-388) — has **no** `laya_steer_tool_choice` field, and the applicator (:622-636) applies only `laya_enabled / laya_auto_type_memories / laya_failure_triage / laya_failure_triage_knn / laya_auto_finetune`. With no `deny_unknown_fields`, serde silently drops the key, so toggling "tool-choice steering" in Settings → Classifier neither persists nor takes effect live — `rewire.rs:164 set_tool_choice_enabled(laya_cfg.steer_tool_choice)` reads the flag from the just-reloaded config, which never received the UI value. `save_settings` (settings.rs:975-985) parses into exactly this DTO, so there is no other path.

Evidence this is pre-existing, not a regression of this diff: `git show 7b7691b` (the commit that added steer_tool_choice) touched `general.rs`, `settings.rs` (the read-side `LayaWire`) and `tauri.ts`, but never `settings_dto.rs`; `git log -- src/config/settings_dto.rs` confirms no commit between 7b7691b and this change added the field. This change completed the read direction (fixture + `LayaWire.steer_tool_choice`) and fixed `is_default` so a hand-set flag persists — but the UI toggle remains dead. The read fixture test `ClassifierSection.test.ts:159-174` only asserts the frontend source declares the field, so nothing pins the backend apply.

Fix: add `#[serde(default)] pub laya_steer_tool_choice: Option<bool>` to `SettingsSaveDto` + an apply arm next to the other five, plus a `settings_dto` patch-apply test asserting it lands in `general.general.laya.steer_tool_choice` (and absent = keep). Alternatively, if the intent is that this toggle is not user-settable from Settings, the field must be removed from `SettingsSavePatch` + `ClassifierSection.tsx:222` — but 7b7691b's commit message ("config/IPC/UI" round-trip) says saveability was intended.
