## Findings

### LOW 1 — savings row's session attribution uses the SessionState mirror, not the turn's authoritative id (turn.rs:2734-2735)

`recall_block` records the row with `self.session_id()` (turn.rs:2734-2735), which reads the SessionState mirror (loop_impl.rs:1548-1554). But `run_turn` receives the authoritative id as a parameter (turn.rs:297), and the tree's own documentation for the neighbouring ledger path is explicit that the parameter wins and that the two can diverge: record_stats_row's doc says "`session_id` is the turn's authoritative id (the parameter, not loop state — **they can diverge if a caller passes an id without set_session_id**)" (turn.rs:2971-2977). The savings row can therefore be attributed to a stale or `None` session when a caller passes an id without `set_session_id` — inconsistent with the documented convention, and it misattributes per-session savings stats (the IPC layer queries those by session). Threading the parameter through `auto_recall` → `recall_block` (both live in turn.rs and are called only from run_turn, which holds `session_id`) is a two-signature change. Functionally minor: in the normal production path the AgentTask sets session state so they match.

### LOW 2 — the lever-OFF half of the acceptance test is weaker than plan step 7(b) promised (tests.rs:11259-11264)

Plan step 7(b) promised "assert byte equality against format_recall_context output, i.e. today's behaviour". What shipped (tests.rs:11262-11264) is only `turn2_off.contains(M1_HEAD)` — a containment check. The OFF run also never asserts that **no** `recall_delta` row reaches the ledger (`_store_off` is discarded at tests.rs:11260). So a regression where the OFF path (or the `after >= before` guard fallback) silently recorded a savings row while serving the full block would pass this test. The production code is correct — the OFF path returns `full` before any cache lock or savings call (turn.rs:2689-2697), and prompt.rs:1987 does assert byte-equality of the two render functions — but the end-to-end OFF assertions don't pin the whole contract.
