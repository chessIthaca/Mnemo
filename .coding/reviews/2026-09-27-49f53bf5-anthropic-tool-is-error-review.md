### Finding 1 (HIGH): `synthesize_not_run_results` leaves the not-run flag false — hard-stop mid-batch results reach Anthropic as `is_error: false`

- **Location:** `src/agent/turn.rs:4470-4489` (`synthesize_not_run_results`), called from the tool loop's `hard_stop` branch (`src/agent/turn.rs:2080-2082`) — when the currently executing tool hard-stops (approval denial / ask_user / interrupt), the REMAINING calls of the batch are synthesized as not-run by this function.
- **Evidence:** line 4478 pushes `messages.push(Message::tool_result(tc.id.clone(), tc.name.clone(), not_run));` with `not_run = "interrupted: not run (turn stopped)"` and no `tool_is_error`. `Message::tool_result` initializes the flag false, and `tool_result_block` (src/provider/anthropic.rs:589) always emits `"is_error": m.tool_is_error` — so these messages serialize as `"is_error": false`: the structured signal says "success" while the content says not-run. That is precisely the wire-vs-truth mismatch this plan fixes; the model is told the call succeeded.
- **It contradicts the change set's own artifacts:** the sibling not-run sites set `true` (mid-stream stop block `src/agent/turn.rs:4153-4160`; bad-JSON retry `src/agent/turn.rs:4415-4418`); the comment at `turn.rs:4109-4110` claims the mid-stream path produces "the same structure the tool loop's own stop paths produce"; the new field doc says the flag covers "FAILED (or never-run)"; and the acceptance criterion — "A failed or not-run tool result reaches the provider as is_error true" — is violated on a reachable production path (any hard stop with ≥2 calls in the batch; the messages land in history and ride the next request after the interrupt resolves).
- **Fix (one line):** `messages.push(Message { tool_is_error: true, ..Message::tool_result(tc.id.clone(), tc.name.clone(), not_run) });` — after which the comment at 4109-4110 becomes true as written. Extend the turn-level regression coverage (or a sibling test): force a hard stop on a 2-call batch (e.g. first call triggers an approval denial) and assert the next request's remaining tool result serializes `tool_is_error: true`.
