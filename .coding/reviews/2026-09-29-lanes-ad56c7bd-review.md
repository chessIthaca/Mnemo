### Findings

**L1 (low) — the lane memo keys plan identity by title, so two consecutive plans with the same title can leak a decision across the plan boundary.**
`needs_classify` (src/agent/step_lanes.rs) treats a memo as same-plan when `current.plan_title == plan_title`; `Plan` carries no unique id, so a NEW plan created with the SAME title as its predecessor, entering the same step index under an unchanged escalation epoch, hits `Reuse` — the previous plan's step decision (and its resolved model) serves the new plan's first attempt of that step. Agent-generated plan titles do repeat ("Fix the failing test"), and the stated invariant in PLAN.md is "the memo re-uses a decision for the same plan+step". Impact is bounded: one stale user-chosen lane model for one step attempt; no pin is violated and the epoch/step rules still hold. Suggested fix: include a per-plan-creation discriminator in the memo key (e.g. the plan's file stem/id from the workflow's plan handle, or a monotonically increasing plan counter bumped wherever a plan is created/loaded), so `Fresh` triggers on any new plan regardless of title.
