## Findings

**LOW 1 — stale spend-attribution slot is never cleared when no plan is live.** `set_spend_attribution` (turn.rs:510) is only called when `plan_scope` is `Some`; `take_spend_attribution` consumes at the usage site. If a request errors reporting no usage (stamp left in the slot) and the plan subsequently ends without another main request (e.g. crash-adjacent or externally-driven workflow clear — not via finish/abandon tools, whose requests consume the stamp first), a later planless request in the same loop instance would consume the stale stamp: a phantom row billed to the finished plan, and `plan_spend` re-keyed to the dead plan id. Impact is dormant in practice — the finished plan's cost report was already written at finish, so no report ever reads the phantom row, and caps only fire when a plan is live — but it is exactly the "stale attribution" window the plan's risk register names. Suggested hardening: clear the slot when `plan_scope` is `None` (one-line else branch at the stamp site), or take-and-discard at turn start when no plan is live. A test asserting a planless turn after an unconsumed stamp writes no row would pin it.

**LOW 2 — the cost report's `Totals` line counts verify evidence rows as "request(s)".** `cost_report` (budget.rs:286) renders `rows.len()` as "{n} request(s)", which includes 0-token `verify` rows; a plan with 10 model requests and 4 deterministic checks reports "14 request(s)". The same rows also inflate the per-lane `(no lane)` bucket count. Cosmetic (tokens are unaffected; verify rows are listed separately under "Deterministic checks"), but the label is factually wrong for the reader. Suggested fix: count `rows.iter().filter(|r| r.reason != "verify")` for the totals line (and per-lane counts), or relabel to "ledger row(s)".
