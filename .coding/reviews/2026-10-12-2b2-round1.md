### Finding 1 (HIGH) — console mode (-console) silently regressed to NoPolicy agents

Pre-2b.2, `factory.build()` inline-constructed `WorkflowPolicy` for **every** loop (commit cad67fc, 2a.6: "the policy Arc holds through the build") — console mode included, since it uses the same `brain.factory`. Post-2b.2, `set_policy_factory` is called only in main.rs's GUI arm `Ok(BrainOutcome::Ready(brain)) => { … }` (:453 → :502, before the first build at :536). The console path — `console::run_console()` (src-tauri/src/console.rs:1203) — calls `crate::build_brain(None, …)` directly and never runs that arm, and a repo-wide search confirms no `set_policy_factory` call anywhere in console.rs. Consequences for console-mode agents (the main REPL agent + every spawned child):

- They now build with `NoPolicy`: the volatile tail loses the workflow-state section and routing falls to the hardcoded `["free"]` chain instead of the state-scoped slot chain — while the kernel-registered plan tools (create_plan/complete_step/…) remain, so a console agent can run plans but no longer *sees* its plan state in its prompt nor routes by state.
- No test covers this: the console tests (console.rs:2113 `make_factory` + the spawner tests at :2136-2377) assert bookkeeping, not policy semantics, so the full battery stays green while the regression ships silently.

The audit section of the step file (## Audit, decisions D1-D6 + the 2b.2 step text :124-131) never mentions the console path — I checked — so this is not a documented deferral to 2b.3. Fix: wire the app `WorkflowPolicyFactory` in `run_console` before `console::start(brain)` builds/spawns agents (or hoist the wiring into a shared helper both the GUI Ready arm and run_console call), and note the console-mode shape in the step file's audit while at it.
