## Findings (all low)

**F1. `Engine::session()` is missing from the landed surface (bookkeeping accuracy).**
Step file §C D4's own surface list reads "start/spawn/**session**/host_events/shutdown/start_blocking only" and master spec §5.3 :299 sketches `pub fn session(&self, id: &SessionId) -> Option<AgentSession>` — `src/headless/engine.rs` ships 5 of the 6 (no `session()`), and the close report's deviation list (mpsc reply, 13th param, byte contract, busy/timeout export, engine-side parking) does not record the omission. Land it in 3b or amend §G so the record matches the tree. Note: a naive future implementation returning a fresh `AgentSession` handle would reset the parked flag — see F3's suggested home for it.

**F2. `run_to_completion` subscribes after sending — a lost `Finished` hangs the call forever (`src/headless/session.rs:300-305`).**
The prompt is queued at :300-304 and the broadcast subscription created at :305. A `Finished` broadcast landing in that window is never seen; the loop's exits are `Finished`/`Exited` (a live session never emits `Exited` mid-life) or the bus `Err` (close/lag) — so the call would block indefinitely with no timeout arm. The window is narrow — the caller runs an unbroken ready-poll chain from send to subscribe, so the whole turn plus the pump hop must complete on another worker inside it — but limit-immediate turns (wall-clock already expired: `Finished` at the first request head with zero provider work, exactly the `limits_wall_clock` shape) make it non-zero, and `#[tokio::test]`'s current-thread runtime can never catch it. Fix is one line: create `rx` before `self.send(..)`.

**F3. The parked flag is per-handle and only maintained by `run_to_completion` — the raw `send()`/`events()` surface never parks (`src/headless/session.rs:116,144-149,322-327`).**
`parked` is an `AtomicBool` on the `AgentSession` handle, set only by `run_to_completion`'s own event watch. A caller using the public `send()` + `events()` pair (§5.3 :319-320/:327-338) gets no `session_parked` after a limit hit — each further prompt enqueues a turn that immediately ends `LimitReached` at the request head. No cost leaks (verified: `begin_request` re-checks every request; the limits tests pin the provider call counts), but the spec's "parks the session" is realized only on the convenience method. Moving the flag into `EngineInner` keyed by `SessionId` and setting it in the pump (which observes every `Finished`) makes parking session-scoped, fixes the raw surface, and makes any future `session()`-built handle correct by construction.

**F4. Pump bookkeeping misses the console's final-`Error` arm (`src/headless/engine.rs` pump vs `src-tauri/src/console.rs:998-1008`).**
The console forwarder maps `Error{retrying:false}` → `on_turn_ended(id, false)`; the engine pump handles only `Started`/`Finished`/`Exited`, calling `on_turn_ended(agent, true)`. If the agent's post-error bookkeeping `Finished` (console.rs:990-991's comment) clears the running flag, a child of an engine session that dies on a final error still notifies its parent with `success=true` — the wrong flag for the error path. Mirror the console's arm in the pump, or document the reliance on the bookkeeping `Finished` plus the flag consequence explicitly in the pump's comment.

**F5. Approve/Answer on an unknown or already-resolved request id reports `session_closed` (`src/headless/session.rs:170-194`).**
Both arms fall back to `EngineError::session_closed("no pending approval '{request_id}'")` / `("no pending question '{question_id}'")`. A live session reporting itself closed misuses the one code the step file freezes as the stable wire contract; a caller distinguishing "session gone" from "stale request id" cannot. Add a distinct code (e.g. `unknown_request`) before the codes freeze — cheap now, breaking later.

**F6. Formatting drift in the landed hunk (`src/host/runtime.rs:227-231`).**
The 3a.6 `seed_messages` block (`// 3a.6 (G5): the resume seed …` through `task.seed_messages(messages);`) is indented one level shallow inside the `{ manager }` spawn block while its neighbors sit at 8 spaces. Cosmetic, but `cargo fmt --check` (or any future fmt CI) flags the hunk; run `cargo fmt` on it.

**F7. README.md / PLAN.md carry no mention of the new public `mnemo::headless` engine (doc sync).**
The module docs themselves are exemplary (every file documents its §5.3 anchor and design intent), and the arc's own sequencing defers exposure to 3c / the JS binding to job 5 — deferring is defensible. Flagged so it is not lost: 3c's completion (the full public surface) should add the README section + PLAN.md provider-strategy note; job 5's final acceptance should verify it. If 3c/5 already carry that item in their step files, this collapses to a note.
