## F1 (HIGH) — tier-1 named-policy spawn leaks the named factory into the shared `policy_factory` slot; every subsequent non-tier-1 spawn of that engine builds under it

**Evidence.**
- `AgentLoopFactory` is `#[derive(Clone)]` (src/agent/factory.rs:235) and `policy_factory` is `Arc<RwLock<Option<Arc<dyn AgentPolicyFactory>>>>` (src/agent/factory.rs:328) — a derived clone SHARES that slot with the base factory (the landing note's "the clone shares the live seams" is right by design for `provider`/`context_manager`/`spawner`/`descendant_tracker`; `tool_selection` is a plain clone-local field, so tier 2 is isolated correctly).
- The engine's tier-1 arm (src/headless/engine.rs:179-199): the comment says "Both tiers build on a PER-SPAWN factory clone — the shared factory is never mutated", then the code does `let per_spawn = (*self.inner.host.factory).clone(); per_spawn.set_policy_factory(named);` — and `set_policy_factory` (src/agent/factory.rs:802-810) writes `Some(factory)` into `self.policy_factory`, i.e. through the SHARED Arc. The clone gives no isolation for this field; the comment's claim is factually wrong for it. There is no restore after the spawn anywhere in `Engine::spawn`.
- The build consumes that slot at three sites — `create_workflow` (factory.rs:1092), `register_policy_factory_tools` (factory.rs:1604), `build_policy` + `attach_loop` (factory.rs:1168-1203) — each read at build time inside `spawn_agent_shared` (src/host/runtime.rs:73-313 → `build_with_id_and_plans_dir`).
- The base slot is initialized to `None` (factory.rs:489) and set ONCE at engine start to `FreePolicyFactory` (src/headless/engine.rs:530-534, `start_inner`).

**Consequences (deterministic, no concurrency needed).** After ANY tier-1 spawn with a non-free named factory `N`, the slot holds `N` for the engine's lifetime:
1. A subsequent plain `(None, None)` spawn (engine.rs:224-228 — the SAME `Arc<AgentLoopFactory>`, same slot) builds its session under `N`: `N`'s `register_tools` pollutes the registry, `N`'s `create_workflow` builds the workflow handle, `N`'s `build_policy`/`attach_loop` run — a session that asked for NO policy silently gets `N`'s tool surface, gates, and prompt head.
2. A subsequent tier-2 or tier-3 spawn: the build runs `N`'s three consumption sites, then the post-build swap (engine.rs:299-316) replaces only the policy OBJECT (`DeclarativePolicy`/`ExternalPolicy` wrapping `loop.policy()`); `N`'s registered tools, workflow handle, and attach side effects are NOT un-done. Under tier 1 + tier 2 this inverts the intended semantics: R1 says the tool array changes only at spawn — here an unrelated session's spawn changes it to `N`'s table.
3. **Concurrent race:** `spawn()` is `pub async fn` and the registry lock only covers the name lookup; `set_policy_factory` runs before `spawn_agent_shared`, whose entry awaits (`manager.lock().await`, `cleanup_inactive_subagents(...).await` — host/runtime.rs:108-120) precede the build. Two concurrent tier-1 spawns `P` and `Q` can interleave as set-P → set-Q → build-P → build-Q, handing BOTH sessions `Q`'s policy.

**Why the tests missed it.** `guardrails_selection_gate_rules_and_policy_registry` (tests/integration/headless_kernel.rs:1559) registers `mnemo.free = FreePolicyFactory` — identical to the base slot value, so the leak writes the same value it leaks — and its legs (a1)/(a2) (tier-2 spawns) run BEFORE the tier-1 legs; no leg spawns a plain or tier-2 session AFTER a tier-1 spawn.

**Fix direction (parent's choice).** Either make `Clone` manual and `policy_factory` clone-local with snapshot inheritance (a fresh `RwLock` seeded from the base slot's current read at clone time — the app path is unaffected since the app never clones; the engine's plain/tier-2/3 arms still see `FreePolicyFactory`, tier-1 writes stay clone-local and die with the clone); or thread the named factory through `spawn_agent_shared` as an explicit one-shot param (like `host_tools`/`permission`) with a per-build override. A save/restore around the spawn is NOT sufficient — it still races concurrent spawns.

**Suggested regression test:** register a named factory that registers a sentinel tool (or stamps an observable prompt head), spawn tier-1 under it, then spawn a plain `(None, None)` session and assert the plain session's surface contains NO sentinel and its policy head is the free default; plus two concurrent tier-1 spawns asserting each session sees its own policy.

## F2 (LOW) — a registered factory that refuses is silently substituted with the GATED coding default, and `register_policy` doesn't document the contract

`Engine::register_policy` (src/headless/engine.rs, the tier-1 registry) exposes `Arc<dyn AgentPolicyFactory>` to hosts. The factory build always passes `PolicyFactoryCtx` with `prompt: None` (src/agent/factory.rs:1174-1186, hardcoded), and a refusal — e.g. any NoPolicy-semantics factory returning `KernelError::PromptRequired` (the 2c.1/G1 contract) — is swallowed by the factory-level fallback at factory.rs:1195: the session is built with `NoPolicy::with_coding_default()` — the NON-ungated (gated) default — and the spawn SUCCEEDS. The factory comment says "the Engine path (3a) owns propagating the error to its spawn callers", but no such propagation exists on the tier-1 path (the build is infallible; the engine never sees the refusal). Pre-3c this was benign (the app factory never errs; `FreePolicyFactory` handles `None` internally — policy.rs:342-368), but tier 1 makes third-party factories reachable: a host registering a prompt-spec-requiring factory gets silently re-gated sessions with no error. The `register_policy` doc comment should at minimum state the contract ("build_policy runs with `prompt: None`; refusals silently attach the coding-default fallback"); better, the tier-1 path could fail the spawn on refusal (spawn_failed) so G1's "never a silent coding default" holds on the new surface.
