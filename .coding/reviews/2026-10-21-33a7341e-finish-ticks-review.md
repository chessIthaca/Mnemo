**L1 (low) — `persist_completed_marks` flips checkbox-shaped lines in the whole file, not just the Steps/Detailed-steps sections.** `tick_checkbox_line` is applied to every line of the frame, so a line in Goal/Context that *begins* with `- [ ]` (e.g. a bug plan whose Context quotes the symptom fixture, or a review-findings list pasted into Context) gets flipped to `- [x]` on disk while the in-memory `complete_all_steps` leaves it alone (it only touches `steps` + `detailed_steps`). Divergence between disk and memory plus prose mutation; the parser ignores such lines, so re-parse is unaffected. Low probability (checkbox literals in Context are usually inline, as in 33a7341e.md itself), low impact. Suggest scoping the flip to the `## Steps` / `## Detailed steps` sections (track the current `##` header while iterating) or documenting the constraint in the method's doc comment.

**L2 (low) — retry-after-IO-error hazard in `finish`.** At mod.rs:1082-1088, if `persist_completed_marks` fails (transient IO error), `?` aborts **after** `complete_all_steps` already ticked the in-memory model but **before** the state flip — the workflow stays Reviewing with memory ticked. A retried finish then sees `flipped == 0`, skips the disk persist entirely, and completes with open checkboxes on disk — exactly the divergence this fix removes. Un-gating the persist (always call `persist_completed_marks`; it is idempotent and cheap when nothing flips) heals the retry path.
