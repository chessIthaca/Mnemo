## Findings

**L1 (low) — Tool entries are not turn-scoped; a reused stream index or call id can contaminate another card.**
- Evidence: `mnemo2/src/lib/leadState.ts:163-174` routes argument fragments by `entry.streamIndex === index` with only `result === null` as a guard, and `startToolEntry` (leadState.ts:139) unconditionally resets an existing entry to `result: null` (clearing `arguments` and `liveOutput`) when `tool_call_start` re-announces the same call id. Tool indices restart at 0 each turn, and `leadEventNeedsSnapshot` (leadState.ts:525-545) does not include `error`, so an errored turn performs no snapshot rebuild.
- Failure mode: a tool entry orphaned in running state — a turn dying between `tool_call_start` and `tool_result` with no `finished` (e.g. a non-retrying provider error mid-call) — keeps `streamIndex: 0`; the next turn's first call also starts at index 0, so its argument fragments append to the orphaned card, which then shows Running with another call's arguments. A re-announced completed id would flip a Completed/Failed card back to Running.
- Impact: misleading UI in a narrow error path only; self-heals at the next snapshot refresh (after the next `finished`); output routing is by unique call id, so no output or transcript data is ever corrupted.
- Required fix: turn-scope the routing — e.g. strip `streamIndex` from all tool entries on `started` (or only route fragments to entries created since the last `started`) — and preserve a finalized entry's `result` across a re-start. Add the L4c regression test.

**L2 (low) — A rejected renderer import is cached forever.**
- Evidence: `mnemo2/src/components/Markdown.svelte:1-8` caches the dynamic-import promise at module scope (`markdownModule ??= import(...)`); the `.catch` at 63-65 keeps the previous frame but never clears the cache.
- Impact: one chunk-load failure (rare in a bundled Tauri app, plausible in a dev/web context) leaves every Markdown instance on the plain-text fallback for the app's lifetime, the error silently swallowed on every render.
- Required fix: clear the cache on rejection so the next render retries, e.g. `markdownModule ??= import("../lib/markdown").catch((e) => { markdownModule = null; throw e; });`.

**L3 (low) — Empty-result cards render an empty collapsible "Result"/"Error".**
- Evidence: `mnemo2/src/components/ToolActivity.svelte:48-55` gates only the inner `<pre>` on `entry.result.output`; the `<details>` renders whenever a result exists. A success with empty output (e.g. a shell command with no stdout) yields an expandable "Result" summary with nothing under it. The plan states raw arguments and live/result output blocks render "only when nonempty" — arguments and live output are gated correctly (34-46); the result block is not.
- Impact: cosmetic — an expandable disclosure that opens to nothing.
- Required fix: gate the `<details>` on `entry.result.output` (or render a non-collapsible status line for empty results).

**L4 (low) — Three test-coverage gaps against the stated acceptance criteria.**
- (a) Split-surrogate avoidance in `appendLiveOutputTail` (leadState.ts:99-100) is untested: the 16 KiB test (leadState.test.ts:353-391) uses pure ASCII (`"a".repeat(20_000)` + `"b"`); criterion 1 explicitly names "without a split surrogate". Add a test whose cap cut lands between a surrogate pair and asserts the orphaned low surrogate is dropped and length is exactly 16 KiB - 1.
- (b) No LeadChat test unmounts the component or asserts `disconnect`/`cancelAnimationFrame`: criterion 3's "cleans up observer/frame on unmount" is implemented (LeadChat.svelte:29-36) but unprotected by a regression test, unlike Markdown's unmount test (Markdown.test.ts:101-112).
- (c) No test feeds live tool events after a snapshot restore — restored entries must ignore fragment routing and a new turn's call must get its own card; this is exactly the property whose failure mode L1 describes, so the L1 fix needs this test anyway.
- Impact: the implemented behaviors are correct today (verified by reading), but the acceptance criteria name them and nothing locks them.
- Required fix: add the three focused tests (all small reducer/component cases).
