- Evidence (a): `mnemo2/src/components/Markdown.svelte:4-10` correctly clears the module-scoped `markdownModule` promise in its rejection handler before rethrowing, so a later render retries — but no test exercises a rejecting import. The only test mock resolves through a gate that is always released (`Markdown.test.ts:5-17`, `55-58`); all three tests (lines 60-116) end in resolved imports. Red-capable gap: against the pre-fix code (cached rejected promise kept forever) a reject-once-then-resolve test would see the second render never commit (`hasRendered` stays false, the plain-text fallback persists), so the fix is currently unprotected against a silent regression.
- Evidence (b): `mnemo2/src/components/ToolActivity.svelte:48` now gates the Result/Error `<details>` on `entry.result && entry.result.output` — but ToolActivity has no test file, and no suite renders an empty-output result: `LeadChat.test.ts:170-217` uses only nonempty outputs, and the leadState tests assert reducer state, not the disclosure. Red-capable gap: against the pre-fix unconditional `<details>`, an empty-output success rendered an expandable "Result" that opened to nothing — exactly the cosmetic defect round 1 reported as L3.
- Impact: both fixed behaviors can silently reappear; the plan's own step 8 states the "nonempty output" gating invariant and acceptance criterion 2 names "retries after a failed import". The L1 and L4 fixes were all locked by tests; these two were not.
- Required fix: two focused tests. In `Markdown.test.ts`: make the mocked `../lib/markdown` import reject for the first render and resolve for the retry, assert the component recovers and commits rendered HTML on the next render (assert the retry call happens — fails against the pre-fix cache-forever behavior). In `LeadChat.test.ts` (or a new `ToolActivity.test.ts`): render a tool entry with `{ success: true, output: "" }` and one with `{ success: false, output: "" }`, assert no "Result"/"Error" `<details>` renders while the "Completed"/"Failed" status badge does (fails against the pre-fix unconditional disclosure).
