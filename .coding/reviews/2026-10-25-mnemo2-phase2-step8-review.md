## Findings

**F1 (LOW) — `shutdown(&self)` fixes the session bus but leaves `host_events_tx` alive: the same hang class, latent.** `src/headless/engine.rs:67` — `host_events_tx: broadcast::Sender<HostEvent>` is a plain field; `shutdown` (engine.rs:448-469) aborts the pump and takes the *session* bus sender but never clears the host-events sender. On a shared `Arc<Engine>` that outlives `shutdown` (exactly the Mnemo2 shape this delta fixes), a `host_events()` subscriber never observes `RecvError::Closed` until the Arc drops. Pre-Phase-2 `shutdown(self)` dropped this field at shutdown time, so this is a real behavior change for that surface — the sibling of the bug that hung the integration suite. It is latent today: the only subscribers are tests (`tests/integration/headless.rs:384` discards the receiver; `tests/integration/headless_kernel.rs:732-767` never awaits post-shutdown), and no production code subscribes host events on the shared engine. Fix suggestion: the same `std::sync::Mutex<Option<…>>` take in `shutdown`, or an explicit doc note on `host_events()` that it closes on engine *drop*, not shutdown, for shared engines.

**F2 (LOW) — `spawn` on a shut-down engine does full host work and registers the session *before* the `session_closed` check.** `src/headless/engine.rs:333-405` — `spawn` runs `spawn_agent_shared` (line 333, creating an agent in the host runtime) and inserts the id into `inner.sessions` (line 402) *before* `session_bus()` fails the call (403-405). Every spawn rejected on a shut-down engine therefore leaves a registered-but-unusable idle agent in the registry and the host runtime (and a spawn racing a shutdown can re-populate the just-cleared registry). No live task leaks (no prompt served) and the engine is typically dropped right after, but the guard was newly introduced by this change and should be side-effect-free: hoist the `self.session_bus().ok_or_else(|| EngineError::session_closed("the engine is shut down"))` check to the top of `spawn` (fail fast before any host work). The interleaving semantics are unchanged — today's code has the same TOCTOU window between insert and check.

**F3 (LOW) — the `connectTeam` handshake gate has no regression coverage.** `mnemo2/src/lib/store.host.test.ts:42` mocks `createTeamTransport` to `() => null`, so `connectTeam` (store.ts:711-716) returns at the transport-null check and its `probeMnemo2Host` gate — one of the three gates this delta claims — is never exercised; the test covers `openFolder` and (via `listCalls`) `loadProjects` only. Cheap addition: mock a non-null team transport with an `onEvent` spy, call `actions.connectTeam()` (or `openProject`) with `handshake: false`, and assert 0 subscriptions; flip `handshake: true` and assert 1. The gate code itself is correct (verified by reading).

## Verification detail

**Engine shutdown fix (src/headless/engine.rs) — verified correct.**
- No std-Mutex guard across an await: both critical sections are sync and statement-scoped — `session_bus()` clones inside one expression (engine.rs:434-436); `shutdown`'s `take()` is a single `let` with no await inside (engine.rs:467). The tokio `sessions` locks in `spawn`/`session`/`shutdown` release at their statement ends before the bus lock is taken; lock order is one-directional (sessions → manager → bus), no cycle. The pump holds a bus clone but never touches the std mutex.
- Poisoning: unreachable for a legitimate caller — the only lock sites are `clone()` and `take()`, neither can panic; the `.expect` matches the codebase's existing idiom (engine.rs:219 `policy_registry`).
- Idempotent shutdown: second call cancels over an empty registry, clears an empty map, `abort()` on the aborted pump is a no-op, `take()` on `None` is a no-op; returns `Ok`.
- `session_closed` contract: right choice. error.rs:62-68 documents the code as the closed-session surface ("every `send` on it fails with this code", §7 row 15 pinned); session.rs:240-247 is the existing precedent (registry lookup miss → `session_closed`). The spawn-after-shutdown reuse stays in the pinned family; the planned-but-never-landed `engine_shutdown` constructor (error.rs:31-33 comment) would be an unpinned new code — reusing the pinned one is correct.
- Sender topology: clones exist only in the engine's `Mutex<Option<…>>` (taken at shutdown, after the pump abort), the pump task (dropped by abort), and session handles (dropped by callers) — so `Closed` is observable exactly when the delta intends. `AgentSession::events()` subscribes to the session's own clone (session.rs:234-238), so pre-shutdown sessions keep observable events until dropped, and no subscriber-creation path regressed (spawn refuses; `host_events()` still subscribes — see F1 for its lifetime).
- Regression test `shutdown_through_a_shared_arc_closes_the_bus` (headless.rs:614-643): genuinely exercises the Arc shape — spawns, subscribes via `session.events()`, shuts down through the Arc, drops the session, asserts `RecvError::Closed` within 5s (strict: any event or `Lagged` panics), then asserts a later spawn yields `session_closed`. Imports (`RecvError`, `tempfile`, `ScriptedLlm`) all exist in the file. Red before the fix is credible: without `take()`, the engine's sender survives in the Arc and `recv` hangs — matching the recorded symptom.
