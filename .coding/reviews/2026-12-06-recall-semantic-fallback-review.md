### Findings

**LOW-1 — boundary value in the weight-rationale comment is off by the crossover.** `src/memory/mod.rs:1355` and `mod.rs:1370`: "a strong semantic match (sim ≥ ~0.85) legitimately outweighs a bare keyword hit (0.3)". With weight 0.35 the crossover is exactly 0.3/0.35 = 6/7 ≈ **0.857** — at sim = 0.85 the semantic term is 0.2975 < 0.3, i.e. it does *not* outweigh. The "~" hedges it, but this comment is the reference a future weight-tuner will read. Fix: change both occurrences to "sim ≥ ~0.86" (or state the crossover: "sim > 6/7 ≈ 0.857"). Doc-only.

**LOW-2 — latent footgun: a future real embedder that forgets to override `model_id()` silently inherits the 0.2 weight.** `src/memory/embedder.rs:44-50`: the trait default is `"hash"`, and recall's cosine weight now branches on that exact string (`mod.rs:1373`). No remote embedder exists today, but the trait docs and the new comments already anticipate one; an implementation that neglects the override would produce real embeddings scored at the noise weight with no error anywhere — semantic matches systematically understated, invisibly. Fix: extend the `model_id` doc comment with one line, e.g. "Real embedding models MUST override this — recall tiers its cosine weight on this id (0.2 for the hash fallback, 0.35 otherwise)." Doc-only hardening.
