# Architecture Review — Mnemo at HEAD (`wt/agenticcoding`)

**Perspective:** Architecture / structural design (read-only)
**Reviewer:** read-only review subagent
**Scope:** whole codebase at HEAD — `src/` (mnemo crate, the "brain"), `src-tauri/` (Tauri app shell + IPC), `frontend/` (React/TS). No code executed; findings reasoned from source with file:line evidence.

## Architecture overview

**Layering (the foundational decision — correct):** The brain (`src/lib.rs`) declares 18 top-level modules (`agent`, `app`, `backlog`, `browser`, `codegraph`, `config`, `error`, `mcp`, `memory`, `model_resolver`, `project`, `provider`, `runtime`, `safety_rules`, `skill`, `thread_util`, `tool`, `workflow`) and has **zero dependency on Tauri**. The dependency direction is one-way: `src-tauri/main.rs` imports *from* `mnemo`; the brain never imports *from* the shell. The IPC layer (`src-tauri/src/ipc/mod.rs:5-17`) is an explicit adapter — "the brain is fully decoupled: it speaks `AgentCommand`/`AgentEvent` over channels. This module adapts that to Tauri's IPC." This means the brain is testable and reusable without a GUI, exactly as `lib.rs:8-10` claims.

**The agent loop (`src/agent/`):** Cleanly split by responsibility — `loop_impl.rs` (the `AgentLoop` struct, handles, public API), `turn.rs` (the `run_turn` driver: token-count → summarize → auto-recall → stream → dispatch → feed-back → repeat), `dispatch.rs` (tool-call dispatch + approval gate + provider retry), `context.rs` (token counting + summarization), `prompt.rs` (system-prompt assembly), `factory.rs` (per-agent construction), `approval.rs` (safety-boundary checks). The module doc (`agent/mod.rs:5-21`) documents the turn lifecycle and the split rationale.

**Provider abstraction (`src/provider/`):** The `LlmClient` trait (`provider/mod.rs:376`) is an async trait with one core method — `complete() -> Result<BoxStream<'_, LlmEvent>>` (`:401-406`) — plus capability introspection. `Capabilities` (`:32-49`) is a per-provider-kind struct (OpenAI/Local/Anthropic defaults at `:53-96`) with config overrides (`capabilities_with_overrides`, `:128`). Two implementations: `openai.rs` (4481 lines) and `anthropic.rs` (1821 lines). Shared streaming helpers (`DeltaAccumulator`, `ToolCallAccumulator`) live in `stream.rs`. The trace log (`trace.rs`) is a bounded ring buffer shared across all providers.

**Tool system (`src/tool/`):** The `Tool` trait (`tool/mod.rs:106`) with four categories (`Agent`/`Workflow`/`Memory`/`Browser`, `:33-42`) and a `SafetyLevel` (`AutoRun`/`NeedsApproval`, `:46-51`). The workflow's `allowed_tools()` returns a `ToolFilter` applied at **two** layers: schema-build (hides tools from the model) AND dispatch-time re-check (`dispatch.rs:99-111` — "a hallucinated name omitted from the schema still cannot run"). This defense-in-depth is the right pattern.

**Workflow state machine (`src/workflow/`):** Five states (`Planning`/`Executing`/`Reviewing`/`Complete`/`Skill`, `workflow/mod.rs:26-49`) with *enforced* gates — `Workflow::allowed_tools()` returns a `ToolFilter` the loop applies before building the request schema, so in `Planning` write tools are omitted entirely (`mod.rs:7-10`). The plan stack (`PlanFrame`, `:64-70`) supports sub-plans. The skill overlay (`ActiveSkill`, `:78-93`) carries its own tool allow-list. `finish` is gated on a non-empty review report — "the review is unskippable by construction, not by convention" (`:36-39`). Sidecar persistence (`StackSidecar`, `:104`) survives restarts.

**Multi-agent runtime (`src/runtime/`):** `AgentManager` (`runtime/mod.rs:28-33`) spawns agents as tokio tasks, routes commands by id, and fans-in events via a bounded `mpsc::channel`. Critically, `take_fanin_rx()` (`:83-88`) lets the event forwarder own the receiver directly — "no manager lock while waiting on `recv()`" (avoids the deadlock where a Tauri command blocks on the manager lock while the forwarder holds it waiting for the next event). `AgentLoopFactory` builds a fresh `AgentLoop` per agent, each with its own `Workflow` + `ToolRegistry` — "multi-agent is safe for concurrent implementation" (`ipc/state.rs:11-16`).

**Memory (`src/memory/`):** Four-tier model (Working/Episodic/Semantic/Procedural, `types.rs:18-27`) after agent-memory.dev. SQLite + FTS5 + ONNX embeddings. The consolidation pipeline (`consolidation.rs`) distills working → episodic/semantic/procedural. All SQLite + ONNX work runs in `spawn_blocking` (verified in the performance axis). `MemoryStore` is shared via `Arc` across agents.

**IPC boundary (`src-tauri/src/ipc/`):** 24 domain submodules (`mod.rs:19-43`). `IpcState` (`state.rs:48-60`) groups state into nested contexts (`AgentRuntimeContext`, `ProjectContext`, `BacklogContext`) so each command module reaches only what it needs. A **lock-ordering invariant** is documented (`state.rs:42-47`): "when both `manager` and `agent_loops` must be held, always acquire `manager` first, then `agent_loops`." The event forwarder (`events.rs`) translates `AgentEvent`s to Tauri events, with `TurnResolveLatch` ensuring at-most-once terminal-outcome resolution (`events.rs:21-27`).

**Error handling (`src/error.rs`):** A single `thiserror::Error` enum (`:13-84`) with `#[from]` for io/json/toml/sqlite. Classification methods `is_non_retryable()` (`:86`) and `is_rate_limited()` distinguish error classes for the retry/fallback logic. The binary boundary converts to `anyhow`.

**Frontend (`frontend/src/`):** React + TypeScript. Components organized by domain (chat, layout, settings, views, projects, about, common). The agent-event listener is a module-scope singleton (`useAgentEvents.ts`) with rAF-batched flushing. `Message` is `React.memo`-wrapped with a custom `arePropsEqual` (`Message.tsx:35,435`). The event reducer (`agentEventReducer.ts`) is a pure reducer returning Effects — a sound pattern.

## Fresh findings

### A1 — LOW: Stream-safety logic is provider-specific, not shared (abstraction leak)

**Evidence:** The `LlmClient` trait (`src/provider/mod.rs:376`) defines a uniform streaming contract — `complete() -> Result<BoxStream<'_, LlmEvent>>`. The shared `stream.rs` module (209 lines) houses the cross-provider streaming helpers: `DeltaAccumulator` and `ToolCallAccumulator` (`stream.rs:17,40`). But the repetition guard — `detect_repetition` (`openai.rs:1590`), `bound_repetition_buffer` (`openai.rs:1568`), and the constants `REPETITION_WINDOW=200` / `REPETITION_THRESHOLD=3` / `REPETITION_BUFFER_CAP=2048` (`openai.rs:115,117,138`) — are **private to the OpenAI client**. The Anthropic provider's streaming loop (`anthropic.rs:940`) accumulates `TextDelta` events with no repetition check (confirmed: zero matches for `detect_repetition`/`bound_repetition_buffer`/`REPETITION` in `anthropic.rs`). The OpenAI client is 4481 lines vs Anthropic's 1821 — the 2.5× size gap reflects feature asymmetry, not just protocol difference.

**Why it matters (architecture lens):** The trait promises a uniform streaming interface, but one implementation carries a safety feature the other lacks. This is an abstraction leak: stream-safety is a *cross-cutting concern* (every provider can degenerate into a repetition loop), yet it's implemented as OpenAI-specific code. The consequence (a stuck Anthropic stream wastes output tokens unbounded by the guard) is the performance finding F1; the *architectural* concern is that the trait's contract doesn't enforce stream-safety, so it's applied inconsistently and will be missed again when a third provider is added. The shared `stream.rs` module — already the home for cross-provider streaming helpers — is the natural place for the guard.

**Recommendation:** Lift `detect_repetition` + `bound_repetition_buffer` + the three constants into `stream.rs` as provider-agnostic free functions (or a small `RepetitionGuard` struct wrapping the bounded buffer + check). Apply the guard in the Anthropic loop's `TextDelta` arm, mirroring the OpenAI call site (`openai.rs:1103-1137`). This makes the guard a property of the streaming layer, not of one provider — future providers inherit it for free.

## Strengths (verified)

- **Brain/shell decoupling is real.** `src/lib.rs` has no `tauri` import; the IPC layer is an explicit adapter over the channel contract (`ipc/mod.rs:5-17`). The brain is fully testable without a GUI.
- **Enforced workflow gates (defense in depth).** `Workflow::allowed_tools()` returns a `ToolFilter` applied at schema-build (hides tools from the model) AND re-enforced at dispatch time (`dispatch.rs:99-111`) — a hallucinated or stale tool name cannot bypass the Planning/Skill gate. The review is unskippable by construction (`finish` gated on a non-empty review report, `workflow/mod.rs:36-39`).
- **Multi-agent-ready from day one.** `AgentLoopFactory` builds a fresh `AgentLoop` per agent with its own `Workflow` + `ToolRegistry`; `AgentManager` fans-in events via a bounded channel. `take_fanin_rx()` (`runtime/mod.rs:83-88`) avoids the manager-lock-while-waiting deadlock. No shared mutable workflow state across agents.
- **Clean provider abstraction.** `LlmClient` is a minimal async trait (one streaming method + capability introspection). `Capabilities` per-kind with config overrides lets endpoints proxy models with different limits. The provider cache (`model_resolver.rs:167`) reuses `reqwest::Client` connection pools across turns.
- **Documented lock-ordering invariant.** `IpcState` (`state.rs:42-47`) documents the `manager`-before-`agent_loops` ordering and recommends snapshot-then-drop to avoid holding both. The event forwarder owns the fan-in receiver directly (no lock while waiting on `recv()`).
- **At-most-once terminal resolution.** `TurnResolveLatch` (`events.rs:21-27`) ensures a turn resolves the backlog at most once, even when a failure path emits both a final `Error` and `Finished`.
- **Unified error type with classification.** A single `thiserror` enum with `is_non_retryable()` / `is_rate_limited()` classification powering the fail-fast + 429-fallback paths. Good test coverage of the classification (distinctness + non-429 exclusion tests).
- **Sound retry layering.** `complete_with_retry` (provider-call level, 3 attempts, exponential backoff) + `run_turn_attempt` (turn level, with the `tried_fallback` single-switch cap). Non-retryable and rate-limited errors short-circuit immediately. `MAX_BAD_JSON_RETRIES=8` handles malformed tool-call JSON with a sanitization re-parse, feeding the error back as a tool message.
- **Frontend architecture is sound.** Pure reducer returning Effects (executed by the store), module-scope singleton listener with rAF batching, `React.memo` with custom equality on the hottest component. The reducer's per-flush string concat is a documented, accepted O(n²)-amortized trade-off.

The IPC lock-ordering invariant and channel contract are platform-agnostic. ✓

## Summary

The Mnemo architecture is well-engineered and structurally sound. The foundational decision — a fully decoupled brain that speaks channels, adapted to Tauri IPC by a thin shell — is correct and consistently applied: the brain has zero Tauri dependencies, the workflow is an enforced state machine with defense-in-depth tool gating, the multi-agent runtime is fan-in/fan-out with a deadlock-avoiding receiver-ownership pattern, and the IPC boundary has a documented lock-ordering invariant. The provider abstraction is a clean async streaming trait. The one fresh finding (A1) is a provider-abstraction leak: the repetition guard — a cross-cutting stream-safety concern — is private to the OpenAI client rather than in the shared `stream.rs` module, so the Anthropic provider lacks it. The prior String-based error classification (AE1) remains an accepted, twice-documented trade-off, now partially mitigated by the `is_rate_limited()` classification layer added with the 429-fallback feature. Neither finding indicates a structural defect — the layering, separation of concerns, and enforcement mechanisms are all correct.
