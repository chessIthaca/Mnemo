`handleSave` runs `setCacheCeilingSnap(cacheCeiling)` unconditionally, while the section's own comment (lines 116–119: "Anything else — stray text, sub-floor values — must not latch dirty (reviews I4 + F3 pattern)") and the sibling knobs at lines 172–175 (`setTraceBudgetSnap(budgetValid ? traceBudget : traceBudgetSnap); if (!budgetValid) setTraceBudget(traceBudgetSnap)` and the identical pair for `reqCap`) explicitly guard against latching an unsaveable value. An invalid ceiling (sub-floor number like `1000`, or `NaN` from stray text — both filtered out of the patch by `cacheCeilingDirty` at line 123) is still written into the snapshot whenever a save fires for another dirty knob, so the input then displays a value that was never persisted, with no dirty flag, until the section reloads. Nothing incorrect is ever sent to the backend (patch is gated by `cacheCeilingDirty`), so severity is low — but the fix is a one-line mirror of the existing pattern: `setCacheCeilingSnap(cacheCeilingValid ? cacheCeiling : cacheCeilingSnap); if (!cacheCeilingValid) setCacheCeiling(cacheCeilingSnap);`
