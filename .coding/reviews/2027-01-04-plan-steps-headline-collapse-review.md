### Findings

**L1 — Popup step label assumes in-order completion** — `frontend/src/components/layout/ExecutingStepPopup.tsx:29`
`· step ${Math.min(completed + 1, total)}/${total}` derives the step number from the completed count. If steps complete out of order (e.g. steps 1 and 3 done, step 2 current), the header reads "step 3/3" while the line below shows step 2's headline. `current` is already in scope — `current.index + 1` is exact, and the existing in-order test fixture ("step 2/3") stays green under it. Note the same completed+1 assumption is pre-existing in the toolbar's `stateLabel` (StatusBar.tsx:537-541), so today popup and toolbar agree; fixing only the popup makes the popup exact but able to disagree with the toolbar in the rare out-of-order case. Either switch to `current.index + 1` or leave as-is for toolbar consistency — flagging so the choice is deliberate.

**L2 — Stale expansion overrides: two residual leak paths** — `frontend/src/components/views/PlanProgress.tsx:101-111, 153-158`
(a) Same-title plan replacement / `update_plan` does not reset `expandOverrides` — the title-change reset (lines 101-111) keys on `plan.title`, and `PlanFile` (types.ts:103-108) carries no id, so title is the only identity signal in the payload. Acknowledged design limit; impact is cosmetic (a row starts expanded/collapsed contrary to default) and self-corrects on toggle. Acceptable as-is.
(b) `ancestorOverrides` resets ONLY on agent change (line 95) — never when switching between different ancestors: `viewAncestor` (line 63) fetches a different plan but keeps the map, so expanding step 1 of ancestor A and then viewing ancestor B shows B's step 1 expanded. Ancestors DO carry ids (`parents: { id: string; title: string }[]`, line 17), so clearing (or keying) `ancestorOverrides` per ancestor id inside `viewAncestor` is a cheap fix. It is also not reset on plan-title change (only `expandOverrides` is, line 109).

**L3 — Test gap: reset logic unpinned** — `frontend/src/components/views/PlanProgress.expand.test.ts`
The contracts pin the executing gate, the override-default expression, and PlanStepRow×2, but nothing pins the title-change reset effect (PlanProgress.tsx:101-111 — the anti-stale-leak logic behind L2) or the ancestor-view collapsed default (`ancestorOverrides[step.index] ?? false`).
