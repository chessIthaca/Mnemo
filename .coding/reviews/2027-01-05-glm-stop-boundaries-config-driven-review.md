## Findings

### Low 1 — client_factory wiring line has no test coverage (unlike its sibling field)

`src/provider/client_factory.rs:102` — `stop_boundary_strings: endpoint.stop_boundary_strings_for(model)` is the only untested link in the chain. The sibling wiring for `stop_token_ids` IS asserted in `openai_client_config_propagates_sampling_and_stop_params` (client_factory.rs:896 `cfg1.stop_token_ids`, :907 `cfg2.stop_token_ids`), but that test was not extended: it sets no `stop_boundary_strings` on its fixture `Endpoint`/`ModelSpec` and asserts none on `cfg1`/`cfg2`. The resolution logic is tested in endpoints.rs and the consumption in openai.rs, but both openai.rs test suites construct `OpenAiClientConfig` directly — bypassing client_factory — so deleting the wiring line (falling back to `Default`'s empty vec) would fail NO test, silently disabling the whole feature in production.

**Fix:** in `openai_client_config_propagates_sampling_and_stop_params`, add `stop_boundary_strings` to the model spec (e.g. 2 entries) and the endpoint (1 entry) and assert `cfg1.stop_boundary_strings` / `cfg2.stop_boundary_strings` resolve model-then-endpoint — mirroring the existing `stop_token_ids` asserts exactly.

### Low 2 — patch.rs carry-over test uses raw angle-bracket tag literals, violating the documented escapes lesson

`src/config/patch.rs:1087` and `:1095` initialize the new field with raw tag-shaped literals (`\u{3c}|model-bound|\u{3e}` and `\u{3c}|ep-bound|\u{3e}` written as raw angle-bracket text), asserted raw at `:1121`/`:1129`. The transport-hardening lesson (PLAN.md item 8, the DECISION file, and this plan's own spec) mandates that tag literals in tests be built from `\u{3c}`/`\u{3e}` escapes, never raw angle-bracket text — raw tags were stripped in text transports during the original fix's development. These are synthetic tags (not real GLM tokens) and they demonstrably survived transport this time, but the hazard is real in this very file: the pre-existing `stop` entries in the same test read as empty strings through the read transport (stripped or empty — indistinguishable from outside). A future transport that strips `<|...|>`-shaped text would silently degrade this test.

**Fix:** build the four literals from `\u{3c}`/`\u{3e}` escapes (e.g. `vec!["\u{3c}|model-bound|\u{3e}".into()]`), matching every other new test in this change (endpoints.rs fixtures use TOML `\u003C` escapes; openai.rs tests use Rust `\u{3c}` escapes).
