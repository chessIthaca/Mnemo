## Findings

### LOW 1 — `startup_snapshot`'s backlog read path left on the raw `BacklogItem` shape

`src-tauri/src/ipc/startup.rs:37` (`pub backlog: Vec<BacklogItem>`) and `:109` (`state.backlog.store.lock().await.items().to_vec()`) — the fourth IPC backlog read path was not routed through the new `resolve_item_view`. The frontend seeds its backlog state from this snapshot on mount (App.tsx:227–249, tauri.ts:249), so the initial payload's items lack `checkpoint_sha` until the first `backlog://changed` event or `backlog_list` refresh. Not a runtime break (the TS field is optional and has no consumer yet), but two claims are now inaccurate: the `StartupSnapshot` field doc "The backlog (same as `backlog_list`)" (startup.rs:36) and the types.ts doc "always present from the backend". Pre-existing and adjacent: the snapshot's items also bypass image resolution — they carry stored relative PATHs, not data URLs, unlike all other read paths (the 2026-08-30/2026-12-04 boundary work listed backlog_add/backlog_list/emit_backlog_changed/dispatch_item + run_all_dispatch_next; startup.rs was missed). Fix: route the snapshot's items through `resolve_item_view` (one map under the existing lock — same pattern as `emit_backlog_changed`), retype the field to `Vec<BacklogItemView>`, and update the field doc; that closes both the checkpoint_sha gap and the pre-existing image gap in one change. Alternatively, if left for a follow-up, soften the two doc claims so the wire contract is documented truthfully.
