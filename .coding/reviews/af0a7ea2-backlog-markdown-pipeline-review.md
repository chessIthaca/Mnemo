## Findings

1. **(low) Suspense fallback window collapses single newlines on the backlog card — transient 2026-08-21 regression.**
   - `frontend/src/components/views/BacklogView.tsx:643` — the card display div dropped `whitespace-pre-wrap` (replaced by prose classes). Before this change that class covered the lazy-load window by inheritance.
   - `frontend/src/components/chat/Markdown.tsx:19-21` — `MarkdownFallback` renders raw children under className `markdown-fallback`, and that class has **no CSS rule anywhere in the repo** (repo-wide search: the only occurrence is Markdown.tsx:20). So during the first paint before the lazy markdown chunk resolves, a multi-line item renders with `white-space: normal` and its single newlines collapse — exactly the regression the plan guards against, in transient form (self-heals once the chunk loads; chat/plan/FileViewer share the same latent gap, the backlog card is the newly-regressed surface).
   - The plan explicitly says to keep "the whitespace-pre-wrap fallback classes". The BacklogView.test.ts comment justifying the drop ("it would double-break") is inaccurate — remark-breaks consumes `\n` into `<br>` so no literal newline remains in the rendered output, and `<pre>` sets its own white-space — but dropping pre-wrap on the rendered path is still fine; the gap is the fallback path.
   - **Fix:** give the fallback pre-wrap, e.g. `.markdown-fallback { white-space: pre-wrap; }` in the global stylesheet (or `whitespace-pre-wrap break-words` classes on the fallback div). One rule fixes backlog, chat, plan, and FileViewer fallbacks and makes the currently-dead class meaningful.

2. **(low) Chip wiring deviates from the plan's prescribed mechanism (behavior-equivalent today).**
   - Plan step 4: add `md?: boolean` to `ToolCardChip`, set it only on the argLabel-derived chip when `name === "backlog_add"`, and render non-path chips through InlineMarkdown when set.
   - The implementation instead checks `name === "backlog_add"` at the render site (`frontend/src/components/chat/Message.tsx:792`) for ALL pathless chips, and no `md` flag was added.
   - Verified equivalent today: for backlog_add the only pathless chips are the per-call argLabel chips (the engine chip is search-only, the browser chip is browser-family-only, and `toolCardPaths.ts:74` keeps `text` out of path chips). Risk: if backlog_add ever gains another pathless chip kind, it would silently render as markdown.
   - **Fix:** either align with the plan (add the flag at the chip push site) or accept the name-check coupling and make the render-site comment state it precisely (the current comment already scopes the behavior to argLabel-derived chips — the code should match that claim).
