### HOW: byte-for-byte file copies via chunked file_write + git diff --no-index verification

Copying a large file byte-for-byte with the file tools (shell Copy-Item is forbidden by the file-mutation policy):
1. Read the source in ~400-line read_files ranges (larger ranges get archived to the expand_result store and must be retrieved again).
2. Write the target with file_write mode="overwrite" (first chunk, ≤~4000 chars) then mode="append" chunks, always split at LINE boundaries with each chunk ending in "\n" — appends concatenate verbatim (verified: per-chunk byte counts sum exactly; no inserted separators).
3. Verify with `git diff --no-index <src> <dst>` (exit 0 + no output = byte-identical) and fix discrepancies with file_edit single-line SUBSTRING anchors (exclude leading whitespace — e.g. anchor on `vi.mock("path…", () => ({`, not on the line's indentation) or read-receipt line cites.
Known hazards: (a) chunk boundaries systematically lose or duplicate boundary lines (5 dropped lines + 2 duplicated `});` across ~30 boundaries in one 60KB copy — every one caught by the final diff; recheck the first/last line of each chunk against the read); (b) transcription contamination inserts a familiar wrong token (wrote "MIT OR Apache-2.0" where the source said "MIT" on 11 adjacent lines); (c) the file tools CANNOT produce a file without a trailing newline — a line-cite replacing the last line with a no-newline variant is refused ("produced no change"), so a source lacking a final newline yields a copy with one extra byte (acceptable, document in the commit). For mangled unicode (em-dash → U+FFFD) use a from_read line cite — an old_string anchor cannot match the unknown bytes.
