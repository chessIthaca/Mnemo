### DECISION: deletion-preview superseded_by uses ledger::merged, not bare status Merged

Plan 01762f92 step 1 (commit c2f606e on wt/agent-supersed): the plan text said superseded_by = "another record with the same plan_id/plan_step and status Merged", but the implementation uses ledger::merged(other) — status Merged AND merge record present AND revert_commit.is_none(). Rationale: revert_merge keeps status == Merged after backing out (team.rs revert_locked only sets merge.revert_commit), and after_revert already reopens the board step when no other ledger::merged task remains; a plain status check would let the delete sheet claim "Its step landed through X" for a worker whose merge was reverted, and the frontend then suppresses the red unmerged-work warning for work that never landed. For every non-reverted case (the reported senderLedger34/senderReplay36 scenario and the regression test) ledger::merged ≡ status == Merged. ledger::merged also requires the merge record, which real merged workers always carry; the crafted-ledger regression test therefore stamps a merge object on the merged record.
