### HOW: reading repo files in mnemo2 vitest tests — no node:fs, import JSON instead

Two gates make node:fs unusable in mnemo2 vitest tests (hit on plan 09d6fe1f step 5, commit 2143fabb):

1. Vite's asset transform statically rewrites the literal `new URL("...", import.meta.url)` (the brief's readFileSync + fileURLToPath recipe) into an http dev-server URL (http://localhost:3000/package.json) — fileURLToPath then throws "The URL must be of scheme file". Verified empirically: import.meta.url itself IS a proper file:/// URL; only the new-URL-with-literal pattern is transformed.

2. mnemo2/tsconfig.json has "types": ["vite/client"] and the workspace (root + mnemo2) has NO @types/node at all — `import { readFileSync } from "node:fs"` fails svelte-check ("Cannot find name 'node:fs'") and adding the dependency means touching mnemo2/package.json + lockfile + tsconfig (out of a frontend step's scope).

Resolution used: import the file as JSON instead (`import packageJson from "../../package.json"`), relying on resolveJsonModule: true already in the tsconfig. Same file, same data, fully typed, passes svelte-check, vitest and the production build. If a future test genuinely needs node APIs, @types/node must be added to mnemo2 devDependencies AND "node" appended to the tsconfig types array — a dependency change the lead must sanction.
