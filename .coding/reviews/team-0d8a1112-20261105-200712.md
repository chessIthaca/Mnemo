### BUG: pump_worker's transcript refresh discarded a review recorded while its git tip probe ran

Symptom (macOS CI run 42071163294, plan 0d8a1112): mnemo2::runtime::lead_merges_from_inside_its_own_turn failed intermittently with "the current worker tip has not been reviewed" although team.review() had returned Ok just before the merge.

Root cause: pump_worker's trailing refresh task reads the worker tip (`phase3::tip`, a `git rev-parse`) OUTSIDE the records lock, then locks the records and clears worker.review/worker.checks whenever that snapshot tip differs. A review recorded while the probe was in flight (the lead committing a fix on the worker branch and reviewing that commit right after the Completed status) postdates the observation and is at the CURRENT tip, but the stale snapshot compared its older tip against it and dropped both the review and its checks. The tests commit_worker_file + team.review() immediately after wait_for_worker_status(Completed), so on a slow runner they land exactly in that window (the refresh also re-fires on the trailing Usage event, 10 ms after the terminal one).

Fix (commit 01617cac on wt/agent-macFlaky, src-tauri/src/mnemo2/team.rs): capture `tip_read_ms = phase3::now_ms()` BEFORE the tip probe and skip the clearing when `review.reviewed_at_ms >= tip_read_ms` — such a review covers whatever HEAD is now; keeping it is safe because validate_merge re-reads the live tip and every check tip. Extracted as `clear_review_for_a_newer_tip(worker, current_tip, tip_read_ms)` with regression test `mnemo2::team::tests::a_refresh_that_read_the_tip_before_the_review_keeps_that_review` (red without the guard).

Companion item in the same commit: serve_tests dropped the first FakeServer and sent request 2 immediately; macOS can complete a handshake from the closed listener's backlog and reset it, yielding HttpError::Io ("connection reset by peer (os error 54)") instead of HttpError::Connect, so the deliberate no-resend rule fired. testutil::wait_until_connect_fails (probe connect must FAIL — Windows drops the SYN from a closed loopback port instead of refusing, so "refused" is not portable and the bridge resends every failed connect) now runs after each drop that expects the "Mnemo2 is gone" path.
