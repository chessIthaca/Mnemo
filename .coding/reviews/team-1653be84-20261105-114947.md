### HOW: zip 9's ZipFile::name() is fallible — laya.rs skips undecodable names

zip 9 (8.6.0 -> 9.3.0, commit 3f7303bc on wt/agent-secRustB, plan 1653be84 step 1) changed `ZipFile::name()` from `&str` to `ZipResult<Cow<'_, str>>`. It is the only zip API break in our tree: `is_dir()`, `by_index()`, `ZipArchive::new`, and the writer (`start_file` + `SimpleFileOptions`, used by the laya test fixtures) are unchanged.

Fix in src/host/laya.rs `extract_uv_asset`: `let Ok(name) = entry.name() else { continue };` — an undecodable name is skipped and the scan continues. That is what zip 8 did implicitly (`String::from_utf8_lossy` -> U+FFFD, never equal to the ASCII binary, so the entry never matched and the loop moved on); propagating with `?` would instead abort extraction over a decoy entry.

Entry names are still only compared (never used as write paths), so the traversal refusal is untouched; note the zip branch checks `is_dir()` but not `is_symlink()` (pre-existing: `io::copy` writes the link-target text as file content, no traversal).

Verified: cargo tree -i zip shows only zip v9.3.0; rustls 0.23.43 -> 0.23.46 via `cargo update -p rustls` (single rustls version, rustls-webpki 0.103.16 along). Targeted `cargo update -p` only — Cargo.lock keeps the vendored wry/tauri patches (no [[patch.unused]], wry 0.57.2 source-less), guarded by tests/integration/ci_workflow.rs `cargo_lock_keeps_the_vendored_patches` (run as `cargo test --test integration ci_workflow::`; there is no `--test ci_workflow` target).
