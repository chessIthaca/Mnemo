Implementation decisions worth remembering:
- The built-in spec-driven schema's `specs` artifact uses a GLOB template path (`specs/**/*.md`). Schema::load reads templates as single literal files, so a fork of the built-in materializes glob templates under a literal name (`specs.md` = artifact id + the glob's extension) — Windows forbids `*` in file names outright, and a materialized fork must pass Schema::load. fn literal_template_name in specs_settings.rs owns this rule; file-based fork sources are copied verbatim (a Unix folder could hold the literal `**`/`*.md` names).
- store_artifact (template + instruction edit) writes both files, reloads with Schema::load, and restores the previous bytes when the edited schema does not validate.
- run_openspec_validate resolves the CLI by scanning PATH for openspec/.exe/.cmd/.bat (npm's .cmd shim is not resolvable by Command::new on Windows) and runs it via `cmd /S /C` on Windows with `.coding/` as cwd; validate_with(root, cli: Option<PathBuf>) is the tested core so the no-CLI refusal is testable without mutating process env.
- mnemo2 is an npm workspace of the repo root: fresh worktrees have no node_modules and need `npm install` at the ROOT (not in mnemo2/) before npm run check / vitest work.
