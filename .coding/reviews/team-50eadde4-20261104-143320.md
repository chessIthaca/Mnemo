### BUG: routing gates read Laya's margin confidence, not the top probability

Root cause (fixed in commit 9cb3eac5, branch wt/agent-layaConf, plan 50eadde4 step 1): a live `/v1/systemone` choice answer carries TWO confidence numbers — the pick's lower, margin-like `confidence` (e.g. 0.6742) and the top option's probability, Laya's `answer_confidence` (e.g. 0.9113, floor 1/labels). `src/memory/classifier.rs` `parse_answer_for` keeps both in `Answer::Choice { label, confidence, probabilities }`, but every routing gate read only `confidence`, which the gates in `src/agent/route_question.rs` (DEFAULT_MIN_CONFIDENCE_3 = 0.475, DEFAULT_MIN_CONFIDENCE_2 = 0.60) are NOT calibrated for — so routing almost never cleared.

Fix: `route_question::answer_confidence(&Answer) -> f64` — for `Answer::Choice`, the max over `probabilities` (via `max_by(total_cmp)`, since f64 is not `Ord` and `Iterator::max()` will not compile), else the pick's `confidence`; other primitives keep `Answer::confidence()`. Consumed at the three routing gates only: Mnemo2 `dispatch_routing::classify_dispatch` (decision `confidence` + `cleared`, so logged route rows carry the top probability), Mnemo2 `route_eval::classify_corpus` (the eval scores what the gate reads), and Mnemo1 `model_routing::classify_task_text`.

Do NOT move `parse_answer_for`, the `Answer` type, failure triage, memory auto-typing or tool choice onto `answer_confidence`: those are calibrated on `Answer::confidence` and must keep reading it.
