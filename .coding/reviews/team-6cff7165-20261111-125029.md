### HOW: run long cargo/clippy checks in a Mnemo worker worktree (shell hard 300s cap)

The `shell` tool kills a command at 300 s regardless of the requested timeout, and a killed cargo leaves child rustc processes compiling in the background (they finish, warming target/, but the command's exit code is lost). For a cold Mnemo2 worker worktree, run the long check detached and poll a log + exit-code file:

```powershell
$root="C:\Mnemo\.worktrees\<agent>"; $log="$root\target\clippy.log"; $exit="$root\target\clippy.exit"
$inner="cargo +1.99.1 clippy -p mnemo-app --all-targets --features mnemo2 *> '$log'; `$LASTEXITCODE | Set-Content '$exit'"
$line="powershell.exe -NoProfile -Command `"$inner`""
Invoke-CimMethod -ClassName Win32_Process -MethodName Create -Arguments @{CommandLine=$line; CurrentDirectory=$root}
```

`Start-Process -NoNewWindow` does NOT work: the harness stops a background process that keeps the output pipe open. Poll with `Test-Path target\clippy.exit` / `Get-Content ...`, and check no cargo/rustc is running before launching (a concurrent run blocks on the target lock). Prereq for a cold worktree: `npm ci` at the repo root then `npm run build:mnemo2` before the first cargo test, else tauri's build script fails.
