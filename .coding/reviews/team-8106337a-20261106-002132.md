### HOW: lint the mnemo2 feature tree — clippy needs --features mnemo2

Procedural (mnemo-app, 2026-11-05, step 3 of plan 8106337a, commit 4092ef7a): `cargo clippy --workspace --all-targets -- -D warnings` does NOT lint the mnemo2 module tree — `mnemo2 = []` in src-tauri/Cargo.toml is not a default feature, so plain workspace clippy (and plain `cargo test`) never compiles `src-tauri/src/mnemo2/**`. Lint it with `cargo clippy -p mnemo-app --features mnemo2 --all-targets -- -D warnings`; trust its result only after a real compile (a sub-second "Finished" can be a cache hit — after `cargo clean -p mnemo-app` the fresh lint takes ~50s). Same rule as the constitution's feature-gated test clause, applied to clippy. Also: `IndexingTracker::new()` returns `Arc<Self>` — do not wrap it in another Arc (double-Arc cost one build cycle on laya_check.rs tests).

### HOW: svelte-test rerender re-fires every prop-reading $effect — shield reads behind $derived

@testing-library/svelte v5's rerender (svelte-core props.svelte.js) swaps the whole props object (`currentProps = $state.raw({ ...currentProps, ...nextProps })`), so ANY $effect that reads ANY prop re-runs on EVERY rerender — even when the prop it reads is unchanged. This bit plan 8106337a step 4 (TiersPage, commit fa611b39): the initial-load $effect read `layaTransport`, so a rerender that only changed `evalPass` re-fired the whole Promise.all load and double-counted routingStatus reads in the "re-reads routing when a check finishes" test. Fix pattern: put the effect's prop read behind a `$derived` (`const activeTransport = $derived(layaTransport);`) — a derived that recomputes to an identical value does not re-run downstream effects, so the effect only fires when the transport itself actually changes. In the real app props are fine-grained per-prop signals, so this only manifests under the test library's proxy; the derived shield is harmless in production and makes rerender-based tests deterministic.
