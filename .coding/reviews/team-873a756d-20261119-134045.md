### BUG: `?` on an Option issue-classifier disabled a healthy vision client

In src/provider/client_factory.rs `build_vision_client`, `match vision_issue(config)? { … }` was wrong: `vision_issue` returns `None` when the config resolves *cleanly*, so `?` returned None from the function and built no VisionClient for a perfectly valid `[general.vision_model]` — every executor/audit worker silently had no image tools (found in review of commit 416c6089, plan 873a756d). Fix (a7aba679): only short-circuit on an actual issue — `if let Some(issue) = vision_issue(config) { match issue { UnlistedModel => {}, MissingEndpoint => return None, AnthropicEndpoint => { warn; return None } } }`, then build. General rule: a classifier returning `Option<Problem>` must never be `?`-ed; `None` is the success path. Regression tests: `build_vision_client_builds_for_a_valid_endpoint`, `build_vision_client_builds_for_an_unlisted_model`, and the end-to-end `a_valid_vision_config_offers_the_image_group` (src/agent/factory.rs — the other factory image-group tests inject a MockDescriber and never reach build_vision_client).
