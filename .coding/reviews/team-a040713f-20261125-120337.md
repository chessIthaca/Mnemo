### HOW: build and test mnemo's remote node link (src/remote)

`src/remote` (plan a040713f, the hub↔node link) is gated by mnemo's `remote` feature, which implies `headless`. A plain `cargo test -p mnemo` does NOT compile it: run `cargo test -p mnemo --features remote remote::` (all link/pairing tests live there and use `tokio::io::duplex`, no ports). `cargo test --workspace` picks the feature up through `src-tauri/mnemo2-app`, whose mnemo dependency lists `remote`.

Seams for phases 3-6: `Link::dial`/`dial_on` (node) and `accept`/`accept_on` with `HubAuth{hub_id, hub_epoch, tokens}` (hub); `Link::{call, call_stream, notify, closed, peer_epoch}`; `LinkHandler::{request, note}` with `StreamTx::start` before the first `item`; `LinkSlot::{set, wait_up}`; `PairingRegistry::{issue_code, redeem}` + `NodeRegistry` (files under the hub state dir) + `NodeIdentity` (node.json) + `pair_with`/`serve_pairing`. Handshake refusals come back as `RemoteError.code` = the refusal reason (unknown_node, proto, bad_proof, bad_code, expired); frame/frame-MAC violations close the link and fail pending calls with `link_down`.
