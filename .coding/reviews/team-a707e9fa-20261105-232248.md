### SPEC: plan_create spec-impact gate — governed_files maps, spec_impact declaration, new-capability rule

The spec-impact gate (plan a707e9fa, commit f02da93 on wt/agent-specGate): OpenSpec is enforced, not encouraged. Mechanics: (1) .coding/openspec/config.yaml `governed_files` maps capability -> exact repo-relative paths, parsed by OpenSpecConfig (src/app/openspec/schema.rs); empty/absent list = no gating for that capability. (2) PlanBoard::spec_impact_issues (src/app/plan_board.rs) intersects the plan steps' file paths (step_paths) with the map — for each hit capability with no spec delta on the plan it refuses via resumability_gate_error("spec impact not covered", ...), naming the capability and both remedies (attach a delta via plan_create/plan_update spec_deltas, or declare no impact). (3) The escape hatch: plan_create's optional `spec_impact: {none: bool, reason: string}` — none=true + non-empty reason exempts; recorded as a dated "no spec impact" decision line in the plan markdown AND as BoardEntry/BoardPlan field `no_spec_impact` in board.json; a declaration without a reason is refused. (4) plan_update add_steps runs the same gate over the added steps (combined deltas cover; the plan's recorded declaration exempts). (5) New-capability rule: a delta whose capability has no spec dir under .coding/openspec/specs/ is refused unless config.yaml declares a NON-EMPTY governed_files list for it — in update only the newly added deltas are checked (old in-flight plans don't retroactively fail). Path matching (same_repo_path) normalizes \ to / and strips leading ./. team.rs is governed by FOUR capabilities (dispatch-routing, external-lead, tier-ladder, worker-brief) — a plan touching it needs a delta per hit capability or a no-impact declaration. plan-board governs src/app/plan_board.rs + src/app/tool/workflow/board.rs.
