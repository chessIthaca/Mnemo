### HOW: run long cargo builds detached via WMI, not Start-Process (shell tool kills spawned trees at the call boundary)

Detached cargo builds in this project MUST be launched via WMI process creation, not Start-Process: the Mnemo2 worker shell tool kills the whole spawned process tree when the tool call returns.

Evidence (2026-11-08, worktree agent-deltaBat, plan aa44321b step 1): (1) `Start-Process cargo ... -NoNewWindow -RedirectStandardOutput/-RedirectStandardError` died with 0-byte logs — the harness noted "a background process started by the command kept the output pipe open; it was stopped"; (2) `Start-Process powershell -File <script> -WindowStyle Hidden` (no pipe held) was still killed before its first output line; (3) the identical script launched with `([wmiclass]'Win32_Process').Create('powershell -NoProfile -ExecutionPolicy Bypass -File "C:\<worktree>\.coding\tmp\verify-battery.ps1"', 'C:\<worktree>', $null)` survived across tool calls (verified with a heartbeat script; parent is WmiPrvSE.exe, outside the tool's tree).

Working recipe for the long (cold, >300 s) cargo battery:
1. `file_write` a runner .ps1 into `.coding/tmp/` (gitignored scratch): one line per cargo command with `*> .coding/tmp/<name>.log` (the native command's own exit code still lands in $LASTEXITCODE), plus `"step exit=$LASTEXITCODE" | Out-File .coding/tmp/verify-summary.txt -Append -Encoding utf8` per step — poll only the summary, one tool call per ~4 min of `Start-Sleep`.
2. Launch via the WMI Create call above; poll with `Get-Content .coding/tmp/verify-summary.txt` and `Get-Process -Id <pid>`.
3. A fresh worktree also needs `npm ci --no-audit --no-fund` + `npm run build` first (tauri's `generate_context!` requires target/frontend-dist to exist); ~50 s + ~5 s.
4. Log gotcha: PowerShell 5.1 `*>` redirection writes non-UTF-8 logs — `read_files` fails on them ("stream did not contain valid UTF-8"); read them with `Get-Content`/`Select-String` from the shell instead.
5. npm ci prints an expected `npm warn install-scripts .npmrc allow-scripts setting is being ignored` warning (exit 0 — do not treat as failure).
