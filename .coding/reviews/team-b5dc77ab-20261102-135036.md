### HOW: Mnemo2 Files tab — lazy Git-aware tree via ls-tree/ls-files, paths confined by canonicalize (plan b5dc77ab step 1, commit ba3cca09)

The lead's Workbench Files tab (mnemo2) lists the project tree lazily — one directory per IPC call, never a walk — and confines every path to the project root.

Backend: src-tauri/src/mnemo2/files_view.rs (commands files_list / files_read / files_find, registered in mnemo2/mod.rs directly after ipc::workbench_preferences_set).
- One-level listing = tracked entries from `git ls-tree -z HEAD` (or `HEAD:<dir>`) merged with untracked ones from `git ls-files --others --exclude-standard --directory -z -- <dir>/`. Deriving immediate children from those gives .gitignore-awareness for free (ignored build output never reaches the UI) and shows tracked-but-ignored files correctly. A non-Git project (ls-files fails) falls back to std::fs::read_dir, skipping .git.
- Path safety: resolve() rejects NUL bytes, every non-Normal path component (so `..`, `/etc`, `C:\...`, `\\server\share`), then canonicalizes root.join(rel) with dunce and requires starts_with(canonical root) — catching symlinks/junctions that escape. Reads: 256 KB cap, cut on a UTF-8 boundary, NUL byte in the first 8 KB => binary (text empty).
- files_find answers the path filter from `git ls-files --cached --others --exclude-standard`, capped at 200.

Frontend: mnemo2/src/lib/files.ts (FilesTransport + createFilesTransport/seedFilesPreview, visibleRows, languageFor, highlightFile via highlight.js/lib/common + DOMPurify, formatBytes), mnemo2/src/components/FilesTab.svelte (tree, filter, drill-down read-only viewer), WorkbenchTab gained "files" at the END of the union plus ProjectPreferences.workbench_tab in projectEngine.ts (the persisted-tab union lives there, not in types.ts).

Gotcha: `git ls-tree -z` records are `<mode> SP <type> SP <sha> TAB <name> NUL`; `ls-files --others --directory -z -- .` emits `<path> NUL` with no `./` prefix and a trailing `/` on condensed directories.

Preview: a dev-only `files` scene in mnemo2/src/test/previewScenes.ts (after worker-thread) seeds the transport via seedFilesPreview; previewScenes.test.ts pins the ordered scene-name list, so a new scene must be added there too.
