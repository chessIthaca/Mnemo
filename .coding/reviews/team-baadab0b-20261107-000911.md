### BUG: a merged worker's stuck checkout is retried until it is gone

A merged Mnemo2 worker whose checkout could not be removed (Windows os error 32 — a shell whose working folder was inside .worktrees/agent-*) used to keep the folder and the "merged, but worktree cleanup needs attention" note for ever, and sweep_merged_branches skips a worker with a checkout folder, so its branch was never auto-deleted. Root cause: cleanup_agent_worktree ran only twice per worker (merge_locked, recover_worker) and never again. Fix (plan baadab0b): retry the removal for every Merged worker whose error starts with one of the two checkout-cleanup notes ("merged, but…" / "merge recovered, but…"), both in merge_locked before sweep_merged_branches and once in TeamRuntime::open after schedule_trash_sweep, awaited under the merge lock then sweep_merged_branches(""). A successful retry (or a folder already gone) clears the note and persists; the existing sweep deletes the branch. No setting, event or UI change; cleanup_agent_worktree/remove_leftover_checkout guards unchanged. Documented in mnemo2/README.md, plugin/skills/mnemo-lead/SKILL.md item 6 and plugin/skills/mnemo-review/SKILL.md section 7.
