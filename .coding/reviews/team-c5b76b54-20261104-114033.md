### SPEC: Mnemo2 window close is a setting (auto/tray/quit) in mnemo2.toml [window], live-read on every close

Mnemo2's window-close behaviour (plan c5b76b54, commit 2d97d68b on wt/agent-closeTra, 2026-11-03):

- The setting is `[window] close = "auto" | "tray" | "quit"` in <config_dir>/mnemo2.toml (Mnemo2's own file, never config.toml). Default and missing-or-invalid fallback: `auto` (invalid eprintln!s a warning, then Auto). Module: src-tauri/src/mnemo2/window_settings.rs — `close_action(behavior, started_hidden, tray_ok)` is the pure decision table; `WindowBehavior` (RwLock<CloseBehavior> + AtomicBool tray_notice_shown) is the managed live state, `take_tray_notice()` claims the notification exactly once per process.
- mod.rs loads the word once at startup via `resolve_config_dir(None)` and reads it LIVE on every CloseRequested, so a Settings > Appearance save applies without a restart. Auto = today's rule exactly (hide to tray iff the window started hidden behind a tray icon); Tray hides whenever a tray exists; Quit routes through `request_quit` (workers confirm first) — never app.exit directly.
- The first hide-to-tray close per run sends one OS notification: title "Mnemo2 is still running", body "It keeps running in the tray. Use Quit in the tray menu to exit, or change this in Settings > Appearance." (tauri_plugin_notification; failure logged + ignored).
- The save rides the existing appearance_settings_save command (no new commands): the wire/patch gained `close_behavior` (serde lowercase); appearance_settings::save_settings writes it via window_settings::save_close_behavior (dispatch_routing-style read-modify-write that keeps [routing]) and the command pushes it into the managed WindowBehavior via save_settings_live(setup, patch, Option<&WindowBehavior>).
- Frontend: AppearancePage.svelte has the "When I close the window" radiogroup (exact labels: "Automatic — hide to the tray when Claude Code started Mnemo2, otherwise quit" / "Hide to the tray" / "Quit Mnemo2" + hint "Mnemo2 keeps running in the tray while hidden; use Quit in the tray menu to exit."); saves like the other groups.

### SPEC: Mnemo2's Appearance settings surface lives in lib/sounds.ts, not settingsEngine.ts

When a plan or review says the Mnemo2 Appearance page's settings engine is in `mnemo2/src/lib/settingsEngine.ts`, it is wrong: settingsEngine.ts is the Settings > Endpoints/tiers transport only. The Appearance page's data layer lives in `mnemo2/src/lib/sounds.ts` — AppearanceSettings, AppearancePatch, AppearanceTransport, normalizeAppearance (safety net for older hosts), createTauriAppearanceTransport (invokes appearance_settings_get/appearance_settings_save), setPreviewAppearanceTransport and the SOUND_ROWS table. Its theme row table lives in `mnemo2/src/lib/theme.ts` (THEME_ROWS, applyTheme, parseTheme), and the dev-only preview-scene seed is `mnemo2/src/test/previewAppearance.ts` (previewAppearanceSettings + createPreviewAppearanceTransport). Adding an Appearance field means touching: sounds.ts (types + normalize), the Svelte page + its .test.ts, previewAppearance.ts, sounds.test.ts and theme.test.ts literals. Plan c5b76b54's brief named settingsEngine.ts for this; the change correctly landed in sounds.ts (commit 2d97d68b).
