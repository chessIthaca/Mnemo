### PLAN: Laya async — explicit-choice dispatches defer the classification (plan c74b1987)

Implemented in commit 5825f5a (wt/agent-layaAsyn, plan c74b1987 step 1): when a dispatch carries an explicit tier or model choice and classification would actually run (classifiable text, >=2 tiers, classifier installed, mode != Off), route_implementation_dispatch (src-tauri/src/mnemo2/team.rs) returns immediately with a null Laya label; the classification runs in a background tokio task (spawn_pending_classification) under the same routing_permit and 3s timeout, writes the same corpus rows via the shared helpers dispatch_route_row / dispatch_lead_override_row, and attaches laya_tier/confidence/cleared to the worker's routing record (nudge-path live-record mutation), persisting best-effort. Key decisions forced by code reality: (1) the task is spawned from dispatch_locked after provisioning, not from route_implementation_dispatch — the auto-assigned worker id only exists there and the corpus row needs it; (2) WorkerRouting.cleared is bool, not Option (the plan said "already Option" — only laya_tier/confidence are); it stays false until the label lands, no schema change; (3) routed_by resolves at dispatch time and stays "lead" for async explicit dispatches even when Laya clears a different tier — the override is corpus-only (LeadOverride row still written, so every override remains a training label); (4) the dispatch answer prints "Laya: classifying in the background; the label will land on the routing record." instead of a wrong "Laya: offline."; (5) skip conditions (too_short/one_tier/no classifier) stay inline — their outcome needs no call. Non-explicit paths byte-identical. Side effects to know: a background classification holds the routing permit, so a concurrent drift classification can lose its 3s window (drift_never_blocks_the_message stub delay reduced 2s->1s for this); the boundary test tauri_uses_only_public_api gained two more mnemo::agent::model_routing::append_row call sites in team.rs (spawn_pending_classification) on top of its pre-existing failure.
