### BUG: OpenSpec merges doubled blank lines + wrote THEN for extra outcomes (fixed 1f3d1837)

Fixed on wt/agent-specSpac commit 1f3d1837 (plan d590bfad step 1), files src/openspec/spec.rs + tests in src/openspec/delta.rs.

Symptom: closing a plan whose spec change modified one requirement added an extra blank line before every other requirement in the capability's .coding/openspec/specs/<cap>/spec.md, growing one per merge; a scenario with two outcomes rendered '- **THEN**' twice.

Root cause 1: Spec::parse stores each Requirement's original Markdown sliced from its '### Requirement:' heading to the START of the next heading, so Requirement::original includes the trailing blank line. Once a delta clears Spec::original, Spec::render rebuilt via 'push(\n) + push_str(requirement.render())' and each preserved block re-emitted its trailing blank line. Fix in Spec::render's reassembly: push '\n' + requirement.render().trim_end() + '\n'; extra sections likewise trim_end + '\n' after ensuring the buffer ends with "\n\n". The unchanged-document early return (byte-identical round trip) is untouched.

Root cause 2: Scenario::render wrote every `then` entry as THEN. Now then[0] is THEN, then[1..] are AND, explicit `and` entries are AND. Parsing is unchanged (an AND bullet goes to `and`), so then=[a,b] round-trips as then=[a], and=[b].

Regression tests: delta::tests::modified_delta_keeps_one_blank_line_between_requirements (two MODIFIED merges in a row -> no "\n\n\n", untouched requirement blocks appear once unchanged) and spec::tests::scenario_renders_second_outcome_as_and. Both verified failing before the fix (the first merge doubled the blank line; second outcome rendered '- **THEN** t2').

Also cleaned .coding/openspec/specs/tier-ladder/spec.md (three doubled blank lines collapsed, second THEN -> AND).
