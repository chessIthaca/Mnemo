### REVIEW: Mnemo2 settings dialog — closure silently loses drafts on 6 of 7 draft pages

Full architecture and style review of the Mnemo2 settings dialog (SettingsDialog.svelte + Sheet.svelte + 9 pages), read-only, 2026-11-05, plan e76ff094. The .coding/reviews/ path is tool-protected, so this record is the durable report; the plan-close report carries the trail.

Verification: `npx vitest run src/components src/lib` — 1026 tests passed (exit 0); `npx svelte-check` — 0 errors, 0 warnings; one runtime warning `[svelte] assignment_value_stale` at ModelsPage.svelte:159:57 (budget accept callback uses the assignment as an expression value; a block-bodied arrow clears it).

Architecture: Sheet content exists only while open ({#if open}, Sheet.svelte:88) — closing unmounts every page and destroys all draft state. Escape → onclose() unconditional (Sheet:61-66); backdrop is a full-screen <button> (:90); SettingsDialog passes onclose through unchecked (:124) and rail switches unmount pages (:134). Seven per-open transports (SettingsDialog:86-92); one endpoints+tiers load gates 7 pages while Project/Specs render regardless (:94-115, :148-185). Save models: Project + Appearance are immediate-apply (nothing to lose); Endpoints/Tiers/Models/Savings/Safety/MCP/Specs are draft+Save/Discard.

Findings:
- F1 HIGH — Closing the dialog (X, Escape, backdrop) or switching rail pages silently destroys unsaved edits on 6 of the 7 draft-bearing pages. Only TiersPage guards: capture-phase window click/keydown + beforeunload + confirm("Discard unsaved Tiers edits?") (TiersPage:621-644); leavesPage (layaSettings.ts:474-481) counts Escape and clicks on a button outside the page root — the backdrop being a <button> is what makes it work.
- F2 MEDIUM — That guard is fragile and untested: no test exercises the confirm path (search "Tiers edits|confirm(" in *.test.ts: zero matches; leavesPage unit-tested only, layaSettings.test.ts:161-186); it depends on capture-vs-bubble ordering against Sheet's svelte:window handler; it only recognizes button clicks; native confirm() is the app's third confirmation idiom (inline banner EndpointsPage:313-318, Sheet-based WorkerDeleteSheet).
- F3 MEDIUM — EndpointsPage "Discard changes" (EndpointsPage:317) ADOPTS the draft (snapshot = JSON.stringify(draft)) instead of reverting it; harmless today because every stashed action replaces the draft, but it inverts the button's meaning; should reload like discard() (:118-126).
- F4 MEDIUM — Over-broad load gating: loadError/loading from the endpoints+tiers read also blank Safety/MCP/Appearance (SettingsDialog:148-151, :166-183), which consume no endpoints/tiers data; a failed endpoints read makes three unrelated pages unusable, and Project/Specs are exempt — inconsistent.
- F5 LOW — refreshAfterEndpointChange swallows the tiers re-read error (.catch(() => {}), SettingsDialog:120): after an endpoint save, a failed re-read leaves the dialog silently stale; a later Tiers save can clobber backend rewrites.
- F6 LOW — assignment_value_stale runtime warning at ModelsPage:159:57 (see verification).
- F7 STYLE — Six near-identical draft/dirty/save/discard implementations; a shared useDraft() composable would collapse them and give the close guard one plug point (the structural fix for F1/F2).
- F8 STYLE — leavesPage, a generic UI predicate, lives in the domain lib layaSettings.ts:474, imported only by TiersPage.
- Good: errorText + role="alert" used consistently; a11y fundamentals (role=dialog, aria-modal, aria-current rail, focus trap/restore, inert background); Appearance optimistic-apply with rollback; documented adopt-snapshot semantics; per-open transports with a non-Tauri fallback; preview transport injection for tests.
- Residual: beforeunload behavior in the Tauri webview vs the [window] close auto/tray/quit setting is unverified from source; needs a live desktop check.

Recommended follow-ups (a fix plan, not done here): (1) dialog-level dirty registry + one confirmation idiom — pages register dirty state, Sheet close paths and rail switches consult it; integration tests dirty→close→confirm→decline/accept per page; (2) fix EndpointsPage:317 to revert, not adopt; (3) surface the :120 re-read failure; (4) narrow load gating to pages that consume endpoints/tiers; (5) block-bodied accept at ModelsPage:159; (6) extract useDraft() together with (1); (7) move leavesPage to a shared lib or retire it with the registry.
