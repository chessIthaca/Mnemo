### SPEC: every automatic memory re-embed goes through reembed_if_needed and shows on the status line

After an embedding-model change, every automatic re-embed (brain startup, deferred load, Settings rewire, and install_embedder for Install, Setup::reembed and the startup load) calls crate::memory::reembed_if_needed.

What it does:
- It re-embeds only stale rows (embedding NULL, or a model/dim mismatch, compared null-safe with IS NOT), so a pass cut off by closing the window resumes.
- It publishes ReembedEvent (started, progress, done, failed) on MemoryStore::reembed_events(), a tokio watch so a late subscriber reads the last state.
- The Mnemo2 IndexingTracker folds it into the 'embeddings' pass. IndexingStatus.svelte shows "Re-embedding memories · n/N memories".

Only the manual Memory tab "Rebuild search" still uses reembed_all (every row). Never add a new automatic re-embed that bypasses reembed_if_needed. Plan ebd13a79.
