### DECISION: Mnemo2 theme is data-theme on html + tokens in app.css; CSP forbids an inline pre-paint script

Mnemo2's theme (plan f1bd54e5 step 4, commit cf9f532 on wt/agent-darkThem) works like this: `mnemo2/src/lib/theme.ts` paints `data-theme` ("light"/"dark") onto `<html>`, sets `color-scheme` and `<meta theme-color>`, mirrors the `[ui] theme` choice to `localStorage["mnemo2.theme"]`, and follows `prefers-color-scheme` live while the choice is "system". `mnemo2/src/app.css` declares every colour token once in `:root` (light, byte-identical to the old literals) and overrides only the flipping ones in `:root[data-theme="dark"]` — no component carries a literal colour (exception: Collapsible's `#000` mask gradient and the hue-based avatars, whose lightness is tokenised as `--avatar-bg-lightness` / `--avatar-ink-lightness`).

Constraint worth remembering: the Tauri CSP is `script-src 'self'`, so an inline pre-paint script in index.html is BLOCKED. Pre-paint therefore = `data-theme="dark"` statically on `<html>` in index.html/preview.html (the UiConfig default theme) plus `applyCachedTheme()` as main.ts's first statement, then `actions.initTheme()` (store action at the end of its actions object) reads the authoritative `[ui] theme` through the Appearance transport.

Backend: `src-tauri/src/mnemo2/appearance_settings.rs` now accepts `theme` in its patch, normalises it and refuses unknown words (nothing written). Preview page: `?theme=light|dark` or a scene's `theme` field (dark variants mission-control-dark / lead-chat-dark / graph-dark) — preview repaints pass `remember=false` so they never overwrite the saved choice.
