## Plan notes (retired at close)

### BUG: never name a Svelte 5 $state variable "state" — svelte-check reads the rune as a store subscription

In a Svelte 5 runes component (svelte 5.57.x / svelte-check 4.7.x, as in mnemo2), `let state = $state<T>(...)` fails svelte-check: a variable literally named `state` makes the `$state` rune read as that variable's store subscription ("'state' implicitly has type 'any' … referenced in its own initializer", "Block-scoped variable '$state' used before its declaration", then "Untyped function calls may not accept type arguments" on EVERY generic `$state<T>()` in the file). Rename the variable (e.g. `updateState`); generic `$state<T>(init)` is fine once no variable collides with a rune name ($state/$derived/$effect/$props). Precedent: UpdateBanner.svelte in commit 6bcb6b15, plan f3d43b57 step 2. Related same-commit lesson: fire-and-forget event-subscription chains (`void client.onState(...).then(...)`) need a rejection handler, or App-level tests that mock isTauriRuntime true make vitest fail the whole run on unhandled rejections from the real @tauri-apps/api listen.

### HOW: keep a feature-gated module warning-free in both builds under #![deny(warnings)]

Mnemo2's updater module (src-tauri/src/mnemo2/updates.rs, plan f3d43b57) must compile cleanly with AND without its `auto-update` Cargo feature, and the crate root has `#![deny(warnings)]` — so dead_code breaks one side of a simple `#[cfg]` split. Working shape (no #[allow], per project rule): (1) keep the check/download machinery (begin_check/run_check/now_ms/traits) always compiled and *referenced* in both builds — a no-feature `struct SourceBuild` implementing UpdateSource (returns Ok(None)) is passed where the feature build passes PluginSource, so the no-feature build still "uses" the machinery; (2) the background `start()` body stays always compiled and exits early on `UpdateState::Disabled`, so FIRST_CHECK_DELAY/CHECK_INTERVAL are used in every build; (3) a wire enum variant never constructed in one build (e.g. `Disabled`) needs the module exported (`pub mod updates;` like `pub mod claude_code;`) — `pub(crate) mod` keeps it crate-private, so dead_code flags the variant. Private consts used in only one cfg branch must be inlined (a literal is never dead code).
