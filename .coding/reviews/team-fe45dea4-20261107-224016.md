### HOW: compare git-diff text in PowerShell without UTF-8 mojibake

On this Windows machine, PowerShell 5.1 decodes external-command stdout (git diff, git show) using the console codepage (CP437/1252 family), NOT UTF-8. Any verification script that compares git-output text against file content mangles every non-ASCII byte: an em dash "—" (UTF-8 E2 80 94) shows up as "ΓÇö" (CE 93 C3 87 C3 B6) and produces false "missing line" mismatches. Fix: set `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` BEFORE capturing git output, and read the compared files with `Get-Content -Encoding UTF8`. Hit during plan fe45dea4 step 2's pure-move verification (store.ts -> store/*.ts, commit 890e3a57): the em-dash line in openTrace's doc comment was the only false positive, which revealed the encoding cause — exactly one moved line contained non-ASCII. Also note the read_files archiver redacts some tokens in displayed large reads (e.g. `number`); when copying code byte-exactly, re-read the region in small ranges (<250 lines) that display unredacted, or use read-receipt-cited edits.
