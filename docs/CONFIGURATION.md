# Mnemo — configuration reference

How to configure Mnemo: global config in `~/.mnemo/`, provider endpoints and models, MCP servers, and the per-project `.coding/` state. Feature and workflow detail lives in [FEATURES.md](./FEATURES.md); the quickstart lives in the [README](../README.md).

## Configuration

Global config lives in `~/.mnemo/` — `config.toml` (defaults, safety mode, per-state model routing, the `[memory]` retrieval knobs — recency-decay half-life, per-query cap, derived per-class cap, digest budgets), and the `[context]` compaction knobs — `summarize_at_fill_rate` (fraction of window triggering summarization) plus `preflight_compact` / `compact_headroom_tokens` (defaults on / 32 000) enabling aggressive keep_recent=3 compaction once a session exceeds its remaining headroom before each provider call) and `proxy_cache_ceiling_tokens` (default 340 000, `0` disables) — summarize before the ~340K-token cliff where LiteLLM-class proxies drop whole-conversation prefix caching; also settable in Settings → Advanced), plus `[general].auto_compact_on_plan_complete` (default off, Settings → Advanced) which compacts the main agent's context between Run-All items — after each completed plan, before the next dispatches — gated on the same fill-rate dial: it fires only when the post-item context is at/above the effective `summarize_at_fill_rate` threshold (proxy-ceiling cap included); below it the summarization call is skipped and the next item dispatches directly, so overnight loops start every item clean without paying a summarization call on small contexts (a failed or timed-out compaction logs and proceeds; the loop never stalls), `endpoints.toml` (providers + models + pricing — the Settings → Pricing model field is an editable combobox listing the models the configured endpoints serve, annotated with their endpoint names, plus free typing for anything else; each endpoint declares a kind — `openai`, `local`, or `anthropic` for the native Messages API, which also accepts an optional `workspace_id` sent as the `anthropic-workspace-id` header on every request so usage is attributed to a specific workspace), `keys.toml` (API keys, user-only permissions), and `projects.toml` (known projects). The system prompts (preamble, workflow lifecycle, app rules, tool strategy, memory records, per-state workflow guidance) and the tools-array descriptions are compiled constants — not configurable per install. Installs predating the rename are migrated from `~/.myharness` automatically on first launch.

The **context-economy levers** are opt-in — `[general.optimizer]` in `config.toml`, every flag `false` by default and omitted while default: `delta_reads` (a re-read of a file the agent already has serves a skeleton or a unified diff instead of the whole file), `compress_output` (collapse known command families — `cargo`, `npm`/`yarn`/`pnpm`, `pytest`, `go` — to their signal lines, dedup repeats, and redact credentials on every model-served surface), `archive` (archive tool results at/above `archive_min_chars`, default 20 000 chars, keep a preview in context, and retrieve the full text later with the always-advertised `expand_result` tool by id or keyword), `compaction_survival` (archive the region a summary is about to drop as a checkpoint, hand the summarizer the decisions seen so far as a must-preserve block, and leave a post-compaction digest note naming the checkpoint), `quality_score` (grade the context S–F from fill, wasted tokens and stale re-reads, shown in the ctx hover popup) and `lean_output_nudge` (past `lean_output_fill_pct` fill — default 25 — ride one lean-output steering line on the volatile tail so the cached prefix is never touched). Further knobs: `compress_min_chars` (default 2 000), `nudge_cooldown_requests` (default 10, shared by both nudges) and `compress_extra_commands` (extra command prefixes to compress). Every lever writes a row to the `savings_events` ledger so its cost/benefit is auditable; the Dashboard view (right panel, immediately before Memory) reads that ledger back per project. With a flag off its code path is byte-identical to the pre-lever behaviour.

The **Laya classifier** is opt-in — `[general.laya]` in `config.toml`: `enabled = true` plus `endpoint = "http://127.0.0.1:8000"`, the base URL of a running `laya-serve` instance (install it yourself: `pip install "laya[serve]"`, then run `laya-serve`; it binds `0.0.0.0:8000`). Disabled by default — the section is omitted from `config.toml` while untouched, and an absent or disabled section builds no classifier client, makes no call, and adds no startup cost; enabled without a (non-blank) endpoint logs a warning and stays disabled. Settings → Classifier edits the keys (external `endpoint`, or the managed sidecar's `mode`/`checkpoint`) plus the four consumer opt-ins — `auto_type_memories` (memory prefix correction), `failure_triage` (classify failures to steer retries), `failure_triage_knn` (the kNN overlay that learns from the failure-triage training log via the local memory embedder — needs no `laya-serve`), `auto_finetune` (the startup fine-tune, managed mode only; all default `false` and omitted while default) — and shows the live status (`disabled` / `installing` / `downloading` / `starting` / `ready` / `failed`, plus a `finetuning` payload while the startup fine-tune runs). No auth is sent yet: the service's optional `LAYA_API_KEY` bearer is not part of this surface.

The `[ui]` display toggles live in the same file and are edited in Settings → Chat (token usage in the activity bar, tool/knowledge activity cards, thread line, prose cap, turn tint, hover timestamps). The **steering notes** that ride in tool output are individually controllable: `[ui.steering_notes]` carries one optional boolean per kind — `auto_delegated`, `search_nudge`, `shell_tip`, `graph_miss`, `recall_rider`, `read_nudge`, `literal_tip`, `known_memory_hit`, `consolidation_due`, `shell_redirect`, `edit_stale_read` — rendered as one checkbox per kind ("Steering notes in tool results"), and an unset key falls back to that kind's default: only `auto_delegated` is hidden by default, the other ten are shown. This is a DISPLAY-layer filter — the tool result the model reads, including a note's re-issue escape hatch, is never modified; only the chat ToolCard's render drops the line. Matching is anchored to the start of a line or to the note's own marker shape, so a `path:line:`-prefixed hit line in a search/read result keeps quoted note text visible — with one deliberate exception: the stale-read matcher keys on the note's own drift sentence, so a line reproducing that sentence in full is hidden wherever it sits, location prefix included. Otherwise only a raw stream (`shell` output, the generic output fallback) can match a note copied verbatim at column 0. `auto_delegated` also honors the older `[ui].show_delegation_notes` boolean, which still parses and seeds its default (the per-kind key wins when both are set); the AUTO-DELEGATED graph header doubles as the `search_nudge` marker, so either flag hides it.

Models inside an endpoint are plain ids (`models = ["gpt-4o"]`) or per-model tables (`[[endpoint.models]]`) with their own `max_context`, `max_output_tokens`, `reasoning_effort` default, and `reasoning_efforts` allow-list — a single endpoint can host models with different token budgets and reasoning surfaces. The per-model `reasoning_effort` (settable on each model row in Settings → Providers) wins over the endpoint's value when set; unset inherits the endpoint's (then the app default `max`), and the status-bar effort dropdown stays the runtime override on top of it. Per-context slots in `[models]` (Settings → Models, one effort dropdown per context row) take the same `reasoning_effort`: a set value wins over the model's own default for that context only (planning/executing/bug_fixing/reviewing/complete/subagent/skill), unset inherits the chain above, and anthropic-kind endpoints ignore it (the Messages API has no effort field). The `summarize` slot is a dedicated consumer outside that chain: it routes compaction summaries (auto-compaction + the run-all between-items compact) to its model; unset (or dangling) rides the turn's model. Caveat: the summarize model's own context window is never consulted — the whole to-summarize region is sent to it, so pick a cheap model whose window covers your largest contexts (a too-small window fails the compaction; the turn continues — compaction is never a blocker). The `bug_fixing` slot is a plan-kind override, not a state: while the active plan's kind is `bug_fixing` and the workflow is in that plan's active lifecycle (Executing or Reviewing), it wins over the `executing` slot — so a bug-fixing session can run on a max-reasoning model while implementation plans keep the executing slot; unset (or dangling — the endpoint no longer exists) inherits `executing`, then the default. Base URLs are forgiving: a missing trailing `/` is auto-appended on save. Models whose tokenizer emits its stop boundaries as raw text (GLM-5.3's role tags + newline cascades) are fixed by config, not code: `stop_boundary_strings` on the endpoint or a model entry (model-level wins) lists the boundary strings — they ride the request `stop` list ahead of your own `stop` sequences and also arm the client-side stream guard that cuts a runaway stream at the first boundary; the same strings are escaped to a visible `⟦raw:\uXXXX…⟧` marker in tool-result messages (serving layers may strip them from request input too — the model then can't see them in tool results) and restored to the raw token by the file tools on write, so token-containing files round-trip read → write unchanged; pair with `stop_token_ids` for servers that honor token ids (the GLM-5.3 example: the four role-tag boundaries plus the `\n\n\n\n`/`\n\n\n` cascades, and ids `[151329, 151330, 151336]`). The effort dropdown's `off` choice has the same escape hatch: `reasoning_effort_off_wire` on the endpoint or a model entry (model-level wins) sets the wire value `off` encodes as — unset, the built-in default applies (DeepSeek-family model names → `none`, the enum's explicit thinking-off variant; everyone else omits the field), so a renamed or fine-tuned DeepSeek model that needs the mapping the name-based default can't see is fixed by config. Aliases and fine-tunes are covered — resolution is by config, never by model-name prefix. Strict tool schemas are capability-gated per endpoint: `supports_strict_schema` on an endpoint entry overrides the kind default (`openai` kinds enforce, `local`/`anthropic` don't) — set it `false` for an OpenAI-kind endpoint behind a litellm/vertex-class proxy that rejects the field, or `true` for a local endpoint that enforces it. When the effective value is true, the mutation/plan tools (`file_edit`, `file_write`, `file_append`, `convert_line_endings`, `create_plan`, `update_plan`, `complete_step`, `abandon_plan`, `finish`) are advertised with `"strict": true` and their schemas normalized to strict-legal form (every property required, optional ones nullable, `additionalProperties: false`) — the tools' forgiving argument forms keep working unchanged, and read-only tools stay unnormalized.

MCP servers live in `mcp.toml` — `[[server]]` entries with a name and exactly one transport: `command` + `args` (stdio, e.g. `npx -y @modelcontextprotocol/server-filesystem`) or `url` (+ `headers_env`) for remote servers. Secrets never enter the file: `env` and `headers_env` carry environment variable NAMES whose values are resolved from the environment at connect time. Each enabled server exposes its tools as a deferred `mcp.<name>` group (one index-line until the agent calls `load_tools`), and every MCP tool call is approval-gated. Settings → MCP edits the set and has a Test button (connect + list tools); saves apply to agents built afterwards — a restart always picks them up. Two per-server knobs: `trusted = true` skips the per-call approval prompt for that server's tools (auto-approve for servers you trust — it never widens the plan-first state gates), and `idle_timeout_secs` drops a cached connection that has been idle that long, re-establishing it lazily on the next call (omit it to keep connections until they fail).

MCP config is two-scope: the installation-wide `~/.mnemo/mcp.toml` is union-merged with an optional per-project `.coding/mcp.toml` — the project file wins by name (same philosophy as skills: global baseline, project overrides). The Settings → MCP list tags each server with its source, and a save splits entries back into their files. Remote servers can authenticate with OAuth 2.1 (`auth = "oauth"` + a pre-registered `client_id`; optional `scopes`): Connect opens the browser login (PKCE S256, loopback redirect), tokens live in `keys.toml`, and expired access tokens refresh automatically on 401. Servers that advertise prompts and resources also expose `mcp__<server>__get_prompt` / `mcp__<server>__read_resource` agent tools (capability-gated, registered at reveal); server-initiated `sampling/createMessage` requests are declined with a standard JSON-RPC error so servers never hang.

Per-project state lives in `<project>/.coding/` — knowledge files, plans, review reports, the backlog (`.coding/backlog.jsonl`, git-union-merged across worktrees), the memory + knowledge-graph databases (both git-ignored, rebuildable caches), and the skills (`.coding/skills/`, seeded at init from the app's embedded baseline — write-if-missing, so project-specific edits are preserved and deleted files self-heal on the next init).
