# Mnemo — feature reference

The detail behind the [README](../README.md)'s highlights: what the engine under Mnemo2 does — memory, the code graph, the tools, providers, safety and the token-saving levers. The app itself (lead, team, workbench) is described in [mnemo2/README.md](../mnemo2/README.md), the review gate in [REVIEW-POLICY.md](./REVIEW-POLICY.md), configuration in [CONFIGURATION.md](./CONFIGURATION.md).

## Key ideas

- **Plans live on a board, not in a chat.** The lead writes every task as a plan with a spec for each step; workers receive the plan and their step, and the plan file on disk is what survives restarts and model switches.
- **Memory is first-class infrastructure.** Every turn auto-recalls relevant memories; sessions consolidate into episodic summaries, distilled facts, and reusable procedures. The agent you talk to next week remembers this week's decisions — because a forgotten decision is a defect: the cost is not the retyping, it is the wrong call made confidently on a stale premise.
- **Tool usage is optimized.** Semantic code indexing and purpose-built tools replace grep archaeology — editing with a map, not a torch: the right file, first try.
- **Review is unskippable by construction.** A worker's branch cannot merge without the lead's review evidence, checks on the exact commit and every finding closed; high-risk work also needs an independent read-only audit (see [REVIEW-POLICY.md](./REVIEW-POLICY.md)).
- **Bugs get their own plan kind.** A `bug_fixing` plan names its symptom and its regression test, and it cannot close until the regression test is recorded.
- **Everything survives an interruption, even when context resets.** The spec is a file on disk, not a chat message: plans live on disk with per-step checkboxes, memory lives in SQLite, and the lead's transcript and the worker ledger are saved in `.coding/mnemo2/`, so a restarted Mnemo2 resumes where it stopped.
- **Context is the scarce resource.** Shell/build noise never enters the window, occasional tool families stay deferred until wanted, and the tool array is byte-stable so provider prompt caches hit.

A chat window can suggest all of the above. **A harness enforces it.**

## Key features

**Safety**
- Diff-based approval gate with three safety modes (approve-each / auto-approve-project / autonomous); git `merge` and `push` are always approval-gated
- Path sandbox confining all file tools to the project; protected `.coding/` live state and the `.git` control plane (planted hooks/`core.fsmonitor` can never be written by the file tools); refusals are hardlink-aware (a `.coding/**` file whose inode is shared with another name is refused) and re-run on the canonical path (a Win32 8.3 alias like `.coding/KNOWLE~1/…` cannot plant a subtree inside a protected tree), and the creation ladder fails closed on link components — a dangling link leaf included, with its one lexical fallback (a just-created parent) re-checked for link-freedom; API keys stored user-only (Windows DACL / `0o600`)
- Crash-safe resume: plans, the lead transcript and the worker ledger persist across restarts
- Hang watchdog: if the main thread ever stalls >10 s (a Windows "Not responding" hang), the app writes an evidence report — `hang-<timestamp>.txt` in the project's `.coding/logs/` (or `%TEMP%\mnemo-hang-reports\` when no project is open) — with the stall duration, main-thread CPU busy-vs-blocked sample, a stack walk of the stalled main thread (module!symbol + file:line per frame), and a wait-chain summary naming the blocked-on object (all Windows-only enrichment), plus the agent's recent activity — so the next freeze names its exact line instead of being guessed at.
- Live shell output: while a `shell` call runs, its stdout/stderr stream to the tool card as they are produced (throttled, with a per-call live budget), so a multi-minute build shows progress; the final tool result the model reads is unchanged
- Command-aware shell-output filtering: `cargo`/`npm`/`git status` noise (Compiling…, passing tests, asset tables) is collapsed to errors, warnings, and summaries before it reaches the transcript — errors are never hidden, unknown commands pass through, and the raw unfiltered stdout/stderr remain in the tool result's `data` field. Configure via the `[shell_filter]` section of config.toml

**Memory**
- Four tiers: working (raw events), episodic (session summaries), semantic (durable facts), procedural (workflows)
- SQLite + FTS5 keyword search combined with bundled ONNX embeddings (fastembed; hash fallback) for semantic recall — no external service needed; keyword hits re-rank by cosine, and a zero-keyword query falls through to a capped semantic scan (200 most-recent) so paraphrases and stemming misses still surface; the cosine weight is embedder-aware (0.2 hash fallback / 0.35 real embedding models)
- Automatic consolidation pipeline plus manual maintenance in the Memory tab (Diagnostics → Memory upkeep: clean up memory, rebuild search, rebuild index)
- Typed memory records: title prefixes `SPEC:`/`DECISION:`/`BUG:`/`PLAN:`/`HOW:`/`REVIEW:` classify records; the four knowledge types (SPEC/DECISION/BUG/HOW) live as **files** under `.coding/knowledge/<type>/` — git-tracked, wiki-linked (`[[spec/x]]`, `[[plan/<id>]]`, `[[src/...]]`), unbounded bodies with TOML front matter (title/status/supersedes/created); `memory_write`/`memory_supersede`/`memory_update`/`memory_delete` operate on the files (the truth), and the derived index holds budgeted digests with path+commit pointers (the derived index auto-truncates digests to stay compact; the file is complete). Supersede-not-delete keeps history (superseded files/records are excluded from recall by default, retrievable via `include_superseded`); a startup digest-integrity sweep quarantines — never deletes — records corrupted at write/index time (a digest cut mid-path, the `.c`-truncated class, or a body self-marked no longer true) with the same recoverable-history semantics, retrievable via `include_quarantined`; the auto-recalled-memories block itself is task-scoped and noise-controlled (backlog c68a8c3b): with a plan active the recall query embeds the plan's goal+context so the plan's own records outrank generic matches, and noisy rows are dismissible per-session via `recall_feedback`; superseding rewrites stale hand-written `File:` pointer lines in the successor body to the tool-chosen canonical path (the caller cannot know the deduped filename), and a targeted reindex of a successor knowledge file resolves its `supersedes` against the on-disk corpus (predecessor context + metadata reconciliation) so updates no longer error or leave stale digests; hygiene tools `memory_update`/`memory_amend`/`memory_supersede`/`memory_delete` (`memory_amend` appends a dated amendment paragraph to a knowledge record — the sanctioned `.coding/knowledge/**` addition writer, stripping a leading `Amended …:` heading the caller supplies so exactly one heading lands, dated by the tool; `memory_update` also carries a `find`/`replace_with` targeted-repair mode that fixes stray text in a record body in place, so record text is repairable in-tool rather than via the shell fallback), `recall_feedback` (per-session dismissal of noisy auto-recalled rows: the agent passes the `(id: ...)` values from the RECALLED MEMORIES block and the injector drops them for the session's remainder — the store is untouched, so `memory_search` still finds them and future sessions re-derive normally), `memory_consolidate` for distillation, and the single retrieval tool `memory_search` (a ranked query, or a query-less browse narrowed by record_type/tier/prefix that replaces the former list-only tool) plus read-only `git_read`
- Derived index: `.coding/plans`, `.coding/reviews`, `.coding/knowledge/**`, and the pending backlog are indexed into budgeted PLAN:/REVIEW:/SPEC:/DECISION:/BUG:/HOW: digests with path pointers (incremental, idempotent; rebuild wipes only derived records — authored memories are sacred). **Startup reconciliation**: on project open the corpus is checked against the index state (content hashes); when the on-disk truth drifted — a git merge landed, a record was edited, or `memory.db` was deleted — the index is re-derived from the files in the background; an in-sync startup stays silent. The Memory tab's Diagnostics box shows the counts and the index state, and Memory upkeep rebuilds it by hand
- **The SQLite DBs are caches, the files are the truth**: `.coding/memory.db` and `.coding/codegraph.db` are gitignored rebuildable stores — deleting either forces a full rebuild from source (knowledge files, plans, reviews, source code). Git carries only the truth files. Creating a project seeds the ignore rules for those caches — plus `.worktrees/`, the plans stack pointer, the instance marker, logs and backlog attachments — and the `.coding/backlog.jsonl merge=union` attribute: `Project::init` MERGES them into an existing `.gitignore`/`.gitattributes` — only lines not already covered are appended (a leading-slash form counts as covered, a commented-out one does not), user lines are never reordered or overwritten, the file's own CRLF style is kept, and a re-run is a byte-identical no-op
- **Working-branch topology**: the lead works on one long-lived branch (`wt/mnemo` in this repository); each worker gets a `wt/agent-*` branch and `.worktrees/agent-*` checkout forked from the lead branch tip and is merged back with `--no-ff` after review, after which Mnemo2 deletes the worker's branch and checkout. Landing on `main` is a pull request. `.coding/` travels with git, so knowledge files, plans, reviews and the backlog merge across instances — `backlog.jsonl` uses git's union merge driver (concurrent adds concatenate cleanly; UUID ids never collide) — and the memory index re-derives automatically at the next project open after a merge
- Scale knobs in the `[memory]` config section of config.toml: recency-decay half-life, per-query result cap, derived per-class cap, digest auto-truncation lengths

**Code intelligence**
- Tree-sitter knowledge graph (Rust, TS/TSX, JS, Python, Go, Java, C/C++, C#, Ruby, PHP, HTML) in a per-project SQLite DB, kept fresh by a file watcher whose trigger set matches the content index's coverage — `.coding/` artifacts (knowledge, plans, reviews, backlog) included, with only the app's own SQLite stores excluded (an index pass writes them itself)
- Agent tools: `graph_search`, `graph_context` (360° view), `graph_impact` (blast radius), `graph_path`; the Graph tab and the side panel's Graph view
- FTS5 content index behind the `search` and `search_read` tools (literal single-line queries, bm25-ranked) with transparent walk fallback — the walk PRUNES ignored directories (never enumerates their children); index hits are freshness-checked per query (each hit file's on-disk mtime vs the as-of-index mtime — in the edit→watcher gap a modest staleness is repaired inline under an adaptive bound: up to 32 stale files are re-indexed within a ~500 ms budget and the query re-served from the fresh index with a "reindexed N stale file(s)" note that names the first three paths and points at `~/.mnemo/index-staleness.jsonl` (one record per stale file — path, cause class, mtimes, inline-vs-surfaced), while a staleness beyond that ceiling, a set whose repair exhausted the budget, or a running index pass serves the authoritative walk with a "content index stale for N file(s)" note instead of pre-edit content — every stale path still recorded, above the ceiling included); an EMPTY fetch is never trusted either — the watcher's reindex lags newly written files, so a zero-hit literal always falls through to the authoritative walk (no silent false negatives for fresh .coding/ files); globs support brace alternation (`**/*.{ts,tsx}` expands into concrete alternatives — the glob crate has none natively) and a glob matching zero files says so ("the glob matched no files — if that's unexpected, use extension-anchored shapes like **/*.rs") instead of a bare "no matches"; a zero-hit content search falls back to filename matching (a plan file never contains its own id)

**Agents, providers & interface**
- Lead and workers: Mnemo2's lead and every worker run as sessions on one shared headless `Engine`. Workers have a dedicated executor prompt and cannot plan, spawn agents or ask the user; audit workers for high-risk reviews are read-only. Each worker runs on its tier's model and can be moved to another tier mid-task with its transcript and checkout kept (see [mnemo2/README.md](../mnemo2/README.md))
- Any OpenAI-compatible endpoint plus local providers (Ollama, LM Studio) and native Anthropic Messages API endpoints (Anthropic or any compatible gateway via a custom base URL); reasoning-effort and vision support (per endpoint, or per model — one endpoint can mix text-only and vision-capable models); full request tracing
- Optional Laya classifier (off by default): a local `laya-serve` sidecar that Mnemo downloads, starts and stops itself on 127.0.0.1, answering typed questions with calibrated probabilities. Disabled means no HTTP client, no calls and no startup cost. Its consumers, each confidence-gated and each off by default: **tier routing** (Settings → Tiers: watch, suggest or pick each worker's tier at dispatch), **memory auto-typing** (`[general.laya] auto_type_memories`: corrects a record's typed prefix above 0.80 confidence), **failure triage** (`[general.laya] failure_triage`: classifies tool and provider failures as transient, permanent, needs-user or flaky-test, re-runs a confident transient read-only call without a model round-trip, and logs every disposition to `~/.mnemo/laya/training/failure_triage.jsonl`) and the **kNN overlay** (`[general.laya] failure_triage_knn`: votes with the most similar logged failures, embedded by the local memory embedder)
- Reasoning-state continuity: each provider's assistant turn is stored **verbatim** in `Message::raw` (reassembled from streamed deltas) and echoed unchanged by the request builder — so reasoning fields (`thought_signature`, `reasoning_content`, thinking-block `signature`, `encrypted_content`) and any unknown keys round-trip byte-identical; a `ProviderPolicy` data object per provider (`src/provider/policy.rs`) captures each provider's reasoning contract and drives cross-vendor detection (full builder consultation of include/template/reasoning-field params is a follow-up); cross-vendor model switches strip reasoning + set `reasoning_stripped` (one-way — see `strip_cross_vendor_reasoning` doc); compaction never trims inside an open tool loop; serialization-bug 400s (missing `thought_signature`, `reasoning_content must be passed back`, `Expected thinking…found text`, `modified prior content`) fail loudly and are never retried; the OpenAI Responses API (`previous_response_id`) provides server-side stateful mode alongside the stateless raw-echo path
- Per-model endpoint config: each model within an endpoint can carry its own max input/output token caps and reasoning-effort allow-list; base URLs are forgiving (a missing trailing `/` is auto-added on save and load), and token caps discovered from the provider auto-fill the per-model entries in Settings
- Provider retries that never hide: every failed provider attempt is surfaced as a transient "attempt N/3 failed, retrying" note; non-retryable errors (context overflow, auth failure, model-not-found) fail immediately instead of burning the retry stack, and a 429 (rate limit or out of quota) stops after one attempt against that provider and switches to the same model on a different endpoint if one is configured (the alternate stays sticky for that model id), with an actionable error when no other endpoint serves the model
- The LLM trace records per-request phase timings — prep (local prompt build: token counting, recall, prompt assembly), compact (auto-compaction call), backoff (retry sleeps before this attempt), connect (the POST in flight: TCP/TLS + upload + server ack), wait (TTFT: POST-send → first token — upload + server prefill/queue), reasoning (thinking time), generation (answer time), stall (byte-silence gaps inside the generation window), and tool-execution time — so you can see where each request's latency actually went; error records (connect timeout, stream stall, HTTP error) carry their elapsed time in the connect/wait/generation buckets too, so a 10s connect timeout or 30s dead-connection stall is attributed instead of lost; a user interrupt that drops a live stream mid-flight stamps the record **cancelled** (not failed) — no provider-errors row, and the aborted request still lands a `cancelled` row in request_stats so it stays countable; reasoning text is recognized from `reasoning_content`, `reasoning`, and inline thinking-tag blocks (Ollama / DeepSeek thinking mode)
- Incremental token accounting: the turn loop re-tokenizes only messages appended since the last count (plus a head swap) instead of a full-history BPE pass per request, so context counting stays O(1) per loop iteration even as the conversation grows
- Context compaction that never wedges the conversation: the verbatim-kept tail is cut at a tool-call boundary (no orphaned tool results whose assistant call was summarized away), `/compact` in the lead composer announces start + result in the transcript on every path, and a mid-task compact resumes the interrupted work on the compacted conversation instead of stopping execution; past its remaining headroom toward a session's last tokens it automatically turns aggressive (`keep_recent=3`) so long sessions never fatal with `ContextWindowExceededError`; a turn whose context STILL stays over the threshold re-compacts at most 4 times (escalating `keep_recent` to 1) before aborting the turn with a clear error instead of re-compacting every iteration forever, and error loops are owned by the consecutive-error cap, which counts error INTERACTIONS: a batch of same-time failing calls is one interaction, giving the model a repair chance between interactions (backlog 7f72d3d7); the former turn-level repetition guard (3 byte-identical consecutive responses) was removed 2027-01-24 — after the interaction-aware fix its only reachable domain was identical responses following SUCCESSFUL batches, which aborted legitimate re-reads, so identical re-emission after success no longer aborts (within-response loops stay owned by the in-stream R10 guard)
- Token-optimizer levers (every flag ON by default since 2027-01-25 — `[general.optimizer]` in `config.toml`; uncheck a lever in **Settings → Savings** to opt out; backlog e4a50d22; **Settings → Savings** in the app edits the same keys from inside the UI, applied live without a restart): seven independent context-economy levers, each writing a `savings_events` ledger row so its cost/benefit is auditable. **Outline reads** (`delta_reads`) — a whole read of a source file over 500 lines serves its signature outline (ranged reads always serve exact lines; smaller files are served whole), and an outline never costs more than the full read. Read output numbers lines `12: code` — no column padding and no trailing whitespace (the edit tools' whitespace-normalized fallback still lands an anchor copied from that view); indentation is kept, since the edit payloads must reproduce it. **Output compression** (`compress_output`) — known command families (`cargo`, `npm`/`yarn`/`pnpm`, `pytest`, `go`, plus `compress_extra_commands`) collapse to their signal lines with repeats deduped, and credentials are redacted on every line the compactor serves (output it never sees — short results, non-family commands — passes through verbatim). **Archive + expand** (`archive`) — tool results at/above `archive_min_chars` (default 20 000) are archived in full to SQLite (FTS5-indexed) and replaced by a preview, and the always-advertised `expand_result` tool retrieves any row by id or keyword. **Compaction survival** (`compaction_survival`) — before a summary replaces the region it drops, that region is archived as a checkpoint, the decisions seen so far ride the summarizer as a must-preserve block, and a post-compaction digest note (files touched, commands run, errors seen) names the checkpoint id, so the dropped detail stays one `expand_result` away. **Quality score** (`quality_score`) — the context is graded S–F from how full the window is, and the grade shows in the ctx hover popup. **Lean-output nudge** (`lean_output_nudge`) — past `lean_output_fill_pct` fill (default 25) one steering line keeps the model's own output lean. **Recall delta** (`recall_delta`) — a repeat auto-recall of a memory whose id AND content hash were already injected in the same compaction epoch renders a compact reference (tier, title, stable id, score, `unchanged since injection (turn N)`) instead of re-sending the 160-char snippet; a new, changed, or post-compaction recall still arrives in full, and the reference points at `memory_search` because the volatile tail is popped right after every request; an ALL-elided set — every row already injected, the set unchanged since its last sighting — collapses into ONE sentinel line (`N recalled memories unchanged since injection (first at turn M); re-read with memory_search if needed.`) instead of N references, so an unchanged five-row recall costs one line (mixed sets keep the per-row references; backlog c68a8c3b). Invariants: nothing is dropped before it is archived (every archive/store error is fail-open, falling back to the pre-lever behaviour), the already-sent conversation prefix is never mutated (the lean-output nudge rides the volatile tail, popped right after the request, while the post-compaction digest is a persistent note on the freshly-compacted conversation — neither rewrites already-sent content, so the provider prefix cache stays valid), tools stay store-free (they emit `data.savings`; the turn loop records), token counts are estimates (chars/4, `measured = false`), and with a flag off its code path is byte-identical to pre-lever behaviour. The **Savings** card on the **Cost** tab reads that ledger back per project: metered total saved tokens + event count, a per-kind and per-day breakdown, the recent events, and a prompt-cache section (cached vs prompt tokens, hit rate) whose dollar figures are labelled ESTIMATED and priced from the `[[pricing]]` table at the project's own realized input/cached rates — never mixed into the metered totals.
- Links in chat open in the side panel's Browser pane on Windows, and in the system browser elsewhere
- Headless Chromium browser tools (`offscreen_browser_*`) and — on Windows — live embedded-WebView2 Browser pane tools (`browser_*`) the agent can click, type, and screenshot — and, via vendored wry 0.57.2 patches (`vendor/wry/PATCHES.md`), the Browser pane signs in to AAD/MSA sites silently with the Windows primary account (Edge-equivalent OS SSO) and its Reload button always bypasses the HTTP cache (CDP Page.reload with ignoreCache — no stale pages after a redeploy); opening the same project in a second instance asks for confirmation
- MCP (Model Context Protocol) servers: third-party tool servers configured in `mcp.toml` (stdio commands or remote URLs; env-var names only, never values). Each server's tools appear to the agent as a deferred `mcp.<name>` group — one index line until `load_tools` reveals them — with every call approval-gated (unless the server is explicitly trusted, which skips only the per-call prompt) and connections lazy + self-healing; Settings → MCP edits the set with a Test button and live per-server status lines
- Image parsing: when the main model is text-only and a vision model is configured, each pasted image is described by the vision model before the turn starts
- Svelte 5 UI (Mnemo2): lead chat, Team (mission control), Cost, Graph and Plans tabs, and a side panel with Browser, Diff, Plan, Files, Git, Trace, Graph and Memory
- Dark and light themes, set in Settings → Appearance
- The `git` tool forwards validated extra flags for read queries (`status`/`diff`/`log`/`branch list`) — precise queries such as `git diff main..feat --stat`, `git log -5`, or `git branch -vv` run through the tool instead of falling back to the shell (`branch list` uses an allowlist of read-only listing flags; positionals are refused since they create branches) — and its structured `restore` subcommand (`paths` + optional `source` tree-ish and `target` worktree/staged/both) restores files from a ref or discards uncommitted/staged changes without the shell
- The `git` tool is forgiving about its `subcommand`/`action` fields: the subcommand name may be given in either field, and branch/stash action names are accepted in the `subcommand` field (`subcommand: "delete"` = branch delete) — swapped or redundant fields no longer fail the call, and error messages list the valid values
- The `git` tool's schema marks `subcommand` as required, its description carries a per-subcommand required-fields map (commit→message, merge/checkout→branch, restore→paths, branch delete/create→branch), and per-subcommand validation errors quote the exact expected arguments — a model that drops a required field gets the full expected shape back in the error, not just the field name
- `git diff` output is never truncated — the user-mandated exception to the ~100 KiB tool-output cap (a truncated diff could hide changes under review), mirroring the read-only `git_read` tool
- Backlog: ideas for later live in `.coding/backlog.jsonl` (git union merge). The agent adds items with `backlog_add`; an item can be handed to the lead to plan, and the plan it becomes marks the item done
- Plan resumability gate: `plan_create` rejects plans too thin to survive a restart. The context must be substantive (at least 40 characters), every step must name the file paths it touches, and a `bug_fixing` plan must name its regression test
